# Figures: conventions

Every tier keeps its figures in `tier-NN-*/figures/` (the files the markdown embeds) and the scripts that make them in `tier-NN-*/figures/src/`. Regenerate a tier's figures with:

```sh
python tier-NN-*/figures/src/make_all.py
```

**Rules**
1. **Generated, not drawn.** A figure is produced by a script that imports the tier's own code (`tier-NN-*/code/`, `lab/`). Any number shown in a picture is computed by that code (several scripts assert it equals the library output before drawing).
2. **Formats.** SVG for 2-D line art (text stays selectable), PNG for static 3-D views, GIF for motion (Manim-style: dark canvas, smooth easing, one idea per step). Keep a GIF under about 1.5 MB (fewer frames, fewer colours).
3. **Style.** `figures-common/figstyle.py` defines the dark palette, easing, GIF writer and caption helper. Do not hard-code colours in scripts.
4. **In the concept file.** Place the figure at the point where it explains the mechanism (usually the end of section 4, "How does it work?"). Use this block: bold label `Figure N-k — title`, image with descriptive alt text, a *How to read it* paragraph that states what the viewer should notice, and a *Generated by* line naming the script.
5. **Own work only.** Figures are original. Do not copy figures from papers or websites (copyright); describe the idea and redraw it.
6. **Naming.** `fig_<chapter>_<short_name>.<ext>` (for example `fig_3_20_backprop.gif`), script with the same stem.

Interactive 3-D (rotate with the mouse) cannot be embedded in GitHub markdown; static views and rotating GIFs are used instead.
