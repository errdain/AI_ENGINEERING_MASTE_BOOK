# 2.9 Samples

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: Medium · Hands-on: High

### 1. What is it?
One **example/instance/row**: a single `(x, y)` observation. A dataset is a collection of samples assumed to be drawn from some data-generating process.

### 2. Why does it exist?
The number, diversity and representativeness of samples determine how reliably patterns can be learned and measured.

### 3. Detailed explanation
- **i.i.d. assumption (1.27):** most theory assumes samples are independent and identically distributed. It fails with time series, grouped users, duplicates and feedback loops.
- **Sample size effect (learning curve):** held-out accuracy of logistic regression on two Gaussian classes (average over 10 seeds): n=5 → 79.7%, n=20 → 88.9%, n=100 → 92.1%, n=400 → 92.4%. Returns diminish; model capacity and noise set the ceiling.
- **Representativeness beats quantity.** Millions of samples from the wrong population still give a model for the wrong population (sampling bias).
- **Coverage of rare cases:** rare events (fraud, failures) need enough positive samples; use stratification (2.10) and targeted collection.
- **Duplicates and near-duplicates** inflate counts and leak across splits.
- **Terminology note:** 'sample' in statistics can mean a *set* of observations; in ML it usually means one row. This book uses 'sample' for one row and 'dataset' for the collection.

### 4. How does it work?
Collect → validate each row (schema, ranges, missingness) → deduplicate → store with identifiers and timestamps → split.

### 5. Simple example
Each patient file in a clinical study.

### 6. Technical example
One training sample for an LLM is a tokenized sequence (or a prompt/response pair in fine-tuning).

### 8. Input → Process → Output
`event / entity → one row (x, y, id, time)`

### 9. Enterprise use case
Data contracts define what a valid row is; sampling plans ensure coverage of segments, regions and time.

### 10. AI engineering connection
Prompt/response pairs, retrieved passages, conversation turns and tool traces are all 'samples' for evaluation and fine-tuning datasets.

### 11. Advantages
Simple unit to count, weight, audit and trace.

### 12. Limitations
A sample may not be independent or representative; one row may hide a group structure.

### 13. Trade-offs
Collect more vs collect better; labeling more rows vs improving features.

### 14. Common mistakes
Counting duplicates as independent samples; ignoring sampling bias; random-splitting grouped data; small-n conclusions from a single run.

### 15. Performance / cost
Sample count drives training cost; use learning curves to decide if more data is worth it.

### 16. Security
Each sample may contain personal data: minimize, anonymize, set retention.

### 17. Interview explanation
"A sample is one row of data, an input and usually its label. More samples help with diminishing returns, but representativeness and independence matter more than raw count: duplicates and grouped data break the i.i.d. assumption and make evaluation optimistic."

### 18. Rapid-fire
