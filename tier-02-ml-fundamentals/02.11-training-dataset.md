# 2.11 Training dataset

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: High · Hands-on: Very high
Prerequisites: 2.10 · Leads to: 2.19 Gradient descent, 2.27 Overfitting, 2.47 Scaling

### 1. What is it?
The subset of data used to **fit the model's parameters**.

### 2. Why does it exist?
Learning requires examples; keeping them separate from evaluation data makes the measured performance honest.

### 3. Detailed explanation
- **Only the training set may influence fitted quantities:** weights, scaler means/variances, imputation medians, vocabulary, PCA directions, feature selection. Fit these on training data and *apply* them to validation/test (our `StandardScaler.fit` and `impute_median(X_train, X)` follow this).
- **Training error is optimistic.** It measures fit, not generalization (2.27, 2.31).
- **Augmentation, resampling and class weights apply to the training set only.** Never oversample before splitting (duplicates would leak into evaluation).
- **Size:** depends on model capacity and signal; use learning curves (2.9) to judge.
- **Typical split:** 60/20/20 or 80/10/10; for huge data a small percentage suffices for validation/test; for tiny data prefer cross-validation (2.44).
- **Shuffling:** shuffle each epoch for SGD (2.20) except where order matters (time series).

### 4. How does it work?
Fit scalers/encoders → train model by minimizing loss → monitor training loss (and validation loss) over epochs (2.22).

### 8. Input → Process → Output
`train split → fit preprocessing → fit model → trained parameters`

### 9. Enterprise use case
Training data snapshots are immutable and versioned so any model can be reproduced.

### 10. AI engineering connection
Pretraining corpora, instruction-tuning data, reward-model preference data are training datasets; decontaminate them against evaluation benchmarks.

### 11. Advantages
Direct learning signal; many tools to enlarge/augment it.

### 12. Limitations
Can be unrepresentative, noisy, duplicated; models memorize it if large relative to data.

### 13. Trade-offs
Larger training share improves the model but weakens validation/test precision.

### 14. Common mistakes
Fitting scalers on all data; oversampling before the split; training on validation/test 'just a bit'; changing the training set between experiments without recording.

### 15. Performance / cost
Data loading often limits GPU utilization; cache and parallelize.

### 16. Security
Training data can leak via memorization; apply deduplication and access controls.

### 17. Interview explanation
"The training set is what the model fits on — including any statistics like scaler means. I fit preprocessing on training data only, apply augmentation and resampling only there, and never judge the model on it, because training error is optimistic."

### 18. Rapid-fire
Training set fits parameters and preprocessing statistics; never used to judge generalization.
