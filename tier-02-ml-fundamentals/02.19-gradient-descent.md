# 2.19 Gradient descent

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: Very high · Hands-on: Very high
Prerequisites: 1.23, 2.17, 2.18 · Leads to: 2.20 SGD, 2.25 Learning rate, Tier 3 Backpropagation, Tier 4 Optimisers

> **In plain words**
> **Gradient descent** is how most models learn: **look at the slope of the error, take a small step downhill, and repeat.** Like walking down a hill in fog by always stepping in the steepest downhill direction you can feel.
> The size of each step is the **learning rate**. Too small and you crawl; too big and you overshoot and bounce around or fly off.

**You need first:** 1.23 Gradients and 2.17 Loss functions.

> **Figure 2.19-1 — the gradient-descent loop**
>
> ```mermaid
> flowchart LR
>     A["start: θ₀"] --> B["compute the gradient ∇J(θ)<br/>on the data"]
>     B --> C["step: θ ← θ − η·∇J"]
>     C --> D{"small enough change?<br/>or budget used up?"}
>     D -->|no| B
>     D -->|yes| E["done: θ*"]
> ```
>
> *How to read it:* every loop computes the slope, moves a little against it, and checks whether to stop. Everything else in training (SGD, momentum, Adam, backpropagation) is a refinement of *how the slope is estimated or used*, not of this loop.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| gradient `∇J` | the direction of steepest increase of the objective |
| learning rate `η` | the step size |
| full-batch GD | uses all examples to compute each gradient |
| convergence | the steps stop changing the answer |
| stationary point | where the gradient is zero |
| conditioning | how stretched the loss "valley" is (1.45) |
| early stopping | stop when validation loss stops improving |

### 1. What is it?
An iterative method that minimises an objective by repeatedly stepping against its gradient: `θ ← θ − η·∇J(θ)`, with learning rate `η` (2.25).

### 2. Why does it exist?
Closed-form solutions exist only for simple models. Gradient descent works for **any differentiable model**, including networks with billions of parameters.

### 3. Detailed explanation
- **Intuition:** the gradient (1.23) points uphill; stepping the other way lowers `J` for a small enough `η`.
- **Full-batch ("vanilla") gradient descent** uses all `n` examples for every gradient: exact, but one update per pass over the data, which is expensive for big data.
- **Convex case:** on linear regression, gradient descent converges to the closed-form least-squares answer, with the loss decreasing steadily.
- **Non-convex case (neural networks):** it reaches a stationary point that may be a saddle or a local minimum (1.46, 1.47); good initialisation and noise help.
- **Conditioning:** the speed depends on how stretched the loss valley is (the Hessian's condition number). Unscaled features create narrow valleys and force a tiny learning rate (2.25, 2.47).
- **Stopping rules:** gradient norm small, loss change small, a fixed budget of iterations, or validation loss stops improving (early stopping, 2.12).
- **Variants** (SGD 2.20; momentum and Adam in Tier 4) change how the gradient is estimated or used, not the basic idea.
- **Gradient checking** with finite differences validates an implementation (1.21, 1.25).

### 4. How does it work?
Initialise `θ` → compute the gradient of the objective on the data → update → check the stopping rule → repeat.

### 5. Simple example
Walking downhill in fog by always taking a small step in the steepest downward direction.

**By hand.** Minimise `J(w) = (w − 3)²` starting at `w = 0` with `η = 0.1`. The gradient is `2(w − 3)`.

| Step | `w` | gradient `2(w − 3)` | new `w = w − 0.1·gradient` |
|---|---|---|---|
| 0 | 0 | −6 | 0.6 |
| 1 | 0.6 | −4.8 | 1.08 |
| 2 | 1.08 | −3.84 | 1.464 |
| 3 | 1.464 | −3.07 | 1.771 |

Each step covers 20% of the remaining distance, so `w` creeps toward 3.

### 6. Technical example
Fitting a logistic regression with many iterations of gradient descent gives (almost) the unpenalised library solution; training a neural network is the same loop, with backpropagation providing the gradients.

### 7. Code
**① By hand (plain Python).** Fit a line `y = w·x + b` by gradient descent.

```python
xs = [1.0, 2.0, 3.0, 4.0]
ys = [3.0, 5.0, 7.2, 8.8]
w, b, lr = 0.0, 0.0, 0.05
for step in range(1, 2001):
    dw = sum(2 * (w * x + b - y) * x for x, y in zip(xs, ys)) / len(xs)        # gradient of the mean squared error
    db = sum(2 * (w * x + b - y) for x, y in zip(xs, ys)) / len(xs)
    w, b = w - lr * dw, b - lr * db
    if step in (1, 10, 100, 2000):
        loss = sum((w * x + b - y) ** 2 for x, y in zip(xs, ys)) / len(xs)
        print(f"step {step:>4}: w = {w:.4f}  b = {b:.4f}  loss = {loss:.4f}")
print("closed-form answer from 2.15: w = 1.96, b = 1.1")
```

```text
step    1: w = 1.7450  b = 0.6000  loss = 1.1522
step   10: w = 2.0736  b = 0.7660  loss = 0.0366
step  100: w = 1.9892  b = 1.0140  loss = 0.0192
step 2000: w = 1.9600  b = 1.1000  loss = 0.0180
closed-form answer from 2.15: w = 1.96, b = 1.1
```

**② With NumPy.** Gradient descent reaches the least-squares answer.

```python
import numpy as np

rng = np.random.default_rng(0)
X = rng.normal(0, 1, (300, 2))
y = 2 * X[:, 0] - X[:, 1] + 0.5 + rng.normal(0, 0.3, 300)
A = np.column_stack([X, np.ones(300)])
theta = np.zeros(3)
for _ in range(300):
    theta -= 0.1 * (2 / len(A)) * A.T @ (A @ theta - y)                  # full-batch gradient step
exact, *_ = np.linalg.lstsq(A, y, rcond=None)
print("gradient descent:", theta.round(4))
print("least squares   :", exact.round(4))
```

```text
gradient descent: [ 2.007  -0.9909  0.4921]
least squares   : [ 2.007  -0.9909  0.4921]
```

**③ With PyTorch.** The same loop with automatic gradients.

```python
import torch

torch.manual_seed(0)
X = torch.randn(300, 2)
y = 2 * X[:, 0] - X[:, 1] + 0.5 + 0.3 * torch.randn(300)
model = torch.nn.Linear(2, 1)
opt = torch.optim.SGD(model.parameters(), lr=0.1)               # here every step uses ALL the data = gradient descent
for step in range(300):
    opt.zero_grad()
    loss = torch.nn.functional.mse_loss(model(X).squeeze(1), y)
    loss.backward()
    opt.step()
print("weights:", [round(v, 3) for v in model.weight.flatten().tolist()], " bias:", round(model.bias.item(), 3), " loss:", round(loss.item(), 4))
```

```text
weights: [1.967, -0.963]  bias: 0.501  loss: 0.0967
```

### 8. Input → Process → Output
`θ₀ → ∇J(θₜ) → θₜ₊₁ = θₜ − η∇J → … → θ*`

<summary><b>Beyond the basics (sections 9–16)</b> — real-world use, limits, mistakes. Skip on a first read.</summary>

### 9. Enterprise use case
Training jobs are long-running gradient-descent loops with checkpoints, monitoring of loss and gradient norm, and automatic restarts.

### 10. AI engineering connection
All neural-network training: the forward pass computes `J`, backpropagation computes `∇J`, and the optimiser applies the update (Tiers 3–4).

### 11. Advantages
General, scalable and simple; works with any differentiable objective.

### 12. Limitations
Finds only stationary points; sensitive to the learning rate and scaling; the full-batch cost grows with the data.

### 13. Trade-offs
Exact gradients (stable, slow per step) versus cheaper, noisy gradients (2.20).

### 14. Common mistakes
A learning rate that is too large; unscaled features; a wrong gradient sign; not zeroing accumulated gradients; stopping on training loss only.

### 15. Performance / cost
The cost per step is proportional to the dataset size (full batch), which is why mini-batches dominate in practice.

### 16. Security
Gradients can leak training data in distributed or federated settings; clip them and add noise for privacy.

</details>

### 17. Interview explanation
"Gradient descent minimises the objective by repeatedly stepping against its gradient, scaled by the learning rate. On convex problems like linear regression it converges to the closed-form answer; on neural networks it finds good stationary points. Scaling the features and choosing the learning rate decide whether it converges quickly or not at all."

### 18. Rapid-fire answer
`θ ← θ − η∇J`; converges to least squares on linear regression; speed depends on conditioning and `η`.

### 20. Hands-on exercise
**Goal:** see how feature scaling changes the number of steps.

1. Fit `y = 3·x₁ + 2·x₂` where `x₁` is in the range 0–1 and `x₂` in the range 0–1000.
2. Run gradient descent with a fixed learning rate small enough not to diverge, until the loss is below `0.01` (cap at 20,000 steps). Count steps.
3. Repeat after standardising both features.

<details>
<summary>Show a solution</summary>

```python
import numpy as np

rng = np.random.default_rng(0)
X = np.column_stack([rng.uniform(0, 1, 200), rng.uniform(0, 1000, 200)])
y = 3 * X[:, 0] + 2 * X[:, 1]

def steps_needed(X, y, lr):
    w = np.zeros(X.shape[1])
    for step in range(1, 20001):
        w -= lr * (2 / len(X)) * X.T @ (X @ w - y)
        if np.mean((X @ w - y) ** 2) < 0.01:
            return step
    return ">20000 (did not reach it)"

# for the raw features the learning rate must be tiny (about 1/largest curvature) or the steps explode
print("raw features     :", steps_needed(X, y, lr=1e-7))
Z = (X - X.mean(axis=0)) / X.std(axis=0)
yc = y - y.mean()
print("standardised     :", steps_needed(Z, yc, lr=0.1))
```

```text
raw features     : >20000 (did not reach it)
standardised     : 40
```

On badly scaled features the learning rate has to be tiny to stay stable, so progress along the small-scale direction is painfully slow.
</details>
