# 2.42 Confusion matrix

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: Very high · Hands-on: Very high
Prerequisites: 2.14 · Leads to: 2.37–2.41, 2.51, error analysis

### 1. What is it?
A table counting predictions against truth. For binary: `[[TN, FP], [FN, TP]]`; for K classes: a `K×K` matrix with `cm[i, j]` = samples of true class `i` predicted as `j`.

### 2. Why does it exist?
All threshold-based classification metrics derive from it, and it shows *which* errors occur, not only how many.

### 3. Detailed explanation
- **Derived metrics:** accuracy `(TP+TN)/N`, precision `TP/(TP+FP)`, recall `TP/(TP+FN)`, specificity `TN/(TN+FP)`, FPR `FP/(FP+TN)`, F1 `2TP/(2TP+FP+FN)`.
- **Convention warning:** libraries differ in orientation (rows = true vs rows = predicted). Ours and scikit-learn's: rows are true classes, columns predicted. State it on every printed matrix.
- **Normalization:** normalize by row (true class) to see recall per class, by column to see precision, by total for joint frequencies.
- **Multiclass error analysis:** off-diagonal cells reveal confusable class pairs (e.g., 'refund' vs 'cancellation'), guiding label cleaning, features or data collection. Per-class precision/recall come from the diagonal and row/column sums.
- **Cost-sensitive evaluation:** multiply by a cost matrix and sum. Example (20% positives, miss costs 10, false alarm 1): `cm = [[2359, 56], [95, 490]]` → expected cost 0.335 per sample (`(56 + 10·95)/3000`).
- **Threshold-dependent:** a different threshold gives a different matrix; plot the matrix at the operating point actually used.
- **Counts vs rates:** report counts too; percentages hide small sample sizes.
- **Beyond classification:** the same idea underlies tool-selection matrices for agents, retrieval hit/miss tables, and moderation outcome tables.

### 4. How does it work?
Loop over examples and increment `cm[true, pred]` (vectorized with `np.add.at`).

### 8. Input → Process → Output
`(y_true, y_pred) → counts per (true, pred) pair`

### 9. Enterprise use case
Review boards want the matrix at the production threshold with costs; QA uses it to prioritize labeling fixes.

### 10. AI engineering connection
Used for intent routing, guardrail decisions, tool-call correctness, retrieval hit/miss, LLM-judge agreement with humans.

### 11. Advantages
Complete, transparent, source of most metrics.

### 12. Limitations
Threshold-dependent; large for many classes; ignores confidence.

### 13. Trade-offs
Detail vs readability for many classes (use top confusions or normalized heatmaps).

### 14. Common mistakes
Mixed row/column orientation; unnormalized matrices on imbalanced data; interpreting off-diagonals without sample sizes; evaluating on the training set.

### 15. Performance / cost
`O(n)` to build; `O(K²)` memory.

### 16. Security
Reveals where attackers can induce misclassification; monitor off-diagonals for safety classes.

### 17. Interview explanation
"The confusion matrix counts predictions against truth — TP, FP, FN, TN for binary — and every threshold-based metric comes from it. I check its orientation, look at row-normalized rates for recall, and use the off-diagonal cells in multiclass problems to find which classes get confused so I can fix labels or features."
