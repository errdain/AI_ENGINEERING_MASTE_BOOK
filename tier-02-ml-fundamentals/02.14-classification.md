# 2.14 Classification

### 1. What is it?
Supervised learning where the target `y` is a **discrete category**: binary (spam / not spam), multiclass (one of K), or multilabel (several can be true).

### 2. Why does it exist?
Many decisions are choices among categories: approve/deny, route to a team, detect an object type. Classification turns evidence into a category or a probability for each category.

### 3. Detailed explanation
- **Output forms:** a hard class, a score, or a probability vector. Binary models usually output `p = σ(z)` (sigmoid of a logit); multiclass models output `softmax(z)` (1.42, 1.43), a categorical distribution that sums to 1.
- **Training objective:** cross-entropy / negative log-likelihood (1.35, 1.37), whose gradient with respect to the logits is `softmax(z) − onehot(y)`.
- **Decision rule:** predict `argmax` class, or for binary tasks compare `p` with a **threshold**. 0.5 is a default, not a law. If a missed positive costs 5× a false alarm, the best threshold moves down: in the lab, cost 48 at 0.5 falls to 27 at 0.1.
- **Decision boundary:** logistic/softmax regression has linear boundaries in feature space; engineered features or neural nets give curved boundaries (2.1, XOR example).
- **Multiclass vs multilabel:** softmax forces classes to compete; multilabel uses independent sigmoids.
- **Probabilities are only useful if calibrated** (2.43). A high score is not a guaranteed probability.
- **Demonstration (3 Gaussian classes, 600 train / 300 test):** softmax regression reaches 99.7% test accuracy (chance 33%) and its probabilities sum to 1.
- Worked-example model in this book: logistic regression (`mlkit.LogisticRegression`), verified against scikit-learn.

### 4. How does it work?
Features → linear (or deep) scores per class → softmax/sigmoid → probabilities → threshold or argmax → decision, evaluated with the metrics in 2.37–2.42.

### 5. Simple example
A sorting hat: look at features, pick a house; the 'confidence' tells how close the call was.

### 6. Technical example
Intent classification for customer messages with 12 intents; a guardrail classifier labeling outputs as safe/unsafe; the output layer of an LLM is a classifier over the vocabulary (next-token prediction).

### 8. Input → Process → Output
`x → logits z → softmax / sigmoid → p(class | x) → threshold / argmax → label`

### 9. Enterprise use case
Classification powers routing, triage, moderation, fraud flags and eligibility checks, usually with human review for borderline scores and thresholds set from business costs.

### 10. AI engineering connection
Intent routers, guardrail classifiers (Tier 32), rerankers (Tier 21), LLM-as-judge verdicts and the LLM's own next-token distribution are classification problems.

### 11. Advantages
Well-understood losses and metrics; probabilistic outputs support cost-based decisions.

### 12. Limitations
Requires labeled categories; fixed label set; poor on out-of-distribution inputs; scores need calibration.

### 13. Trade-offs
Hard labels are simple but throw away uncertainty; probabilities enable thresholds and abstention but need calibration.

### 14. Common mistakes
Using accuracy on imbalanced data (2.45); default 0.5 threshold; softmax on multilabel problems; ignoring 'none of the above'; reading scores as calibrated probabilities.

### 15. Performance / cost
Inference is cheap for linear models; large vocabularies make softmax expensive (cost ∝ number of classes).

### 16. Security
Adversarial inputs can flip classes; classifiers used as safety filters need red-teaming; thresholds are policy decisions.

### 17. Interview explanation
"Classification predicts a category. The model outputs logits, softmax or sigmoid turns them into probabilities, and I train with cross-entropy. The decision threshold should come from the cost of each error, not default to 0.5, and I check calibration before trusting the probabilities."

### 18. Rapid-fire
Predict a discrete class via logits → softmax/sigmoid; train with cross-entropy; set the threshold by cost.
