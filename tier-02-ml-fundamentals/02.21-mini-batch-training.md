# 2.21 Mini-batch training

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: High · Hands-on: Very high
Prerequisites: 2.20 · Leads to: 2.22–2.24 Epoch/batch/iteration, Tier 4 Batch size (4.13) and gradient accumulation (4.14)

### 1. What is it?
Updating parameters using the average gradient of a **small group (mini-batch) of samples**, typically 16–4096, rather than one sample or the whole dataset.

### 2. Why does it exist?
It balances gradient noise against computation, and fits hardware: GPUs process batches in parallel far more efficiently than single samples.

### 3. Detailed explanation
- **Gradient estimate:** `g_B = (1/B) Σ_{i∈B} ∇ℓᵢ`, unbiased, with variance ≈ `σ²/B`.
- **Trade-offs:**
  - Small B: many noisy updates per epoch, low memory per step, regularizing noise, poor hardware utilization.
  - Large B: smooth gradient, parallel efficiency, but fewer updates per epoch and often needs a larger learning rate/warmup and can generalize worse if increased naively.
- **Diminishing returns:** once the gradient noise is small relative to the true gradient, a bigger batch adds cost without proportional benefit.
- **Memory:** activation memory grows linearly with B. Gradient accumulation simulates a large batch by summing gradients over several small ones (Tier 4, 4.14).
- **Last partial batch:** with `n=1050`, `B=100` an epoch has 10 full batches plus one of 50 (11 iterations); `drop_last=True` discards the partial batch (10 iterations).
- **Batch composition:** random shuffling, stratification for rare classes, bucketing by length for sequences (padding waste).
- **Batch normalization** couples samples in a batch (Tier 3, 3.30): batch size then affects model behaviour, not only optimization.
- **Learning-rate coupling:** a common heuristic scales the learning rate with batch size (linear or square-root scaling); treat as a starting point to tune.

### 4. How does it work?
Shuffle indices → slice into batches → for each batch compute loss, gradient, update → repeat each epoch.

### 5. Simple example
Polling 32 people at a time instead of one or the whole town.

### 6. Technical example
Fine-tuning with batch size 32, sequences padded per batch; pretraining with a global batch of millions of tokens across many GPUs.

### 7. Code
```python
import numpy as np, mlkit as M
sizes = [len(b) for b in M.minibatches(1050, 100, np.random.default_rng(0))]
print(sizes, M.iterations_per_epoch(1050, 100), M.iterations_per_epoch(1050, 100, drop_last=True))   # [100]*10+[50] 11 10
```

### 8. Input → Process → Output
`dataset → shuffle → batches of B → one update per batch`

### 9. Enterprise use case
Batch size drives throughput, cost and memory; teams tune it against GPU utilization and convergence.

### 10. AI engineering connection
Token-based batch sizes in LLM training; per-device vs global batch; micro-batches in pipeline parallelism (Tier 4, 4.30–4.34).

### 11. Advantages
Efficient hardware use; tunable noise; standard practice.

### 12. Limitations
Extra hyperparameter coupled with the learning rate; batch-dependent layers; memory limits.

### 13. Trade-offs
Throughput and stability vs generalization and update frequency.

### 14. Common mistakes
Changing batch size without retuning the learning rate; evaluating with a different batch size and BatchNorm in train mode; dropping data silently with drop_last; unshuffled data ordered by class.

### 15. Performance / cost
GPU utilization usually rises with B until memory or bandwidth saturates; profile.

### 16. Security
Batches built from mixed tenants can leak information via batch-dependent layers; avoid cross-tenant batches in training on private data.

### 17. Interview explanation
"Mini-batch training averages the gradient over a small group of samples, giving an unbiased estimate with variance falling like one over B, and it uses GPUs efficiently. I tune batch size against memory and throughput, retune the learning rate when I change it, and use gradient accumulation if memory is the limit."

### 18. Rapid-fire
Average gradient over B samples: variance ~1/B, parallel efficient; retune LR when B changes.
