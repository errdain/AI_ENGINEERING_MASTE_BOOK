# 2.32 Regularisation

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: Very high · Hands-on: Very high
Prerequisites: 2.18, 2.27, 1.15 · Leads to: Tier 3 Dropout (3.28) and Weight decay (3.29), Tier 10 Fine-tuning

> **In plain words**
> **Regularisation** is anything that **stops a model from becoming too complicated**, so it overfits less. The most common kind adds a **penalty on large weights** to the training objective: "fit the data, but keep your weights small".
> Two flavours: **L2 (ridge)** shrinks all weights gently; **L1 (lasso)** pushes some weights to **exactly zero**, which switches features off. Like telling a student to answer briefly: less room to ramble into noise.

**You need first:** 2.18 Objective functions, 2.27 Overfitting, 1.15 Norms.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| regularisation | any technique that limits effective complexity |
| L2 / ridge / weight decay | penalty `λ‖w‖₂²` |
| L1 / lasso | penalty `α‖w‖₁` |
| sparsity | many weights exactly zero |
| dropout | randomly switching off units during training (Tier 3) |
| augmentation | adding modified copies of training examples |
| `λ`, `α` | strength of the penalty |

### 1. What is it?
Any technique that **reduces overfitting by constraining the model's effective complexity**: penalty terms, early stopping, dropout, data augmentation, ensembling, parameter sharing.

### 2. Why does it exist?
Flexible models fit noise. Regularisation trades a little bias for a large reduction in variance (2.30).

### 3. Detailed explanation
- **L2 / ridge / weight decay:** objective `J = loss + λ‖w‖₂²` (2.18). Shrinks all weights smoothly. Equivalent to a Gaussian prior on the weights (1.34).
- **L1 / lasso:** `J = loss + α‖w‖₁`. Produces **exactly zero** weights (feature selection) because of the sharp corner of the L1 shape at zero (1.15).
- **A U-shape in `λ`:** too little penalty overfits, too much underfits. Choose `λ` on validation data (2.36). For a degree-15 polynomial fitted to 30 noisy points, a tiny `λ` rescues a hopeless validation error and a huge `λ` flattens the curve again.
- **Sparsity:** with 10 features of which only 2 matter, lasso keeps exactly those two; ridge keeps all 10 non-zero (small "noise" coefficients).
- **Scale the features first.** Penalties act on coefficient size, which depends on feature scale (2.47). Never penalise the intercept.
- **Other regularisers:** **early stopping** (2.27, an implicit regulariser), **dropout** (randomly removes units), **data augmentation** (label-preserving variants), **ensembling or bagging** (averages variance away), **label smoothing** (softens targets).
- **The strength `λ`** belongs to the objective (2.18) and is tuned like any hyper-parameter (2.35).
- **Weight decay versus L2 in adaptive optimisers (Adam):** not identical; AdamW decouples them (Tier 4, 4.9). REVIEW_REQUIRED against current documentation.

### 4. How does it work?
Add the penalty to the objective (or change the training procedure), tune its strength on validation data, retrain on train + validation, evaluate once on the test set.

### 5. Simple example
Telling a student to answer briefly: there is less room to ramble into noise.

**How lasso zeroes a weight, by hand.** Suppose the data alone suggests a weight `z`. With penalty `α`, the lasso answer is the **soft-threshold**: `w = sign(z)·max(|z| − α, 0)`.

| data suggests `z` | `α = 0.5` gives | what happened |
|---|---|---|
| 2.0 | 1.5 | shrunk by 0.5 |
| 0.4 | 0 | a small weight is erased entirely |
| −1.2 | −0.7 | shrunk toward 0 |

Ridge would instead scale every weight by the same factor (`z/(1 + λ)`), never exactly to zero.

### 6. Technical example
LLM fine-tuning with weight decay 0.01, dropout in adapters, and early stopping on validation loss.

### 7. Code
**① By hand (plain Python).** Ridge shrinks, lasso soft-thresholds.

```python
def ridge(z, lam):   return z / (1 + lam)
def lasso(z, alpha): return (abs(z) - alpha if abs(z) > alpha else 0.0) * (1 if z > 0 else -1)

for z in (2.0, 0.4, -1.2):
    print(f"data suggests {z:+.1f}:  ridge(lam=1) -> {ridge(z, 1):+.2f}   lasso(alpha=0.5) -> {lasso(z, 0.5):+.2f}")
```

```text
data suggests +2.0:  ridge(lam=1) -> +1.00   lasso(alpha=0.5) -> +1.50
data suggests +0.4:  ridge(lam=1) -> +0.20   lasso(alpha=0.5) -> +0.00
data suggests -1.2:  ridge(lam=1) -> -0.60   lasso(alpha=0.5) -> -0.70
```

**② With NumPy.** A ridge path: coefficients against `λ`.

```python
import numpy as np

rng = np.random.default_rng(0)
X = rng.normal(0, 1, (100, 8))
y = 3 * X[:, 0] - 2 * X[:, 1] + 1.2 * X[:, 2] + rng.normal(0, 1, 100)          # only 3 features matter
Xc, yc = X - X.mean(axis=0), y - y.mean()
print("lambda   first three (true) weights          largest noise weight")
for lam in (0, 10, 100, 1000, 10000):
    w = np.linalg.solve(Xc.T @ Xc + lam * np.eye(8), Xc.T @ yc)
    print(f"{lam:>6}   {np.round(w[:3], 2)}   {np.abs(w[3:]).max():.3f}")
```

```text
lambda   first three (true) weights          largest noise weight
     0   [ 2.87 -1.93  1.15]   0.127
    10   [ 2.54 -1.71  1.  ]   0.149
   100   [ 1.25 -0.87  0.49]   0.192
  1000   [ 0.21 -0.15  0.09]   0.052
 10000   [ 0.02 -0.02  0.01]   0.006
```

**③ With scikit-learn.** Lasso selects features; ridge keeps them all.

```python
import numpy as np
from sklearn.linear_model import Lasso, Ridge

rng = np.random.default_rng(1)
X = rng.normal(0, 1, (100, 10))
y = 3 * X[:, 0] - 2 * X[:, 1] + rng.normal(0, 1, 100)                              # only features 0 and 1 matter
lasso = Lasso(alpha=0.3).fit(X, y)
ridge = Ridge(alpha=10).fit(X, y)
print("lasso keeps features:", np.flatnonzero(lasso.coef_).tolist())
print("ridge: number of non-zero weights:", int((np.abs(ridge.coef_) > 1e-12).sum()), "of 10; largest 'noise' weight:", round(float(np.abs(ridge.coef_[2:]).max()), 3))
```

```text
lasso keeps features: [0, 1]
ridge: number of non-zero weights: 10 of 10; largest 'noise' weight: 0.173
```

### 8. Input → Process → Output
`complex model + penalty → smaller effective capacity → lower variance`

### 9. Enterprise use case
Regularised baselines are standard in regulated settings because they are stable and auditable.

### 10. AI engineering connection
Weight decay, dropout, LoRA rank limits, early stopping, label smoothing, data augmentation and KL penalties to a reference model (1.38) all regularise.

### 11. Advantages
Cheap, general, and often the highest-return fix for overfitting.

### 12. Limitations
Introduces bias and a new hyper-parameter; the effect depends on feature scaling and the optimiser.

### 13. Trade-offs
Strength `λ`: more shrinkage means more bias and less variance.

### 14. Common mistakes
Not standardising features; tuning `λ` on the test set; penalising the bias term; using L1 and expecting stability with correlated features; assuming weight decay equals L2 for every optimiser.

### 15. Performance / cost
Penalties are almost free; searching `λ` costs training runs.

### 16. Security
Regularisation reduces memorisation, which helps privacy, but gives no formal guarantee (use differential privacy for that).

### 20. Hands-on exercise
**Goal:** find the best ridge strength with a validation set (the U-shape).

1. Fit a degree-15 polynomial (standardised features) with ridge to 30 noisy sine points.
2. Try `α` from 1e-8 to 10 and compute the validation error on 500 new points.
3. Which `α` is best, and what happens at both ends?

<details>
<summary>Show a solution</summary>

```python
import numpy as np
from sklearn.linear_model import Ridge
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures, StandardScaler

rng = np.random.default_rng(1)
f = lambda x: np.sin(np.pi * x)
x, xv = rng.uniform(-1, 1, (30, 1)), rng.uniform(-1, 1, (500, 1))
y, yv = f(x[:, 0]) + rng.normal(0, 0.2, 30), f(xv[:, 0]) + rng.normal(0, 0.2, 500)
for alpha in (1e-8, 1e-6, 1e-4, 1e-2, 1e-1, 1, 10):
    model = make_pipeline(PolynomialFeatures(15), StandardScaler(), Ridge(alpha=alpha)).fit(x, y)
    print(f"alpha {alpha:<8}: validation MSE {np.mean((model.predict(xv) - yv) ** 2):.3f}")
```

```text
alpha 1e-08   : validation MSE 48.544
alpha 1e-06   : validation MSE 2.171
alpha 0.0001  : validation MSE 0.342
alpha 0.01    : validation MSE 0.056
alpha 0.1     : validation MSE 0.054
alpha 1       : validation MSE 0.078
alpha 10      : validation MSE 0.191
```
