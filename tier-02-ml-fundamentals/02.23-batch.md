> **In plain words**
> A **batch** is **a group of examples processed together** in one step. The number of examples in it is the **batch size**.
> Like baking a tray of cookies together instead of one by one. Batching makes hardware efficient and averages out noise. Beware: the word is used in several ways (below), so always check which one is meant.

**You need first:** 2.21 Mini-batch and 2.22 Epoch; tensors (1.4) help.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| batch | the examples processed together in one step |
| batch size `B` | how many examples per batch |
| full batch | all `n` examples (batch gradient descent) |
| micro-batch | what fits on one device at a time |
| global (effective) batch | micro-batch × accumulation steps × devices |
| padding / mask | filling short sequences to a common length and ignoring the filler |
| continuous batching | serving many requests together as they arrive (Tier 11) |

### 1. What is it?
A **group of examples processed together** in one forward/backward pass. Its size is the *batch size* `B`.

### 2. Why does it exist?
Batching uses parallel hardware efficiently and averages out gradient noise.

### 3. Detailed explanation
- **An overloaded word.** "Batch gradient descent" means `B = n` (all the data); "mini-batch" means `1 < B < n`; many libraries say "batch" when they mean mini-batch. In this book: **batch** = the group of examples in one step; **full batch** = the entire dataset.
- **Shapes:** a batch of 32 sequences of 128 tokens with width 768 is a tensor `(32, 128, 768)` (1.4). The first axis is the batch axis.
- **Kinds of batch size:** per-device (micro) batch, gradient-accumulation steps, and the **global (effective) batch** = micro-batch × accumulation × data-parallel replicas.
- **Variable lengths:** pad to a common length and keep a mask, or group by length; padding wastes compute.
- **Not the same as "batch processing"** in data engineering (Tier 38): processing data in bulk offline is a different use of the word.
- **Inference batching:** serving systems batch concurrent requests (dynamic or continuous batching, Tier 11) to raise throughput at some cost in latency.

### 4. How does it work?
Pick `B` example indices → gather the features and labels → stack them into tensors → run forward and backward once.

### 5. Simple example
A tray of cookies baked together instead of one by one.

**Global batch, by hand.** 8 GPUs × micro-batch 16 × 8 accumulation steps = **1,024** examples per optimiser update. Only this global number determines the optimisation behaviour; the micro-batch just fits the memory.

### 6. Technical example
A global batch of 1,024 sequences = 8 GPUs × micro-batch 16 × 8 accumulation steps.

### 7. Code
**① By hand (plain Python).** Gather rows into a batch.

```python
data = [(i, i * 10) for i in range(10)]                  # 10 (x, y) examples
batch_indices = [3, 7, 1, 9]
x_batch = [data[i][0] for i in batch_indices]
y_batch = [data[i][1] for i in batch_indices]
print("batch x:", x_batch, " batch y:", y_batch, " batch size:", len(batch_indices))
print("global batch for 4 GPUs, micro-batch 8, accumulation 4:", 4 * 8 * 4)
```

```text
batch x: [3, 7, 1, 9]  batch y: [30, 70, 10, 90]  batch size: 4
global batch for 4 GPUs, micro-batch 8, accumulation 4: 128
```

**② With NumPy.** The batch axis, and reducing over the right axis.

```python
import numpy as np

batch = np.random.default_rng(0).normal(0, 1, (32, 128, 768))      # (batch, sequence, features)
print("shape:", batch.shape, " batch size:", batch.shape[0])
print("one example's tokens:", batch[5].shape)
print("mean over the sequence axis, per example:", batch.mean(axis=1).shape)
print("a per-example loss would have shape:", batch.mean(axis=(1, 2)).shape, "-> averaged over the batch axis it becomes one number")
```

```text
shape: (32, 128, 768)  batch size: 32
one example's tokens: (128, 768)
mean over the sequence axis, per example: (32, 768)
a per-example loss would have shape: (32,) -> averaged over the batch axis it becomes one number
```

**③ With PyTorch.** Variable-length sequences: pad and mask.

```python
import torch
from torch.nn.utils.rnn import pad_sequence

seqs = [torch.tensor([1, 2, 3]), torch.tensor([4, 5]), torch.tensor([6, 7, 8, 9])]
batch = pad_sequence(seqs, batch_first=True, padding_value=0)       # shape (batch, longest length)
mask = torch.tensor([[1] * len(s) + [0] * (batch.shape[1] - len(s)) for s in seqs])
print(batch)
print("mask (1 = real token, 0 = padding):\n", mask)
print("wasted slots:", int((mask == 0).sum()), "of", mask.numel())
```

```text
tensor([[1, 2, 3, 0],
        [4, 5, 0, 0],
        [6, 7, 8, 9]])
mask (1 = real token, 0 = padding):
 tensor([[1, 1, 1, 0],
        [1, 1, 0, 0],
        [1, 1, 1, 1]])
wasted slots: 3 of 12
```

### 9. Enterprise use case
Batch size is the main throughput and cost lever in both training and serving.

### 10. AI engineering connection
Micro-batch versus global batch in distributed training; continuous batching in LLM serving (Tier 11); batch embedding of documents for indexing (Tier 20).

### 11. Advantages
Hardware efficiency.

### 12. Limitations
Memory grows with `B`; latency rises for batched serving.

### 13. Trade-offs
Throughput versus latency (inference); noise versus memory (training).

### 14. Common mistakes
Mixing the meanings of "batch"; forgetting the batch axis in reductions (1.6); padding without masks; reporting the per-device batch as the global one.

### 15. Performance / cost
Choose `B` to saturate the accelerator without running out of memory; profile throughput against `B`.

### 16. Security
Batched serving can leak across requests through shared state or caches; isolate per-tenant data.

### 20. Hands-on exercise
**Goal:** keep an effective batch of 64 with only 16 examples in memory.

1. Using PyTorch, take a linear model and 64 random examples.
2. Compute the gradient in one go on all 64.
3. Then compute it with **4 accumulation steps of 16**, each divided by 4, accumulating before the optimiser step. Compare the two gradients.

<details>
<summary>Show a solution</summary>

```python
import torch

torch.manual_seed(0)
X, y = torch.randn(64, 3), torch.randn(64)
w = torch.zeros(3, requires_grad=True)

((X @ w - y) ** 2).mean().backward()                     # one pass over all 64
full = w.grad.clone()
w.grad = None

for chunk in range(4):                                   # four micro-batches of 16
    xb, yb = X[chunk * 16:(chunk + 1) * 16], y[chunk * 16:(chunk + 1) * 16]
    (((xb @ w - yb) ** 2).mean() / 4).backward()         # divide by 4 so the pieces average correctly
print("same gradient:", torch.allclose(full, w.grad, atol=1e-6))
```

```text
same gradient: True
```

</details>
