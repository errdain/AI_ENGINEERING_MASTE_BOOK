# 2.23 Batch

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: Medium · Hands-on: Very high
Prerequisites: 2.21, 2.22 · Leads to: 2.24 Iteration, Tier 4 Batch size, gradient accumulation

### 1. What is it?
A **group of samples processed together** in one forward/backward pass. Its size is the *batch size* `B`.

### 2. Why does it exist?
Batching exploits parallel hardware and averages gradient noise.

### 3. Detailed explanation
- **Overloaded word.** 'Batch gradient descent' means B = n (all data); 'mini-batch' means 1 < B < n; many libraries say 'batch' for mini-batch. This book: **batch** = the group of samples in one step; **full batch** = the entire dataset.
- **Shapes:** a batch of 32 sequences of 128 tokens with `d_model = 768` is a tensor `(32, 128, 768)` (1.4). The first axis is the batch axis.
- **Types of batch size:** per-device (micro) batch, gradient-accumulation steps, and **global/effective batch** = micro-batch × accumulation × data-parallel replicas.
- **Variable lengths:** pad to a common length with a mask or bucket by length; padding wastes compute.
- **Batch ≠ batch processing in data engineering** (Tier 38): the offline processing of data in bulk is a different use of the word.
- **Inference batching:** serving systems batch concurrent requests (dynamic or continuous batching, Tier 11) to raise throughput at some latency cost.

### 4. How does it work?
Select B sample indices → gather features/labels → stack into tensors → run forward/backward once.

### 5. Simple example
A tray of cookies baked together instead of one by one.

### 6. Technical example
Global batch 1,024 sequences = 8 GPUs × micro-batch 16 × 8 accumulation steps.

### 7. Code
```python
import numpy as np, mlkit as M
batches = list(M.minibatches(10, 4, np.random.default_rng(0)))
print([b.tolist() for b in batches])         # three batches of sizes 4, 4, 2 covering indices 0..9 once
```

### 8. Input → Process → Output
`B samples → stacked tensors → one forward/backward`

### 9. Enterprise use case
Batch size is the main throughput/cost lever in both training and serving.

### 10. AI engineering connection
Micro-batch vs global batch in distributed training; continuous batching in LLM serving (Tier 11); batch embedding of documents for indexing (Tier 20).

### 11. Advantages
Hardware efficiency.

### 12. Limitations
Memory scales with B; latency rises for batched serving.

### 13. Trade-offs
Throughput vs latency (inference) and noise vs memory (training).

### 14. Common mistakes
Mixing the meanings of 'batch'; forgetting the batch axis in reductions (1.6); padding without masks; reporting per-device batch as global.

### 15. Performance / cost
Choose B to saturate the accelerator without OOM; profile throughput vs B.

### 16. Security
Batched serving can leak across requests through shared state or caches; isolate per-tenant data.

### 17. Interview explanation
"A batch is the group of samples processed together in one step. I distinguish micro-batch, accumulation steps and the global batch, since only the global batch determines the optimization behaviour, and I'm careful with the word 'batch' because it also means full-dataset gradient descent."

### 18. Rapid-fire
Batch = samples processed together per step; global batch = micro × accumulation × replicas.
