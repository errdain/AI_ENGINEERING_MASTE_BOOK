# 2.27 Overfitting

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: Very high · Hands-on: Very high
Prerequisites: 2.26, 2.12 · Leads to: 2.30 Bias–variance, 2.31 Generalization, 2.32 Regularization, 2.44 Cross-validation

### 1. What is it?
A model that **fits the training data (including its noise) too closely** and therefore performs worse on new data.

### 2. Why does it exist?
Training error alone rewards memorization. Knowing overfitting's signature and cures is central to every ML project.

### 3. Detailed explanation
- **Signature:** training error keeps falling while validation error stops improving and then rises. A large gap between them.
- **Polynomial demonstration (same data as 2.26):** degree 15 gets train MSE 0.016 (lowest of all) but validation MSE **23.5**, about 460× worse than degree 3 (0.051). Degrees 5 and 9 (validation 0.060, 0.056) are mildly worse than degree 3, showing the gradual transition.
- **Early stopping demonstration (30 samples, 60 features, noisy labels; gradient descent from zero):** validation MSE is lowest at epoch 61 (4.33); by epoch 3,000 the model interpolates the training set (train MSE → 10⁻¹²) and validation MSE has risen to 5.06. Early stopping on a validation set captures the best point.
- **Causes:** model capacity high relative to data (many parameters, few samples), noisy labels, too many features, training too long, repeated tuning on the same validation set (2.12), leakage that looks like skill (2.33).
- **Remedies (use in this order of effort):** more or better data and augmentation; simpler model; regularization (2.32); early stopping; dropout/weight decay (Tier 3); cross-validation to choose complexity (2.44); ensembling.
- **Modern nuance:** very large neural networks can fit training data perfectly and still generalize ("benign overfitting"/double descent). The classical U-shaped curve is a useful heuristic for small models and small data, not a universal law (REVIEW_REQUIRED: cite the double-descent literature).
- **Memorization in LLMs** is a form of overfitting with privacy implications (see 2.31, Tier 9).

### 4. How does it work?
Track train and validation metrics together at every epoch or complexity setting; the point where they diverge marks the onset.

### 5. Simple example
Memorizing the answers to last year's exam without understanding the subject.

### 6. Technical example
A decision threshold tuned on the same 200 validation items 500 times will look great there and worse in production.

### 7. Code

import mlkit as M
x, y = M.make_sine(30, 0.2, seed=1); xv, yv = M.make_sine(500, 0.2, seed=101)

### 8. Input → Process → Output
`high capacity + limited/noisy data → memorize noise → low train error, high validation error`

### 9. Enterprise use case
Release gates compare train vs validation vs test metrics and stop launches when the gap exceeds a threshold.

### 10. AI engineering connection
Fine-tuning LLMs on small datasets for too many epochs, prompt engineering tuned on a few examples, and RAG parameters tuned on one eval set are all overfitting risks.

### 11. Advantages
(Of detecting it) cheap and actionable via validation curves.

### 12. Limitations
A single validation set is noisy; heavy tuning overfits the validation set itself.

### 13. Trade-offs
Capacity and training time reduce bias but increase variance (2.30).

### 14. Common mistakes
Judging by training metrics; no held-out set; tuning on the test set; ignoring high variance across folds; equating a small gap with a good model (it can be underfit).

### 15. Performance / cost
Early stopping saves compute; heavy regularization sweeps cost compute.

### 16. Security
Overfit models memorize training records, enabling membership-inference and extraction attacks.

### 17. Interview explanation
"Overfitting is when the model learns the noise in the training set, so training error keeps dropping while validation error rises. I monitor both curves, use cross-validation and regularization, stop early, and prefer more or cleaner data. For very large networks I remember the classical U-shape isn't always the whole story, but I still validate on held-out data."

### 18. Rapid-fire
Overfit = train error ↓, validation error ↑; fix with data, simpler model, regularization, early stopping.

### 19. Interview questions

- Advanced: Why can heavy hyperparameter tuning overfit the validation set?
