> **In plain words**
> **Accuracy** is **the share of predictions that are correct**. 98 right out of 100 is 98%.
> It is the easiest metric to understand, and the easiest to be fooled by. If only 1% of cases are positive, a "model" that **always says negative** is 99% accurate and **finds nothing**. This is the **accuracy paradox**.

**You need first:** 2.14 Classification; the confusion matrix (2.42) helps.

> **Figure 2.37-1 — accuracy from the confusion matrix**
>
> ```mermaid
> flowchart LR
>     A["TP: predicted yes, truly yes"] --> N["correct"]
>     B["TN: predicted no, truly no"] --> N
>     C["FP: predicted yes, truly no"] --> W["wrong"]
>     D["FN: predicted no, truly yes"] --> W
>     N --> R["accuracy = (TP + TN) / all"]
>     W --> R
> ```
>
> *How to read it:* accuracy counts the two kinds of correct answers over all answers. It treats the two kinds of mistake (false alarms and misses) identically and ignores how rare each class is, which is why it can mislead.

| Word | What it means here |

| accuracy paradox | high accuracy with a useless model |
| majority baseline | always predict the commonest class |
| balanced accuracy | the average of per-class recall |
| top-k accuracy | is the right answer among the top k? |

### 1. What is it?
The **fraction of predictions that are correct**: `accuracy = (TP + TN) / (TP + TN + FP + FN)`.

### 2. Why does it exist?
It is the simplest summary of a classifier's overall hit rate and is easy to communicate.

### 3. Detailed explanation
- **It works when** classes are roughly balanced and all errors cost about the same.
- **The accuracy paradox:** with about 1% positives, a model that *always predicts negative* scores about **99%** accuracy and finds **zero** positives (recall 0). A real model that scores 99.5% is only slightly better on paper. Accuracy hides the thing we care about.
- **Balanced accuracy** = the mean of the recall on each class: **0.50** for the always-negative model (chance) and much higher for a real one: a far more honest picture.
- **Always compare with the majority-class baseline** (2.46): the improvement over 99%, not the raw 99.5%, is the skill.
- **Not differentiable,** so it is not a training loss (2.17); it also jumps with the threshold.
- **It depends on the decision threshold** and on the class prevalence of the evaluation set (2.50).
- **Multiclass:** accuracy is still the fraction correct; micro-averaged F1 equals accuracy for single-label problems (2.40).
- **Top-k accuracy** (is the right answer among the top k?) suits retrieval and large label sets.
- **Uncertainty:** a test set of `n` items gives a standard error of about `√(p(1 − p)/n)`; report an interval (2.13).

### 4. How does it work?
Predict labels → compare with the truth → average the 0/1 indicator of being correct.

### 5. Simple example
The share of exam questions answered correctly.

**The paradox, by hand.** 1,000 transactions, 10 fraudulent.

| Model | correct | accuracy | frauds found |
|---|---|---|---|
| "always say not-fraud" | 990 | **99.0%** | **0 of 10** |
| a real model: 8 frauds caught, 5 false alarms | 8 + 985 = 993 | 99.3% | 8 of 10 |

The useless model looks almost as good on paper.

### 6. Technical example
Image classification on balanced classes (ImageNet-style); top-5 accuracy for problems with many classes.

### 7. Code
**① By hand (plain Python).**

```python
tp, fp, fn, tn = 8, 5, 2, 985                      # a real model on 1,000 transactions (10 frauds)
print("real model accuracy      :", (tp + tn) / (tp + fp + fn + tn))
print("always-negative accuracy :", (0 + 990) / 1000, "(finds 0 of 10 frauds)")
recall, specificity = tp / (tp + fn), tn / (tn + fp)
print("balanced accuracy, real model     :", round((recall + specificity) / 2, 3))
print("balanced accuracy, always-negative:", (0 + 1) / 2)
```

```text
real model accuracy      : 0.993
always-negative accuracy : 0.99 (finds 0 of 10 frauds)
balanced accuracy, real model     : 0.897
balanced accuracy, always-negative: 0.5
```

**② With NumPy.** The paradox on a larger simulated problem.

```python
import numpy as np

rng = np.random.default_rng(0)
y = (rng.random(20000) < 0.0107).astype(int)                          # about 1.07% positives
score = rng.normal(0, 1, 20000) + 3.0 * y                               # a decent scoring model
pred = (score > 2.0).astype(int)
never = np.zeros_like(y)

def stats(p):
    tp = ((p == 1) & (y == 1)).sum(); tn = ((p == 0) & (y == 0)).sum()
    return (p == y).mean(), tp / y.sum(), (tp / y.sum() + tn / (y == 0).sum()) / 2
for name, p in (("real model", pred), ("always negative", never)):
    acc, rec, bal = stats(p)
    print(f"{name:<16} accuracy {acc:.3f}   recall {rec:.2f}   balanced accuracy {bal:.2f}")
```

```text
real model       accuracy 0.975   recall 0.83   balanced accuracy 0.90
always negative  accuracy 0.990   recall 0.00   balanced accuracy 0.50
```

**③ With scikit-learn.**

```python
import numpy as np
from sklearn.metrics import accuracy_score, balanced_accuracy_score, top_k_accuracy_score

y = np.array([0] * 990 + [1] * 10)
always_negative = np.zeros(1000, dtype=int)
print("accuracy          :", accuracy_score(y, always_negative))
print("balanced accuracy :", balanced_accuracy_score(y, always_negative))

# top-k accuracy: is the right class among the 2 highest scores?
scores = np.array([[0.1, 0.5, 0.4], [0.7, 0.2, 0.1], [0.2, 0.3, 0.5]])
print("top-1 accuracy:", top_k_accuracy_score([1, 0, 1], scores, k=1, labels=[0, 1, 2]), "  top-2 accuracy:", top_k_accuracy_score([1, 0, 1], scores, k=2, labels=[0, 1, 2]))
```

```text
accuracy          : 0.99
balanced accuracy : 0.5
top-1 accuracy: 0.6666666666666666   top-2 accuracy: 1.0
```

### 9. Enterprise use case
Executives understand accuracy, so it appears in reports, but model owners track class-wise recall and precision alongside it.

### 10. AI engineering connection
Exact-match and multiple-choice accuracy on LLM benchmarks; routing accuracy for intent classifiers; always paired with slice metrics (Tier 30).

### 11. Advantages
Simple, interpretable, one number.

### 12. Limitations
Misleading with imbalance, unequal error costs, or when calibration matters.

### 13. Trade-offs
Simplicity versus information: accuracy discards the type of error and the score confidence.

### 14. Common mistakes
Reporting accuracy alone on imbalanced data; comparing accuracies across datasets with different prevalence; ignoring the baseline; optimising it directly.

### 15. Performance / cost
`O(n)`; trivial.

### 16. Security
A high headline accuracy can mask a failure on a small, high-risk subgroup (an attack class, a protected group). Evaluate slices.

### 20. Hands-on exercise
**Goal:** watch accuracy mislead as positives get rarer.

1. A classifier has TPR 0.9 and FPR 0.05. Compute its accuracy at prevalences 50%, 10%, 1% and 0.1%.
2. Compute the accuracy of "always negative" at the same prevalences.
3. When does the useless model beat the real one?

<details>
<summary>Show a solution</summary>

```python
for prevalence in (0.5, 0.1, 0.01, 0.001):
    real = 0.9 * prevalence + (1 - 0.05) * (1 - prevalence)           # TPR * pi + TNR * (1 - pi)
    never = 1 - prevalence
    print(f"prevalence {prevalence:>6.1%}: real model {real:.3f}   always negative {never:.3f}   {'<- useless model wins' if never > real else ''}")
```

```text
prevalence  50.0%: real model 0.925   always negative 0.500   
prevalence  10.0%: real model 0.945   always negative 0.900   
prevalence   1.0%: real model 0.950   always negative 0.990   <- useless model wins
prevalence   0.1%: real model 0.950   always negative 0.999   <- useless model wins
```
