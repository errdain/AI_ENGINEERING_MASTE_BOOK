# 2.37 Accuracy

### 1. What is it?
The **fraction of predictions that are correct**: `accuracy = (TP + TN) / (TP + TN + FP + FN)`.

### 2. Why does it exist?
It is the simplest summary of a classifier's overall hit rate and is easy to communicate.

### 3. Detailed explanation
- **Works when** classes are roughly balanced and all errors cost about the same.
- **The accuracy paradox:** with 1.07% positives, a model that *always predicts negative* scores **98.9%** accuracy and finds **zero** positives (recall 0). A real model scoring 99.5% looks only slightly better. Accuracy hides the thing we care about.
- **Balanced accuracy** = mean of recall on each class: 0.50 for the always-negative model (chance), 0.81 for the real one, a far more honest picture.
- **Always compare against the majority-class baseline** (2.46): the improvement over 98.9%, not the raw 99.5%, is the skill.
- **Not differentiable,** so it is not a training loss (2.17); it is also discontinuous in the threshold.
- **Accuracy depends on the decision threshold** and on class prevalence in the evaluation set (2.50).
- **Multiclass:** accuracy is still the fraction correct; micro-averaged F1 equals accuracy for single-label problems (2.40).
- **Top-k accuracy** (is the right answer among the top k?) suits retrieval and large label sets.
- **Uncertainty:** a test set of `n` items gives a standard error of about `√(p(1−p)/n)`; report an interval (2.13).

### 4. How does it work?
Predict labels → compare with truth → average the 0/1 indicator of correctness.

### 5. Simple example
The share of exam questions answered correctly.

### 6. Technical example
Image classification on balanced ImageNet-style classes; top-5 accuracy for many-class problems.

### 8. Input → Process → Output
`predictions, labels → count matches → ratio`

### 9. Enterprise use case
Executives understand accuracy, so it is used in reports, but model owners track class-wise recall/precision alongside it.

### 10. AI engineering connection
Exact-match and multiple-choice accuracy on LLM benchmarks; routing accuracy for intent classifiers; always paired with slice metrics (Tier 30).

### 11. Advantages
Simple, interpretable, one number.

### 12. Limitations
Misleading with imbalance, unequal costs, or when calibration matters.

### 13. Trade-offs
Simplicity versus information: accuracy discards error type and score confidence.

### 14. Common mistakes
Reporting accuracy alone on imbalanced data; comparing accuracies across datasets with different prevalence; ignoring the baseline; optimizing it directly.

### 15. Performance / cost
`O(n)`; trivial.

### 16. Security
A high headline accuracy can mask a failure on a small, high-risk subgroup (attack class, protected group); evaluate slices.

### 17. Interview explanation
"Accuracy is the share of correct predictions. It's fine on balanced problems, but with 1% positives a model that always says 'negative' gets 99% accuracy and finds nothing, so I compare with the majority baseline and look at recall, precision or balanced accuracy."

### 18. Rapid-fire
Accuracy = correct / total; misleading under imbalance; compare to the majority baseline.
