# 2.20 Stochastic gradient descent (SGD)

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: Very high · Hands-on: Very high
Prerequisites: 2.19, 1.27, 1.29 · Leads to: 2.21 Mini-batch, 2.25 Learning rate, Tier 4 SGD/Momentum/Adam

> **In plain words**
> **SGD** is gradient descent in a hurry: instead of using **all** your data to work out the slope before each step, it uses **one random example** (or a small random group). The slope estimate is **noisy but right on average**, and far cheaper.
> The noise makes the path jittery, so SGD **hovers around** the best answer instead of landing exactly on it, unless you slowly shrink the step size.
> Like estimating a town's average opinion by asking one random person at a time: noisy, but fast and unbiased.

### 1. What is it?
Gradient descent where each step uses the gradient of a **single randomly chosen example** (or a small random subset) as a noisy estimate of the full gradient.

### 2. Why does it exist?
The full-data gradient is expensive when `n` is large. A random example's gradient is much cheaper and, on average, points the right way.

### 3. Detailed explanation
- **Unbiased estimate:** `E[∇ℓ(xᵢ)] = ∇J` when the example is drawn uniformly (1.29). Averaging the gradients of batches that partition the data reproduces the full gradient exactly.
- **Noise:** single-example gradients have high variance. The variance of a batch-mean gradient falls roughly like `1/B`.
- **A constant learning rate leaves a noise floor:** SGD jitters around the optimum instead of converging. A **decaying** learning rate shrinks the jitter.
- **Benefits of noise:** it helps escape saddle points and sharp minima in non-convex problems (1.46) and acts as a mild regulariser.
- **Shuffling:** each epoch uses a fresh random order (sampling without replacement), which is usually better than sampling with replacement.
- **Convergence conditions** for decreasing steps: `Σηₜ = ∞` and `Σηₜ² < ∞` (for example `η/t`).
- **Terminology warning:** frameworks and papers say "SGD" for any mini-batch method (2.21); pure SGD means batch size 1. The optimiser object `torch.optim.SGD` is covered in Tier 4 (4.6).

### 4. How does it work?
Shuffle → pick an example (or batch) → compute its gradient → update → repeat; once every example has been seen once, an epoch (2.22) ends.

### 5. Simple example
Estimating the average height in a town by asking one random person at a time: each answer is noisy, but the running average settles near the truth.

**With numbers.** The true average is 170. Ask people one at a time: 160, 180, 175, 165, 170 → running averages 160, 170, 171.7, 170, 170. Each single answer is off, but the running average hugs 170.

### 6. Technical example
Training a logistic regression on 10⁸ rows with batch size 256 and a decaying learning rate.

### 7. Code
**① By hand (plain Python).** SGD with a constant versus a decaying learning rate.

```python
import random

def run(decay, seed=0, steps=6000):
    rng = random.Random(seed)
    data = [(x, 2 * x + 1 + rng.gauss(0, 1)) for x in [rng.uniform(-1, 1) for _ in range(500)]]     # y = 2x + 1 + noise
    w, b = 0.0, 0.0
    for t in range(steps):
        x, y = data[rng.randrange(len(data))]                      # one random example per step
        lr = 0.05 / (1 + t / 200) if decay else 0.05
        err = w * x + b - y
        w, b = w - lr * 2 * err * x, b - lr * 2 * err
    return ((w - 2) ** 2 + (b - 1) ** 2) ** 0.5

print("distance from the true (2, 1), constant learning rate :", round(run(False), 3))
print("distance from the true (2, 1), decaying learning rate :", round(run(True), 3))
```

```text
distance from the true (2, 1), constant learning rate : 0.336
distance from the true (2, 1), decaying learning rate : 0.061
```

**② With NumPy.** The batch-gradient variance falls like `1/B`.

```python
import numpy as np

rng = np.random.default_rng(0)
X = rng.normal(0, 1, (5000, 2))
y = X @ np.array([2.0, -1.0]) + rng.normal(0, 1, 5000)
w = np.zeros(2)
per_example = 2 * (X @ w - y)[:, None] * X                      # the gradient of each example, shape (5000, 2)
print("full gradient:", per_example.mean(axis=0).round(3))
for B in (1, 8, 64, 512):
    estimates = np.array([per_example[rng.integers(0, 5000, B)].mean(axis=0) for _ in range(2000)])
    print(f"batch size {B:>3}: mean of estimates {estimates.mean(axis=0).round(2)}   variance {estimates.var(axis=0).mean():7.3f}")
```

batch size  64: mean of estimates [-4.08  2.07]   variance   0.531

**③ With PyTorch.** Full batch, mini-batch and pure SGD on the same problem.

```python
import torch

torch.manual_seed(0)
X = torch.randn(256, 2)
y = X @ torch.tensor([2.0, -1.0]) + 0.05 * torch.randn(256)

def train(batch_size, lr, epochs=60):
    torch.manual_seed(1)
    model = torch.nn.Linear(2, 1)
    opt = torch.optim.SGD(model.parameters(), lr=lr)
    updates = 0
    for _ in range(epochs):
        perm = torch.randperm(256)
        for i in range(0, 256, batch_size):
            idx = perm[i:i + batch_size]
            opt.zero_grad()
            torch.nn.functional.mse_loss(model(X[idx]).squeeze(1), y[idx]).backward()
            opt.step()
            updates += 1
    return updates, torch.nn.functional.mse_loss(model(X).squeeze(1), y).item()

for name, bs, lr in (("full batch", 256, 0.1), ("mini-batch 32", 32, 0.1), ("pure SGD (1)", 1, 0.02)):
    updates, loss = train(bs, lr)
    print(f"{name:<14} updates {updates:>6}   final loss {loss:.4f}")
```

```text
full batch     updates     60   final loss 0.0028
mini-batch 32  updates    480   final loss 0.0028
pure SGD (1)   updates  15360   final loss 0.0030
```

### 8. Input → Process → Output
`random example → noisy gradient → small step → repeat`

<summary><b>Beyond the basics (sections 9–16)</b> — real-world use, limits, mistakes. Skip on a first read.</summary>

### 9. Enterprise use case
Online and streaming learning, huge datasets, and all deep-learning training rely on SGD-style updates.

### 10. AI engineering connection
LLM training uses mini-batch SGD variants (AdamW) with very large effective batch sizes via accumulation and parallelism (Tier 4).

### 11. Advantages
Cheap steps; scales to huge data; the noise can help generalisation; works online.

### 12. Limitations
Noisy convergence; sensitive to the learning-rate schedule; hard to parallelise at batch size 1.

### 13. Trade-offs
Smaller batches give more updates per epoch and more noise; larger ones are steadier but costlier per step.

### 14. Common mistakes
Expecting exact convergence with a constant learning rate; not shuffling; judging by the loss of one noisy step; treating SGD as "any optimiser".

### 15. Performance / cost
The cost per step does not depend on the dataset size; total cost scales with epochs × data.

### 16. Security
Per-example gradients are also what differential-privacy methods clip and add noise to (DP-SGD).

</details>

### 17. Interview explanation
"SGD replaces the full gradient with a gradient from a random sample, which is an unbiased but noisy estimate. That makes each step cheap and the noise even helps escape bad regions, but with a constant learning rate it only hovers near the optimum, so we decay the rate or increase the batch size."

### 18. Rapid-fire answer
A noisy, unbiased gradient from random examples; cheap steps; needs a decaying learning rate to converge exactly.

<details>
<summary>Show a solution</summary>

```python
import random

def run(lr_fn, seed=0, steps=6000):
    rng = random.Random(seed)
    data = [(x, 2 * x + 1 + rng.gauss(0, 1)) for x in [rng.uniform(-1, 1) for _ in range(500)]]
    w = b = 0.0
    for t in range(steps):
        x, y = data[rng.randrange(500)]
        err = w * x + b - y
        w, b = w - lr_fn(t) * 2 * err * x, b - lr_fn(t) * 2 * err
    return ((w - 2) ** 2 + (b - 1) ** 2) ** 0.5

def average(lr_fn):                                            # average over 10 random runs to smooth out luck
    return sum(run(lr_fn, seed=s) for s in range(10)) / 10

for lr in (0.2, 0.05, 0.01):
    print(f"constant {lr:<5}: average distance {average(lambda t: lr):.3f}")
print(f"decaying    : average distance {average(lambda t: 0.05 / (1 + t / 200)):.3f}")
```

```text
constant 0.2  : average distance 0.389
constant 0.05 : average distance 0.296
constant 0.01 : average distance 0.156
decaying    : average distance 0.104
```

A smaller constant rate lowers the jitter (at the price of slower progress); a schedule that starts large and shrinks does best of all.
</details>
