# 2.25 Learning rate

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: Very high · Hands-on: Very high
Prerequisites: 2.19, 1.23, 1.18 · Leads to: Tier 4 LR scheduling (4.10), warmup (4.11), cosine decay (4.12), 2.35 Hyperparameters

### 1. What is it?
The scalar `η` that scales each gradient step: `θ ← θ − η∇J`. It sets how far the parameters move per update.

### 2. Why does it exist?
Too small wastes compute; too large overshoots and diverges. It is usually the single most important hyperparameter.

### 3. Detailed explanation
- **Stability limit for a quadratic objective:** GD converges iff `η < 2/λ_max`, where `λ_max` is the largest eigenvalue of the Hessian (1.18, 1.45, 1.23). For the lab's regression `λ_max = 2.174`, so the limit is 0.920. Running at 0.9× the limit converged (final loss 0.0098 = noise floor); at 1.1× the loss exploded to 3×10³¹.
- **Sweep (200 epochs, full batch):** final loss 4.36 (η = 1e-4), 2.28 (1e-3), 0.0135 (1e-2), 0.0098 (1e-1). Too small is slow, not wrong.
- **Feature scale controls the usable rate.** Multiplying one feature by 30 reduces the stability limit from 0.92 to 0.0011, about 840× smaller; standardize inputs (2.47).
- **Rule of thumb for finding η:** a log-scale range test: increase η exponentially over a short run; choose a value somewhat below where loss starts to blow up.
- **Schedules** (Tier 4): warmup (small η at first), decay (cosine, step, 1/t) to reduce noise near the end (2.20). Adaptive optimizers (Adam) rescale per-parameter steps but still need a global η.
- **Interaction with batch size:** larger batches tolerate (and often need) larger η (2.21).
- **Diagnosis:** loss diverges/NaN → too high; loss decreases very slowly and smoothly → too low; loss decreases then oscillates/plateaus noisily → reduce or decay.
- **Don't tune on the test set.** Treat η as a hyperparameter selected on validation data (2.12, 2.35).

### 4. How does it work?
Choose η from a range test/sweep → add warmup and decay → monitor loss and gradient norm → adjust.

### 5. Simple example
Step length when walking downhill: too short takes forever, too long overshoots the valley.

### 6. Technical example
AdamW with peak η = 3e-4, 500 warmup steps and cosine decay; fine-tuning a pretrained model with η 10–100× smaller than pretraining.

### 7. Code
```python
import numpy as np, mlkit as M
X, y = M.make_linear(200, noise=0.1, seed=0)
A = np.hstack([X, np.ones((200, 1))]); lam = np.linalg.eigvalsh(2 * A.T @ A / 200).max()
limit = 2 / lam                                         # ≈ 0.92
for lr in (0.9 * limit, 1.1 * limit):
    print(round(lr, 3), M.sgd_linear(X, y, lr=lr, epochs=200)[2]['epoch_loss'][-1])   # 0.0098   3e31
```

### 8. Input → Process → Output
`gradient × η → parameter change`

### 9. Enterprise use case
Learning-rate choice dominates training cost and failure rate; runs are launched with sweeps and automatic divergence alerts.

### 10. AI engineering connection
Fine-tuning rates, LoRA rates, warmup and decay schedules (Tier 4, Tier 10) are among the first settings engineers tune.

### 11. Advantages
One knob with large impact; simple to reason about for convex problems.

### 12. Limitations
Best value depends on model, data scale, batch size and optimizer; no universal default.

### 13. Trade-offs
Speed of progress vs stability and final accuracy.

### 14. Common mistakes
Using the same rate when changing batch size or optimizer; unscaled features; skipping warmup for large models; tuning on test data; changing several hyperparameters at once.

### 15. Performance / cost
A good learning rate can cut training time several-fold; a bad one wastes the entire run.

### 16. Security
Divergent or tampered training runs can silently produce bad models; keep run-level monitoring and checkpoints.

### 17. Interview explanation
"The learning rate scales the gradient step. For a quadratic objective GD is stable only below 2 over the largest Hessian eigenvalue, which is why unscaled features force tiny rates. I find a range with a log-scale sweep, use warmup and decay, and retune it when I change batch size or optimizer."

### 18. Rapid-fire
η scales each step; stable iff η < 2/λ_max (quadratic); sweep on a log scale; retune with batch size.
