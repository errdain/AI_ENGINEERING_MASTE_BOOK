# 2.45 Class imbalance

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: Very high · Hands-on: Very high
Prerequisites: 2.14, 2.37–2.41 · Leads to: 2.50 Dataset imbalance, 2.51 Metric selection, fraud and safety systems

> **In plain words**
> **Class imbalance** means **one class is much rarer than the other**: 2% fraud, 0.1% defects. The rare class is usually the one that matters, but normal training and accuracy favour the common one.
> The key lesson: tricks such as **class weights** and **oversampling** don't make the model *smarter*, they **move the operating point**, trading precision for recall. Often just **tuning the threshold** does the same job more cheaply. What changes the result is choosing the **right metric** and the **right threshold for the costs**.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| imbalance | one class is much rarer |
| class weights | make rare-class errors count more in the loss |
| oversampling | repeat (or synthesise) rare-class examples |
| undersampling | drop some majority examples |
| SMOTE | create new rare examples by interpolating neighbours |
| PR-AUC / average precision | ranking quality that reflects precision |
| operating point | the chosen threshold and its precision/recall |

### 1. What is it?
A classification problem where **one class is much rarer than the others**, such as 2% fraud or 0.1% defects. This concept covers the *modelling and metric consequences*; 2.50 covers the *dataset-level* aspects (sampling, prevalence, calibration).

### 2. Why does it matter?
Standard training and accuracy favour the majority class; rare classes are often the ones that matter.

### 3. Detailed explanation
- **Symptoms:** high accuracy but near-zero recall on the rare class (2.37); predicted probabilities that rarely exceed 0.5 for positives.
- **Metrics:** prefer precision, recall, F1, PR-AUC (average precision), balanced accuracy and cost-based measures; report per-class results (2.38–2.42).
- **The levers** (illustrated with 2% positives): *plain* logistic regression has high precision and moderate recall; *class weights* and *random oversampling* give very high recall and very low precision; a *tuned threshold* on the plain model reaches a similar trade-off. **PR-AUC is the same for all of them.**
- **Key lesson:** weights and resampling **move the operating point, they do not improve the ranking**. Here they trade precision for recall, and F1 actually *falls* because the default threshold is no longer appropriate. Tuning the threshold on the plain model achieves a comparable trade-off more cheaply. Choose the operating point from the costs (2.51).
- **Techniques:** class weights or cost-sensitive losses; oversampling (random, SMOTE-style interpolation); undersampling the majority; threshold moving; focal loss; ensembling with balanced bootstraps; an anomaly-detection framing when positives are extremely rare; collecting more positives or active learning.
- **Resample only the training part,** after splitting (otherwise duplicates leak into evaluation, 2.33). Never resample validation or test data if you want production-representative metrics.
- **Probabilities become miscalibrated** after resampling or weighting; correct the prior or recalibrate (2.43, 2.50).
- **Multiclass imbalance:** use macro-F1 and per-class recall; stratified splits (2.10).
- **What counts as "rare"?** Think in absolute numbers of positives, not just the ratio: 100 positives out of 10,000 is a very different learning problem from 100,000 out of 10,000,000.

### 4. How does it work?
Quantify the prevalence → choose suitable metrics → build the majority baseline → try threshold tuning, weights and resampling → compare at the cost-based operating point on an untouched, representative validation set.

### 5. Simple example
Finding a few needles in a haystack: counting "hay correctly identified" doesn't help.

**Class weights, by hand.** 10,000 training rows: 9,800 negatives, 200 positives. The "balanced" weights are `n / (2 × count)`: negatives `10,000 / (2 × 9,800) = 0.51`, positives `10,000 / (2 × 200) = 25`. A missed positive now hurts the loss 49 times more than a missed negative.

### 6. Technical example
Credit-card fraud with 0.2% positives; rare-defect detection in manufacturing; harmful-content classification.

### 7. Code
**① By hand (plain Python).** Balanced class weights and the effect of weights on a loss.

```python
negatives, positives = 9800, 200
n = negatives + positives
w_neg, w_pos = n / (2 * negatives), n / (2 * positives)
print(f"weights: negative {w_neg:.2f}, positive {w_pos:.1f}  (ratio {w_pos / w_neg:.0f}x)")
print("a missed positive now counts as much as", round(w_pos / w_neg), "missed negatives")
```

```text
weights: negative 0.51, positive 25.0  (ratio 49x)
a missed positive now counts as much as 49 missed negatives
```

**② With NumPy and scikit-learn.** The comparison: weights, oversampling and a tuned threshold.

```python
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import average_precision_score, f1_score, precision_score, recall_score

rng = np.random.default_rng(0)
def data(n):
    y = (rng.random(n) < 0.02).astype(int)
    return rng.normal(0, 1, (n, 5)) + 1.6 * y[:, None], y
Xtr, ytr = data(10000)
Xval, yval = data(10000)
Xte, yte = data(10000)

def report(name, p, t=0.5):
    pred = p > t
    print(f"{name:<22} precision {precision_score(yte, pred, zero_division=0):.3f}  recall {recall_score(yte, pred):.3f}  F1 {f1_score(yte, pred):.3f}  PR-AUC {average_precision_score(yte, p):.3f}")

plain = LogisticRegression().fit(Xtr, ytr)
weighted = LogisticRegression(class_weight="balanced").fit(Xtr, ytr)
pos = np.where(ytr == 1)[0]
Xo, yo = np.vstack([Xtr, np.repeat(Xtr[pos], 49, axis=0)]), np.concatenate([ytr, np.ones(len(pos) * 49, dtype=int)])    # oversample AFTER the split
oversampled = LogisticRegression().fit(Xo, yo)

report("plain", plain.predict_proba(Xte)[:, 1])
report("class weights", weighted.predict_proba(Xte)[:, 1])
report("random oversampling", oversampled.predict_proba(Xte)[:, 1])
ts = np.arange(0.05, 0.96, 0.01)
p_val = plain.predict_proba(Xval)[:, 1]
best_t = ts[int(np.argmax([f1_score(yval, p_val > t) for t in ts]))]               # tuned on VALIDATION data
report(f"plain, threshold {best_t:.2f}", plain.predict_proba(Xte)[:, 1], best_t)
```

```text
plain                  precision 0.877  recall 0.734  F1 0.799  PR-AUC 0.876
class weights          precision 0.363  recall 0.944  F1 0.525  PR-AUC 0.870
random oversampling    precision 0.368  recall 0.944  F1 0.529  PR-AUC 0.870
plain, threshold 0.41  precision 0.853  recall 0.757  F1 0.802  PR-AUC 0.876
```

**③ With PyTorch.** A weighted loss (`pos_weight`) as the code-level lever.

```python
import torch

torch.manual_seed(0)
X = torch.randn(10000, 5)
y = (torch.rand(10000) < 0.02).float()
X[y == 1] += 1.6
for pos_weight in (1.0, 49.0):
    model = torch.nn.Linear(5, 1)
    opt = torch.optim.Adam(model.parameters(), lr=0.05)
    loss_fn = torch.nn.BCEWithLogitsLoss(pos_weight=torch.tensor(pos_weight))
    for _ in range(300):
        opt.zero_grad(); loss_fn(model(X).squeeze(1), y).backward(); opt.step()
    p = torch.sigmoid(model(X).squeeze(1)).detach()
    pred = p > 0.5
    recall = ((pred & (y == 1)).sum() / y.sum()).item()
    precision = ((pred & (y == 1)).sum() / pred.sum().clamp(min=1)).item()
    print(f"pos_weight {pos_weight:>4}: recall {recall:.3f}  precision {precision:.3f}  (weighting moves the operating point)")
```

```text
pos_weight  1.0: recall 0.558  precision 0.972  (weighting moves the operating point)
pos_weight 49.0: recall 0.953  precision 0.302  (weighting moves the operating point)
```

### 9. Enterprise use case
Fraud, safety, security and quality teams work with prevalence-aware metrics, review capacities and threshold policies, not accuracy.

### 10. AI engineering connection
Guard-rail classifiers, rare-intent routers, hallucination detectors and jailbreak detection are all severely imbalanced; evaluation sets are often built by oversampling positives (then corrected for prevalence).

### 11. Advantages
Relatively cheap fixes exist; the main gain is choosing the right metrics and threshold.

### 12. Limitations
Weights and resampling don't create information; very few positives limit any method.

### 13. Trade-offs
Recall versus precision (review load); over- or undersampling versus information loss or overfitting.

### 14. Common mistakes
Reporting accuracy; oversampling before the split; evaluating on a rebalanced set and quoting the number as production precision; ignoring calibration shift; believing weights improve the ranking.

### 15. Performance / cost
Oversampling inflates training time; undersampling saves it.

### 16. Security
Adversaries target the rare class (new fraud patterns); monitor and refresh positives continuously.

### 17. Interview explanation
"With a rare class, accuracy is useless, so I use PR-AUC, recall and precision at a chosen operating point, and cost-based thresholds. Class weights and resampling shift the operating point rather than improving ranking; often a tuned threshold on a well-calibrated model does just as well. I resample only inside the training split and correct probabilities afterwards."

### 18. Rapid-fire answer
Rare class: use PR-AUC, recall and precision; weights and resampling move the threshold, not the ranking; resample after splitting.

### 20. Hands-on exercise
**Goal:** check that SMOTE-like interpolation also moves the operating point.

1. Take the training data above. For each positive, create synthetic positives by interpolating between it and a random other positive (`x_new = x + u·(x' − x)`, `u` uniform in `[0, 1]`), until positives equal negatives.
2. Fit logistic regression on the training set plus the synthetic positives.
3. Report precision, recall and PR-AUC on the test set. Compare with plain.

<details>
<summary>Show a solution</summary>

```python
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import average_precision_score, precision_score, recall_score

rng = np.random.default_rng(0)
def data(n):
    y = (rng.random(n) < 0.02).astype(int)
    return rng.normal(0, 1, (n, 5)) + 1.6 * y[:, None], y
Xtr, ytr = data(10000); Xte, yte = data(10000)

pos = Xtr[ytr == 1]
n_new = (ytr == 0).sum() - len(pos)
a, b = pos[rng.integers(0, len(pos), n_new)], pos[rng.integers(0, len(pos), n_new)]
synthetic = a + rng.random((n_new, 1)) * (b - a)                       # interpolate between pairs of positives
X2, y2 = np.vstack([Xtr, synthetic]), np.concatenate([ytr, np.ones(n_new, dtype=int)])

for name, (X, y) in (("plain", (Xtr, ytr)), ("SMOTE-like", (X2, y2))):
    p = LogisticRegression().fit(X, y).predict_proba(Xte)[:, 1]
    print(f"{name:<11} precision {precision_score(yte, p > 0.5, zero_division=0):.3f}  recall {recall_score(yte, p > 0.5):.3f}  PR-AUC {average_precision_score(yte, p):.3f}")
```

```text
plain       precision 0.884  recall 0.789  PR-AUC 0.903
SMOTE-like  precision 0.440  recall 0.959  PR-AUC 0.903
```
