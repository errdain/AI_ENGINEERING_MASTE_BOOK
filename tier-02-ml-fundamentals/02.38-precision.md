# 2.38 Precision

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: Very high · Hands-on: High
Prerequisites: 2.42, 1.33 · Leads to: 2.39 Recall, 2.40 F1, 2.41 PR curve, 2.51 Metric selection

### 1. What is it?
Of the items the model **flagged as positive, the fraction that truly are positive**: `precision = TP / (TP + FP)` (positive predictive value).

### 2. Why does it exist?
It answers 'when the model raises its hand, how often is it right?', which governs the cost of false alarms.

### 3. Detailed explanation
- **Conditional probability view:** `precision = P(actual positive | predicted positive)` (1.33).
- **It depends on prevalence.** With a fixed classifier (TPR 0.90, FPR 0.05): `precision = TPR·π / (TPR·π + FPR·(1−π))` gives 0.947 at π=0.5, 0.667 at 10%, **0.154 at 1%**, 0.018 at 0.1%. The same model has very different precision in different populations (Bayes, 1.34).
- **Threshold trade-off (10% positives):** thresholds 0.1/0.3/0.5/0.7/0.9 give precision 0.571, 0.791, 0.874, 0.928, 0.970 while recall falls 0.921 → 0.447 (2.39).
- **Undefined when nothing is predicted positive** (0/0). `mlkit.precision` returns 0 by default and exposes `zero_division`; always state the convention.
- **Where precision matters most:** when false positives are expensive: spam filters blocking real mail, manual-review queues, automated account suspension.
- **Precision@k** (fraction of the top-k results that are relevant) is the retrieval/RAG analogue (Tier 20, 21).
- **Micro/macro averaging** for multiclass (2.40).

### 4. How does it work?
Count predicted positives, count how many were truly positive, divide.

### 5. Simple example
Of the 20 emails the filter put in spam, 18 really were spam: precision 90%.

### 6. Technical example
A fraud model flags 100 transactions; 30 are fraud: precision 30%. Review capacity of 100 cases/day determines whether that's acceptable.

### 8. Input → Process → Output

### 9. Enterprise use case
Precision links directly to reviewer workload and customer friction; teams set a minimum precision (e.g., ≥ 90%) and maximize recall subject to it.

### 10. AI engineering connection
Precision of retrieved chunks (precision@k), of tool calls that were necessary, of guardrail blocks that were justified, of claims in an answer that are supported (faithfulness).

### 11. Advantages
Intuitive; ties to cost of false alarms.

### 12. Limitations
Ignores missed positives; shifts with prevalence; unstable when few predictions are positive.

### 13. Trade-offs
Raising the threshold increases precision and decreases recall.

### 14. Common mistakes
Comparing precision across datasets with different prevalence; reporting precision without recall; undefined values hidden as 0; evaluating on a rebalanced set and quoting production precision.

### 15. Performance / cost
`O(n)`.

### 16. Security
Low-precision security alerts cause alert fatigue and real incidents get ignored.

### 17. Interview explanation
"Precision is the fraction of flagged items that are truly positive: TP over TP plus FP. It's a conditional probability, so it depends on prevalence — the same classifier can have 95% precision at a 50% base rate and 15% at 1%. I choose a threshold to meet a precision floor set by review capacity."

### 18. Rapid-fire
Precision = TP/(TP+FP) = P(positive | flagged); falls with lower prevalence and lower thresholds.
