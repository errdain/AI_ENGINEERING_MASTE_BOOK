# 2.7 Features

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: High · Hands-on: Very high
Prerequisites: 1.2, 1.3 · Leads to: 2.47 Scaling, 2.48 Feature engineering, 2.33 Leakage

### 1. What is it?
The **measurable input variables** that describe a sample; the columns of the feature matrix `X` (shape `(n_samples, n_features)`).

### 2. Why does it exist?
A model sees only features. Their quality, scale, and relevance set the ceiling on what any algorithm can achieve.

### 3. Detailed explanation
- **Types:** numeric (continuous, count), categorical (one-hot, embeddings), ordinal, text (tokens/embeddings), image/audio (pixels/spectrograms), time-based (lags, rolling stats).
- **Representation matters:** the XOR task fails for a linear model on raw `(x₁, x₂)` but succeeds once `x₁·x₂` is added (2.1: 45.5% → 96.5%).
- **Irrelevant features add noise and variance.** With 100 training rows, adding 60 pure-noise columns drops held-out accuracy from 92.1% to 79.6% for an unregularized logistic regression (average over 10 seeds).
- **Feature availability at prediction time:** a feature that is not known when the prediction is made (or is derived from the label) is **leakage** (2.33).
- **Scaling and encoding:** distance-based and gradient-based models need comparable scales (2.47); unseen categories need a policy (`one_hot` rejects unseen codes in our code).
- **Learned features:** deep nets and embeddings learn features instead of hand-designing them (2.1, Tier 6).

### 4. How does it work?
Raw data → cleaning → encoding → derived features → feature matrix → model. Training and serving must apply the same transformations.

### 5. Simple example
The questions on a form: the answers you can collect determine what decisions are possible.

### 6. Technical example
Loan model features: income, debt ratio, account age (numeric), employment type (categorical), recent late payments (count).

### 8. Input → Process → Output
`raw record → feature extraction → numeric vector x`

### 9. Enterprise use case
Feature stores keep one definition per feature for training and serving, with ownership, freshness and lineage.

### 10. AI engineering connection
Embeddings are learned features; structured-output extraction (Tier 19) produces features from text; RAG metadata filters are features.

### 11. Advantages
Direct control over what the model can see; cheap gains from good features.

### 12. Limitations
Manual features need domain knowledge; they can encode bias (proxy variables).

### 13. Trade-offs
More features: more signal but more noise, cost and leakage risk.

### 14. Common mistakes
Training/serving skew (different code paths); forgetting missing-value handling; including identifiers; features unavailable at prediction time.

### 15. Performance / cost
Feature computation often dominates serving latency; precompute or cache.

### 16. Security
Sensitive attributes (and close proxies) create legal and fairness risk; log and review feature use.

### 17. Interview explanation
"Features are the inputs the model sees, the columns of X. Quality and availability at prediction time matter more than the algorithm, and irrelevant features add variance. I make sure features are computed identically in training and serving, and I check for leakage."
