# 2.10 Dataset construction

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: High · Hands-on: Very high
Prerequisites: 2.7–2.9 · Leads to: 2.11–2.13, 2.33 Leakage, 2.34 Shift, Tier 38 Data engineering

### 1. What is it?
The process of turning raw data into a **documented, versioned, split, leakage-safe** dataset for training and evaluation: define the task, collect, clean, deduplicate, label, split, document.

### 2. Why does it exist?
Models inherit every flaw in the dataset. Most real-world ML failures trace to data construction, not algorithms.

### 3. Detailed explanation
- **Steps:** (1) define unit of prediction, target and prediction time; (2) collect and join sources with timestamps; (3) clean (schema, ranges, units, missing values); (4) deduplicate (exact and near-duplicate); (5) label with versioned definitions (2.8); (6) **split** (2.11–2.13) respecting groups and time; (7) document (provenance, intended use, known gaps); (8) version and checksum.
- **Split by the unit that must generalize.** If users appear in many rows, a random row split puts the same user in train and test. In the lab, 1-nearest-neighbour on 60 users × 10 rows reaches 99.5% accuracy on a random row split but 44% (chance) on a user-grouped split, while the labels are random per user. 58 users appear on both sides of the random split; 0 in the grouped split.
- **Time-based splits** for forecasting or any process that evolves: train on the past, test on the future.
- **Stratification** keeps class proportions across splits (`train_val_test_indices(..., stratify=y)`), important for rare classes.
- **Point-in-time correctness:** features must be computed using only information available at the prediction time.
- **Dataset documentation** (datasheets/data cards): purpose, collection method, demographics/coverage, label process, licenses, limitations.
- **Fixed random seeds and stored split indices** make experiments reproducible.

### 4. How does it work?
Write the dataset recipe as code (not a notebook-only process), run it deterministically, and store the output with a version hash.

### 5. Simple example
Preparing exam questions: choose representative questions, remove duplicates, keep the answer key separate, and never reuse practice questions on the final exam.

### 8. Input → Process → Output
`raw sources → clean → dedupe → label → split (group/time/stratified) → versioned dataset + card`

### 9. Enterprise use case
Data platforms (Tier 38) provide lineage, quality checks, and access control; datasets are treated as versioned products with owners.

### 10. AI engineering connection
RAG corpora, fine-tuning sets and evaluation sets are constructed datasets; decontamination (removing test items from training data) is part of the process.

### 11. Advantages
Reproducibility, trustworthy evaluation, easier debugging.

### 12. Limitations
Time-consuming; some biases cannot be fixed after collection.

### 13. Trade-offs
Strict group/time splits reduce optimistic bias but leave fewer rows per split.

### 14. Common mistakes
Random-splitting grouped or temporal data; cleaning with test statistics; undocumented label versions; duplicates across splits; building features with future information.

### 15. Performance / cost
Deduplication and joins on large data need scalable tooling; store processed splits to avoid recompute.

### 16. Security
Remove or protect personal data; check licenses and consent; guard against poisoned sources.

### 17. Interview explanation
"I treat dataset construction as engineering: define the prediction unit and time, clean, deduplicate, label with versioned definitions, then split by the thing that must generalize — user, document or time — and document it. A random row split on grouped data can look 99% accurate and be chance in production."

### 18. Rapid-fire
Define → collect → clean → dedupe → label → split by group/time → document & version.
