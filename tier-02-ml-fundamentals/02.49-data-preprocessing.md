# 2.49 Data preprocessing

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: High · Hands-on: Very high
Prerequisites: 2.10, 2.33, 2.47 · Leads to: Tier 38 AI Data Engineering, 2.50 Dataset imbalance

> **In plain words**
> **Preprocessing** is **washing and chopping the ingredients before cooking**: fixing missing values, taming outliers, removing duplicates, converting categories to numbers, scaling. Models fail on dirty or inconsistent data.
> Three golden rules: **learn every statistic from the training set only**, **do it in the right order**, and **ship the same recipe to production** (package it as a pipeline). And a surprise: **missing values can carry information**, so don't just throw them away.

**You need first:** 2.10 Dataset construction, 2.33 Data leakage, 2.47 Scaling.

> **Figure 2.49-1 — the order of operations**
>
> ```mermaid
> flowchart LR
>     S["split"] --> I["impute missing<br/>(train median)"]
>     I --> C["clip outliers<br/>(train percentiles)"]
>     C --> E["encode categories"]
>     E --> SC["scale<br/>(train mean/std)"]
>     SC --> R["resample<br/>(training only)"]
>     R --> M["model"]
> ```
>
> *How to read it:* the **split comes first**; every later step learns its numbers (medians, bounds, category lists, means) on the training part and merely applies them to validation, test and production. A *pipeline* object packages exactly this chain so it can be re-used unchanged.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| imputation | filling in missing values |
| MCAR / MAR / MNAR | missing completely at random / depending on observed data / depending on the missing value itself |
| missing indicator | a 0/1 column saying "this value was missing" |
| winsorising / clipping | capping values at percentiles |
| unseen category | a category at prediction time that training never saw |
| pipeline | a fitted chain of preprocessing steps and a model |
| data contract | an agreement on the schema and ranges of the data |

### 1. What is it?
The **cleaning and preparation steps applied before modelling**: handling missing values, outliers, duplicates, types and units, encoding categories, scaling, and assembling reproducible pipelines.

### 2. Why does it exist?
Models fail on dirty or inconsistent data, and inconsistent preprocessing between training and serving is a major source of production bugs.

### 3. Detailed explanation
- **Missing values** come in types: MCAR (random), MAR (depends on other observed data), MNAR (depends on the missing value or the label itself). Options: drop rows (loses data, can bias), impute (mean, median, mode, model-based), and **add a missing-indicator feature**. If positives have more missing values than negatives, the *missingness itself carries signal*, and the indicator recovers it.
- **Impute with training statistics only** (2.33). The median is robust to outliers.
- **Outliers:** investigate first (an error, or a real extreme?). Clip (winsorise) at training percentiles, transform, or use robust models.
- **Duplicates:** exact and near-duplicates inflate scores across splits (2.10); de-duplicate before splitting.
- **Types, units, schema:** enforce types, consistent units and time zones; validate ranges; fail loudly on schema changes.
- **Categorical handling:** one-hot, ordinal, target encoding (out-of-fold), embeddings; decide what happens with **unseen categories**.
- **Pipelines:** a pipeline fits every step on the training data only and re-applies the fitted steps to new data. This reproduces a careful manual train-only fit exactly.
- **Order of operations:** split → impute → clip → encode → scale → resample (training only) → model.
- **Text and LLM preprocessing:** normalisation, de-duplication, language and PII filtering, chunking, tokenisation (Tiers 6, 20, 38).
- **Document everything:** data contracts, validation rules and the fitted artefacts (imputer medians, scaler statistics, category maps) shipped with the model.

### 4. How does it work?
Profile the data → define the cleaning rules → implement them as a pipeline → fit on training data → validate on held-out data → monitor input quality in production.

### 5. Simple example
Washing and chopping ingredients the same way every time before cooking.

**Median imputation with an indicator, by hand.** Ages `[25, 31, ?, 40, ?]`. Training median (of the known values `25, 31, 40`) = 31. Filled values: `[25, 31, 31, 40, 31]`; indicator column: `[0, 0, 1, 0, 1]`. The model can now learn "missing age" as its own signal.

### 6. Technical example
A healthcare model: impute lab values with training medians, add "lab not ordered" indicators, clip physiological outliers, one-hot encode the admission type.

### 7. Code
**① By hand (plain Python).** Impute with the training median, add an indicator, clip.

```python
train = [25, 31, None, 40, None, 38, 200]               # 200 is a suspicious outlier
known = sorted(v for v in train if v is not None)
median = known[len(known) // 2]
low, high = known[0], sorted(known)[-2]                 # crude clipping bounds from the training data
filled = [median if v is None else min(max(v, low), high) for v in train]
indicator = [1 if v is None else 0 for v in train]
print("median:", median)
print("filled & clipped:", filled)
print("missing indicator:", indicator)
```

```text
median: 38
filled & clipped: [25, 31, 38, 40, 38, 38, 40]
missing indicator: [0, 0, 1, 0, 1, 0, 0]
```

**② With NumPy and scikit-learn.** Missingness can be informative.

```python
import numpy as np
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression

rng = np.random.default_rng(0)
n = 4000
y = rng.integers(0, 2, n)
x = rng.normal(0, 1, n) + 0.4 * y
missing = rng.random(n) < np.where(y == 1, 0.6, 0.05)                     # positives are MUCH more often missing
x_obs = np.where(missing, np.nan, x)
tr, te = slice(0, 2500), slice(2500, n)

imp = SimpleImputer(strategy="median").fit(x_obs[tr].reshape(-1, 1))
X_plain = imp.transform(x_obs.reshape(-1, 1))
X_ind = np.column_stack([X_plain, np.isnan(x_obs)])                         # add the missing indicator
print("median imputation only      :", round(LogisticRegression().fit(X_plain[tr], y[tr]).score(X_plain[te], y[te]), 3))
print("median imputation + indicator:", round(LogisticRegression().fit(X_ind[tr], y[tr]).score(X_ind[te], y[te]), 3), "(missingness carried signal)")
```

```text
median imputation only      : 0.645
median imputation + indicator: 0.778 (missingness carried signal)
```

**③ With scikit-learn.** A pipeline that handles missing numbers, categories and unseen categories.

```python
import numpy as np
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

# columns: [age (may be missing), income, city]
X_train = np.array([[25, 50000, "Pune"], [31, 62000, "Goa"], [np.nan, 58000, "Pune"], [40, 90000, "Goa"],
                    [35, 71000, "Pune"], [29, 40000, "Goa"]], dtype=object)
y_train = np.array([0, 1, 0, 1, 1, 0])
numeric = make_pipeline(SimpleImputer(strategy="median", add_indicator=True), StandardScaler())
prep = ColumnTransformer([("num", numeric, [0, 1]), ("cat", OneHotEncoder(handle_unknown="ignore"), [2])])
pipe = make_pipeline(prep, LogisticRegression()).fit(X_train, y_train)                # everything is fitted on TRAIN only

X_new = np.array([[np.nan, 65000, "Delhi"]], dtype=object)                            # a missing age AND an unseen city
print("the pipeline predicts without crashing:", pipe.predict(X_new).tolist())
print("fitted medians learned from training data:", pipe.named_steps["columntransformer"].named_transformers_["num"][0].statistics_.tolist())
```

```text
the pipeline predicts without crashing: [0]
fitted medians learned from training data: [31.0, 60000.0]
```

### 9. Enterprise use case
Data-quality gates, schema registries and automated tests (Tiers 38, 34) stop bad data before it reaches models.

### 10. AI engineering connection
Document parsing and cleaning for RAG corpora, PII scrubbing, de-duplication, chunking and metadata normalisation (Tiers 20, 38).

### 11. Advantages
Reliability, reproducibility, and often large accuracy gains.

### 12. Limitations
Time-consuming; choices (imputation, clipping) embed assumptions.

### 13. Trade-offs
Aggressive cleaning removes noise but may remove real, rare signal.

### 14. Common mistakes
Imputing with global statistics; dropping missingness information; inconsistent preprocessing between training and serving; silent type coercion; cleaning test data using test statistics.

### 15. Performance / cost
Pipelines add serving latency; precompute offline where possible.

### 16. Security
Validate and sanitise inputs (injection, malformed records); strip or mask PII.

### 20. Hands-on exercise
**Goal:** see why clipping before scaling helps when outliers appear.

1. Make a feature with 200 ordinary values (around 50) plus 5 gross outliers (10,000), and a label that depends on the ordinary part.
2. Standardise the raw feature, and also clip at the training 5th–95th percentiles first, then standardise.
3. Compare logistic-regression test accuracy.

<details>
<summary>Show a solution</summary>

```python
import numpy as np
from sklearn.linear_model import LogisticRegression

rng = np.random.default_rng(0)
n = 1500
x = rng.normal(50, 10, n)
y = (x + rng.normal(0, 5, n) > 50).astype(int)
x[rng.choice(n, 40, replace=False)] = 10000.0                             # gross outliers (data errors)
tr, te = slice(0, 1000), slice(1000, n)

def accuracy(feature):
    return LogisticRegression().fit(feature[tr].reshape(-1, 1), y[tr]).score(feature[te].reshape(-1, 1), y[te])

z_raw = (x - x[tr].mean()) / x[tr].std()
lo, hi = np.percentile(x[tr], [5, 95])                                    # bounds from TRAINING data only
c = np.clip(x, lo, hi)
z_clip = (c - c[tr].mean()) / c[tr].std()
print("standardise only      :", round(accuracy(z_raw), 3))
print("clip, then standardise:", round(accuracy(z_clip), 3))
```

```text
standardise only      : 0.496
clip, then standardise: 0.872
```

</details>
