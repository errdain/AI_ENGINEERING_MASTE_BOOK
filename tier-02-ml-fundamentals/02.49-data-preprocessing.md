# 2.49 Data preprocessing

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: High · Hands-on: Very high
Prerequisites: 2.10, 2.33, 2.47 · Leads to: Tier 38 AI Data Engineering, 2.50 Dataset imbalance

### 1. What is it?
The **cleaning and preparation steps applied before modelling**: handling missing values, outliers, duplicates, types and units, encoding categories, scaling, and assembling reproducible pipelines.

### 2. Why does it exist?
Models fail on dirty or inconsistent data; consistent preprocessing between training and serving is a major source of production bugs.

### 3. Detailed explanation
- **Missing values:** types — MCAR (random), MAR (depends on observed data), MNAR (depends on the missing value or the label itself). Options: drop rows (loses data, can bias), impute (mean/median/mode, model-based), **add a missing-indicator feature**. In the lab, missingness is much more frequent for positives; median imputation alone gives 82.4% accuracy; adding an indicator gives **88.9%**: *missingness itself carried signal*.
- **Impute with training statistics only** (2.33). Median is robust to outliers.
- **Outliers:** investigate first (error vs real extreme). Winsorize/clip at training percentiles, transform, or use robust models. With 20 gross outliers (1e4) the unclipped pipeline scores 78.4% vs **81.9%** when clipping at training 5th–95th percentiles before scaling.
- **Duplicates:** exact and near-duplicates inflate scores across splits (2.10); dedupe before splitting.
- **Types, units, schema:** enforce types, consistent units and time zones; validate ranges; fail loudly on schema changes.
- **Categorical handling:** one-hot, ordinal, target encoding (out-of-fold), embeddings; define behaviour for **unseen categories** (`one_hot` raises on unseen codes).
- **Pipelines:** a pipeline object fits every step on training data only and re-applies the fitted steps to new data. Our `Pipeline` reproduces a manual train-only fit exactly (tested).
- **Order of operations:** split → impute → clip → encode → scale → resample (training only) → model.
- **Text/LLM preprocessing:** normalization, deduplication, language/PII filtering, chunking, tokenization (Tier 6, 20, 38).
- **Document everything:** data contracts, validation rules and the fitted artifacts (imputer medians, scaler stats, category maps) shipped with the model.

### 4. How does it work?
Profile data → define cleaning rules → implement as a pipeline → fit on training data → validate on held-out data → monitor input quality in production.

### 9. Enterprise use case
Data-quality gates, schema registries and automated tests (Tier 38, 34) stop bad data before it reaches models.

### 10. AI engineering connection
Document parsing/cleaning for RAG corpora, PII scrubbing, deduplication, chunking and metadata normalization (Tier 20, 38).

### 11. Advantages
Reliability, reproducibility, often large accuracy gains.

### 12. Limitations
Time-consuming; choices (imputation, clipping) embed assumptions.

### 13. Trade-offs
Aggressive cleaning removes noise but may remove real, rare signal.

### 14. Common mistakes
Imputing with global statistics; dropping missingness information; inconsistent preprocessing between training and serving; silent type coercion; cleaning test data using test statistics.

### 15. Performance / cost
Pipelines add serving latency; precompute offline where possible.

### 16. Security
Validate and sanitize inputs (injection, malformed records); strip or mask PII.

### 17. Interview explanation
"Preprocessing means validating and cleaning the data, handling missing values, outliers, duplicates and categories, then scaling, all fit on training data only and packaged as a pipeline reused at inference. Missingness can be informative, so I often add indicator features, and I monitor input quality in production."
