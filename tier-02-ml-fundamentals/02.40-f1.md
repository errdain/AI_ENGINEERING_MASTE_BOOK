> **In plain words**
> **F1** squeezes **precision and recall into one number** using the **harmonic mean**, which punishes lopsided results. With precision 0.9 and recall 0.1 the ordinary average is a flattering 0.50, but F1 is only **0.18**: you can't hide a terrible recall behind a perfect precision.
> **F-beta** lets you say which one matters more (F2 favours recall, F0.5 favours precision).

**You need first:** 2.38 Precision and 2.39 Recall.

> **Figure 2.40-1 — harmonic versus arithmetic mean**
>
> ```mermaid

> *How to read it:* the harmonic mean is pulled toward the smaller of the two values, so a model must be decent at **both** to score well.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| F1 | `2PR/(P + R) = 2TP/(2TP + FP + FN)` |
| harmonic mean | `2ab/(a + b)`: dominated by the smaller value |
| `F_β` | `(1 + β²)PR/(β²P + R)`: weights recall β times as much |
| macro-F1 | average of per-class F1 (all classes equal) |
| micro-F1 | pool all TP/FP/FN, then compute F1 |
| weighted-F1 | per-class F1 weighted by class size |
| support | the number of true examples of a class |

### 1. What is it?
The **harmonic mean of precision and recall**: `F1 = 2PR/(P + R) = 2TP / (2TP + FP + FN)`. The general `F_β` weights recall `β` times as much as precision.

### 2. Why does it exist?
One number that balances precision and recall and punishes an imbalance between them.

### 3. Detailed explanation
- **Harmonic, not arithmetic, mean:** with `P = 0.9` and `R = 0.1`, the arithmetic mean is 0.50 but F1 is **0.18**.
- **Ignores true negatives:** `F1 = 2TP/(2TP + FP + FN)`; this suits settings where negatives are plentiful and uninteresting.
- **`F_β`:** `F_β = (1 + β²)PR/(β²P + R)`. F2 favours recall, F0.5 favours precision. Example: flagging all 5 items when 4 are truly positive gives `P = 0.8`, `R = 1`: F1 is 0.889 but F2 is 0.952.
- **Multiclass averaging** (from the confusion matrix, 2.42):
  - **Macro-F1:** the average of per-class F1; treats every class equally; sensitive to rare classes.
  - **Micro-F1:** pool all TP, FP, FN; for single-label multiclass problems it equals accuracy.
  - **Weighted-F1:** per-class F1 weighted by support.
- **Threshold-dependent and not a probability metric:** F1 changes with the threshold; optimise the threshold on validation data and report it.
- **Limits in practice:** the equal weight on P and R rarely matches real costs; F1 is not calibration-aware; it is undefined (reported as 0) if nothing is predicted positive.
- **Token-level F1** is also used in extractive question answering to compare answer spans (a different object with the same formula).

### 4. How does it work?
Compute precision and recall from the confusion matrix and combine them harmonically (or compute `2TP/(2TP + FP + FN)` directly).

### 5. Simple example
A student must be good at both speed and accuracy; being perfect at one and awful at the other still fails.

**By hand.**

| `P` | `R` | arithmetic mean | F1 |
|---|---|---|---|
| 0.5 | 1.0 | 0.75 | 0.667 |
| 0.9 | 0.1 | 0.50 | **0.18** |
| 0.8 | 0.8 | 0.80 | 0.80 |

When `P = R`, F1 equals both. The more they differ, the more F1 falls below their average.

### 6. Technical example
Named-entity recognition scored with entity-level F1; an intent classifier scored with macro-F1 so common intents don't dominate.

### 7. Code
**① By hand (plain Python).**

```python
def f1(p, r):
    return 2 * p * r / (p + r) if p + r else 0.0

def fbeta(p, r, beta):
    return (1 + beta ** 2) * p * r / (beta ** 2 * p + r) if p + r else 0.0

print("P=0.9, R=0.1 -> arithmetic", (0.9 + 0.1) / 2, " F1", round(f1(0.9, 0.1), 3))
print("P=0.5, R=1.0 -> F1", round(f1(0.5, 1.0), 3))
print("P=0.8, R=1.0 -> F1", round(f1(0.8, 1.0), 3), " F2", round(fbeta(0.8, 1.0, 2), 3), " F0.5", round(fbeta(0.8, 1.0, 0.5), 3))
tp, fp, fn = 30, 10, 20
print("2TP/(2TP+FP+FN) =", round(2 * tp / (2 * tp + fp + fn), 3), " same as F1:", round(f1(tp / (tp + fp), tp / (tp + fn)), 3))
```

```text
P=0.9, R=0.1 -> arithmetic 0.5  F1 0.18
P=0.5, R=1.0 -> F1 0.667
P=0.8, R=1.0 -> F1 0.889  F2 0.952  F0.5 0.833
2TP/(2TP+FP+FN) = 0.667  same as F1: 0.667
```

**② With NumPy.** Macro versus micro F1 from a multiclass confusion matrix.

```python
import numpy as np

cm = np.array([[90, 5, 5],       # rows = true class, columns = predicted
               [10, 80, 10],
               [2, 3, 15]])      # a rare, hard third class
tp = np.diag(cm)
fp = cm.sum(axis=0) - tp
fn = cm.sum(axis=1) - tp
f1_per_class = 2 * tp / (2 * tp + fp + fn)
print("per-class F1:", f1_per_class.round(3))
print("macro-F1:", round(float(f1_per_class.mean()), 3), "  (every class counts equally)")
micro = 2 * tp.sum() / (2 * tp.sum() + fp.sum() + fn.sum())
print("micro-F1:", round(float(micro), 3), "  accuracy:", round(float(tp.sum() / cm.sum()), 3), "(equal for single-label problems)")
```

```text
per-class F1: [0.891 0.851 0.6  ]
macro-F1: 0.781   (every class counts equally)
micro-F1: 0.841   accuracy: 0.841 (equal for single-label problems)
```

**③ With scikit-learn.**

```python
import numpy as np
from sklearn.metrics import f1_score, fbeta_score

y_true = np.array([0] * 100 + [1] * 100 + [2] * 20)
y_pred = np.array([0] * 90 + [1] * 5 + [2] * 5 + [0] * 10 + [1] * 80 + [2] * 10 + [0] * 2 + [1] * 3 + [2] * 15)
for avg in ("macro", "micro", "weighted"):
    print(f"{avg:>8}-F1:", round(f1_score(y_true, y_pred, average=avg), 3))
yb = np.array([1, 1, 1, 1, 0]); pb = np.array([1, 1, 1, 1, 1])
print("binary: F1", round(f1_score(yb, pb), 3), "  F2", round(fbeta_score(yb, pb, beta=2), 3))
```

```text
   macro-F1: 0.781
   micro-F1: 0.841
weighted-F1: 0.846
binary: F1 0.889   F2 0.952
```

### 9. Enterprise use case
F1 is common on dashboards, but regulated decisions set explicit precision and recall floors rather than one F1.

### 10. AI engineering connection
Entity extraction, classification of tool-use intents, span-F1 for question answering, safety-classifier evaluation.

### 11. Advantages
A single, imbalance-aware summary.

### 12. Limitations
Weighs P and R equally, depends on the threshold, ignores TN and calibration, and hides the trade-off curve.

### 13. Trade-offs
The simplicity of F1 versus the information in the full precision–recall curve.

### 14. Common mistakes
Comparing F1 at different thresholds; mixing macro and micro; using F1 for balanced multiclass problems where accuracy suffices; optimising F1 without checking costs.

### 15. Performance / cost
`O(n)`.

### 16. Security
Gaming: tuning the threshold on the test set to maximise F1 (2.13).

### 17. Interview explanation
"F1 is the harmonic mean of precision and recall, so it punishes lopsided models: P = 0.9, R = 0.1 gives 0.18, not 0.5. It ignores true negatives, which is good for rare-event problems, but it assumes precision and recall matter equally, so I use F-beta or explicit cost-based thresholds when they don't."

### 18. Rapid-fire answer
F1 = 2PR/(P + R) = 2TP/(2TP + FP + FN); harmonic mean; macro versus micro averaging; threshold-dependent.

### 20. Hands-on exercise
**Goal:** compare the best threshold for F1 and for F2.

1. Use simulated scores (10% positives).
2. Scan thresholds 0.05 to 0.95 and find the one maximising F1 and the one maximising F2.
3. Which is lower, and why?

<details>
<summary>Show a solution</summary>

```python
import numpy as np

rng = np.random.default_rng(0)
y = (rng.random(20000) < 0.10).astype(int)
score = np.clip(0.55 * y + rng.normal(0.25, 0.18, 20000), 0, 1)

def fbeta(t, beta):
    pred = score > t
    tp = (pred & (y == 1)).sum()
    p, r = tp / max(pred.sum(), 1), tp / y.sum()
    return (1 + beta ** 2) * p * r / (beta ** 2 * p + r) if p + r else 0.0

ts = np.arange(0.05, 0.96, 0.01)
for beta in (1, 2):
    best = ts[int(np.argmax([fbeta(t, beta) for t in ts]))]
    print(f"F{beta}: best threshold {best:.2f}  (score {fbeta(best, beta):.3f})")
```

```text
F1: best threshold 0.63  (score 0.826)
F2: best threshold 0.54  (score 0.852)
```

F2 values recall more, so its best threshold is lower: it accepts more false alarms to miss fewer positives.
