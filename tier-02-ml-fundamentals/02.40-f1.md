# 2.40 F1 score

### 1. What is it?
The **harmonic mean of precision and recall**: `F1 = 2PR/(P+R) = 2TP / (2TP + FP + FN)`. The general `F_β` weights recall `β` times as much as precision.

### 2. Why does it exist?
One number that balances precision and recall and punishes imbalance between them.

### 3. Detailed explanation
- **Harmonic, not arithmetic, mean:** with P=0.9 and R=0.1, the arithmetic mean is 0.50 but F1 is **0.18**: a model that is great at one and terrible at the other cannot score well.
- **Ignores true negatives:** `F1 = 2TP/(2TP+FP+FN)`; it is therefore suited to settings where negatives are plentiful and uninteresting.
- **F_β:** `F_β = (1+β²)PR/(β²P+R)`. F2 favours recall, F0.5 favours precision. Example: predicting all 5 items positive when 4 are truly positive gives P=0.8, R=1: F1 0.889 but F2 0.952.
- **Multiclass averaging** (from the confusion matrix, 2.42):
  - **Macro-F1:** average of per-class F1; treats all classes equally; sensitive to rare classes.
  - **Micro-F1:** pool all TP/FP/FN; for single-label multiclass equals accuracy.
  - **Weighted-F1:** per-class F1 weighted by support.
  On an imbalanced 4-class example, macro-F1 is 0.921 versus micro-F1/accuracy 0.963; per-class recall ranges 0.74–1.00, which the macro figure reveals. Our macro/micro match scikit-learn.
- **Threshold-dependent and not a probability metric:** F1 changes with the threshold; optimize the threshold on validation data (`best_f1_threshold`) and report it.
- **Limitations in practice:** the equal weight on P and R rarely matches real costs; F1 is not calibration-aware; undefined (0) with no positives predicted.
- **Token-level F1** is also used in extractive QA to compare answer spans (different object, same formula).

### 4. How does it work?
Compute precision and recall from the confusion matrix, then combine harmonically (or compute `2TP/(2TP+FP+FN)` directly).

### 5. Simple example
A student must be good at both speed and accuracy; being perfect at one and awful at the other still fails.

### 6. Technical example
Named-entity recognition scored with entity-level F1; intent classifier with macro-F1 to avoid being dominated by common intents.

### 8. Input → Process → Output
`precision, recall → harmonic mean → single score`

### 9. Enterprise use case
F1 is common in dashboards, but regulated decisions set explicit precision/recall floors instead of a single F1.

### 10. AI engineering connection
Entity extraction, classification of tool-use intents, span-F1 for QA, safety classifier evaluation.

### 11. Advantages
Single, imbalance-aware summary.

### 12. Limitations
Equal P/R weighting, threshold-dependent, ignores TN and calibration, hides trade-off curve.

### 13. Trade-offs
F1 simplicity vs the information in the full precision–recall curve.

### 14. Common mistakes
Comparing F1 at different thresholds; mixing macro and micro; using F1 for balanced multi-class where accuracy suffices; optimizing F1 without checking costs.

### 15. Performance / cost
`O(n)`.

### 16. Security
Gaming: tune the threshold on the test set to maximize F1 (2.13).

### 17. Interview explanation
"F1 is the harmonic mean of precision and recall, so it punishes lopsided models: P=0.9, R=0.1 gives 0.18, not 0.5. It ignores true negatives, which is good for rare-event problems, but it assumes precision and recall matter equally, so I use F-beta or explicit cost-based thresholds when they don't."
