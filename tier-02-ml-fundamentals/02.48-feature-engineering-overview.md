# 2.48 Feature engineering overview

**Metadata** — Tier: 2 · Phase: 1 · Priority: P1 · Difficulty: 2/5 · Interview: Medium-High · Hands-on: Very high
Prerequisites: 2.7, 2.47, 2.33 · Leads to: Tier 6 Embeddings (learned features), Tier 38 Feature stores

### 1. What is it?
Creating **new input variables from raw data** so a model can find the pattern more easily: transformations, interactions, aggregations, encodings and domain-specific signals.

### 2. Why does it exist?
A better representation can matter more than a better algorithm, especially for tabular data (2.1: adding `x₁x₂` took a linear model from 45% to 96%).

### 3. Detailed explanation
Common operations:
- **Numeric transforms:** log/`log1p`/square root for skew (skewness 5.17 → 0.04), clipping, binning, ratios (debt/income), differences.
- **Interactions & polynomials:** products and powers (`poly_features`); capture non-additive effects.
- **Aggregations:** counts, sums, means over windows or groups (purchases in last 30 days), always point-in-time correct (2.33).
- **Cyclical encoding:** hour/day/month as `(sin, cos)` so 23:00 is close to 00:00. Raw hour distance 23 vs cyclic 0.26; midnight-to-noon raw 12 vs cyclic 2.0 (the maximum).
- **Categorical encodings:** one-hot (low cardinality), ordinal (true order), hashing, learned embeddings (high cardinality, Tier 6), **target encoding** (mean of the label per category).
- **Target-encoding leakage demo:** 300 categories with *no* relation to a binary label. Computed from the whole dataset, the encoding correlates 0.55 with the label (pure leakage) and a model gets 75.9% on training rows but chance (47%) on new rows. Computed **out-of-fold** the correlation is 0.03, as it should be.
- **Text/image/audio:** classical features (TF-IDF, color histograms) are being replaced by learned embeddings; the engineering moves to data and prompts (Tier 6, 17).
- **Feature selection:** drop features with no signal, near-zero variance, high correlation with others, or leakage; L1 regularization (2.32), importance with permutation tests; select inside CV folds (2.33).
- **Process:** hypothesize from domain knowledge → build → test on validation via a fixed protocol → keep what helps → document definitions and owners → monitor for drift (2.34).
- **Training/serving parity:** compute features with the same code online and offline (feature stores).
- **Deep learning shift:** networks learn features from raw data, but engineered features still help with small tabular data and with injecting constraints.

### 4. How does it work?
Brainstorm signals → implement as pure functions with timestamps → evaluate incremental value via CV → freeze definitions.

Adding a 'price per square metre' column to help predict house values faster than raw price and area alone.

### 8. Input → Process → Output
`raw data → domain-informed transformations → feature matrix`

### 9. Enterprise use case
Feature stores govern definitions, backfills and point-in-time joins so data scientists reuse trusted features.

### 10. AI engineering connection
Metadata features for retrieval filters, query rewriting signals, routing features for model gateways (Tier 16); learned embeddings as features (Tier 6).

### 11. Advantages
Large gains on tabular data; injects domain knowledge; improves interpretability.

### 12. Limitations
Needs expertise and time; can create leakage and brittleness; maintenance cost.

### 13. Trade-offs
More features: more signal but more variance and operational complexity.

### 14. Common mistakes
Using post-outcome data; target encoding without folds; creating features on the full dataset; features that can't be computed at serving time; unreproducible notebook features.

### 15. Performance / cost
Heavy aggregations can dominate serving latency; precompute and cache.

### 16. Security
Features derived from sensitive attributes (or close proxies) create legal and fairness risks.

### 17. Interview explanation
"Feature engineering turns raw data into more informative inputs — ratios, aggregates, interactions, cyclical encodings, careful categorical encodings. The big risk is leakage: target encoding and aggregates must be computed out-of-fold and point-in-time. For text and images I'd now rely on learned embeddings."

### 18. Rapid-fire
Create informative inputs (transforms, interactions, aggregates, encodings); beware leakage; ensure serving parity.
