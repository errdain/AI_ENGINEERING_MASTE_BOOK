# 2.48 Feature engineering overview

**Metadata** — Tier: 2 · Phase: 1 · Priority: P1 · Difficulty: 2/5 · Interview: Medium-High · Hands-on: Very high
Prerequisites: 2.7, 2.47, 2.33 · Leads to: Tier 6 Embeddings (learned features), Tier 38 Feature stores

> **In plain words**
> **Feature engineering** is **creating better inputs from raw data** so the model can find the pattern more easily: a ratio (debt ÷ income), a count over a time window, the hour of day written so that 23:00 is close to 00:00.
> **Better inputs often beat fancier models**, especially on tables of data. The big danger is **leakage**: an engineered feature must only use information that exists at prediction time.

**You need first:** 2.7 Features, 2.47 Scaling, 2.33 Data leakage.

> **Figure 2.48-1 — from raw data to engineered features**
>
> ```mermaid
> flowchart LR
>     R["raw data<br/>timestamp, amount,<br/>city, history"] --> T["transform<br/>(log, ratio, bins)"]
>     R --> I["interactions<br/>(x₁·x₂)"]
>     R --> A["aggregates<br/>(purchases in last 30 days)"]

>     I --> M
>     A --> M
>     E --> M

>
> *How to read it:* each family of operations turns raw columns into new columns. Every arrow must respect one rule: **the value must be computable at prediction time, using only past information.**

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| feature engineering | creating informative inputs |
| interaction | a product or combination of features |
| aggregation | counts, sums, means over a window or group |
| cyclical encoding | `(sin, cos)` for circular quantities like hour |
| one-hot / ordinal / hashing | ways to encode categories |
| target encoding | replace a category by the average label for it |
| out-of-fold | computed without the rows it will be applied to |
| point-in-time correctness | uses only past information |

### 1. What is it?
Creating **new input variables from raw data** so a model can find the pattern more easily: transformations, interactions, aggregations, encodings and domain-specific signals.

### 2. Why does it exist?
A better representation can matter more than a better algorithm, especially for tabular data (see 2.1: adding the single feature `x₁x₂` took a linear model from chance to nearly perfect).

### 3. Detailed explanation
Common operations:
- **Numeric transforms:** log, `log1p` or square root for skew, clipping, binning, ratios (debt/income), differences.
- **Interactions and polynomials:** products and powers capture non-additive effects.
- **Aggregations:** counts, sums, means over windows or groups ("purchases in the last 30 days"), always point-in-time correct (2.33).
- **Cyclical encoding:** hour, day or month as `(sin, cos)` so that 23:00 is close to 00:00. The raw distance between hours 23 and 0 is 23; the cyclic distance is small.
- **Categorical encodings:** one-hot (low cardinality), ordinal (when there is a true order), hashing, learned embeddings (high cardinality, Tier 6), and **target encoding** (the mean label per category).
- **Target-encoding leakage:** with 300 categories that have *no* relation to the label, a target encoding computed on the whole dataset appears strongly correlated with the label (pure leakage) and a model looks good on training rows but is at chance on new rows. Computed **out-of-fold**, the correlation is about 0, as it should be.
- **Text, images, audio:** classical features (TF-IDF, colour histograms) are being replaced by learned embeddings; the engineering moves to data and prompts (Tiers 6, 17).
- **Feature selection:** drop features with no signal, near-zero variance, high correlation with others, or leakage; L1 regularisation (2.32); permutation importance; select inside CV folds (2.33).
- **Process:** hypothesise from domain knowledge → build → test on validation under a fixed protocol → keep what helps → document the definitions and owners → monitor drift (2.34).
- **Training/serving parity:** compute features with the same code online and offline (feature stores).
- **Deep learning:** networks learn features from raw data, but engineered features still help with small tabular data and for injecting constraints.

### 4. How does it work?
Brainstorm signals → implement them as pure functions with timestamps → evaluate the incremental value by cross-validation → freeze the definitions.

### 5. Simple example
Adding a "price per square metre" column helps predict house values faster than raw price and area alone.

**Cyclical encoding, by hand.** Hours as points on a clock: `(sin(2πh/24), cos(2πh/24))`.

| hours | raw distance | cyclic (clock) distance |
|---|---|---|
| 23 and 0 | 23 | 0.26 (neighbours!) |
| 0 and 12 | 12 | 2.0 (opposite sides: the maximum) |

### 6. Technical example
Fraud features: velocity (transactions in the last 10 minutes), distance from the last location, deviation from the user's average spend.

### 7. Code
**① By hand (plain Python).** Ratios and cyclical hours.

```python
import math

applicant = {"income": 50000, "debt": 20000, "hour": 23}
print("debt-to-income ratio:", applicant["debt"] / applicant["income"])

def clock(h):
    a = 2 * math.pi * h / 24
    return (math.sin(a), math.cos(a))

def dist(p, q): return math.dist(p, q)
print("raw gap between hour 23 and 0:", 23, "  clock distance:", round(dist(clock(23), clock(0)), 2))
print("raw gap between hour 0 and 12:", 12, "  clock distance:", round(dist(clock(0), clock(12)), 2))
```

```text
debt-to-income ratio: 0.4
raw gap between hour 23 and 0: 23   clock distance: 0.26
raw gap between hour 0 and 12: 12   clock distance: 2.0
```

**② With NumPy.** The target-encoding leak, and the out-of-fold fix.

```python
import numpy as np

rng = np.random.default_rng(0)
n, n_cat = 1000, 300
cat = rng.integers(0, n_cat, n)
y = rng.integers(0, 2, n)                                           # labels have NOTHING to do with the category

naive = np.array([y[cat == c].mean() if (cat == c).any() else y.mean() for c in cat])      # uses each row's OWN label
print("naive target encoding: correlation with the label =", round(float(np.corrcoef(naive, y)[0, 1]), 2), "(leakage)")

oof = np.zeros(n)
folds = np.arange(n) % 5
for f in range(5):
    tr, va = folds != f, folds == f
    means = {c: y[tr & (cat == c)].mean() for c in np.unique(cat[tr])}
    oof[va] = [means.get(c, y[tr].mean()) for c in cat[va]]                                  # encode with OTHER folds only
print("out-of-fold encoding : correlation with the label =", round(float(np.corrcoef(oof, y)[0, 1]), 2), "(about zero, as it should be)")
```

```text
naive target encoding: correlation with the label = 0.55 (leakage)
out-of-fold encoding : correlation with the label = 0.04 (about zero, as it should be)
```

**③ With scikit-learn.** `TargetEncoder` does the out-of-fold step for you.

```python
import numpy as np
from sklearn.preprocessing import TargetEncoder

rng = np.random.default_rng(0)
cat = rng.integers(0, 300, (1000, 1))
y = rng.integers(0, 2, 1000)
enc = TargetEncoder(smooth="auto", cv=5, random_state=0)
z = enc.fit_transform(cat, y)                                   # cross-fitted: each row is encoded without its own label
print("TargetEncoder.fit_transform correlation with the label:", round(float(np.corrcoef(z[:, 0], y)[0, 1]), 3))
print("new category value handled gracefully:", enc.transform([[999]]).round(3).tolist(), "(falls back to the overall mean)")
```

```text
TargetEncoder.fit_transform correlation with the label: 0.054
new category value handled gracefully: [[0.506]] (falls back to the overall mean)
```

### 9. Enterprise use case
Feature stores govern definitions, backfills and point-in-time joins so data scientists reuse trusted features.

### 10. AI engineering connection
Metadata features for retrieval filters, query-rewriting signals, routing features for model gateways (Tier 16); learned embeddings as features (Tier 6).

### 11. Advantages
Large gains on tabular data; injects domain knowledge; improves interpretability.

### 12. Limitations
Needs expertise and time; can create leakage and brittleness; has a maintenance cost.

### 13. Trade-offs
More features give more signal but also more variance and operational complexity.

### 14. Common mistakes
Using post-outcome data; target encoding without folds; creating features on the full dataset; features that can't be computed at serving time; irreproducible notebook features.

### 15. Performance / cost
Heavy aggregations can dominate serving latency; precompute and cache.

### 16. Security
Features derived from sensitive attributes (or close proxies) create legal and fairness risks.

### 17. Interview explanation
"Feature engineering turns raw data into more informative inputs: ratios, aggregates, interactions, cyclical encodings, careful categorical encodings. The big risk is leakage: target encoding and aggregates must be computed out-of-fold and point-in-time. For text and images I'd now rely on learned embeddings."

### 18. Rapid-fire answer
Create informative inputs (transforms, interactions, aggregates, encodings); beware of leakage; ensure serving parity.

### 20. Hands-on exercise
**Goal:** show an interaction feature rescuing a linear model.

1. Make data where the label is `1` when `x₁` and `x₂` have the same sign.
2. Fit logistic regression on `(x₁, x₂)` and on `(x₁, x₂, x₁·x₂)`.
3. Compare the test accuracy.

<details>
<summary>Show a solution</summary>

```python
import numpy as np
from sklearn.linear_model import LogisticRegression

rng = np.random.default_rng(0)
X = rng.normal(0, 1, (1500, 2))
y = (X[:, 0] * X[:, 1] > 0).astype(int)
plain = LogisticRegression().fit(X[:1000], y[:1000])
Xi = np.column_stack([X, X[:, 0] * X[:, 1]])
inter = LogisticRegression().fit(Xi[:1000], y[:1000])
print("without the interaction:", round(plain.score(X[1000:], y[1000:]), 3))
print("with x1*x2             :", round(inter.score(Xi[1000:], y[1000:]), 3))
```

```text
without the interaction: 0.67
with x1*x2             : 0.98
```
