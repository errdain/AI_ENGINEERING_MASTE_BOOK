# 2.6 Reinforcement learning overview

**Metadata** — Tier: 2 · Phase: 1 · Priority: P1 · Difficulty: 2/5 · Interview: Medium-High · Hands-on: Medium
Prerequisites: 2.2, 1.29 · Leads to: Tier 10 RLHF/alignment, Tier 26 Agents (decision loops)

### 1. What is it?
Learning to act by **trial and error to maximize cumulative reward**. An *agent* observes a *state*, takes an *action*, receives a *reward* from the *environment*, and updates its *policy*.

### 2. Why does it exist?
Some problems have no labeled 'right action', only delayed outcomes (win/lose, user satisfied). RL optimizes behaviour against such signals.

### 3. Detailed explanation
- **Vocabulary:** state `s`, action `a`, reward `r`, policy `π(a|s)`, return (discounted sum of future rewards), value function, environment dynamics.
- **Exploration vs exploitation:** exploit what looks best now, but explore to discover better options. Pure greed can get stuck forever.
- **Demonstration (3-armed bandit, true payoff rates 0.2/0.5/0.8, 3,000 steps):** a purely greedy agent never leaves the first arm: average reward 0.199, best-arm share 0%. An ε-greedy agent (ε=0.1) reaches 0.764 average reward and pulls the best arm 92% of the time.
- **Differences from supervised learning:** feedback is evaluative (a score), not instructive (the correct answer); actions affect future data; credit assignment over time is hard.
- **In modern AI:** RLHF/RLAIF and preference optimization adapt LLMs using reward signals (Tier 10). "Agents" in Tier 26 use decision loops, but most LLM agents are *not* trained with RL; do not use the word 'agent' loosely (`GLOSSARY.md`).
- Safety: optimizing a proxy reward can be gamed ("reward hacking").

### 4. How does it work?
Loop: observe state → choose action (policy) → get reward and next state → update value/policy estimates → repeat. Bandits are the one-state special case.

### 5. Simple example
Training a dog with treats: it tries actions and learns which ones earn rewards.

### 6. Technical example
Optimizing an LLM against a learned reward model while a KL penalty (1.38) keeps it near the reference model.

### 8. Input → Process → Output
`state → policy → action → environment → reward + next state → policy update`

### 9. Enterprise use case
Recommendation/ads allocation (bandits), robotics, operations control, game AI; A/B testing is a simple exploration policy.

### 10. AI engineering connection
Preference tuning of LLMs (Tier 10), tool-use policies, exploration in online learning to rank.

### 11. Advantages
Optimizes real objectives, handles sequential decisions.

### 12. Limitations
Sample-hungry, unstable, sensitive to reward design; hard to debug and evaluate.

### 13. Trade-offs
Exploration costs short-term reward; higher ε explores more but exploits less.

### 14. Common mistakes
Reward misspecification; evaluating only on training environment; no exploration; confusing RL with 'any LLM that loops'.

### 15. Performance / cost
Often needs millions of interactions; simulators are used to avoid real-world cost.

### 16. Security
Reward hacking, unsafe exploration in the real world, and manipulation of the feedback channel.

### 17. Interview explanation
