> **In plain words**
> **Tuning** is **searching for the hyper-parameter values that give the best validation score**, under a limited compute budget. Two basic ways: **grid search** (try every combination on a grid) and **random search** (try random combinations).
> A surprising fact: with the same budget, **random search usually wins**, because it tries many *different* values of the one setting that really matters.
> And a warning: the **best of many trials is always a little lucky**, so confirm the winner on data it never influenced.

**You need first:** 2.35 Hyper-parameters, 2.12 Validation set.

### 1. What is it?
The process of **searching for the hyper-parameter values that give the best validation performance**, using grid search, random search or smarter methods, under a compute budget.

### 2. Why does it exist?
Good settings can matter as much as the choice of algorithm. A systematic search beats guesswork and is reproducible.

### 3. Detailed explanation
- **Grid search:** try every combination on a grid. Simple, but exponential in the number of hyper-parameters, and wasteful when only a few matter.
- **Random search:** sample configurations from distributions (log-uniform for rates). With the same budget it tries many *distinct* values of the important hyper-parameter. Averaged over many problems it finds a better value than a grid of the same size.
- **Smarter methods:** Bayesian optimisation (model the objective, pick promising configurations), successive halving and Hyperband (stop poor trials early), population-based training. Use them when trials are expensive (REVIEW_REQUIRED: verify details when writing the library-specific section).
- **Match the validation protocol to the data size:** a hold-out validation set for large data; k-fold cross-validation for small data (2.44); group- or time-aware folds when needed (2.10).
- **Selection optimism:** the best of many candidates is biased upward. In the experiment below, the best of 300 random classifiers on pure noise looks clearly better than chance in cross-validation and falls back to chance on fresh data. **Nested cross-validation** (an inner loop tunes, an outer loop evaluates) or a final untouched test set gives an honest estimate (2.13).
- **A practical workflow:** (1) start from sensible defaults and a baseline (2.46); (2) tune the most influential knobs first (learning rate, regularisation); (3) search coarse-to-fine; (4) fix seeds and log everything; (5) retrain the winner on train + validation; (6) evaluate on test once.
- **Budget awareness:** set a maximum number of trials or time; consider diminishing returns; prefer simplifying the model or improving the data before long searches.
- **Reproducibility:** record the data version, code version, hyper-parameters, seeds and environment.

### 4. How does it work?
Define the space → choose a method and a budget → run trials (in parallel if possible) → rank by validation metric (with spread across seeds or folds) → pick → confirm on the test set.

### 5. Simple example
Trying different oven settings, noting the results, narrowing in on the best, and having someone else taste the final cake.

**By hand.** A search over learning rates `{0.001, 0.01, 0.1}` and penalties `{0, 0.5, 1}` is a 3 × 3 grid: 9 trials, 3 distinct learning rates. If the best learning rate is 0.03, the grid never tries it. Random search with 9 trials draws 9 different learning rates, one of which is probably close.

### 6. Technical example
Random search over learning rate (log-uniform 1e-5…1e-2), weight decay and warm-up fraction, with early stopping of poor runs: 40 trials on 4 GPUs.

### 7. Code
**① By hand (plain Python).** Grid versus random: how many distinct learning rates do 9 trials cover?

```python
import random

random.seed(0)
grid = [(lr, l2) for lr in (1e-3, 1e-2, 1e-1) for l2 in (0.0, 0.5, 1.0)]
rand = [(10 ** random.uniform(-3, -1), random.uniform(0, 1)) for _ in range(9)]
print("grid  : trials", len(grid), " distinct learning rates", len({lr for lr, _ in grid}))
print("random: trials", len(rand), " distinct learning rates", len({round(lr, 6) for lr, _ in rand}))
```

```text
grid  : trials 9  distinct learning rates 3
random: trials 9  distinct learning rates 9
```

**② With NumPy.** Which finds a better configuration on average?

```python
import numpy as np

def trial_loss(lr, l2, best_lr):                                   # the learning rate matters most
    return (np.log10(lr) - np.log10(best_lr)) ** 2 + 0.02 * (l2 - 0.3) ** 2

rng = np.random.default_rng(0)
grid_best, rand_best, wins = [], [], 0
for _ in range(300):
    best_lr = 10 ** rng.uniform(-3, -1)                            # a different "true" best learning rate each time
    g = min(trial_loss(lr, l2, best_lr) for lr in (1e-3, 1e-2, 1e-1) for l2 in (0.0, 0.5, 1.0))
    r = min(trial_loss(10 ** rng.uniform(-3, -1), rng.uniform(0, 1), best_lr) for _ in range(9))
    grid_best.append(g); rand_best.append(r); wins += r < g
print(f"average best loss found with 9 trials: grid {np.mean(grid_best):.3f}   random {np.mean(rand_best):.3f}")
print(f"random search wins in {100 * wins / 300:.0f}% of the 300 problems")
```

```text
average best loss found with 9 trials: grid 0.089   random 0.028
random search wins in 80% of the 300 problems
```

**③ With scikit-learn.** Search with cross-validation, then see the selection optimism.

```python
import numpy as np
from scipy.stats import loguniform
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import RandomizedSearchCV, cross_val_score

rng = np.random.default_rng(0)
y = rng.integers(0, 2, 60)
X = rng.normal(0, 1, (60, 40))                                    # pure noise: no configuration can truly work
search = RandomizedSearchCV(LogisticRegression(max_iter=2000), {"C": loguniform(1e-4, 1e2)}, n_iter=60, cv=5, random_state=0).fit(X, y)
print("best cross-validated score found by the search:", round(search.best_score_, 3), "(optimistic: the truth is 0.5)")
nested = cross_val_score(RandomizedSearchCV(LogisticRegression(max_iter=2000), {"C": loguniform(1e-4, 1e2)}, n_iter=60, cv=5, random_state=0), X, y, cv=5)
print("nested cross-validation (honest)              :", round(nested.mean(), 3))
```

```text
best cross-validated score found by the search: 0.617 (optimistic: the truth is 0.5)
nested cross-validation (honest)              : 0.467
```

### 9. Enterprise use case
Experiment-tracking platforms schedule trials, store configurations and results, and enforce that final reports use untouched test data.

### 10. AI engineering connection
Tuning retrieval and generation settings against a development set; evaluating prompt variants with confidence intervals; LoRA hyper-parameter sweeps.

### 11. Advantages
Systematic, parallelisable, auditable.

### 12. Limitations
Expensive; overfits the validation set if overused; results vary with seeds.

### 13. Trade-offs
More trials give a higher expected best score but more selection optimism and cost.

### 14. Common mistakes
Tuning on the test set; reporting the best validation score as the expected performance; huge searches on a tiny validation set; ignoring seed variance; grid search over many dimensions.

### 15. Performance / cost
Parallelise trials; use early stopping or successive halving; reuse cached features.

### 16. Security
Search logs may contain data identifiers; protect experiment stores. Cap compute spend with budgets.

### 20. Hands-on exercise
**Goal:** see selection optimism on pure noise.

1. Make 100 examples with 20 random features and random 0/1 labels.
2. Build 300 "models", each being a random feature-sign rule (pick a random feature and a random sign), and score each on 5-fold-like halves (use the first 50 examples as "validation").
3. Pick the best on the first 50 and score the same rule on the other 50. What happens?

<details>
<summary>Show a solution</summary>

```python
import numpy as np

rng = np.random.default_rng(0)
X, y = rng.normal(0, 1, (100, 20)), rng.integers(0, 2, 100)
rules = [(rng.integers(0, 20), rng.choice([-1, 1])) for _ in range(300)]                 # 300 meaningless "models"
score = lambda rule, rows: np.mean(((rule[1] * X[rows, rule[0]]) > 0).astype(int) == y[rows])
val, fresh = np.arange(50), np.arange(50, 100)
best = max(rules, key=lambda r: score(r, val))
print("winner's score on the 'validation' half:", round(float(score(best, val)), 2), "(looks skilled)")
print("winner's score on the fresh half       :", round(float(score(best, fresh)), 2), "(back to chance)")
```

```text
winner's score on the 'validation' half: 0.62 (looks skilled)
winner's score on the fresh half       : 0.46 (back to chance)
```
