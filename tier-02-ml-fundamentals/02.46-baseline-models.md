# 2.46 Baseline models

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: High · Hands-on: Very high
Prerequisites: 2.14, 2.15, 2.13 · Leads to: every evaluation; Tier 30 Evaluation baselines

### 1. What is it?
A **simple reference model or rule** against which any proposed model must prove its value: predict the majority class or mean, repeat the last value, a linear/logistic model, a hand-written rule, or the current production system.

### 2. Why does it exist?
A metric number is meaningless without a reference. A baseline reveals how much the complexity actually buys.

### 3. Detailed explanation
- **Levels of baselines:** (1) trivial (majority class, mean/median, random); (2) naive domain heuristics (previous value, seasonal naive, keyword rules); (3) simple learned models (linear/logistic regression, small trees); (4) the incumbent production model or human performance.
- **Classification example (30% positives):** majority-class accuracy **0.696**, logistic regression **0.802** → real skill ≈ 10 points, not 80.
- **Forecasting example (random-walk-like series):** mean-forecast MSE 0.840, **naive "tomorrow = today" 0.188**, linear trend fitted on the past **1.213** (worse than the mean!). The naive baseline beats a fitted model; a "sophisticated" model must beat 0.188.
- **Baselines catch problems:** a model that barely beats the majority baseline suggests underfitting (2.26) or missing signal; a model far above any plausible ceiling suggests leakage (2.33).
- **Human baselines:** inter-annotator agreement or expert performance sets an approximate ceiling; models near it have little room left.
- **For LLM applications:** baselines include a keyword search, a template/rule system, a smaller model, the prompt-only version before RAG, or the previous release.
- **Fair comparison:** identical data splits, preprocessing and metric; tuned effort comparable (tune the baseline too); report uncertainty (2.13, 2.44).
- **Cost-aware baselines:** include latency, cost and maintainability; a 1% gain may not justify 100× cost.

### 4. How does it work?
Build the cheapest sensible baselines first; record their scores; require every later model to beat them on the same protocol.

### 5. Simple example
Before buying a faster car, time the bicycle.

### 6. Technical example
Customer-support routing: keyword rules → TF-IDF + logistic regression → fine-tuned transformer → LLM. Each step must justify its cost over the previous one.

### 8. Input → Process → Output
`task → cheapest reference → score → required improvement`

### 9. Enterprise use case
Model approval requires a baseline comparison and the incremental benefit-versus-cost case.

### 10. AI engineering connection
Prompt-only vs RAG vs fine-tuning comparisons; BM25 vs dense retrieval baselines; rule-based guardrails vs ML guardrails (Tier 30).

### 11. Advantages
Cheap, informative, prevents wasted effort.

### 12. Limitations
A weak baseline makes any model look good; a strong baseline may be hard to define.

### 13. Trade-offs
Effort spent on baselines vs on the main model, usually well spent.

### 14. Common mistakes
No baseline; comparing a tuned model against an untuned baseline; baselines evaluated on different splits; using only the majority baseline when a strong heuristic exists.

### 15. Performance / cost
Baselines are cheap and often serve as fallbacks in production.

### 16. Security
Rule-based baselines can serve as safe fallbacks when the ML system fails or is attacked.

### 17. Interview explanation
"I always build the cheapest sensible baselines first — majority class or mean, a naive heuristic like yesterday's value, a simple linear model — and make every model beat them on the same splits. In one forecasting example the naive 'tomorrow equals today' beat a fitted linear trend, which is exactly the lesson."

### 18. Rapid-fire
Majority/mean, naive heuristic, simple model, incumbent; every model must beat them on identical splits.
