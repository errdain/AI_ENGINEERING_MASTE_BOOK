# 2.46 Baseline models

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: High · Hands-on: Very high

> **In plain words**
> A **baseline** is **the simplest sensible thing you could do instead**: always predict the most common class, always predict the average, say "tomorrow equals today", or use a one-line rule.
> Any fancy model must **beat the baseline** to be worth its cost. A score means nothing without a reference: "80% accurate" is brilliant if the baseline gets 50% and a disaster if it gets 79%. Before buying a faster car, time the bicycle.

**You need first:** 2.14 Classification, 2.15 Regression, 2.13 Test set.

> **Figure 2.46-1 — a ladder of baselines**
>
> ```mermaid

> *How to read it:* climb the ladder from cheapest to most demanding. Each new model has to justify its extra cost over the rung beneath it.

**Words you'll meet on this page**

| Word | What it means here |

| majority-class baseline | always predict the commonest class |

| naive forecast | "tomorrow equals today" |

### 1. What is it?
A **simple reference model or rule** against which any proposed model must prove its value: predict the majority class or the mean, repeat the last value, a linear or logistic model, a hand-written rule, or the current production system.

### 2. Why does it exist?
A metric number is meaningless without a reference. A baseline shows how much the complexity actually buys.

### 3. Detailed explanation
- **Levels:** (1) trivial (majority class, mean or median, random); (2) naive domain heuristics (previous value, seasonal naive, keyword rules); (3) simple learned models (linear or logistic regression, small trees); (4) the incumbent production model, or human performance.
- **Classification example (30% positives):** the majority class alone gives 70% accuracy, so a model at 80% has about 10 points of real skill, not 80.
- **Forecasting example (a random-walk-like series):** "tomorrow = today" beats a fitted straight-line trend, and a fitted line can even do worse than predicting the mean. A "sophisticated" model must beat the naive forecast.
- **Baselines catch problems:** a model that barely beats the majority baseline suggests underfitting (2.26) or a missing signal; a model far above any plausible ceiling suggests leakage (2.33).
- **Human baselines:** inter-annotator agreement or expert performance sets an approximate ceiling.
- **For LLM applications:** baselines include a keyword search, a template or rule system, a smaller model, the prompt-only version before RAG, or the previous release.
- **Fair comparison:** identical data splits, preprocessing and metric; comparable tuning effort (tune the baseline too); report uncertainty (2.13, 2.44).
- **Cost-aware baselines:** include latency, cost and maintainability; a 1% gain may not justify 100× the cost.

### 4. How does it work?
Build the cheapest sensible baselines first; record their scores; require every later model to beat them under the same protocol.

### 5. Simple example
Before buying a faster car, time the bicycle.

**By hand.** 100 customers, 30 churn. "Predict nobody churns" is right 70 times: **70% accuracy** for a model that does nothing. A churn model with 80% accuracy therefore has 10 points of skill.

### 6. Technical example
Customer-support routing: keyword rules → TF-IDF + logistic regression → fine-tuned transformer → LLM. Each step must justify its cost over the previous one.

### 7. Code
**① By hand (plain Python).** The majority baseline and the "skill" over it.

```python
labels = [1] * 30 + [0] * 70                                   # 30% churn
baseline_acc = max(labels.count(0), labels.count(1)) / len(labels)
model_acc = 0.80
print("majority baseline accuracy:", baseline_acc)
print("model accuracy            :", model_acc, "-> real improvement:", round(model_acc - baseline_acc, 2))
```

```text
majority baseline accuracy: 0.7
model accuracy            : 0.8 -> real improvement: 0.1
```

**② With NumPy.** A forecasting series: mean, naive, and a fitted linear trend.

```python
import numpy as np

rng = np.random.default_rng(0)
series = np.cumsum(rng.normal(0, 1, 400))                       # random-walk-like
train, test = series[:300], series[300:]
mean_mse = np.mean((test - train.mean()) ** 2)
naive_mse = np.mean((test[1:] - test[:-1]) ** 2)                # 'tomorrow = today'
slope, intercept = np.polyfit(np.arange(300), train, 1)
trend = intercept + slope * np.arange(300, 400)
trend_mse = np.mean((test - trend) ** 2)
print(f"mean forecast MSE : {mean_mse:.3f}")
print(f"naive forecast MSE: {naive_mse:.3f}   <- hard to beat")
print(f"fitted linear trend MSE: {trend_mse:.3f}")
```

```text
mean forecast MSE : 258.767
naive forecast MSE: 0.849   <- hard to beat
fitted linear trend MSE: 146.924
```

**③ With scikit-learn.** `Dummy` models are the library's baselines.

```python
import numpy as np
from sklearn.dummy import DummyClassifier, DummyRegressor
from sklearn.linear_model import LinearRegression, LogisticRegression

rng = np.random.default_rng(0)
y = (rng.random(2000) < 0.30).astype(int)
X = rng.normal(0, 1, (2000, 4)) + 0.8 * y[:, None]
for name, model in (("majority baseline", DummyClassifier(strategy="most_frequent")), ("logistic regression", LogisticRegression())):
    print(f"{name:<20} test accuracy {model.fit(X[:1000], y[:1000]).score(X[1000:], y[1000:]):.3f}")

target = X[:, 0] * 2 + rng.normal(0, 1, 2000)
dummy, lin = DummyRegressor().fit(X[:1000], target[:1000]), LinearRegression().fit(X[:1000], target[:1000])
print(f"mean baseline R²: {dummy.score(X[1000:], target[1000:]):.3f}   linear regression R²: {lin.score(X[1000:], target[1000:]):.3f}")
```

```text
majority baseline    test accuracy 0.673
logistic regression  test accuracy 0.808
mean baseline R²: -0.001   linear regression R²: 0.825
```

### 9. Enterprise use case
Model approval requires a baseline comparison and the case for incremental benefit versus cost.

### 10. AI engineering connection
Prompt-only versus RAG versus fine-tuning comparisons; BM25 versus dense-retrieval baselines; rule-based versus ML guard-rails (Tier 30).

### 11. Advantages
Cheap, informative, and prevents wasted effort.

### 12. Limitations
A weak baseline makes any model look good; a strong baseline may be hard to define.

### 13. Trade-offs
Effort spent on baselines versus on the main model; usually well spent.

### 14. Common mistakes
No baseline; comparing a tuned model with an untuned baseline; baselines evaluated on different splits; using only the majority baseline when a strong heuristic exists.

### 15. Performance / cost
Baselines are cheap and often serve as fallbacks in production.

### 16. Security
Rule-based baselines can serve as safe fallbacks when the ML system fails or is attacked.

### 17. Interview explanation

### 20. Hands-on exercise
**Goal:** add a seasonal-naive baseline.

1. Make a series with a weekly pattern: `value = pattern[t mod 7] + noise`.
2. Compare the naive ("same as yesterday") forecast with the seasonal-naive ("same as 7 days ago") forecast.
3. Which has the lower error?

<details>
<summary>Show a solution</summary>

```python
import numpy as np

rng = np.random.default_rng(0)
pattern = np.array([10, 12, 15, 14, 18, 25, 22], dtype=float)           # weekdays vs weekend
t = np.arange(280)
series = pattern[t % 7] + rng.normal(0, 1, 280)
naive = np.mean((series[1:] - series[:-1]) ** 2)
seasonal = np.mean((series[7:] - series[:-7]) ** 2)
print(f"naive ('same as yesterday') MSE        : {naive:.2f}")
print(f"seasonal naive ('same as 7 days ago') MSE: {seasonal:.2f}")
```

```text
naive ('same as yesterday') MSE        : 34.24
seasonal naive ('same as 7 days ago') MSE: 2.10
```
