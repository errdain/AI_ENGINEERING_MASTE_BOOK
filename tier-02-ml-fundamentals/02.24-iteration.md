# 2.24 Iteration

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: Medium · Hands-on: Very high
Prerequisites: 2.21–2.23 · Leads to: Tier 4 Training loop, schedules, checkpoints

### 1. What is it?
One **parameter update**: a forward pass, loss, backward pass and optimizer step on one batch. Also called a *step*.

### 2. Why does it exist?
Schedules, logging and checkpoints are usually defined per step because it is the unit of actual parameter change.

### 3. Detailed explanation
- **Relations:** `iterations per epoch = ⌈n/B⌉`; `total steps = epochs × iterations per epoch` (for 1,050 samples, B=100, 3 epochs → 33).
- **Examples across modes:** full-batch GD: 1 iteration per epoch; pure SGD: `n` iterations per epoch (1,050 here); mini-batch: in between.
- **With gradient accumulation,** one optimizer step (a 'global step') spans several forward/backward passes (micro-steps). Be explicit about which you count (Tier 4, 4.14).
- **Learning-rate schedules, warmup, evaluation and checkpoint intervals** use global steps (Tier 4, 4.10–4.11, 4.20).
- **Training curves** are plotted against steps (or tokens) so runs with different batch sizes remain comparable if you also track samples seen.
- **Convergence in iterations vs wall-clock:** a small batch may need more iterations but less time per iteration; compare using time or compute (FLOPs), not iterations alone.

### 4. How does it work?
`step += 1` after each optimizer update; log loss, learning rate and gradient norm per step or every N steps.

### 5. Simple example
One stride on the way downhill.

### 6. Technical example
Checkpoint every 1,000 steps; warmup over the first 500 steps; evaluate every 200.

### 7. Code
```python
import mlkit as M
print(M.iterations_per_epoch(1050, 100) * 3)     # 33 steps for 3 epochs of n=1050, B=100
print(M.iterations_per_epoch(1050, 1), M.iterations_per_epoch(1050, 1050))   # pure SGD: 1050, full batch: 1
```

### 8. Input → Process → Output
`batch → forward → loss → backward → optimizer step → step counter +1`

### 9. Enterprise use case
Experiment tracking keys metrics by global step so dashboards and alerts align across runs.

### 10. AI engineering connection
LLM training logs 'steps' and 'tokens seen'; learning-rate schedules and evaluation cadence are step-based (Tier 4).

### 11. Advantages
Precise unit for scheduling and comparison.

### 12. Limitations
Not comparable across different batch sizes without samples/tokens seen.

### 13. Trade-offs
Frequent logging/eval gives visibility but adds overhead.

### 14. Common mistakes
Confusing steps with epochs; counting micro-steps as steps; schedules defined in epochs when data size changes; comparing runs by steps only.

### 15. Performance / cost
Time per step is the key profiling metric.

### 16. Security
Checkpoint cadence affects what an attacker can steal or what you can recover.

### 17. Interview explanation
"An iteration or step is one parameter update on one batch. Steps per epoch equal n divided by batch size, rounded up, and I schedule learning rate, evaluation and checkpoints by global step, taking care to count optimizer steps rather than accumulation micro-steps."

### 18. Rapid-fire
Iteration = one optimizer update; steps/epoch = ⌈n/B⌉; schedules use global steps.
