# 2.24 Iteration

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: Medium · Hands-on: Very high
Prerequisites: 2.21–2.23 · Leads to: Tier 4 Training loop, schedules, checkpoints

> **In plain words**
> An **iteration** (also called a **step**) is **one parameter update**: take one batch, run it through the model, compute the loss, work out the gradients, and nudge the weights.
> Think of one stride on the way downhill. Learning-rate schedules, logging and checkpoints are usually counted in steps, because a step is the unit in which the model actually changes.

**You need first:** 2.21 Mini-batch, 2.22 Epoch, 2.23 Batch.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| iteration / step | one optimiser update |
| global step | the running count of optimiser steps |
| micro-step | one forward/backward pass inside gradient accumulation |
| warm-up | a period of small learning rates at the start |
| checkpoint | a saved copy of the model at some step |
| samples (or tokens) seen | steps × batch size (× length) |

### 1. What is it?
One **parameter update**: a forward pass, the loss, a backward pass and an optimiser step on one batch. Also called a *step*.

### 2. Why does it exist?
Schedules, logging and checkpoints are usually defined per step, because that is the unit of actual parameter change.

### 3. Detailed explanation
- **Relations:** iterations per epoch = `⌈n/B⌉`; total steps = epochs × iterations per epoch (for 1,050 examples, `B = 100`, 3 epochs: 33).
- **Across modes:** full-batch gradient descent: 1 iteration per epoch; pure SGD: `n` iterations per epoch (1,050 here); mini-batch: in between.
- **With gradient accumulation,** one optimiser step (a "global step") spans several forward/backward passes (micro-steps). Be explicit about which one you count (Tier 4, 4.14).
- **Learning-rate schedules, warm-up, evaluation and checkpoint intervals** use global steps (Tier 4).
- **Training curves** are plotted against steps (or tokens), so that runs with different batch sizes stay comparable if you also track the samples seen.
- **Iterations versus wall-clock time:** a small batch may need more iterations but less time per iteration. Compare using time or compute (FLOPs), not iterations alone.

### 4. How does it work?
`step += 1` after every optimiser update; log the loss, the learning rate and the gradient norm each step or every N steps.

### 5. Simple example
One stride on the way downhill.

**By hand.** 10,000 examples, `B = 250`, 5 epochs → `10,000 / 250 = 40` iterations per epoch → **200** steps. If you evaluate every 50 steps you evaluate 4 times.

### 6. Technical example
Save a checkpoint every 1,000 steps; warm up the learning rate over the first 500 steps; evaluate every 200.

### 7. Code
**① By hand (plain Python).** The step-count formula in three modes.

```python
import math

def steps(n, B, epochs):
    return epochs * math.ceil(n / B)

print("3 epochs, n=1050, B=100 :", steps(1050, 100, 3))
print("pure SGD (B=1), 1 epoch   :", steps(1050, 1, 1))
print("full batch (B=n), 1 epoch :", steps(1050, 1050, 1))
print("5 epochs, n=10,000, B=250:", steps(10_000, 250, 5))
```

```text
3 epochs, n=1050, B=100 : 33
pure SGD (B=1), 1 epoch   : 1050
full batch (B=n), 1 epoch : 1
5 epochs, n=10,000, B=250: 200
```

**② With NumPy.** Compare two runs fairly: steps versus samples seen.

```python
import numpy as np

rng = np.random.default_rng(0)
X = rng.normal(0, 1, (2000, 3))
y = X @ np.array([2.0, -1.0, 0.5]) + 0.1 * rng.normal(0, 1, 2000)

def run(B, lr, steps):
    w, curve = np.zeros(3), []
    for s in range(1, steps + 1):
        idx = rng.integers(0, len(X), B)
        w -= lr * 2 * X[idx].T @ (X[idx] @ w - y[idx]) / B
        curve.append((s, s * B, float(np.mean((X @ w - y) ** 2))))
    return curve

for B in (8, 64):
    step_, seen, loss = run(B, 0.05, 100)[-1]
    print(f"B = {B:>2}: after {step_} steps = {seen:>4} samples seen, loss {loss:.4f}")
```

```text
B =  8: after 100 steps =  800 samples seen, loss 0.0105
B = 64: after 100 steps = 6400 samples seen, loss 0.0105
```

**③ With PyTorch.** Gradient accumulation: micro-steps versus optimiser steps.

```python
import torch

torch.manual_seed(0)
model = torch.nn.Linear(3, 1)
opt = torch.optim.SGD(model.parameters(), lr=0.05)
X, y = torch.randn(64, 3), torch.randn(64)
accumulation, micro_steps, optimiser_steps = 4, 0, 0
for i in range(0, 64, 8):                                    # 8 micro-batches of 8
    loss = torch.nn.functional.mse_loss(model(X[i:i + 8]).squeeze(1), y[i:i + 8]) / accumulation
    loss.backward()
    micro_steps += 1
    if micro_steps % accumulation == 0:
        opt.step(); opt.zero_grad()
        optimiser_steps += 1                                  # only now does the model change
print("micro-steps:", micro_steps, "  optimiser steps (global steps):", optimiser_steps)
```

```text
micro-steps: 8   optimiser steps (global steps): 2
```

### 9. Enterprise use case
Experiment tracking keys metrics by global step so dashboards and alerts line up across runs.

### 10. AI engineering connection
LLM training logs "steps" and "tokens seen"; learning-rate schedules and evaluation cadence are step-based (Tier 4).

### 11. Advantages
A precise unit for scheduling and comparison.

### 12. Limitations
Not comparable across different batch sizes without also tracking samples or tokens seen.

### 13. Trade-offs
Frequent logging and evaluation give visibility but add overhead.

### 14. Common mistakes
Confusing steps with epochs; counting micro-steps as steps; defining schedules in epochs when the data size changes; comparing runs by steps only.

### 15. Performance / cost
Time per step is the key profiling metric.

### 16. Security
Checkpoint cadence affects what an attacker can steal and what you can recover.

### 20. Hands-on exercise
**Goal:** compute how many optimiser steps a training plan needs.

1. 50,000 examples, micro-batch 32 on each of 4 GPUs, accumulation 2, 3 epochs.
2. Work out the global batch, the optimiser steps per epoch (round up) and the total optimiser steps.
3. Check with code.

<details>
<summary>Show a solution</summary>

```python
import math

n, micro, gpus, accum, epochs = 50_000, 32, 4, 2, 3
global_batch = micro * gpus * accum
per_epoch = math.ceil(n / global_batch)
print("global batch:", global_batch)
print("optimiser steps per epoch:", per_epoch)
print("total optimiser steps:", per_epoch * epochs)
```

```text
global batch: 256
optimiser steps per epoch: 196
total optimiser steps: 588
```
