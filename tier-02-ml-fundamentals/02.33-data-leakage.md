# 2.33 Data leakage

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: Very high · Hands-on: Very high
Prerequisites: 2.10–2.13 · Leads to: 2.44 Cross-validation, Tier 30 Evaluation, Tier 31 Monitoring

### 1. What is it?
When **information that would not be available at prediction time** enters training or model selection, making evaluation scores unrealistically good.

### 2. Why does it exist?
Leakage is one of the most common and costly ML failures: a model looks excellent in development and collapses in production.

### 3. Detailed explanation
Main forms, each demonstrated in the lab:
1. **Target leakage:** a feature that is a consequence or proxy of the label (e.g., 'refund issued' when predicting fraud). Data with *no* signal (`sep=0`) plus one label-derived feature gives **100% test accuracy** versus 50% honest.
2. **Preprocessing/selection leakage:** using the whole dataset to fit scalers, impute, select features, tune thresholds or embeddings *before* splitting. With 1,000 pure-noise features, 60 samples and random labels, selecting the 20 best features on all data and then cross-validating gives **90% accuracy**; selecting inside each training fold gives **41.7%** (chance). This is the "selection bias" trap.
3. **Temporal leakage:** random splits on time-dependent data let the model interpolate between neighbours. A 1-NN on the time index of a random walk has MSE 0.77 under a random split and **17.1** under a forward-in-time split.
4. **Group/duplicate leakage:** the same user/document/near-duplicate appears on both sides (2.10: 99.5% vs 44%).
5. **Benchmark contamination:** test items appear in (pre)training data (2.13).
6. **Tuning leakage:** repeated use of the test set to make decisions (2.12, 2.13).

- **Detection:** implausibly high scores; a single feature with outsized importance; performance that vanishes on a later time slice; train/test overlap checks (IDs, hashes, fuzzy matching); ablating suspicious features.
- **Prevention:** define the prediction time and allow only information before it (point-in-time joins); split first, then fit all preprocessing on the training portion only (pipelines/CV inside folds); split by group/time; version and dedupe datasets; lock the test set; review features with domain experts.
- **Leakage ≠ overfitting:** overfitting is fitting noise in the training data; leakage corrupts the *evaluation* so the result is wrong regardless of model.

### 4. How does it work?
Walk the pipeline step by step asking: 'at prediction time, would I have this information, and was it computed using only training data?'

### 5. Simple example
A student who saw the exam questions in advance scores 100% but hasn't learned the subject.

### 6. Technical example
Predicting hospital readmission using a 'discharge summary' field written after the readmission decision; a RAG evaluation whose gold passages were included in the prompt template.

### 8. Input → Process → Output
`future/label information leaks into features or selection → inflated validation score → production failure`

### 9. Enterprise use case
Feature stores with point-in-time correctness and CI checks for train/test overlap prevent leakage at scale.

### 10. AI engineering connection
Prompt-tuning on the eval set, evaluation questions present in the retrieval corpus, test data in fine-tuning sets, LLM judges that see reference answers they should not.

### 11. Advantages
(Of understanding it) the fastest way to explain 'too good to be true' results.

### 12. Limitations
Subtle leaks can pass reviews; no tool catches them all.

### 13. Trade-offs
Strict isolation costs data and engineering effort but protects credibility.

### 14. Common mistakes
Fitting scalers/PCA/encoders on all data; oversampling before splitting; random split of time series; features derived from post-outcome events; reusing validation for final reporting.

### 15. Performance / cost
Pipelines that recompute preprocessing per fold cost more compute: acceptable.

### 16. Security
Leakage can also mean data exfiltration (sensitive information flows into places it shouldn't); different problem, same word: say which.

### 17. Interview explanation
"Data leakage is when information not available at prediction time reaches training or model selection, so the evaluation is too optimistic. The classic cases are target leakage, preprocessing or feature selection on the full dataset, and random splits on time-ordered or grouped data. I prevent it by splitting first, fitting everything inside the training fold, splitting by time or group, and being suspicious of results that look too good."

### 18. Rapid-fire
Information from outside the training/prediction-time boundary inflates scores; split first, fit inside folds, split by time/group.
