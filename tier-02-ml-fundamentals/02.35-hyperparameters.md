# 2.35 Hyperparameters

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: High · Hands-on: Very high
Prerequisites: 2.18, 2.25 · Leads to: 2.36 Tuning, Tier 4 training configuration

### 1. What is it?
Settings that **control the learning process or model structure and are set before (not learned by) training**: learning rate, batch size, epochs, regularization strength, tree depth, number of layers/units, `k` in k-means, decision threshold, chunk size in RAG.

### 2. Why does it exist?
The same algorithm with different hyperparameters can underfit, overfit or diverge; they must be chosen deliberately.

### 3. Detailed explanation
- **Parameters vs hyperparameters:** parameters (weights) are learned by optimization; hyperparameters are chosen by you and (indirectly) tuned using validation performance (2.12).
- **Groups:** *optimization* (learning rate 2.25, batch size 2.21, epochs 2.22, optimizer, schedule), *regularization* (λ, dropout rate, weight decay 2.32), *architecture/capacity* (depth, width, polynomial degree), *data/pipeline* (augmentation, class weights, scaling method, sequence length), *decision* (threshold, `k`).
- **Scales matter:** many are best searched on a log scale (learning rate 1e-5…1e-1, λ 1e-6…10). Others are categorical (optimizer type) or integer (depth).
- **Importance is uneven:** often one or two hyperparameters (typically the learning rate) dominate, which is why random search beats grid search (2.36).
- **Interactions:** learning rate and batch size, λ and model size, epochs and learning-rate schedule.
- **Defaults are starting points**, tuned for typical conditions; document the values used in every experiment, with seed and data version.
- **Not hyperparameters:** the learned weights, activations, and running statistics. **Prompt text** in LLM applications behaves like a hyperparameter set (temperature, top-p, max tokens, few-shot count, chunk size, top-k) and deserves the same discipline (Tier 17, 20).
- **Hyperparameter choice leaks information from the validation set** (2.12); the final test estimate must remain untouched (2.13).

### 4. How does it work?
Define the search space with ranges and scales → choose a tuning method (2.36) → evaluate configs on validation data → select → retrain → test once.

### 5. Simple example
The oven temperature and baking time: not part of the cake, but they decide how it turns out.

### 6. Technical example
LoRA rank 16, learning rate 2e-4, 3 epochs, warmup 3%, batch size 32 are hyperparameters of a fine-tune.

### 7. Code
```python
import numpy as np, mlkit as M
space = {'lr': lambda r: 10 ** r.uniform(-4, -1), 'l2': lambda r: r.uniform(0, 1)}    # log-uniform lr, uniform l2
best, score, hist = M.random_search(lambda p: (np.log10(p['lr']) + 2) ** 2 + (p['l2'] - 0.1) ** 2, space, 50, seed=0)
```

### 8. Input → Process → Output
`config (hyperparameters) → training procedure → model → validation score`

### 9. Enterprise use case
Configurations are stored as code/YAML with versioning so any model can be reproduced and audited.

### 10. AI engineering connection
Temperature/top-p, retrieval top-k, chunk size/overlap, reranker depth, agent step limits: all are tunable hyperparameters evaluated on a development set.

### 11. Advantages
Direct control of behaviour and cost.

### 12. Limitations
Many interacting settings; search is expensive; results depend on data and seeds.

### 13. Trade-offs
Wider searches find better configs but cost compute and risk overfitting the validation set.

### 14. Common mistakes
Tuning on the test set; searching on a linear scale for rates; changing many settings at once; not recording configs; trusting a single seed's best result.

### 15. Performance / cost
Each trial is a full (or truncated) training run; budget with early-stopping rules.

### 16. Security
Hyperparameters like temperature and max tokens affect safety and cost exposure (Tier 32); cap user-controllable values.

### 17. Interview explanation
"Hyperparameters are the settings I choose before training, like learning rate, batch size, regularization strength and model size, as opposed to parameters that are learned. They usually act on a log scale, a few dominate, and I tune them against a validation set while keeping the test set untouched."

### 18. Rapid-fire
Pre-set controls (lr, batch, λ, depth, threshold) tuned on validation; parameters are learned.
