# 2.18 Objective functions

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: High · Hands-on: High
Prerequisites: 2.17, 1.45 · Leads to: 2.32 Regularisation, 2.35 Hyper-parameters, Tier 10 Alignment objectives

> **In plain words**
> The **objective** is **the full thing the optimiser tries to make small**. Usually it is the **average loss** (how wrong the predictions are) **plus a penalty** that discourages needlessly complicated models.
> It is "get the answers right, **but** don't make the solution absurd". The knob `λ` sets how much the penalty counts. And remember: the objective is what you *minimise*; the **metric** is what you *report*. They are not the same thing.

**You need first:** 2.17 Loss functions.

> **Figure 2.18-1 — objective = data loss + penalty**
>
> ```mermaid
> flowchart LR
>     D["data loss<br/>(average of ℓ over examples)"] --> J["objective J(θ)"]
>     P["penalty λ·R(θ)<br/>(e.g. λ × sum of squared weights)"] --> J
>     J --> O["optimiser minimises J"]
>     O --> M["metric on validation data<br/>(what you report)"]
> ```
>
> *How to read it:* the optimiser only ever sees `J`. A bigger `λ` makes the penalty louder, so it accepts a slightly worse data fit in exchange for smaller, steadier weights. The metric is checked separately on validation data and may move differently from `J`.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| loss `ℓ` | error on one example (2.17) |
| objective `J` | total quantity minimised: data loss + penalties |
| regularisation | a penalty that favours simpler models |
| ridge / L2 | penalty `λ·Σ wᵢ²` |
| lasso / L1 | penalty `λ·Σ \|wᵢ\|` |
| `λ` | strength of the penalty (a hyper-parameter) |
| Goodhart's law | when a measure becomes the target, it stops being a good measure |

### 1. What is it?
The **total quantity the optimiser minimises (or maximises)**: typically the average data loss plus regularisation terms, possibly constraints or extra goals.

### 2. Why does it exist?
Real training goals include more than fitting the data: keep weights small, stay near a reference model, balance several tasks. The objective combines them in one number.

### 3. Detailed explanation
- **Typical form:** `J(θ) = (1/n) Σ ℓ(f(xᵢ; θ), yᵢ) + λ·R(θ)`, with `R = ‖θ‖₂²` (ridge or weight decay) or `‖θ‖₁` (lasso).
- **Terminology:** "loss" usually means the per-example error; "cost" or "objective" the whole function being optimised. Papers use these loosely; this book uses *loss* for `ℓ` and *objective* for `J`.
- **Regularisation as a prior:** L2 corresponds to a Gaussian prior on the weights, L1 to a Laplace prior (1.34).
- **Effect of `λ`:** as `λ` grows, the weights shrink and the data loss rises slightly: shrinkage trades fit for stability (2.32).
- **Objective ≠ metric.** A model that minimises log-loss on a dataset with 20% positives can still have a mediocre F1 at threshold 0.5; tuning the threshold changes F1 without changing the objective (2.40, 2.45).
- **Several goals at once:** weighted sums (task loss + helper losses); RLHF maximises reward minus `β·KL` (1.38). The weights between terms are hyper-parameters (2.35).
- **Convexity (1.45):** convex objectives (linear and logistic regression with convex penalties) have a global optimum; deep-network objectives do not.
- **Constraints** are handled by penalties, projections or Lagrangian methods.

### 4. How does it work?
Define `J` → differentiate (autodiff) → the optimiser steps along `−∇J` → monitor both the objective and the validation metric.

### 5. Simple example
Not just "get the answer right" but "get it right without making the solution absurdly complicated".

**By hand: one weight.** Data: `x = 1, y = 2`. Model `ŷ = w·x`. Data loss `(w − 2)²`. Penalty `λ w²` with `λ = 1`.

| `w` | data loss | penalty | objective `J` |
|---|---|---|---|
| 2.0 | 0 | 4 | 4 |
| 1.5 | 0.25 | 2.25 | 2.5 |
| **1.0** | 1 | 1 | **2** |
| 0.5 | 2.25 | 0.25 | 2.5 |

Without a penalty the best `w` is 2 (perfect fit); with `λ = 1` the best is `w = 1`: shrunk toward 0.

### 6. Technical example
Fine-tuning with weight decay `λ = 0.01`; a distillation objective `α·CE(y) + (1 − α)·KL(teacher‖student)`.

### 7. Code
**① By hand (plain Python).** Scan `w` and find the objective's minimum for several `λ`.

```python
def best_w(lam):
    ws = [i / 100 for i in range(0, 301)]
    J = lambda w: (w - 2) ** 2 + lam * w ** 2              # data loss + penalty
    return min(ws, key=J)

for lam in (0, 0.1, 1, 10):
    print(f"lambda = {lam:>4}: best w = {best_w(lam):.2f}   (closed form 2/(1+lambda) = {2 / (1 + lam):.2f})")
```

```text
lambda =    0: best w = 2.00   (closed form 2/(1+lambda) = 2.00)
lambda =  0.1: best w = 1.82   (closed form 2/(1+lambda) = 1.82)
lambda =    1: best w = 1.00   (closed form 2/(1+lambda) = 1.00)
lambda =   10: best w = 0.18   (closed form 2/(1+lambda) = 0.18)
```

**② With NumPy.** Ridge regression: the closed form shrinks the coefficients as `λ` grows.

```python
import numpy as np

rng = np.random.default_rng(0)
X = rng.normal(0, 1, (40, 6))
y = 2 * X[:, 0] - X[:, 1] + rng.normal(0, 1, 40)              # only 2 of the 6 features matter
Xc, yc = X - X.mean(axis=0), y - y.mean()
for lam in (0, 1, 10, 100):
    w = np.linalg.solve(Xc.T @ Xc + lam * np.eye(6), Xc.T @ yc)     # ridge solution
    data_loss = np.mean((yc - Xc @ w) ** 2)
    print(f"lambda = {lam:>3}: coefficient norm {np.linalg.norm(w):.2f}   data loss {data_loss:.2f}")
```

```text
lambda =   0: coefficient norm 2.42   data loss 1.03
lambda =   1: coefficient norm 2.35   data loss 1.04
lambda =  10: coefficient norm 1.86   data loss 1.29
lambda = 100: coefficient norm 0.65   data loss 3.77
```

**③ With scikit-learn.** Objective versus metric: log-loss and F1 are different questions.

```python
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import f1_score, log_loss

rng = np.random.default_rng(0)
y = (rng.random(2000) < 0.2).astype(int)                         # 20% positives
X = rng.normal(0, 1, (2000, 3)) + 1.0 * y[:, None]
model = LogisticRegression().fit(X[:1000], y[:1000])
p = model.predict_proba(X[1000:])[:, 1]
yt = y[1000:]
print("log loss (the objective):", round(log_loss(yt, p), 3))
for t in (0.5, 0.3, 0.2):
    print(f"F1 at threshold {t}: {f1_score(yt, p > t):.3f}")
```

```text
log loss (the objective): 0.34
F1 at threshold 0.5: 0.619
F1 at threshold 0.3: 0.654
F1 at threshold 0.2: 0.632
```

### 8. Input → Process → Output
`data loss + λ·penalty (+ other terms) → J(θ) → optimiser`

<summary><b>Beyond the basics (sections 9–16)</b> — real-world use, limits, mistakes. Skip on a first read.</summary>

### 9. Enterprise use case
Governance often adds constraints (fairness, monotonicity, latency budgets) as extra terms or after-the-fact rules.

### 10. AI engineering connection
Weight decay in AdamW (Tiers 3–4), RLHF and DPO objectives (Tier 10), multi-task losses in embedding training (Tier 6).

### 11. Advantages
One mathematical object captures all the training goals.

### 12. Limitations
The weights between terms are somewhat arbitrary; an unsuitable objective is optimised very efficiently toward the wrong goal.

### 13. Trade-offs
More regularisation: a simpler, steadier model. Less: lower training error and higher variance.

### 14. Common mistakes
Regularising the intercept or unscaled features unequally; tuning `λ` on test data; confusing objective with metric; forgetting that weight decay and L2 differ under adaptive optimisers (REVIEW_REQUIRED, Tier 4).

### 15. Performance / cost
Extra terms add compute only when they are costly (for example a KL term that needs a pass through a reference model).

### 16. Security
Objectives that reward a proxy invite gaming (Goodhart's law). Monitor outcomes the proxy does not cover.

### 17. Interview explanation
"The objective is what the optimiser actually minimises: the average data loss plus regularisation or other terms. I keep it separate from the evaluation metric, tune the trade-off weights on validation data, and remember that a good objective value doesn't automatically mean a good business metric."

### 18. Rapid-fire answer
Objective = data loss + penalties; different from the evaluation metric; `λ` trades fit for simplicity.

### 20. Hands-on exercise
**Goal:** choose `λ` using validation data.

1. Make 40 training and 200 validation points with 20 pure-noise features (and 2 useful ones).
2. Fit ridge regression for `λ` = 0, 0.1, 1, 10, 100.
3. Print the validation MSE; which `λ` is best?

<details>
<summary>Show a solution</summary>

```python
import numpy as np

rng = np.random.default_rng(0)
d = 22
w_true = np.zeros(d); w_true[:2] = [2.0, -1.0]
Xtr, Xva = rng.normal(0, 1, (40, d)), rng.normal(0, 1, (200, d))
ytr = Xtr @ w_true + rng.normal(0, 1, 40)
yva = Xva @ w_true + rng.normal(0, 1, 200)
for lam in (0, 0.1, 1, 10, 100):
    w = np.linalg.solve(Xtr.T @ Xtr + lam * np.eye(d), Xtr.T @ ytr)
    print(f"lambda = {lam:>5}: validation MSE {np.mean((yva - Xva @ w) ** 2):.3f}")
```

```text
lambda =     0: validation MSE 2.508
lambda =   0.1: validation MSE 2.480
lambda =     1: validation MSE 2.318
lambda =    10: validation MSE 2.312
lambda =   100: validation MSE 4.160
```

A moderate `λ` helps; too large a penalty underfits.
