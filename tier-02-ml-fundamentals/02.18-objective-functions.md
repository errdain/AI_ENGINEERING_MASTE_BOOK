# 2.18 Objective functions

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: High · Hands-on: High
Prerequisites: 2.17, 1.45 · Leads to: 2.32 Regularization, 2.35 Hyperparameters, Tier 10 Alignment objectives

### 1. What is it?
The **total quantity the optimizer minimizes (or maximizes)**: typically the average data loss plus regularization terms, possibly constraints or extra goals.

### 2. Why does it exist?
Real training goals include more than fitting the data: keep weights small, stay near a reference model, balance several tasks. The objective combines them.

### 3. Detailed explanation
- **Typical form:** `J(θ) = (1/n) Σ ℓ(f(xᵢ;θ), yᵢ) + λ·R(θ)`, with `R = ‖θ‖₂²` (ridge / weight decay) or `‖θ‖₁` (lasso).
- **Terminology:** 'loss' usually means the per-example error; 'cost' or 'objective' the full function being optimized. Papers use these loosely; this book uses *loss* for `ℓ`, *objective* for `J`.
- **Regularization as a prior:** L2 corresponds to a Gaussian prior on weights, L1 to Laplace (1.34).
- **Effect of λ (6 features, 40 samples, only 2 informative):** coefficient norm 2.42 at λ=0 → 2.35 at λ=1 → 1.86 at λ=10, while the data loss rises 1.03 → 1.04 → 1.29: shrinkage trades fit for stability (2.32).
- **Objective ≠ metric.** A logistic model on a 20%-positive dataset minimizes log loss (0.303 in the lab) yet its F1 at threshold 0.5 is 0.65; after threshold tuning F1 changes without changing the objective (2.40, 2.45).
- **Multi-objective training:** weighted sums (task loss + auxiliary losses); RLHF maximizes reward minus `β·KL` (1.38). Weights between terms are hyperparameters (2.35).
- **Convexity (1.45):** convex objectives (linear/logistic regression, with convex regularizers) have a global optimum; deep-network objectives do not.
- **Constraint handling:** penalties, projections, or Lagrangian methods.

### 4. How does it work?
Define `J` → differentiate (autodiff) → optimizer steps along `−∇J` → monitor both the objective and the validation metric.

### 5. Simple example
Not just 'get the answer right' but 'get it right without making the solution absurdly complicated'.

### 6. Technical example
Fine-tuning with weight decay `λ=0.01`; distillation objective `α·CE(y) + (1−α)·KL(teacher‖student)`.

### 7. Code
```python
import mlkit as M
X, y = M.make_linear(40, w=(2, -1, 0, 0, 0, 0), noise=1.0, seed=0)
for lam in (0, 1, 10):
    m = M.LinearRegression(ridge=lam).fit(X, y)
    print(lam, round(float((m.coef_ ** 2).sum() ** .5), 2), round(M.mse(y, m.predict(X)), 2))   # shrinks as λ grows
```
TESTED (`ex_2_18`; ridge solution equals scikit-learn `Ridge`).

### 8. Input → Process → Output
`data loss + λ·penalty (+ other terms) → J(θ) → optimizer`

### 9. Enterprise use case
Governance often adds constraints (fairness, monotonicity, latency budgets) as extra terms or post-hoc rules.

### 10. AI engineering connection
Weight decay in AdamW (Tier 4/3), RLHF/DPO objectives (Tier 10), multi-task losses in embedding training (Tier 6).

### 11. Advantages
One mathematical object captures all training goals.

### 12. Limitations
Weights between terms are arbitrary; an unsuitable objective optimizes the wrong thing very efficiently.

### 13. Trade-offs
Larger regularization = simpler, more stable model; smaller = lower training error and higher variance.

### 14. Common mistakes
Regularizing the intercept or unscaled features unequally; tuning λ on test data; confusing objective with metric; forgetting that weight decay and L2 differ under adaptive optimizers (REVIEW_REQUIRED, Tier 4).

### 15. Performance / cost
Extra terms add compute only if costly (e.g., a KL needing a reference-model pass).

### 16. Security
Objectives that reward a proxy invite gaming (Goodhart); monitor outcomes the proxy does not cover.

### 17. Interview explanation
"The objective is what the optimizer actually minimizes: the average data loss plus regularization or other terms. I keep it separate from the evaluation metric, tune the trade-off weights on validation data, and remember that a good objective value doesn't automatically mean a good business metric."

### 18. Rapid-fire
Objective = data loss + penalties; differs from the evaluation metric; λ trades fit for simplicity.
