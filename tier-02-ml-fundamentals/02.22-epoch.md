> **In plain words**
> An **epoch** is **one complete pass through the whole training dataset**: every training example has been used once.
> Models rarely learn from a single pass, so training runs for many epochs. Like reading a textbook cover to cover once, twice, three times… The number of epochs is a setting you choose, and the right amount is found by watching the **validation** loss.

**You need first:** 2.21 Mini-batch training.

> *How to read it:* a training run is made of epochs; each epoch is made of batches; each batch triggers one update (an *iteration*, 2.24). With `n = 1050` and `B = 100`, one epoch is 11 iterations, so 3 epochs are 33.

### 1. What is it?
One **complete pass of the training algorithm over the entire training dataset**: every training example is used once.

### 2. Why does it exist?
Learning usually needs many passes. Epochs are the natural unit for counting progress and for scheduling evaluations.

### 3. Detailed explanation
- **Epochs × iterations:** iterations per epoch = `⌈n/B⌉` (or `⌊n/B⌋` with drop-last); total iterations = epochs × that (2.24). For `n = 1050`, `B = 100` and 3 epochs, that is 33 updates.
- **The number of epochs is a hyper-parameter** (2.35). Too few: underfitting (2.26). Too many: overfitting (2.27). Use **early stopping** on validation loss.
- **Shuffle every epoch** so batches differ from pass to pass.
- **Large-scale pretraining** often does less than one epoch over a huge corpus, or a few epochs over high-quality data; repeating data many times risks memorisation. Describe such runs by **tokens or steps** rather than epochs.
- **Evaluation:** compute validation metrics and save checkpoints at epoch (or step) boundaries.
- **Don't confuse** epoch (a pass over the data), **iteration** (one update) and **batch** (a group of examples) (2.23, 2.24).

### 4. How does it work?
`for epoch in range(E): shuffle(data); for batch in batches: update; then evaluate`.

### 5. Simple example
Reading the whole textbook once = one epoch.

**By hand.** 1,000 examples, batch size 250, 5 epochs:
- iterations per epoch = 1,000 / 250 = 4;
- total updates = 5 × 4 = 20;
- examples seen = 5 × 1,000 = 5,000 (each example 5 times).

### 6. Technical example
Fine-tuning a classifier for 3 epochs with early stopping (patience 1) on the validation loss.

### 7. Code
**① By hand (plain Python).** The loop structure and the counts.

```python
n, B, epochs = 1050, 100, 3
updates = 0
for epoch in range(1, epochs + 1):
    for start in range(0, n, B):                  # one batch per step
        updates += 1
    print(f"after epoch {epoch}: {updates} updates so far")
print("formula: epochs * ceil(n / B) =", epochs * -(-n // B))
```

```text
after epoch 1: 11 updates so far
after epoch 2: 22 updates so far
after epoch 3: 33 updates so far
formula: epochs * ceil(n / B) = 33
```

**② With NumPy.** Early stopping with patience: stop when validation loss stops improving.

```python
import numpy as np

rng = np.random.default_rng(0)
n_train, n_val, d = 30, 300, 60
w_true = np.zeros(d); w_true[:5] = 1.0
Xtr, Xva = rng.normal(0, 1, (n_train, d)), rng.normal(0, 1, (n_val, d))
ytr = Xtr @ w_true + rng.normal(0, 2, n_train)
yva = Xva @ w_true + rng.normal(0, 2, n_val)

w = np.zeros(d)
best, best_epoch, patience, bad = np.inf, 0, 5, 0
for epoch in range(1, 301):
    w -= 0.01 * (2 / n_train) * Xtr.T @ (Xtr @ w - ytr)               # one full-batch epoch
    val = np.mean((Xva @ w - yva) ** 2)
    if val < best:
        best, best_epoch, bad = val, epoch, 0
    else:
        bad += 1
    if bad >= patience:
        print(f"stopped at epoch {epoch}: no improvement for {patience} epochs; best was epoch {best_epoch} (validation loss {best:.2f})")
        break
```

```text
stopped at epoch 21: no improvement for 5 epochs; best was epoch 16 (validation loss 7.78)
```

**③ With PyTorch.** A `DataLoader` loop that counts epochs and iterations.

```python
import torch
from torch.utils.data import DataLoader, TensorDataset

X = torch.randn(1050, 4)
y = X.sum(dim=1)
loader = DataLoader(TensorDataset(X, y), batch_size=100, shuffle=True)         # reshuffled at the start of each epoch
model = torch.nn.Linear(4, 1)
opt = torch.optim.SGD(model.parameters(), lr=0.05)
steps = 0
for epoch in range(3):
    for xb, yb in loader:
        opt.zero_grad()
        torch.nn.functional.mse_loss(model(xb).squeeze(1), yb).backward()
        opt.step()
        steps += 1
    print(f"epoch {epoch + 1} finished, total optimiser steps: {steps}")
```

```text
epoch 1 finished, total optimiser steps: 11
epoch 2 finished, total optimiser steps: 22
epoch 3 finished, total optimiser steps: 33
```

### 9. Enterprise use case
Training dashboards plot metrics per epoch or step; budgets and schedules are expressed in epochs or tokens.

### 10. AI engineering connection
LLM training budgets are measured in tokens or steps; fine-tuning on small datasets typically uses 1–5 epochs (REVIEW_REQUIRED: a rule of thumb, not a law).

### 11. Advantages
An easy-to-understand progress unit.

### 12. Limitations
Meaningless for streaming or endless data; hides the effect of batch size.

### 13. Trade-offs
More epochs lower the training loss with diminishing returns and a rising risk of overfitting.

### 14. Common mistakes
Comparing runs by epochs when batch sizes differ; not shuffling; training a fixed number of epochs regardless of validation behaviour.

### 15. Performance / cost
Epoch time = iterations × time per iteration.

### 16. Security
Many epochs on small, sensitive datasets increase memorisation risk.

### 20. Hands-on exercise
**Goal:** find the best epoch from a loss curve.

1. Use the NumPy setup above, but run all 100 epochs without stopping.
2. Record the training and validation loss each epoch.
3. Print the epoch with the lowest validation loss, and the training loss at that epoch and at epoch 100.

<details>
<summary>Show a solution</summary>

```python
import numpy as np

rng = np.random.default_rng(0)
n_train, n_val, d = 30, 300, 60
w_true = np.zeros(d); w_true[:5] = 1.0
Xtr, Xva = rng.normal(0, 1, (n_train, d)), rng.normal(0, 1, (n_val, d))
ytr = Xtr @ w_true + rng.normal(0, 2, n_train)
yva = Xva @ w_true + rng.normal(0, 2, n_val)

w, train_loss, val_loss = np.zeros(d), [], []
for _ in range(100):
    w -= 0.01 * (2 / n_train) * Xtr.T @ (Xtr @ w - ytr)
    train_loss.append(np.mean((Xtr @ w - ytr) ** 2))
    val_loss.append(np.mean((Xva @ w - yva) ** 2))
best = int(np.argmin(val_loss)) + 1
print("best epoch:", best, " validation loss there:", round(val_loss[best - 1], 2))
print("training loss at the best epoch:", round(train_loss[best - 1], 2), "  at epoch 100:", round(train_loss[-1], 3), "(keeps falling)")
print("validation loss at epoch 100:", round(val_loss[-1], 2), "(worse: overfitting)")
```

```text
best epoch: 16  validation loss there: 7.78
training loss at the best epoch: 2.79   at epoch 100: 0.144 (keeps falling)
validation loss at epoch 100: 8.65 (worse: overfitting)
```
