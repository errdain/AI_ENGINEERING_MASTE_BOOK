# 2.22 Epoch

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: Medium · Hands-on: Very high
Prerequisites: 2.21 · Leads to: 2.23 Batch, 2.24 Iteration, 2.27 Overfitting (early stopping)

### 1. What is it?
One **complete pass of the training algorithm over the entire training dataset**: every training sample is used once.

### 2. Why does it exist?
Learning usually needs many passes. Epochs are the natural unit for counting training progress and scheduling evaluations.

### 3. Detailed explanation
- **Epochs × iterations:** `iterations per epoch = ⌈n/B⌉` (or `⌊n/B⌋` with drop-last); total iterations = epochs × that (2.24). For `n=1050`, `B=100`, 3 epochs: 33 iterations (verified by counting updates).
- **Number of epochs is a hyperparameter** (2.35). Too few: underfitting (2.26). Too many: overfitting (2.27). Use early stopping on validation loss.
- **Shuffle each epoch** so batches differ between passes.
- **Large-scale pretraining** often does less than one epoch over huge corpora or a few epochs over high-quality data; repeating data many times risks memorization. Describe training by **tokens/steps** rather than epochs when datasets are streamed.
- **Epoch-end evaluation:** compute validation metrics and save checkpoints at epoch (or step) boundaries.
- **Don't confuse** the epoch (a pass over the data) with an iteration (one parameter update) or a batch (a group of samples) (2.23, 2.24).

### 4. How does it work?
`for epoch in range(E): shuffle(data); for batch in batches: update; evaluate`.

### 6. Technical example
Fine-tuning a classifier for 3 epochs with early stopping patience 1 on validation loss.

### 7. Code
```python
import mlkit as M
X, y = M.make_linear(1050, noise=0.1, seed=0)
_, _, h = M.sgd_linear(X, y, lr=0.05, batch_size=100, epochs=3)
print(h['iterations'])      # [11, 22, 33]   — cumulative updates after each epoch
```

### 8. Input → Process → Output
`full pass over the training set → one epoch`

### 9. Enterprise use case
Training dashboards plot metrics per epoch/step; budgets and schedules are expressed in epochs or tokens.

### 10. AI engineering connection
LLM training budgets are measured in tokens/steps; fine-tuning on small datasets uses 1–5 epochs typically (REVIEW_REQUIRED: rule-of-thumb, not a law).

### 11. Advantages
Easy-to-understand progress unit.

### 12. Limitations
Meaningless for streaming/infinite data; hides batch size effects.

### 13. Trade-offs
More epochs improve training loss with diminishing returns and rising overfitting risk.

### 14. Common mistakes
Comparing runs by epochs with different batch sizes; not shuffling; training for a fixed number of epochs regardless of validation behaviour.

### 15. Performance / cost
Epoch time = iterations × time per iteration.

### 16. Security
Many epochs on small, sensitive datasets increase memorization risk.

### 17. Interview explanation
"An epoch is one full pass over the training data. The number of epochs is a hyperparameter; I use validation loss with early stopping instead of guessing, and for streaming or very large datasets I count steps or tokens."
