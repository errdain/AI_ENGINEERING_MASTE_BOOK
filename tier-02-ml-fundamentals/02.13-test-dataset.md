# 2.13 Test dataset

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: Very high · Hands-on: High
Prerequisites: 2.12 · Leads to: 2.31 Generalization, 2.37–2.43 Metrics, Tier 30 Evaluation

### 1. What is it?
Held-out data used **once, at the end**, to estimate how the final model will perform on new data.

### 2. Why does it exist?
It is the only unbiased estimate of generalization, provided it never influenced any modelling decision.

### 3. Detailed explanation
- **Lock it away:** no tuning, no feature selection, no looking at errors to design new features. If you do, create a new fresh test set.
- **Peeking inflates scores (demonstrated):** choosing the best of 200 pure-guess classifiers by their accuracy on a 100-item test set gives 62% on that set (the mean was 50.4%), but the chosen classifier scores 47.7% on 5,000 fresh items: chance.
- **Size determines precision.** The standard error of an accuracy estimate is `√(p(1−p)/n)`; with n=100 and p=0.9 it's 3 points, so 'a 1-point gain' is noise.
- **Representativeness:** it should mimic production: same time period distribution, same preprocessing, same label process. For temporal problems the test set is the *latest* period.
- **Report uncertainty:** confidence intervals or multiple seeds/bootstrap resamples.
- **Benchmark contamination:** public test sets can leak into pretraining data; a model can score high by memorization. Keep a private held-out set (Tier 15, 30).
- **After release,** production monitoring (2.34) replaces the static test set as the ongoing evaluation.

### 4. How does it work?
Freeze the final pipeline → score once on test → report metric(s) with uncertainty → if you must iterate, collect a new test set.

### 8. Input → Process → Output
`final model + untouched test set → metric (+ interval) → release decision`

### 9. Enterprise use case
Release gates require test results on a frozen, access-controlled set; changes to the set are versioned and reviewed.

### 10. AI engineering connection
Golden datasets for RAG/agents (Tier 30) play this role; they need refresh policies as products and users change.

### 11. Advantages
Honest estimate; supports go/no-go decisions.

### 12. Limitations
One-time use; finite size → uncertainty; may not match future data.

### 13. Trade-offs
Big test set = precise estimate but fewer training rows; refresh cost vs staleness.

### 14. Common mistakes
Using test results to tune; reporting the best of many test runs; tiny test sets; test set that differs from production; contamination.

### 15. Performance / cost
Cheap to compute, expensive to create (labels).

### 16. Security
Protect test sets from leakage to training pipelines or vendors; log access.

### 17. Interview explanation
"The test set gives the final unbiased estimate, so I only touch it once, after all decisions are made. If I peek and iterate, the score becomes optimistic — I can show that picking the best of 200 coin-flip models on 100 test items gives 62% while fresh data gives chance. I also report uncertainty because small test sets are noisy."

### 18. Rapid-fire
Use once at the end; peeking inflates; size sets precision; keep a private set.
