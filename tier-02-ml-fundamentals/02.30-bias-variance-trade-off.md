# 2.30 Bias–variance trade-off

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 3/5 · Interview: Very high · Hands-on: Medium
Prerequisites: 2.28, 2.29 · Leads to: 2.31 Generalization, 2.32 Regularization, 2.36 Tuning

### 1. What is it?
For squared-error regression, the expected test error at a point decomposes as **`Bias² + Variance + Irreducible noise`**. Changing model complexity trades the first two against each other.

### 2. Why does it exist?
It explains why neither the simplest nor the most flexible model is best, and how to reason about the right complexity.

### 3. Detailed explanation
- **Decomposition:** `E[(y − f̂(x))²] = (E f̂(x) − f(x))² + E[(f̂(x) − E f̂(x))²] + σ²` (noise). In the lab the identity holds numerically to within floating-point error.
- **Results for noisy sine, 30 training points (σ²=0.04):**
  | degree | bias² | variance | expected test MSE |
  |---|---|---|---|
  | 0 | 0.495 | 0.0016 | 0.537 |
  | 1 | 0.205 | 0.0028 | 0.247 |
  | 3 | 0.005 | 0.0050 | 0.050 |
  | 5 | ≈0 | 0.0074 | **0.0475** |
  | 10 | ≈0 | 0.0139 | 0.0539 |
  The minimum is at degree 5; beyond it variance grows while bias is already ≈ 0. The floor is the noise 0.04: no model can do better on this noise.
- **Ridge at fixed high capacity:** degree-10 test MSE 0.0539 (λ=0) → 0.0490 (λ=0.01) → 0.1196 (λ=1): a mild λ lowers variance for little bias, an excessive λ adds a lot of bias. The sweet spot is found on validation data (2.36).
- **Scope:** the exact decomposition applies to squared error. For other losses analogous but not identical decompositions exist. The classical U-shaped curve describes many small/medium problems; very over-parameterized networks can show **double descent** where test error falls again beyond the interpolation threshold (REVIEW_REQUIRED: citation).
- **Practical use:** read learning curves. High train *and* validation error ⇒ bias problem (add capacity/features). Low train, high validation ⇒ variance problem (more data, regularize, simplify).
- **Irreducible noise** sets the best achievable score; knowing it (or estimating it from human disagreement) tells you when to stop tuning.

### 4. How does it work?
Vary complexity (degree, depth, λ, number of epochs), measure validation error, choose the minimum, and verify on the test set once.

### 5. Simple example
Fitting a suit: too loose (bias) hangs badly; too tight (variance) rips when you move; tailor to the person (data), not to one pose.

### 6. Technical example
Gradient-boosted trees: depth and number of rounds raise capacity; shrinkage (learning rate) and subsampling lower variance.

### 8. Input → Process → Output
`complexity ↑ → bias² ↓, variance ↑ → test error U-shape (classical regime)`

### 9. Enterprise use case
Model-selection standards specify validation protocols and report the learning curves used to justify complexity.

### 10. AI engineering connection
Choosing LoRA rank, number of epochs, model size and prompt/example counts follows the same logic; report variance across seeds.

### 11. Advantages
Gives a principled mental model for complexity control.

### 12. Limitations
Exact only for squared loss and a fixed true function; in practice bias and variance are hard to separate on real data.

### 13. Trade-offs
This concept *is* the trade-off.

### 14. Common mistakes
Treating it as a law for all models; trying to reduce both with the same lever; ignoring noise floor; choosing complexity on the test set.

### 15. Performance / cost
Higher complexity costs more compute and data.

### 16. Security
Complex models memorize more (privacy); simple models are easier to audit.

### 17. Interview explanation
"Expected squared error equals bias squared plus variance plus irreducible noise. Simple models have high bias and low variance; flexible models the reverse. I read learning curves to see which side I'm on, then adjust capacity or regularization. For very large networks the picture can be more subtle — double descent — but validation still decides."

### 18. Rapid-fire
Error = bias² + variance + noise; complexity trades bias for variance; validate to find the sweet spot.
