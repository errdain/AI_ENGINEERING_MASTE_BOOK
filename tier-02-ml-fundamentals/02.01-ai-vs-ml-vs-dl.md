# 2.1 Artificial Intelligence vs Machine Learning vs Deep Learning

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: High · Hands-on: Low
Prerequisites: Tier 1 (a little: numbers and lists) · Leads to: 2.2–2.6, Tiers 3, 8, 16

> **In plain words**
> **AI** is the big goal: machines doing things we call intelligent. **Machine learning (ML)** is one way to get there: instead of writing the rules by hand, you **show examples and let the computer find the rules**. **Deep learning (DL)** is a kind of ML that uses **many-layered neural networks**, which even learn *which features matter* on their own.
> Think of them as **nested boxes: AI ⊃ ML ⊃ DL**. Large language models (ChatGPT-style systems) live in the innermost box.

**You need first:** nothing. This page sets the vocabulary for the rest of the book.

### 1. What is it?
Three nested terms:
- **Artificial Intelligence (AI):** any system that performs tasks we associate with intelligence: search, planning, rules and expert systems, learning.
- **Machine Learning (ML):** the part of AI where behaviour is *learned from data* by fitting parameters, rather than written by hand.
- **Deep Learning (DL):** the part of ML that uses neural networks with many layers that learn their own intermediate features.

Large language models and most generative AI are deep-learning systems.

### 2. Why does it exist?
Writing rules by hand works when the rules are known and few. It fails for pictures, speech, language and anything with too many edge cases. ML replaces "write the rule" with "show examples and fit a function". DL replaces "design the features" with "learn the features".

### 3. Detailed explanation
- **What changes between the three is who supplies the knowledge.** Rules: a human writes it. Classical ML: a human designs the features, the algorithm learns the weights. Deep learning: the network learns features and weights together.
- **Not every AI is ML.** A chess engine using search and a hand-written scoring rule is AI with no learning. **Not every ML is deep:** linear regression, logistic regression, k-means and gradient-boosted trees are ML but not DL.
- **Data and compute trade-off.** DL usually needs much more data and compute, but copes with raw pixels, audio and text where hand-made features are hard. On small tables of data, simpler ML often wins.
- **Terminology discipline** (see `GLOSSARY.md`): "agent" and "AI system" are not synonyms for "LLM". Use **model** for the learned function and **system** for everything around it.

### 4. How does it work?
The common pipeline: define the task → collect data → choose a model family → define a loss (2.17) → fit the parameters by optimisation (2.19) → evaluate on unseen data (2.13) → deploy and monitor (2.34). Rules, classical ML and DL differ only in what the "model family" step provides.

### 5. Simple example
**A recipe.**
- *AI by rules:* a chef writes the recipe by hand.
- *ML:* a cook tastes many dishes and learns which amounts work; a human still decides the ingredients that matter.
- *DL:* a cook who also figures out *which ingredients matter at all*.

**A concrete task: the XOR-like puzzle.** Points in the plane `(x₁, x₂)` are labelled "A" when `x₁` and `x₂` have the **same sign**, "B" otherwise.

| Approach | What happens |
|---|---|
| a rule such as "if `x₁ > 0` say A" | right about half the time (no better than guessing) |
| a **linear** learner (a straight line) | also near chance: no straight line separates these classes |
| the same learner + **one engineered feature** `x₁·x₂` | nearly perfect |
| a small **neural network** | nearly perfect, and it found the helpful feature itself |

### 6. Technical example
**Fraud detection.** A rule ("block if amount > $5,000") is AI without ML. A logistic regression on hand-built features is classical ML. A sequence model reading raw transaction histories is DL.

### 7. Code
The XOR-like puzzle, climbed from rules to deep learning.

**① By hand (plain Python): a rule-based "AI".** A human writes the rule; nothing is learned.

```python
import random

random.seed(0)
points = [(random.gauss(0, 1), random.gauss(0, 1)) for _ in range(2000)]
labels = [1 if x1 * x2 > 0 else 0 for x1, x2 in points]          # 1 = same sign

def rule(x1, x2):                                                   # a plausible hand-written rule
    return 1 if x1 > 0 else 0

accuracy = sum(rule(*p) == y for p, y in zip(points, labels)) / len(points)
print("rule-based accuracy:", round(accuracy, 3), "(about chance)")
```

```text
rule-based accuracy: 0.489 (about chance)
```

**② With scikit-learn: classical ML.** The learner is linear; the *human* supplies the feature.

```python
import numpy as np
from sklearn.linear_model import LogisticRegression

rng = np.random.default_rng(0)
X = rng.standard_normal((1200, 2))
y = (X[:, 0] * X[:, 1] > 0).astype(int)
train, test = slice(0, 800), slice(800, 1200)

plain = LogisticRegression().fit(X[train], y[train])
print("linear learner on (x1, x2)        :", round(plain.score(X[test], y[test]), 3))

X_eng = np.column_stack([X, X[:, 0] * X[:, 1]])                      # a human adds the feature x1*x2
engineered = LogisticRegression().fit(X_eng[train], y[train])
print("same learner + feature x1*x2      :", round(engineered.score(X_eng[test], y[test]), 3))
```

```text
linear learner on (x1, x2)        : 0.58
same learner + feature x1*x2      : 0.983
```

**③ With PyTorch: deep learning.** A small network learns the feature by itself.

```python
import numpy as np
import torch

rng = np.random.default_rng(0)
X = rng.standard_normal((1200, 2)).astype("float32")
y = (X[:, 0] * X[:, 1] > 0).astype("float32")
Xt, yt = torch.tensor(X), torch.tensor(y)

torch.manual_seed(0)
net = torch.nn.Sequential(torch.nn.Linear(2, 16), torch.nn.Tanh(), torch.nn.Linear(16, 1))
opt = torch.optim.Adam(net.parameters(), lr=0.05)
for _ in range(300):
    opt.zero_grad()
    loss = torch.nn.functional.binary_cross_entropy_with_logits(net(Xt[:800]).squeeze(1), yt[:800])
    loss.backward()
    opt.step()
pred = (net(Xt[800:]).squeeze(1) > 0).float()
print("small neural network, test accuracy:", round((pred == yt[800:]).float().mean().item(), 3))
```

```text
small neural network, test accuracy: 0.993
```

*Notice:* the data never changed. Only **who supplied the knowledge** did.

### 9. Enterprise use case
Teams choose the *simplest* approach that meets the requirement: rules for stable policies, classical ML for tabular prediction, DL or LLMs for text, images and audio. Mixed systems (rules as guard-rails around a model) are common.

### 10. AI engineering connection
Everything later in this book is deep-learning-based AI engineering (Tiers 3–15) or systems built around deep-learning models (Tiers 16+). The ML fundamentals in this tier (splits, losses, metrics, leakage) apply unchanged to LLM evaluation.

### 11. Advantages
A shared vocabulary; helps pick the right tool and cost level.

### 12. Limitations
The boundaries are blurry (a transformer plus a rule-based router is both), and the terms are diluted by marketing.

### 13. Trade-offs
Rules: transparent, no data needed, brittle. ML: adaptable, needs data and labels. DL: powerful on unstructured data, needs scale, harder to interpret.

### 14. Common mistakes
Calling every product "AI" or every model "deep learning"; defaulting to DL for small tabular data; skipping a simple baseline (2.46); treating "AI" as a single technology.

### 15. Performance / cost
Compute and data costs rise from rules to classical ML to DL. Always compare against a cheap baseline before paying for a bigger model.

### 16. Security
Learned systems inherit data biases and can be attacked (poisoning, adversarial inputs); rule systems have predictable but exploitable gaps. Both need testing.

</details>

### 17. Interview explanation
"AI is the broad goal of machines doing intelligent tasks; machine learning is the part where behaviour is learned from data instead of hand-coded; deep learning is ML using many-layer neural networks that learn their own features. LLMs sit inside deep learning. I'd still start with a simple baseline, because on small tabular data a linear model or trees often beat a neural net."

### 18. Rapid-fire answer
AI ⊃ ML ⊃ DL: AI = intelligent behaviour, ML = learned from data, DL = learned with deep neural networks.

### 20. Hands-on exercise
**Goal:** see which approach suffers most when data is scarce.

1. Re-run the three approaches on the XOR-like puzzle, but train on only **40** points (test on 400).
2. Which accuracy changes most compared with 800 training points?
3. Why?

<details>
<summary>Show a solution</summary>

```python
import numpy as np
import torch
from sklearn.linear_model import LogisticRegression

rng = np.random.default_rng(0)
X = rng.standard_normal((440, 2))
y = (X[:, 0] * X[:, 1] > 0).astype(int)
tr, te = slice(0, 40), slice(40, 440)

X_eng = np.column_stack([X, X[:, 0] * X[:, 1]])
print("engineered feature, 40 train points:", round(LogisticRegression().fit(X_eng[tr], y[tr]).score(X_eng[te], y[te]), 3))

Xt, yt = torch.tensor(X, dtype=torch.float32), torch.tensor(y, dtype=torch.float32)
torch.manual_seed(0)
net = torch.nn.Sequential(torch.nn.Linear(2, 16), torch.nn.Tanh(), torch.nn.Linear(16, 1))
opt = torch.optim.Adam(net.parameters(), lr=0.05)
for _ in range(300):
    opt.zero_grad()
    torch.nn.functional.binary_cross_entropy_with_logits(net(Xt[tr]).squeeze(1), yt[tr]).backward()
    opt.step()
print("neural network, 40 train points    :", round(((net(Xt[te]).squeeze(1) > 0).float() == yt[te]).float().mean().item(), 3))
```

```text
engineered feature, 40 train points: 0.978
neural network, 40 train points    : 0.863
```

The network, which has to *discover* the feature, loses the most; the model with the human-supplied feature barely cares. Deep models need more data in exchange for needing less human design.
