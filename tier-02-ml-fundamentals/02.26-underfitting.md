# 2.26 Underfitting

**Metadata** — Tier: 2 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: High · Hands-on: High
Prerequisites: 2.15, 2.17 · Leads to: 2.27 Overfitting, 2.28 Bias, 2.30 Bias–variance trade-off

> **In plain words**
> A model **underfits** when it is **too simple (or trained too little) to capture the real pattern**. It does badly on the training data **and** on new data.
> Like describing a mountain range with a single straight line. The telltale sign: the **training error is already high**, and the validation error is about the same. More data will not help, because the model cannot represent the pattern.

**You need first:** 2.15 Regression and 2.17 Loss functions.

> **Figure 2.26-1 — the signature of underfitting**
>
> ```mermaid
> flowchart LR
>     A["train error HIGH"] --> C["underfitting"]
>     B["validation error HIGH<br/>(about the same)"] --> C
>     C --> D["fix: richer model,<br/>better features,<br/>less regularisation,<br/>train longer"]
>     C -.-> E["NOT: more data"]

>
> *How to read it:* look at both errors together. If both are high and close to each other, the model is the problem (underfitting), not the amount of data. If training error is low but validation error is high, that is the opposite problem, overfitting (2.27). The picture of the same 30 points fitted by too-simple, good and too-flexible curves is Figure 2.27-1.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| underfitting | the model is too simple to capture the pattern |
| capacity | how flexible a model is (more parameters, more flexible) |
| noise floor | the error no model can beat because the data itself is noisy |
| baseline | a trivial model (always predict the mean or the majority) |
| high bias | systematic error that more data cannot remove (2.28) |
| polynomial degree | 0 = constant, 1 = line, 3 = cubic, … |

### 1. What is it?
A model that is **too simple, too constrained, or trained too little to capture the real pattern**, so it performs poorly on both the training data and new data.

### 2. Why does it exist (as a concept)?
Recognising underfitting tells you to add capacity, features or training time, and *not* to waste effort on regularisation or more data.

### 3. Detailed explanation
- **Signature:** high training error *and* a similar high validation error (a small gap). More data does not fix it.
- **Causes:** the model class is too simple (a line for a sine wave), too few or uninformative features (2.7), too much regularisation (2.32), too few epochs or too small a learning rate (2.25), or poor optimisation.
- **Underfitting is high bias** (2.28): a systematic error that persists however much data you collect.
- **Baselines (2.46) expose it:** if your model barely beats the "always predict the mean" or majority baseline, suspect underfitting (or that the signal is simply missing).
- **Remedies:** a richer model (more layers or units, non-linear features, interactions), better features, less regularisation, longer or better-tuned optimisation, and a check for bugs (unscaled inputs, wrong labels).

### 4. How does it work?
Compare the training error with a reference: the noise level, human performance, or a strong baseline. A large training error means the model has not learned what the data allows.

### 5. Simple example
Describing a mountain range with one straight line.

**With numbers** (points from a noisy sine curve; true noise level: error 0.04 is the best any model can do):

| Model | Train error | Validation error | Verdict |
|---|---|---|---|
| degree 0 (a constant) | ≈ 0.50 | ≈ 0.53 | underfit |
| degree 1 (a line) | ≈ 0.21 | ≈ 0.27 | underfit |
| degree 3 | ≈ 0.03 | ≈ 0.05 | about right |

Degrees 0 and 1 are far above the 0.04 noise floor on *both* sets.

### 6. Technical example
A linear classifier on XOR-like data scores about 50%, however many examples you add (2.1).

### 7. Code
**① By hand (plain Python).** The simplest underfit: always predict the average.

```python
import math, random

random.seed(1)
xs = [random.uniform(-1, 1) for _ in range(30)]
ys = [math.sin(math.pi * x) + random.gauss(0, 0.2) for x in xs]
mean = sum(ys) / len(ys)
mse = sum((y - mean) ** 2 for y in ys) / len(ys)
print("a constant model (the mean) has training error:", round(mse, 3), "  noise floor: 0.04")
```

```text
a constant model (the mean) has training error: 0.491   noise floor: 0.04
```

**② With NumPy.** Train and validation error for a few degrees.

```python
import numpy as np

rng = np.random.default_rng(1)
f = lambda x: np.sin(np.pi * x)
x, xv = rng.uniform(-1, 1, 30), rng.uniform(-1, 1, 500)
y, yv = f(x) + rng.normal(0, 0.2, 30), f(xv) + rng.normal(0, 0.2, 500)

for degree in (0, 1, 3):
    coefs = np.polyfit(x, y, degree)
    print(f"degree {degree}: train MSE {np.mean((np.polyval(coefs, x) - y) ** 2):.3f}   validation MSE {np.mean((np.polyval(coefs, xv) - yv) ** 2):.3f}")
```

```text
degree 0: train MSE 0.535   validation MSE 0.549
degree 1: train MSE 0.242   validation MSE 0.257
degree 3: train MSE 0.053   validation MSE 0.054
```

**③ With scikit-learn.** A learning curve: more data does not rescue a line.

```python
import numpy as np
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import learning_curve
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures

rng = np.random.default_rng(1)
X = rng.uniform(-1, 1, (1500, 1))
y = np.sin(np.pi * X[:, 0]) + rng.normal(0, 0.2, 1500)
for degree in (1, 3):
    model = make_pipeline(PolynomialFeatures(degree), LinearRegression())
    sizes, train, val = learning_curve(model, X, y, train_sizes=[30, 100, 400, 1000], cv=5, scoring="neg_mean_squared_error")
    print(f"degree {degree}: " + "   ".join(f"n={n}: train {-t:.3f} / val {-v:.3f}" for n, t, v in zip(sizes, train.mean(axis=1), val.mean(axis=1))))
```

```text
degree 1: n=30: train 0.195 / val 0.286   n=100: train 0.230 / val 0.242   n=400: train 0.234 / val 0.239   n=1000: train 0.239 / val 0.239
degree 3: n=30: train 0.030 / val 0.055   n=100: train 0.045 / val 0.043   n=400: train 0.044 / val 0.042   n=1000: train 0.042 / val 0.042
```

### 9. Enterprise use case
Model reviews check train-versus-validation error first: a low-capacity model that fails on both signals a modelling problem, not a data-volume problem.

### 10. AI engineering connection
A too-small LLM, over-aggressive quantisation, a too-short fine-tune, or a frozen backbone with a tiny head can underfit the target task; evaluation on the training set reveals it.

### 11. Advantages
Simple models are cheap, stable and interpretable.

### 12. Limitations
They cannot capture complex relationships; limited ceiling.

### 13. Trade-offs
Moving away from underfitting adds capacity, which risks overfitting (2.27, 2.30).

### 14. Common mistakes
Collecting more data to fix underfitting; blaming the data when the optimiser never converged; over-regularising; not checking the training error.

### 15. Performance / cost
Underfit models are cheap to train and serve but waste the business value of the data.

### 16. Security
A model that underfits a subgroup can be systematically unfair to it even if overall metrics look fine; check slices.

</details>

### 17. Interview explanation
"Underfitting means the model is too simple or under-trained, so both training and validation error are high. I confirm it by comparing training error with a baseline or a noise floor, and fix it with a richer model, better features, less regularisation or more optimisation, not by collecting more data."

### 18. Rapid-fire answer
Underfit = high train and validation error (high bias); fix capacity, features or training, not data volume.

### 20. Hands-on exercise
**Goal:** show that more data barely helps a line.

1. Fit a degree-1 polynomial to noisy sine data with 30 points and again with 3,000 points.
2. Print the validation error each time.
3. Compare with the degree-3 fit on the same 3,000 points.

<details>
<summary>Show a solution</summary>

```python
import numpy as np

rng = np.random.default_rng(1)
f = lambda x: np.sin(np.pi * x)
xv = rng.uniform(-1, 1, 2000); yv = f(xv) + rng.normal(0, 0.2, 2000)

def val_error(n, degree):
    x = rng.uniform(-1, 1, n)
    y = f(x) + rng.normal(0, 0.2, n)
    return np.mean((np.polyval(np.polyfit(x, y, degree), xv) - yv) ** 2)

print("line, 30 points   :", round(val_error(30, 1), 3))
print("line, 3000 points :", round(val_error(3000, 1), 3), "(barely better: the model is the limit)")
print("cubic, 3000 points:", round(val_error(3000, 3), 3), "(a richer model helps)")
```

```text
line, 30 points   : 0.251
line, 3000 points : 0.234 (barely better: the model is the limit)
cubic, 3000 points: 0.044 (a richer model helps)
```
