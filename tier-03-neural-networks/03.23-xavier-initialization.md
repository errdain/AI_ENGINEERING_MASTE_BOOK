# 3.23 Xavier (Glorot) initialization

**Metadata** — Tier: 3 · Phase: 1 · Priority: P1 · Difficulty: 3/5 · Interview: High · Hands-on: High
Prerequisites: 3.22, 1.30 · Leads to: 3.24 He initialization

> **In plain words**
> **Xavier initialization** is a rule for the **size of the starting weights** in layers followed by **tanh-like** (or no) activations. It says: make the weights' spread depend on **both how many inputs and how many outputs** the layer has, so the signal going forward and the gradient going backward both keep a steady size.
> The rule: variance = `2 / (fan_in + fan_out)`. Bigger layers get smaller weights.

**You need first:** 3.22 Parameter initialization, 1.30 Variance.

> **Figure 3.23-1 — the rule in one picture**
>
> ```mermaid
> flowchart LR
>     S["layer shape<br/>fan_in → fan_out"] --> V["variance =<br/>2 / (fan_in + fan_out)"]
>     V --> N["normal: std = √variance"]
>     V --> U["uniform: ± √(6 / (fan_in + fan_out))"]
>     N --> W["starting weights"]
>     U --> W
> ```
>
> *How to read it:* from the layer's two sizes you get one variance; you can then draw the weights from a normal curve with that spread or from a flat (uniform) range whose spread is the same. See Figure 3.22-1 in the previous concept for the effect over 30 layers: Xavier keeps tanh signals alive (0.63 → 0.13) where bad choices collapse or saturate.

| uniform `U(−a, a)` | every value in the range equally likely |

### 1. What is it?
An initialization that sets weight variance to `Var(W) = 2/(fan_in + fan_out)` (normal) or draws `W ~ U(−a, a)` with `a = √(6/(fan_in + fan_out))` (uniform). It is designed to keep activation and gradient variances similar across layers for linear or symmetric (tanh-like) activations. Proposed by Glorot & Bengio (2010).

### 2. Why does it exist?
It is a compromise between preserving forward variance (which needs `1/fan_in`) and backward variance (which needs `1/fan_out`).

### 3. Detailed explanation
- **Derivation sketch (linear units, independent zero-mean weights and inputs):** `Var(z) = fan_in · Var(W) · Var(x)`. Forward stability requires `Var(W) = 1/fan_in`; backward stability requires `Var(W) = 1/fan_out`. The compromise gives `2/(fan_in + fan_out)`.
- **Uniform version:** a uniform on `[−a, a]` has variance `a²/3`; setting that equal to `2/(fan_in + fan_out)` gives `a = √(6/(fan_in + fan_out))`.
- **Intended activations:** tanh/sigmoid in their near-linear regime, or linear layers.
- **Deep tanh stacks:** activation spread declines slowly but stays alive, whereas tiny weights collapse and `N(0,1)` saturates (Figure 3.22-1). PyTorch's recommended `gain` for tanh is 5/3, which rescales Xavier for tanh's compressive effect.
- **With ReLU it under-scales:** the signal shrinks by about √2 per layer, motivating He (3.24).
- **Transformers** often use a small fixed-std normal init (for example 0.02) with residual-branch scaling instead; the principle (control variance) is the same (REVIEW_REQUIRED per model).
- **Assumptions:** independence and zero mean; they hold approximately at initialization only.

### 4. How does it work?
Compute fan_in and fan_out from the weight shape and sample from the scaled normal or uniform distribution.

### 5. Simple example
Split the difference between "keep the forward signal steady" and "keep the backward signal steady".

**By hand.** A layer with `fan_in = 256` and `fan_out = 512`: `Var(W) = 2/(256+512) = 2/768 ≈ 0.0026`, so the std is `√0.0026 ≈ 0.051`. The uniform bound is `√(6/768) ≈ 0.088`.

### 6. Technical example
`torch.nn.init.xavier_uniform_(w, gain=torch.nn.init.calculate_gain('tanh'))`.

### 7. Code
**① By hand (plain Python).** The two formulas for a 256 → 512 layer.

```python
import math

fan_in, fan_out = 256, 512
variance = 2 / (fan_in + fan_out)
print("variance:", round(variance, 5), " std:", round(math.sqrt(variance), 4))
print("uniform bound a:", round(math.sqrt(6 / (fan_in + fan_out)), 4))
print("check: a^2/3 equals the variance:", math.isclose((6 / (fan_in + fan_out)) / 3, variance))
```

```text
variance: 0.0026  std: 0.051
uniform bound a: 0.0884
check: a^2/3 equals the variance: True
```

**② With NumPy.** Sample the weights and check them.

```python
import numpy as np

rng = np.random.default_rng(0)
fan_in, fan_out = 256, 512
bound = np.sqrt(6 / (fan_in + fan_out))
normal = rng.normal(0, np.sqrt(2 / (fan_in + fan_out)), (fan_out, fan_in))
uniform = rng.uniform(-bound, bound, (fan_out, fan_in))
print("normal  std:", normal.std().round(4), " (target 0.051)")
print("uniform std:", uniform.std().round(4), " max |w|:", np.abs(uniform).max().round(4), "<= bound", bound.round(4))
```

```text
normal  std: 0.0511  (target 0.051)
uniform std: 0.051  max |w|: 0.0884 <= bound 0.0884
```

**③ With PyTorch.** The library helper matches the formula; the tanh gain.

```python
import torch

torch.manual_seed(0)
w = torch.empty(512, 256)
torch.nn.init.xavier_normal_(w)
print("xavier_normal_ std :", round(w.std().item(), 4), " formula:", round((2 / (256 + 512)) ** 0.5, 4))
torch.nn.init.xavier_uniform_(w)
print("xavier_uniform_ max:", round(w.abs().max().item(), 4), " bound  :", round((6 / (256 + 512)) ** 0.5, 4))
print("recommended gain for tanh:", round(torch.nn.init.calculate_gain("tanh"), 3))
```

```text
xavier_normal_ std : 0.0511  formula: 0.051
xavier_uniform_ max: 0.0884  bound  : 0.0884
recommended gain for tanh: 1.667
```

### 9. Enterprise use case
Framework defaults vary; document the initializer in model cards for reproducibility.

### 10. AI engineering connection
Used in embeddings and projections of many models; knowing the variance principle is needed to modify architectures safely.

### 11. Advantages
Principled; works well for symmetric activations and shallow-to-moderate depth.

### 12. Limitations
Not tuned for ReLU; assumptions are approximate; deep nets still need normalization or residuals.

### 13. Trade-offs
Uniform versus normal variants are equivalent in variance; differences are minor.

### 14. Common mistakes
Using Xavier with ReLU; forgetting gain for tanh; computing fan_in/out incorrectly for convolutions; mixing PyTorch `(out, in)` with Keras `(in, out)` when computing fans.

### 15. Performance / cost
None.

### 16. Security
No direct issue; reproducibility only.

### 17. Interview explanation
"Xavier initialization sets weight variance to 2 over fan-in plus fan-out, balancing forward and backward variance preservation for symmetric activations like tanh. For ReLU I switch to He, which doubles the variance because ReLU zeroes half the units."

### 20. Hands-on exercise
**Goal:** see Xavier keep a tanh stack alive and shrink a ReLU stack.

1. Build 20 layers of width 200 with Xavier-normal weights.
2. Run unit-variance inputs through once with tanh and once with ReLU.
3. Print the final activation std for each.

<details>
<summary>Show a solution</summary>

```python
import numpy as np

rng = np.random.default_rng(0)
width, depth = 200, 20
x = rng.normal(0, 1, (512, width))
for name, act in (("tanh", np.tanh), ("relu", lambda v: np.maximum(0, v))):
    h = x
    for _ in range(depth):
        h = act(h @ rng.normal(0, np.sqrt(2 / (2 * width)), (width, width)))
    print(f"{name}: std after {depth} layers = {h.std():.2e}")
```

```text
tanh: std after 20 layers = 1.64e-01
relu: std after 20 layers = 5.97e-04
```
