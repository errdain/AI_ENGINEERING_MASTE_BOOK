# 3.4 Hidden layers

**Metadata** — Tier: 3 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: High · Hands-on: High
Prerequisites: 3.3, 3.9 · Leads to: 3.17 MLP, 3.25 Vanishing gradients, 3.27 Residual connections

### 1. What is it?
The layers **between input and output** that transform features into progressively more useful internal representations. Each is typically a Dense layer followed by an activation. Their count is the **depth**, their size the **width**.

### 2. Why does it exist?
Without a hidden layer the model is linear; hidden layers let it learn nonlinear functions and its own features.

### 3. Detailed explanation
- **No hidden layer = linear model.** On a circle-shaped class boundary, a linear classifier reaches 60.1% accuracy; a one-hidden-layer MLP with 16 tanh units reaches 99.4% (3.17).
- **Representation learning:** early layers capture simple patterns, later layers combine them (edges → shapes → objects in vision; this hierarchy is an observed tendency, not a guarantee).
- **Depth vs width:** width increases capacity per layer; depth composes features and can represent some functions with exponentially fewer units, but it complicates optimization (vanishing/exploding gradients, 3.25–3.26) and needs tools such as residual connections (3.27) and normalization (3.30–3.32).
- **Parameter count:** a hidden layer with `n_in` inputs and `n_h` units has `n_in·n_h + n_h` parameters. Example 784→128→64→10: 100,480 + 8,256 + 650 = **109,386** (matches PyTorch).
- **Compute and memory:** FLOPs per sample ≈ 2 × parameters (forward); activations must be stored for backprop (3.20), so memory grows with width × depth × batch.
- **Choosing size:** start small, increase until validation stops improving (2.30); regularize (3.28, 3.29); widths are often powers of two for hardware efficiency.
- **Bottlenecks:** layers narrower than their neighbours force compression (autoencoders).
- **Hidden units are not individually interpretable by default;** interpretability work (probing, mechanistic analysis) is a separate field (REVIEW_REQUIRED before claiming specific roles).

### 4. How does it work?
`h₁ = φ(W₁x + b₁)`, `h₂ = φ(W₂h₁ + b₂)`, … each layer re-represents the previous one.

### 5. Simple example
Successive translators, each rephrasing the message into a form the next can use.

### 6. Technical example
The Transformer's feed-forward sublayer is a two-layer MLP with a hidden width typically about 4× the model dimension (Tier 8).

### 7. Code
```python
import nn as N
m = N.MLP([784, 128, 64, 10]); print(m.n_params())                       # 109386
lin = N.MLP([2, 2]); mlp = N.MLP([2, 16, 2], activation='tanh')           # linear vs one hidden layer on a circle dataset
```

### 8. Input → Process → Output
`x → [Dense → φ] × L → representation → output layer`

### 9. Enterprise use case
Architecture size is a cost lever: parameters drive memory, latency and training cost.

### 10. AI engineering connection
Depth and width of Transformers (Tier 8, 12); the hidden size `d_model` is the width carried through the residual stream.

### 11. Advantages
Learn features automatically; expressive.

### 12. Limitations
More parameters → overfitting risk and cost; harder optimization with depth.

### 13. Trade-offs
Wider/deeper = more capacity vs more compute, data need and instability.

### 14. Common mistakes
Adding layers without activations (collapses); too large for the data; ignoring initialization when going deeper; assuming deeper is always better.

### 15. Performance / cost
Parameter count × batch determines GPU memory and time.

### 16. Security
Large capacity increases memorization and extractable training data.

### 17. Interview explanation
"Hidden layers are where the network builds its own features: each Dense layer plus activation re-represents the input. With none the model is linear; more width or depth increases capacity at the cost of compute, overfitting risk and harder optimization, so I size by validation performance."

### 18. Rapid-fire
Hidden layers = Dense+activation stacks between input and output; none → linear; depth/width trade capacity vs cost.
