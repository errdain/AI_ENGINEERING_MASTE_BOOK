# 3.6 Weights

**Metadata** — Tier: 3 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: High · Hands-on: High
Prerequisites: 3.1, 1.3 · Leads to: 3.20 Backpropagation, 3.22 Initialization, 3.29 Weight decay

### 1. What is it?
The **learnable coefficients** of a layer that scale each input before summation: a weight matrix `W` of shape `(n_out, n_in)` (PyTorch convention) per Dense layer.

### 2. Why does it exist?
Weights are where the model's learned knowledge lives. Training is the search for good values.

### 3. Detailed explanation
- **Role:** `w_ij` says how strongly input `j` influences unit `i`. Positive excites, negative inhibits, near zero ignores.
- **Shape and count:** `n_out × n_in` per layer; modern models have billions of such numbers. Storage = parameters × bytes per parameter (1.40): 7B parameters ≈ 14 GB in 16-bit.
- **Learned, not set:** they start from a random initialization (3.22) and are updated by gradient descent using gradients from backprop (3.20): `W ← W − η ∂L/∂W`.
- **Why random start:** identical weights make hidden units compute identical things forever (symmetry); randomness breaks the tie. Scale matters: too large or too small makes signals explode or vanish (3.22–3.26).
- **Interpretation:** on standardized inputs, a large |weight| indicates a feature the model relies on. In the lab, for a logistic unit where only feature 0 matters, learned |w₀| = 6.18 and |w₁| = 0.045. In deep networks individual weights are not interpretable.
- **Regularization:** weight decay (3.29) shrinks weights; pruning removes small ones; quantization stores them in fewer bits (Tier 11).
- **Sharing:** convolution and recurrence reuse the same weights across positions, reducing parameters (Tier 5, 13).
- **Weights vs hyperparameters (2.35):** weights are learned; hyperparameters are set.
- **Checkpoints:** the weights are the model artifact; protect and version them; load from trusted formats only (1.4).

### 4. How does it work?
Initialize → forward uses them → loss → gradient w.r.t. each weight → optimizer update → repeat.

### 5. Simple example
The volume knobs on a mixing desk, one per input.

### 6. Technical example
A 4096×4096 weight matrix has 16.8M numbers (64 MiB in float32, 1.3).

### 8. Input → Process → Output
`init → forward use → gradient → update → trained weights`

### 9. Enterprise use case
Weight files are valuable IP and an attack surface; versioning, checksums, access control and signed artifacts apply.

### 10. AI engineering connection
LoRA trains low-rank weight updates (Tier 10); quantization compresses weights (Tier 11); merging models combines weights.

### 11. Advantages
Flexible, learned from data.

### 12. Limitations
Opaque; memory-hungry; sensitive to initialization and scaling.

### 13. Trade-offs
More weights: more capacity, more cost and overfitting risk.

### 14. Common mistakes
Initializing all to zero; wrong shape convention; forgetting weights are shared/tied; loading untrusted checkpoints.

### 15. Performance / cost
Memory ≈ parameters × bytes; bandwidth often limits inference speed.

### 16. Security
Weights can encode memorized training data and can be tampered with (backdoors); verify provenance.

### 17. Interview explanation
"Weights are the learned coefficients that scale each input to each unit, stored as matrices of shape out-by-in. They start random to break symmetry and are updated with gradients. Their number drives memory and compute, so I think in parameters and bytes."

### 18. Rapid-fire
Learnable per-connection scales (W: out×in); random init, trained by gradients; the model artifact.
