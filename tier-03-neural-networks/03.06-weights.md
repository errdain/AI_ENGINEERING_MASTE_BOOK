# 3.6 Weights

**Metadata** — Tier: 3 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: High · Hands-on: High
Prerequisites: 3.1, 1.3 · Leads to: 3.20 Backpropagation, 3.22 Initialisation, 3.29 Weight decay

> **In plain words**
> **Weights** are the **learned dials of the network**: one number per connection, saying how strongly one input influences one unit. A positive weight excites, a negative weight inhibits, a weight near zero ignores.
> Everything a model "knows" is stored in its weights. Training is the search for good values. They start as small random numbers (all-equal weights would make every unit identical forever) and are nudged by gradients.

**You need first:** 3.1 The artificial neuron, 1.3 Matrices.

> **Figure 3.6-1 — a layer's weights are a matrix**
>
> ```mermaid

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| weight `w_ij` | strength of the link from input `j` to unit `i` |
| weight matrix `W` | all weights of a layer, shape `(n_out, n_in)` |
| initialisation | the starting values (small random numbers) |
| symmetry breaking | randomness that makes units differ |
| parameter | any learned number (weights and biases) |
| pruning / quantisation | removing small weights / storing them in fewer bits |
| checkpoint | a saved file of all the weights |

### 1. What is it?
The **learnable coefficients** of a layer that scale each input before summation: a weight matrix `W` of shape `(n_out, n_in)` (PyTorch convention) for every Dense layer.

### 2. Why does it exist?
Weights are where the model's learned knowledge lives. Training is the search for good values.

### 3. Detailed explanation
- **Role:** `w_ij` says how strongly input `j` influences unit `i`.
- **Shape and count:** `n_out × n_in` per layer; modern models have billions. Storage = parameters × bytes per parameter (1.40): 7 billion parameters ≈ 14 GB in 16-bit.
- **Learned, not set:** they start from a random initialisation (3.22) and are updated by gradient descent using gradients from backpropagation (3.20): `W ← W − η·∂L/∂W`.
- **Why a random start:** identical weights make hidden units compute identical things forever (*symmetry*); randomness breaks the tie. The *scale* matters: too large or too small makes signals explode or vanish (3.22–3.26).
- **Interpretation:** on standardised inputs a large `|weight|` marks a feature the model relies on. In deep networks, individual weights are not interpretable.
- **Regularisation:** weight decay (3.29) shrinks weights; pruning removes small ones; quantisation stores them in fewer bits (Tier 11).
- **Sharing:** convolution and recurrence reuse the same weights across positions, reducing parameters (Tiers 5, 13).
- **Weights versus hyper-parameters (2.35):** weights are learned; hyper-parameters are set.
- **Checkpoints:** the weights are the model artefact; protect and version them; load only from trusted formats (1.4).

### 4. How does it work?
Initialise → the forward pass uses them → loss → gradient with respect to each weight → optimiser update → repeat.

### 5. Simple example
The volume knobs on a mixing desk, one per input.

**By hand.** A unit with weights `w = [2, −1, 0]` and inputs `x = [3, 4, 100]`: `z = 2·3 − 1·4 + 0·100 = 2`. The third input (weight 0) is ignored completely, even though its value is huge.

### 6. Technical example
A 4096 × 4096 weight matrix has 16.8 million numbers (64 MiB in float32, 1.3).

### 7. Code
**① By hand (plain Python).** Weights decide what matters.

```python
x = [3, 4, 100]
for name, w in (("ignore the 3rd input", [2, -1, 0]), ("listen to the 3rd input", [2, -1, 0.1])):
    print(f"{name:<24} z = {sum(a * b for a, b in zip(w, x))}")
print("memory of a 7-billion-parameter model in 16-bit:", 7e9 * 2 / 1e9, "GB")
print("weights in a 4096 x 4096 matrix:", 4096 * 4096, " = ", 4096 * 4096 * 4 / 2**20, "MiB in float32")
```

```text
ignore the 3rd input     z = 2
listen to the 3rd input  z = 12.0
memory of a 7-billion-parameter model in 16-bit: 14.0 GB
weights in a 4096 x 4096 matrix: 16777216  =  64.0 MiB in float32
```

**② With NumPy.** Learned weights reveal relevance: only feature 0 matters.

```python
import numpy as np

rng = np.random.default_rng(0)
X = rng.normal(0, 1, (500, 2))
y = (X[:, 0] + 0.1 * rng.normal(0, 1, 500) > 0).astype(float)           # only feature 0 matters
w, b = np.zeros(2), 0.0
for _ in range(2000):
    p = 1 / (1 + np.exp(-(X @ w + b)))
    w -= 0.1 * X.T @ (p - y) / len(y)
    b -= 0.1 * np.mean(p - y)
print("learned weights:", w.round(2), "-> feature 0 gets a large weight, feature 1 almost none")
```

```text
learned weights: [ 6.81 -0.2 ] -> feature 0 gets a large weight, feature 1 almost none
```

**③ With PyTorch.** Why a random start: zero weights keep units identical.

```python
import torch

def train(init):
    torch.manual_seed(0)
    net = torch.nn.Sequential(torch.nn.Linear(2, 3), torch.nn.Tanh(), torch.nn.Linear(3, 1))
    if init == "zeros":
        for p in net.parameters():
            torch.nn.init.zeros_(p)
    X = torch.randn(200, 2); y = ((X[:, 0] * X[:, 1]) > 0).float()
    opt = torch.optim.SGD(net.parameters(), lr=0.5)
    for _ in range(100):
        opt.zero_grad()
        torch.nn.functional.binary_cross_entropy_with_logits(net(X).squeeze(1), y).backward()
        opt.step()
    return net[0].weight.detach()

for init in ("random", "zeros"):
    W = train(init)
    print(f"{init:<7} first-layer weights, rows = hidden units:\n{W.numpy().round(2)}")
```

```text
random  first-layer weights, rows = hidden units:
[[-0.5   0.36]
 [-0.76 -0.9 ]
 [-0.44  0.81]]
zeros   first-layer weights, rows = hidden units:
[[0. 0.]
 [0. 0.]
 [0. 0.]]
```

### 9. Enterprise use case
Weight files are valuable intellectual property and an attack surface; versioning, checksums, access control and signed artefacts apply.

### 10. AI engineering connection
LoRA trains low-rank weight updates (Tier 10); quantisation compresses weights (Tier 11); model merging combines weights.

### 11. Advantages
Flexible and learned from data.

### 12. Limitations
Opaque; memory-hungry; sensitive to initialisation and scaling.

### 13. Trade-offs
More weights mean more capacity, but also more cost and overfitting risk.

### 14. Common mistakes
Initialising everything to zero; a wrong shape convention; forgetting that weights may be shared or tied; loading untrusted checkpoints.

### 15. Performance / cost
Memory ≈ parameters × bytes; bandwidth often limits inference speed.

### 16. Security
Weights can encode memorised training data and can be tampered with (backdoors); verify provenance.

### 17. Interview explanation
"Weights are the learned coefficients that scale each input to each unit, stored as matrices of shape out-by-in. They start random to break symmetry and are updated with gradients. Their number drives memory and compute, so I think in parameters and bytes."

### 18. Rapid-fire answer
Learnable per-connection scales (`W`: out × in); random initialisation, trained by gradients; the model artefact.
