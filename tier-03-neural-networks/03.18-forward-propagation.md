# 3.18 Forward propagation

**Metadata** — Tier: 3 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: High · Hands-on: Very high
Prerequisites: 3.8, 3.9, 3.16, 3.17 · Leads to: 3.19 Computational graph, 3.20 Backpropagation, Tier 4 Training loop

### 1. What is it?
Computing the network's output from its input by applying each layer in order: `a₀ = x`, `zₗ = Wₗaₗ₋₁ + bₗ`, `aₗ = φ(zₗ)`, … until the final output (logits or values), and then the loss.

### 2. Why does it exist?
It is the prediction step at inference time and the first half of every training step. The values it computes are cached for the backward pass.

### 3. Detailed explanation
- **Worked trace (input `x = [1, 2]`, 2→3→1 ReLU network):** `W₁ = [[0.5, −1], [2, 0.1], [−0.3, 0.8]]`, `b₁ = [0, 1, −0.2]` → `z₁ = [−1.5, 3.2, 1.1]` → `a₁ = [0, 3.2, 1.1]` (ReLU zeroes the first unit); `W₂ = [1, −1, 0.5]`, `b₂ = 0.1` → `z₂ = 0·1 − 3.2 + 0.55 + 0.1 = −2.55`. The NumPy library returns exactly −2.55.
- **Deterministic:** with fixed weights and no dropout (3.28) the same input always gives the same output (tested). Batch-dependent layers (BatchNorm, 3.30) are the exception in training mode.
- **Cost:** about `2 × (number of weights)` FLOPs per sample: 218,368 for 784→128→64→10 (weights only). Cost for a batch scales linearly.
- **Memory:** inference can discard each activation after use. **Training must keep them** for the backward pass: for batch 32 on 784→128→64→10 that is `32 × (784+128+64+10) = 31,552` floats just for post-layer activations (plus pre-activations in this implementation). For large models, activation memory often exceeds parameter memory, hence activation checkpointing (Tier 4, 4.41).
- **Train vs eval mode:** dropout and batch normalization behave differently (3.28, 3.30); forgetting `model.eval()` is a classic bug.
- **Numerical issues:** overflow in activations or logits (1.44); use stable softmax/loss (1.43).
- **Batching:** one matmul per layer for the whole batch (3.8); sequences add a time axis (Tier 7–8).
- **Autoregressive generation** repeats a forward pass per generated token (with a KV cache to avoid recomputation, Tier 11).

### 4. How does it work?
Loop over layers: `x = layer.forward(x)`; keep each layer's inputs for the backward pass when training.

### 5. Simple example
An assembly line: each station transforms what it receives and passes it on.

### 6. Technical example
A Transformer forward pass is embedding → N blocks of (attention, MLP) with residuals and norms → output projection.

### 7. Code
```python
import numpy as np, nn as N
x = np.array([[1.0, 2.0]]); W1 = np.array([[0.5, -1], [2, 0.1], [-0.3, 0.8]]); b1 = np.array([0, 1, -0.2]); W2 = np.array([[1, -1, 0.5]]); b2 = np.array([0.1])
z1 = x @ W1.T + b1; a1 = np.maximum(0, z1); z2 = a1 @ W2.T + b2; print(z1, a1, z2)    # [[-1.5 3.2 1.1]] [[0. 3.2 1.1]] [[-2.55]]
```

### 8. Input → Process → Output
`x → z₁ → a₁ → … → logits → loss (cache activations if training)`

### 9. Enterprise use case
Inference services are forward-only; their latency and cost are governed by forward FLOPs and memory bandwidth.

### 10. AI engineering connection
LLM inference is repeated forward propagation; prefill processes the prompt in parallel, decode is one token per pass (Tier 11).

### 11. Advantages
Simple, parallel across the batch; no parameter updates.

### 12. Limitations
Sequential over layers; cached activations dominate training memory.

### 13. Trade-offs
Activation checkpointing trades extra forward recomputation for memory.

### 14. Common mistakes
Forgetting eval mode; mixing up pre- and post-activation values; computing in float16 without care; storing activations at inference.

### 15. Performance / cost
Fuse bias + activation; use batched matmuls; reduce precision (Tier 11).

### 16. Security
Inputs flow through the whole model: validate shapes and ranges at the entry (3.3).

### 17. Interview explanation
"Forward propagation applies each layer in order — weighted sum, bias, activation — to produce the output and then the loss. At inference I can throw activations away; in training I keep them because backprop needs them, which is why training memory is dominated by activations rather than weights."

### 18. Rapid-fire
z=Wa+b, a=φ(z) layer by layer; ≈2·weights FLOPs per sample; training caches activations; eval vs train mode matters.
