# 3.3 Input layer

**Metadata** — Tier: 3 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: Medium · Hands-on: High
Prerequisites: 1.4, 2.7, 2.47 · Leads to: 3.4 Hidden layers, Tier 6 Embeddings, Tier 13 Vision

### 1. What is it?
The **entry point of a network**: it holds the feature vector (or tensor) for each sample. It performs no computation and has no parameters; it defines the **input shape**.

### 2. Why does it exist?
The network's first weight matrix must match the input dimension, and everything upstream (encoding, scaling) determines what the network can learn from.

### 3. Detailed explanation
- **Shape:** batch-first `(B, n_in)` for tabular data; `(B, T)` of integer token ids for text before embedding; `(B, C, H, W)` for images; `(B, T, d)` for sequences of vectors (1.4, 1.5).
- **The first Dense layer fixes `n_in`:** `W₁` has shape `(n_hidden, n_in)`; changing the number of features changes the model.
- **Preprocessing belongs before the input layer:** scaling/standardization (2.47), missing-value handling (2.49), encoding of categories (2.48). Unscaled inputs make optimization slow (2.25).
- **Text:** integer token ids are *not* fed as numbers; they index an **embedding table** (Tier 6), which acts as the first layer.
- **Images:** flatten (MLP) or keep spatial structure (CNN, Tier 13); a 28×28 grayscale image flattens to 784 inputs (our 784→128→64→10 example).
- **Variable-length inputs:** pad and mask, or use architectures that handle sequences (Tier 5, 8).
- **Input validation:** check shapes, dtypes, ranges and NaNs at the boundary; unexpected inputs fail silently inside matrix multiplications otherwise.
- **Parameter-free:** the input layer adds no parameters; the first hidden layer carries the `n_in × n_hidden` weights.

### 4. How does it work?
Collect/encode/scale features → assemble into a tensor `(B, n_in)` → feed to the first layer.

### 5. Simple example
The reception desk where all information arrives in a fixed format.

### 6. Technical example
MNIST MLP: 784 pixel inputs scaled to [0,1]; tabular MLP: standardized numeric features plus one-hot encodings.

### 7. Code
```python
import numpy as np, nn as N
m = N.MLP([784, 128, 64, 10]); x = np.zeros((32, 784))      # batch of 32 flattened 28×28 images
print(m.forward(x).shape, m.layers[0].W.shape)               # (32, 10)  (128, 784): first layer weights fixed by n_in = 784
```

### 8. Input → Process → Output
`raw data → encode/scale → tensor (B, n_in) → first layer`

### 9. Enterprise use case
A data contract defines the input schema; models are versioned together with their preprocessing.

### 10. AI engineering connection
LLM inputs are token ids → embeddings; multimodal models project each modality into a shared input space (Tier 23).

### 11. Advantages
Clear interface between data and model.

### 12. Limitations
Fixed size for plain MLPs; sensitive to feature scaling and ordering.

### 13. Trade-offs
Flattening discards spatial/temporal structure that specialized architectures exploit.

### 14. Common mistakes
Feeding unscaled features; wrong batch axis; training/serving feature order mismatch; feeding token ids as numbers; no input validation.

### 15. Performance / cost
Input pipelines (loading, augmentation) often bottleneck GPUs (Tier 4, 4.26).

### 16. Security
Inputs are the attack surface: adversarial examples, injection, malformed tensors; validate and bound them.

### 17. Interview explanation
"The input layer just defines the shape and passes the features through; the first dense layer's weight matrix has to match it. What matters is what comes before it: scaling, encoding, and for text turning token ids into embeddings."

### 18. Rapid-fire
Input layer: parameter-free entry defining shape (B, n_in); preprocessing and encoding happen before it.

### 19. Interview questions
- Basic: What is the shape of the input for a batch of 64 MNIST images in an MLP?
- Intermediate: Why aren't token ids fed directly as numbers?
- Advanced: How do you guarantee serving inputs match training inputs?
