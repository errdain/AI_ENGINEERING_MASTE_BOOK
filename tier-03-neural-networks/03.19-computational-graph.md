# 3.19 Computational graph

**Metadata** — Tier: 3 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: High · Hands-on: High
Prerequisites: 3.18, 1.25 · Leads to: 3.20 Backpropagation, 3.21 Automatic differentiation

### 1. What is it?
A **directed acyclic graph** whose nodes are values (inputs, parameters, intermediate results) and whose edges are the operations connecting them. Evaluating the graph forward computes the output; walking it backward applies the chain rule.

### 2. Why does it exist?
Representing a computation as a graph makes gradients mechanical: each operation only needs to know its own local derivative.

### 3. Detailed explanation
- **Example:** `f = (a·b + c)·(−2)` with `a = 2, b = −3, c = 10`: `e = a·b = −6`, `d = e + c = 4`, `f = −8`. Graph size: 7 nodes (a, b, c, e, d, the constant −2, f). Backward gives `∂f/∂a = b·(−2) = 6`, `∂f/∂b = a·(−2) = −4`, `∂f/∂c = −2` (all matched by the autodiff engine).
- **Nodes shared by several consumers receive the sum of their gradient contributions:** for `y = x·x + 2x` at `x = 3`, `x` is used three times and `dy/dx = 2x + 2 = 8` (tested). This is the multivariable chain rule (1.25).
- **Single neuron graph:** `tanh(w₀x₀ + w₁x₁)` has 8 nodes; a real network has millions of them, but they are organized in tensor-level operations (matmul, add, activation), not scalars.
- **Static vs dynamic graphs:** *define-by-run* (PyTorch eager) builds the graph as Python executes, so ordinary `if`/loops work; *define-then-run* (older TensorFlow 1.x, `jit`/`torch.compile` tracing) fixes the graph first, enabling optimizations like operator fusion. Control flow that depends on data needs special handling in traced/compiled modes.
- **Graph as an optimization target:** compilers fuse operations, remove redundant ones, and plan memory.
- **Only differentiable paths carry gradients:** `detach()`, `no_grad`, integer ops, `argmax`, rounding, and sampling cut the graph (tested: gradient through `round` is 0).
- **Leaves vs intermediates:** parameters and inputs are leaves; frameworks store gradients on leaves (`AccumulateGrad` in PyTorch). The gradient function chain for `tanh(sum(w·x))` is `TanhBackward → SumBackward → MulBackward → AccumulateGrad` (verified in the PyTorch build lab).
- **Memory:** the graph keeps references to intermediate tensors until `backward()` finishes; holding losses in Python lists keeps the whole graph alive (a common memory leak: store `loss.item()` instead).

### 4. How does it work?
Each operation creates an output node that remembers its inputs and a local backward rule; backward traverses nodes in reverse topological order.

### 5. Simple example
A recipe flowchart where every step knows how much the final dish changes if its own ingredient changes.

### 6. Technical example
`torch.autograd` records `grad_fn` nodes during the forward pass; `loss.backward()` walks them in reverse.

### 7. Code
```python
from autodiff import Value
a, b, c = Value(2.0), Value(-3.0), Value(10.0); f = (a * b + c) * Value(-2.0); f.backward()
print(f.data, a.grad, b.grad, c.grad, f.graph_size())     # -8.0  6.0  -4.0  -2.0  7
```

### 8. Input → Process → Output
`inputs → ops (nodes) → loss; backward: reverse topological order`

### 9. Enterprise use case
Graph compilers (XLA, TorchInductor, TensorRT) optimize deployed graphs; exporting formats like ONNX serialize them.

### 10. AI engineering connection
Understanding the graph explains memory use, fusion, checkpointing, and why dynamic control flow is harder to compile.

### 11. Advantages
Makes differentiation automatic and optimizable.

### 12. Limitations
Memory overhead; graph breaks hurt compilers; dynamic shapes complicate optimization.

### 13. Trade-offs
Dynamic graphs: flexible, easy debugging. Static/compiled graphs: faster, harder to debug.

### 14. Common mistakes
Keeping graph references alive (memory leaks); accidentally detaching; in-place operations that overwrite values needed for backward; assuming Python control flow is captured in traced graphs.

### 15. Performance / cost
Fusion reduces memory traffic; graph capture reduces Python overhead.

### 16. Security
Untrusted serialized graphs/models can execute code or ops; load only trusted artifacts.

### 17. Interview explanation
"A computational graph records how values are computed from inputs through operations. Backpropagation is a reverse traversal applying each node's local derivative, summing contributions where a value is used more than once. PyTorch builds the graph dynamically during the forward pass and frees it after backward."

### 18. Rapid-fire
DAG of ops; backward = reverse traversal with local derivatives; shared nodes sum gradients; PyTorch builds it dynamically.
