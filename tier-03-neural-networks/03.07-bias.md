# 3.7 Bias

**Metadata** — Tier: 3 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: Medium-High · Hands-on: High
Prerequisites: 3.6 · Leads to: 3.8 Weighted sum, 3.30 Batch normalization

### 1. What is it?
The **learnable offset** `b` added to the weighted sum: `z = w·x + b`. It shifts the activation threshold independently of the inputs.

### 2. Why does it exist?
Without it, a neuron's decision boundary must pass through the origin and a unit with zero input must output `φ(0)`.

### 3. Detailed explanation
- **Geometry:** `w·x + b = 0` is a hyperplane; `w` sets its orientation, `b` its offset from the origin.
- **Demonstration:** data whose class boundary is `x₁ + x₂ = 6.5` (not through the origin). A logistic unit **with** bias reaches 92.3% accuracy; **without** bias 66.2%.
- **Parameters:** one per unit: `n_out` per Dense layer.
- **Initialization:** biases usually start at zero (the symmetry is already broken by weights).
- **Regularization:** biases are usually excluded from weight decay (3.29), like the intercept in ridge regression (2.32).
- **Redundancy with normalization:** layers followed by BatchNorm/LayerNorm often drop the bias because the normalization's shift parameter plays that role (3.30–3.31). Many modern LLMs also remove bias terms in linear layers to save parameters and simplify training (design choice; REVIEW_REQUIRED per model).
- **Naming warning:** this 'bias' (offset term) is unrelated to statistical bias (2.28), dataset bias, or fairness bias.
- **Output bias** can encode class priors (e.g., initialize to `log(p/(1−p))` for imbalanced binary targets so early training is stable).

### 4. How does it work?
Add `b` to each unit's weighted sum before the activation; learn it like the weights.

The base price before adding per-item charges.

### 6. Technical example
`torch.nn.Linear(in, out, bias=False)` omits it; the first layer of a CNN usually has a bias unless followed by BatchNorm.

### 7. Code
```python
import nn as N, numpy as np
fit = lambda bias: N.MLP([2, 1], bias=bias, seed=0).fit(X, y.reshape(-1, 1), loss='bce', lr=0.1, epochs=800)
# boundary x1 + x2 = 6.5: with bias 0.92 accuracy, without bias 0.66
```

### 8. Input → Process → Output
`z = w·x + b`

### 9. Enterprise use case
Nothing special; but exported models must include biases consistently across frameworks.

### 10. AI engineering connection
Bias handling differs across architectures (bias-free Transformer variants); an LM head bias can shift token priors.

### 11. Advantages
Adds flexibility cheaply.

### 12. Limitations
Redundant after normalization; negligible parameter share in large layers.

### 13. Trade-offs
Removing biases simplifies and saves parameters but reduces flexibility slightly.

### 14. Common mistakes
Penalizing biases with weight decay; omitting bias where needed; confusing it with statistical bias; wrong broadcasting (bias must broadcast over the batch axis).

### 15. Performance / cost
Negligible compute; bias add is often fused into the matmul.
