# 3.12 ReLU

**Metadata** — Tier: 3 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: Very high · Hands-on: Very high

> **In plain words**
> **ReLU** ("rectified linear unit") is `max(0, x)`: **pass positive numbers through unchanged, replace negatives with 0**. Like a one-way valve.
> It is cheap, and for positive inputs its slope is exactly 1, so it doesn't squash gradients the way sigmoid does. That is a big reason deep networks became trainable. The one risk: a unit whose input is always negative outputs 0 forever and stops learning (a **dead ReLU**).

**You need first:** 3.9 Activation functions.

> *How to read it:* the gradient is an on/off switch. While a unit is active the backward signal passes through unchanged; while it is off, nothing gets through. See the curve in Figure 3.9-1.

### 1. What is it?
The **rectified linear unit** `ReLU(x) = max(0, x)`: identity for positive inputs, zero for negative ones. Its derivative is 1 for `x > 0` and 0 for `x < 0`.

### 2. Why does it exist?
It is cheap, does not saturate for positive inputs (gradient exactly 1), and produces sparse activations, which made deep networks trainable at scale.

### 3. Detailed explanation
- **Gradient flow:** no shrinking factor for active units, which largely cured vanishing gradients compared with sigmoid and tanh.
- **Sparsity:** roughly half of the units are zero for symmetric pre-activations.
- **Dying ReLU:** a unit whose pre-activation is negative for *all* inputs gets zero gradient and never recovers. Causes: too high a learning rate, a large negative bias, a bad initialisation.
- **Fixes:** Leaky ReLU `max(αx, x)` with small `α` (0.01), PReLU (learned `α`), ELU, GELU or SiLU, lower learning rates, He initialisation (3.24).
- **Not differentiable at 0:** frameworks define a value there (usually 0); irrelevant in practice (1.21).
- **Unbounded above:** activations can grow; normalisation helps (3.30–3.32).
- **Piecewise-linear networks:** a ReLU network computes a piecewise-linear function; for example the XOR network `h = ReLU(x₁ + x₂, x₁ + x₂ − 1)`, `y = h₁ − 2h₂` is exact (3.17).
- **Where used:** CNNs and MLPs by default; Transformers moved to GELU or SiLU variants (3.13–3.14), though ReLU is still used (REVIEW_REQUIRED per model).

### 4. How does it work?
Element-wise `max(0, z)`; in backpropagation pass the gradient where `z > 0` and block it elsewhere.

### 5. Simple example
A one-way valve: positive flow passes unchanged, negative flow is blocked.

**By hand.**

|---|---|---|
| −2 | 0 | 0 |

| 3 | 3 | 1 |

### 7. Code
**① By hand (plain Python).**

```python
relu = lambda z: max(0.0, z)
leaky = lambda z, a=0.01: z if z > 0 else a * z
grad = lambda z: 1.0 if z > 0 else 0.0
for z in (-2, 0.5, 3):
    print(f"z = {z:>4}: relu {relu(z):.1f}   gradient {grad(z):.0f}   leaky relu {leaky(z):+.3f}")
```

```text
z =   -2: relu 0.0   gradient 0   leaky relu -0.020
z =  0.5: relu 0.5   gradient 1   leaky relu +0.500
z =    3: relu 3.0   gradient 1   leaky relu +3.000
```

**② With NumPy.** Sparsity, and how a negative shift kills units.

```python
import numpy as np

rng = np.random.default_rng(0)
z = rng.normal(0, 1, 100000)
print("share of units that are exactly 0 for centred inputs :", f"{np.mean(np.maximum(z, 0) == 0):.1%}")
print("after a bias of -1 (inputs shifted down)             :", f"{np.mean(np.maximum(z - 1, 0) == 0):.1%}", "are off (zero gradient)")
```

```text
share of units that are exactly 0 for centred inputs : 50.2%
after a bias of -1 (inputs shifted down)             : 84.2% are off (zero gradient)
```

**③ With PyTorch.** Detecting dead units, and the Leaky ReLU fix.

```python
import torch

torch.manual_seed(0)
layer = torch.nn.Linear(10, 50)
with torch.no_grad():
    layer.bias.fill_(-6.0)                                   # a bias this negative switches most units off
x = torch.randn(256, 10)
out = torch.relu(layer(x))
dead = (out.max(dim=0).values == 0).float().mean().item()
print(f"share of units that output 0 for EVERY example in the batch (dead): {dead:.0%}")
print("with Leaky ReLU nothing is fully dead:", bool((torch.nn.functional.leaky_relu(layer(x), 0.01).abs().max(dim=0).values > 0).all()))
```

```text
share of units that output 0 for EVERY example in the batch (dead): 100%
with Leaky ReLU nothing is fully dead: True
```

### 9. Enterprise use case
Very cheap on all hardware, which simplifies deployment and quantisation.

### 10. AI engineering connection
The default in vision and tabular networks; understanding dead units helps debug stalled training.

### 11. Advantages
Simple, fast, non-saturating, sparse.

### 12. Limitations
Dying units; not zero-centred; unbounded; a kink at 0.

### 13. Trade-offs
Sparsity and speed versus the risk of dead units.

### 14. Common mistakes
A large learning rate that kills many units; initialisation without He scaling; ReLU on outputs that must be negative; monitoring only the loss and missing the dead fraction.

### 15. Performance / cost
The cheapest activation; ideal for memory-bound kernels.

### 16. Security
Nothing specific.

### 17. Interview explanation
"ReLU is max(0, x): gradient 1 when active, so it doesn't saturate like sigmoid and it's very cheap. The main risk is dying units, where a neuron's input stays negative and it stops learning; I use He initialisation, sensible learning rates, and Leaky ReLU or GELU if I see dead fractions climbing."

`max(0, x)`; gradient 1 or 0; sparse; risk of dying units; use He initialisation; Leaky ReLU or GELU as alternatives.

### 20. Hands-on exercise
**Goal:** log the dead fraction per layer, and see that dead units do not recover.

1. Build a PyTorch MLP `10 → 32 → 32 → 1` with ReLU. Set the first layer's bias to −4 (a very unlucky start).
2. Write a function that returns, for each ReLU layer, the fraction of units that output 0 for the whole batch.
3. Train for 300 steps with a small learning rate. Print the dead fractions and the loss before and after.

<details>
<summary>Show a solution</summary>

```python
import torch

torch.manual_seed(0)
X = torch.randn(256, 10); y = X[:, 0]
net = torch.nn.Sequential(torch.nn.Linear(10, 32), torch.nn.ReLU(), torch.nn.Linear(32, 32), torch.nn.ReLU(), torch.nn.Linear(32, 1))
with torch.no_grad():
    net[0].bias.fill_(-4.0)                                           # a very negative bias: most units start dead

def dead_fractions():
    h, out = X, []
    for layer in net:
        h = layer(h)
        if isinstance(layer, torch.nn.ReLU):
            out.append(round((h.max(dim=0).values == 0).float().mean().item(), 2))
    return out

print("dead fraction per ReLU layer at the start:", dead_fractions())
opt = torch.optim.SGD(net.parameters(), lr=0.05)
for _ in range(300):
    opt.zero_grad()
    loss = ((net(X).squeeze(1) - y) ** 2).mean()
    loss.backward()
    opt.step()
print("after 300 steps                          :", dead_fractions(), " loss:", round(loss.item(), 3), "(the target has variance about 1)")
```

```text
dead fraction per ReLU layer at the start: [1.0, 0.5]
after 300 steps                          : [1.0, 0.5]  loss: 0.962 (the target has variance about 1)
```

A dead unit has zero gradient, so nothing can revive it: the whole first layer stays off and the network cannot learn.
