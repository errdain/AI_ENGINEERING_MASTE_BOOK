# 3.12 ReLU

**Metadata** — Tier: 3 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: Very high · Hands-on: Very high
Prerequisites: 3.9 · Leads to: 3.24 He initialization, Leaky ReLU, GELU/SiLU

### 1. What is it?
The **rectified linear unit** `ReLU(x) = max(0, x)`: identity for positive inputs, zero for negative ones. Derivative: 1 for `x > 0`, 0 for `x < 0`.

### 2. Why does it exist?
It is cheap, does not saturate for positive inputs (gradient exactly 1), and produces sparse activations, which made deep networks trainable at scale.

### 3. Detailed explanation
- **Gradient flow:** no shrinking factor for active units, which largely cured vanishing gradients compared with sigmoid/tanh.
- **Sparsity:** roughly half of the units are zero for symmetric pre-activations (lab: 50% of inputs on [−6,6] have zero gradient).
- **Dying ReLU:** a unit whose pre-activation is negative for all inputs gets zero gradient and never recovers. In the lab, with pre-activations shifted by −1, **61%** are ≤ 0. Causes: too-high learning rates, large negative bias, bad initialization.
- **Fixes:** Leaky ReLU `max(αx, x)` with small α (0.01), PReLU (learned α), ELU, GELU/SiLU, lower learning rates, He initialization (3.24).
- **Non-differentiable at 0:** frameworks define the derivative there (usually 0); irrelevant in practice. Sub-gradient view (1.21).
- **Unbounded above:** activations can grow; normalization helps (3.30–3.32).
- **Piecewise-linear networks:** a ReLU network computes a piecewise-linear function; the XOR network `h = ReLU(x₁+x₂, x₁+x₂−1)`, `y = h₁ − 2h₂` is exact (3.17).
- **Where used:** CNNs and MLPs by default; Transformers moved to GELU/SiLU variants (3.13–3.14) though ReLU is still used (REVIEW_REQUIRED: per-model).

### 4. How does it work?
Elementwise `max(0, z)`; backprop passes the gradient where `z > 0` and blocks it elsewhere.

### 5. Simple example
A one-way valve: let positive flow through unchanged and block negative.

### 6. Technical example
ResNet blocks use ReLU after each convolution/normalization.

### 7. Code
```python
import numpy as np, nn as N
print(N.relu(np.array([-2., 0., 3.])), N.d_relu(np.array([-2., 3.])), N.leaky_relu(np.array([-2.])))   # [0 0 3] [0 1] [-0.02]
```

### 8. Input → Process → Output
`z → max(0,z); backward: gradient × 1[z>0]`

### 9. Enterprise use case
Very cheap on all hardware, simplifying deployment and quantization.

### 10. AI engineering connection
Default in vision and tabular nets; understanding dead units helps debug stalled training.

### 11. Advantages
Simple, fast, non-saturating, sparse.

### 12. Limitations
Dying units; not zero-centered; unbounded; kink at 0.

### 13. Trade-offs
Sparsity and speed vs risk of dead units.

### 14. Common mistakes
Large learning rate causing mass dying; init without He scaling; ReLU on outputs that must be negative; monitoring only loss and missing dead fractions.

### 15. Performance / cost
Cheapest activation; ideal for memory-bound kernels.

### 16. Security
N/A.

### 17. Interview explanation
"ReLU is max(0,x): gradient 1 when active, so it doesn't saturate like sigmoid and it's very cheap. The main risk is dying units, where a neuron's input stays negative and it stops learning; I use He initialization, sensible learning rates, and Leaky ReLU or GELU if I see dead fractions climbing."

### 18. Rapid-fire
max(0,x); gradient 1/0; sparse; risk of dying units; use He init; Leaky ReLU/GELU as alternatives.
