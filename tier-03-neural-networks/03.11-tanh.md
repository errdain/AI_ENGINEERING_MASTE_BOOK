> **In plain words**
> **Tanh** is the sigmoid's **zero-centred cousin**: an S-curve that maps any number into **(−1, 1)** instead of (0, 1). Zero input gives exactly 0, and the curve is steeper (slope up to 1.0 at the middle).
> Balanced outputs make learning better behaved than with the all-positive sigmoid, but tanh **still flattens at the ends**, so it still suffers from vanishing gradients in deep stacks. It lives on in recurrent networks.

### 1. What is it?
`tanh(x) = (eˣ − e⁻ˣ)/(eˣ + e⁻ˣ)`, an S-shaped function mapping the reals to `(−1, 1)`: a rescaled, zero-centred sigmoid.

### 2. Why does it exist?
Zero-centred outputs make optimisation better behaved than the sigmoid's all-positive outputs, and the steeper slope gives larger gradients near 0.

### 3. Detailed explanation
- **Relation:** `tanh(x) = 2σ(2x) − 1`; derivative `1 − tanh²(x)`, maximum **1.0** at 0.
- **It still saturates:** on [−6, 6] about half of the inputs have `tanh′ < 0.01`; deep tanh stacks also suffer from vanishing gradients unless the initialisation keeps pre-activations near the linear region (Xavier, 3.23).
- **Where used:** recurrent networks (hidden-state candidates in LSTM and GRU, Tier 5), small MLPs, outputs bounded to (−1, 1). Transformers use GELU or SiLU in the feed-forward block.
- **Xavier (Glorot) initialisation** was derived for symmetric activations like tanh (3.23).
- **Small networks:** a tanh MLP solves XOR and fits `sin(x)` (3.17).
- **Zero-centred is not always better:** for very deep networks other design choices matter more (normalisation, residual connections).
- **Numerics:** `np.tanh` is stable; naive exponential forms overflow for large `|x|`.

### 4. How does it work?
Squash to (−1, 1); in backpropagation multiply by `1 − tanh²`.

### 5. Simple example
A balanced dimmer that goes from "strongly negative" to "strongly positive".

**By hand.**

| `x` | `tanh(x)` | slope `1 − tanh²` |
|---|---|---|
| −2 | −0.964 | 0.071 |
| 0 | 0 | 1.000 |
| 2 | +0.964 | 0.071 |

### 6. Technical example
An LSTM cell's candidate `c̃ = tanh(W[h, x] + b)` and output `h = o ⊙ tanh(c)`.

### 7. Code
**① By hand (plain Python).**

```python
import math

for x in (-2, 0, 2):
    t = math.tanh(x)
    print(f"x = {x:>2}: tanh {t:+.3f}   slope {1 - t * t:.3f}")
print("tanh(x) = 2*sigmoid(2x) - 1 at x=1.5:", round(math.tanh(1.5), 6), "=", round(2 / (1 + math.exp(-3)) - 1, 6))
```

```text
x = -2: tanh -0.964   slope 0.071
x =  0: tanh +0.000   slope 1.000
x =  2: tanh +0.964   slope 0.071
tanh(x) = 2*sigmoid(2x) - 1 at x=1.5: 0.905148 = 0.905148
```

**② With NumPy.** Large unscaled inputs saturate tanh.

```python
import numpy as np

rng = np.random.default_rng(0)
for scale in (1, 50):
    z = rng.normal(0, scale, 10000)
    slope = 1 - np.tanh(z) ** 2
    print(f"inputs with std {scale:>2}: share of units with slope < 0.01 = {np.mean(slope < 0.01):.1%}  (saturated: they barely learn)")
```

```text
inputs with std  1: share of units with slope < 0.01 = 0.2%  (saturated: they barely learn)
inputs with std 50: share of units with slope < 0.01 = 95.3%  (saturated: they barely learn)
```

**③ With PyTorch.** Tanh versus sigmoid on XOR.

```python
import torch

X = torch.tensor([[0., 0.], [0., 1.], [1., 0.], [1., 1.]])
y = torch.tensor([0., 1., 1., 0.])

def solves_xor(act, seed):
    torch.manual_seed(seed)
    net = torch.nn.Sequential(torch.nn.Linear(2, 4), act, torch.nn.Linear(4, 1))
    opt = torch.optim.Adam(net.parameters(), lr=0.05)
    for _ in range(500):
        opt.zero_grad()
        torch.nn.functional.binary_cross_entropy_with_logits(net(X).squeeze(1), y).backward()
        opt.step()
    return bool(((net(X).squeeze(1) > 0).float() == y).all())

for name, act in (("tanh", torch.nn.Tanh()), ("sigmoid", torch.nn.Sigmoid())):
    print(f"{name:<8} solved XOR in {sum(solves_xor(act, s) for s in range(10))} of 10 random starts")
```

```text
tanh     solved XOR in 9 of 10 random starts
sigmoid  solved XOR in 9 of 10 random starts
```

### 9. Enterprise use case
Rarely a deployment decision; it matters for legacy recurrent models.

### 10. AI engineering connection
Recurrent state updates, small controllers, bounded outputs (for example actions in [−1, 1]).

### 11. Advantages
Zero-centred, smooth, stronger gradients than sigmoid.

### 12. Limitations
Saturates; costs `exp`; vanishing gradients with depth.

### 13. Trade-offs
Better than sigmoid for hidden layers, worse than the ReLU family for deep feed-forward networks.

### 14. Common mistakes
Large unscaled inputs saturating tanh; mixing it with He initialisation; assuming it fixes vanishing gradients.

### 15. Performance / cost
Slightly costlier than ReLU.

### 16. Security
Nothing specific.

### 17. Interview explanation
"Tanh is a zero-centred sigmoid with range (−1, 1) and derivative 1 − tanh², maximum 1. It trains better than sigmoid in hidden layers, but it still saturates; it lives on in recurrent networks and with Xavier initialisation."

### 18. Rapid-fire answer
tanh ∈ (−1, 1), zero-centred, derivative `1 − tanh² ≤ 1`; saturates; common in RNN cells.

### 20. Hands-on exercise
**Goal:** see how input scale decides how many tanh units saturate.

1. Draw 10,000 pre-activations from a normal distribution with standard deviation 0.5, 1, 5 and 50.
2. For each, compute the share of units whose slope `1 − tanh²(z)` is below 0.01.
3. What do you conclude about unscaled inputs?

<details>
<summary>Show a solution</summary>

```python
import numpy as np

rng = np.random.default_rng(0)
for scale in (0.5, 1, 5, 50):
    z = rng.normal(0, scale, 10000)
    print(f"pre-activation std {scale:>4}: {np.mean(1 - np.tanh(z) ** 2 < 0.01):.1%} of units are saturated")
```

```text
pre-activation std  0.5: 0.0% of units are saturated
pre-activation std    1: 0.3% of units are saturated
pre-activation std    5: 54.5% of units are saturated
pre-activation std   50: 95.2% of units are saturated
```

With large pre-activations nearly every unit sits on a flat part of the curve, where gradients are almost zero. Standardise the inputs (2.47) and initialise sensibly (3.23).
