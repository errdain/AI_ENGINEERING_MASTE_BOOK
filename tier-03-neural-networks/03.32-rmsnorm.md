# 3.32 RMSNorm

**Metadata** — Tier: 3 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: High · Hands-on: Medium
Prerequisites: 3.31 · Leads to: Tier 8 and 12 modern LLM architectures

### 1. What is it?
Root-mean-square normalization: `y = γ ⊙ x / √(mean(x²) + ε)`. It rescales each sample to unit RMS **without subtracting the mean** and has only a scale parameter `γ` (no shift). Proposed by Zhang & Sennrich (2019).

### 2. Why does it exist?
It keeps LayerNorm's rescaling benefit with fewer operations and parameters, and has worked as well in many Transformers.

### 3. Detailed explanation
- **Comparison with LayerNorm (D = 1024, 4096 tokens):**
  | property | LayerNorm | RMSNorm |
  |---|---|---|
  | mean subtraction | yes | no |
  | invariant to adding a constant | yes (error 1.8×10⁻¹⁵) | **no** (error 3.9 after +7) |
  | invariant to scaling the input | yes | yes (error 2.8×10⁻⁷ for 10×) |
  | parameters | 2D = 2,048 | D = 1,024 |
  | time (NumPy, this implementation) | 1× | about 0.34× (≈2.9× faster) |
- **When they agree:** for zero-mean inputs they differ only by the small sample-mean term (max difference 0.145 for random data with D = 1024); when inputs have a large common offset (mean 5) the difference is 3.3 because RMSNorm keeps the offset.
- **Hypothesis behind it:** the *rescaling* invariance matters most; re-centering contributes little in practice (REVIEW_REQUIRED: cite ablations).
- **Backward** (tested vs `torch.nn.RMSNorm`): `dx = r·(γ⊙dy) − r³·x·Σ(γ⊙dy⊙x)/D`, `dγ = Σ dy·x̂`, with `r = 1/√(mean(x²)+ε)`.
- **Usage:** a number of recent open LLM families use RMSNorm with pre-norm (REVIEW_REQUIRED: cite specific models); some architectures keep LayerNorm.
- **Cost:** one reduction instead of two, fewer parameters, simpler kernels. In fused GPU kernels the saving is smaller than in this NumPy measurement (REVIEW_REQUIRED).
- **Precision:** accumulate `mean(x²)` in float32; large activations can overflow in fp16 (1.44).
- **Epsilon** placement inside the square root; `ε` values differ by implementation (1e-6 here, matching PyTorch's `RMSNorm` default in our tests with explicit eps).

### 4. How does it work?
Compute the RMS over the feature axis, divide, multiply by the learned gain.

### 5. Simple example
Adjusting the volume so every speaker has the same loudness without moving their baseline.

### 6. Technical example
`y = x * rsqrt(mean(x²) + eps) * weight` in LLaMA-style blocks.

### 7. Code
```python
import numpy as np, nn as N
rn = N.RMSNorm(1024); y = rn.forward(X)                  # unit RMS per row, mean not removed
print(np.sqrt((y ** 2).mean(-1))[:3], rn.n_params())      # [1. 1. 1.]  1024  (LayerNorm has 2048)
```

### 8. Input → Process → Output
`x → x/RMS(x) → γ⊙`

### 9. Enterprise use case
Fewer parameters and cheaper kernels reduce serving cost slightly; weights must be ported with the right normalization type.

### 10. AI engineering connection
Pre-norm RMSNorm in several modern decoder-only LLMs (Tier 8, 12).

### 11. Advantages
Cheaper than LayerNorm; scale-invariant; fewer parameters.

### 12. Limitations
No re-centering; not shift-invariant; empirical rather than theoretical justification.

### 13. Trade-offs
Lower cost vs possible small quality difference in some settings.

### 14. Common mistakes
Assuming RMSNorm equals LayerNorm; porting weights between the two types; wrong epsilon; low-precision accumulation.

### 15. Performance / cost
One reduction per token; fuse with residual add.

N/A.

### 17. Interview explanation
"RMSNorm rescales each token by its root-mean-square and a learned gain, skipping the mean subtraction and the shift parameter of LayerNorm. It's cheaper, still scale-invariant, and many recent LLMs use it in a pre-norm layout — but it's not shift-invariant, so it isn't a drop-in numerical replacement."

### 18. Rapid-fire
y=γ·x/√(mean(x²)+ε): no mean subtraction, no β; scale-invariant, not shift-invariant; cheaper than LayerNorm.
