# 3.16 Linear / Dense layer

**Metadata** — Tier: 3 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: Very high · Hands-on: Very high
Prerequisites: 3.6–3.8, 1.11 · Leads to: 3.17 MLP, Tier 7–8 projections

### 1. What is it?
The layer `y = x Wᵀ + b` (also called **fully connected**, **dense**, or **linear**): every output unit is a weighted sum of all input units.

### 2. Why does it exist?
It is the basic parameterized building block; Transformers are stacks of linear layers plus attention and normalization.

### 3. Detailed explanation
- **Shapes:** `x:(B,n_in)`, `W:(n_out,n_in)`, `b:(n_out)` → `y:(B,n_out)`. Parameters `n_in·n_out + n_out`. Applied to `(B,T,d)` tensors it acts on the last axis.
- **Backward (derived, tested vs PyTorch):** with upstream gradient `dY`: `dW = dYᵀ X`, `db = Σ_batch dY`, `dX = dY W`. Each is itself a matrix product (1.11).
- **A stack of linear layers is linear:** `W₂(W₁x)` equals `(W₂W₁)x`; 8→6→3 has 75 parameters but expresses only what 27 can (3.9).
- **Variants:** no-bias linear, low-rank factorization `W ≈ BA` (LoRA, Tier 10), quantized linear (int8/4-bit, Tier 11), sparse/structured linear, tied embeddings.
- **Cost:** `2·n_in·n_out` FLOPs per sample forward, about twice that for backward (weights and inputs).
- **Initialization matters** (3.22–3.24) and shapes must match across layers (shape asserts help).
- **Convention:** the library follows PyTorch's `(out,in)` weight shape; Keras/TensorFlow store `(in,out)`; conversions require a transpose.
- **Fully connected ≠ always best:** convolution (weight sharing), attention (data-dependent mixing) and recurrence exploit structure to cut parameters.

### 4. How does it work?
Matrix multiply plus bias; cache the input for the backward pass.

### 5. Simple example
Every output looks at every input and keeps its own set of weights.

### 6. Technical example
Q/K/V/output projections in attention and both FFN matrices in a Transformer block are Dense layers.

### 7. Code
```python
import numpy as np, nn as N
d = N.Dense(8, 6, rng=np.random.default_rng(0)); y = d.forward(np.ones((5, 8))); dx = d.backward(np.ones_like(y))
print(d.W.shape, d.dW.shape, dx.shape, d.n_params())       # (6, 8) (6, 8) (5, 8) 54
```

### 8. Input → Process → Output
`x (B,n_in) → xWᵀ + b → y (B,n_out)`

### 9. Enterprise use case
Linear layers dominate parameter counts, hence memory and serving cost.

### 10. AI engineering connection
Most of an LLM's parameters live in Dense layers; LoRA and quantization target them.

### 11. Advantages
General, hardware-optimal (matmul).

### 12. Limitations
Parameter-heavy; no structure assumed; linear on its own.

### 13. Trade-offs
Capacity vs parameter count; fully connected vs structured layers.

### 14. Common mistakes
Shape/transposition errors; forgetting activation between layers; wrong convention when loading weights from another framework.

### 15. Performance / cost
Choose dimensions as multiples of hardware tile sizes; fuse bias/activation.

### 16. Security
Weight tensors are the attack/leak surface (3.6).

### 17. Interview explanation
"A dense layer computes xWᵀ + b; its backward pass is three matrix products — dW = dYᵀX, db = sum of dY, dX = dY·W. Without a nonlinearity two of them collapse into one, so I always count parameters as n_in·n_out plus bias and watch the weight-shape convention across frameworks."

### 18. Rapid-fire
y = xWᵀ+b; params n_in·n_out+n_out; dW = dYᵀX, db = ΣdY, dX = dY·W; stacks of linear collapse.
