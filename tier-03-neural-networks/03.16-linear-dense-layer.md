# 3.16 Linear / Dense layer

**Metadata** — Tier: 3 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: Very high · Hands-on: Very high
Prerequisites: 3.6–3.8, 1.11 · Leads to: 3.17 MLP, Tiers 7–8 projections

> **In plain words**
> A **dense** (or **linear**, or **fully connected**) layer is **a whole row of neurons that each look at all the inputs**: `y = xWᵀ + b`. It is **one matrix multiplication plus a bias**, the workhorse of every neural network. Transformers are mostly stacks of dense layers plus attention and normalisation.
> Learning needs three more matrix products: the **backward pass** gives the gradients for the weights, the bias and the input.

**You need first:** 3.6 Weights, 3.7 Bias, 3.8 Weighted sum, 1.11 Matrix multiplication.

> **Figure 3.16-1 — a dense layer, forward and backward**
>
> ```mermaid
> flowchart LR
>     X["x (B, n_in)"] --> F["y = x Wᵀ + b"]
>     F --> Y["y (B, n_out)"]
>     Y -.->|"upstream gradient dY"| BW["backward:<br/>dW = dYᵀ x<br/>db = sum of dY<br/>dx = dY W"]
> ```
>
> *How to read it:* the forward pass (solid arrows) multiplies by `Wᵀ` and adds `b`. The backward pass (dotted) receives `dY` from the next layer and returns how the loss changes with the weights, the bias, and the layer's own input (to pass on to the previous layer).

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| dense / linear / fully connected | `y = xWᵀ + b` |
| `n_in`, `n_out` | input and output sizes |
| upstream gradient `dY` | the gradient arriving from the next layer |
| `dW`, `db`, `dX` | gradients for weights, bias and input |
| low-rank factorisation | `W ≈ BA` (LoRA, Tier 10) |
| weight tying | sharing an embedding matrix with the output layer |

### 1. What is it?
The layer `y = xWᵀ + b` (also called **fully connected**, **dense** or **linear**): every output unit is a weighted sum of all the input units.

### 2. Why does it exist?
It is the basic parameterised building block; Transformers are stacks of linear layers plus attention and normalisation.

### 3. Detailed explanation
- **Shapes:** `x: (B, n_in)`, `W: (n_out, n_in)`, `b: (n_out)` → `y: (B, n_out)`. Parameters: `n_in·n_out + n_out`. Applied to `(B, T, d)` tensors it acts on the last axis.
- **Backward** (derived, and checked against autograd): with upstream gradient `dY`: `dW = dYᵀ X`, `db = Σ_batch dY`, `dX = dY W`. Each one is itself a matrix product (1.11).
- **A stack of linear layers is linear:** `W₂(W₁x) = (W₂W₁)x`; an 8 → 6 → 3 pair has 75 parameters but expresses only what 27 can (3.9).
- **Variants:** no-bias linear, low-rank factorisation `W ≈ BA` (LoRA, Tier 10), quantised linear (int8, 4-bit, Tier 11), sparse or structured linear, tied embeddings.
- **Cost:** `2·n_in·n_out` FLOPs per example forward, about twice that for the backward pass (weights and inputs).
- **Initialisation matters** (3.22–3.24), and shapes must match across layers (shape assertions help).
- **Convention:** PyTorch stores `W` as `(out, in)`; Keras and TensorFlow store `(in, out)`, so converting needs a transpose.
- **Fully connected is not always best:** convolution (weight sharing), attention (data-dependent mixing) and recurrence exploit structure to cut parameters.

### 4. How does it work?
Matrix multiply plus bias; cache the input for the backward pass.

### 5. Simple example
Every output looks at every input, with its own set of weights.

**Counting.** `Linear(512, 2048)`: weights `512 × 2048 = 1,048,576` plus 2,048 biases = **1,050,624** parameters.

### 6. Technical example
The Q, K, V and output projections in attention, and both matrices of the feed-forward block in a Transformer, are dense layers.

### 7. Code
**① By hand (plain Python).** Forward and backward for a tiny layer with loops.

```python
X = [[1.0, 2.0], [3.0, 4.0]]                      # 2 examples, 2 inputs
W = [[0.5, -1.0], [2.0, 0.0], [1.0, 1.0]]         # 3 outputs
b = [0.0, 1.0, -1.0]
Y = [[sum(X[i][k] * W[j][k] for k in range(2)) + b[j] for j in range(3)] for i in range(2)]
print("forward Y:", Y)

dY = [[1.0, 0.0, 1.0], [0.0, 1.0, 1.0]]           # pretend upstream gradient
dW = [[sum(dY[i][j] * X[i][k] for i in range(2)) for k in range(2)] for j in range(3)]   # dYᵀ X
db = [sum(dY[i][j] for i in range(2)) for j in range(3)]                                   # sum over the batch
print("dW:", dW)
print("db:", db)
```

```text
forward Y: [[-1.5, 3.0, 2.0], [-2.5, 7.0, 6.0]]
dW: [[1.0, 2.0], [3.0, 4.0], [4.0, 6.0]]
db: [1.0, 1.0, 2.0]
```

**② With NumPy.** The same layer, with a finite-difference check of the backward formulas.

```python
import numpy as np

rng = np.random.default_rng(0)
X, W, b = rng.normal(0, 1, (5, 8)), rng.normal(0, 1, (6, 8)), rng.normal(0, 1, 6)
dY = rng.normal(0, 1, (5, 6))
Y = X @ W.T + b
dW, db, dX = dY.T @ X, dY.sum(axis=0), dY @ W
print("shapes:", Y.shape, dW.shape, db.shape, dX.shape)

loss = lambda W_: ((X @ W_.T + b) * dY).sum()                 # a loss whose gradient with respect to Y is exactly dY
h, num = 1e-6, np.zeros_like(W)
for i in range(W.shape[0]):
    for j in range(W.shape[1]):
        Wp, Wm = W.copy(), W.copy(); Wp[i, j] += h; Wm[i, j] -= h
        num[i, j] = (loss(Wp) - loss(Wm)) / (2 * h)
print("dW matches finite differences:", np.allclose(dW, num, atol=1e-6))
```

```text
shapes: (5, 6) (6, 8) (6,) (5, 8)
dW matches finite differences: True
```

**③ With PyTorch.** Parameter counts, autograd, LoRA and tying.

```python
import torch

layer = torch.nn.Linear(512, 2048)
print("Linear(512, 2048) parameters:", sum(p.numel() for p in layer.parameters()))

x = torch.randn(3, 512)
layer(x).sum().backward()
print("autograd dW = (dY)ᵀ x holds:", torch.allclose(layer.weight.grad, torch.ones(3, 2048).T @ x, atol=1e-4))

r = 16
print("LoRA rank-16 update trainable parameters:", r * (512 + 2048), "versus the full matrix:", 512 * 2048)
vocab, d = 50_000, 768
print("weight tying saves", vocab * d, "parameters for a 50k x 768 embedding / output matrix")
```

```text
Linear(512, 2048) parameters: 1050624
autograd dW = (dY)ᵀ x holds: True
LoRA rank-16 update trainable parameters: 40960 versus the full matrix: 1048576
weight tying saves 38400000 parameters for a 50k x 768 embedding / output matrix
```

### 9. Enterprise use case
Linear layers dominate parameter counts, hence memory and serving cost.

### 10. AI engineering connection
Most of an LLM's parameters live in dense layers; LoRA and quantisation target them.

### 11. Advantages
General and hardware-optimal (matrix multiplication).

### 12. Limitations
Parameter-heavy; assumes no structure; linear on its own.

### 13. Trade-offs
Capacity versus parameter count; fully connected versus structured layers.

### 14. Common mistakes
Shape and transposition errors; forgetting an activation between layers; the wrong convention when loading weights from another framework.

### 15. Performance / cost
Choose dimensions as multiples of hardware tile sizes; fuse the bias and activation.

### 16. Security
Weight tensors are the attack and leak surface (3.6).

</details>

### 17. Interview explanation
"A dense layer computes xWᵀ + b; its backward pass is three matrix products: dW = dYᵀX, db = sum of dY, dX = dY·W. Without a non-linearity two of them collapse into one, so I always count parameters as n_in·n_out plus bias and watch the weight-shape convention across frameworks."

### 18. Rapid-fire answer
`y = xWᵀ + b`; parameters `n_in·n_out + n_out`; `dW = dYᵀX`, `db = ΣdY`, `dX = dY·W`; stacks of linear layers collapse.

### 20. Hands-on exercise
**Goal:** count what weight tying saves.

1. A language model has a 50,000-token vocabulary and width 768.
2. The input embedding table is `50,000 × 768`, and the output layer is a `Linear(768, 50,000)` with a weight of the same shape.
3. Count the parameters with and without tying them.

<details>
<summary>Show a solution</summary>

```python
import torch

vocab, d = 50_000, 768
embedding = torch.nn.Embedding(vocab, d)
head = torch.nn.Linear(d, vocab, bias=False)
untied = sum(p.numel() for p in embedding.parameters()) + sum(p.numel() for p in head.parameters())
head.weight = embedding.weight                                    # tie: one shared matrix
tied_count = sum(p.numel() for p in {id(p): p for p in list(embedding.parameters()) + list(head.parameters())}.values())
print("untied parameters:", untied)
print("tied parameters  :", tied_count, f"(saves {untied - tied_count:,})")
```

```text
untied parameters: 76800000
tied parameters  : 38400000 (saves 38,400,000)
```

</details>
