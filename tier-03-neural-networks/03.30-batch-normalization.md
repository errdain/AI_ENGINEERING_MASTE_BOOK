# 3.30 Batch normalization

**Metadata** — Tier: 3 · Phase: 1 · Priority: P0 · Difficulty: 3/5 · Interview: High · Hands-on: High
Prerequisites: 3.9, 1.30, 3.20 · Leads to: 3.31 Layer normalization, Tier 13 CNNs

### 1. What is it?
A layer that **normalizes each feature over the batch** to zero mean and unit variance, then applies a learned scale `γ` and shift `β`: `y = γ·(x − μ_B)/√(σ²_B + ε) + β`. Running averages of `μ` and `σ²` are used at inference. Introduced by Ioffe & Szegedy (2015).

### 2. Why does it exist?
It keeps layer inputs at a stable scale, allowing higher learning rates, faster training and less sensitivity to initialization.

### 3. Detailed explanation
- **Training vs eval:** training uses the current batch's statistics (and updates running averages with momentum); evaluation uses the running statistics (tested against `torch.nn.BatchNorm1d`, including the running mean/variance update and the eval output). After 40 passes over a dataset with feature means around 3 and std 5, the running mean was within 0.13 of the true mean, and eval-mode outputs had mean 0.001 and std 0.997.
- **Backward** (derived, tested vs PyTorch): `dx = (1/N)·inv_std·(N·dx̂ − Σdx̂ − x̂·Σ(dx̂·x̂))`, plus `dγ = Σ dy·x̂`, `dβ = Σ dy`.
- **Higher learning rates:** an 8-block ReLU net at learning rate 0.5 diverges to infinity without normalization but reaches loss 0.0059 with BatchNorm (lab).
- **Batch dependence is the main drawback.** The output for one fixed sample varies with the other samples in its batch: standard deviation across random batches 0.88 (batch size 2), 0.42 (8), 0.18 (32), 0.07 (128): roughly `1/√B`. With a batch of **one**, the normalized output is exactly zero (variance undefined). Training and eval behaviour also differ: the same input gave outputs that differ by up to 4.9 in train vs eval mode right after the first batch.
- **Where it is used:** convolutional networks (normalizing over batch and spatial positions), MLPs. **Transformers use LayerNorm/RMSNorm instead** because sequence batches are variable, small per device, and train/eval consistency is needed (3.31–3.32).
- **Why it works** is debated: reducing 'internal covariate shift' was the original claim; later work points to smoother loss landscapes and better-conditioned gradients (REVIEW_REQUIRED: cite).
- **Position:** commonly Dense/Conv → BN → activation. The preceding bias is redundant because `β` plays that role (3.7).
- **Regularizing side effect:** batch noise acts as mild regularization.
- **Practical issues:** small batches, distributed training (sync BN), frozen BN when fine-tuning with tiny batches, running-stat momentum, and eps.
- **Inference folding:** at eval BN is a fixed affine transform and can be folded into the preceding linear/conv layer.

### 4. How does it work?
Compute batch mean and variance per feature, normalize, scale/shift; keep exponential moving averages for inference.

### 5. Simple example
Re-calibrating every instrument against the group average before reading the results.

### 6. Technical example
ResNet blocks: Conv → BN → ReLU. Fine-tuning detection models often freezes BN statistics.

### 7. Code
```python
import numpy as np, nn as N
bn = N.BatchNorm1d(8); y = bn.forward(X_batch)                 # train mode: batch stats
bn.training = False; y_eval = bn.forward(X_batch)               # eval mode: running stats
print(N.BatchNorm1d(8).forward(X_batch[:1]))                    # batch of one → all zeros
```

### 8. Input → Process → Output
`x → (x−μ_B)/σ_B → γ·x̂+β`; eval: running μ,σ²

### 9. Enterprise use case
Serving requires eval mode and correctly restored running statistics; distribution shift can make stale statistics harmful.

### 10. AI engineering connection
Dominant in CNNs (Tier 13); replaced by LayerNorm/RMSNorm in LLMs (3.31–3.32).

### 11. Advantages
Faster, more stable training; allows higher learning rates; mild regularization.

### 12. Limitations
Batch-size dependent; train/eval discrepancy; awkward for sequences, RNNs and tiny batches.

### 13. Trade-offs
Strong optimization benefits vs batch coupling and mode complexity.

### 14. Common mistakes
Forgetting eval mode; batch size 1 or 2 in training; using BN with dropout before it carelessly; not synchronizing across devices; leaving updated running stats while 'freezing' a model.

### 15. Performance / cost
Extra memory bandwidth (can be fused or folded at inference).

### 16. Security
Batch statistics couple requests in a batch; avoid cross-tenant batching at inference with training-mode BN; membership inference can exploit running stats.

### 17. Interview explanation
"Batch norm standardizes each feature using the batch mean and variance, then applies a learned scale and shift; at inference it uses running averages. It lets me use much higher learning rates — in my test a deep ReLU net diverged at 0.5 without it and trained with it — but its output depends on the rest of the batch, and with a batch of one it collapses, which is why Transformers use LayerNorm."

### 18. Rapid-fire
