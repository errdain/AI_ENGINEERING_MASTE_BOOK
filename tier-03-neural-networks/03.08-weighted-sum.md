# 3.8 Weighted sum

**Metadata** — Tier: 3 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: High · Hands-on: Very high
Prerequisites: 1.10, 1.11, 3.6, 3.7 · Leads to: 3.9 Activation functions, 3.16 Dense layer

### 1. What is it?
The neuron's **pre-activation**: `z = Σⱼ wⱼxⱼ + b = w·x + b`. For a whole layer and batch it is a matrix product: `Z = X Wᵀ + b`.

### 2. Why does it exist?
It is the linear mixing step that combines features; almost all of a network's compute is spent here.

### 3. Detailed explanation
- **Dot-product view (1.10):** `z` measures how aligned the input is with the weight vector, plus an offset; cosine-like when weights and inputs are normalized (1.17).
- **Matrix form (1.11):** `Z = X Wᵀ + b` with `X:(B,n_in)`, `W:(n_out,n_in)`, `b:(n_out,)` → `Z:(B,n_out)`. Row `i` of `Z` depends only on row `i` of `X` (batch independence; tested), except for batch-dependent layers (BatchNorm, 3.30).
- **Cost:** `2·n_in·n_out` FLOPs per sample (multiply + add). A nested-loop implementation and the matrix form agree exactly but the vectorized form was about 2,500× faster in the lab (BLAS/SIMD), the reason networks are written in matrix form.
- **Pre-activation statistics matter:** the scale of `z` determines whether activations saturate (sigmoid/tanh, 3.10–3.11) or die (ReLU, 3.12). Initialization (3.22–3.24) aims for `Var(z) ≈ Var(x)`.
- **Precision:** accumulate sums in higher precision than the stored weights (1.40).
- **Linear layer on sequences:** for `X:(B,T,d)` the same weights act on the last axis (broadcasting, 1.7).
- **Hyperplane view:** `z = 0` is the decision boundary of a single unit (3.7).

### 4. How does it work?
Multiply each input by its weight, sum, add bias — vectorized over units and batch.

### 5. Simple example
A shopping total: quantity × price for each item, plus a fixed fee.

### 6. Technical example
The Q, K, V projections and feed-forward layers in Transformers are weighted sums implemented as large matmuls (Tier 7–8).

### 7. Code
```python
import numpy as np
Z = X @ W.T + b                 # (B, n_in) @ (n_in, n_out) + (n_out,) → (B, n_out)
# equals the triple loop  Z[i, j] = b[j] + Σ_k X[i, k] * W[j, k]
```
TESTED (`lab_01_neurons_and_mlp.ex_3_8`: equality with loops, row independence, speed-up).

### 8. Input → Process → Output
`X (B,n_in), W (n_out,n_in), b → Z (B,n_out)`

### 9. Enterprise use case
Compute budgets and GPU sizing are derived from counts of these multiplications.

### 10. AI engineering connection
FLOPs ≈ 2 × parameters per token for dense layers; attention adds the sequence-length-dependent part (Tier 7, 11).

### 11. Advantages
Simple, parallel, hardware-friendly.

### 12. Limitations
Purely linear; needs activation for expressiveness.

### 13. Trade-offs
Wider layers = more mixing capacity = more compute.

### 14. Common mistakes
Wrong transpose (`X @ W` vs `X @ W.T`); forgetting bias broadcasting; mixing batch and feature axes; Python loops over samples.

### 15. Performance / cost
Matmul efficiency depends on shapes (multiples of 8/16/64 on tensor cores) and dtype.

### 17. Interview explanation
"The weighted sum is w·x plus bias; for a layer it's one matrix multiply, X times W-transpose plus b. That matmul is where nearly all the compute goes, so we write everything in batched matrix form, and we choose initialization so the sums keep a sensible scale."

### 18. Rapid-fire
z = w·x + b; layer form Z = X Wᵀ + b; ≈2·n_in·n_out FLOPs per sample.
