# 3.8 Weighted sum

**Metadata** — Tier: 3 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: High · Hands-on: Very high
Prerequisites: 1.10, 1.11, 3.6, 3.7 · Leads to: 3.9 Activation functions, 3.16 Dense layer

> **In plain words**
> The **weighted sum** is the neuron's **first step**: multiply each input by its weight, add them all up, and add the bias: `z = w·x + b`. It is also called the **pre-activation**.
> Like a shopping total: quantity × price for each item, plus a fixed fee. For a whole layer and a whole batch of examples it is **one matrix multiplication**, and that matmul is where nearly all of a network's computing time goes.

**You need first:** 1.10 Dot product, 1.11 Matrix multiplication, 3.6 Weights, 3.7 Bias.

>
> ```mermaid
> flowchart LR

> *How to read it:* each row of `X` is one example; each column of `Wᵀ` is one neuron's weights; entry `Z[i, j]` is neuron `j`'s weighted sum for example `i`. Doing all of them at once is a single matrix multiplication.

### 1. What is it?
The neuron's **pre-activation**: `z = Σⱼ wⱼxⱼ + b = w·x + b`. For a whole layer and batch it is a matrix product: `Z = X Wᵀ + b`.

### 2. Why does it exist?
It is the linear mixing step that combines features; almost all of a network's compute is spent here.

### 3. Detailed explanation
- **Dot-product view (1.10):** `z` measures how aligned the input is with the weight vector, plus an offset.
- **Matrix form (1.11):** `Z = X Wᵀ + b` with `X: (B, n_in)`, `W: (n_out, n_in)`, `b: (n_out,)` → `Z: (B, n_out)`. Row `i` of `Z` depends only on row `i` of `X` (batch independence), except in batch-dependent layers (BatchNorm, 3.30).
- **Cost:** `2·n_in·n_out` floating-point operations per example (multiply + add). A nested-loop version and the matrix version agree exactly, but the vectorised one is far faster (BLAS and SIMD), which is why networks are written in matrix form.
- **Pre-activation statistics matter:** the scale of `z` decides whether activations saturate (sigmoid and tanh, 3.10–3.11) or die (ReLU, 3.12). Initialisation (3.22–3.24) aims for `Var(z) ≈ Var(x)`.
- **Precision:** accumulate sums in higher precision than the stored weights (1.40).
- **Sequences:** for `X: (B, T, d)` the same weights act on the last axis (broadcasting, 1.7).
- **Hyperplane view:** `z = 0` is the decision boundary of a single unit (3.7).

### 4. How does it work?
Multiply each input by its weight, add them up, add the bias; vectorised over units and batch.

### 5. Simple example
A shopping total: quantity × price for each item, plus a fixed fee.

**By hand.** `w = [2, −1]`, `x = [3, 4]`, `b = 1`: `z = 2·3 + (−1)·4 + 1 = 3`.

**A layer.** Two examples `X = [[1, 2], [3, 4]]`, two neurons `W = [[1, 0], [1, 1]]`, `b = [0, −1]`:

| | neuron 0 (`x₁`) | neuron 1 (`x₁ + x₂ − 1`) |
|---|---|---|
| example 0 | 1 | 2 |
| example 1 | 3 | 6 |

### 6. Technical example
The Q, K, V projections and feed-forward layers in Transformers are weighted sums implemented as large matrix multiplications (Tiers 7–8).

### 7. Code
**① By hand (plain Python).** The triple loop, exactly as defined.

```python
X = [[1, 2], [3, 4]]
W = [[1, 0], [1, 1]]                               # 2 neurons, each with 2 weights
b = [0, -1]
Z = [[b[j] + sum(X[i][k] * W[j][k] for k in range(2)) for j in range(2)] for i in range(2)]
print("Z =", Z)
print("single neuron w=[2,-1], x=[3,4], b=1:", 2 * 3 + (-1) * 4 + 1)
```

```text
Z = [[1, 2], [3, 6]]
single neuron w=[2,-1], x=[3,4], b=1: 3
```

**② With NumPy.** The matrix form equals the loops, and is much faster.

```python
import time
import numpy as np

rng = np.random.default_rng(0)
X, W, b = rng.normal(0, 1, (64, 300)), rng.normal(0, 1, (200, 300)), rng.normal(0, 1, 200)

def loops(X, W, b):
    Z = np.zeros((len(X), len(W)))
    for i in range(len(X)):
        for j in range(len(W)):
            Z[i, j] = b[j] + sum(X[i, k] * W[j, k] for k in range(X.shape[1]))
    return Z

t0 = time.perf_counter(); Z1 = loops(X, W, b); t_loop = time.perf_counter() - t0
t0 = time.perf_counter(); Z2 = X @ W.T + b; t_mat = time.perf_counter() - t0
print("same numbers:", np.allclose(Z1, Z2))
print("matrix form is at least 100x faster:", t_loop / t_mat > 100)
Z_half = X[:10] @ W.T + b
print("row independence (first 10 rows identical when computed alone):", np.allclose(Z2[:10], Z_half))
```

```text
same numbers: True
matrix form is at least 100x faster: True
row independence (first 10 rows identical when computed alone): True
```

**③ With PyTorch.** `F.linear`, and a sequence batch.

```python
import torch
import torch.nn.functional as F

X, W, b = torch.randn(4, 3), torch.randn(2, 3), torch.randn(2)
print("X @ W.T + b equals F.linear:", torch.allclose(X @ W.T + b, F.linear(X, W, b)))
seq = torch.randn(4, 10, 3)                                       # (batch, tokens, features)
print("sequence batch (4, 10, 3) -> ", tuple(F.linear(seq, W, b).shape), "  (same weights applied to the last axis)")
print("FLOPs per example for a 3 -> 2 layer:", 2 * 3 * 2)
```

```text
X @ W.T + b equals F.linear: True
sequence batch (4, 10, 3) ->  (4, 10, 2)   (same weights applied to the last axis)
FLOPs per example for a 3 -> 2 layer: 12
```

### 8. Input → Process → Output
`X (B, n_in), W (n_out, n_in), b → Z (B, n_out)`

### 9. Enterprise use case
Compute budgets and GPU sizing are derived from counts of these multiplications.

### 10. AI engineering connection
FLOPs ≈ 2 × parameters per token for dense layers; attention adds the part that depends on sequence length (Tiers 7, 11).

### 11. Advantages
Simple, parallel, hardware-friendly.

### 12. Limitations
Purely linear; needs an activation for expressiveness.

### 13. Trade-offs
Wider layers mean more mixing capacity and more compute.

### 14. Common mistakes
The wrong transpose (`X @ W` versus `X @ W.T`); forgetting bias broadcasting; mixing batch and feature axes; Python loops over examples.

### 15. Performance / cost
Matmul efficiency depends on shapes (multiples of 8, 16 or 64 on tensor cores) and on the data type.

### 16. Security
Nothing specific.

### 17. Interview explanation
"The weighted sum is w·x plus bias; for a layer it's one matrix multiply, X times W-transpose plus b. That matmul is where nearly all the compute goes, so we write everything in batched matrix form, and we choose initialisation so the sums keep a sensible scale."

### 18. Rapid-fire answer
`z = w·x + b`; layer form `Z = X Wᵀ + b`; about `2·n_in·n_out` FLOPs per example.

### 19. Interview questions
- **Basic:** Compute `z` for `w = [2, −1]`, `x = [3, 4]`, `b = 1`.
- **Intermediate:** What are the shapes in `X @ W.T + b`?
- **Advanced:** Why do tensor-core-friendly shapes matter?

### 20. Hands-on exercise
**Goal:** find the FLOPs of a small network.

1. A network is `784 → 256 → 128 → 10`.
2. Compute the multiply-add FLOPs per example (`2·n_in·n_out` per layer).
3. How many FLOPs for a batch of 64?

<details>
<summary>Show a solution</summary>

```python
sizes = [784, 256, 128, 10]
per_example = sum(2 * a * b for a, b in zip(sizes, sizes[1:]))
print("FLOPs per example:", per_example)
print("FLOPs for a batch of 64:", 64 * per_example)
print("parameters:", sum(a * b + b for a, b in zip(sizes, sizes[1:])), "(FLOPs ≈ 2 × weights, as promised)")
```
