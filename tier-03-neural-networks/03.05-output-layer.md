# 3.5 Output layer

**Metadata** — Tier: 3 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: High · Hands-on: High
Prerequisites: 3.4, 2.14, 2.15 · Leads to: 3.15 Softmax, 2.17 Loss functions, Tier 16 LLM heads

> **In plain words**
> The **output layer** is the **last layer**: it writes the network's answer in the form the task needs: **one number** (a price), **one yes/no score**, or **one score per category**.
> Three things have to match as a set: **how many output units**, **which activation** turns scores into the final form, and **which loss** grades it. Mismatches (like applying softmax twice) are a classic source of silent bugs.

**You need first:** 3.4 Hidden layers, 2.14 Classification, 2.15 Regression.

> **Figure 3.5-1 — choose units, activation and loss as a matched set**
>
> ```mermaid
> flowchart LR
>     H["last hidden<br/>representation"] --> D["Dense → logits"]
>     D --> R["regression:<br/>1 unit, no activation → MSE"]
>     D --> B["binary: 1 logit → sigmoid → BCE"]
>     D --> M["multiclass: K logits → softmax → cross-entropy"]
>     D --> L["multilabel: K logits → K sigmoids → BCE per label"]
> ```
>
> *How to read it:* the same final Dense layer produces raw scores (**logits**); what you do with them depends on the task. In practice the activation is folded *into the loss* for numerical stability, so the network itself outputs logits.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| logit | the raw score before sigmoid or softmax |
| sigmoid | squashes one score into (0, 1) |
| softmax | turns K scores into K probabilities that sum to 1 |
| multiclass | exactly one of K labels is right |
| multilabel | any number of the K labels can be right |
| LM head | the output layer of a language model over its vocabulary |
| weight tying | sharing the input embedding and output weights |

### 1. What is it?
The **final layer** that produces the prediction in the form the task needs: its size, activation and paired loss depend on the problem.

### 2. Why does it exist?
A mismatch between the output layer and the loss (softmax twice, a wrong size) is a common source of silent errors.

### 3. Detailed explanation

| Task | Output units | Activation (on logits) | Loss |
|---|---|---|---|
| Regression (1 value) | 1 | none (identity) | MSE / MAE / Huber |
| Binary classification | 1 (a logit) | sigmoid | binary cross-entropy |
| Multiclass (one label) | K | softmax | categorical cross-entropy |
| Multilabel (several labels) | K | K independent sigmoids | BCE per label |
| Language model (next token) | vocabulary size V | softmax over V | cross-entropy |

- **Feed logits, not probabilities, to the loss:** compute softmax or sigmoid *inside* the loss (2.17, 1.43) for numerical stability.
- **Output size drives parameters:** a language-model head projecting `d_model = 768` onto a 50,000-token vocabulary has `768 · 50,000 + 50,000 ≈ 38.45` million parameters, a large share of a small model. Weight tying with the input embedding is a common saving (Tier 8).
- **Output range matters:** a final ReLU forbids negative regression outputs; a sigmoid bounds outputs to (0, 1); choose accordingly.
- **Calibration:** softmax outputs are not guaranteed to be calibrated (2.43).
- **Multiple heads:** one backbone with several output layers for multi-task learning.
- **Structured outputs:** JSON or tool calls (Tier 19) are produced by the LM head token by token, constrained by decoding; they are not separate output layers.

### 4. How does it work?
The final Dense layer maps the last hidden representation to task-sized logits; the loss (or the inference step) applies the right activation.

### 5. Simple example
The form on which the network writes its answer: one number, a yes/no, or a score per category.

**By hand, three tasks, one logit vector `z = [2.0, 0.5, −1.0]`:**

| Task | Interpretation | Result |
|---|---|---|
| multiclass (3 classes) | softmax(z) | `[0.79, 0.18, 0.04]`: class 0, 79% |
| multilabel (3 tags) | sigmoid on each | `[0.88, 0.62, 0.27]`: tags 0 and 1 on |
| regression (1 value from z₀) | identity | `2.0` |

### 6. Technical example
A 10-class digit classifier: `Dense(64 → 10)` producing logits for a softmax cross-entropy loss.

### 7. Code
**① By hand (plain Python).**

```python
import math

z = [2.0, 0.5, -1.0]
softmax = [math.exp(v) / sum(math.exp(u) for u in z) for v in z]
sigmoid = [1 / (1 + math.exp(-v)) for v in z]
print("softmax  :", [round(v, 3) for v in softmax], " sum =", round(sum(softmax), 6), "(classes compete)")
print("sigmoids :", [round(v, 3) for v in sigmoid], " sum =", round(sum(sigmoid), 3), "(each tag independent)")
print("LM head parameters, 768 -> 50,000:", 768 * 50_000 + 50_000)
```

```text
softmax  : [0.786, 0.175, 0.039]  sum = 1.0 (classes compete)
sigmoids : [0.881, 0.622, 0.269]  sum = 1.772 (each tag independent)
LM head parameters, 768 -> 50,000: 38450000
```

**② With NumPy.** Activation inside the loss: stable cross-entropy from logits.

```python
import numpy as np

def cross_entropy_from_logits(z, y):
    z = z - z.max(axis=1, keepdims=True)                              # stable log-softmax
    log_p = z - np.log(np.exp(z).sum(axis=1, keepdims=True))
    return -log_p[np.arange(len(y)), y].mean()

logits = np.array([[2.0, 0.5, -1.0], [0.1, 0.2, 3.0]])
print("loss:", round(float(cross_entropy_from_logits(logits, np.array([0, 2]))), 4))
print("extreme logits stay finite (loss is essentially 0):", abs(round(float(cross_entropy_from_logits(np.array([[1000.0, -1000.0, 0.0]]), np.array([0]))), 6)))
```

```text
loss: 0.1755
extreme logits stay finite (loss is essentially 0): 0.0
```

**③ With PyTorch.** Matching heads and losses, and the "double softmax" bug.

```python
import torch
import torch.nn.functional as F

torch.manual_seed(0)
h = torch.randn(4, 16)                                             # last hidden representation for 4 examples
head = torch.nn.Linear(16, 5)                                      # 5 classes
logits = head(h)
y = torch.tensor([0, 3, 1, 4])
print("correct (logits -> cross_entropy)  :", round(F.cross_entropy(logits, y).item(), 4))
print("bug (softmax first, then the loss) :", round(F.cross_entropy(torch.softmax(logits, dim=1), y).item(), 4), "<- runs, but wrong")

multilabel = torch.randint(0, 2, (4, 5)).float()
print("multilabel loss (BCE per tag)      :", round(F.binary_cross_entropy_with_logits(logits, multilabel).item(), 4))
print("regression head (1 unit, no activation):", tuple(torch.nn.Linear(16, 1)(h).shape))
```

```text
correct (logits -> cross_entropy)  : 1.7905
bug (softmax first, then the loss) : 1.6339 <- runs, but wrong
multilabel loss (BCE per tag)      : 0.7769
regression head (1 unit, no activation): (4, 1)
```

### 8. Input → Process → Output
`last hidden state → Dense → logits → (softmax or sigmoid) → prediction + loss`

<details>
<summary><b>Beyond the basics (sections 9–16)</b> — real-world use, limits, mistakes. Skip on a first read.</summary>

### 9. Enterprise use case
Output specifications (classes, ranges, thresholds) are part of the model contract with consumers.

### 10. AI engineering connection
LM heads, reward-model scalar heads, classification heads on embeddings, multiple heads in multimodal models.

### 11. Advantages
A task-specific interface with standard loss pairings.

### 12. Limitations
A fixed number of classes; changing the label set needs a new head or retraining.

### 13. Trade-offs
Large vocabularies increase compute and memory in the output projection.

### 14. Common mistakes
Applying softmax before a loss that applies it again; a sigmoid for mutually exclusive classes; the wrong number of units; a ReLU on a regression output.

### 15. Performance / cost
A vocabulary-size softmax is a notable cost at inference (sampling) and in memory for the logit tensor.

### 16. Security
Output filtering and validation are a safety layer: never trust raw model outputs for actions.

</details>

### 17. Interview explanation
"The output layer matches the task: one linear unit for regression, one logit for binary classification, K logits with softmax for multiclass, K independent sigmoids for multilabel. I feed logits to a loss that includes the activation for stability, and I watch the size: an LM head over a 50k vocabulary is tens of millions of parameters."

### 18. Rapid-fire answer
Regression: 1 linear unit; binary: 1 logit + sigmoid; multiclass: K logits + softmax; multilabel: K sigmoids; pass logits to the loss.

### 19. Interview questions
- **Basic:** What is the output layer for 5-class single-label classification?
- **Intermediate:** Softmax versus independent sigmoids: when do you use each?
- **Advanced:** Why feed logits instead of probabilities to the loss?
- **Scenario:** Your tagger should allow "no label", one label, or several. Design the output and loss.

### 20. Hands-on exercise
**Goal:** see that co-occurring labels need sigmoids, not softmax.

1. Make a dataset with 3 tags where each tag is independently on with probability 0.5 (so several can be on).
2. Train one `Linear` head with `BCEWithLogitsLoss`.
3. Show that the per-tag sigmoid probabilities do **not** sum to 1, and that softmax would be the wrong model.

<details>
<summary>Show a solution</summary>

```python
import torch

torch.manual_seed(0)
X = torch.randn(2000, 3)
Y = ((X + 0.5 * torch.randn(2000, 3)) > 0).float()                       # each tag depends on its own feature; several can be on
head = torch.nn.Linear(3, 3)
opt = torch.optim.Adam(head.parameters(), lr=0.05)
for _ in range(300):
    opt.zero_grad()
    torch.nn.functional.binary_cross_entropy_with_logits(head(X), Y).backward()
    opt.step()
p = torch.sigmoid(head(X[:5])).detach()
print("tag probabilities for 5 examples:\n", p.round(decimals=2))
print("row sums (not 1):", [round(v, 2) for v in p.sum(dim=1).tolist()])
print("average number of tags on per example:", round(Y.sum(dim=1).mean().item(), 2), "(a softmax would force exactly one)")
```

        [0.2400, 0.0000, 0.7800],
        [0.0100, 0.7900, 0.7500],
        [0.6000, 0.9900, 0.9700]])
row sums (not 1): [0.37, 2.06, 1.02, 1.55, 2.57]
