### 1. WHAT IS IT?

A **query** `q_i` is the vector a token uses to *ask* "which other tokens are relevant to me?". It is token *i* acting as the reader.

### 2. WHY DOES IT EXIST?

To pick relevant information the model needs a representation of the *need*, separate from the representation used to be found (key) and the information handed over (value). Separating the roles makes attention asymmetric and expressive.

### 3. DETAILED EXPLANATION

Shape for one sequence: `Q ∈ ℝ^{T×d_k}`, one row per query position. Queries and keys must share the dimension `d_k` because they are dotted ([7.6 Dot-product similarity](07.06-dot-product-similarity.md)). The query is not stored in the input; it is *computed* as `q_i = x_i W_q` ([7.5 Q/K/V projections](07.05-q-k-v-projections.md)). In self-attention each token produces a query; in cross-attention the queries come from the decoder side ([7.13 Cross-attention](07.13-cross-attention.md)).

### 4. HOW DOES IT WORK?

1. Take the row `x_i` of the input.
2. Multiply by the learned matrix `W_q` (d_model × d_k).
3. Dot the resulting `q_i` with every key to get one score per key.

### 5. SIMPLE EXAMPLE

Your search query typed into a search engine: it encodes what you need, not what any document says.

### 6. TECHNICAL EXAMPLE

In a decoder-only LLM, the query at the last prompt position is what retrieves context to predict the next token; at generation time only the *new* token needs a fresh query (the older ones' queries are never needed again, which is why the KV cache stores K and V but not Q; Tier 11).

### 7. CODE

```python
import numpy as np
rng = np.random.default_rng(0)
X = rng.normal(size=(6, 8))          # 6 tokens, d_model = 8
Wq = rng.normal(size=(8, 4))         # d_k = 4
Q = X @ Wq                           # (6, 4): one query per token
```
Projection code in context: `MultiHeadAttention.__call__` in [`lab/attention_np.py`](lab/attention_np.py).

### 8. INPUT → PROCESS → OUTPUT

```
x_i (d_model) ──·W_q──► q_i (d_k) ──·k_jᵀ for all j──► scores s_i (S)
```

### 9. ENTERPRISE USE CASE

Not a standalone enterprise topic; matters when debugging shape or caching bugs (e.g. why decode code caches K/V only).

### 10. AI ENGINEERING CONNECTION

The query side is what changes between self-attention, cross-attention and retrieval-like read-outs of memory ([7.12 Self-attention](07.12-self-attention.md), [7.13 Cross-attention](07.13-cross-attention.md)).

### 11. ADVANTAGES

Lets each token ask a different question; learnable.

### 12. LIMITATIONS

A single query vector per head is a fixed-size "question"; it cannot express arbitrarily complex needs, which is one motivation for multiple heads ([7.18 Multi-head attention](07.18-multi-head-attention.md)).

### 13. TRADE-OFFS

Larger `d_k` gives a richer query but a costlier dot product and a larger score variance (needs scaling, [7.8 Scaling by √dk](07.08-scaling-by-dk.md)).

### 14. COMMON MISTAKES

Thinking queries are cached during decoding (they are not); mismatching `d_k` between W_q and W_k.

### 15. PERFORMANCE / COST CONSIDERATIONS

One matmul `X W_q`: O(T·d_model·d_k).

### 16. SECURITY CONSIDERATIONS

No specific concern beyond the shared attention note in [7.1 Why attention](07.01-why-attention.md).

### 17. INTERVIEW EXPLANATION

*"The query is a learned linear projection of a token that says what that token is looking for; it is dotted with every key to get relevance scores."*

### 18. RAPID-FIRE ANSWER

Query = X·W_q: what this token is looking for.
