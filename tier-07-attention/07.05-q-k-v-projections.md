### 1. WHAT IS IT?

The **Q/K/V projections** are three learned linear layers `W_q, W_k, W_v` that map each token's representation `x` into query, key and value spaces:
`Q = X W_q`, `K = X W_k`, `V = X W_v`.

### 2. WHY DOES IT EXIST?

Without projections the score would be `x_i · x_j`, which is symmetric and ties "similar tokens" to "attend strongly". Projections let token *i* attend to token *j* for *asymmetric* reasons (a verb looking for its subject), and let matching and content live in different subspaces.

### 3. DETAILED EXPLANATION

```
Q = X·W_q   W_q ∈ ℝ^{d_model × d_k}
K = X·W_k   W_k ∈ ℝ^{d_model × d_k}
V = X·W_v   W_v ∈ ℝ^{d_model × d_v}
```
They are ordinary learned linear layers (Tier 3) trained by backprop. Many LLMs drop the bias terms (follow the model card; `REVIEW_REQUIRED` per model). In **cross-attention** Q is computed from one tensor and K, V from another ([7.13 Cross-attention](07.13-cross-attention.md)). Multi-head attention uses one set per head, usually implemented as one big matmul followed by a reshape ([7.18 Multi-head attention](07.18-multi-head-attention.md), [7.19 Head dimensions](07.19-head-dimensions.md)). Production code often *fuses* the three into a single `d_model × 3·d_model` matmul for speed; the maths is identical.

![Q/K/V projections](figures/11_qkv_projections.png)

*Figure — left: the same X goes through three different matrices. Middle: raw `X Xᵀ` is symmetric. Right: with projections `Q Kᵀ` is not symmetric.*

### 4. HOW DOES IT WORK?

1. Allocate three weight matrices (initialised small, e.g. variance 1/d_model).
2. Multiply `X` by each.
3. (Multi-head) reshape the last dimension into `H` heads of `d_h` ([7.19 Head dimensions](07.19-head-dimensions.md)).
4. Pass Q, K, V into scaled dot-product attention ([7.11 Scaled dot-product attention](07.11-scaled-dot-product-attention.md)).

### 5. SIMPLE EXAMPLE

Three different "lenses" put on the same photo: one to find, one to be found, one to read.

### 6. TECHNICAL EXAMPLE

In PyTorch `nn.Linear` stores weight as `(out, in)`, so the NumPy matrix `W` (d_model × d_k) equals `linear.weight.T`. The lab test copies weights with `.T` to prove NumPy and PyTorch agree.

### 7. CODE

```python
# Manual projections (NumPy) and the PyTorch equivalent (run from lab/)
import numpy as np, torch
rng = np.random.default_rng(0)
X = rng.normal(size=(1, 5, 16))
Wq = rng.normal(size=(16, 16)) / 4
Q_np = X @ Wq
lin = torch.nn.Linear(16, 16, bias=False)
with torch.no_grad(): lin.weight.copy_(torch.tensor(Wq.T))     # (out,in) = W.T
Q_t = lin(torch.tensor(X, dtype=torch.float32)).detach().numpy()
print(np.allclose(Q_np, Q_t, atol=1e-5))                        # True
```
Full implementations: [`lab/attention_np.py`](lab/attention_np.py), [`lab/attention_torch.py`](lab/attention_torch.py); test `test_numpy_mha_matches_torch_module` in [`lab/test_tier07.py`](lab/test_tier07.py).

### 8. INPUT → PROCESS → OUTPUT

```
X (T×d_model) ─┬─·W_q─► Q (T×d_k)
               ├─·W_k─► K (S×d_k)
               └─·W_v─► V (S×d_v)
```

### 9. ENTERPRISE USE CASE

Parameter counts of attention layers (4·d_model² with output projection, [7.20 Projection matrices](07.20-projection-matrices.md)) are used for model-size and fine-tuning-budget estimates (e.g. which matrices LoRA targets; Tier 10).

### 10. AI ENGINEERING CONNECTION

These matrices are what fine-tuning methods such as LoRA commonly adapt (Tier 10; `REVIEW_REQUIRED` for specific recipes).

### 11. ADVANTAGES

Asymmetric, learnable, separable roles; just matmuls.

### 12. LIMITATIONS

Linear maps only; any non-linearity comes later from the FFN (Tier 8). Fixed `d_k` limits per-head capacity.

### 13. TRADE-OFFS

Separate versus fused projections: fused is faster, separate is simpler and supports MQA/GQA differently-sized K/V ([7.21 MQA](07.21-mqa.md), [7.22 GQA](07.22-gqa.md)).

### 14. COMMON MISTAKES

(1) Transposing weight conventions between NumPy and PyTorch. (2) Computing K and V from the decoder state in cross-attention instead of the encoder output. (3) Forgetting the head reshape/transposition ([7.19 Head dimensions](07.19-head-dimensions.md)).

### 15. PERFORMANCE / COST CONSIDERATIONS

Three matmuls of O(T·d_model²) each: linear in sequence length, unlike the n² score term ([7.23 Attention complexity](07.23-attention-complexity.md)).

### 16. SECURITY CONSIDERATIONS

Weights are model IP; nothing attention-specific beyond usual model-file handling.

### 17. INTERVIEW EXPLANATION

*"Q, K and V are three learned linear projections of the same input. Separate projections make attention asymmetric and let matching and content use different subspaces."*

### 18. RAPID-FIRE ANSWER

Q=XW_q, K=XW_k, V=XW_v: three learned linear maps.
