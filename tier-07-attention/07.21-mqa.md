### 1. WHAT IS IT?

Multi-Query Attention (MQA): all query heads share **one** key head and **one** value head (`H_kv = 1`).

### 2. WHY DOES IT EXIST?

During autoregressive decoding the K and V of all past tokens are cached ([7.24 Attention memory requirements](07.24-attention-memory-requirements.md)). With MHA the cache has `H` K/V heads per layer; at long context or large batch it is large, and **reading it from memory every step** limits decoding speed (memory-bandwidth bound). Sharing K/V shrinks the cache and the bytes read.

### 3. DETAILED EXPLANATION

Proposed by Shazeer (2019; `REVIEW_REQUIRED` citation details). KV cache shrinks by `H×`; K/V projections shrink too. Query heads stay independent (each has its own W_q slice and softmax). Quality can drop slightly versus MHA and training can be less stable (`REVIEW_REQUIRED`: reported in the GQA paper). GQA is the middle ground ([7.22 GQA](07.22-gqa.md)).

![MHA vs GQA vs MQA](figures/05_mha_mqa_gqa.png)

*Figure — the three variants differ only in how many K/V heads exist. Move H and H_kv in [the multi-head / GQA explorer](interactive/multihead_gqa.html).*

### 4. HOW DOES IT WORK?

1. Project K and V to a single head (`d_h`).
2. Broadcast the same K/V to all `H` query heads.
3. Per-head attention as usual.

### 5. SIMPLE EXAMPLE

Many students (queries) all consulting the same single reference book (K/V).

### 6. TECHNICAL EXAMPLE

Cache bytes = `2·L·H_kv·d_h·n·B·bytes`; with `n = 8192`, 32 layers, `d_h = 128`, fp16: MHA (32 KV heads) = 4 GiB per sequence, MQA = 0.125 GiB (exact arithmetic for these illustrative shapes).

### 7. CODE

```python
import numpy as np
from attention_np import MultiHeadAttention, kv_cache_bytes
mqa = MultiHeadAttention(d_model=32, n_heads=8, n_kv_heads=1)        # MQA
x = np.random.default_rng(0).normal(size=(1, 6, 32))
print(mqa(x).shape, mqa.Wk.shape)                                    # (1, 6, 32) (32, 4)
print(kv_cache_bytes(32, 1, 128, 8192) / 2**30, "GiB")                # 0.125
```
Implementation: `n_kv_heads` argument in [`lab/attention_np.py`](lab/attention_np.py) and [`lab/attention_torch.py`](lab/attention_torch.py).

### 8. INPUT → PROCESS → OUTPUT

```
H query heads ─┐
               ├─► share ONE K head, ONE V head ─► per-head attention ─► concat ─► W_o
```

### 9. ENTERPRISE USE CASE

Maximum cache/bandwidth savings for latency-sensitive serving (`REVIEW_REQUIRED` for specific products).

### 10. AI ENGINEERING CONNECTION

Some early/smaller LLMs adopted MQA; most recent large open models use GQA instead (`REVIEW_REQUIRED` per model; Tier 12).

### 11. ADVANTAGES

Smallest KV cache; fastest decode; fewer parameters.

### 12. LIMITATIONS

Possible quality drop; less capacity in K/V.

### 13. TRADE-OFFS

Memory/bandwidth versus quality; GQA interpolates ([7.22 GQA](07.22-gqa.md)).

### 14. COMMON MISTAKES

Sizing the cache with `H` instead of 1; forgetting to broadcast K/V to all heads.

### 15. PERFORMANCE / COST CONSIDERATIONS

Cache ÷ H; the main benefit is at decode time, where the cache is read each token (memory-bound).

### 16. SECURITY CONSIDERATIONS

None specific.

### 17. INTERVIEW EXPLANATION

*"MQA shares a single key and value head across all query heads, shrinking the KV cache by a factor of H and speeding decoding, with a possible small quality loss."*

### 18. RAPID-FIRE ANSWER

One shared K/V head for all query heads.
