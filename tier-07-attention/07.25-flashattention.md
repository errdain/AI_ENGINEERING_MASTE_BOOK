### 1. WHAT IS IT?

FlashAttention computes **exact** attention in **tiles** that fit in fast on-chip memory using an **online softmax**, so the full `n×n` score matrix is never written to slow GPU memory.

### 2. WHY DOES IT EXIST?

On modern accelerators attention is often limited by **memory traffic**, not arithmetic: naive attention writes the n×n scores to high-bandwidth memory, reads them back for softmax, writes weights, reads them again for `WV`.

### 3. DETAILED EXPLANATION

**Idea** (Dao et al., 2022 — `REVIEW_REQUIRED` for details): process key/value tiles one at a time, keeping per row a running max `m`, running denominator `ℓ` and running output accumulator; rescale them whenever a new tile raises the max. In the backward pass needed pieces are recomputed rather than saved. Result: identical outputs (up to floating-point rounding), activation memory linear in `n`, substantially fewer slow-memory reads/writes, hence typically large speed-ups at long sequences (magnitude depends on hardware and version — `REVIEW_REQUIRED`).

**Online-softmax identity.** For a row split into two chunks with maxima `m₁, m₂` and partial sums `ℓ₁ = Σexp(x−m₁)`, `ℓ₂ = Σexp(x−m₂)`, with `m = max(m₁, m₂)`: `ℓ = ℓ₁·exp(m₁−m) + ℓ₂·exp(m₂−m)`. Partial numerators combine the same way.

What it is **not**: not an approximation, and it does not change the O(n²) FLOP count. Later versions/variants exist (`REVIEW_REQUIRED`; fast-moving).

**In practice.** `torch.nn.functional.scaled_dot_product_attention` can dispatch to a fused/flash-style kernel when device, dtype, mask type and shapes allow, otherwise to a plain "math" path (`REVIEW_REQUIRED`: hardware/version dependent). The lab runs on CPU; its tests verify **numerical equivalence of the math**, not flash performance (`NOT_TESTED` on GPU).

### 4. HOW DOES IT WORK?

1. Split K, V into tiles.
2. For each tile: scores `S_t = Q K_tᵀ/√d`; `m_new = max(m, rowmax S_t)`; `p = exp(S_t − m_new)`.
3. `ℓ = ℓ·exp(m − m_new) + rowsum p`; `acc = acc·exp(m − m_new) + p V_t`; `m = m_new`.
4. Output `acc / ℓ`.

### 5. SIMPLE EXAMPLE

Adding up a long receipt tile by tile on a small notepad, correcting the running total whenever a bigger item changes your reference point.

### 6. TECHNICAL EXAMPLE

`tiled_attention` in the lab implements steps 1–4 in NumPy; `test_tiled_online_softmax_attention_is_exact` shows equality to full attention for tile sizes 1, 3, 4, 16, with and without the causal mask.

### 7. CODE

```python
import numpy as np
from attention_np import tiled_attention, scaled_dot_product_attention, causal_mask
rng = np.random.default_rng(0)
q, k, v = rng.normal(size=(9, 8)), rng.normal(size=(9, 8)), rng.normal(size=(9, 5))
ref, _ = scaled_dot_product_attention(q, k, v, causal_mask(9))
out = tiled_attention(q, k, v, tile=4, mask=causal_mask(9))
print(np.abs(out - ref).max() < 1e-12)            # True
```
Source: `tiled_attention` in [`lab/attention_np.py`](lab/attention_np.py). This teaches the algebra only; a real kernel also controls on-chip memory placement.

### 8. INPUT → PROCESS → OUTPUT

```
Q tile + (K,V) tiles streamed ─► running (m, ℓ, acc) per row ─► acc/ℓ = exact attention
(never store the n×n matrix)
```

### 9. ENTERPRISE USE CASE

Enables long-context training/serving on fixed GPU memory; typical default in modern frameworks when supported (`REVIEW_REQUIRED`).

### 10. AI ENGINEERING CONNECTION

Makes 8k–128k contexts practical; combine with GQA and paged KV caches (Tier 11).

### 11. ADVANTAGES

Exact; O(n) extra memory; faster due to less memory traffic.

### 12. LIMITATIONS

Same quadratic FLOPs; needs fused-kernel support (hardware, dtype, mask kinds); complex to implement and debug.

### 13. TRADE-OFFS

Speed/memory versus implementation complexity and kernel-availability constraints.

### 14. COMMON MISTAKES

Calling it an approximation; expecting it to reduce FLOPs; assuming PyTorch always uses it (dispatch depends on conditions).

### 15. PERFORMANCE / COST CONSIDERATIONS

Benefit grows with sequence length; speed-up magnitudes `REVIEW_REQUIRED`, not measured here.

### 16. SECURITY CONSIDERATIONS

Custom fused kernels deserve numerical tests against a reference (as the lab does).

### 17. INTERVIEW EXPLANATION

*"FlashAttention computes exact attention without ever materialising the n-by-n score matrix: it processes the sequence in tiles in on-chip memory with an online softmax, and recomputes in the backward pass. It cuts memory from quadratic to linear and cuts memory traffic, which is the real bottleneck, but the FLOPs are still quadratic."*

### 18. RAPID-FIRE ANSWER

Exact, tiled, IO-aware attention: O(n) extra memory, O(n²) compute.
