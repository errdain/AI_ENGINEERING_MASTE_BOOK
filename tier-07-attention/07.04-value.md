### 1. WHAT IS IT?

A **value** `v_j` is the vector token *j* hands over when attention selects it. The output is a weighted mix of values.

### 2. WHY DOES IT EXIST?

What a token should *contribute* is different from how it should be *found*. Having a separate value projection lets the model move useful content without distorting the matching geometry.

### 3. DETAILED EXPLANATION

Shape `V ∈ ℝ^{S×d_v}`. `v_j = x_j W_v`. `d_v` may differ from `d_k` in theory, but in practice `d_v = d_k = d_model / H` ([7.19 Head dimensions](07.19-head-dimensions.md)). The output row is `Σ_j w_ij v_j` ([7.10 Weighted values](07.10-weighted-values.md)), a convex combination, so it stays inside the convex hull of the value rows.

### 4. HOW DOES IT WORK?

1. `v_j = x_j W_v`.
2. After softmax gives weights ([7.9 Softmax](07.09-softmax.md)), multiply: `Out = W V`.

### 5. SIMPLE EXAMPLE

The text inside the cookbook you actually read once the label got it chosen.

### 6. TECHNICAL EXAMPLE

Induction-style "copy" behaviour ([7.27 Attention patterns](07.27-attention-patterns.md)) can be seen as keys matching earlier occurrences while values carry the next token's identity forward.

### 7. CODE

```python
import numpy as np
rng = np.random.default_rng(0)
X = rng.normal(size=(6, 8)); Wv = rng.normal(size=(8, 4))
V = X @ Wv                                 # (6, 4)
w = np.full((1, 6), 1/6)                   # uniform weights
print((w @ V).round(3), V.mean(0).round(3))  # uniform weights = plain average
```

### 8. INPUT → PROCESS → OUTPUT

```
weights (T×S)  ×  V (S×d_v)  ─►  output (T×d_v)
```

### 9. ENTERPRISE USE CASE

Values are the other half of the KV cache; cache sizing treats K and V symmetrically ([7.24 Attention memory requirements](07.24-attention-memory-requirements.md)).

### 10. AI ENGINEERING CONNECTION

Values are what is eventually written into the residual stream (Tier 8) after the output projection ([7.20 Projection matrices](07.20-projection-matrices.md)).

### 11. ADVANTAGES

Decouples content from matching; cheap linear map.

### 12. LIMITATIONS

Output is limited to a convex mix of existing values for one head; richer output needs multiple heads and `W_o`.

### 13. TRADE-OFFS

`d_v` size versus output-projection cost and cache size.

### 14. COMMON MISTAKES

Applying softmax to V; mixing up which tensor supplies V in cross-attention (the context, not the decoder state).

### 15. PERFORMANCE / COST CONSIDERATIONS

Projection O(S·d_model·d_v); the `W V` product costs T·S·d_v multiply-adds.

### 16. SECURITY CONSIDERATIONS

Poisoned content in values (e.g. injected instructions) is blended like any other (see [7.1 Why attention](07.01-why-attention.md)).

### 17. INTERVIEW EXPLANATION

*"Values carry the information that gets mixed. Keys decide how much of each value is used, values decide what is actually passed on."*

### 18. RAPID-FIRE ANSWER

Value = X·W_v: the payload that gets averaged.

### 19. INTERVIEW QUESTIONS

**Basic.** What is the role of V?

**Intermediate.** Why is the output a convex combination of value rows?

**Advanced.** What would happen if V were the identity (V = X)? What capacity is lost?

**Scenario.** Attention output looks like a plain average of the context. What does that tell you about the weights?
