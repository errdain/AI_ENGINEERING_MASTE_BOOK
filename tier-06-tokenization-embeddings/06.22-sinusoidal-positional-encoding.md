# 6.22 Sinusoidal positional encoding

**Metadata** — Tier: 6 · Phase: 2 · Priority: High · Difficulty: Intermediate · Interview: High · Hands-on: High
Prerequisites: [6.20 Positional information](06.20-positional-information.md) · Leads to: [6.23 Relative positional encoding](06.23-relative-positional-encoding.md), [6.24 RoPE](06.24-rope.md)

> **In plain words**
> **Sinusoidal positional encoding** gives every position a fixed vector built from sine and cosine waves of different wavelengths, like the hands of a clock: fast waves tell neighbouring positions apart, slow waves tell far-apart positions apart. Nothing is learned (no parameters), and the vector is simply added to the token embedding. It comes from the original Transformer paper.

### 1. What is it?

Sinusoidal positional encoding is the fixed, parameter-free scheme from the original Transformer: each position gets a vector of sines and cosines at geometrically spaced frequencies, added to the token embedding.

### 2. Why does it exist?

Provides unique, smoothly varying position codes with no parameters, and makes relative offsets easy to compute (a shift by *k* is a linear map of the encoding).

### 3. Detailed explanation

```
PE[pos, 2i]   = sin(pos / 10000^(2i/d))
PE[pos, 2i+1] = cos(pos / 10000^(2i/d))
```
Each dimension pair is a wave with its own wavelength, from `2*pi` up to `10000*2*pi`: fast pairs resolve neighbouring positions, slow pairs distinguish far ones, like the digits of a clock. A shift by *k* acts on each (sin, cos) pair as a rotation by `k*omega_i`, hence a **linear map**; this was the design motivation. In practice it extrapolates only weakly to lengths unseen in training (`REVIEW_REQUIRED` for strength of claim).

### 5. Simple example

A clock with many hands: the second hand tells fine differences, the hour hand tells coarse ones; together they identify the time uniquely.

**By hand.** For `d = 4`: frequencies `1` and `1/100` (since `10000^(-2i/d)` with `i = 0, 1`). Position 0 → `[sin 0, cos 0, sin 0, cos 0] = [0, 1, 0, 1]`. Position 1 → `[sin 1, cos 1, sin 0.01, cos 0.01] = [0.84, 0.54, 0.01, 1.00]`. Position 2 → `[0.91, −0.42, 0.02, 1.00]`. The first pair changes quickly with position, the second slowly.

### 6. Technical example

Position 0 is `[0,1,0,1,...]` (all sines 0, all cosines 1), a fact the lab test checks.

### 7. Code

**① By hand (plain Python).** Compute the table for four positions with the formula.

```python
import math

d = 4
def pe(pos):
    row = []
    for i in range(d // 2):
        w = 10000 ** (-2 * i / d)
        row += [math.sin(pos * w), math.cos(pos * w)]
    return row

for pos in range(3):
    print(f"position {pos}:", [round(v, 2) for v in pe(pos)])
```

```text
position 0: [0.0, 1.0, 0.0, 1.0]
position 1: [0.84, 0.54, 0.01, 1.0]
position 2: [0.91, -0.42, 0.02, 1.0]
```

**② With NumPy.** The full table, and similarity between positions.

```python
import numpy as np

n, d = 50, 16
pos = np.arange(n)[:, None]
freq = 10000 ** (-np.arange(0, d, 2) / d)
pe = np.zeros((n, d)); pe[:, 0::2] = np.sin(pos * freq); pe[:, 1::2] = np.cos(pos * freq)
print("shape:", pe.shape, "  all values within [-1, 1]:", bool(np.abs(pe).max() <= 1.0))
print("position 0, first four values:", pe[0, :4])
dots = (pe @ pe[10]).round(1)
print("dot product with position 10 at positions 10, 11, 15, 30:", dots[[10, 11, 15, 30]], "(maximum d/2 = 8 at itself)")
```

```text
shape: (50, 16)   all values within [-1, 1]: True
position 0, first four values: [0. 1. 0. 1.]
dot product with position 10 at positions 10, 11, 15, 30: [8.  7.5 6.1 5.8] (maximum d/2 = 8 at itself)
```

### 8. Input → Process → Output

```
pos, dim-pair i ──► sin/cos(pos·ω_i) with ω_i = 10000^(-2i/d) ──► vector added to token embedding
```

### 9. Enterprise use case

Rarely a deployment choice today, but appears in many baseline/legacy models and encoders for time-series and vision patches.

### 10. AI engineering connection

Historical foundation; the rotation idea is the conceptual ancestor of RoPE ([6.24 RoPE](06.24-rope.md)).

### 11. Advantages

No parameters; any length can be computed; smooth; interpretable.

### 12. Limitations

Absolute (relative info is implicit); weak extrapolation in practice; added at the input only.

### 13. Trade-offs

No parameters versus less flexibility than learned or relative methods.

### 14. Common mistakes

- Odd `d_model`.
- Forgetting to scale embeddings consistent with the original recipe.
- Assuming it guarantees length generalization.

### 15. Performance / cost

Precompute the table once; O(L*d) memory.

### 16. Security

Nothing specific.

### 20. Hands-on exercise

Use the interactive page: change base from 10000 to 100; observe which dimensions stop varying.

<details>
<summary>Show a solution</summary>

```python
import numpy as np
import sys
sys.path.insert(0, "lab")
from positional import sinusoidal

pe = sinusoidal(200, 32)
for gap in (1, 5, 20, 100):
    sims = [pe[i] @ pe[i + gap] / (np.linalg.norm(pe[i]) * np.linalg.norm(pe[i + gap])) for i in range(0, 100)]
    print(f"gap {gap:>3}: average cosine similarity between positions {np.mean(sims):.2f}")
```

```text
gap   1: average cosine similarity between positions 0.96
gap   5: average cosine similarity between positions 0.74
gap  20: average cosine similarity between positions 0.65
gap 100: average cosine similarity between positions 0.58
```

Nearby positions are similar and distant ones less so: a free notion of distance that a learned table (6.21) would have to discover.
