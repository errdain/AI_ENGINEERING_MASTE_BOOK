# 6.21 Learned positional embeddings

**Metadata** — Tier: 6 · Phase: 2 · Priority: Medium · Difficulty: Beginner · Interview: Medium · Hands-on: Medium
Prerequisites: [6.20 Positional information](06.20-positional-information.md), [6.18 Embedding matrix](06.18-embedding-matrix.md) · Leads to: [6.23 Relative positional encoding](06.23-relative-positional-encoding.md)

> **In plain words**
> **Learned absolute positional embeddings** are a second embedding table, one row per *position* (0, 1, 2, … up to a maximum length). The input to the model is `token vector + position vector`. It is the simplest scheme (used by GPT-2 and BERT), but a position beyond the table's last row simply has no vector.

**You need first:** [6.20 Positional information](06.20-positional-information.md), [6.18 Embedding matrix](06.18-embedding-matrix.md).

> **Figure 6.21-1 — Token vector plus position vector**
>
> ```mermaid
> flowchart LR
>     A["token id"] --> B["token table E[id]"]
>     C["position number"] --> D["position table P[pos]"]
>     B --> E["+"]
>     D --> E
>     E --> F["input to the first layer"]
> ```
>
> *How to read it:* two lookups, one by token id and one by position number, are added. Both tables are trained like any other weights. The position table has exactly `L_max` rows, which is the longest input the model can accept.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| absolute position | the index of a token in the sequence: 0, 1, 2 … |
| L_max | the number of rows of the position table = maximum context length |
| learned | trained by backpropagation, not computed from a formula |
| extrapolation | handling positions longer than any seen in training |
| interpolation | squeezing positions to reuse existing rows for longer inputs |
| IndexError | what happens when you ask for a row that does not exist |

### 1. What is it?

Learned absolute positional embeddings are a second trainable table `P in R^(L_max x d)`; the input is `E[token] + P[position]`.

### 2. Why does it exist?

The simplest way to give the model position information: let it learn whatever representation of 'position k' is useful.

### 3. Detailed explanation

Used by GPT-2 (1,024 positions) and BERT (512 positions) (`REVIEW_REQUIRED`). **Limits:** positions beyond `L_max` have no vector, so there is no built-in extrapolation; extending context means adding and training new rows (or interpolating existing ones). The table costs `L_max*d` parameters.

### 4. How does it work?

`x_t = E[id_t] + P[t]` for `t = 0..L-1`; `P` is trained by backprop with the rest of the model.

### 5. Simple example

Numbered seats: seat 57 simply doesn't exist in a hall with 50 seats.

**By hand.** `d = 3`, `L_max = 4`. Token vector for "cat" `[1, 0, 2]`; position vectors `P[0] = [0, 0, 0]`, `P[1] = [0.1, 0.2, 0.3]`. "cat" at position 1 enters the model as `[1.1, 0.2, 2.3]`. The same word at position 0 enters as `[1, 0, 2]`: that difference is all the model has to know the order. Position 4 would need a fifth row that does not exist.

### 6. Technical example

GPT-2 small: 1024 x 768 = 786k position parameters.

### 7. Code

**① By hand (plain Python).** Add the two vectors and show the out-of-range failure.

```python
tok = {"cat": [1.0, 0.0, 2.0]}
P = [[0.0, 0.0, 0.0], [0.1, 0.2, 0.3], [0.2, 0.4, 0.6], [0.3, 0.6, 0.9]]    # L_max = 4 rows
for pos in (0, 1):
    print(f"'cat' at position {pos}:", [round(a + b, 2) for a, b in zip(tok["cat"], P[pos])])
try:
    P[4]
except IndexError:
    print("position 4 -> IndexError: the table has only", len(P), "rows")
```

```text
'cat' at position 0: [1.0, 0.0, 2.0]
'cat' at position 1: [1.1, 0.2, 2.3]
position 4 -> IndexError: the table has only 4 rows
```

**② With NumPy.** Parameters of the position table, and why it adds to GPT-2-sized models only a little.

```python
import numpy as np

for name, L, d in (("GPT-2-style", 1024, 768), ("BERT-base-style", 512, 768), ("a 128k-context model", 131_072, 4096)):
    print(f"{name:<22} L_max = {L:>7,}, d = {d:>4}: position table {L * d / 1e6:8.2f} million parameters")
rng = np.random.default_rng(0)
P = rng.normal(size=(16, 8))
print("interpolating 16 rows to serve 32 positions:", np.stack([np.interp(np.linspace(0, 15, 32), np.arange(16), P[:, c]) for c in range(8)], axis=1).shape)
```

```text
BERT-base-style        L_max =     512, d =  768: position table     0.39 million parameters
a 128k-context model   L_max = 131,072, d = 4096: position table   536.87 million parameters
interpolating 16 rows to serve 32 positions: (32, 8)
```

**③ With PyTorch.** Two nn.Embedding tables added together.

```python
import torch

torch.manual_seed(0)
V, L_max, d = 100, 16, 8
tok, pos = torch.nn.Embedding(V, d), torch.nn.Embedding(L_max, d)
ids = torch.randint(0, V, (2, 10))
x = tok(ids) + pos(torch.arange(10))                     # broadcast over the batch
print("input shape (batch, sequence, d):", tuple(x.shape))
try:
    pos(torch.arange(20))
except IndexError:
    print("asking for 20 positions with L_max = 16 -> IndexError")
```

```text
input shape (batch, sequence, d): (2, 10, 8)
asking for 20 positions with L_max = 16 -> IndexError
```

### 9. Enterprise use case

Legacy encoder models used in classification/search pipelines still use this scheme; max length is a hard limit in those services.

### 10. AI engineering connection

Baseline against which sinusoidal, RoPE and ALiBi are compared.

### 11. Advantages

Simple; flexible; learnable.

### 12. Limitations

Hard max length; no extrapolation; extra parameters; absolute only.

### 13. Trade-offs

Flexibility versus generalization beyond trained length.

### 14. Common mistakes

- Feeding sequences longer than `L_max` (index error or silent truncation).
- Resizing the table without training new rows.

### 15. Performance / cost

`L_max*d` parameters; negligible compute.

### 16. Security

Hard length caps are a reliable guardrail against over-long input; enforce them in tokens before the model.

```python
import torch

pos = torch.nn.Embedding(8, 4)
a, b = pos(torch.arange(8))[1], pos(torch.arange(8))[6]
print("positions 1 and 6 start as different random vectors:", not torch.equal(a, b))

```

```text
positions 1 and 6 start as different random vectors: True
cosine similarity between positions 1 and 6 before any training: -0.04
```

Before training, the position vectors are random and carry no notion of 'nearby'. Training has to discover from data that position 5 is close to position 6, something a sinusoidal table (6.22) has built in.
