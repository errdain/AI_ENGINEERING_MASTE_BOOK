### 1. WHAT IS IT?

A token embedding is the learnable vector associated with one token ID: the model's first representation of that token.

### 2. WHY DOES IT EXIST?

Integer IDs have no geometry; vectors let the network express similarity and let gradient descent shape each token's meaning.

### 3. DETAILED EXPLANATION

At the input layer the vector depends **only on the ID** (static): the word 'bank' gets the same vector in 'river bank' and 'bank loan'. Context is added by later layers ([Tier 8](../tier-08-transformer-architecture/README.md)). Embeddings are learned by backpropagation like any weight; only rows for tokens that appear in the batch receive gradient.

Original-Transformer convention: embeddings are scaled by `sqrt(d_model)` before adding position encodings (`REVIEW_REQUIRED`: practice varies by model).

### 5. SIMPLE EXAMPLE

A name badge with a long number written on it that follows each token around.

### 6. TECHNICAL EXAMPLE

Repeated IDs share a row, so repeated tokens in a sentence produce identical input vectors until positions are added.

### 7. CODE

```python
import torch, torch.nn as nn
emb = nn.Embedding(num_embeddings=8, embedding_dim=4)   # E: 8 x 4
ids = torch.tensor([2, 5, 2])
x = emb(ids)                                            # (3, 4)
assert torch.equal(x[0], x[2])                          # same ID -> same vector
x.sum().backward()
rows_touched = (emb.weight.grad.abs().sum(1) > 0).nonzero().flatten().tolist()
print(rows_touched)                                     # [2, 5] only
```

### 8. INPUT → PROCESS → OUTPUT

```
[2, 5, 2] ──E[ids]──► (3, d) float tensor ──► + position info ──► transformer
```

### 9. ENTERPRISE USE CASE

Fine-tuning that adds domain tokens must initialize the new rows sensibly (e.g. mean of constituent sub-token embeddings), a standard engineering practice.

### 10. AI ENGINEERING CONNECTION

First layer of every LLM; the output layer is often tied to it (see [6.18 Embedding matrix](06.18-embedding-matrix.md)).

### 11. ADVANTAGES

Learned, dense, cheap lookup; sparse gradients.

### 12. LIMITATIONS

Static (context-free) at input; rare tokens are undertrained; table size scales with V.

### 13. TRADE-OFFS

Higher d = more capacity and memory.

### 14. COMMON MISTAKES

- Confusing token embeddings with sentence embeddings ([6.26 Token vs semantic embeddings](06.26-token-vs-semantic-embeddings.md)).
- Treating a newly added token's random row as meaningful.

### 15. PERFORMANCE / COST CONSIDERATIONS

Lookup is memory-bound and cheap; the table is `V*d` parameters.

### 16. SECURITY CONSIDERATIONS

Embedding rows of rarely-seen tokens may leak memorized training strings via nearest-neighbour inspection; do not publish raw embeddings of private-data-trained models without review (`REVIEW_REQUIRED`).

### 17. INTERVIEW EXPLANATION

*"A token embedding is a learned vector for each token ID, looked up from a table. It's context-free at the input; transformer layers add context."*

### 18. RAPID-FIRE ANSWER

Learned vector per token ID; static at input.
