# 6.16 Attention masks

**Metadata** — Tier: 6 · Phase: 2 · Priority: Critical · Difficulty: Intermediate · Interview: Very high · Hands-on: High
Prerequisites: [6.9 PAD](06.09-pad.md), [6.7 Token IDs](06.07-token-ids.md) · Leads to: [Tier 7](../tier-07-attention/README.md) (attention math), [Tier 8](../tier-08-transformer-architecture/README.md)

> **In plain words**
> An **attention mask** tells the attention layer which positions it may look at. The **padding mask** hides the filler tokens; the **causal mask** hides the future so that, when predicting a token, the model cannot peek at the answer. Masked positions get a score of `−∞`, so after the softmax their weight is exactly zero.

**You need first:** [6.9 PAD](06.09-pad.md), [6.7 Token IDs](06.07-token-ids.md).

| Word | What it means here |
|---|---|

| padding mask | hides <PAD> positions |
| causal mask | hides future positions (lower-triangular) |

### 1. What is it?

An attention mask is a 0/1 (or 0/-infinity) array telling the attention layer which positions may be attended to. The **padding mask** hides `<PAD>` positions; the **causal mask** hides future positions.

### 2. Why does it exist?

Padding carries no information and the future must be invisible during next-token training; masks enforce both without changing tensor shapes.

### 3. Detailed explanation

Masking is applied to attention *scores* before softmax: allowed positions keep their score, forbidden ones are set to `-inf`, so softmax gives them exactly zero weight. Full attention mathematics is owned by [Tier 7](../tier-07-attention/README.md); this file covers only what the *tokenization* side must provide: the PAD mask.

Combining: `allowed = causal AND key_is_real`. A row with **no** allowed key (possible with left padding and a padded query) produces NaN in softmax; frameworks avoid or patch that case (`REVIEW_REQUIRED` per framework).

### 5. Simple example

Covering the blank lines of an exam sheet so that nobody can read answers into them, and covering the future pages so nobody peeks ahead.

**By hand.** Three real tokens then two pads (`[1,1,1,0,0]`) and a causal mask. For the query at position 2, allowed keys are positions 0, 1, 2 (causal) AND real (padding mask) = `[1,1,1,0,0]`. Raw scores `[0.5, 0.1, 0.4, ...]` become `[0.5, 0.1, 0.4, −∞, −∞]`; softmax gives weights `[0.39, 0.26, 0.35, 0, 0]` (they sum to 1; the masked ones are exactly 0).

### 6. Technical example

In a batch with lengths 5 and 8, sequence A's three last key positions are masked for every query.

### 7. Code

**① By hand (plain Python).** Build the combined mask for one batch row and apply it to scores.

```python
import math

real = [1, 1, 1, 0, 0]                                  # 3 real tokens, 2 pads
n = len(real)
scores = [0.5, 0.1, 0.4, 0.9, 0.9]                     # raw scores of the query at position 2
q = 2
allowed = [1 if (k <= q and real[k] == 1) else 0 for k in range(n)]    # causal AND real
masked = [s if a else -math.inf for s, a in zip(scores, allowed)]
exps = [math.exp(s) for s in masked]
weights = [e / sum(exps) for e in exps]
print("allowed keys:", allowed)
print("weights:", [round(w, 2) for w in weights], " sum =", round(sum(weights), 2))
```

```text
allowed keys: [1, 1, 1, 0, 0]
weights: [0.39, 0.26, 0.35, 0.0, 0.0]  sum = 1.0
```

**② With NumPy.** The full batch of masks with arrays; padded rows can become NaN if everything is masked.

```python
import numpy as np

lengths = [3, 5]
pm = np.arange(5)[None, :] < np.array(lengths)[:, None]            # (batch, key) True for real tokens
causal = np.tril(np.ones((5, 5), dtype=bool))
allowed = causal[None] & pm[:, None, :]                             # (batch, query, key)
scores = np.zeros((2, 5, 5))
scores = np.where(allowed, scores, -np.inf)
with np.errstate(invalid="ignore"):
    w = np.exp(scores - scores.max(-1, keepdims=True)); w /= w.sum(-1, keepdims=True)
print("last real query of the short row:", w[0, 2].round(2))
print("a padded QUERY (row 4 of the short sequence) still has allowed keys:", allowed[0, 4].sum(), "of 5")
print("weights on padded keys are zero:", bool((w[0][:, 3:] == 0).all()))
```

```text
last real query of the short row: [0.33 0.33 0.33 0.   0.  ]
a padded QUERY (row 4 of the short sequence) still has allowed keys: 3 of 5
weights on padded keys are zero: True
```

### 9. Enterprise use case

Serving stacks build masks per batch; wrong masks are a data-leakage bug across requests in shared batches.

### 10. AI engineering connection

Foundation of correct batched training/inference for every transformer; mask bugs produce subtly wrong results without errors.

### 11. Advantages

Fixed shapes; GPU-friendly; exact.

### 12. Limitations

O(n^2) mask memory if materialized (fused kernels avoid it); all-masked rows give NaN.

### 13. Trade-offs

Explicit masks are simple but wasteful; fused/flash kernels trade flexibility for memory ([Tier 7](../tier-07-attention/README.md)).

### 14. Common mistakes

- Forgetting the padding mask.
- Using 0 instead of -inf (or a large negative) on *scores*.
- Mask dtype/broadcast shape errors.
- Left-padding with absolute positions not shifted.

### 15. Performance / cost

Mask construction is cheap; materialized masks cost O(batch x seq^2) memory.

### 16. Security

Incorrect masks can leak one request's tokens into another's attention in multi-tenant batching; test with canary inputs.
