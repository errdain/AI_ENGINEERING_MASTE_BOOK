# 6.3 Word tokenization

**Metadata** — Tier: 6 · Phase: 2 · Priority: Medium · Difficulty: Beginner · Interview: Medium · Hands-on: Medium
Prerequisites: [6.1 Text preprocessing](06.01-text-preprocessing.md) · Leads to: [6.5 Subword tokenization](06.05-subword-tokenization.md), [6.6 Vocabulary](06.06-vocabulary.md), [6.8 UNK](06.08-unk.md)

> **In plain words**
> **Word tokenization** cuts text into words and gives each distinct word one vocabulary entry. Sequences are short and each token has an obvious meaning, but the vocabulary explodes (every inflection, name and typo is new) and any word not seen in training becomes `<UNK>`, throwing its information away.

**You need first:** [6.1 Text preprocessing](06.01-text-preprocessing.md).

> **Figure 6.3-1 — Whole-word lookup and the unknown-word problem**
>
> ```mermaid
> flowchart LR
>     A["the dog sat"] --> B["the | dog | sat"]
>     B --> C["look up each word"]
>     C --> D["the = 2, dog = UNK (never seen), sat = 4"]
> ```
>
> *How to read it:* every word is looked up as a whole. Words seen in training get their id; any other word maps to the same `<UNK>` id, so the model cannot tell "dog" from "zebra" from a typo.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| word token | a vocabulary entry for one whole word |
| vocabulary explosion | the number of distinct words grows without bound as text grows |
| <UNK> | the placeholder id for words the vocabulary lacks |
| OOV | out-of-vocabulary |
| inflection | a changed form of a word: walk, walks, walked |
| type vs token | a type is a distinct word, a token is one occurrence |

### 1. What is it?

Word tokenization splits text into words (usually on whitespace and punctuation) and gives each distinct word one vocabulary entry.

### 2. Why does it exist?

Words are the natural unit humans reason about and give short sequences; classic NLP (bag-of-words, word2vec, early RNN models) was built on them.

### 3. Detailed explanation

Strengths: short sequences and each token already carries a recognizable meaning.

Weaknesses: (1) the vocabulary explodes: every inflection, typo, name, URL and number is a new entry, easily 10^5-10^6 types; (2) anything unseen becomes `<UNK>` ([6.8 UNK](06.08-unk.md)), losing information at exactly the rare words that often matter; (3) no parameter sharing between `unhappy` and `unhappiness`; (4) the rule "split on spaces" fails for Chinese, Japanese and Thai, which do not use spaces between words.

### 4. How does it work?

Split with a rule or regex, build a word->ID table from the most frequent N words, map everything else to `<UNK>`.

### 5. Simple example

A dictionary of whole words: fast to look things up, but a new slang term has no entry at all.

**By hand.** Vocabulary built from "the cat sat on the mat the cat ran": the (3), cat (2), sat, on, mat, ran → keep the 4 most frequent: `the, cat, sat, on` plus `<UNK>`. Now encode "the dog sat": `the` → known, `dog` → unseen → `<UNK>`, `sat` → known, giving `[the, UNK, sat]`. The word `dog` is lost.

### 6. Technical example

A 50,000-word vocabulary with d=768 embeddings is ~38M parameters in the table; covering a billion-word web corpus without UNK would need far more entries, which is the problem subwords ([6.5 Subword tokenization](06.05-subword-tokenization.md)) solve.

### 7. Code

**① By hand (plain Python).** A word vocabulary and its unknown-word rate.

```python
import re
from collections import Counter

corpus = "the cat sat on the mat the cat ran"
words = re.findall(r"\w+|[^\w\s]", corpus.lower())
vocab = {"<UNK>": 0}
for w, _ in Counter(words).most_common(4):
    vocab[w] = len(vocab)
encode = lambda s: [vocab.get(w, 0) for w in re.findall(r"\w+|[^\w\s]", s.lower())]
print("vocabulary:", vocab)
print("the dog sat ->", encode("the dog sat"), "   (dog is unseen -> 0)")
test = "the cat sat on the mat while a dog ran"
ids = encode(test)
print("UNK rate on a new sentence:", round(ids.count(0) / len(ids), 2))
```

```text
vocabulary: {'<UNK>': 0, 'the': 1, 'cat': 2, 'sat': 3, 'on': 4}
the dog sat -> [1, 0, 3]    (dog is unseen -> 0)
UNK rate on a new sentence: 0.5
```

**② With NumPy.** Vocabulary growth: new words keep appearing as the text grows (Heaps' law).

```python
import numpy as np

rng = np.random.default_rng(0)
ranks = np.arange(1, 50_001)
p = 1 / ranks; p /= p.sum()                                   # a Zipf-like word distribution: a few very common words, a long tail
stream = rng.choice(ranks, size=200_000, p=p)
for n in (1_000, 10_000, 100_000, 200_000):
    print(f"after {n:>7,} tokens: {len(np.unique(stream[:n])):>6,} distinct words")
```

```text
after   1,000 tokens:    625 distinct words
after  10,000 tokens:  3,930 distinct words
after 100,000 tokens: 19,661 distinct words
after 200,000 tokens: 28,495 distinct words
```

**③ With PyTorch.** The memory price: one embedding row per word type.

```python
import torch

for V, d in ((10_000, 256), (500_000, 256), (500_000, 4096)):
    print(f"vocabulary {V:>7,} x {d:>4} dimensions = {V * d:>13,} parameters = {V * d * 4 / 1e9:6.2f} GB in float32")
torch.manual_seed(0)
table = torch.nn.Embedding(10_000, 256)
print("one lookup:", tuple(table(torch.tensor([42])).shape))
```

```text
vocabulary  10,000 x  256 dimensions =     2,560,000 parameters =   0.01 GB in float32
vocabulary 500,000 x  256 dimensions =   128,000,000 parameters =   0.51 GB in float32

```

### 9. Enterprise use case

Still used in classical search/analytics (TF-IDF, keyword filters, BM25) where whole words are the right unit; not used as the input layer of modern LLMs.

### 10. AI engineering connection

Motivates [6.8 UNK](06.08-unk.md) and [6.5 Subword tokenization](06.05-subword-tokenization.md); also the reason lexical retrieval (BM25) and neural tokenization see text differently in hybrid RAG.

### 11. Advantages

Shortest sequences; interpretable tokens; fast.

### 12. Limitations

Huge vocabularies; frequent `<UNK>`; no morphology sharing; language-dependent splitting rules.

### 13. Trade-offs

Short sequences versus a giant embedding/softmax table and OOV loss.

### 14. Common mistakes

- Using whitespace splitting for languages without spaces.
- Forgetting that punctuation and casing multiply the vocabulary.
- Treating `<UNK>` rate as a harmless statistic (it hides entities and numbers).

### 15. Performance / cost

Embedding and output softmax grow with V (see [6.28 Vocabulary-size trade-offs](06.28-vocabulary-size-trade-offs.md)); sparse gradients make rare words nearly untrained.

### 16. Security

Out-of-vocabulary entities (new product names, injected strings) all collapse to the same `<UNK>`, which hides them from downstream checks.

</details>

### 17. Interview explanation

*"Word tokenization gives short sequences but an enormous vocabulary and unknown-word problem. Subword tokenization keeps frequent words whole and splits rare ones, getting the best of both."*

### 18. Rapid-fire answer

One token per word: short sequences, huge vocab, OOV.
