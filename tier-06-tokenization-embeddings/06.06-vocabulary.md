# 6.6 Vocabulary

**Metadata** — Tier: 6 · Phase: 2 · Priority: High · Difficulty: Beginner · Interview: High · Hands-on: Medium
Prerequisites: [6.5 Subword tokenization](06.05-subword-tokenization.md) · Leads to: [6.7 Token IDs](06.07-token-ids.md), [6.18 Embedding matrix](06.18-embedding-matrix.md), [6.28 Vocabulary-size trade-offs](06.28-vocabulary-size-trade-offs.md)

> **In plain words**
> The **vocabulary** is the table that maps every token (a string or bytes) to an integer id, plus the rules (merges or probabilities) needed to cut text into those tokens. Its size `V` fixes the shape of the model's first layer (`V × d` embedding table) and of its last layer (`V` scores per position).

**You need first:** [6.5 Subword tokenization](06.05-subword-tokenization.md).

> **Figure 6.6-1 — The vocabulary fixes two layer shapes**
>
> ```mermaid
> flowchart LR
>     T["token strings / bytes"] --> I["integer ids 0 … V−1"]
>     I --> E["embedding table E: V × d"]
>     I --> O["output layer: V scores"]
> ```
>
> *How to read it:* the vocabulary decides how many rows the embedding table has and how many scores the output layer produces. Change the vocabulary and both layers (and the whole trained model) no longer fit.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| vocabulary size V | the number of distinct tokens |
| token → id | the lookup table from piece to integer |
| merge table | the rules that build the pieces from text (BPE) |
| special tokens | reserved entries such as <PAD>, <BOS>, <EOS>, <UNK> |
| embedding table | a V × d matrix with one vector per token |
| checkpoint | the saved model weights; it is tied to one vocabulary |

### 1. What is it?

The vocabulary is the ordered table mapping each token (string or bytes) to an integer ID, plus the rules (merges, probabilities) needed to produce those tokens from text.

### 2. Why does it exist?

A model with fixed-size embedding and output layers needs a closed, finite set of symbols agreed between training and inference.

### 3. Detailed explanation

The vocabulary has size V. That number sets the shape of the embedding matrix `V x d` ([6.18 Embedding matrix](06.18-embedding-matrix.md)) and of the output layer (V logits per position). It contains base symbols, learned pieces and special tokens ([6.8 UNK](06.08-unk.md)-[6.11 EOS](06.11-eos.md)).

Vocabulary and weights are inseparable: ID 5231 means row 5231 of *this* checkpoint's matrix. Examples of sizes (`REVIEW_REQUIRED`, verify per model card): GPT-2 about 50k, BERT-base about 30k, Llama 2 about 32k, newer Llama/GPT-4-class models roughly 100k-200k+.

### 4. How does it work?

Training produces `token -> id` and often `id -> token` plus merges/probabilities; serialization writes them to files (`vocab.json`, `merges.txt`, `.model`, `tokenizer.json` depending on library, `REVIEW_REQUIRED`). The lab exposes `ByteBPE.vocab` and `vocab_size = 4 specials + 256 bytes + #merges`.

### 5. Simple example

The legend of a map: everyone using the map must agree on what each symbol means.

**By hand.** The lab tokenizer has 4 special tokens + 256 byte tokens + one token per merge. With 10 merges: `V = 4 + 256 + 10 = 270`. With embedding dimension 4 the table has `270 × 4 = 1,080` numbers, and the model's output layer produces 270 scores at every position. A real model with `V = 100,000` and `d = 4,096` has `410 million` numbers in the table alone.

### 6. Technical example

Adding 3 chat special tokens to a base model means resizing the embedding and output matrices (`V -> V+3`), initializing the new rows, and fine-tuning so they acquire meaning.

### 7. Code

**① By hand (plain Python).** A vocabulary is two dictionaries.

```python
tokens = ["<PAD>", "<UNK>", "the", "cat", "sat", "mat"]
token_to_id = {t: i for i, t in enumerate(tokens)}
id_to_token = {i: t for t, i in token_to_id.items()}
print(token_to_id)
print("size V =", len(tokens))
print("ids for 'the cat sat':", [token_to_id[w] for w in "the cat sat".split()])
print("back to tokens:", [id_to_token[i] for i in [2, 3, 4]])
```

```text
{'<PAD>': 0, '<UNK>': 1, 'the': 2, 'cat': 3, 'sat': 4, 'mat': 5}
size V = 6
ids for 'the cat sat': [2, 3, 4]
back to tokens: ['the', 'cat', 'sat']
```

**② With NumPy.** How vocabulary size sets the layer shapes and the memory.

```python
import numpy as np

for V, d in ((32_000, 4096), (128_000, 4096)):
    emb = V * d
    print(f"V = {V:>7,}, d = {d}: embedding table {emb:,} numbers ({emb * 2 / 1e9:.2f} GB in 16-bit); output layer produces {V:,} scores per position")
rng = np.random.default_rng(0)
V, d = 270, 4
E = rng.normal(size=(V, d))
print("toy table shape:", E.shape, "   one token's vector:", E[42].round(2))
```

```text
V =  32,000, d = 4096: embedding table 131,072,000 numbers (0.26 GB in 16-bit); output layer produces 32,000 scores per position
V = 128,000, d = 4096: embedding table 524,288,000 numbers (1.05 GB in 16-bit); output layer produces 128,000 scores per position
toy table shape: (270, 4)    one token's vector: [1.65 0.92 1.07 0.05]
```

### 9. Enterprise use case

Model registries version tokenizer files together with checkpoints; a mismatched tokenizer is a classic deployment incident.

### 10. AI engineering connection

V determines embedding/softmax memory ([6.28 Vocabulary-size trade-offs](06.28-vocabulary-size-trade-offs.md)) and which strings are cheap or expensive in tokens.

### 11. Advantages

Closed finite alphabet enables fixed-size layers and fast lookup.

### 12. Limitations

Frozen after training; extending requires embedding surgery; different models are not interchangeable.

### 13. Trade-offs

Large V: fewer tokens but bigger layers and rarer-token undertraining; small V: the opposite.

### 14. Common mistakes

- Loading a tokenizer from model A with weights from model B.
- Resizing the vocabulary without initializing/training new rows.
- Not versioning tokenizer files.

### 15. Performance / cost

Embedding + output head cost O(V d) parameters/memory each; see the calculator in [explore: `vocab_tradeoff.html`](interactive/vocab_tradeoff.html).

### 16. Security

Treat tokenizer files as code-adjacent artifacts: verify checksums and avoid loading from untrusted sources (some formats may execute code when loaded; check your library, `REVIEW_REQUIRED`).

```python
for V in (1_000, 32_000, 100_000, 256_000):
    d = 4096
    print(f"V = {V:>7,}: embedding {V * d / 1e6:8.1f} million numbers, output layer {V * d / 1e6:8.1f} million (if not tied)")
```

```text
V =   1,000: embedding      4.1 million numbers, output layer      4.1 million (if not tied)
V =  32,000: embedding    131.1 million numbers, output layer    131.1 million (if not tied)
V = 100,000: embedding    409.6 million numbers, output layer    409.6 million (if not tied)
V = 256,000: embedding   1048.6 million numbers, output layer   1048.6 million (if not tied)
```

With 'weight tying' the output layer reuses the embedding table, so the cost is paid once; large vocabularies are expensive at both ends.
