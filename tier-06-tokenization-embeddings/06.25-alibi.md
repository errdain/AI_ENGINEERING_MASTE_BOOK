# 6.25 ALiBi

**Metadata** — Tier: 6 · Phase: 2 · Priority: High · Difficulty: Intermediate · Interview: High · Hands-on: Medium
Prerequisites: [6.23 Relative positional encoding](06.23-relative-positional-encoding.md), [6.16 Attention masks](06.16-attention-masks.md) · Leads to: [Tier 12](../tier-12-modern-architectures/README.md)

> **In plain words**
> **ALiBi** (attention with linear biases) is the simplest relative scheme: it adds a **penalty proportional to the distance** to each attention score, `score(i, j) = q·k − m·(i − j)`, with a different fixed slope `m` for every attention head. No position vectors, nothing rotated, nothing learned. Nearby tokens are favoured; heads with small slopes still look far, heads with large slopes stay local.

**You need first:** [6.23 Relative positional encoding](06.23-relative-positional-encoding.md), [6.16 Attention masks](06.16-attention-masks.md).

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| ALiBi | Attention with Linear Biases |
| slope m | penalty per step of distance; fixed, one per head |
| distance i − j | how far back the key is from the query |
| recency bias | preferring nearby tokens |
| geometric sequence | each slope is a constant fraction of the previous one |
| causal | a token only attends to itself and earlier tokens |

### 1. What is it?

ALiBi (Attention with Linear Biases) uses no position vectors: it adds a *linear penalty proportional to distance* to the attention logits, with a different fixed slope per head.

### 2. Why does it exist?

To get a parameter-free position scheme that extrapolates to longer sequences than were seen in training (reported in the original work; `REVIEW_REQUIRED` for magnitude).

### 3. Detailed explanation

For query *i* and key *j* (causal, j <= i): `score(i,j) = q_i . k_j - m_h * (i - j)`. Slopes `m_h` form a geometric sequence per head: `2^(-8*h/n_heads)` for h = 1..n (n a power of two): with 8 heads, 1/2, 1/4, ..., 1/256. Heads with small slopes attend widely; heads with large slopes are strongly local. Distant tokens are softly down-weighted. Used by some open models (e.g. BLOOM, MPT; `REVIEW_REQUIRED`).

Compared to RoPE ([6.24 RoPE](06.24-rope.md)): ALiBi changes only the score; nothing is added to embeddings or rotated; it is simpler but inherently biased toward recency.

### 4. How does it work?

Add `bias[h, i, j] = -m_h * (i - j)` to the score matrix before softmax; causal mask sets j > i to -inf.

### 5. Simple example

A tax on reading far-back words: the further back, the bigger the discount on its influence.

**By hand.** With 8 heads the slopes are `1/2, 1/4, …, 1/256`. For the head with slope 0.5 and a key 3 tokens back, the score loses `0.5 × 3 = 1.5`. For the head with slope 1/256 the same key loses only `0.012`. So head 1 is nearly local (weights on distant keys shrink by `e^−1.5`) and head 8 is almost position-blind.

### 6. Technical example

With slope 0.5, a token 3 steps back gets -1.5 added to its logit.

### 7. Code

**① By hand (plain Python).** The slopes and one row of the bias.

```python
n_heads = 8
slopes = [2 ** (-8 * h / n_heads) for h in range(1, n_heads + 1)]
print("slopes:", [round(s, 4) for s in slopes])
slope = slopes[0]
print("bias for a query at position 3 over keys 0..3:", [slope * (j - 3) for j in range(4)])
```

```text
slopes: [0.5, 0.25, 0.125, 0.0625, 0.0312, 0.0156, 0.0078, 0.0039]
bias for a query at position 3 over keys 0..3: [-1.5, -1.0, -0.5, 0.0]
```

**② With NumPy.** The full bias matrix and its effect on softmax weights.

```python
import numpy as np

n, slope = 6, 0.5
i, j = np.indices((n, n))
bias = np.where(j <= i, -slope * (i - j), -np.inf)
scores = np.zeros((n, n)) + bias                                  # pretend all content scores are equal
w = np.exp(scores - scores.max(1, keepdims=True)); w /= w.sum(1, keepdims=True)
print("attention weights of the last query with ALiBi:", w[-1].round(2))
print("equal content scores, yet recent keys get more weight: only distance mattered")
```

```text
attention weights of the last query with ALiBi: [0.03 0.06 0.09 0.15 0.25 0.41]
equal content scores, yet recent keys get more weight: only distance mattered
```

### 9. Enterprise use case

Chosen when training budgets don't allow long-context training but long inference contexts are needed (`REVIEW_REQUIRED`).

### 10. AI engineering connection

One of the two main parameter-free relative schemes; contrast with [6.24 RoPE](06.24-rope.md).

### 11. Advantages

No parameters; trivial; good length extrapolation in original reports; no embedding changes.

### 12. Limitations

Strong recency bias can hamper long-range retrieval; less adopted in recent models than RoPE (`REVIEW_REQUIRED`).

### 13. Trade-offs

Simplicity and extrapolation versus recency bias.

### 14. Common mistakes

- Wrong slope schedule for non-power-of-two head counts.
- Forgetting the causal mask for decoder models.

### 15. Performance / cost

Bias is precomputable; negligible compute.

### 16. Security

None specific; recency bias can make models more susceptible to instructions placed at the end of long prompts (`REVIEW_REQUIRED`).

### 20. Hands-on exercise

Print slopes for 16 heads and plot the bias of the first and last head.

<details>
<summary>Show a solution</summary>

```python
import numpy as np

n = 8
i, j = np.indices((n, n))
for slope in (0.0625, 0.5, 4.0):
    bias = np.where(j <= i, -slope * (i - j), -np.inf)
    w = np.exp(bias[-1] - bias[-1].max()); w /= w.sum()
    print(f"slope {slope:>6}: weight on the nearest key {w[-1]:.2f}, on the farthest {w[0]:.4f}")
```

```text
slope 0.0625: weight on the nearest key 0.15, on the farthest 0.0994
slope    0.5: weight on the nearest key 0.40, on the farthest 0.0121
slope    4.0: weight on the nearest key 0.98, on the farthest 0.0000
```
