# 6.13 WordPiece

**Metadata** — Tier: 6 · Phase: 2 · Priority: High · Difficulty: Intermediate · Interview: High · Hands-on: Medium
Prerequisites: [6.5 Subword tokenization](06.05-subword-tokenization.md), [6.12 BPE](06.12-bpe.md) · Leads to: [6.15 Unigram LM tokenizer](06.15-unigram-lm-tokenizer.md), [6.27 Tokenizer training](06.27-tokenizer-training.md)

> **In plain words**
> **WordPiece** is the sub-word method behind BERT. Like BPE it builds a vocabulary from small pieces upward, but it chooses merges by a *likelihood-style score* instead of raw counts, and it encodes a word with **greedy longest match**: take the longest piece from the start, then continue on the rest. Pieces that continue a word are written with a `##` prefix: `un ##happi ##ness`.

**You need first:** [6.5 Subword tokenization](06.05-subword-tokenization.md), [6.12 BPE](06.12-bpe.md).

> **Figure 6.13-1 — Greedy longest-match encoding**
>
> ```mermaid
> flowchart LR
>     A["unhappiness"] --> B["longest prefix in vocab: un"]

> *How to read it:* start at the left, take the longest piece that is in the vocabulary, then repeat on what is left (using the `##` form). If at some point nothing matches, BERT's implementation turns the whole word into `[UNK]`.

### 1. What is it?

WordPiece is the subword algorithm used by BERT-family models: it builds a vocabulary from characters upward like BPE, but selects merges by a *likelihood-based score* and encodes with greedy longest-match-first.

### 2. Why does it exist?

Selecting merges that most increase the likelihood of the training data (rather than raw pair frequency) discourages merging pairs that are frequent only because their parts are frequent.

### 3. Detailed explanation

**Vocabulary building.** Commonly described scoring: `score(a,b) = freq(ab) / (freq(a) * freq(b))` (exact scoring/implementation details vary, `REVIEW_REQUIRED` before quoting formulas externally). Continuation pieces are marked with a `##` prefix: `un ##happi ##ness`.

**Encoding** is deterministic greedy **longest-match-first**: for each word, find the longest prefix in the vocabulary, then continue on the remainder with `##`-prefixed pieces. In BERT's implementation, if any remainder cannot be matched the *entire word* becomes `[UNK]` ([6.8 UNK](06.08-unk.md)).

Differences from BPE ([6.12 BPE](06.12-bpe.md)): the training criterion; the encoding algorithm (longest match, not merge replay); `##` markers instead of leading-space markers; typically a character (not byte) base, hence UNK exists.

### 4. How does it work?

Training: start with characters, repeatedly pick the pair with the best score, merge, until vocabulary size. Encoding: longest-match-first with `##`.

### 5. Simple example

Reading an unfamiliar word by biting off the longest chunk you recognize from the left, then doing the same for what is left.

**By hand.** Vocabulary `{un, play, ##ing, ##happi, ##ness, happy}`. "playing": longest prefix `play`, remainder `ing` → `##ing` → `play | ##ing`. "unhappiness": `un`, then `##happi`, then `##ness` → 3 pieces. "xyz": no prefix matches → `[UNK]`. A merge score such as `freq(ab) / (freq(a)·freq(b))` favours pairs that occur together *more often than chance*, not merely often.

### 6. Technical example

`playing -> play ##ing` and `unhappiness -> un ##happi ##ness` (the exact split depends on the learned vocabulary).

### 7. Code

**① By hand (plain Python).** Greedy longest-match WordPiece encoding.

```python
vocab = {"un", "play", "##ing", "##happi", "##ness", "happy"}

def wordpiece(word):
    pieces, start = [], 0
    while start < len(word):
        end = len(word)
        while end > start:
            piece = word[start:end] if start == 0 else "##" + word[start:end]
            if piece in vocab:
                break
            end -= 1
        else:
            return ["[UNK]"]                              # BERT: one failure makes the whole word unknown
        pieces.append(piece); start = end
    return pieces

for w in ("playing", "unhappiness", "unplayed", "xyz"):
    print(f"{w:<12} -> {wordpiece(w)}")
```

```text
playing      -> ['play', '##ing']
unhappiness  -> ['un', '##happi', '##ness']
unplayed     -> ['[UNK]']
xyz          -> ['[UNK]']
```

**② With NumPy.** The merge score: frequent versus frequent-together.

```python
import numpy as np

freq = {"a": 100, "b": 100, "c": 20, "d": 20}
pairs = {("a", "b"): 30, ("c", "d"): 15}                       # how often each pair occurs together
for (x, y), f in pairs.items():
    print(f"pair {x}{y}: count {f:>3}   score = {f} / ({freq[x]} * {freq[y]}) = {f / (freq[x] * freq[y]):.4f}")
best = max(pairs, key=lambda p: pairs[p] / (freq[p[0]] * freq[p[1]]))
print("BPE would merge:", max(pairs, key=pairs.get), "   WordPiece (likelihood score) would merge:", best)
```

```text
pair ab: count  30   score = 30 / (100 * 100) = 0.0030
pair cd: count  15   score = 15 / (20 * 20) = 0.0375
BPE would merge: ('a', 'b')    WordPiece (likelihood score) would merge: ('c', 'd')
```

### 9. Enterprise use case

Search/classification systems built on BERT-family encoders (ticket routing, semantic search) inherit its lower-cased, 30k-vocabulary behaviour (`REVIEW_REQUIRED` per checkpoint); domain terms may fragment, which is why domain-adapted vocabularies exist.

### 10. AI engineering connection

Tokenizer of many encoder/embedding models used in RAG retrieval ([6.26 Token vs semantic embeddings](06.26-token-vs-semantic-embeddings.md)); decoder-only LLMs mostly use BPE/SentencePiece instead.

### 11. Advantages

Deterministic and fast encoding; principled merge criterion; compact vocabularies.

### 12. Limitations

UNK possible with a character base; greedy longest match is not globally optimal; training procedure not fully standardized in public implementations.

### 13. Trade-offs

Good morphological pieces and small vocabulary versus possible information loss through UNK.

### 14. Common mistakes

- Forgetting `##` handling when detokenizing.
- Assuming the vocabulary is cased when it is not.
- Quoting scoring formulas as exact.

### 15. Performance / cost

Longest-match encoding is O(n * max_piece_len) per word with simple implementations; fast trie/automaton versions exist.

### 16. Security

Rare-character inputs map to `[UNK]` and can mask content from classifiers; normalize and test adversarial inputs.
