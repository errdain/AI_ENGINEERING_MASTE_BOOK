# 6.15 Unigram LM tokenizer

**Metadata** — Tier: 6 · Phase: 2 · Priority: Medium · Difficulty: Advanced · Interview: Medium · Hands-on: Medium
Prerequisites: [6.5 Subword tokenization](06.05-subword-tokenization.md), [6.13 WordPiece](06.13-wordpiece.md) · Leads to: [6.14 SentencePiece](06.14-sentencepiece.md), [6.27 Tokenizer training](06.27-tokenizer-training.md)

> **In plain words**
> The **Unigram** tokenizer starts with a *big* list of candidate pieces and **prunes** it, keeping the pieces that matter most for explaining the text. Every piece has a probability; a text is cut up in whichever way gives the **highest total probability** (found with dynamic programming). Unlike BPE it can offer several valid segmentations, which can be sampled for regularization.

**You need first:** [6.5 Subword tokenization](06.05-subword-tokenization.md), [6.13 WordPiece](06.13-wordpiece.md).

> **Figure 6.15-1 — Train big, prune small**
>
> ```mermaid
> flowchart LR
>     A["big seed vocabulary + probabilities"] --> B["fit probabilities (EM)"]
>     B --> C["drop the least useful pieces"]
>     C -->|repeat until target size| B
>     C --> D["final vocabulary"]
> ```
>
> *How to read it:* the opposite direction to BPE: begin with many candidate pieces, estimate how likely each is, remove the ones whose loss hurts the corpus likelihood least, and repeat until the vocabulary is the target size. Single characters are always kept so every text can be covered.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| unigram model | treats tokens as independent: P(text) = product of piece probabilities |
| segmentation | one way of cutting a string into vocabulary pieces |
| Viterbi | dynamic programming that finds the best segmentation |
| EM | expectation–maximization: alternately guess segmentations and re-estimate probabilities |
| pruning | removing the least useful pieces |
| subword regularization | sampling different segmentations during model training |

### 1. What is it?

The Unigram language-model tokenizer starts from a large candidate vocabulary and prunes it top-down, using a probabilistic model in which each token has a probability and a text is segmented to maximize its likelihood.

### 2. Why does it exist?

Unlike BPE it gives a principled probability for every segmentation, can output several alternatives, and enables *subword regularization* (sampling segmentations during training for robustness).

### 3. Detailed explanation

**Model:** the probability of a segmentation is the product of token probabilities (tokens treated as independent, hence 'unigram'). **Training:** EM-style: fit token probabilities for a large seed vocabulary, compute how much corpus likelihood would drop if each token were removed, prune the least harmful (e.g. 10-20% per round, keeping single characters so coverage is guaranteed), repeat until target size. **Encoding:** Viterbi search for the best segmentation (see code); or sampling for regularization.

### 4. How does it work?

Candidates -> estimate probabilities -> prune lowest-loss tokens -> repeat; encode with Viterbi.

### 5. Simple example

Choosing the cheapest way to break a sentence into dictionary chunks, where each chunk has a price and you minimize the total.

**By hand.** Piece probabilities `a: 0.1, b: 0.1, ab: 0.5, abab: 0.01`. For "abab": segmentation `ab|ab` has probability `0.5 × 0.5 = 0.25`; `a|b|a|b` has `0.1⁴ = 0.0001`; `abab` alone has `0.01`. The best is `ab|ab`. For "abc", `c` has no probability: it cannot be covered, which is why real systems always keep every single character.

### 6. Technical example

With `a`, `b`, `ab` available, the string `abab` is segmented as `ab|ab` when `ab` is much more probable than `a`+`b`.

### 7. Code

**① By hand (plain Python).** Viterbi: best segmentation by dynamic programming.

```python
import math

logp = {"a": math.log(0.1), "b": math.log(0.1), "ab": math.log(0.5), "abab": math.log(0.01)}

def best_segmentation(text):
    best = [(-math.inf, None)] * (len(text) + 1)
    best[0] = (0.0, None)
    for end in range(1, len(text) + 1):
        for start in range(end):
            piece = text[start:end]
            if piece in logp and best[start][0] > -math.inf:
                score = best[start][0] + logp[piece]
                if score > best[end][0]:
                    best[end] = (score, start)
    if best[-1][0] == -math.inf:
        return None, None
    pieces, end = [], len(text)
    while end > 0:
        start = best[end][1]; pieces.append(text[start:end]); end = start
    return pieces[::-1], math.exp(best[-1][0])

for t in ("abab", "ab", "abc"):
    print(t, "->", best_segmentation(t))
```

```text
abab -> (['ab', 'ab'], 0.25)
ab -> (['ab'], 0.5)
abc -> (None, None)
```

**② With NumPy.** All segmentations of 'abab' and their probabilities.

```python
import numpy as np

p = {"a": 0.1, "b": 0.1, "ab": 0.5, "abab": 0.01}
def all_segmentations(text):
    if not text:
        yield []
        return
    for i in range(1, len(text) + 1):
        if text[:i] in p:
            for rest in all_segmentations(text[i:]):
                yield [text[:i]] + rest

rows = sorted(((float(np.prod([p[x] for x in seg])), seg) for seg in all_segmentations("abab")), reverse=True)
for prob, seg in rows:
    print(f"{prob:.4f}  {'|'.join(seg)}")
print("sum over these segmentations:", round(sum(r[0] for r in rows), 4), "(a toy table, not a full model, so it need not be 1)")
```

```text
0.2500  ab|ab
0.0100  abab
0.0050  ab|a|b
0.0050  a|b|ab
0.0001  a|b|a|b
sum over these segmentations: 0.2701 (a toy table, not a full model, so it need not be 1)
```

### 9. Enterprise use case

Used (via SentencePiece) in T5-family models; the sampling mode is a data-augmentation tool for noisy-text domains.

### 10. AI engineering connection

Alternative to BPE; subword regularization can improve robustness in some translation settings (`REVIEW_REQUIRED` for magnitude).

### 11. Advantages

Probabilistic, multiple segmentations, principled pruning.

### 12. Limitations

More complex to train; independence assumption; slower than BPE encoding.

### 13. Trade-offs

Flexibility (sampling, probabilities) versus simplicity of BPE.

### 14. Common mistakes

- Pruning away single characters (breaks coverage).
- Treating Unigram as a neural LM.
- Using sampling at inference when deterministic output is needed.

### 15. Performance / cost

Viterbi is O(n * max_piece_len); training is heavier than BPE.

### 16. Security

Sampling-based tokenization is non-deterministic: disable it at inference, otherwise caching/audit logs differ run-to-run.

</details>
