# 6.24 RoPE

**Metadata** — Tier: 6 · Phase: 2 · Priority: Critical · Difficulty: Advanced · Interview: Very high · Hands-on: High
Prerequisites: [6.22 Sinusoidal positional encoding](06.22-sinusoidal-positional-encoding.md), [6.23 Relative positional encoding](06.23-relative-positional-encoding.md), [Tier 7](../tier-07-attention/README.md) · Leads to: [Tier 12](../tier-12-modern-architectures/README.md) (long-context scaling)

> **In plain words**
> **RoPE** (rotary position embedding) tells attention where tokens are by **rotating** each query and key vector by an angle proportional to the token's position. The dot product of a rotated query and a rotated key then depends only on the **offset** between the two tokens, exactly what we want from a relative scheme. No parameters, applied to queries and keys only, used by most recent open LLMs.

**You need first:** [6.22 Sinusoidal positional encoding](06.22-sinusoidal-positional-encoding.md), [6.23 Relative positional encoding](06.23-relative-positional-encoding.md), [Tier 7](../tier-07-attention/README.md).

> *How to read it:* each 2-D pair of the vector turns by `m·θ` at position `m`. Pairs on the left rotate fast (fine position detail), pairs on the right barely rotate (long range). Because rotations preserve length, only the angle between query and key (their offset) matters.

| Word | What it means here |
|---|---|
| rotation | turning a 2-D vector by an angle without changing its length |
| θ_i | the rotation speed of pair i: base^(−2i/d) |
| base | 10000 in the original; larger values stretch the slow pairs for long contexts |
| pair | two consecutive dimensions treated as one 2-D point |
| offset | m − n, the distance between query and key positions |
| position interpolation | rescaling positions so a long text fits the trained range |

### 1. What is it?

Rotary Position Embedding (RoPE) encodes position by *rotating* query and key vectors in 2-D subspaces by an angle proportional to the token's position.

### 2. Why does it exist?

It gives attention scores that depend on content and the **relative** offset only, with no extra parameters, and it is widely adopted in open LLM families (`REVIEW_REQUIRED` for specific models).

### 3. Detailed explanation

Split a head's vector (dimension `d_head`, even) into `d_head/2` pairs. Pair *i* at position *m* is rotated by angle `m*theta_i`, with `theta_i = base^(-2i/d_head)` (base 10000 in the original paper; some newer models use larger bases for long context, `REVIEW_REQUIRED` per model).

**Key property.** With rotation matrices `R`, `(R_m q) . (R_n k) = q^T R_(n-m) k`: the score depends on the content of q and k and only on the **offset** `m - n`. Rotations preserve vector norms. RoPE is applied to **Q and K** (not V, not the residual stream).

**Frequency spread.** Low pair indices have large `theta` and rotate fast (fine position resolution); high indices barely rotate (long-range). Lowering the base makes more pairs rotate; raising it stretches the slow ones. **Context extension** (position interpolation, base change, YaRN-style methods) rescales these frequencies; [Tier 12](../tier-12-modern-architectures/README.md) is authoritative for variants.

**Implementation conventions** differ: *interleaved* pairs `(x0,x1),(x2,x3)...` (the lab) vs *half-split* pairs `(x_i, x_(i+d/2))` used by some libraries; loading a checkpoint with the wrong convention gives silently wrong results (`REVIEW_REQUIRED` for specific libraries).

### 4. How does it work?

theta. The left pair has a large theta and spins fast; the right pairs barely move.*

### 5. Simple example

Two compass needles: if you rotate both by the same amount, the angle between them (and thus how they relate) is unchanged; only the gap matters.

**By hand.** One pair `(x, y) = (1, 0)`, speed `θ = 90° = π/2` per position. Position 0: `(1, 0)`. Position 1: `(0, 1)`. Position 2: `(−1, 0)`. Take a query `q = (1, 0)` at position 3 and a key `k = (1, 0)` at position 1: rotate q by 270° → `(0, −1)`, k by 90° → `(0, 1)`; dot = −1. The same q, k at positions 5 and 3 (same offset 2): q by 450° = 90° → `(0, 1)`, k by 270° → `(0, −1)`; dot = −1. Same offset, same score.

### 6. Technical example

Rotating q at position 5 and k at position 2 gives the same dot product as q at 12 and k at 9.

### 7. Code

**① By hand (plain Python).** Rotate one pair and check that the dot product depends only on the offset.

```python
import math

def rotate(v, angle):
    c, s = math.cos(angle), math.sin(angle)
    return (v[0] * c - v[1] * s, v[0] * s + v[1] * c)

theta = math.pi / 2
q, k = (1.0, 0.5), (0.3, 1.0)
dot = lambda a, b: a[0] * b[0] + a[1] * b[1]
for m, n in ((3, 1), (5, 3), (10, 8), (5, 4)):
    score = dot(rotate(q, m * theta), rotate(k, n * theta))
    print(f"query at {m:>2}, key at {n:>2}: offset {m - n}  score {score:+.3f}")
```

```text
query at  3, key at  1: offset 2  score -0.800
query at  5, key at  3: offset 2  score -0.800
query at 10, key at  8: offset 2  score -0.800
query at  5, key at  4: offset 1  score +0.850
```

**② With NumPy.** Full RoPE on vectors, using the tier's formulas written out.

```python
import numpy as np

def rope(x, base=10000.0):
    n, d = x.shape
    ang = np.arange(n)[:, None] * base ** (-np.arange(0, d, 2) / d)
    cos, sin = np.cos(ang), np.sin(ang)
    out = np.empty_like(x)
    out[:, 0::2] = x[:, 0::2] * cos - x[:, 1::2] * sin
    out[:, 1::2] = x[:, 0::2] * sin + x[:, 1::2] * cos
    return out

rng = np.random.default_rng(0)
q, k = rng.normal(size=(1, 8)), rng.normal(size=(1, 8))
Q, K = rope(np.repeat(q, 20, 0)), rope(np.repeat(k, 20, 0))
print("same offset (3), different places :", np.isclose(Q[5] @ K[2], Q[12] @ K[9]))
print("different offsets                  :", np.isclose(Q[5] @ K[2], Q[5] @ K[3]))
x = rng.normal(size=(6, 8))
print("rotation preserves vector norms    :", np.allclose(np.linalg.norm(rope(x), axis=1), np.linalg.norm(x, axis=1)))
```

```text
same offset (3), different places : True
different offsets                  : False
rotation preserves vector norms    : True
```

### 9. Enterprise use case

Teams extending context windows of open models do so by changing RoPE scaling/base plus fine-tuning; evaluation on long documents is required (`REVIEW_REQUIRED` for methods' quality claims).

### 10. AI engineering connection

Position scheme of Llama-style and many other open LLMs; central to long-context engineering ([Tier 12](../tier-12-modern-architectures/README.md)).

### 11. Advantages

Relative information with no learned table; norm-preserving; no change to V; efficient.

### 12. Limitations

Quality can degrade beyond trained length; extension needs frequency scaling; convention mismatches between libraries.

### 13. Trade-offs

Elegant and parameter-free versus the need for scaling tricks and careful implementation.

### 14. Common mistakes

- Odd head dimension.
- Applying RoPE to V.
- Interleaved vs half-split mismatch with a checkpoint.
- Using an RoPE base different from the checkpoint's.

### 15. Performance / cost

Cheap elementwise rotations on Q and K (fused in modern kernels); cos/sin tables can be cached.

### 16. Security

Very long contexts enabled by RoPE scaling enlarge the prompt-injection surface and cost; enforce token budgets.
