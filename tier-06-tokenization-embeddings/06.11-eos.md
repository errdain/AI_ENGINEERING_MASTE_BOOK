# 6.11 EOS

**Metadata** — Tier: 6 · Phase: 2 · Priority: High · Difficulty: Beginner · Interview: High · Hands-on: Medium
Prerequisites: [6.7 Token IDs](06.07-token-ids.md), [6.10 BOS](06.10-bos.md) · Leads to: [Tier 10](../tier-10-fine-tuning-alignment/README.md); generation/inference tiers

> **In plain words**
> `<EOS>` ("end of sequence") marks where a sequence ends. During generation the model keeps producing tokens until it emits EOS (or hits a length limit). If fine-tuning data forgets EOS, or the loss ignores it, the model never learns to stop and rambles on.

**You need first:** [6.7 Token IDs](06.07-token-ids.md), [6.10 BOS](06.10-bos.md).

> *How to read it:* generation repeats until EOS is sampled, or a maximum length or stop string is reached. Chat models often have several end-of-turn tokens, and all of them must be in the stop list.

### 1. What is it?

`<EOS>` (end of sequence) is a special token marking where a sequence ends.

### 2. Why does it exist?

A generative model needs a learnable signal for 'stop'; training documents end with EOS so that at inference the model can emit it and generation halts.

### 3. Detailed explanation

Generation loops stop when EOS is sampled (or a max-length / stop-string is hit). If fine-tuning data omits EOS (or the loss masks it out), the model rarely learns to stop and rambles until the length limit ([Tier 10](../tier-10-fine-tuning-alignment/README.md)). Chat models often have additional end-of-turn tokens; stop criteria must include all of them (`REVIEW_REQUIRED` per model).

### 4. How does it work?

Training: append EOS to each target. Inference: sample until EOS or limit. Decoding strips specials.

### 5. Simple example

The 'The End' card: without it viewers don't know when the film is over.

**By hand.** Training example "The sky is blue." tokenized as `[BOS, The, sky, is, blue, ., EOS]`. The model is trained to predict EOS after the final period. If the data was built without EOS, then after "." the training target is the start of the *next* document or padding, and the model never learns that this is a good place to stop.

### 6. Technical example

Cost control: a missing stop condition turns a 50-token answer into a 2,000-token bill.

### 7. Code

**① By hand (plain Python).** A generation loop that stops at EOS or at the length limit.

```python
EOS = 2
script = [11, 12, 13, EOS, 99, 98]                              # what a 'model' would emit; tokens after EOS are never produced
out = []
for step, tok in enumerate(script):
    if tok == EOS:
        print(f"stopped at step {step} because EOS was emitted")
        break
    out.append(tok)
print("generated:", out)
no_eos = [11, 12, 13, 14, 15, 16, 17, 18]
print("without EOS the loop runs to the limit:", no_eos[:5], "... (cut at max_new_tokens = 5)")
```

```text
stopped at step 3 because EOS was emitted
generated: [11, 12, 13]
without EOS the loop runs to the limit: [11, 12, 13, 14, 15] ... (cut at max_new_tokens = 5)
```

**② With NumPy.** Learning to stop: the loss at the EOS position.

```python
import numpy as np

logits = np.array([0.5, 1.2, -0.3, 2.0, 0.1])                    # scores for the next token after the final period
probs = np.exp(logits - logits.max()); probs /= probs.sum()
EOS = 4
print("probability of EOS right now:", round(float(probs[EOS]), 3))
print("loss if EOS is the target (trained to stop):", round(float(-np.log(probs[EOS])), 2))
print("with EOS missing from the data, this position gets no signal at all")
```

```text
probability of EOS right now: 0.078
loss if EOS is the target (trained to stop): 2.55
with EOS missing from the data, this position gets no signal at all
```

### 9. Enterprise use case

Platform teams set max-tokens and stop sequences as defence in depth in addition to EOS, to cap cost.

### 10. AI engineering connection

Core to fine-tuning data hygiene and to agent loops (tool-call end markers).

### 11. Advantages

Learned, content-aware stopping.

### 12. Limitations

Model may fail to emit it (loops) or emit it too early; token differs per model/template.

### 13. Trade-offs

Relying on EOS alone is cheap but not safe; combine with length limits.

### 14. Common mistakes

- Fine-tuning without EOS.
- Masking the EOS target in the loss.
- Forgetting model-specific end-of-turn tokens in stop lists.

### 15. Performance / cost

Late stops = wasted decoding steps and cost; set `max_tokens`.

### 16. Security

Treat user text containing the EOS string as plain text; unbounded generation is a cost-DoS vector, so always cap output tokens.

</details>

<details>
<summary>Show a solution</summary>

```python
generated = [5, 6, 7, 2, 9]                                      # 2 = <EOS>, 9 = <|end_of_turn|>
stops = {2, 9}
for i, t in enumerate(generated):
    if t in stops:
        print(f"stop at position {i} (token {t})"); break
print("with only EOS=2 in the stop list the model would stop at:", generated.index(2))
print("a chat model that emits 9 instead of 2 would never stop with stops = {2}:", 9 not in {2})
```

