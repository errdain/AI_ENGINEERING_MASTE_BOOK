# 6.20 Positional information

**Metadata** — Tier: 6 · Phase: 2 · Priority: Critical · Difficulty: Intermediate · Interview: Very high · Hands-on: Medium
Prerequisites: [6.17 Token embedding](06.17-token-embedding.md), [Tier 7](../tier-07-attention/README.md) (attention) · Leads to: [6.21 Learned positional embeddings](06.21-learned-positional-embeddings.md), [6.22 Sinusoidal positional encoding](06.22-sinusoidal-positional-encoding.md), [6.23 Relative positional encoding](06.23-relative-positional-encoding.md), [6.24 RoPE](06.24-rope.md), [6.25 ALiBi](06.25-alibi.md)

> **In plain words**
> Self-attention treats its input as an **unordered set**: shuffle the tokens and you just get the same outputs shuffled. Language needs order ("dog bites man" ≠ "man bites dog"), so a Transformer must be **told where each token is**. There are four families: learned absolute positions, sinusoidal, RoPE, and ALiBi.

**You need first:** [6.17 Token embedding](06.17-token-embedding.md), [Tier 7](../tier-07-attention/README.md) (attention).

> **Figure 6.20-1 — Where position information enters**
>
> ```mermaid

>     A["token embeddings"] --> B["+ absolute position vectors<br/>(learned or sinusoidal)"]
>     A --> C["rotate queries and keys by position (RoPE)"]

> *How to read it:* two of the families change the input vectors (learned and sinusoidal absolute positions); the other two change the attention computation itself (RoPE rotates queries and keys, ALiBi adds a distance-dependent bias to the scores).

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| positional encoding | information about token order |
| absolute position | token number 57 in the sequence |
| relative position | how many tokens apart two tokens are |
| equivariant | shuffling the input just shuffles the output |
| extrapolation | working on sequences longer than any seen in training |
| order-blind | unaware of token order |

### 1. What is it?

Positional information is any mechanism that tells a Transformer *where* each token is in the sequence, because self-attention alone is order-blind.

### 2. Why does it exist?

Self-attention ([Tier 7](../tier-07-attention/README.md)) treats its input as a *set*: permute the tokens and, without position information, each token's output is the same vector (just permuted). 'dog bites man' and 'man bites dog' would be indistinguishable.

### 3. Detailed explanation

Four families exist:

| Method | Learned params | Relative? | Extrapolates | Where applied |
|---|---|---|---|---|
| Learned absolute ([6.21 Learned positional embeddings](06.21-learned-positional-embeddings.md)) | yes (`L_max x d`) | no | no | input embedding |
| Sinusoidal ([6.22 Sinusoidal positional encoding](06.22-sinusoidal-positional-encoding.md)) | none | implicitly | weakly | input embedding |
| RoPE ([6.24 RoPE](06.24-rope.md)) | none | **yes** | with scaling | Q and K |
| ALiBi ([6.25 ALiBi](06.25-alibi.md)) | none | **yes** | good (original work) | attention logits |

Two design questions separate them: **absolute vs relative** (token #57 vs 3 tokens back) and **input-side vs attention-side** (added to embeddings vs injected into scores). Relative, attention-side methods dominate recent open LLMs (`REVIEW_REQUIRED` for exact adoption statements; see [Tier 12](../tier-12-modern-architectures/README.md)).

### 4. How does it work?

Either add a position vector to each token embedding (`x = E[token] + P[pos]`) or modify the attention score computation (rotate Q/K, or add a distance bias).

### 5. Simple example

Words on separate index cards dropped on the floor: you need page numbers on the cards (absolute), or notes like 'the card two before me' (relative).

**By hand.** Without positions, the output for a token depends only on *which* tokens are present, not where. Take 3 tokens with 1-D values `[1, 2, 3]`; the attention output for the token with value 2 is the same whether the order is `[1,2,3]` or `[3,2,1]`. After adding a position signal `[0, 1, 2]` to each, the sets `{1+0, 2+1, 3+2}` and `{3+0, 2+1, 1+2}` differ, so the two orders are now distinguishable.

### 6. Technical example

Without position information a Transformer is *permutation-equivariant*: output rows permute exactly as the inputs do.

### 7. Code

**① By hand (plain Python).** Show that attention without positions ignores order.

```python
import math

def attend(values):
    out = []
    for q in values:
        w = [math.exp(q * k) for k in values]; w = [x / sum(w) for x in w]
        out.append(sum(wi * v for wi, v in zip(w, values)))
    return out

order1, order2 = [1.0, 2.0, 3.0], [3.0, 2.0, 1.0]
print("outputs for order 1:", [round(x, 3) for x in attend(order1)])
print("outputs for order 2:", [round(x, 3) for x in attend(order2)], "(the same numbers, reversed: only reshuffled)")
pos = [0.0, 1.0, 2.0]
a = attend([v + p for v, p in zip(order1, pos)]); b = attend([v + p for v, p in zip(order2, pos)])
print("with positions the multiset of outputs differs:", sorted(round(x, 3) for x in a) != sorted(round(x, 3) for x in b))
```

```text
outputs for order 1: [2.575, 2.851, 2.948]
outputs for order 2: [2.948, 2.851, 2.575] (the same numbers, reversed: only reshuffled)
with positions the multiset of outputs differs: True
```

**② With NumPy.** Order-blindness of self-attention, and how positions break the symmetry.

```python
import numpy as np

rng = np.random.default_rng(0)
X = rng.normal(size=(4, 8))
perm = [2, 0, 3, 1]
def attn(X):
    s = X @ X.T / np.sqrt(X.shape[1]); w = np.exp(s - s.max(1, keepdims=True)); w /= w.sum(1, keepdims=True)
    return w @ X
print("shuffled input gives shuffled output (order-blind):", np.allclose(attn(X)[perm], attn(X[perm])))
P = np.sin(np.arange(4)[:, None] / (10 ** (np.arange(8)[None] / 8)))
print("after adding positions the symmetry is broken   :", not np.allclose(attn(X[perm] + P), attn(X + P)[perm]))
```

```text
shuffled input gives shuffled output (order-blind): True
after adding positions the symmetry is broken   : True
```

```python
import numpy as np
from positional import sinusoidal
rng = np.random.default_rng(0)
X = rng.normal(size=(4, 8))
perm = [2, 0, 3, 1]
def attn(X):                      # one-head self-attention, no learned weights, no positions
    s = X @ X.T / np.sqrt(X.shape[1]); w = np.exp(s - s.max(1, keepdims=True)); w /= w.sum(1, keepdims=True)
    return w @ X
print(np.allclose(attn(X)[perm], attn(X[perm])))                      # True: order-blind (equivariant)
P = sinusoidal(4, 8)
print(np.allclose(attn(X + P)[perm], attn(X[perm] + P)))              # False: positions break the symmetry
```

### 9. Enterprise use case

Context-length extension projects (supporting 128k-token documents) are mostly positional-encoding projects; they're a major cost/quality decision.

### 10. AI engineering connection

Determines maximum and extrapolation context length; see [Tier 12](../tier-12-modern-architectures/README.md) for long-context variants.

### 11. Advantages

Restores order sensitivity at low cost.

### 12. Limitations

Each method has limits on length generalization and compatibility.

### 13. Trade-offs

Absolute: simple, no extrapolation. Relative: better generalization, more complexity.

### 14. Common mistakes

- Assuming Transformers 'know' order inherently.
- Mixing checkpoints and code with different position conventions.
- Expecting a model to work beyond trained length without scaling.

### 15. Performance / cost

Learned tables: `L_max*d` params; RoPE/ALiBi: negligible params, small compute at attention.

### 16. Security

Position tricks (context stuffing, very long inputs) can be used to bury instructions; long contexts widen the prompt-injection surface.

</details>

### 17. Interview explanation

*"Attention is permutation-equivariant, so we inject position: added learned or sinusoidal vectors at the input, or relative schemes like RoPE and ALiBi inside attention. Relative methods generalize better to longer sequences."*

### 18. Rapid-fire answer

Attention is order-blind; positions must be injected (absolute, sinusoidal, RoPE, ALiBi).
