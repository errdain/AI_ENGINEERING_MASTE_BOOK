# 6.29 Byte fallback

**Metadata** — Tier: 6 · Phase: 2 · Priority: High · Difficulty: Intermediate · Interview: High · Hands-on: Medium
Prerequisites: [6.4 Byte tokenization](06.04-byte-tokenization.md), [6.8 UNK](06.08-unk.md), [6.14 SentencePiece](06.14-sentencepiece.md) · Leads to: [6.31 Tokenization efficiency](06.31-tokenization-efficiency.md)

> **In plain words**
> **Byte fallback** keeps an ordinary vocabulary of characters and sub-words, and encodes any character it does *not* contain as its raw UTF-8 bytes (tokens such as `<0xE6>`), instead of `<UNK>`. Nothing is ever unknown and common text stays cheap. Rare scripts and emoji cost 2–4 byte tokens per character.

**You need first:** [6.4 Byte tokenization](06.04-byte-tokenization.md), [6.8 UNK](06.08-unk.md), [6.14 SentencePiece](06.14-sentencepiece.md).

> *How to read it:* the tokenizer first tries to match its normal pieces. Only when nothing matches does it spell the character out in bytes, so unknown input degrades gracefully instead of becoming `<UNK>`.

### 1. What is it?

Byte fallback keeps a normal subword vocabulary but encodes characters it does not contain as raw UTF-8 bytes (e.g. `<0xE6>` tokens) instead of `<UNK>`.

### 2. Why does it exist?

Makes any input representable (no UNK) while keeping compact tokens for common text; avoids the full cost of pure byte-level tokenization.

### 3. Detailed explanation

Mechanism: reserve 256 byte tokens in the vocabulary. At encode time, a character not covered by any piece is replaced by its UTF-8 bytes, each emitted as a byte token. Decoding concatenates byte tokens back into characters. Used by SentencePiece-based models such as Llama-family tokenizers (verify per model, `REVIEW_REQUIRED`).

Contrast with byte-level BPE ([6.4 Byte tokenization](06.04-byte-tokenization.md), [6.12 BPE](06.12-bpe.md)): there bytes are the *base alphabet* for all merges; with byte fallback the vocabulary is character/subword based and bytes are only the escape hatch. Rare scripts therefore cost 2-4 byte tokens per character - the same asymmetry as pure bytes.

### 4. How does it work?

Encode: segment as usual; for uncovered characters emit byte tokens. Decode: join all pieces; merge consecutive byte tokens and UTF-8 decode.

### 5. Simple example

A dictionary with a 'spell it out in Morse' appendix for words that are not in it.

**By hand.** Vocabulary `{"hello", " world", " "}` plus 256 byte tokens (id 100 + byte). "hello world" → `[hello, " world"]` = 2 tokens. "hello 🙂": `hello`, then `" "`, then the emoji is not in the vocabulary → its 4 UTF-8 bytes `240 159 153 130` become 4 byte tokens: 6 tokens in total and no information lost.

### 6. Technical example

An emoji absent from the vocabulary becomes four byte tokens instead of one UNK.

### 7. Code

**① By hand (plain Python).** A tokenizer with byte fallback, in a few lines.

```python
vocab = {"hello": 0, " world": 1, " ": 2}                    # byte tokens get ids 100 + byte value

def encode(s):
    out, i = [], 0
    pieces = sorted(vocab, key=len, reverse=True)
    while i < len(s):
        p = next((p for p in pieces if s.startswith(p, i)), None)
        if p:
            out.append(vocab[p]); i += len(p)
        else:
            out += [100 + b for b in s[i].encode("utf-8")]; i += 1       # fall back to raw bytes
    return out

print(encode("hello world"))
print(encode("hello 🙂"), "  <- the emoji became 4 byte tokens")
```

```text
[0, 1]
[0, 2, 340, 259, 253, 230]   <- the emoji became 4 byte tokens
```

**② With NumPy.** How expensive is the fallback for different scripts?

```python
samples = {"English": "hello world", "Greek": "γειά σου", "Hindi": "नमस्ते", "Emoji": "🙂🙂🙂"}
for name, s in samples.items():
    print(f"{name:<8}: {len(s):>2} characters -> {len(s.encode()):>2} byte tokens if none are in the vocabulary ({len(s.encode()) / len(s):.1f} per character)")
```

```text
English : 11 characters -> 11 byte tokens if none are in the vocabulary (1.0 per character)
Greek   :  8 characters -> 15 byte tokens if none are in the vocabulary (1.9 per character)
Hindi   :  6 characters -> 18 byte tokens if none are in the vocabulary (3.0 per character)
Emoji   :  3 characters -> 12 byte tokens if none are in the vocabulary (4.0 per character)
```

### 9. Enterprise use case

Multilingual products rely on byte fallback so unexpected scripts, emoji or symbols never crash or silently vanish.

### 10. AI engineering connection

A reason modern LLMs essentially never emit UNK ([6.8 UNK](06.08-unk.md)).

### 11. Advantages

No UNK; keeps compact tokens for common text.

### 12. Limitations

Fallback characters are expensive (2-4 tokens each); byte tokens carry little meaning.

### 13. Trade-offs

Universal coverage with small vocabularies versus high cost for uncovered scripts.

### 14. Common mistakes

- Forgetting to enable byte fallback and getting UNK.
- Assuming it fixes cost for uncovered scripts.
- Decoding byte tokens individually (broken characters).

### 15. Performance / cost

Uncovered scripts: 2-4x tokens per character.

### 16. Security

Byte tokens make arbitrary input representable; combine with token caps and normalization checks.

vocab = {"the", " cat", " sat"}
def cost(s):
    tokens, i = 0, 0
    while i < len(s):
        match = next((p for p in sorted(vocab, key=len, reverse=True) if s.startswith(p, i)), None)
        if match:
            tokens += 1; i += len(match)
        else:
            tokens += len(s[i].encode()); i += 1
