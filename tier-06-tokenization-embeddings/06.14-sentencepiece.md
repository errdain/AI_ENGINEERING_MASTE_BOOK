> **In plain words**
> **SentencePiece** is a tokenizer *toolkit*, not a single algorithm. It trains BPE or Unigram directly on **raw text**, without needing to split into words first, and it treats the space as an ordinary symbol written `▁`. That makes encoding and decoding exactly reversible for any language, including ones written without spaces.

**You need first:** [6.12 BPE](06.12-bpe.md), [6.15 Unigram LM tokenizer](06.15-unigram-lm-tokenizer.md), [6.1 Text preprocessing](06.01-text-preprocessing.md).

> **Figure 6.14-1 — Whitespace is just another symbol**
>
> ```mermaid
> flowchart LR
>     A["Hello world"] --> B["▁Hello▁world (space becomes ▁)"]
>     B --> C["split into pieces: ▁Hello | ▁world"]
>     C --> D["decode: join, replace ▁ with space"]
> ```
>
> *How to read it:* SentencePiece first writes every space as `▁` and then segments the whole string. Decoding is a plain join followed by replacing `▁` with a space, so no information about spaces is ever lost.

### 1. What is it?

SentencePiece is a tokenizer library/framework (not a single algorithm) that trains and applies BPE or Unigram directly on raw text, treating whitespace as an ordinary symbol written `▁`.

### 2. Why does it exist?

Whitespace-based pre-tokenization fails for languages without spaces and makes detokenization ambiguous. Treating the text as a raw stream makes tokenization language-agnostic and exactly reversible.

### 3. Detailed explanation

Key features: (1) **no pre-tokenizer assumption**; (2) **whitespace as `▁`**, so decoding is `concat + replace('▁',' ')`; (3) both **BPE and Unigram** ([6.15 Unigram LM tokenizer](06.15-unigram-lm-tokenizer.md)) model types; (4) built-in normalization (NFKC-style rules by default; configurable, `REVIEW_REQUIRED`); (5) optional **byte fallback** ([6.29 Byte fallback](06.29-byte-fallback.md)).

Examples of use (verify per model, `REVIEW_REQUIRED`): T5 uses SentencePiece Unigram; Llama 1/2 use SentencePiece BPE with byte fallback.

### 4. How does it work?

Training: `SentencePieceTrainer.train(input=..., vocab_size=..., model_type='bpe' or 'unigram', byte_fallback=True)`. Encoding: `sp.encode(text)`; decoding rebuilds spaces from `▁`.

### 5. Simple example

Treating a whole message as one long string of characters (spaces included) and learning where useful breaks are, instead of first cutting it at spaces.

**By hand.** Text `Hello world` → `▁Hello▁world`. A model might split it as `▁Hello | ▁world`. To decode: concatenate → `▁Hello▁world`, replace `▁` by a space → ` Hello world`, strip the leading space → `Hello world`. A Japanese sentence without any spaces goes through the same pipeline unchanged.

### 6. Technical example

Japanese text without spaces is handled with the same code path as English.

### 7. Code

**① By hand (plain Python).** Whitespace as ▁: a reversible round trip in plain Python.

```python
text = "Hello  world, how are you"
marked = "▁" + text.replace(" ", "▁")
pieces = ["▁Hello", "▁", "▁world", ",", "▁how", "▁are", "▁you"]          # one possible segmentation
decoded = "".join(pieces).replace("▁", " ").lstrip(" ")
print("marked :", marked)
print("decoded:", repr(decoded))
print("lossless, including the double space:", decoded == text)
```

```text
marked : ▁Hello▁▁world,▁how▁are▁you
decoded: 'Hello  world, how are you'
lossless, including the double space: True
```

**② With NumPy.** Why no pre-tokenizer matters: counting how often each script needs spaces.

```python
samples = {"English": "the cat sat on the mat", "Japanese": "猫はマットの上に座った", "Thai": "แมวนั่งบนเสื่อ"}
for name, s in samples.items():
    print(f"{name:<9}: {s.count(' ')} spaces in {len(s)} characters -> splitting on spaces gives {len(s.split())} 'word(s)'")
```

```text
English  : 5 spaces in 22 characters -> splitting on spaces gives 6 'word(s)'
Japanese : 0 spaces in 11 characters -> splitting on spaces gives 1 'word(s)'
Thai     : 0 spaces in 14 characters -> splitting on spaces gives 1 'word(s)'
```

### 9. Enterprise use case

Multilingual products (support in 10+ languages) choose SentencePiece-based vocabularies to avoid per-language pre-tokenizers.

### 10. AI engineering connection

Backbone of many open multilingual and Llama-family tokenizers (`REVIEW_REQUIRED`).

### 11. Advantages

Language-agnostic; reversible; self-contained (normalization inside); supports byte fallback.

### 12. Limitations

Default normalization may be lossy; whitespace `▁` conventions differ from GPT-style tokenizers; not a new algorithm.

### 13. Trade-offs

Generality and reversibility versus losing the cheap pre-tokenization heuristics (digits, code indentation) unless configured.

### 14. Common mistakes

- Calling SentencePiece 'a tokenizer algorithm'.
- Forgetting `byte_fallback` and getting UNK.
- Assuming default normalization preserves case/whitespace exactly.

### 15. Performance / cost

Fast C++ implementation; vocabulary choices drive cost as usual ([6.31 Tokenization efficiency](06.31-tokenization-efficiency.md)).

### 16. Security

Loading untrusted `.model` files: treat them as untrusted binary artifacts; do not accept user-supplied tokenizers in multi-tenant systems without review.
