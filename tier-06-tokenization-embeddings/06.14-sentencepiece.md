### 1. WHAT IS IT?

SentencePiece is a tokenizer library/framework (not a single algorithm) that trains and applies BPE or Unigram directly on raw text, treating whitespace as an ordinary symbol written `▁`.

### 2. WHY DOES IT EXIST?

Whitespace-based pre-tokenization fails for languages without spaces and makes detokenization ambiguous. Treating the text as a raw stream makes tokenization language-agnostic and exactly reversible.

### 3. DETAILED EXPLANATION

Key features: (1) **no pre-tokenizer assumption**; (2) **whitespace as `▁`**, so decoding is `concat + replace('▁',' ')`; (3) both **BPE and Unigram** ([6.15 Unigram LM tokenizer](06.15-unigram-lm-tokenizer.md)) model types; (4) built-in normalization (NFKC-style rules by default; configurable, `REVIEW_REQUIRED`); (5) optional **byte fallback** ([6.29 Byte fallback](06.29-byte-fallback.md)).

Examples of use (verify per model, `REVIEW_REQUIRED`): T5 uses SentencePiece Unigram; Llama 1/2 use SentencePiece BPE with byte fallback.

### 4. HOW DOES IT WORK?

Training: `SentencePieceTrainer.train(input=..., vocab_size=..., model_type='bpe' or 'unigram', byte_fallback=True)`. Encoding: `sp.encode(text)`; decoding rebuilds spaces from `▁`.

### 5. SIMPLE EXAMPLE

Treating a whole message as one long string of characters (spaces included) and learning where useful breaks are, instead of first cutting it at spaces.

### 6. TECHNICAL EXAMPLE

Japanese text without spaces is handled with the same code path as English.

### 7. CODE

```python
# NOT RUN here (sentencepiece is not installed in this environment) -- verify the API, REVIEW_REQUIRED
import sentencepiece as spm
spm.SentencePieceTrainer.train(input="corpus.txt", model_prefix="sp", vocab_size=8000,
                               model_type="unigram", byte_fallback=True)
sp = spm.SentencePieceProcessor(model_file="sp.model")
print(sp.encode("Hello world", out_type=str))   # e.g. ['▁Hello', '▁world']
```
The lab's whitespace handling in `_pretokenize` (leading space stays on the word) is the BPE-style analogue; see [`lab/mini_bpe.py`](lab/mini_bpe.py)

### 8. INPUT → PROCESS → OUTPUT

```
raw text (spaces → ▁) ──BPE or Unigram model──► pieces ──► IDs ──decode──► same text
```

### 9. ENTERPRISE USE CASE

Multilingual products (support in 10+ languages) choose SentencePiece-based vocabularies to avoid per-language pre-tokenizers.

### 10. AI ENGINEERING CONNECTION

Backbone of many open multilingual and Llama-family tokenizers (`REVIEW_REQUIRED`).

### 11. ADVANTAGES

Language-agnostic; reversible; self-contained (normalization inside); supports byte fallback.

### 12. LIMITATIONS

Default normalization may be lossy; whitespace `▁` conventions differ from GPT-style tokenizers; not a new algorithm.

### 13. TRADE-OFFS

Generality and reversibility versus losing the cheap pre-tokenization heuristics (digits, code indentation) unless configured.

### 14. COMMON MISTAKES

- Calling SentencePiece 'a tokenizer algorithm'.
- Forgetting `byte_fallback` and getting UNK.
- Assuming default normalization preserves case/whitespace exactly.

### 15. PERFORMANCE / COST CONSIDERATIONS

Fast C++ implementation; vocabulary choices drive cost as usual ([6.31 Tokenization efficiency](06.31-tokenization-efficiency.md)).

### 16. SECURITY CONSIDERATIONS

Loading untrusted `.model` files: treat them as untrusted binary artifacts; do not accept user-supplied tokenizers in multi-tenant systems without review.
