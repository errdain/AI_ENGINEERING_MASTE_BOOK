# 6.9 PAD

**Metadata** — Tier: 6 · Phase: 2 · Priority: High · Difficulty: Beginner · Interview: High · Hands-on: High
Prerequisites: [6.7 Token IDs](06.07-token-ids.md) · Leads to: [6.16 Attention masks](06.16-attention-masks.md)

> **In plain words**
> `<PAD>` is the filler token added to shorter sequences so that a batch becomes a **rectangular grid** (all rows the same length). It carries no information, so it must be **hidden from attention** (by a mask) and **ignored by the loss**. Otherwise the model would learn from, and be confused by, meaningless filler.

**You need first:** [6.7 Token IDs](06.07-token-ids.md).

### 1. What is it?

`<PAD>` is the filler token appended (or prepended) to shorter sequences so that a batch of sequences forms a rectangular tensor.

### 2. Why does it exist?

GPUs process tensors of fixed shape; sequences in a batch have different lengths.

### 3. Detailed explanation

PAD carries no information and must not influence the result: the **attention mask** ([6.16 Attention masks](06.16-attention-masks.md)) hides PAD positions from attention, and the **loss** must ignore PAD targets (e.g. `ignore_index` in cross-entropy). Padding side matters: right padding is the training default; left padding is typical for batched *generation* so that the last real token is aligned at the end (`REVIEW_REQUIRED` per framework).

Cost: padding wastes compute proportional to the pad fraction; bucketing sequences by length reduces it.

### 4. How does it work?

`max_len = max(len(s))`; fill every row to `max_len` with the PAD ID; build a 0/1 mask.

### 5. Simple example

Putting blank sheets into folders so that all folders have the same thickness; the blank sheets are ignored when reading.

**By hand.** Two sequences `[7, 8]` and `[9]` with `<BOS>=1`, `<EOS>=2`, `<PAD>=0`: wrapped they are `[1, 7, 8, 2]` and `[1, 9, 2]`; the second is padded to `[1, 9, 2, 0]`. The mask is `[[1,1,1,1],[1,1,1,0]]`. Padding wastes 1 of 8 positions here (12.5%).

### 6. Technical example

A batch of 3 prompts with lengths 5, 9 and 3 becomes a 3x9 tensor; 27 slots, 17 real tokens, 37% padding waste.

### 7. Code

**① By hand (plain Python).** Pad a batch and build the mask in plain Python.

```python
PAD, BOS, EOS = 0, 1, 2
seqs = [[7, 8], [9], [4, 5, 6]]
wrapped = [[BOS] + s + [EOS] for s in seqs]
longest = max(len(s) for s in wrapped)
ids = [s + [PAD] * (longest - len(s)) for s in wrapped]
mask = [[1] * len(s) + [0] * (longest - len(s)) for s in wrapped]
for row, m in zip(ids, mask):
    print(row, m)
print("padding fraction:", round(sum(m.count(0) for m in mask) / (len(mask) * longest), 2))
```

```text
[1, 7, 8, 2, 0] [1, 1, 1, 1, 0]
[1, 9, 2, 0, 0] [1, 1, 1, 0, 0]
[1, 4, 5, 6, 2] [1, 1, 1, 1, 1]
padding fraction: 0.2
```

**② With NumPy.** The cost of padding when lengths vary a lot, and how bucketing helps.

```python
import numpy as np

rng = np.random.default_rng(0)
lengths = rng.integers(5, 200, size=64)
padded_cells = lengths.max() * lengths.size
print(f"random batch: longest {lengths.max()}, real tokens {lengths.sum()}, padded cells {padded_cells}, waste {1 - lengths.sum() / padded_cells:.0%}")
sorted_len = np.sort(lengths).reshape(8, 8)                    # bucketing: batches of similar lengths
cells = (sorted_len.max(axis=1, keepdims=True) * np.ones((1, 8))).sum()
print(f"after bucketing into 8 batches of 8: waste {1 - lengths.sum() / cells:.0%}")
```

```text
random batch: longest 199, real tokens 6654, padded cells 12736, waste 48%
after bucketing into 8 batches of 8: waste 9%
```

**③ With PyTorch.** Padding must not reach the loss: ignore_index.

```python
import torch

torch.manual_seed(0)
logits = torch.randn(2, 4, 6)                                   # (batch, positions, vocabulary)
targets = torch.tensor([[2, 3, 1, 0], [4, 2, 0, 0]])             # 0 is <PAD>
mask = targets != 0
loss_all = torch.nn.functional.cross_entropy(logits.reshape(-1, 6), targets.reshape(-1))
loss_ignore = torch.nn.functional.cross_entropy(logits.reshape(-1, 6), targets.reshape(-1), ignore_index=0)
print("loss counting padding as real targets:", round(loss_all.item(), 3))
print("loss with ignore_index=0 (correct)   :", round(loss_ignore.item(), 3), "  real positions:", int(mask.sum()), "of", mask.numel())
```

```text
loss counting padding as real targets: 2.049
loss with ignore_index=0 (correct)   : 1.937   real positions: 5 of 8
```

### 9. Enterprise use case

Inference servers use length bucketing or continuous batching to cut padding waste (see Tier 11).

### 10. AI engineering connection

Source of subtle bugs: forgetting the mask leaks PAD into attention; forgetting `ignore_index` trains the model to predict PAD.

### 11. Advantages

Enables dense batched computation.

### 12. Limitations

Wasted compute and memory; must be masked in both attention and loss.

### 13. Trade-offs

Simplicity of rectangular batches versus wasted FLOPs; packing and bucketing trade code complexity for efficiency.

### 14. Common mistakes

- Attending to PAD (no mask).
- Including PAD in the loss.
- Left/right padding mismatch at generation time.
- Using the EOS ID as PAD without handling the mask carefully (common in some models; follow the model card).

### 15. Performance / cost

Padding fraction = wasted FLOPs. Sorting by length or packing multiple sequences per row can recover most of it.

### 16. Security

Differences in padding behaviour between batch sizes can change outputs slightly and cause non-determinism; do not treat PAD handling as security-neutral in multi-tenant batching (cross-request leakage if masks are wrong).
