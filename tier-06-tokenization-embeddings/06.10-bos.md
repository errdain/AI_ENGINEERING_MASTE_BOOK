# 6.10 BOS

**Metadata** — Tier: 6 · Phase: 2 · Priority: Medium · Difficulty: Beginner · Interview: Medium · Hands-on: Medium
Prerequisites: [6.7 Token IDs](06.07-token-ids.md), [6.9 PAD](06.09-pad.md) · Leads to: [6.11 EOS](06.11-eos.md), [Tier 10](../tier-10-fine-tuning-alignment/README.md)

> **In plain words**
> `<BOS>` ("beginning of sequence") is a special token placed at the very start of a sequence. It gives the model a fixed starting point and a place to "park" attention. Conventions differ between models (always, never, sometimes), so you should let the tokenizer library add it, not add it by hand: adding it twice is a common silent bug.

**You need first:** [6.7 Token IDs](06.07-token-ids.md), [6.9 PAD](06.09-pad.md).

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| <BOS> | token marking the start of a sequence |

| double BOS | BOS added twice, once by hand and once by the library |
| control token | a token with a special role, never ordinary text |

### 1. What is it?

`<BOS>` (beginning of sequence) is a special token placed at the start of a sequence.

### 2. Why does it exist?

It gives the first real token a consistent left context, provides a place for the model to 'park' attention, and marks document boundaries when sequences are packed.

### 3. Detailed explanation

Conventions differ: some models always prepend BOS, some never do, some use it only for particular tasks; chat models add role/turn markers on top of it (chat templates, [Tier 10](../tier-10-fine-tuning-alignment/README.md)). Always follow the model card and let the library's tokenizer add it (`add_special_tokens`), rather than adding it by hand twice (double-BOS is a common silent bug).

**Security:** the *string* `<BOS>` typed by a user must not be parsed into the control token; treat user text as plain text.

### 4. How does it work?

Encoder: `ids = [BOS] + tokenize(text)` (+ EOS, [6.11 EOS](06.11-eos.md)). Decoder skips specials when rendering text.

### 5. Simple example

The title line at the top of a page that tells the reader a new document starts here.

**By hand.** Text "low" becomes a few piece ids; with specials the sequence is `[1, ..., 2]`: id 1 first (BOS), id 2 last (EOS). Decoding skips the specials, so the round trip returns exactly "low". If you add BOS by hand and the library adds it too, you get `[1, 1, ...]`, a shifted, slightly broken input.

### 6. Technical example

Packed pre-training batches concatenate documents separated by EOS/BOS so the model learns boundaries (REVIEW_REQUIRED which tokens each model uses).

### 7. Code

**① By hand (plain Python).** Wrap a sequence with BOS/EOS and show the double-BOS bug.

```python
BOS, EOS = 1, 2
ids = [31, 32, 33]
once = [BOS] + ids + [EOS]
twice = [BOS] + once                                            # the library added BOS again
print("correct:   ", once)
print("double BOS:", twice)
print("decode skips specials:", [i for i in once if i not in (BOS, EOS)])
```

```text
correct:    [1, 31, 32, 33, 2]
double BOS: [1, 1, 31, 32, 33, 2]
decode skips specials: [31, 32, 33]
```

**② With NumPy.** What BOS gives attention: a position that exists in every sequence (toy).

```python
import numpy as np

rng = np.random.default_rng(0)
scores = rng.normal(size=(1, 5))                                 # raw attention scores of the first real token
mask = np.array([[True, False, False, False, False]])
only_self = np.exp(np.where(mask, scores, -np.inf)); only_self /= only_self.sum()
print("first token without BOS must attend to itself only:", only_self.round(2))
with_bos = np.exp(scores[:, :2] - scores[:, :2].max()); with_bos /= with_bos.sum()
print("with a BOS position it can split its attention:   ", with_bos.round(2))
```

```text
first token without BOS must attend to itself only: [[1. 0. 0. 0. 0.]]
with a BOS position it can split its attention:    [[0.56 0.44]]
```

**③ With the tier library.** The tier tokenizer adds and strips specials.

```python
import sys
sys.path.insert(0, "lab")
from mini_bpe import ByteBPE

tok = ByteBPE.train("low lower lowest " * 20, 5)
plain = tok.encode("low")
wrapped = tok.encode("low", add_special=True)
print("without specials:", plain, "   with:", wrapped)
print("first / last id:", wrapped[0], wrapped[-1], "(BOS = 1, EOS = 2)")
print("decoding skips specials:", tok.decode(wrapped) == "low")
```

```text
without specials: [261]    with: [1, 261, 2]
first / last id: 1 2 (BOS = 1, EOS = 2)
decoding skips specials: True
```

### 9. Enterprise use case

Prompt-assembly services centralize BOS/template handling so product teams cannot double-add or omit it.

### 10. AI engineering connection

A wrong BOS convention shifts outputs measurably in some models; chat templates build on it.

### 11. Advantages

Consistent anchor; boundary signal.

### 12. Limitations

Model-specific conventions; harmless when absent in some models, damaging in others.

### 13. Trade-offs

Extra token per sequence versus consistent anchoring.

### 14. Common mistakes

- Double BOS (template adds one, tokenizer adds another).
- Omitting it for a model that expects it.
- Parsing user-typed `<BOS>` as a control token.

### 15. Performance / cost

One extra token per sequence: negligible.

### 16. Security

Special-token injection: user text containing control-token strings can hijack chat structure; disable special-token parsing for untrusted text (`REVIEW_REQUIRED` flag names per library).

</details>
