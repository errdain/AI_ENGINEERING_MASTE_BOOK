### 1. WHAT IS IT?

Pooling summarizes each small window of a feature map with a fixed function (max or average), reducing spatial size and giving local shift tolerance.

### 2. WHY DOES IT EXIST?

Cuts compute/memory, grows the receptive field, and makes features less sensitive to exact position.

### 3. DETAILED EXPLANATION

**Max pool** keeps the strongest response (detector-like); **average pool** keeps the mean; **global average pooling** (GAP) averages the whole map to one value per channel, replacing big dense layers.

**No parameters**, so no learning; gradients route only to the max location (max) or evenly (avg).

**Modern trend.** Many nets use strided convs instead and GAP at the end; ViTs have no spatial pooling but have [CLS]/mean token pooling ([13.18 Vision encoders](13.18-vision-encoders.md)).

![Receptive field growth and 2x2 max pooling](figures/04_receptive_field_pooling.png)

*Look at: right panel - 16x16 shrinks to 8x8 but the circle survives; left panel - pooling makes the receptive field grow faster than convs alone.*

### 4. HOW DOES IT WORK?

Slide a k x k window with stride s (default s=k) and take max/mean. Output size uses the same formula as convolution (no padding).

### 5. SIMPLE EXAMPLE

`[[1,2],[3,4]]` max-pools to `[4]`, average-pools to `[2.5]`.

### 6. TECHNICAL EXAMPLE

`max_pool2d(arange(16).reshape(4,4))` = `[[5,7],[13,15]]` (tested in `test_max_pool_and_receptive_field`).

### 7. CODE

```python
import sys; sys.path.insert(0, "lab")
import numpy as np
from vision import max_pool2d
print(max_pool2d(np.arange(16.).reshape(4, 4)))        # [[ 5.  7.] [13. 15.]]
```

### 8. INPUT → PROCESS → OUTPUT

Input: feature map. Process: window reduce. Output: smaller map.

### 9. ENTERPRISE USE CASE

Not an enterprise decision on its own; shows up in architecture-search/latency budgets for edge deployments.

### 10. AI ENGINEERING CONNECTION

GAP produces the image embedding in classic CNNs ([13.14 Image embeddings](13.14-image-embeddings.md)); attention pooling replaces it in CLIP-style ViTs (see [13.20 CLIP](13.20-clip.md)).

### 11. ADVANTAGES

Parameter-free, cheap, local invariance.

### 12. LIMITATIONS

Discards location and fine detail; max pool is not smooth.

### 13. TRADE-OFFS

Pooling vs strided conv: fixed/cheap vs learned/flexible.

### 14. COMMON MISTAKES

Pooling too early (small objects vanish); using pooling in dense-prediction models without decoders; expecting exact translation invariance (it is only approximate).

### 15. PERFORMANCE / COST CONSIDERATIONS

Reduces following layers' cost ~4x for 2x2/2 pooling.

### 16. SECURITY CONSIDERATIONS

Not applicable.

### 17. INTERVIEW EXPLANATION

Pooling downsamples each window by max or mean: no parameters, reduces cost, adds small-shift invariance and grows the receptive field. Global average pooling replaces large dense heads and yields a fixed-size embedding for any input size.

### 18. RAPID-FIRE ANSWER

Parameter-free window summary (max/mean) that shrinks maps and adds local invariance.
