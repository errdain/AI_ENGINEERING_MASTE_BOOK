### 1. WHAT IS IT?

An image embedding is a fixed-length vector produced by a vision encoder that summarizes an image so that similar images (or images with similar meaning) have nearby vectors.

### 2. WHY DOES IT EXIST?

Raw pixels do not support similarity: two photos of the same cat differ in almost every pixel. Embeddings enable retrieval, clustering, near-duplicate detection and transfer to new tasks with a linear probe.

### 3. DETAILED EXPLANATION

**Source.** Take the pooled penultimate output of a CNN/ViT (classification-trained or self-supervised/contrastive-trained).

**Comparing.** L2-normalize and use cosine similarity (or dot product on normalized vectors).

**Quality depends on training objective.** A classifier trained on 4 shape classes embeds shape but may ignore colour; a contrastive (image, caption) model ([13.20 CLIP](13.20-clip.md)) embeds both if captions mention both.

**Evaluation.** recall@k on a labelled gallery; chance for k=1 with 12 equal groups is about 1/12.

**ANN search at scale.** Millions of vectors need approximate nearest-neighbour indexes (Tier 20).

### 4. HOW DOES IT WORK?

encoder(x) -> pooled vector -> (optional projection) -> L2-normalize -> store/query by cosine similarity.

### 5. SIMPLE EXAMPLE

Search 'photos like this one': embed the query, return the 5 nearest stored embeddings.

### 6. TECHNICAL EXAMPLE

Lab: `TinyCNN.embed` returns 32-d vectors; `retrieval_recall` ranks gallery images by cosine similarity to caption embeddings. After CLIP-style training the toy reaches recall@1 of about 1.0 vs chance about 0.08 on 12 captions (measured; test requires > 3x chance and > 0.5).

### 7. CODE

```python
import sys; sys.path.insert(0, "lab")
import torch, torch.nn.functional as F
from vision import make_dataset
from models import TinyCNN
X, ys, yc = make_dataset(6, seed=0)
z = F.normalize(TinyCNN().embed(torch.as_tensor(X)), dim=-1)   # (6, 32), unit length
print((z @ z.T).shape)                                          # all-pairs cosine similarity
```
Lab: [`lab/models.py`](lab/models.py), `retrieval_recall`.

### 8. INPUT → PROCESS → OUTPUT

Input: image. Process: encoder + pooling + normalize. Output: d-dimensional unit vector.

### 9. ENTERPRISE USE CASE

E-commerce 'visually similar items': embed catalogue images offline, index in a vector DB, embed the user's photo online. Governance: version the encoder; re-embed everything when it changes.

### 10. AI ENGINEERING CONNECTION

Image embeddings power multimodal RAG (Tier 20), dedup in dataset curation ([Tier 9 Pretraining](../tier-09-foundation-model-pretraining/)), and are the visual tokens' source in VLMs ([13.22 Vision-language models (VLMs)](13.22-vision-language-models-vlms.md)).

### 11. ADVANTAGES

Compact, reusable, enable similarity search and cheap linear probes.

### 12. LIMITATIONS

Objective-dependent (what is encoded is what training rewarded); not interpretable; drifts with encoder version.

### 13. TRADE-OFFS

Dimension (accuracy vs storage/search cost); frozen generic encoder vs fine-tuned domain encoder.

### 14. COMMON MISTAKES

Comparing embeddings from different models; forgetting to normalize; using an ImageNet classifier on domain imagery without evaluating recall; not re-indexing after upgrading the encoder.

### 15. PERFORMANCE / COST CONSIDERATIONS

Storage = N*d*bytes (10M x 512 float32 = ~20 GB); quantization/ANN trade recall for memory (REVIEW_REQUIRED per index).

### 16. SECURITY CONSIDERATIONS

Embeddings can leak information about inputs (inversion attacks, REVIEW_REQUIRED); access-control vector stores like the images; adversarial images can be crafted to land near any target.

### 17. INTERVIEW EXPLANATION

An image embedding maps an image to a vector where distance reflects similarity under the training objective. I take the pooled encoder output, L2-normalize, compare by cosine, evaluate with recall@k on labelled data, and re-embed the corpus whenever the encoder changes.

### 18. RAPID-FIRE ANSWER

Fixed-size vector from an image encoder; nearby = similar.
