### 1. WHAT IS IT?

ResNet (He et al., 2015) is the family of CNNs built from residual blocks in four stages of increasing channels and decreasing resolution (ResNet-18/34 use basic blocks; ResNet-50/101/152 use 1x1-3x3-1x1 'bottleneck' blocks).

### 2. WHY DOES IT EXIST?

It won ImageNet 2015 and became the default backbone for classification, detection and segmentation for years, showing that depth works once gradients flow.

### 3. DETAILED EXPLANATION

**Layout.** 7x7/2 conv stem + max-pool -> 4 stages (strides 4, 8, 16, 32 relative to input) -> global average pool -> linear.

**Bottleneck block.** 1x1 reduce -> 3x3 -> 1x1 expand, cutting FLOPs for the same width.

**Sizes (REVIEW_REQUIRED, from the original paper/torchvision docs).** ResNet-50 has about 25.6M parameters and ~4 GFLOPs at 224x224 (published figures; verify against current docs).

**Today.** Still a robust, fast baseline and frequent backbone (detection, medical, edge). Variants: ResNeXt, ResNet-D, BiT. Transformers and ConvNeXt-style modernized CNNs compete at the top end (REVIEW_REQUIRED for current rankings).

### 4. HOW DOES IT WORK?

Stem downsamples 4x; each stage = repeated residual blocks, the first with stride 2 and a 1x1 projection shortcut; final GAP gives a 512- or 2048-d embedding.

### 5. SIMPLE EXAMPLE

Think of it as the lab's TinyResNet scaled up: more stages, more blocks, more channels.

### 6. TECHNICAL EXAMPLE

`TinyResNet` in the lab: stem conv+pool, 2 residual blocks, pool, GAP, linear embedding. Parameter counts are printed by `run_lab.py`.

### 7. CODE

```python
import sys; sys.path.insert(0, "lab")
from models import TinyResNet, count_params
print(count_params(TinyResNet(blocks=2)), count_params(TinyResNet(blocks=4)))
# framework equivalent (needs torchvision and, for pretrained weights, internet): torchvision.models.resnet50()
```
REVIEW_REQUIRED: torchvision API/weight names change between releases.

### 8. INPUT → PROCESS → OUTPUT

Input: (B,3,224,224). Process: stem, 4 residual stages, GAP. Output: 2048-d embedding (ResNet-50) -> logits.

### 9. ENTERPRISE USE CASE

Hospitals and factories frequently fine-tune a pretrained ResNet-50 because it is well-understood, quick to serve and easy to validate.

### 10. AI ENGINEERING CONNECTION

ResNet features are the 'classic image embedding' ([13.14 Image embeddings](13.14-image-embeddings.md)) and the backbone inside detection/segmentation models; CLIP also released ResNet-based image encoders (REVIEW_REQUIRED).

### 11. ADVANTAGES

Reliable, fast, well-supported, easy to fine-tune.

### 12. LIMITATIONS

Less accurate than large pretrained ViTs at the top end; fixed local design.

### 13. TRADE-OFFS

Depth (18 vs 50 vs 152) vs latency; accuracy vs deployability.

### 14. COMMON MISTAKES

Training from scratch on tiny data instead of fine-tuning; mismatched BatchNorm statistics when batch size is tiny (use frozen BN or GroupNorm); wrong input normalization.

### 15. PERFORMANCE / COST CONSIDERATIONS

ResNet-50 is typically a few ms per image on a modern GPU with batching (REVIEW_REQUIRED, hardware-dependent).

### 16. SECURITY CONSIDERATIONS

Pretrained checkpoints: verify source/hash; pickle files can execute code.

### 17. INTERVIEW EXPLANATION

ResNet stacks residual blocks in four stages, downsampling by 32 overall, ending in global pooling. Bottleneck blocks (1x1-3x3-1x1) keep deep versions affordable. It remains a strong, cheap baseline and a standard feature extractor even though ViTs lead on large-scale benchmarks.

### 18. RAPID-FIRE ANSWER

Four-stage CNN of residual blocks (stem 7x7/2, GAP head); ResNet-50 uses bottlenecks.
