### 1. WHAT IS IT?

Chart and table visual understanding is reading structured visuals: recovering a table's rows/columns/cells from an image, or extracting values and relationships from plots.

### 2. WHY DOES IT EXIST?

Key facts live in tables and charts that plain OCR flattens into jumbled text.

### 3. DETAILED EXPLANATION

**Tables.** Detect table region -> recognise structure (rows, columns, spans) -> OCR cells -> output grid (CSV/HTML/JSON). Hard: merged cells, borderless tables, multi-page tables.

**Charts.** Identify type, axes, legend, then read values: either by derendering to data tables or asking a VLM. Precise reading needs axis calibration (pixel -> value mapping).

**Linear axis calibration.** Given two reference ticks (p1,v1), (p2,v2): `v = v1 + (p - p1)*(v2 - v1)/(p2 - p1)`.

**Metrics.** Cell-level F1 / structure similarity for tables; relaxed accuracy (within ~5% of value) for chart QA (REVIEW_REQUIRED for exact benchmark definitions).

**Failure modes.** Plausible but wrong numbers, mixing up legend colours, log axes.

### 4. HOW DOES IT WORK?

Detect -> structure -> read -> reconcile (e.g. subtotals) -> output.

### 5. SIMPLE EXAMPLE

Bar at pixel y=120 where tick 0 is at y=300 and tick 100 at y=100 -> value 90.

### 6. TECHNICAL EXAMPLE

Calibration above: p=120, (300,0), (100,100): v = 0 + (120-300)*(100-0)/(100-300) = 90.

### 7. CODE

```python
def pixel_to_value(p, p1, v1, p2, v2):
    return v1 + (p - p1) * (v2 - v1) / (p2 - p1)
print(pixel_to_value(120, 300, 0, 100, 100))      # 90.0
```

### 8. INPUT → PROCESS → OUTPUT

Input: chart/table image. Process: structure + calibration + OCR. Output: data table.

### 9. ENTERPRISE USE CASE

Financial analysts digitise tables from PDF reports; every extracted number carries a source crop and a reconciliation check against totals.

### 10. AI ENGINEERING CONNECTION

Benchmark area for VLMs (chart QA); also feeds RAG indexes with structured data.

### 11. ADVANTAGES

Unlocks data trapped in images.

### 12. LIMITATIONS

Layout variety, log scales, overlapping series, estimation error.

### 13. TRADE-OFFS

Derendering (accurate, fragile) vs VLM reading (flexible, approximate).

### 14. COMMON MISTAKES

Trusting VLM values to 2 decimals; ignoring axis units/scale; losing merged-cell structure.

### 15. PERFORMANCE / COST CONSIDERATIONS

High resolution needed for dense tables; tile with overlap.

### 16. SECURITY CONSIDERATIONS

Same as [13.28 Document-image understanding](13.28-document-image-understanding.md): PII, injection, wrong-number risk in financial decisions.

### 17. INTERVIEW EXPLANATION

Tables need structure recognition plus OCR; charts need axis calibration and legend mapping. VLMs read both approximately; for decisions I reconcile numbers against totals or source data and keep the original crop for audit.

### 18. RAPID-FIRE ANSWER

Recover cell structure from table images and data values from plots.
