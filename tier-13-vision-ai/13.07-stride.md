### 1. WHAT IS IT?

Stride is the step (in pixels) the kernel moves between positions. Stride 1 visits every position; stride 2 skips every other, halving each spatial dimension.

### 2. WHY DOES IT EXIST?

Downsampling inside the network reduces compute and grows the receptive field quickly ([13.10 Receptive fields](13.10-receptive-fields.md)).

### 3. DETAILED EXPLANATION

**Effect on size.** `out = floor((n + 2p - k)/s) + 1`; with k=3, p=1, s=2: 32 -> 16.

**Strided conv vs pooling.** Strided convs learn their downsampling; pooling ([13.9 Pooling](13.09-pooling.md)) is fixed. Modern nets use both.

**Aliasing.** Large strides without prior smoothing can alias fine patterns and miss thin features.

**Patch embedding.** A ViT patch embedding is a convolution with kernel = stride = patch size ([13.17 Patch embeddings](13.17-patch-embeddings.md)).

Play: stride slider in [`conv_explorer.html`](interactive/conv_explorer.html) (also shows the receptive-field jump).

### 4. HOW DOES IT WORK?

Window origin at (i*s, j*s) for output (i,j). The `jump` (distance between adjacent outputs in input pixels) multiplies by s per layer.

### 5. SIMPLE EXAMPLE

Stride 2 on a 6-wide row visits columns 0, 2 (kernel 3, no pad): 2 outputs instead of 4.

### 6. TECHNICAL EXAMPLE

n=17,k=3,s=2,p=1 -> floor((17+2-3)/2)+1 = 9. The formula is checked against torch in `test_conv_output_size_formula_matches_torch`.

### 7. CODE

```python
import sys; sys.path.insert(0, "lab")
from vision import conv_out_size
print([conv_out_size(32, 3, s, 1) for s in (1, 2, 4)])   # [32, 16, 8]
```

### 8. INPUT → PROCESS → OUTPUT

Input: n, k, s, p. Process: formula. Output: output length per axis.

### 9. ENTERPRISE USE CASE

Mobile vision teams use stride-2 stem convs to cut early-layer compute dramatically (often the most expensive layers at high resolution).

### 10. AI ENGINEERING CONNECTION

Stride appears in ResNet stems/stages ([13.13 ResNet](13.13-resnet.md)), ViT patchify ([13.17 Patch embeddings](13.17-patch-embeddings.md)) and U-Net down paths ([13.27 Image segmentation](13.27-image-segmentation.md)).

### 11. ADVANTAGES

Cheap downsampling; fast receptive-field growth.

### 12. LIMITATIONS

Information loss; aliasing; coarse localization.

### 13. TRADE-OFFS

Early large stride: speed vs lost small-object detail.

### 14. COMMON MISTAKES

Off-by-one from forgetting floor; odd sizes that drop border pixels silently; stride > kernel size (gaps).

### 15. PERFORMANCE / COST CONSIDERATIONS

Stride s cuts conv cost ~s^2 per layer at the same channels.

### 16. SECURITY CONSIDERATIONS

Not applicable beyond input-size validation.

### 17. INTERVIEW EXPLANATION

Stride is the step size of the kernel; stride s divides output size by about s per axis. It is learned downsampling that reduces compute and grows the receptive field; too aggressive and small objects vanish.

### 18. RAPID-FIRE ANSWER

Step between kernel positions; stride s shrinks each dimension by ~s.
