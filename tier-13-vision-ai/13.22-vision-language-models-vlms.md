### 1. WHAT IS IT?

A vision-language model (VLM) accepts images (and text) and generates text: it couples a vision encoder to a language model so you can ask questions about images, read documents or describe scenes.

### 2. WHY DOES IT EXIST?

CLIP can match images and text but cannot *answer* or *reason in language* about an image. VLMs add generation by plugging visual features into an LLM.

### 3. DETAILED EXPLANATION

**Common recipe (LLaVA-style).** vision encoder (ViT, often CLIP/SigLIP-style) -> projector (MLP, or Q-Former/resampler) -> visual tokens concatenated with text tokens -> LLM decoder -> answer. See [13.23 Cross-modal attention concepts](13.23-cross-modal-attention-concepts.md) for how modalities interact and [13.24 Visual instruction tuning](13.24-visual-instruction-tuning.md) for training.

**Variants.** (a) Projector + LLM (cheap, popular); (b) cross-attention layers injected into the LLM (Flamingo-style); (c) natively multimodal models trained end-to-end on interleaved data (REVIEW_REQUIRED, vendor-specific details are rarely public).

**Token budget.** Each image costs visual tokens (e.g. 576 for a 336 px, p=14 grid: 24x24 - verify per model, REVIEW_REQUIRED); high-resolution tiling multiplies this. Tokens consume context and latency ([Tier 11 Inference & Optimization](../tier-11-llm-inference-optimization/)).

**Failure modes.** Hallucinated objects, counting/spatial errors, small-text misreads, over-reliance on language priors.

### 4. HOW DOES IT WORK?

Image -> ViT patch tokens -> projector maps each to the LLM's embedding dimension -> sequence `[visual tokens][prompt tokens]` -> autoregressive decoding (Tier 7-8, [Tier 11 Inference & Optimization](../tier-11-llm-inference-optimization/)).

### 5. SIMPLE EXAMPLE

Show a photo of a receipt and ask 'what is the total?'; the model reads visual tokens and writes '$23.40'.

### 6. TECHNICAL EXAMPLE

The lab does *not* train a VLM (no downloads, CPU only); it provides the pieces: a vision encoder (`TinyViT.patches/embed`), contrastive alignment (`fit_clip`), and the token-count arithmetic in the explorer. VLM comparison in the lab is limited to measuring tokens/cost, not quality.

### 7. CODE

```python
# Token arithmetic for a LLaVA-style VLM (numbers are inputs, not facts about a specific model)
side, patch = 336, 14
visual_tokens = (side // patch) ** 2          # 576
context, text_tokens = 4096, 200
print(visual_tokens, context - visual_tokens - text_tokens)   # tokens left for the answer
```
Framework note: Hugging Face `transformers` provides several VLM classes (REVIEW_REQUIRED, names change).

### 8. INPUT → PROCESS → OUTPUT

Input: image(s) + text prompt. Process: encode, project, concatenate, decode. Output: generated text.

### 9. ENTERPRISE USE CASE

Insurance claims triage: photo + policy text -> structured damage summary with citations; human review remains for payouts. Governance: log image hashes, prompts and model versions.

### 10. AI ENGINEERING CONNECTION

VLMs are the multimodal front door to agents and RAG ([13.28 Document-image understanding](13.28-document-image-understanding.md), [13.29 Chart/table visual understanding](13.29-chart-table-visual-understanding.md)), combining the vision encoder with the LLM stack from Tiers 7-11.

### 11. ADVANTAGES

Open-ended visual QA, OCR-free document reading, single interface for many tasks.

### 12. LIMITATIONS

Hallucination, high token cost, weak precise localization/counting, privacy surface.

### 13. TRADE-OFFS

Resolution/tiling (accuracy on small text) vs tokens (cost/latency); frozen encoder (cheap) vs tuned (better).

### 14. COMMON MISTAKES

Trusting VLM output as ground truth; sending unnecessarily large images; no evaluation on own data; ignoring image-borne prompt injection.

### 15. PERFORMANCE / COST CONSIDERATIONS

Prefill cost grows with visual tokens; cache image embeddings for repeated questions; downscale when resolution is not needed.

### 16. SECURITY CONSIDERATIONS

Images can carry instructions (prompt injection through visible text/QR/steganographic content): treat image content as untrusted input; strip metadata; limit tool permissions.

### 17. INTERVIEW EXPLANATION

A VLM connects a vision encoder to an LLM through a projector that turns image patches into visual tokens the LLM reads alongside text. It is trained on image-text data and then instruction-tuned. Costs scale with the number of visual tokens; typical failures are hallucination and counting or small-text errors, so I evaluate on my own data and treat image text as untrusted.

### 18. RAPID-FIRE ANSWER

Vision encoder + projector + LLM: images become tokens the LLM can read.
