### 1. WHAT IS IT?

Everything done to raw pixels before the model: decode, resize/crop, scale to [0,1], normalize with per-channel mean and standard deviation, and (in training) random augmentation.

### 2. WHY DOES IT EXIST?

A pretrained model was trained under one specific preprocessing recipe; feeding differently processed pixels is a distribution shift. Augmentation teaches invariances the data does not show.

### 3. DETAILED EXPLANATION

**Resize/crop/pad.** Models expect a fixed size (or a patch-divisible size for ViT). Options: resize (may distort aspect ratio), center-crop (may cut content), letterbox-pad (keeps content, adds borders).

**Normalization.** `x' = (x - mean) / std` per channel. Mean/std come from the *training set of the model* (e.g. ImageNet statistics are widely reused; verify per model card - REVIEW_REQUIRED).

**Augmentation (training only).** Random flips, crops, colour jitter, noise, blur. Never apply random augmentation at inference. Be careful: flipping is wrong for text/digits; crops can remove the label object.

**Train/serve parity.** The single most common source of silent quality loss.

### 4. HOW DOES IT WORK?

uint8 HWC -> resize -> crop -> float /255 -> `(x-mean)/std` -> CHW -> batch. In training insert random transforms before the float cast.

### 5. SIMPLE EXAMPLE

A pixel value 0.5 with mean 0.5 and std 0.25 becomes 0.0; 1.0 becomes 2.0. Everything is now centred and on a comparable scale.

### 6. TECHNICAL EXAMPLE

Per-channel stats let optimization treat R, G, B evenly; without scaling, gradient scales differ and early layers train slowly. Padding choice also changes the output of detection boxes (coordinates must be mapped back).

### 7. CODE

```python
import sys; sys.path.insert(0, "lab")
import numpy as np
from vision import make_dataset, normalize
X, _, _ = make_dataset(8, seed=0)
Z = normalize(X, mean=[0.5, 0.5, 0.5], std=[0.25, 0.25, 0.25])
print(Z.mean().round(2), Z.std().round(2))     # roughly centred
flip = X[:, :, :, ::-1]                       # horizontal-flip augmentation
```

### 8. INPUT → PROCESS → OUTPUT

Input: decoded image. Process: resize -> scale -> normalize (+ augment in training). Output: model-ready float tensor.

### 9. ENTERPRISE USE CASE

A manufacturer's defect detector degraded after a camera firmware update changed white balance. Fix: add colour-jitter augmentation, add a drift monitor on channel means, and keep a golden image set.

### 10. AI ENGINEERING CONNECTION

VLM and CLIP pipelines each ship their own processor (size, mean/std, tiling). Use the processor from the same checkpoint - never hand-roll it.

### 11. ADVANTAGES

Cheap, large accuracy impact; augmentation reduces overfitting without new data.

### 12. LIMITATIONS

Resize can distort or blur small details (text); augmentations can break label semantics.

### 13. TRADE-OFFS

Higher resolution keeps detail but costs compute; aggressive augmentation regularizes but may slow convergence.

### 14. COMMON MISTAKES

Wrong mean/std or RGB/BGR; normalizing twice; augmenting the validation set; resizing with different interpolation at train vs serve; horizontally flipping OCR data.

### 15. PERFORMANCE / COST CONSIDERATIONS

Do heavy augmentation on GPU or in parallel workers; decode+resize on CPU is a typical input bottleneck.

### 16. SECURITY CONSIDERATIONS

Preprocessing is attack surface: adversarial perturbations survive resize partly, and 'image scaling attacks' hide content that appears only after down-sampling (REVIEW_REQUIRED for current defences). Log the exact transform version.

### 17. INTERVIEW EXPLANATION

Preprocessing turns decoded pixels into the exact tensor distribution the model was trained on: resize/crop, scale to [0,1], per-channel normalization. Augmentation is training-only. The classic production bug is train/serve skew, so I reuse the checkpoint's own processor and keep golden-image tests.

### 18. RAPID-FIRE ANSWER

Resize, scale, normalize exactly as at training; augment only in training.
