### 1. WHAT IS IT?

A vision encoder is the network that turns an image into features (a pooled vector or a grid of patch tokens): a CNN, ViT, or hybrid - the 'eyes' of a larger system.

### 2. WHY DOES IT EXIST?

Downstream systems (retrieval, VLMs, detectors) need a reusable, pretrained visual front end instead of learning to see from scratch.

### 3. DETAILED EXPLANATION

**Outputs.** (a) one global vector (retrieval/classification); (b) a token grid (VLMs, detection, segmentation).

**Pretraining families.** Supervised classification; contrastive image-text (CLIP/SigLIP-style, [13.20 CLIP](13.20-clip.md)); self-supervised (masked image modelling, self-distillation - REVIEW_REQUIRED for specific methods).

**Frozen vs tuned.** Many VLMs freeze or lightly tune the encoder and train a projector + LLM ([13.22 Vision-language models (VLMs)](13.22-vision-language-models-vlms.md)).

**Choosing.** Resolution, patch size, output type, license, latency.

### 4. HOW DOES IT WORK?

preprocess -> encoder -> (global vector or token grid) -> task head or projector.

### 5. SIMPLE EXAMPLE

A pretrained ViT/ResNet with its classification head removed.

### 6. TECHNICAL EXAMPLE

The lab's towers expose `embed(x)`: `TinyCNN`, `TinyResNet` and `TinyViT` all return 32-d vectors, so they are interchangeable inside `fit_clip` and `retrieval_recall`.

### 7. CODE

```python
import sys; sys.path.insert(0, "lab")
import torch
from models import TinyCNN, TinyResNet, TinyViT
x = torch.randn(3, 3, 16, 16)
for enc in (TinyCNN(), TinyResNet(), TinyViT()):
    print(type(enc).__name__, enc.embed(x).shape)      # all (3, 32)
```

### 8. INPUT → PROCESS → OUTPUT

Input: image batch. Process: encoder. Output: embeddings or tokens.

### 9. ENTERPRISE USE CASE

Platform teams standardize on one or two approved encoders (license, safety, latency) and expose them as a shared embedding service.

### 10. AI ENGINEERING CONNECTION

Encoder choice sets VLM quality, token count and cost ([13.22 Vision-language models (VLMs)](13.22-vision-language-models-vlms.md)).

### 11. ADVANTAGES

Reusable, strong transfer.

### 12. LIMITATIONS

Fixed training distribution; resolution limits; frozen encoders cap what a VLM can read (e.g. small text).

### 13. TRADE-OFFS

Bigger encoder = better features, higher latency; frozen = cheap, tuned = adaptive.

### 14. COMMON MISTAKES

Evaluating only on ImageNet-like data; ignoring license; mismatching preprocessing.

### 15. PERFORMANCE / COST CONSIDERATIONS

Encoder FLOPs scale with tokens^2 (ViT); cache embeddings for static corpora.

### 16. SECURITY CONSIDERATIONS

Supply-chain risk of downloaded weights; consistency of preprocessing as a security-relevant contract.

### 17. INTERVIEW EXPLANATION

A vision encoder maps images to features: a global embedding or a patch-token grid. I choose it by pretraining objective, resolution, token count and latency, and reuse it frozen or lightly tuned in retrieval and VLM systems.

### 18. RAPID-FIRE ANSWER

Pretrained image-to-features network (CNN/ViT) used as a front end.
