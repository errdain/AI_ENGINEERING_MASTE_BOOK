### 1. WHAT IS IT?

Image patches are the non-overlapping p x p squares an image is cut into; each patch (p*p*C numbers) becomes one token for a ViT.

### 2. WHY DOES IT EXIST?

Pixels as tokens would give 150k tokens for a 224 px image (attention is quadratic); patches cut the sequence to 196 while keeping local detail inside each token.

### 3. DETAILED EXPLANATION

**Counts.** `N = (H/p) * (W/p)`; patch vector length `p*p*C`. For 224, p=16: N=196, vector 768 numbers. Halving p quadruples N.

**Order.** Raster order (row by row); position embeddings tell the model where each came from.

**Invertibility.** Patchify/unpatchify is a lossless reshape (tested), so no information is lost before the learned projection.

**Variants.** Overlapping patches, convolutional stems, multi-scale/windowed patches (Swin-style, REVIEW_REQUIRED), dynamic resolution/aspect-ratio tiling in VLMs.

### 4. HOW DOES IT WORK?

Reshape `(C,H,W)` -> `(C,H/p,p,W/p,p)` -> transpose to `(H/p,W/p,p,p,C)` -> flatten to `(N, p*p*C)`.

### 5. SIMPLE EXAMPLE

4x4 patches on a 16x16 image: 16 tiles.

### 6. TECHNICAL EXAMPLE

`patchify` / `unpatchify` in the lab; test `test_patchify_roundtrip_and_count` asserts exact round-trip for p=2,4,8,16, checks raster order and that p=5 fails; `test_torch_patches_match_numpy_and_patch_embed_is_conv` ties the torch version to numpy.

### 7. CODE

```python
import sys; sys.path.insert(0, "lab")
import numpy as np
from vision import patchify, unpatchify
img = np.random.rand(3, 16, 16).astype(np.float32)
tok = patchify(img, 4)                              # (16, 48)
assert np.array_equal(unpatchify(tok, 4, 3, 16, 16), img)
```

### 8. INPUT → PROCESS → OUTPUT

Input: (C,H,W), p. Process: reshape/transposes. Output: (N, p*p*C) patch vectors.

### 9. ENTERPRISE USE CASE

Document VLMs split large pages into tiles of patches; the tile count directly sets cost per page.

### 10. AI ENGINEERING CONNECTION

Patch count = visual-token count = LLM context consumed by an image in a VLM ([13.22 Vision-language models (VLMs)](13.22-vision-language-models-vlms.md)).

### 11. ADVANTAGES

Lossless, cheap, controls sequence length.

### 12. LIMITATIONS

Patch boundaries are arbitrary (objects straddle them); fixed grid ignores content.

### 13. TRADE-OFFS

Small p: detail, many tokens. Large p: few tokens, lost fine structure (small text).

### 14. COMMON MISTAKES

H or W not divisible by p; confusing (H,W,C) and (C,H,W) flatten order between implementations (breaks pretrained weights); forgetting CLS.

### 15. PERFORMANCE / COST CONSIDERATIONS

N tokens -> attention ~N^2; a 1024 px image at p=14 gives ~5,300 tokens (73x73), which is costly.

### 16. SECURITY CONSIDERATIONS

Not applicable beyond validating sizes.

### 17. INTERVIEW EXPLANATION

Patchifying splits the image into p x p blocks and flattens each into a vector, giving N=(H/p)(W/p) tokens. It is a lossless reshape; the learned part is the following linear projection. Patch size is the main cost knob because attention grows with N squared.

### 18. RAPID-FIRE ANSWER

Cut image into p x p blocks, flatten each -> N=(H/p)(W/p) tokens.
