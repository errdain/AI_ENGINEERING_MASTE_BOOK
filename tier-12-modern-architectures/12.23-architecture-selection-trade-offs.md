### 1. WHAT IS IT?

Architecture selection is choosing among families (encoder, decoder, enc-dec, MoE, SSM/hybrid) and settings (KV heads, windows, experts, context) by workload, memory budget, latency target and quality needs.

### 2. WHY DOES IT EXIST?

The wrong choice shows up as cost: a cache that does not fit, latency that misses an SLA, or an expensive model for a classification task.

### 3. DETAILED EXPLANATION

Compute first, then argue. The lab's **comparison matrix** gives parameters (total/active), KV KiB/token, cache GiB at a context, GFLOPs/token and max concurrent sequences for any `ArchSpec`.

![Comparison matrix](figures/11_comparison_matrix.png)

*Figure: generated matrix. Case-study rows are REVIEW_REQUIRED; illustrative rows are made-up archetypes. Look at the cache and GFLOPs columns: they separate families far more than parameter count does.*

Open the generated table: [`comparison_matrix.html`](figures/comparison_matrix.html).

[Explore: arch_selector.html](interactive/arch_selector.html) — controls: task, context, GPU memory, concurrency, latency priority, recall need, multi-GPU allowed. It checks memory feasibility from the formulas and ranks archetypes with transparent heuristic rules (not benchmark results).

| Need | Lean towards | Reason |
|---|---|---|
| Labels / embeddings | encoder-only | no generation, no cache |
| Transform tasks | enc-dec or small decoder | read input once |
| General chat/agents | dense GQA decoder | ecosystem, quality |
| Max quality per FLOP, memory available | sparse MoE | active params small |
| Very long context, bounded memory | window/SSM/hybrid | capped cache |
| Exact far recall | keep global attention layers | SSM recall limit |

### 4. HOW DOES IT WORK?

1. Write requirements (task, n, concurrency, latency, memory). 2. Compute weights + cache + FLOPs per candidate. 3. Eliminate infeasible. 4. Evaluate survivors on **your** data. 5. Re-check cost at load.

### 5. SIMPLE EXAMPLE

Choosing a vehicle: first filter by cargo and road, then test drive.

### 6. TECHNICAL EXAMPLE

80 GB, 8k context: dense MHA fits ~15 sequences, GQA-8 ~63, MQA ~511 (archetypes; weights differ) — the memory column of the matrix.

### 11. ADVANTAGES

### 12. LIMITATIONS

Formulas ignore quality, kernels, batching effects and quantization; presets are REVIEW_REQUIRED.

### 13. TRADE-OFFS

Quality vs memory vs latency vs ecosystem.

### 14. COMMON MISTAKES

Selecting by parameter count or leaderboard alone; ignoring KV cache at target concurrency.

### 15. PERFORMANCE / COST CONSIDERATIONS

Weights GiB + (cache GiB × sequences) must fit; GFLOPs/token sets throughput.

### 16. SECURITY CONSIDERATIONS

Self-hosting adds duties (patching, access, data residency); vendor models add data-sharing review.

### 17. INTERVIEW EXPLANATION

*"I compute weights, KV cache and FLOPs per token for each candidate at my context and concurrency, eliminate what does not fit, then evaluate survivors on my own task: encoders for labels, dense GQA decoders by default, MoE when memory allows and quality per FLOP matters, windows/SSM/hybrids for very long context."*

### 18. RAPID-FIRE ANSWER

Filter by memory/latency math, then evaluate on your task.
