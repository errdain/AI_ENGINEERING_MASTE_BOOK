- Leads To: Tier 13 (Vision AI)

### 1. WHAT IS IT?

Comparing model families by **architecture and measurable properties** (config, parameters, KV cache, FLOPs, context, licence) instead of a vendor's API or marketing name.

### 2. WHY DOES IT EXIST?

APIs and model names change monthly; configs and formulas are durable and portable across vendors, and API differences hide the cost drivers.

### 3. DETAILED EXPLANATION

A vendor-neutral comparison has four layers: (1) **config facts** → `ArchSpec`, (2) **derived cost** → params, KV, FLOPs (lab), (3) **behaviour** → your own eval set, (4) **operations** → licence, deployment, security. Layer 3 is required; layers 1-2 are free.

### 4. HOW DOES IT WORK?

1. Collect configs from model cards (REVIEW_REQUIRED). 2. Add presets. 3. Run the matrix at your n and GPU. 4. Test shortlisted models on your data behind a thin adapter so providers can be swapped.

### 5. SIMPLE EXAMPLE

Comparing phones by processor, battery and screen rather than by the shop that sells them.

### 6. TECHNICAL EXAMPLE

A thin interface `generate(prompt) -> text` plus a config table lets the same evaluation harness compare self-hosted and hosted models.

### 7. CODE

```python
import sys; sys.path.insert(0, "lab")
import arch_matrix as am
mine = am.replace(am.PRESETS["Dense GQA-8 (illustrative)"], name="my-candidate", n_kv_heads=4)
for r in am.comparison_rows([mine, am.PRESETS["Qwen2.5-7B-shape (case study)"]], n=32768):
    print(r["name"], round(r["cache_gib_at_n"], 2), "GiB cache @32k")
```

### 8. INPUT → PROCESS → OUTPUT

```
model card → ArchSpec → matrix row ─┐

```

### 9. ENTERPRISE USE CASE

Procurement and architecture-board documents; vendor-swap resilience.

### 10. AI ENGINEERING CONNECTION

Pairs with evaluation (Tier 31) and cost control (Tier 36).

### 11. ADVANTAGES

Portable, auditable, vendor-neutral.

### 12. LIMITATIONS

Does not measure quality; configs can be wrong or outdated.

### 13. TRADE-OFFS

Neutrality vs convenience of managed APIs.

### 14. COMMON MISTAKES

Comparing token prices across different tokenizers; trusting benchmarks you did not run.

### 15. PERFORMANCE / COST CONSIDERATIONS

Compare cost per *task*, not per token or per parameter.

### 16. SECURITY CONSIDERATIONS

Vendor comparison must include data residency, retention and licence terms.

### 17. INTERVIEW EXPLANATION

*"I compare families by config-derived memory and FLOPs, then by my own evaluation set, and keep an adapter layer so the choice can change; names and APIs are not architecture."*

### 18. RAPID-FIRE ANSWER

Compare by config-derived costs plus your own eval, not vendor APIs.
