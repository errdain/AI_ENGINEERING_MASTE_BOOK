### 1. WHAT IS IT?

Encoder-decoder models read the input with a bidirectional **encoder** and generate the output with a causal **decoder** that attends to the encoder's outputs through **cross-attention**.

### 2. WHY DOES IT EXIST?

Transform tasks (translation, summarisation, structured rewriting) have a clear input and output; the encoder processes the input once and the decoder conditions on it.

### 3. DETAILED EXPLANATION

Three attention types appear: encoder self-attention (full), decoder self-attention (causal), cross-attention (queries from the decoder, keys/values from the encoder output). Cross-attention K/V are computed once and cached.

![Cross-attention mask](figures/02_encoder_decoder_encdec.png)

*Figure: the two right panels are the decoder's causal self-attention and the all-visible cross-attention to source tokens.*

### 4. HOW DOES IT WORK?

1. Encode source once. 2. At each decode step: causal self-attention over the target prefix, cross-attention over the source, FFN. 3. Cache both self-attn K/V (grows) and cross-attn K/V (fixed).

### 5. SIMPLE EXAMPLE

A human interpreter: first listens to the full sentence (encoder), then speaks while glancing back at their notes (cross-attention).

### 6. TECHNICAL EXAMPLE

A T5-base-shaped model (12+12 layers, ~220 M, REVIEW_REQUIRED). The lab adds one cross-attention block (`4d²`) per decoder layer.

### 8. INPUT → PROCESS → OUTPUT

```
source → ENCODER (bidirectional) → memory
target prefix → DECODER (causal) ⇄ cross-attention(memory) → next token
```

### 9. ENTERPRISE USE CASE

Translation, summarisation, text-to-SQL or normalisation pipelines where output quality on a fixed task matters more than open-ended chat.

### 10. AI ENGINEERING CONNECTION

Whisper-style speech recognition and many OCR/document models are encoder-decoder (Tiers 13-14).

### 11. ADVANTAGES

Efficient use of input; strong on conditional generation; modest size for good task quality.

### 12. LIMITATIONS

Two stacks to serve; less natural for long multi-turn chat; fewer large open recent models.

### 13. TRADE-OFFS

Input-reading efficiency vs unified decoder simplicity.

### 14. COMMON MISTAKES

Forgetting the cross-attention cache; assuming it is obsolete.

### 15. PERFORMANCE / COST CONSIDERATIONS

Encoder cost is paid once per input; decoder per generated token.

### 16. SECURITY CONSIDERATIONS

Same as other generators; the source is untrusted input.

### 17. INTERVIEW EXPLANATION

*"Encoder-decoder models encode the input bidirectionally once and decode causally with cross-attention, which fits transform tasks like translation and summarisation."*

### 18. RAPID-FIRE ANSWER

Encoder reads, decoder writes, cross-attention connects them.
