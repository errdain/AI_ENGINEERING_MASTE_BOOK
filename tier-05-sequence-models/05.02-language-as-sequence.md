# 5.2 Language as a sequence

**Metadata** — Tier: 5 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: High · Hands-on: High
Prerequisites: 5.1 Sequential data, 1.31 Probability · Leads to: 5.3 One-hot encoding, 5.10 RNN, Tier 6 Tokenization

> **In plain words**
> To a computer, a sentence is a **list of tokens** (characters, words or word pieces), and the central task is **predicting the next token** given the ones before. That one task, **language modelling**, is how ChatGPT-style models are trained. The simplest language model just **counts** how often each token follows another; recurrent networks and Transformers learn much richer versions of the same idea.

**You need first:** 5.1 Sequential data, 1.31 Probability.

> **Figure 5.2-1 — from text to a prediction**
>
> ```mermaid
> flowchart LR
>     T["'the cat sat'"] --> K["tokens:<br/>the | cat | sat"]
>     K --> I["ids:<br/>7 | 2 | 9"]
>     I --> M["language model"]
>     M --> P["probability of the next token<br/>on | down | …"]

>
> *How to read it:* text is split into tokens, tokens become integer ids, the model reads the ids and outputs a probability for every possible next token. Generation is repeating this: pick a token from the distribution, append it, predict again.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| token | a unit of text: character, word or sub-word |
| vocabulary | the set of all tokens the model knows |
| id | the integer standing for a token |
| language model | assigns probabilities to token sequences |
| n-gram | counting model that looks back `n − 1` tokens |
| perplexity | `exp(average loss)`; "how many choices the model is torn between" |
| `<unk>` | placeholder for unknown tokens |

### 1. What is it?
Treating text as an ordered list of tokens and modelling `P(next token | previous tokens)`.

### 2. Why does it exist?
The chain rule of probability turns the probability of a whole sentence into a product of next-token probabilities: `P(w₁…w_T) = Π P(w_t | w₁…w_{t-1})`. So a good next-token predictor is a model of language, and one training task teaches grammar, facts and style.

### 3. Detailed explanation
- **Tokenization choices.** Characters: tiny vocabulary, long sequences. Words: short sequences, huge vocabulary, unknown words. Sub-words (BPE, Tier 6): a compromise used by modern models.
- **Special tokens.** `<bos>` (start), `<eos>` (end), `<pad>`, `<unk>`.
- **Counting model (bigram).** `P(w | prev) = count(prev, w) / count(prev)`. Add a small smoothing constant to avoid zeros (code ②).
- **Why counting is not enough.** With vocabulary `V` and context length `n`, there are `Vⁿ` contexts; most never occur in training. Neural models share statistical strength by representing words as vectors (5.4).
- **Perplexity.** `exp(cross-entropy)`. A uniform guess over `V` tokens has perplexity `V`. Lower is better (code ②).
- **Generation.** Sample from the predicted distribution (temperature, top-p; Tier 11) and feed the sample back in.
- **Context.** Knowing more previous tokens helps, but only if the model can use them: the topic of Tier 5.
- **Beyond next-token.** Masked language modelling (BERT) predicts hidden tokens from both sides (Tier 8).

### 4. How does it work?
Tokenize → map to ids → feed ids (as vectors) through a model → softmax over the vocabulary → compare with the true next token (cross-entropy) → learn.

### 5. Simple example
Autocomplete on a phone: after "see you" it suggests "soon", "later", "tomorrow" because it has seen those continuations most often.

**By hand.** Corpus: "the cat sat. the cat ran. the dog sat." After "the": cat ×2, dog ×1 → `P(cat | the) = 2/3`, `P(dog | the) = 1/3`.

### 6. Technical example
An LLM computes a probability for each of about 100,000 tokens at every position and is trained to put high probability on the actual next token.

### 7. Code
**① By hand (plain Python).** Tokenize, build a vocabulary, count bigrams.

```python
text = "the cat sat on the mat. the cat ran. the dog sat on the log."
tokens = text.replace(".", " .").split()
vocab = sorted(set(tokens))
ids = {w: i for i, w in enumerate(vocab)}
print("tokens:", tokens[:8], "...")
print("vocabulary size:", len(vocab), "  ids:", {w: ids[w] for w in vocab[:5]}, "...")

counts = {}
for a, b in zip(tokens, tokens[1:]):
    counts.setdefault(a, {}).setdefault(b, 0)
    counts[a][b] += 1
total = sum(counts["the"].values())
print("after 'the':", {w: f"{c}/{total}" for w, c in sorted(counts["the"].items())})
```

```text
tokens: ['the', 'cat', 'sat', 'on', 'the', 'mat', '.', 'the'] ...
vocabulary size: 9   ids: {'.': 0, 'cat': 1, 'dog': 2, 'log': 3, 'mat': 4} ...
after 'the': {'cat': '2/5', 'dog': '1/5', 'log': '1/5', 'mat': '1/5'}
```

**② With NumPy.** A smoothed bigram model and its perplexity.

```python
import numpy as np

train = "the cat sat on the mat . the cat ran . the dog sat on the log . the dog ran .".split()
test = "the cat sat on the log .".split()
vocab = sorted(set(train)); idx = {w: i for i, w in enumerate(vocab)}; V = len(vocab)
C = np.zeros((V, V))
for a, b in zip(train, train[1:]):
    C[idx[a], idx[b]] += 1
P = (C + 0.1) / (C + 0.1).sum(axis=1, keepdims=True)                   # add-0.1 smoothing
loss = -np.mean([np.log(P[idx[a], idx[b]]) for a, b in zip(test, test[1:])])
print(f"bigram cross-entropy {loss:.3f}   perplexity {np.exp(loss):.2f}   (uniform guess over {V} tokens: perplexity {V})")
print("most likely word after 'the':", vocab[int(P[idx['the']].argmax())])
```

```text
bigram cross-entropy 0.865   perplexity 2.37   (uniform guess over 9 tokens: perplexity 9)
most likely word after 'the': cat
```

**③ With PyTorch.** From ids to next-token logits, and the loss.

```python
import torch

torch.manual_seed(0)
vocab = ["<pad>", "the", "cat", "sat", "on", "mat"]
ids = torch.tensor([[1, 2, 3, 4, 1]])                                    # "the cat sat on the"
target = torch.tensor([[2, 3, 4, 1, 5]])                                  # the next token at each position
emb = torch.nn.Embedding(len(vocab), 8)
head = torch.nn.Linear(8, len(vocab))
logits = head(emb(ids))                                                   # a toy model: no memory of earlier tokens yet
loss = torch.nn.functional.cross_entropy(logits.view(-1, len(vocab)), target.view(-1))
print("logits shape (batch, positions, vocabulary):", tuple(logits.shape))
print(f"untrained loss {loss.item():.3f}   ln(vocabulary size) = {torch.log(torch.tensor(float(len(vocab)))).item():.3f}")
```

```text
logits shape (batch, positions, vocabulary): (1, 5, 6)
untrained loss 1.939   ln(vocabulary size) = 1.792
```

### 9. Enterprise use case
Autocomplete, spell correction, code completion, search query suggestion, speech-recognition rescoring.

### 10. AI engineering connection
Pre-training an LLM is exactly next-token prediction at scale; evaluation uses perplexity and downstream tasks (Tier 9, 15).

### 11. Advantages
Self-supervised: raw text provides the labels.

### 12. Limitations
Unseen n-grams; long-range structure; knowledge is only statistical.

### 13. Trade-offs
Larger vocabularies shorten sequences but increase the output layer and rare-token problems.

### 14. Common mistakes
Computing perplexity with different tokenizations across models and comparing them; testing on training text; forgetting special tokens; no smoothing.

### 15. Performance / cost
Output layer cost grows with vocabulary size (batch × positions × V).

### 16. Security
Models memorize rare strings (emails, keys); filter training data (Tier 15).

</details>

### 17. Interview explanation
"Language modelling factorizes a sentence's probability into next-token probabilities. Counting n-grams is the baseline; neural models represent tokens as vectors to generalize. We train with cross-entropy and report perplexity, which is only comparable under the same tokenization."

### 18. Rapid-fire answer
Text → tokens → ids; model `P(next | previous)`; chain rule; train with cross-entropy; perplexity = exp(loss).

### 20. Hands-on exercise
**Goal:** see how context length changes predictability.

1. Build bigram and trigram models on the training text of code ②.
2. Compare perplexity on the test sentence with smoothing 0.1.

<details>
<summary>Show a solution</summary>

```python
import numpy as np
from collections import Counter

train = "the cat sat on the mat . the cat ran . the dog sat on the log . the dog ran . the cat sat on the log .".split()
test = "the cat sat on the log .".split()
vocab = sorted(set(train)); V = len(vocab)

def perplexity(n):
    ctx_counts, pair_counts = Counter(), Counter()
    for i in range(len(train) - n + 1):
        ctx, w = tuple(train[i:i + n - 1]), train[i + n - 1]
        ctx_counts[ctx] += 1; pair_counts[ctx, w] += 1
    losses = []
    for i in range(len(test) - n + 1):
        ctx, w = tuple(test[i:i + n - 1]), test[i + n - 1]
        p = (pair_counts[ctx, w] + 0.1) / (ctx_counts[ctx] + 0.1 * V)
        losses.append(-np.log(p))
    return float(np.exp(np.mean(losses)))

print(f"bigram perplexity : {perplexity(2):.2f}")
print(f"trigram perplexity: {perplexity(3):.2f}")
```

```text
bigram perplexity : 1.92
trigram perplexity: 1.53
```
