# 5.9 FastText

**Metadata** — Tier: 5 · Phase: 1 · Priority: P1 · Difficulty: 2/5 · Interview: Medium · Hands-on: Medium
Prerequisites: 5.5–5.7 Word2Vec · Leads to: 5.10 RNN, Tier 6 sub-word tokenization

> **In plain words**
> Word2Vec and GloVe give every word its own unrelated vector, so a **word never seen in training has no vector at all**, and "run", "running", "runner" do not share anything. **FastText** (Bojanowski et al., 2017) represents a word as **the sum of the vectors of its character pieces** (n-grams), like `<ru`, `run`, `unn`, `nni`, … That way related words share pieces, **misspellings and rare forms get sensible vectors**, and even completely new words can be embedded.

**You need first:** 5.5–5.7 Word2Vec / skip-gram.

> *How to read it:* `<` and `>` mark the word boundaries. With n-grams of length 3, "where" becomes five pieces plus the whole-word token. Each piece has its own learned vector; the word's embedding is their sum. A new word like "wherever" shares pieces (`<wh`, `whe`, `her`, `ere`) with "where", so it gets a good vector for free.

### 1. What is it?
Skip-gram with negative sampling where the "input vector" of a word is `Σ_{g ∈ ngrams(word)} z_g` (plus the word itself if known).

### 2. Why does it exist?
Many languages are morphologically rich (German compounds, Turkish endings, Finnish cases) so the same stem appears in thousands of forms, most of them rare. Real text also contains typos, names and new words. Whole-word vectors handle none of that.

### 3. Detailed explanation
- **N-gram range.** Typically 3 to 6 characters, with `<` and `>` added: "where" → `<wh`, `whe`, `her`, `ere`, `re>`, ... plus the special whole-word token `<where>`.
- **Training.** Same objective as skip-gram (5.7) but the score uses `Σ z_g · u_context` over the word's n-grams.
- **Hashing.** The number of distinct n-grams is huge, so each is hashed into one of ~2 million buckets; collisions are tolerated.
- **OOV words.** Compute the n-grams of the unseen word and sum the vectors of those that exist: a reasonable embedding with no retraining (code ②).
- **Shared pieces mean shared meaning.** "teach", "teacher", "teaching" share `<te`, `tea`, `eac`, `ach`.
- **Typos** like "recieve" still share most pieces with "receive".
- **Cost.** More vectors to sum and store than Word2Vec; training is a bit slower but still fast.
- **Text classification.** FastText also ships a very fast linear classifier using averaged n-gram embeddings.
- **Limitations.** Still static (no context); similar spelling does not imply similar meaning ("bat" the animal vs "bath").
- **Legacy.** The same sub-word idea reappears in BPE tokenization for Transformers (Tier 6).

### 4. How does it work?
Break the word into n-grams; look up or hash each; sum their vectors; use that sum as the word vector in the skip-gram objective.

### 5. Simple example
Understanding a new word from its parts: "unbelievably" is new to you, yet "un-", "believe" and "-ably" tell you what it means.

**By hand.** n-grams (n = 3) of "<cat>": `<ca`, `cat`, `at>` plus `<cat>`. A new word "<cats>" has `<ca`, `cat`, `ats`, `ts>`: it shares `<ca` and `cat` with "cat", so its vector starts close to "cat".

### 6. Technical example
`fasttext.train_unsupervised("corpus.txt", model="skipgram", minn=3, maxn=6)`; `model.get_word_vector("unseenword")` works for any string.

### 7. Code
**① By hand (plain Python).** Character n-grams with boundary markers.

```python
def ngrams(word, n_min=3, n_max=4):
    w = f"<{word}>"
    return [w[i:i + n] for n in range(n_min, n_max + 1) for i in range(len(w) - n + 1)]

print("where :", ngrams("where", 3, 3))
a, b = set(ngrams("teaching")), set(ngrams("teacher"))
print("pieces shared by 'teaching' and 'teacher':", sorted(a & b))
print("overlap (Jaccard):", round(len(a & b) / len(a | b), 2), "   with 'banana':", round(len(a & set(ngrams('banana'))) / len(a | set(ngrams('banana'))), 2))
```

```text
where : ['<wh', 'whe', 'her', 'ere', 're>']
pieces shared by 'teaching' and 'teacher': ['<te', '<tea', 'ach', 'eac', 'each', 'tea', 'teac']
overlap (Jaccard): 0.33    with 'banana': 0.0
```

**② With NumPy.** An unseen word gets a vector from its pieces.

```python
import numpy as np, zlib

def ngrams(word, n_min=3, n_max=5):
    w = f"<{word}>"
    return [w[i:i + n] for n in range(n_min, n_max + 1) for i in range(len(w) - n + 1)]

B, d = 5000, 16
rng = np.random.default_rng(0)
Z = rng.normal(0, 0.1, (B, d))
bucket = lambda g: zlib.crc32(g.encode()) % B
vec = lambda word: sum(Z[bucket(g)] for g in ngrams(word))
# pretend the table was trained so that related spellings share pieces: here we just check the geometry of the shared pieces
cos = lambda a, b: float(a @ b / (np.linalg.norm(a) * np.linalg.norm(b)))
print("cosine(teaching, teacher)  :", round(cos(vec("teaching"), vec("teacher")), 2), "  (shared pieces)")
print("cosine(teaching, banana)   :", round(cos(vec("teaching"), vec("banana")), 2), "  (no shared pieces)")
print("cosine(receive, recieve)   :", round(cos(vec("receive"), vec("recieve")), 2), "  (a typo still shares pieces)")
```

```text
cosine(teaching, teacher)  : 0.69   (shared pieces)
cosine(teaching, banana)   : -0.07   (no shared pieces)
cosine(receive, recieve)   : 0.42   (a typo still shares pieces)
```

**③ With PyTorch.** `nn.EmbeddingBag` sums the n-gram vectors of each word.

```python
import zlib
import torch

def ngrams(word, n_min=3, n_max=5):
    w = f"<{word}>"
    return [w[i:i + n] for n in range(n_min, n_max + 1) for i in range(len(w) - n + 1)]

B = 5000
bag = torch.nn.EmbeddingBag(B, 16, mode="sum")
def word_vector(word):
    ids = torch.tensor([[zlib.crc32(g.encode()) % B for g in ngrams(word)]])
    return bag(ids)[0]

torch.manual_seed(0)
print("vector shape for a known word  :", tuple(word_vector("running").shape))
print("vector shape for an unseen word:", tuple(word_vector("zorbification").shape), "-> any string gets a vector")
print("number of n-grams: running", len(ngrams("running")), "  zorbification", len(ngrams("zorbification")))
```

```text
vector shape for a known word  : (16,)
vector shape for an unseen word: (16,) -> any string gets a vector
number of n-grams: running 18   zorbification 36
```

### 8. Input → Process → Output
`word → character n-grams → hashed lookups → sum of vectors → word embedding (even for unseen words)`

### 9. Enterprise use case
Search over noisy text (typos, product codes), morphologically rich languages, and fast text classification.

### 10. AI engineering connection
Sub-word tokenizers (BPE, WordPiece; Tier 6) apply the same insight to Transformers.

### 11. Advantages
Handles OOV words, typos and rare forms; good for rich morphology.

### 12. Limitations
Larger tables; spelling similarity is not meaning; static vectors.

### 13. Trade-offs
Shorter n-grams are robust but ambiguous; longer ones are specific but sparse.

### 14. Common mistakes
Forgetting boundary markers; too few hash buckets (collisions); assuming similar spelling means similar meaning.

### 15. Performance / cost
More lookups per word; bucket table size dominates memory.

### 16. Security
Typo-robust embeddings can map adversarial misspellings to the original word, which helps and hurts moderation systems.

</details>

### 17. Interview explanation
"FastText embeds a word as the sum of its character n-gram vectors (plus the word itself), trained with the skip-gram objective. Because words share n-grams, rare words, typos and unseen words get meaningful vectors, which is valuable for morphologically rich languages; the cost is a larger parameter table."

### 18. Rapid-fire answer
Word vector = sum of character n-gram vectors (hashed); skip-gram objective; handles OOV and typos; ancestor of sub-word tokenization.

```python
def count(word, n_min=3, n_max=6):
    L = len(word) + 2                                   # with < and >
    return sum(max(0, L - n + 1) for n in range(n_min, n_max + 1))

print("sequence:", count("sequence"), "n-grams")
print("a 20-letter word:", count("a" * 20), "n-grams")
```

```text
sequence: 26 n-grams
a 20-letter word: 74 n-grams
```
