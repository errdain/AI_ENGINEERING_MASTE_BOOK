# 5.7 Skip-gram

**Metadata** — Tier: 5 · Phase: 1 · Priority: P1 · Difficulty: 2/5 · Interview: High · Hands-on: Medium
Prerequisites: 5.5 Word2Vec, 5.6 CBOW · Leads to: 5.8 GloVe, 5.9 FastText

> **In plain words**
> **Skip-gram** is the other Word2Vec game, the mirror image of CBOW: given **one word**, predict **each of its neighbours**. From "sat" guess "the", "cat", "on", "the". Because every (centre, neighbour) pair is its own training example, rare words get many more updates, so skip-gram usually gives better vectors for **rare words** and works well on smaller data, at the price of being slower.

**You need first:** 5.5 Word2Vec, 5.6 CBOW.

> *How to read it:* one input, many targets. A window of size 2 gives up to four pairs per centre word. The same embedding of "sat" is trained by all of them, which is why skip-gram makes better use of each occurrence of a rare word.

### 1. What is it?
Word2Vec variant with input = centre word and output = a context word, applied to every context word in the window.

### 2. Why does it exist?
Skip-gram gives each rare word as many training signals as it has neighbours, instead of being averaged away in a bag (CBOW). Empirically it gives better embeddings for infrequent words.

### 3. Detailed explanation
- **Objective.** Maximize `Σ_t Σ_{-w≤j≤w, j≠0} log P(w_{t+j} | w_t)`.
- **Softmax version.** `P(o | c) = exp(u_o·v_c) / Σ_{w=1}^{V} exp(u_w·v_c)`. Exact but costs `O(V d)` per pair (code ②).
- **Negative sampling** reduces the cost to `O((k+1) d)` (5.5).
- **Hierarchical softmax** (a tree over the vocabulary, cost `O(log V)`) is another speed-up.
- **Dynamic windows.** Drawing the window size randomly in `1..w` weights nearer words more heavily.
- **Subsampling.** Discard word `w` with probability `1 − sqrt(t / f(w))` (`f` = frequency), so "the" is seen less often than its raw count says.
- **Number of pairs.** `≈ 2w` pairs per token (code ①), so skip-gram trains `≈ 2w` times as many updates as CBOW: slower, richer.
- **The learned geometry.** Related words end up with high dot products; for the shifted-PMI view see 5.5 and 5.8.
- **Limits.** Still static, still no subword info (5.9).

### 4. How does it work?
For each position, for each neighbour: score the true pair against negatives (or all words), compute the gradient, update the two vectors.

### 5. Simple example
A cocktail-party game: someone says one word ("sat") and you guess every word that tends to be near it.

**By hand.** Text of `T` tokens, window `w = 2`: roughly `4T` pairs; with `T = 1,000,000` that is about 4 million updates per epoch.

### 6. Technical example
`gensim.models.Word2Vec(sentences, sg=1, negative=5, window=5, vector_size=300)`.

**② With NumPy.** The exact softmax skip-gram on a toy corpus.

```python
import numpy as np

data = [s.split() for s in ("the cat chased the mouse", "the dog chased the cat", "the cat liked the fish", "the dog liked the bone") * 5]
vocab = sorted({w for s in data for w in s}); idx = {w: i for i, w in enumerate(vocab)}; V = len(vocab)
pairs = [(idx[s[i]], idx[s[j]]) for s in data for i in range(len(s)) for j in range(max(0, i - 2), min(len(s), i + 3)) if j != i]
rng = np.random.default_rng(0)
E, U = rng.normal(0, 0.1, (V, 6)), rng.normal(0, 0.1, (V, 6))
softmax = lambda z: np.exp(z - z.max()) / np.exp(z - z.max()).sum()
for epoch in range(60):
    loss = 0.0
    for c, o in pairs:
        p = softmax(U @ E[c]); loss -= np.log(p[o])
        dz = p.copy(); dz[o] -= 1
        dv = U.T @ dz; U -= 0.05 * np.outer(dz, E[c]); E[c] -= 0.05 * dv
    if epoch in (0, 59):
        print(f"epoch {epoch + 1:>2}: average loss per pair {loss / len(pairs):.3f}")
En = E / np.linalg.norm(E, axis=1, keepdims=True)
print("cat ~ dog:", round(float(En[idx["cat"]] @ En[idx["dog"]]), 2), "   cat ~ chased:", round(float(En[idx["cat"]] @ En[idx["chased"]]), 2) + 0.0)
```

```text
epoch  1: average loss per pair 2.051
epoch 60: average loss per pair 1.444
cat ~ dog: 0.98    cat ~ chased: 0.0
```

**③ With PyTorch.** Skip-gram with a full softmax using `nn.Embedding` + `nn.Linear`.

```python
import torch

data = [s.split() for s in ("the cat chased the mouse", "the dog chased the cat", "the cat liked the fish", "the dog liked the bone") * 5]
vocab = sorted({w for s in data for w in s}); idx = {w: i for i, w in enumerate(vocab)}; V = len(vocab)
pairs = torch.tensor([(idx[s[i]], idx[s[j]]) for s in data for i in range(len(s)) for j in range(max(0, i - 2), min(len(s), i + 3)) if j != i])
torch.manual_seed(0)
emb, out = torch.nn.Embedding(V, 6), torch.nn.Linear(6, V, bias=False)
opt = torch.optim.Adam(list(emb.parameters()) + list(out.parameters()), lr=0.05)
for epoch in range(100):
    loss = torch.nn.functional.cross_entropy(out(emb(pairs[:, 0])), pairs[:, 1]); opt.zero_grad(); loss.backward(); opt.step()
E = torch.nn.functional.normalize(emb.weight.detach(), dim=1)
print(f"final loss {loss.item():.3f}   (the best possible is above 0: a centre word has several likely neighbours)")
print("cat ~ dog:", round((E[idx['cat']] @ E[idx['dog']]).item(), 2))
```

```text
final loss 1.297   (the best possible is above 0: a centre word has several likely neighbours)
cat ~ dog: 0.67
```

### 9. Enterprise use case
Embeddings for specialized, smaller corpora where rare terms matter (product codes, medical terms).

### 10. AI engineering connection
The "predict context from a token" idea reappears in contrastive and autoregressive training.

### 11. Advantages
Good rare-word vectors; works on smaller data.

### 12. Limitations
Slower than CBOW; no word order inside the window; static vectors.

### 13. Trade-offs
Quality of rare words versus training time.

### 14. Common mistakes
Full softmax on a large vocabulary; forgetting subsampling; tiny windows for topical tasks.

### 15. Performance / cost
Pairs ≈ `2w` per token; use negative sampling.

### 16. Security
As Word2Vec.

</details>

### 17. Interview explanation
"Skip-gram predicts each context word from the centre word. It produces about 2w training pairs per token, which makes it slower than CBOW but better for rare words. With a large vocabulary I use negative sampling or hierarchical softmax instead of the exact softmax."

### 18. Rapid-fire answer
Centre → each context word; ~2w pairs per token; better for rare words; negative sampling or hierarchical softmax for speed.
