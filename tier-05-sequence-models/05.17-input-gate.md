# 5.17 Input gate

**Metadata** — Tier: 5 · Phase: 1 · Priority: P0 · Difficulty: 3/5 · Interview: Medium · Hands-on: High
Prerequisites: 5.15 Cell state, 5.16 Forget gate · Leads to: 5.18 Output gate

> **In plain words**
> The **input gate** decides **how much new information to write** into the long-term memory. The cell first proposes new content (the *candidate*, a `tanh` between −1 and 1); the input gate, a number between 0 and 1 for each memory cell, scales how much of that proposal is actually added. With the gate closed, the memory ignores whatever is happening now.

**You need first:** 5.15 Cell state, 5.16 Forget gate.

> **Figure 5.17-1 — the write path**
>
> ```mermaid
> flowchart LR
>     X["xₜ, h(t−1)"] --> G["candidate gₜ = tanh(…)<br/>what could be written"]
>     X --> I["input gate iₜ = σ(…)<br/>how much to write"]
>     G --> P["gₜ × iₜ"]
>     I --> P
>     P --> A["added to the memory:<br/>cₜ = fₜ·c(t−1) + iₜ·gₜ"]
> ```
>
> *How to read it:* two separate computations from the same inputs: *what* to write (candidate) and *how much* to write (gate). Splitting them lets the model see a distracting input yet choose not to store it. In Figure 5.16-1 the average input gate stays moderate: cells write at some steps (the symbol to remember) and not at others.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| input gate `iₜ` | how much of the candidate to write, in (0, 1) |
| candidate `gₜ` | proposed content, in (−1, 1) |
| write | add `iₜ ⊙ gₜ` to the cell state |
| selective storage | store only what matters |
| distractor | an input that should be ignored |
| `W_i`, `W_g` | weights of the input gate and the candidate |
| overwrite | combine a closed forget gate with an open input gate |

### 1. What is it?
`iₜ = σ(W_i [xₜ, h_{t-1}] + b_i)` and `gₜ = tanh(W_g [xₜ, h_{t-1}] + b_g)`; the write is `iₜ ⊙ gₜ`.

### 2. Why does it exist?
In the first LSTM the memory needed protection from irrelevant inputs: if every input were written, the cell would be flooded and old information would be corrupted. The gate learns to open only when the input matters ("input weight conflict" in the original paper; REVIEW_REQUIRED).

### 3. Detailed explanation
- **Candidate versus gate.** The candidate is signed (it can increase or decrease the memory); the gate is non-negative and only scales.
- **Combined with forget:** *overwrite* = forget ≈ 0 and input ≈ 1; *hold* = forget ≈ 1 and input ≈ 0; *accumulate* = both ≈ 1; *clear* = both ≈ 0 (code ① prints this table).
- **Selectivity.** In the memory task of 5.14 the model must write the first symbol and ignore the next 20; the input gate learns to be open at step 0 and mostly closed afterwards.
- **Coupled variant.** Some designs set `i = 1 − f` (one gate controls both), which is also how the GRU works (5.19).
- **Gradient.** `∂cₜ/∂gₜ = iₜ`: a closed input gate also blocks gradient into the candidate path for that step.
- **Saturation.** As for all gates, saturated sigmoids learn slowly.
- **Initialization.** Bias 0 is typical (gate ≈ 0.5); negative biases make a cell reluctant to write at first.
- **Interpretability.** Visualizing `i` over time shows where the model decides information is worth storing.
- **Shared inputs.** All gates read the same `[xₜ, h_{t-1}]`; they differ only in their weights.

### 4. How does it work?
Compute the proposal and the gate from the same inputs; multiply; add to the (already forgotten-from) cell state.

### 5. Simple example
A note-taker at a meeting with a pen (candidate: what could be noted) and a "worth noting?" filter (input gate). Filler remarks pass through the room without touching the notebook.

**By hand.** Candidate `g = 0.8`. Input gate `i = 0.9` → writes `0.72`; `i = 0.1` → writes `0.08`.

### 6. Technical example
For named-entity tagging, cells that store "currently inside a person name" open their input gates at capitalized words and close them for ordinary words (illustrative; REVIEW_REQUIRED).

### 7. Code
**① By hand (plain Python).** The four gate combinations.

```python
c_old, g = 1.0, 0.5
print(f"{'situation':<12}{'forget':>8}{'input':>7}{'new cell state':>16}")
for name, f, i in (("hold", 1, 0), ("overwrite", 0, 1), ("accumulate", 1, 1), ("clear", 0, 0)):
    print(f"{name:<12}{f:>8}{i:>7}{f * c_old + i * g:>16.2f}")
```

**② With NumPy.** An input gate that writes only when a flag says so (hand-set weights).

```python
import numpy as np

sig = lambda z: 1 / (1 + np.exp(-z))
# input x = [value, write_flag]; the gate looks at the flag, the candidate at the value
stream = [(0.9, 1), (0.3, 0), (-0.8, 0), (0.1, 0), (-0.6, 1), (0.7, 0)]
c = 0.0
for t, (value, flag) in enumerate(stream, start=1):
    i = sig(12 * flag - 6)                                    # ≈ 1 if flag else ≈ 0
    g = np.tanh(2 * value)
    c = c + i * g                                             # forget gate fixed at 1 to isolate the input gate
    print(f"t={t}  value={value:+.1f}  flag={flag}  input gate={i:.2f}  cell state={c:+.2f}")
```

```text
t=1  value=+0.9  flag=1  input gate=1.00  cell state=+0.94
t=2  value=+0.3  flag=0  input gate=0.00  cell state=+0.95
t=3  value=-0.8  flag=0  input gate=0.00  cell state=+0.94
t=4  value=+0.1  flag=0  input gate=0.00  cell state=+0.94
t=5  value=-0.6  flag=1  input gate=1.00  cell state=+0.11
t=6  value=+0.7  flag=0  input gate=0.00  cell state=+0.11
```

**③ With PyTorch.** Train a small LSTM on "output the token right after the marker", then read its real input gate.

```python
import torch
from torch import nn

torch.manual_seed(0)
V, T, H = 6, 12, 24                                            # tokens 0-2 are special (2 = marker), 3-5 are ordinary
emb, lstm, head = nn.Embedding(V, 8), nn.LSTM(8, H, batch_first=True), nn.Linear(H, 3)
for name, p in lstm.named_parameters():
    if name.startswith("bias"):
        p.data[H:2 * H] = 1.0                                  # forget gate starts open
opt = torch.optim.Adam([*emb.parameters(), *lstm.parameters(), *head.parameters()], lr=0.01)

def batch(n):
    x = torch.randint(3, V, (n, T)); pos = torch.randint(0, T - 1, (n,))
    x[torch.arange(n), pos] = 2                                # put the marker somewhere
    return x, x[torch.arange(n), pos + 1] - 3, pos             # target: the token right after it

for _ in range(1000):
    x, y, _ = batch(64)
    loss = nn.functional.cross_entropy(head(lstm(emb(x))[0][:, -1]), y); opt.zero_grad(); loss.backward(); opt.step()

x, y, pos = batch(500)
with torch.no_grad():
    print("accuracy (chance 0.33):", round((head(lstm(emb(x))[0][:, -1]).argmax(1) == y).float().mean().item(), 2))
    E, W, U, b = emb(x), lstm.weight_ih_l0, lstm.weight_hh_l0, lstm.bias_ih_l0 + lstm.bias_hh_l0
    h = c = torch.zeros(500, H); gate = []
    for t in range(T):                                         # the LSTM equations, step by step, so we can look at the gates
        i, f, g, o = (E[:, t] @ W.T + h @ U.T + b).chunk(4, dim=1)
        c = torch.sigmoid(f) * c + torch.sigmoid(i) * torch.tanh(g); h = torch.sigmoid(o) * torch.tanh(c)
        gate.append(torch.sigmoid(i).mean(1))                  # average input gate over the memory cells, per example
    gate = torch.stack(gate, 1)                                # (examples, time)
    steps = torch.arange(T)[None]
    just_after_marker = (steps == (pos + 1)[:, None])
    print(f"mean input gate at the step right after the marker: {gate[just_after_marker].mean().item():.2f}")
    print(f"mean input gate at all other steps               : {gate[~just_after_marker].mean().item():.2f}")
```

```text
accuracy (chance 0.33): 1.0
mean input gate at the step right after the marker: 0.89
mean input gate at all other steps               : 0.49
```

### 8. Input → Process → Output
`xₜ, h(t−1) → candidate gₜ and gate iₜ → write iₜ·gₜ into the cell state`

### 9. Enterprise use case
Event-sequence models that should store only significant events (alarms, purchases) and ignore routine ones.

### 10. AI engineering connection
Selective writing to memory is the intuition behind selective state-space models and memory-augmented agents (Tier 12, 19).

### 11. Advantages
Protects memory from noise; separates "what" from "how much".

### 12. Limitations
Extra parameters; saturation; can ignore useful inputs if poorly trained.

### 13. Trade-offs
A conservative gate protects memory but may miss information.

### 14. Common mistakes
Confusing the candidate with the gate; expecting the gate to be binary; averaging gates and over-interpreting.

### 15. Performance / cost
One of the four gate computations.

### 16. Security
No direct issue.

### 17. Interview explanation
"The input gate scales how much of the candidate content, a tanh of the current input and previous output, is added to the cell state. It lets the LSTM ignore irrelevant inputs. Combined with the forget gate it implements hold, overwrite, accumulate or clear."

### 18. Rapid-fire answer
`i = σ(W[x,h]+b)`, candidate `g = tanh(…)`, write `i⊙g`; protects memory from irrelevant input; with forget gate: hold / overwrite / accumulate / clear.

import math
sig = lambda z: 1 / (1 + math.exp(-z))
stream = [(0.4, 0), (0.9, 1), (0.1, 0), (0.2, 0), (-0.5, 1), (0.3, 0)]     # (value, flag)
