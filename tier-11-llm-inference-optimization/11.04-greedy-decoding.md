### 1. WHAT IS IT?

**Greedy decoding** always picks the highest-probability token: `x_t = argmax_i p_i`.

### 2. WHY DOES IT EXIST?

It is the simplest, cheapest and (nearly) deterministic rule, ideal when there is one right answer.

### 3. DETAILED EXPLANATION

Equivalent to temperature -> 0 and to top-k = 1. Good for extraction, classification, SQL and code with tests; prone to repetition and blandness in open-ended text because it can lock into a locally likely loop. It is not guaranteed to find the highest-probability *sequence* (see [11.9 Beam search](11.09-beam-search.md)).

### 4. HOW DOES IT WORK?

Compute logits, take `argmax`, append, repeat. No sampling, no random numbers.

### 5. SIMPLE EXAMPLE

Always ordering the most popular dish regardless of mood.

### 6. TECHNICAL EXAMPLE

A JSON-extraction pipeline runs greedy with `max_new_tokens` and a stop on the closing brace to get stable, parseable output.

### 7. CODE

```python
from decoding import generate
from tiny_gpt import TinyGPT
import torch
torch.manual_seed(0)
m = TinyGPT().eval()
print(generate(m, [1, 2, 3], 8, temperature=0))   # deterministic
```

### 8. INPUT → PROCESS → OUTPUT

```
logits -> argmax -> token
```

### 9. ENTERPRISE USE CASE

Data extraction, classification, routing and tool-call generation commonly default to greedy or very low temperature.

### 10. AI ENGINEERING CONNECTION

Needed for reproducible evals, unit tests of prompts, and any pipeline that parses output.

### 11. ADVANTAGES

Deterministic (barring float effects), cheap, easy to debug.

### 12. LIMITATIONS

Repetitive loops, bland text, can miss better overall sequences.

### 13. TRADE-OFFS

Predictability vs diversity and creativity.

### 14. COMMON MISTAKES

Assuming greedy is bit-identical across hardware/batch sizes; using greedy for creative text and blaming the model for loops.

### 15. PERFORMANCE / COST CONSIDERATIONS

Cheapest rule: no sampling overhead, no extra sequences.

### 16. SECURITY CONSIDERATIONS

Determinism makes outputs reproducible, which helps audits; it does not make outputs safe.

### 17. INTERVIEW EXPLANATION

"Greedy picks the most likely token at every step. It is deterministic and cheap and great for extraction or code with tests, but in open-ended text it tends to loop or be generic, and it can miss a better full sequence that beam search or sampling might find."

### 18. RAPID-FIRE ANSWER

Greedy = argmax each step; same as temperature 0 or top-k 1.

### 19. INTERVIEW QUESTIONS

**Basic.** What is greedy decoding? **Intermediate.** Is greedy optimal for sequence probability? (No.) **Advanced.** Why can greedy differ across runs? (Float non-determinism.) **Scenario.** A summariser loops in one phrase; options? (Repetition penalty, sampling with top-p, or beam with length handling.)

### 20. HANDS-ON EXERCISE

Run `generate(..., temperature=0)` twice and confirm identical outputs; then change one prompt token and compare.
