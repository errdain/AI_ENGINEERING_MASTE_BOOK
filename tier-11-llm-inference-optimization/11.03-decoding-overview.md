### 1. WHAT IS IT?

A **decoding strategy** (decoding rule) maps the logit vector for the next position to one chosen token. This overview classifies the rules and fixes the order in which the lab applies them.

### 2. WHY DOES IT EXIST?

The model only produces a distribution; something must turn it into a concrete token. Different tasks need different behaviour: extraction wants determinism, creative writing wants variety, translation wants high-likelihood sequences.

### 3. DETAILED EXPLANATION

Three families:
- **Deterministic:** greedy ([11.4 Greedy decoding](11.04-greedy-decoding.md)), beam search ([11.9 Beam search](11.09-beam-search.md)).
- **Stochastic:** temperature ([11.5 Temperature](11.05-temperature.md)), top-k ([11.6 Top-k sampling](11.06-top-k-sampling.md)), top-p / nucleus ([11.7 Top-p sampling](11.07-top-p-sampling.md)), min-p.
- **Constrained:** penalties ([11.8 Repetition/frequency penalties](11.08-repetition-frequency-penalties.md)), stop rules ([11.10 Stop sequences](11.10-stop-sequences.md)), grammar/JSON masks (later tiers).

Settings must be **pinned** for evals to be comparable, and the order of operations matters; libraries differ, so always read yours (REVIEW_REQUIRED per library).

### 4. HOW DOES IT WORK?

Lab order (`lab/decoding.py`): **repetition penalty -> temperature -> top-k -> top-p -> (min-p) -> renormalise -> sample**. `temperature == 0` short-circuits to argmax.

### 5. SIMPLE EXAMPLE

Choosing a dish: greedy always orders the top menu item; sampling rolls dice weighted by how much you like each item; top-p ignores dishes you would never order.

### 6. TECHNICAL EXAMPLE

JSON extraction: greedy plus a token cap plus a stop sequence. Marketing copy: temperature about 0.8-1.0 with top-p about 0.9 for variety (starting points, not rules).

### 7. CODE

```python
import torch
from decoding import sample_next

logits = torch.tensor([3.0, 2.0, 1.0, 0.0, -1.0])
print(sample_next(logits, temperature=0))                               # greedy -> 0
g = torch.Generator().manual_seed(0)
print(sample_next(logits, temperature=0.8, top_p=0.9, generator=g))     # typical chat setting
```

See [`lab/decoding.py`](lab/decoding.py).

### 8. INPUT → PROCESS → OUTPUT

```
logits -> [penalties] -> [/T] -> [top-k] -> [top-p] -> [min-p] -> softmax -> {argmax | sample}
```

### 9. ENTERPRISE USE CASE

Platform teams expose a small, vetted set of presets (deterministic, balanced, creative) rather than raw knobs, and pin them per use case.

### 10. AI ENGINEERING CONNECTION

Evals, self-consistency, best-of-N and structured output all depend on explicit decoding settings.

### 11. ADVANTAGES

Cheap, orthogonal controls over quality, diversity and determinism with no retraining.

### 12. LIMITATIONS

Settings interact; no universal best values; determinism is not bit-exact across hardware and batch sizes.

### 13. TRADE-OFFS

Determinism vs diversity; quality vs cost (beam search and best-of-N multiply compute).

### 14. COMMON MISTAKES

- Setting both top-k and top-p without knowing the order.
- Changing temperature and top-p together, so behaviour is hard to reason about.
- Expecting temperature 0 to be bit-identical across GPUs and batch sizes (floating-point non-determinism).

### 15. PERFORMANCE / COST CONSIDERATIONS

Filtering costs are tiny next to the forward pass; the real cost is in extra sequences (beam, best-of-N).

### 16. SECURITY CONSIDERATIONS

Decoding parameters are not a safety control; never rely on low temperature to prevent harmful outputs. Validate and clamp user-supplied settings.

### 17. INTERVIEW EXPLANATION

"Decoding is the policy that turns the model's distribution into a token. Deterministic rules like greedy and beam find likely text, stochastic ones like temperature and top-p sample for variety, and constrained ones restrict what is allowed. I pick based on the task and pin the settings so results are reproducible."

### 18. RAPID-FIRE ANSWER

Decoding rules convert logits to tokens: deterministic, stochastic or constrained, applied in a defined order.
