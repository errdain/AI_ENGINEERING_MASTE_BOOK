### 1. WHAT IS IT?

**Tokens per second (TPS)** is a rate of token generation: either **per-user** (about `1/ITL`) or **system** throughput (tokens/s summed over all concurrent users).

### 2. WHY DOES IT EXIST?

Per-user TPS describes experience; system TPS describes capacity and cost.

### 3. DETAILED EXPLANATION

Always state which one you mean, the batch/concurrency, and the prompt and output lengths: TPS comparisons across different workloads are meaningless. Batching raises system TPS while lowering per-user TPS ([11.19 Batching](11.19-batching.md), [11.43 Throughput](11.43-throughput.md)).

### 4. HOW DOES IT WORK?

Per-user: `N_out / (t_end - t_first)` (or `1/ITL`). System: `sum(output tokens) / wall time`.

### 5. SIMPLE EXAMPLE

Words per minute for one speaker vs words per minute for a whole panel.

### 6. TECHNICAL EXAMPLE

Benchmark reports show tokens/s at several concurrency levels; the lab's decoding timings (greedy 725, T=0.8 604 tok/s) are CPU Python overhead and not a ranking.

### 7. CODE

```python
def tps(n_tokens, seconds): return n_tokens / seconds
print(tps(256, 4.0))                    # per-user rate
print(tps(8 * 256, 5.0))                # system rate at batch 8: higher total, lower per-user
```

### 8. INPUT → PROCESS → OUTPUT

```
tokens produced / time window -> per-user TPS or system TPS
```

### 9. ENTERPRISE USE CASE

Capacity plans use system TPS at SLO-compliant latency.

### 10. AI ENGINEERING CONNECTION

Cost per million tokens is derived from system TPS ([11.45 Inference cost](11.45-inference-cost.md)).

### 11. ADVANTAGES

Simple and comparable when workload is fixed.

### 12. LIMITATIONS

Ambiguous without context.

### 13. TRADE-OFFS

Per-user speed vs system throughput.

### 14. COMMON MISTAKES

Mixing per-user and system numbers; ignoring prompt/output mix.

### 15. PERFORMANCE / COST CONSIDERATIONS

Higher system TPS at the same GPU cost lowers cost per token.

### 16. SECURITY CONSIDERATIONS

None specific.

### 17. INTERVIEW EXPLANATION

"TPS is tokens per second. Per-user it's about 1 over ITL; for the system it's total tokens across all users. I always quote both with the concurrency and sequence lengths, because batching trades one for the other."

### 18. RAPID-FIRE ANSWER

Per-user TPS ~ 1/ITL; system TPS = total tokens/s across users.
