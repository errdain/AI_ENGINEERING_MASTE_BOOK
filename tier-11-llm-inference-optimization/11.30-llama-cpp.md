### 1. WHAT IS IT?

**llama.cpp** is an open-source C/C++ LLM inference engine, CPU-first with several GPU backends, that loads GGUF models. (Concept-level description — `REVIEW_REQUIRED`; check the project README for current features and binary names.)

### 2. WHY DOES IT EXIST?

It made LLMs usable on laptops, phones and servers without Python stacks or datacenter GPUs, with minimal dependencies and heavy use of quantization.

### 3. DETAILED EXPLANATION

- Supports quantized formats ([11.29 GGUF](11.29-gguf.md)), CPU SIMD kernels and GPU offload of some or all layers (`REVIEW_REQUIRED` for backends).
- Includes a CLI and an HTTP server with an OpenAI-style API, and library bindings (`REVIEW_REQUIRED`; binary names have changed over versions).
- Context length, batch size and thread count are runtime knobs; KV cache lives in RAM/VRAM and can itself be quantized (`REVIEW_REQUIRED`).
- Designed first for single-user latency; multi-user serving exists but is not its main design point.

### 4. HOW DOES IT WORK?

Load GGUF (mmap) ─► tokenize ─► prefill in batches ─► decode loop with KV cache, sampling ([11.3 Decoding overview](11.03-decoding-overview.md)) ─► detokenize/stream.

### 5. SIMPLE EXAMPLE

A pocket calculator for language: small, runs anywhere, not a datacenter.

### 6. TECHNICAL EXAMPLE

Run an 8B Q4 model on a laptop CPU at a handful to a few dozen tokens/s depending on memory bandwidth (`REVIEW_REQUIRED`; bandwidth-bound just like [11.39 Memory bandwidth](11.39-memory-bandwidth.md) predicts).

### 7. CODE

```bash
# not executed in this book's tests; flags/binary names REVIEW_REQUIRED
llama-cli -m ./model-Q4_K_M.gguf -p "Explain KV cache in one sentence." -n 64 --temp 0.7
llama-server -m ./model-Q4_K_M.gguf --port 8080 --host 127.0.0.1   # bind to localhost
```
The memory-bound estimate you can check with the lab: tokens/s ≲ memory bandwidth ÷ model bytes (e.g. 50 GB/s ÷ 4.5 GB ≈ 11 tok/s, illustrative).

### 8. INPUT → PROCESS → OUTPUT

```
GGUF file ─► llama.cpp runtime ─► (CPU threads / GPU layers) ─► tokens ─► CLI or HTTP
```

### 9. ENTERPRISE USE CASE

Offline/air-gapped deployments, desktop apps and edge devices where no GPU server is available.

### 10. AI ENGINEERING CONNECTION

Foundation of many local-LLM tools (Ollama builds on this lineage — `REVIEW_REQUIRED`); useful for prototyping agents without API cost.

### 11. ADVANTAGES

- Minimal dependencies; portable; good quantization support; offline.

### 12. LIMITATIONS

- Lower throughput for many users; features trail GPU servers; tuning needed.

### 13. TRADE-OFFS

Portability and simplicity vs peak GPU throughput.

### 14. COMMON MISTAKES

- Benchmarking laptop speed and extrapolating to production concurrency. - Exposing the server on 0.0.0.0 without auth. - Ignoring the context-length memory cost.

### 15. PERFORMANCE / COST CONSIDERATIONS

Decode speed ≈ bandwidth ÷ bytes per token; offloading some layers to GPU speeds those layers.

### 16. SECURITY CONSIDERATIONS

Bind to localhost or add auth/TLS; keep up to date; models can leak prompts via logs.

### 17. INTERVIEW EXPLANATION

"llama.cpp is a lightweight C++ engine that runs quantized GGUF models on CPUs and many GPUs. It's ideal for local and offline use; for many concurrent users on GPUs you would typically use a server engine such as vLLM."

### 18. RAPID-FIRE ANSWER

llama.cpp: portable C++ runtime for quantized GGUF models, optimized for local single-user use.
