### 1. WHAT IS IT?

**Prefix caching** reuses the KV cache of a shared token prefix (system prompt, few-shot examples, a long document) across requests, so prefill for that prefix is skipped.

### 2. WHY DOES IT EXIST?

Many requests start with identical text. Recomputing identical K/V wastes compute and delays the first token.

### 3. DETAILED EXPLANATION

- Works only if the prefix matches **exactly token for token** from the start; so put static content first and per-user content last.
- Engines store KV in blocks keyed by a hash of the prefix tokens; matching blocks are shared (copy-on-write, see [11.21 PagedAttention](11.21-pagedattention.md)).
- Effect: TTFT and prefill cost for the cached part drop to about zero; decode is unchanged.
- Providers' "prompt caching" features are the hosted version (pricing and behaviour REVIEW_REQUIRED).

### 4. HOW DOES IT WORK?

1. Split the prompt into fixed-size token blocks.
2. Hash each block together with the hash of all blocks before it.
3. Look up each hash; reuse every leading block that hits.
4. Prefill only the remaining tokens, then register new blocks.

### 5. SIMPLE EXAMPLE

A restaurant that pre-chops onions every morning: customers' orders start after the shared prep is done.

### 6. TECHNICAL EXAMPLE

A support bot with a 3,000-token system prompt and few-shot examples: only the customer message is prefilled per request.

### 7. CODE

```python
import hashlib

def block_hashes(tokens, block=4):
    """Chained hashes of full blocks: a block's hash covers the whole prefix before it."""
    out, prev = [], b""
    for i in range(0, len(tokens) - len(tokens) % block, block):
        prev = hashlib.sha256(prev + repr(tokens[i:i + block]).encode()).digest()
        out.append(prev)
    return out

cache = set()
def cached_blocks(tokens):
    hs = block_hashes(tokens); n = 0
    for h in hs:
        if h not in cache: break
        n += 1
    cache.update(hs)
    return n

sys_prompt = list(range(100, 112))                 # 12 shared tokens = 3 blocks
print(cached_blocks(sys_prompt + [1, 2, 3, 4]))    # 0 (cold)
print(cached_blocks(sys_prompt + [9, 9, 9, 9]))    # 3 (system prompt reused)
print(cached_blocks([0] + sys_prompt + [1] * 4))   # 0 (one token shift breaks every block)
```

### 8. INPUT → PROCESS → OUTPUT

```
prompt -> blocks -> chained hashes -> hit? reuse KV : prefill block -> register -> continue
```

### 9. ENTERPRISE USE CASE

RAG applications with fixed instructions, multi-turn chat (the whole conversation so far is the prefix), agents with large tool descriptions.

### 10. AI ENGINEERING CONNECTION

Cuts TTFT and cost; shapes prompt design (static first); hosted APIs price cached input tokens differently (REVIEW_REQUIRED).

### 11. ADVANTAGES

Large TTFT and compute savings for repeated prefixes; no quality change (identical K/V).

### 12. LIMITATIONS

Exact match required; cache memory competes with running sequences; eviction policy matters.

### 13. TRADE-OFFS

Memory spent holding cached prefixes vs prefill compute saved.

### 14. COMMON MISTAKES

A timestamp or user name at the top of the prompt, defeating the cache; reordering few-shot examples; assuming a hit on non-contiguous matches.

### 15. PERFORMANCE / COST CONSIDERATIONS

Reduces prefill FLOPs and TTFT; may increase memory pressure.

### 16. SECURITY CONSIDERATIONS

Shared caches can leak "was this prefix seen?" through TTFT timing; scope caches per tenant when prompts are confidential.

### 17. INTERVIEW EXPLANATION

"Prefix caching stores the KV cache of a common prompt prefix keyed by a hash of its tokens, so later requests skip prefilling it. It requires an exact token match from the start, so I put the static system prompt and examples first and variable content last, and I scope caches per tenant for privacy."

### 18. RAPID-FIRE ANSWER

Reuse the KV cache of an identical prompt prefix to skip its prefill; needs exact match; static content first.

### 19. INTERVIEW QUESTIONS

**Basic.** What is prefix caching? **Intermediate.** Why must it match from the start? (Causal: later K/V depend on all earlier tokens.) **Advanced.** How are blocks hashed? **Scenario.** Your cache hit rate dropped to zero after a release; why? (A prefix change, such as a timestamp.)
