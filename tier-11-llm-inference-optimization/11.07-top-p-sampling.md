### 1. WHAT IS IT?

**Top-p (nucleus) sampling** keeps the smallest set of tokens, taken in descending probability order, whose cumulative probability is at least `p`, renormalises and samples. **min-p** (keep tokens with `prob >= min_p x p_max`) is a related, newer rule (REVIEW_REQUIRED for support in specific APIs).

### 2. WHY DOES IT EXIST?

It removes the unreliable tail like top-k does, but the kept-set size **adapts** to the model's confidence: one or two tokens when it is sure, dozens when it is not.

### 3. DETAILED EXPLANATION

- Sort probabilities descending; keep tokens until the cumulative mass reaches `p`.
- Properties verified by the lab tests: kept mass >= p, the set is minimal, it always contains at least one token, and the kept tokens are the most probable ones.
- `p = 1.0` means no truncation. Typical values are around 0.9-0.95 (starting points, not rules).
- In the lab, a token is dropped when the mass *strictly before* it is already >= p, which keeps the token that crosses the threshold.

### 4. HOW DOES IT WORK?

1. Softmax the (temperature-scaled) logits and sort descending.
2. Compute the cumulative sum; mark each token with the mass *before* it.
3. Drop tokens whose preceding mass is already >= p.
4. Renormalise and sample.

### 5. SIMPLE EXAMPLE

Invite guests in order of friendship until the invited group accounts for 90% of the people you care about; a quiet week invites two friends, a busy week invites twenty.

### 6. TECHNICAL EXAMPLE

A chat product uses `temperature ~0.7-1.0` and `top_p ~0.9` (illustrative defaults; REVIEW_REQUIRED per provider).

### 7. CODE

```python
import torch
from decoding import top_p_filter, sample_next

z = torch.tensor([4.0, 3.0, 1.0, 0.5, 0.0, -1.0])
kept = top_p_filter(z, 0.9)
print((kept > float("-inf")).sum().item(), "tokens kept")
print(sample_next(z, temperature=0.8, top_p=0.9, generator=torch.Generator().manual_seed(0)))
```

See [`lab/decoding.py`](lab/decoding.py) (`top_p_filter`, `min_p_filter`).

### 8. INPUT → PROCESS → OUTPUT

```
logits -> softmax -> sort desc -> cumulative mass -> keep until >= p -> renormalise -> sample
```

### 9. ENTERPRISE USE CASE

Default sampling for conversational assistants; teams pin `top_p` per use case and keep it fixed across eval runs.

### 10. AI ENGINEERING CONNECTION

Evals and self-consistency use top-p together with a non-zero temperature; order of filters differs across libraries (REVIEW_REQUIRED).

### 11. ADVANTAGES

Adaptive, simple, prevents tail derailment, widely supported.

### 12. LIMITATIONS

Needs a sort (slight cost); `p` semantics shift with temperature; a flat distribution can still keep very many tokens.

### 13. TRADE-OFFS

Adaptivity vs an extra sort; min-p alternatives scale the cut relative to the top token.

### 14. COMMON MISTAKES

Setting temperature very high and expecting top-p to repair it; forgetting that temperature changes the distribution *before* top-p measures its mass.

### 15. PERFORMANCE / COST CONSIDERATIONS

Sorting `V` entries per step is minor next to the forward pass.

### 16. SECURITY CONSIDERATIONS

Not a safety control.

### 17. INTERVIEW EXPLANATION

"Top-p, or nucleus sampling, keeps the smallest group of top tokens whose probabilities add up to p and samples only from them. Unlike top-k, the group size adapts: tiny when the model is confident, large when it isn't. I use temperature to set diversity and top-p to cut the junk tail."

### 18. RAPID-FIRE ANSWER

Keep the smallest top set with cumulative probability >= p, then sample.

### 19. INTERVIEW QUESTIONS

**Basic.** What does p=1.0 do? (No truncation.) **Intermediate.** Why is it better than top-k? (Adapts.) **Advanced.** What invariants hold for the nucleus? (Mass >= p, minimal, at least one token.) **Scenario.** Answers are still weird at T=1.3 with top-p 0.95; fix? (Lower T or p, or min-p.)
