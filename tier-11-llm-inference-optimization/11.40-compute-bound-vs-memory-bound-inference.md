### 1. WHAT IS IT?

A workload is **compute-bound** when its speed is limited by arithmetic throughput (FLOP/s) and **memory-bound** when limited by memory bandwidth. The **roofline model** decides which: attainable FLOP/s = `min(peak FLOP/s, bandwidth × arithmetic intensity)`.

### 2. WHY DOES IT EXIST?

It tells you which optimization will help: more FLOPs, more bandwidth, or fewer bytes.

### 3. DETAILED EXPLANATION

- **Arithmetic intensity** = FLOPs per byte moved. The **ridge point** = peak ÷ bandwidth (e.g. 300 TFLOPS ÷ 2 TB/s = 150 FLOP/byte; illustrative, `REVIEW_REQUIRED`).
- Dense decode with batch B, w bytes/param: FLOPs ≈ 2·P·B, bytes ≈ P·w → intensity ≈ 2B/w (FP16: B). At B=1 it is ~1 FLOP/byte, far left of the ridge; you need B ≈ 150 (FP16) to become compute-bound.
- Prefill with n tokens has intensity ≈ n → compute-bound for long prompts.
- Caveat: ignores KV reads, attention FLOPs, overheads and communication.

### 4. HOW DOES IT WORK?

Compute intensity ─► compare with ridge ─► left: memory-bound, right: compute-bound.

### 5. SIMPLE EXAMPLE

A kitchen with fast cooks and a slow delivery truck: if every dish needs new ingredients, the truck limits you; if each delivery feeds many dishes, the cooks do.

### 6. TECHNICAL EXAMPLE

For a 7B-class FP16 model with ridge 150: batch 1 → 1/150 of peak FLOPs used. Batch 64 → 64/150 ≈ 43% (illustrative).

### 7. CODE

```python
def roofline(peak_tflops: float, bw_tb_s: float, intensity: float) -> float:
    """Attainable TFLOP/s."""
    return min(peak_tflops, bw_tb_s * intensity)

ridge = 300 / 2.0                       # 150 FLOP/byte
for B in (1, 8, 64, 256):               # fp16 decode: intensity ~ B
    print(B, roofline(300, 2.0, B), "TFLOP/s of", 300)
```

### 14. COMMON MISTAKES

- Confusing GPU "utilization" with efficiency. - Applying FLOP-based reasoning to decode.

### 15. PERFORMANCE / COST CONSIDERATIONS

Throughput scales with batch until the ridge; beyond it latency grows.

### 17. INTERVIEW EXPLANATION

"The roofline says performance is the minimum of peak compute and bandwidth times arithmetic intensity. Decode has tiny intensity, so it's memory-bound; prefill has high intensity, so it's compute-bound. Batching raises decode intensity."

### 18. RAPID-FIRE ANSWER

Roofline: min(peak, bandwidth × intensity); decode left of the ridge, long prefill right.
