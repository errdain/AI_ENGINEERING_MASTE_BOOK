### 1. WHAT IS IT?

**Serving reliability** is the set of practices that keep an LLM service available and within its latency SLOs despite failures, overload and bad deployments.

### 2. WHY DOES IT EXIST?

GPUs fail, requests vary wildly, and streaming responses are hard to retry.

### 3. DETAILED EXPLANATION

Failure modes: GPU OOM from a long-context request, node loss mid-stream, stragglers, overload, bad deployment, cold starts ([11.38 Cold starts](11.38-cold-starts.md)). Practices: timeouts at every hop; `max_tokens` and max-context limits; health checks that run a tiny generation; retries with backoff and idempotency awareness (streams cannot be blindly retried); circuit breakers and fallback models/providers; graceful drain on deploys; canary rollouts compared on quality and latency; cancel generation when the client disconnects.

### 4. HOW DOES IT WORK?

Request → gateway (auth, limits) → replica; on failure → retry/fallback; on overload → shed ([11.24 Admission control](11.24-admission-control.md)); on bad canary → roll back.

### 5. SIMPLE EXAMPLE

An airline: backup crews, checklists and gradual rollouts of new procedures.

### 6. TECHNICAL EXAMPLE

Canary 5% of traffic to a new quantized build; promote only if p95 latency and eval score are within thresholds.

### 7. CODE

```python
# Retry with exponential backoff + jitter, only for idempotent (non-streamed or pre-first-token) failures
import random, time

def call_with_retry(fn, retries=3, base=0.2):
    for i in range(retries + 1):
        try:
            return fn()
        except TimeoutError:
            if i == retries:
                raise
            time.sleep(base * 2 ** i * (1 + random.random()))

attempts = []
def flaky():
    attempts.append(1)
    if len(attempts) < 3:
        raise TimeoutError
    return "ok"

print(call_with_retry(flaky, base=0.01), len(attempts))   # ok 3
```

### 10. AI ENGINEERING CONNECTION

### 11. ADVANTAGES

- Fewer outages, graceful degradation.

### 12. LIMITATIONS

- More components; fallbacks can break data policy.

### 13. TRADE-OFFS

Redundancy cost vs risk.

### 14. COMMON MISTAKES

- Retrying streams blindly. - Health checks that only test the process. - No cancel on disconnect.

### 15. PERFORMANCE / COST CONSIDERATIONS

Headroom for failover costs GPUs.

### 16. SECURITY CONSIDERATIONS

Fallbacks to hosted APIs may violate data rules; test failure paths for leaks; rate limit for DoS.

### 17. INTERVIEW EXPLANATION

"I'd set timeouts and token limits, health checks that actually generate, retries with backoff only where safe, circuit breakers with fallbacks, graceful drains and canary rollouts."

### 18. RAPID-FIRE ANSWER

Timeouts, limits, real health checks, safe retries, fallbacks, canaries.
