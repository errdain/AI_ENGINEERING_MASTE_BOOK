### 1. WHAT IS IT?

**PagedAttention** stores the KV cache in fixed-size **blocks** allocated on demand from a shared pool; a per-request **block table** maps logical block index to physical block, like virtual-memory paging. The idea comes from the vLLM paper (Kwon et al., 2023; REVIEW_REQUIRED for exact claims).

### 2. WHY DOES IT EXIST?

Reserving one contiguous max-length buffer per request wastes memory: requests rarely reach the maximum, and varying lengths fragment the pool. Paging allows more concurrent sequences in the same memory.

### 3. DETAILED EXPLANATION

- Near-zero **external** fragmentation; only the *last block* of each sequence is partly empty (internal fragmentation).
- Cheap sharing of a common prefix: blocks can be shared across requests with copy-on-write ([11.18 Prefix caching](11.18-prefix-caching.md)); beam search can share too.
- Cost: an extra indirection in the attention kernel and engine complexity.
- Block size trade-off: huge blocks waste more internal space; tiny blocks add table overhead and hurt kernel efficiency.
- It raises *capacity and throughput*, not the speed of a single request.

### 4. HOW DOES IT WORK?

1. Allocate a block when the sequence's last block is full.
2. Record the physical block id in the sequence's block table.
3. The attention kernel gathers keys/values through the table.
4. On completion, return the sequence's blocks to the free pool.

### 5. SIMPLE EXAMPLE

Virtual memory: a program sees contiguous addresses, while physical pages are scattered.

### 6. TECHNICAL EXAMPLE

A vLLM-style engine serving many chat users at once: each new 16-token block is allocated as the answer grows, instead of reserving 8k tokens for each user up front.

### 7. CODE

```python
# Toy block allocator: block table per request, free pool of physical block ids.
class BlockPool:
    def __init__(self, n_blocks, block=4):
        self.free, self.block, self.tables, self.lens = list(range(n_blocks)), block, {}, {}
    def append(self, rid):
        n = self.lens.get(rid, 0)
        if n % self.block == 0:                      # last block full (or first token)
            if not self.free:
                raise MemoryError("out of KV blocks")
            self.tables.setdefault(rid, []).append(self.free.pop(0))
        self.lens[rid] = n + 1
    def release(self, rid):
        self.free += self.tables.pop(rid, []); self.lens.pop(rid, None)

p = BlockPool(8)
for _ in range(6): p.append("A")        # 6 tokens -> 2 blocks
for _ in range(3): p.append("B")        # 3 tokens -> 1 block
p.release("A")
for _ in range(5): p.append("C")        # reuses A's freed blocks (non-contiguous)
print(p.tables, p.free)
```

```
logical blocks of request R: [0][1][2]  --block table-->  physical blocks: [7][2][5]   (pool shared by all requests)
```

### 9. ENTERPRISE USE CASE

Self-hosted inference platforms rely on it for GPU memory efficiency under mixed-length traffic.

### 10. AI ENGINEERING CONNECTION

Foundation of vLLM-style serving; enables continuous batching ([11.20 Continuous batching](11.20-continuous-batching.md)), prefix sharing and larger effective batches.

### 11. ADVANTAGES

Higher memory utilisation; more concurrent sequences; sharing prefixes cheaply.

### 12. LIMITATIONS

Kernel indirection; engine complexity; block-size tuning.

### 13. TRADE-OFFS

Capacity vs kernel overhead; block size vs waste.

### 14. COMMON MISTAKES

Thinking paging speeds up one request; choosing blocks too large or too small; assuming the formula in [11.17 KV-cache memory calculation](11.17-kv-cache-memory-calculation.md) already includes fragmentation.

### 15. PERFORMANCE / COST CONSIDERATIONS

Raises concurrent sequences per GPU, lowering cost per token ([11.45 Inference cost](11.45-inference-cost.md)).

### 16. SECURITY CONSIDERATIONS

Freed blocks must be cleared or never exposed to another tenant; block tables are per request.

### 17. INTERVIEW EXPLANATION

"PagedAttention allocates KV cache in small fixed blocks on demand and keeps a block table per request, like virtual memory. That eliminates the memory wasted by reserving max-length buffers and fragmentation, so more sequences fit and prefixes can be shared. It improves throughput, not single-request latency."

### 18. RAPID-FIRE ANSWER

Block-based, on-demand KV allocation with block tables: near-zero fragmentation, more concurrency.
