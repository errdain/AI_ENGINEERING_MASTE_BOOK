### 1. WHAT IS IT?

**Concurrency** is the number of requests being served simultaneously (in flight). By **Little's law**, `in-flight = arrival rate × time in system`.

### 2. WHY DOES IT EXIST?

Capacity planning needs a link between user load, latency and resources.

### 3. DETAILED EXPLANATION

- Concurrency is limited by KV memory ([11.44 GPU-memory budgeting](11.44-gpu-memory-budgeting.md)), batch-size limits, and SLOs: more concurrency raises throughput up to a knee, then raises latency.
- Distinguish **concurrent requests** (users) from **active sequences in the GPU batch**; queued requests do not use GPU but do wait.
- Example: 20 req/s with 10 s average latency means 200 in flight.
[Batching Gantt](interactive/batching_gantt.html): change slots and arrival gap to see queueing.

### 4. HOW DOES IT WORK?

Arrivals ─► queue ─► active batch (limited by slots and KV) ─► completion. Latency = queue + service.

### 5. SIMPLE EXAMPLE

A restaurant: seats (batch slots) limit how many diners eat at once; others wait.

### 6. TECHNICAL EXAMPLE

Benchmark at concurrency 1, 8, 32, 128 and record throughput and p95 latency; choose the highest concurrency meeting the SLO.

### 7. CODE

```python
# run from lab/ : concurrency sweep on the toy scheduler (arrival gap controls offered load)
import random
from scheduler import Req, simulate, metrics

rnd = random.Random(1)
for slots in (2, 4, 8, 16):
    reqs = [Req(i, i * 2, rnd.randint(10, 40), rnd.choice([5, 10, 40])) for i in range(40)]
    fin, rej, log = simulate(reqs, capacity_tokens=800, max_batch=slots, mode="continuous")
    m = metrics(fin, log)
    print(slots, round(m["throughput"], 2), round(m["mean_latency"], 1))
```

### 8. INPUT → PROCESS → OUTPUT

```
users ─► queue ─► [batch slots + KV] ─► tokens ; throughput ↑ with slots, latency ↑ past the knee
```

### 9. ENTERPRISE USE CASE

### 11. ADVANTAGES

- Simple capacity-planning handle (Little's law).

### 12. LIMITATIONS

- Real traffic is bursty; averages hide peaks.

### 13. TRADE-OFFS

Higher concurrency = better utilization but worse latency.

### 14. COMMON MISTAKES

- Benchmarking only at concurrency 1. - Using averages.

### 15. PERFORMANCE / COST CONSIDERATIONS

Concurrency × avg context = KV tokens needed.

### 16. SECURITY CONSIDERATIONS

Per-tenant concurrency limits prevent noisy-neighbour denial of service.

### 17. INTERVIEW EXPLANATION

"Concurrency is how many requests are in flight; Little's law ties it to arrival rate and latency. I'd sweep it, plot throughput vs p95 latency, and pick the knee that meets the SLO, subject to KV memory."

### 18. RAPID-FIRE ANSWER

Concurrency = arrival rate × latency; raise it until the SLO knee.
