### 1. WHAT IS IT?

**vLLM** is an open-source GPU LLM serving engine built around PagedAttention ([11.21 PagedAttention](11.21-pagedattention.md)) and continuous batching ([11.20 Continuous batching](11.20-continuous-batching.md)), with an OpenAI-compatible HTTP server. (Concept-level — `REVIEW_REQUIRED`; features, flags and defaults change quickly.)

### 2. WHY DOES IT EXIST?

Naive serving wastes KV memory (fragmentation, over-reservation) and GPU time (static batches). vLLM's design targets high throughput and good latency for many concurrent users on shared GPUs.

### 3. DETAILED EXPLANATION

- **Core ideas:** paged KV-cache blocks, iteration-level scheduling, prefix caching, quantized-model support, tensor/pipeline parallelism, speculative decoding (`REVIEW_REQUIRED` for each, per version).
- **Key knobs (names may change):** maximum context length, maximum concurrent sequences, GPU-memory utilization fraction, tensor-parallel size, dtype/quantization.
- **Server:** OpenAI-compatible `chat/completions` and `completions`, streaming.
![PagedAttention](figures/06_paged_attention.gif)

*Figure 6 — Logical sequences map to physical KV blocks; look at how blocks are allocated as sequences grow and returned when they finish, so no sequence needs one big contiguous region.*

[KV calculator](interactive/kv_cache_calculator.html) shows block-size and fragmentation effects; [batching Gantt](interactive/batching_gantt.html) shows why iteration-level scheduling wins.

### 4. HOW DOES IT WORK?

Requests enter a queue ─► scheduler picks sequences each iteration subject to KV block availability ─► GPU step for the whole batch ─► finished sequences free blocks, new ones join ─► tokens stream back. If blocks run out, sequences may be preempted (swapped/recomputed) — `REVIEW_REQUIRED`.

### 5. SIMPLE EXAMPLE

A restaurant where tables (blocks) are assigned per group as they arrive, instead of reserving a whole wing for each party.

### 6. TECHNICAL EXAMPLE

A team serves an 8B model for 100 concurrent users on one large GPU. They set the GPU memory fraction so weights + KV fit with headroom, cap context, enable prefix caching for a shared system prompt, and monitor KV utilization ([11.47 Inference observability](11.47-inference-observability.md)).

### 8. INPUT → PROCESS → OUTPUT

```
clients ─► OpenAI-compatible API ─► scheduler (continuous batching) ─► paged KV allocator ─► GPU(s) ─► streamed tokens
```

### 9. ENTERPRISE USE CASE

Internal LLM platforms host open-weight models behind a gateway with auth, quotas and metrics, with vLLM-style engines as the inference layer.

### 10. AI ENGINEERING CONNECTION

Standard engine for self-hosted open models; OpenAI compatibility lets apps move between hosted and self-hosted backends ([11.33 Local vs hosted inference](11.33-local-vs-hosted-inference.md)).

### 11. ADVANTAGES

- High throughput; efficient KV memory; rich parallelism; broad model support.

### 12. LIMITATIONS

- GPU required; version churn; memory tuning; operational complexity.

### 13. TRADE-OFFS

Throughput vs latency (batch size); memory reserved for KV vs for activations; features vs stability.

### 14. COMMON MISTAKES

- Setting max context far above need (wastes KV). - Leaving the server unauthenticated. - Benchmarking at concurrency 1. - Ignoring preemptions.

### 15. PERFORMANCE / COST CONSIDERATIONS

Capacity ≈ free memory ÷ KV bytes/token ([11.44 GPU-memory budgeting](11.44-gpu-memory-budgeting.md)); cost per token falls with utilization ([11.45 Inference cost](11.45-inference-cost.md)).

### 16. SECURITY CONSIDERATIONS

Put auth, rate limits and TLS in front; isolate tenants (prefix caching can leak timing across tenants — `REVIEW_REQUIRED`); pin model digests.

### 17. INTERVIEW EXPLANATION

"vLLM is a GPU serving engine. PagedAttention stores KV cache in fixed-size blocks to avoid fragmentation, and continuous batching admits and retires sequences every step, so the GPU stays busy. It exposes an OpenAI-compatible API, so it's the usual choice for multi-user hosting of open-weight models."

### 18. RAPID-FIRE ANSWER

vLLM = PagedAttention + continuous batching + OpenAI-compatible server for multi-user GPU inference.
