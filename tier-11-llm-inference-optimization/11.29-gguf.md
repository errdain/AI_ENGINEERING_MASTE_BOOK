### 1. WHAT IS IT?

**GGUF** is a single-file binary format for packaging LLM weights plus metadata, used by the llama.cpp ecosystem. It typically stores quantized tensors together with the architecture name, hyperparameters and tokenizer data. (Tool/format descriptions here are concept-level — `REVIEW_REQUIRED`; check the current GGUF specification.)

### 2. WHY DOES IT EXIST?

Running a model locally needs weights, config and tokenizer to stay together and load fast. A self-describing, memory-mappable single file removes the loose-files problem of earlier formats.

### 3. DETAILED EXPLANATION

- **Layout (concept-level, `REVIEW_REQUIRED`):** magic bytes `GGUF`, a version, a tensor count, a metadata key-value count, the metadata (architecture, context length, head counts, tokenizer vocabulary and merges, ...), tensor descriptors (name, shape, quantization type, offset), then an aligned data block.
- **Quantization types** are named like `Q8_0`, `Q4_K_M`, `Q5_K_S`; the name encodes bits and block/mixing scheme. Mixed schemes keep sensitive tensors at higher precision (`REVIEW_REQUIRED`: names and meanings evolve).
- **Memory-mapping** lets the OS page weights lazily, so load time is short and several processes can share pages.
- The tokenizer must match the model — see [Tier 6](../tier-06-tokenization-embeddings/README.md) for tokenization.

### 4. HOW DOES IT WORK?

1. Converter reads original weights (e.g. safetensors) and config. 2. Optional quantization to chosen type. 3. Writes header, metadata, tensor table, data. 4. Runtime parses header, maps data, builds the compute graph for the architecture named in metadata.

### 5. SIMPLE EXAMPLE

### 7. CODE

A tiny header reader (the header fields follow the concept-level layout above; `REVIEW_REQUIRED` — verify against the current spec):

```python
import struct, io

def read_gguf_header(f):
    magic = f.read(4)
    if magic != b"GGUF":
        raise ValueError("not a GGUF file")
    (version,) = struct.unpack("<I", f.read(4))
    tensor_count, kv_count = struct.unpack("<QQ", f.read(16))   # 64-bit counts in recent versions
    return {"version": version, "tensors": tensor_count, "metadata_kv": kv_count}

fake = io.BytesIO(b"GGUF" + struct.pack("<IQQ", 3, 291, 25))     # synthetic header, not a real model
print(read_gguf_header(fake))
```

### 11. ADVANTAGES

- Single portable file; self-describing; fast load via mmap; many quant types.

### 12. LIMITATIONS

- Mostly tied to the llama.cpp ecosystem; format versions change; not a training format.

### 13. TRADE-OFFS

Convenience and portability vs ecosystem lock-in.

### 14. COMMON MISTAKES

- Wrong or missing chat template/tokenizer metadata. - Picking a quant by file size only. - Mixing up converter versions.

### 15. PERFORMANCE / COST CONSIDERATIONS

File size ≈ params × effective bits / 8; mmap needs enough RAM/page cache for steady speed.

### 16. SECURITY CONSIDERATIONS

Treat files from the internet as untrusted: verify hash and publisher; parser bugs in loaders have existed in file formats generally, so keep runtimes updated (`REVIEW_REQUIRED`). Unlike pickle, GGUF is data-only.
