### 1. WHAT IS IT?

**Logits** are the raw, unnormalised real numbers (one per vocabulary entry) that the model's final linear layer outputs at each position. `softmax(logits)` turns them into a probability distribution over the next token.

### 2. WHY DOES IT EXIST?

A network needs an unconstrained output space; probabilities must be positive and sum to 1. Logits are that unconstrained space, and every decoding trick (temperature, top-k, penalties, grammar masks) is a cheap edit of the logit vector before the final softmax and sampling.

### 3. DETAILED EXPLANATION

- Logits are *unnormalised log-probabilities*: `p_i = exp(z_i) / sum_j exp(z_j)`. Only **differences** matter: adding a constant `c` to every logit leaves the softmax unchanged (the constant cancels).
- Vocabulary size `V` is typically tens of thousands to hundreds of thousands (REVIEW_REQUIRED per model), so the logit tensor is `(batch, seq, V)`; generation uses only the last position.
- Setting a logit to `-inf` makes that token impossible. This is how masks, top-k/top-p, banned tokens and grammar-constrained decoding work.
- Log-softmax gives log-probabilities, used for beam search ([11.9 Beam search](11.09-beam-search.md)), perplexity and token-level confidence.

### 4. HOW DOES IT WORK?

1. Final hidden state `h` at the last position (size `d_model`).
2. `logits = h @ W_out` giving a vector of length `V` (often `W_out` is tied to the input embedding matrix, REVIEW_REQUIRED per model).
3. Edit the logits (penalties, masks, temperature).
4. `probs = softmax(logits)`; choose a token ([11.3 Decoding overview](11.03-decoding-overview.md)).

### 5. SIMPLE EXAMPLE

Exam scores before grading on a curve: raw scores can be any number; only after converting them to shares of the total do they behave like probabilities. Giving everyone +10 does not change the shares in a softmax.

### 6. TECHNICAL EXAMPLE

Logits `[2.0, 1.0, 0.1]` give probabilities `[0.659, 0.242, 0.099]`. Adding 5 to each gives `[7.0, 6.0, 5.1]` and identical probabilities. Confidence signals such as top-1 probability or entropy are computed from them for routing and evaluation.

### 7. CODE

```python
import torch

z = torch.tensor([2.0, 1.0, 0.1])
print(z.softmax(-1))             # tensor([0.6590, 0.2424, 0.0986])
print((z + 5).softmax(-1))       # identical: constants cancel
z[1] = float("-inf")             # ban token 1
print(z.softmax(-1))             # token 1 now has probability 0
probs = z.softmax(-1)
entropy = -(probs[probs > 0] * probs[probs > 0].log()).sum()   # uncertainty signal
```

### 8. INPUT → PROCESS → OUTPUT

```
hidden state h --(h @ W_out)--> logits (V) --(edit/mask)--> logits' --softmax--> probs --rule--> token id
```

### 9. ENTERPRISE USE CASE

A support bot logs top-1 probability and entropy per answer and routes low-confidence answers to a human reviewer.

### 10. AI ENGINEERING CONNECTION

Grammar/JSON-constrained decoding masks logits; classification-by-LLM reads the logits of label tokens; evals use log-probs; logit bias APIs let applications boost or ban tokens.

### 11. ADVANTAGES

Simple, differentiable, cheap to edit, and the single interface through which all decoding control is applied.

### 12. LIMITATIONS

Logits are not calibrated probabilities: a high top-1 probability does not guarantee correctness. Raw logits are meaningless across different models or vocabularies.

### 13. TRADE-OFFS

Exposing full logits gives maximum control and information but costs bandwidth (V floats per step) and leaks model information; many APIs expose only top-N log-probs.

### 14. COMMON MISTAKES

- Applying temperature to probabilities instead of logits (divide the logits).
- Treating logits as probabilities.
- Using softmax on `-inf`-everywhere vectors (NaN); always keep at least one token.

### 15. PERFORMANCE / COST CONSIDERATIONS

The output projection `d_model x V` is a large matmul and a sizeable fraction of decode traffic for small models; at V=100k+ the logit tensor for a long prefill is large, so engines compute only the last position.

### 16. SECURITY CONSIDERATIONS

Full logits/log-probs through an API can aid model-extraction attacks (REVIEW_REQUIRED on practical risk); logit-bias features let users steer output, so validate them server-side.

### 17. INTERVIEW EXPLANATION

"Logits are the model's raw scores for every token in the vocabulary. They are not probabilities until you apply softmax. Everything we do at decode time, temperature, top-k, top-p, penalties, grammar masks, is just editing this vector before sampling. Adding a constant to all of them changes nothing, only the differences matter."

### 18. RAPID-FIRE ANSWER

Logits are unnormalised log-probabilities per vocabulary token; softmax makes them a distribution and all decoding controls act on them.

### 19. INTERVIEW QUESTIONS

**Basic.** Are logits probabilities? (No.) What does softmax do? (Exponentiates and normalises.)

**Intermediate.** Why does adding 5 to all logits not matter? (The factor `e^5` cancels in the ratio.) How do you ban a token? (Set its logit to `-inf`.)

**Advanced.** Why are only last-position logits computed at inference? (Earlier positions' next tokens are already known; saves a `V`-wide matmul per prompt token.)

**Scenario.** You need the model to answer only "yes" or "no": how with logits? (Compare the two label-token logits or mask all other tokens.)
