### 1. WHAT IS IT?

**Pipeline-parallel (PP) inference** assigns contiguous groups of layers (stages) to different GPUs; activations flow stage to stage.

### 2. WHY DOES IT EXIST?

When even TP within a node isn't enough, or interconnect between nodes is slow, PP needs only one activation hop per stage, which tolerates slower links.

### 3. DETAILED EXPLANATION

- A single request still traverses all stages serially: latency does not fall, and may rise slightly.
- To keep all stages busy you need several micro-batches or concurrent requests in flight; otherwise there are "bubbles" (idle stages).
- Typical pattern: TP within node, PP across nodes, replicas for throughput (`REVIEW_REQUIRED` per hardware).
- Parallelism is forced by memory first: shard only as much as needed.

### 4. HOW DOES IT WORK?

```
stage0 (layers 0-15, GPU0) ─► stage1 (16-31, GPU1) ─► stage2 (32-47, GPU2) ─► logits
   micro-batch A →   micro-batch B →   (overlap to hide bubbles)
```

### 5. SIMPLE EXAMPLE

An assembly line: each station does one step; the line is full only when many items are in progress.

### 6. TECHNICAL EXAMPLE

A 405B-class model (`REVIEW_REQUIRED`) is served as TP=8 inside each node and PP=2 across two nodes.

### 7. CODE

```python
# Pipeline utilization with m micro-batches over p stages (GPipe-style bubble estimate, ideal equal stages)
def pipeline_utilization(p: int, m: int) -> float:
    return m / (m + p - 1)

for m in (1, 4, 16):
    print(m, round(pipeline_utilization(4, m), 2))   # 0.25, 0.57, 0.84
```

### 8. INPUT → PROCESS → OUTPUT

```
tokens ─► stage 1 ─► stage 2 ─► … ─► stage p ─► logits    (micro-batches overlap)
```

### 9. ENTERPRISE USE CASE

Multi-node serving of very large models where inter-node bandwidth is modest.

### 10. AI ENGINEERING CONNECTION

Fits huge models across nodes; combined with TP ([11.35 Tensor-parallel inference](11.35-tensor-parallel-inference.md)) and replicas ([11.34 Model replicas](11.34-model-replicas.md)).

### 11. ADVANTAGES

- Low communication; tolerates slower links; fits huge models.

### 12. LIMITATIONS

- Bubbles; no latency gain; imbalanced stages; more complex failure handling.

### 13. TRADE-OFFS

Communication vs utilization; latency vs fit.

### 14. COMMON MISTAKES

- Expecting latency to drop. - Too few concurrent requests, leaving stages idle. - Uneven layer split.

### 15. PERFORMANCE / COST CONSIDERATIONS

Utilization ≈ m/(m+p−1) in the simple model; per-stage memory = weights/p.

### 16. SECURITY CONSIDERATIONS

Activations cross nodes; encrypt/isolate the network if required.

### 17. INTERVIEW EXPLANATION

"Pipeline parallelism splits the model by layers across GPUs. Communication is cheap — one hop per stage — so it works across nodes, but a single request still goes through every stage and you need enough concurrent micro-batches to keep stages busy."

### 18. RAPID-FIRE ANSWER

PP splits by layers; low communication; no latency gain; needs micro-batches.
