# 4.31 Data parallelism

**Metadata** — Tier: 4 · Phase: 1 · Priority: P0 · Difficulty: 3/5 · Interview: Very high · Hands-on: Medium
Prerequisites: 4.14 Gradient accumulation, 4.30 Distributed training intro · Leads to: 4.34 FSDP/ZeRO

> **In plain words**
> In **data parallelism** every GPU holds a **complete copy of the model** but processes a **different slice of each batch**. Each computes its own gradient; the GPUs then **average the gradients** (an all-reduce) so every copy takes the **identical update** and stays in sync. It's the simplest and most widely used way to train faster, as long as the model (plus optimizer state) fits on one GPU.

**You need first:** 4.14 Gradient accumulation (averaging gradients), 4.30 Distributed training introduction.

> **Figure 4.31-1 — replicate the model, split the batch, average the gradients**
>
> ```mermaid
> flowchart TB
>     B["global batch of 64"] --> S1["GPU 0: 16 examples"]
>     B --> S2["GPU 1: 16 examples"]
>     B --> S3["GPU 2: 16 examples"]
>     B --> S4["GPU 3: 16 examples"]
>     S1 --> G1["gradient 0"]
>     S2 --> G2["gradient 1"]
>     S3 --> G3["gradient 2"]
>     S4 --> G4["gradient 3"]
>     G1 --> AR["all-reduce:<br/>average"]
>     G2 --> AR
>     G3 --> AR
>     G4 --> AR
>     AR --> U["every GPU applies the same update"]
> ```
>
> *How to read it:* the four GPUs hold identical weights at the start of a step. Each sees a quarter of the global batch, computes a gradient, and the all-reduce makes all four gradients equal to the average, which equals the gradient of the whole batch of 64. The identical update keeps the replicas identical.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| replica | one GPU's copy of the model |
| DDP | `DistributedDataParallel`, PyTorch's data-parallel wrapper |
| all-reduce | sum across ranks, result to everyone |
| `DistributedSampler` | gives each rank a different shard of the dataset |
| bucket | a group of gradients all-reduced together |
| global batch | per-GPU batch × number of GPUs |
| sync BatchNorm | BatchNorm statistics shared across GPUs |

### 1. What is it?
Parallelizing training by replicating the model across devices and sharding the data. Gradients are averaged across replicas every step.

### 2. Why does it exist?
It scales throughput nearly linearly at modest sizes and requires no change to the model. The mathematics is identical to one big batch (4.14).

### 3. Detailed explanation
- **Equivalence.** The average of the per-GPU mean gradients equals the gradient of the global-batch mean (code ②). So N GPUs with batch `b` behave like one GPU with batch `N·b`.
- **DDP details.** Each process builds the same model (same seed or broadcast from rank 0), wraps it in `DistributedDataParallel`, and uses a `DistributedSampler`. During `backward()`, gradients are all-reduced in **buckets** while later layers are still computing (communication overlaps with compute).
- **Learning rate.** The global batch grows with N: scale the learning rate (linear or square-root) and lengthen warm-up (4.13).
- **Per-device memory is unchanged:** each GPU still holds weights, gradients, optimizer state and its activations. If the model doesn't fit, use sharding (4.34).
- **Communication.** Each step all-reduces a volume equal to the gradient size; with a fast interconnect it is small relative to compute for large models.
- **BatchNorm.** Statistics are per GPU unless you use `SyncBatchNorm` (3.30).
- **Accumulation + DDP:** use `no_sync()` on non-final micro-steps (4.14).
- **Checkpointing:** save from rank 0 only; load on all ranks (4.20).
- **Evaluation:** shard validation too, then reduce metrics.
- **Randomness:** seed shuffling per epoch via `sampler.set_epoch(epoch)`, or every epoch uses the same order (4.22).
- **Pitfalls:** uneven shard sizes can hang an all-reduce; parameters unused in the forward pass need `find_unused_parameters=True`.
- **Scaling.** Efficiency of 85–95% on a node is typical; beyond one node network speed matters (REVIEW_REQUIRED).

### 4. How does it work?
Same model everywhere → different data per rank → local backward → bucketed all-reduce of gradients → identical optimizer step.

### 5. Simple example
Four cashiers each ring up a quarter of today's customers, then pool the totals so the shop has one combined number.

**By hand.** Local mean gradients `[1, 3, 5, 7]` → average 4 = the gradient over all four slices combined.

### 6. Technical example
`torchrun --nproc_per_node=8 train.py` with `model = DDP(model, device_ids=[local_rank])` and `sampler = DistributedSampler(dataset)`.

### 7. Code
**① By hand (plain Python).** Four replicas stay identical.

```python
w = [2.0, 2.0, 2.0, 2.0]                                 # one weight per replica, all equal
local_grads = [1.0, 3.0, 5.0, 7.0]                       # each replica's gradient from its data slice
avg = sum(local_grads) / len(local_grads)
w = [wi - 0.1 * avg for wi in w]                         # every replica applies the SAME averaged gradient
print("weights after the step:", w, "-> all equal:", len(set(w)) == 1)
w_bad = [round(wi - 0.1 * g, 2) for wi, g in zip([2.0] * 4, local_grads)]
print("without averaging:", w_bad, "-> replicas drift apart")
```

```text
weights after the step: [1.6, 1.6, 1.6, 1.6] -> all equal: True
without averaging: [1.9, 1.7, 1.5, 1.3] -> replicas drift apart
```

**② With NumPy.** Equivalence with one big batch, and the learning-rate scaling idea.

```python
import numpy as np

rng = np.random.default_rng(0)
X, y = rng.normal(size=(64, 3)), rng.normal(size=64)
w = np.zeros(3)
grad = lambda Xb, yb: 2 * Xb.T @ (Xb @ w - yb) / len(yb)

shards = np.array_split(np.arange(64), 4)
avg = np.mean([grad(X[s], y[s]) for s in shards], axis=0)
print("average of 4 shard gradients :", avg.round(5))
print("gradient of the whole batch  :", grad(X, y).round(5))
print("equal:", np.allclose(avg, grad(X, y)))
print("global batch for 8 GPUs with 32 per GPU:", 8 * 32, "-> scale lr by about", 8 * 32 // 32, "x (or sqrt) from the single-GPU recipe")
```

```text
average of 4 shard gradients : [-3.6000e-04  5.0327e-01  6.7486e-01]
gradient of the whole batch  : [-3.6000e-04  5.0327e-01  6.7486e-01]
equal: True
global batch for 8 GPUs with 32 per GPU: 256 -> scale lr by about 8 x (or sqrt) from the single-GPU recipe
```

**③ With PyTorch.** A real two-process DDP run on CPU: weights stay identical.

```python
import os, tempfile
import torch
import torch.distributed as dist
import torch.multiprocessing as mp
from torch.nn.parallel import DistributedDataParallel as DDP

def worker(rank, world, path):
    dist.init_process_group("gloo", init_method=f"file://{path}", rank=rank, world_size=world)
    torch.manual_seed(0)                                           # same init on every rank
    model = DDP(torch.nn.Linear(4, 1))
    opt = torch.optim.SGD(model.parameters(), lr=0.1)
    g = torch.Generator().manual_seed(100 + rank)                  # DIFFERENT data per rank
    for _ in range(20):
        X = torch.randn(16, 4, generator=g); y = X.sum(dim=1, keepdim=True)
        opt.zero_grad(); torch.nn.functional.mse_loss(model(X), y).backward(); opt.step()
    w = model.module.weight.detach().flatten()
    gathered = [torch.zeros_like(w) for _ in range(world)]
    dist.all_gather(gathered, w)
    if rank == 0:
        print("rank 0 weights:", [round(v, 4) for v in gathered[0].tolist()])
        print("rank 1 weights:", [round(v, 4) for v in gathered[1].tolist()])
        print("replicas identical:", torch.allclose(gathered[0], gathered[1]))
    dist.destroy_process_group()

path = os.path.join(tempfile.mkdtemp(), "rendezvous")
mp.start_processes(worker, args=(2, path), nprocs=2, start_method="fork")
```

```text
rank 0 weights: [0.9904, 0.9867, 0.9739, 0.98]
rank 1 weights: [0.9904, 0.9867, 0.9739, 0.98]
replicas identical: True
```

### 9. Enterprise use case
The default way teams use multi-GPU nodes; also the basis for elastic and spot-instance training with checkpoint/restart.

### 10. AI engineering connection
Combined with sharding and tensor/pipeline parallelism in LLM training; used directly for fine-tuning and small-to-mid models.

### 11. Advantages
Simple; near-linear scaling at moderate size; no model changes.

### 12. Limitations
Model and optimizer state must fit on each GPU; communication grows with model size; large global batches need retuning.

### 13. Trade-offs
Simplicity versus memory efficiency (FSDP/ZeRO trades some communication for memory).

### 14. Common mistakes
Different initialization per rank; forgetting the sampler's `set_epoch`; saving checkpoints from all ranks; unscaled learning rate; unused parameters causing hangs; uneven batches.

### 15. Performance / cost
Overlap all-reduce with backward (buckets); use a fast interconnect; use gradient compression only with care.

### 16. Security
Ranks trust each other; in untrusted settings malicious gradients can poison training (federated learning).

</details>

### 17. Interview explanation
"Data parallelism replicates the model on each GPU, shards the batch, and all-reduces the gradients so every replica applies the same update; mathematically it equals training on the global batch. DDP overlaps the all-reduce with backward. It needs the whole model plus optimizer state on each GPU, so beyond that I move to FSDP/ZeRO."

### 18. Rapid-fire answer
Replicate model, shard data, all-reduce gradients (average); same as a bigger batch; memory per GPU unchanged.

### 20. Hands-on exercise
**Goal:** check how the speed-up depends on communication.

1. A step takes 200 ms compute per GPU; the all-reduce takes 30 ms but overlaps 70% with compute (only 30% is exposed).
2. For N = 1, 8 compute the step time, throughput for 32 examples per GPU and efficiency.

<details>
<summary>Show a solution</summary>

```python
compute, allreduce, exposed = 0.200, 0.030, 0.30
per_gpu = 32
single = per_gpu / compute
for n in (1, 8):
    step = compute + (0 if n == 1 else allreduce * exposed)
    throughput = n * per_gpu / step
    print(f"{n} GPU(s): step {step * 1000:.0f} ms, {throughput:.0f} examples/s, efficiency {throughput / (n * single):.0%}")
```

```text
1 GPU(s): step 200 ms, 160 examples/s, efficiency 100%
8 GPU(s): step 209 ms, 1225 examples/s, efficiency 96%
```
