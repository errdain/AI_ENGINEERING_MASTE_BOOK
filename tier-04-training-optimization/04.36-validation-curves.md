# 4.36 Validation curves

**Metadata** — Tier: 4 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: Very high · Hands-on: Very high

> **In plain words**
> The **validation curve** is the loss (or metric) on **held-out data the model never trains on**, plotted next to the training curve. Training loss tells you how well the model is *memorizing*; validation tells you how well it is *learning something that works on new data*. The **gap** between the two, and the moment validation stops improving, tell you when to stop and what to fix.

**You need first:** 2.12 Early stopping, 2.27 Overfitting, 4.35 Training curves.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| validation set | held-out data used for decisions during training |
| test set | final held-out data used once at the end |
| generalization gap | validation loss minus training loss |
| early stopping | stop when validation stops improving |
| patience | how many epochs to wait without improvement |
| best checkpoint | the weights at the best validation score |
| metric | the number you care about (accuracy, F1, perplexity) |

### 1. What is it?
Evaluating the model on a validation set at regular intervals (every epoch or every N steps) and plotting the result against training.

### 2. Why does it exist?
Training loss always improves if the model can memorize. Only held-out data shows whether the improvement is real.

### 3. Detailed explanation
- **Splits:** train / validation / test (2.13). Validation guides decisions (stopping, hyperparameters); the test set is touched once at the end. Tuning on the test set leaks (2.33).
- **Evaluate in eval mode under `no_grad`** (4.1, 4.2).
- **The gap:** a small gap with high loss = underfit; a growing gap = overfit. Some gap is normal.
- **Early stopping:** keep the best-validation checkpoint (4.20); stop after `patience` evaluations with no improvement larger than a small `min_delta`.
- **Noise:** small validation sets give noisy curves; use enough examples and don't over-react to one epoch.
- **Frequency:** evaluating costs time; large models evaluate every N steps on a subset.
- **Metrics vs loss:** the loss can improve while accuracy does not (or vice versa); track both. For generation, loss/perplexity plus task evaluations (Tier 15).
- **Different distributions:** if validation resembles the real world and training does not, trust validation; check for leakage and duplicates between splits.
- **Double descent and grokking** can make validation improve late (REVIEW_REQUIRED); don't stop too early on very small data without checking.
- **Hyperparameter search** uses validation; report the final test score once.
- **LLMs:** validation loss on a held-out slice of the pre-training mix tracks progress; downstream evals complement it.
- **Time-series data:** split by time, not randomly (2.13).

### 4. How does it work?
Every k steps: switch to eval, compute loss/metric on the validation set, log it, keep the best weights, decide whether to stop.

### 5. Simple example
Practice tests versus the real exam: your practice-test score (training) can reach 100% by memorizing the answers; the surprise quiz (validation) shows what you really learned.

**By hand.** Validation losses `[0.9, 0.6, 0.5, 0.52, 0.55, 0.6]`. Best at epoch 3. With patience 2, stop after epoch 5 and restore epoch 3.

### 6. Technical example
`val_loss` logged every 500 steps; the best checkpoint saved; early stopping with patience 5 in fine-tuning.

### 7. Code
**① By hand (plain Python).** Early stopping with patience.

```python
val = [0.90, 0.60, 0.50, 0.52, 0.55, 0.60, 0.58]
best, best_epoch, bad, patience = float("inf"), 0, 0, 2
for epoch, v in enumerate(val, 1):
    if v < best - 1e-9:
        best, best_epoch, bad = v, epoch, 0
    else:
        bad += 1
    if bad >= patience:
        print(f"stop after epoch {epoch}; restore epoch {best_epoch} (validation loss {best})")
        break
```

```text
stop after epoch 5; restore epoch 3 (validation loss 0.5)
```

```python
import numpy as np

rng = np.random.default_rng(0)
f = lambda x: np.sin(2 * x)
xtr, xva = np.sort(rng.uniform(-2, 2, 15)), rng.uniform(-2, 2, 200)
ytr, yva = f(xtr) + 0.3 * rng.normal(size=15), f(xva) + 0.3 * rng.normal(size=200)
print("degree  train MSE  validation MSE")
for deg in (1, 3, 5, 9, 12):
```


**③ With PyTorch.** Track validation each epoch, keep the best, read the gap.

```python
import copy, torch

torch.manual_seed(0)
def data(n):
    X = torch.randn(n, 20); return X, ((X[:, 0] + 0.5 * torch.randn(n)) > 0).long()
(Xtr, ytr), (Xva, yva) = data(60), data(1000)
net = torch.nn.Sequential(torch.nn.Linear(20, 64), torch.nn.ReLU(), torch.nn.Linear(64, 2))
opt = torch.optim.Adam(net.parameters(), lr=0.01)
best, best_epoch, best_state, history = 9.0, 0, None, []
for epoch in range(1, 101):
    net.train(); opt.zero_grad(); tr = torch.nn.functional.cross_entropy(net(Xtr), ytr); tr.backward(); opt.step()
    net.eval()
    with torch.no_grad():
        va = torch.nn.functional.cross_entropy(net(Xva), yva).item()
    history.append((tr.item(), va))
    if va < best:
        best, best_epoch, best_state = va, epoch, copy.deepcopy(net.state_dict())
print(f"best validation loss {best:.3f} at epoch {best_epoch} of 100")
print(f"at the end: training loss {history[-1][0]:.3f}, validation loss {history[-1][1]:.3f} (gap {history[-1][1] - history[-1][0]:.3f})")
net.load_state_dict(best_state)
```

```text
best validation loss 0.608 at epoch 6 of 100
at the end: training loss 0.000, validation loss 1.484 (gap 1.484)
```

### 8. Input → Process → Output
`weights → eval-mode loss on held-out data → curve → stop / keep best / regularize`

### 9. Enterprise use case
Validation curves gate promotion decisions; teams log them for audit and rollback.

### 10. AI engineering connection
Perplexity on held-out text; reward-model accuracy on held-out comparisons; eval suites.

### 11. Advantages
Honest signal of generalization; basis for early stopping.

### 12. Limitations
Costs compute; small sets are noisy; can leak if reused for many decisions.

### 13. Trade-offs
Frequent evaluation gives finer control but slows training.

### 14. Common mistakes
Validating in train mode; tuning on the test set; duplicates across splits; random splits for time series; stopping on one noisy epoch; forgetting to restore the best weights.

### 15. Performance / cost
Evaluate on a subset during training and the full set at the end.

### 16. Security
Validation data can contain sensitive information; handle like training data.

### 17. Interview explanation
"I track validation loss and metrics alongside training, in eval mode and no_grad. Falling training and rising validation means overfitting, so I stop at the validation minimum with patience and restore the best checkpoint, or add regularization; both high means underfitting. The test set stays untouched until the end."

### 18. Rapid-fire answer
Held-out loss/metric each epoch; gap = over/underfit; early stop with patience and best checkpoint; test set only once.

### 20. Hands-on exercise
**Goal:** see that more data shrinks the gap.

1. Use the setup of code ③ with 30, 60, 240 training examples.
2. Train 60 epochs each; print the final training loss, validation loss and gap.

<details>
<summary>Show a solution</summary>

```python
import torch

def run(n_train):
    torch.manual_seed(0)
    def data(n):
        X = torch.randn(n, 20); return X, ((X[:, 0] + 0.5 * torch.randn(n)) > 0).long()
    (Xtr, ytr), (Xva, yva) = data(n_train), data(1000)
    net = torch.nn.Sequential(torch.nn.Linear(20, 64), torch.nn.ReLU(), torch.nn.Linear(64, 2))
    opt = torch.optim.Adam(net.parameters(), lr=0.01)
    for _ in range(60):
        opt.zero_grad(); tr = torch.nn.functional.cross_entropy(net(Xtr), ytr); tr.backward(); opt.step()
    with torch.no_grad():
        va = torch.nn.functional.cross_entropy(net(Xva), yva).item()
    return tr.item(), va

for n in (30, 60, 240):
    tr, va = run(n)
    print(f"{n:>3} training examples: train {tr:.3f}  validation {va:.3f}  gap {va - tr:.3f}")
```

```text
 60 training examples: train 0.001  validation 1.408  gap 1.407
240 training examples: train 0.005  validation 0.696  gap 0.691
```
