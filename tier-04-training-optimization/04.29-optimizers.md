# 4.29 Optimizers (the `torch.optim` API)

**Metadata** — Tier: 4 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: Medium · Hands-on: Very high
Prerequisites: 4.5–4.9 Update rules, 4.28 nn.Module · Leads to: 4.10 Scheduling (in code), 4.34 Optimizer sharding

> **In plain words**
> Concepts 4.5–4.9 explained *what* SGD, momentum, Adam and AdamW do. This page is about *how you use them in PyTorch*: an optimizer is an object you create with the model's parameters and a learning rate, and which then does `zero_grad()` and `step()`. The useful extras are **parameter groups** (different settings for different layers), the **state dictionary** (for checkpoints), and knowing which optimizer to reach for.

**You need first:** 4.5–4.9 (update rules), 4.28 nn.Module.

> **Figure 4.29-1 — the optimizer object**
>
> ```mermaid
> flowchart LR
>     P["model.parameters()"] --> O["optimizer<br/>(lr, weight decay, betas…)"]
>     O --> Z["zero_grad()"]
>     O --> S["step()<br/>reads .grad, updates weights"]
>     O --> SD["state_dict()<br/>(momentum, Adam m and v)"]
> ```
>
> *How to read it:* the optimizer holds **references** to the parameters, per-group settings and per-parameter state. `zero_grad` clears `.grad`; `step` applies the update rule; `state_dict` is saved in checkpoints (4.20).

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| `torch.optim` | PyTorch's optimizer package |
| param group | a set of parameters with shared hyperparameters |
| `defaults` | settings applied to groups that do not override them |

### 1. What is it?
Classes such as `SGD`, `Adam`, `AdamW`, `RMSprop`, `Adagrad`, each implementing an update rule over a collection of parameters.

### 2. Why does it exist?
It separates the update logic from the model. You can swap optimizers with one line and reuse the same loop.

### 3. Detailed explanation
- **Creation:** `opt = torch.optim.AdamW(model.parameters(), lr=3e-4, weight_decay=0.1)`.
- **Per-step calls:** `opt.zero_grad(set_to_none=True)` (default in recent versions; saves memory and time), `loss.backward()`, `opt.step()`.
- **Parameter groups:** pass a list of dicts, each with `params` and its own settings. Uses: no weight decay on biases/norms (4.9), a smaller learning rate for pretrained layers, or different rates for adapters.
- **Reading and changing the learning rate:** `opt.param_groups[i]["lr"]` (schedulers do this, 4.10).
- **State:** momentum buffers and Adam's moments are created lazily at the first `step()` and keyed by parameter. `opt.state_dict()` / `load_state_dict()` save and restore them.
- **Choosing:** AdamW for Transformers and most fine-tuning; SGD + momentum for many vision models; Adam when you want robust defaults; Adafactor/8-bit variants to save memory (REVIEW_REQUIRED).
- **Adding parameters later:** `opt.add_param_group(...)` for new layers (progressive unfreezing).
- **Frozen parameters** (`requires_grad=False`) have no gradient and are skipped.
- **Speed:** `fused=True` (GPU) or `foreach=True` use fewer kernel launches.
- **Closure:** optimizers like L-BFGS need `opt.step(closure)` that re-evaluates the loss.
- **Pitfalls:** creating the optimizer **before** moving the model to the GPU (older code), forgetting that new layers are not in the optimizer, using `model.parameters()` twice with different groups (a parameter may appear in only one group).
- **Learning-rate finder:** try an exponentially increasing lr for some steps and pick a value a bit below where the loss starts to rise.

### 4. How does it work?
`step()` loops over groups and parameters, reads `p.grad`, updates the per-parameter state, and modifies `p` in place under `no_grad`.

### 5. Simple example
A coach (optimizer) with a clipboard (state): for each athlete (parameter) the coach reads today's feedback (grad), consults notes from earlier days (state), and decides the next adjustment.

**By hand.** Two groups: layer 1 with `lr 1e-3`, layer 2 with `lr 1e-2`; the same gradient value moves layer 2's weights ten times as much.

### 6. Technical example

### 7. Code
**① By hand (plain Python).** A tiny optimizer class with groups and state.

```python
class TinySGD:
    def __init__(self, groups, momentum=0.0):
        self.groups = groups                                          # each: {"params": [list of [value, grad]], "lr": ...}
        self.momentum = momentum
        self.state = {}
    def step(self):
        for g in self.groups:
            for p in g["params"]:
                v = self.momentum * self.state.get(id(p), 0.0) + p[1]
                self.state[id(p)] = v
                p[0] -= g["lr"] * v

a, b = [1.0, 0.5], [1.0, 0.5]                                         # [value, gradient]
opt = TinySGD([{"params": [a], "lr": 0.01}, {"params": [b], "lr": 0.1}])
opt.step()
print("slow group:", a[0], "   fast group:", b[0], "   (same gradient, 10x different lr)")
```

```text
slow group: 0.995    fast group: 0.95    (same gradient, 10x different lr)
```

**② With NumPy.** The same update rule written as a function with explicit state.

```python
import numpy as np

def adam_step(p, g, state, lr=0.1, b1=0.9, b2=0.999, eps=1e-8):
    state["t"] = state.get("t", 0) + 1
    state["m"] = b1 * state.get("m", 0) + (1 - b1) * g
    state["v"] = b2 * state.get("v", 0) + (1 - b2) * g * g
    mh, vh = state["m"] / (1 - b1 ** state["t"]), state["v"] / (1 - b2 ** state["t"])
    return p - lr * mh / (np.sqrt(vh) + eps)

p, st = np.array([1.0, -2.0]), {}
for _ in range(3):
    p = adam_step(p, 2 * p, st)                                        # gradient of sum(p^2)
print("after 3 Adam steps:", p.round(4), "   state keys:", sorted(st))
```

```text
after 3 Adam steps: [ 0.7016 -1.7006]    state keys: ['m', 't', 'v']
```

**③ With PyTorch.** Parameter groups, state, and the same loop with different optimizers.

```python
import torch
from torch import nn

torch.manual_seed(0)
model = nn.Sequential(nn.Linear(4, 8), nn.ReLU(), nn.Linear(8, 1))
opt = torch.optim.AdamW([{"params": model[0].parameters(), "lr": 1e-3}, {"params": model[2].parameters(), "lr": 1e-2}], weight_decay=0.01)
print("groups:", len(opt.param_groups), "   learning rates:", [g["lr"] for g in opt.param_groups])
print("state before first step:", len(opt.state), "entries")
model(torch.randn(16, 4)).sum().backward(); opt.step(); opt.zero_grad(set_to_none=True)
print("state after first step :", len(opt.state), "entries (one per parameter tensor)")
print("a gradient after zero_grad(set_to_none=True):", model[0].weight.grad)

X = torch.randn(256, 4); y = X.sum(dim=1, keepdim=True)
for name, make in (("SGD+momentum", lambda p: torch.optim.SGD(p, lr=0.02, momentum=0.9)), ("Adam", lambda p: torch.optim.Adam(p, lr=0.02)), ("AdamW", lambda p: torch.optim.AdamW(p, lr=0.02))):
    torch.manual_seed(0)
    m = nn.Sequential(nn.Linear(4, 8), nn.ReLU(), nn.Linear(8, 1)); o = make(m.parameters())
    for _ in range(100):
        o.zero_grad(); loss = nn.functional.mse_loss(m(X), y); loss.backward(); o.step()
    print(f"{name:<13}: loss after 100 steps = {loss.item():.4f}")
```

```text
groups: 2    learning rates: [0.001, 0.01]
state before first step: 0 entries
state after first step : 4 entries (one per parameter tensor)
a gradient after zero_grad(set_to_none=True): None
SGD+momentum : loss after 100 steps = 0.0020
Adam         : loss after 100 steps = 0.0075
AdamW        : loss after 100 steps = 0.0075
```

### 9. Enterprise use case
Optimizer choice and settings are part of reproducible training configs (4.21).

### 10. AI engineering connection
LLM recipes specify AdamW with grouped weight decay; fine-tuning uses grouped learning rates; LoRA trains only adapter parameters.

### 11. Advantages
One-line swaps; groups give fine control; fused versions are fast.

### 12. Limitations
State doubles or triples memory; groups can be misconfigured silently.

### 13. Trade-offs
More adaptive optimizers need more memory.

### 14. Common mistakes
Not adding new layers to the optimizer; same parameter in two groups; forgetting `zero_grad`; saving the model but not the optimizer; changing `lr` without updating the scheduler; using different hyperparameters than the recipe.

### 15. Performance / cost
Prefer `fused=True` on GPU; shard optimizer state across devices for big models (4.34).

### 16. Security
Optimizer state files are as sensitive as weights.

</details>

### 20. Hands-on exercise
**Goal:** add a new layer to an existing optimizer.

1. Create a model with one `Linear(2, 2)` and `SGD(lr=0.1)`.
2. Create a new `Linear(2, 1)` and add it with `add_param_group`.
3. Run one step on a loss through both and print that both weights changed.

<details>
<summary>Show a solution</summary>

```python
import torch
from torch import nn

torch.manual_seed(0)
first, head = nn.Linear(2, 2), nn.Linear(2, 1)
opt = torch.optim.SGD(first.parameters(), lr=0.1)
opt.add_param_group({"params": head.parameters(), "lr": 0.05})
before = [first.weight.clone(), head.weight.clone()]
head(first(torch.randn(8, 2))).sum().backward()
opt.step()
print("first layer changed:", not torch.equal(before[0], first.weight))
print("new head changed   :", not torch.equal(before[1], head.weight))
print("number of param groups:", len(opt.param_groups))
```
