> **In plain words**
> A **tensor** is PyTorch's version of a NumPy array: a grid of numbers with a **shape**, a **dtype** (number format) and a **device** (CPU or GPU). Two extra powers make it the foundation of deep learning: it can live on a **GPU**, and it can **remember how it was computed** so PyTorch can differentiate it (`requires_grad`).

**You need first:** 1.2–1.4 (vectors, matrices, tensors), 4.16 (dtypes).

### 1. What is it?
`torch.Tensor`: a multi-dimensional array with a dtype, a device, and optional gradient tracking.

### 2. Why does it exist?
NumPy arrays can't run on GPUs or track gradients. Tensors are NumPy-like, with those abilities added.

### 3. Detailed explanation
- **Creating:** `torch.tensor(list)`, `torch.zeros(shape)`, `torch.randn(shape)`, `torch.arange`, `torch.from_numpy(array)` (shares memory).
- **Shape tools:** `.shape`, `.reshape`, `.view`, `.unsqueeze`, `.squeeze`, `.permute`, `.T`. A `view` shares memory with the original, so changing one changes the other (code ③).
- **dtypes:** `float32` (default for floats), `int64` (default for integers), `bool`, `bfloat16`... Mixed dtypes in an operation are promoted; losses need float predictions and integer class labels.
- **Devices:** `.to("cuda")`; operations need operands on the same device (4.23).
- **Autograd:** `requires_grad=True` records operations; `.backward()` fills `.grad` (4.4). `.detach()` gives a tensor outside the graph; `with torch.no_grad():` disables tracking.
- **Broadcasting:** shapes align from the right; dimensions of size 1 are stretched (1.7).
- **Indexing and slicing** work like NumPy; boolean masks and `gather`/`index_select` for advanced selection.
- **In-place operations** (`x.add_(1)`, `x += 1`) save memory but can break autograd if a needed value is overwritten.
- **Conversions:** `.numpy()` (CPU only, shares memory), `.item()` (one-element tensor → Python number), `.tolist()`.
- **Memory:** `numel() × element_size()` bytes; `.contiguous()` fixes layout after a `permute`.
- **Reductions:** `sum`, `mean`, `max` with `dim=` and `keepdim=`; the most common source of shape bugs.
- **`einsum`** expresses many tensor operations compactly (used in attention, Tier 7).

### 4. How does it work?
A tensor is a pointer to a block of memory plus metadata (shape, strides, dtype, device); operations create new tensors, or views of the same memory.

### 5. Simple example
A spreadsheet that can also live on a faster computer (device) and keep a history of every formula that produced each cell (autograd).

**By hand.** Shape `(2, 3)` has 6 numbers; `float32` uses 4 bytes each, so 24 bytes. `reshape(3, 2)` has the same 6 numbers in a new arrangement.

### 6. Technical example
A batch of token ids has shape `(batch, sequence)` with dtype `int64`; after the embedding layer it is `(batch, sequence, hidden)` with dtype `float32` or `bfloat16`.

### 7. Code
**① By hand (plain Python).** Shape bookkeeping with nested lists.

```python
grid = [[1, 2, 3], [4, 5, 6]]                       # a 2x3 "tensor" as nested lists
rows, cols = len(grid), len(grid[0])
flat = [v for row in grid for v in row]
reshaped = [flat[i:i + rows] for i in range(0, len(flat), rows)]   # 3x2
print("shape:", (rows, cols), "   numbers:", rows * cols, "   as 3x2:", reshaped)
print("transpose:", [[grid[r][c] for r in range(rows)] for c in range(cols)])
```

```text
shape: (2, 3)    numbers: 6    as 3x2: [[1, 2], [3, 4], [5, 6]]
transpose: [[1, 4], [2, 5], [3, 6]]
```

**② With NumPy.** The same ideas in NumPy (PyTorch mirrors this API).

```python
import numpy as np

a = np.arange(6).reshape(2, 3)
print("a:\n", a)
print("a + [10, 20, 30] (broadcast):\n", a + np.array([10, 20, 30]))
print("sum over axis 0:", a.sum(axis=0), "  axis 1:", a.sum(axis=1))
print("keepdims shape:", a.sum(axis=1, keepdims=True).shape)
```

```text
a:
 [[0 1 2]
 [3 4 5]]
a + [10, 20, 30] (broadcast):
 [[10 21 32]
 [13 24 35]]
sum over axis 0: [3 5 7]   axis 1: [ 3 12]
keepdims shape: (2, 1)
```

**③ With PyTorch.** dtype, device, views, in-place edits and autograd.

```python
import torch

x = torch.arange(6, dtype=torch.float32).reshape(2, 3)
print("shape:", tuple(x.shape), " dtype:", x.dtype, " device:", x.device, " bytes:", x.numel() * x.element_size())

v = x.view(3, 2)                                  # shares memory
v[0, 0] = 100.0
print("changing the view changed the original:", x[0, 0].item())
c = x.clone(); c.add_(1)
print("editing a clone leaves the original alone:", x[0, 0].item() == 100.0 and c[0, 0].item() == 101.0)

w = torch.tensor([1.0, 2.0], requires_grad=True)
y = (w ** 2).sum()
y.backward()
print("gradient of sum(w^2):", w.grad.tolist(), "   y requires grad:", y.requires_grad, "   detached:", y.detach().requires_grad)

labels = torch.tensor([0, 2, 1])
print("class labels dtype:", labels.dtype, "(cross_entropy expects int64 labels, float logits)")
print("int + float promotes to:", (torch.tensor([1]) + torch.tensor([0.5])).dtype)
```

```text
shape: (2, 3)  dtype: torch.float32  device: cpu  bytes: 24
changing the view changed the original: 100.0
editing a clone leaves the original alone: True
gradient of sum(w^2): [2.0, 4.0]    y requires grad: True    detached: False
class labels dtype: torch.int64 (cross_entropy expects int64 labels, float logits)
int + float promotes to: torch.float32
```

### 9. Enterprise use case
Tensor shapes and dtypes are the contract between data pipelines, models and serving; shape tests catch integration bugs.

### 10. AI engineering connection
Everything in LLMs is tensors: tokens, embeddings, attention scores, KV caches, weights.

### 11. Advantages
NumPy-like, GPU-ready, differentiable.

### 12. Limitations
Easy to create silent shape/broadcast bugs; GPU memory is limited.

### 13. Trade-offs
Views save memory but create aliasing; copies are safe but cost memory.

### 14. Common mistakes
Wrong `dim` in reductions; broadcasting surprises; mutating a view; mixing devices; integer labels as float; `.numpy()` on a tensor that requires grad or lives on the GPU; accumulating tensors with graphs in a list.

### 15. Performance / cost
Prefer batched tensor operations to Python loops; avoid unnecessary copies and host-device transfers.

### 16. Security
Loading tensors from untrusted pickles can run code; use safe formats.

### 17. Interview explanation
"A tensor is a typed, shaped array that can live on CPU or GPU and optionally record operations for autodiff. Most bugs come from shape, dtype, device or requires_grad; views share memory while clone copies; and broadcasting aligns shapes from the right."

### 18. Rapid-fire answer
Array + dtype + device + `requires_grad`; views share memory; broadcasting from the right; `.item()`, `.detach()`, `.to()`.

### 20. Hands-on exercise
**Goal:** predict and check broadcasting shapes.

1. Create `a` of shape `(4, 1, 3)` and `b` of shape `(5, 1)`.
2. What is the shape of `a + b`? Predict, then check.
3. Sum over the last dimension keeping dims and print the shape.

<details>
<summary>Show a solution</summary>

```python
import torch

a = torch.zeros(4, 1, 3)
b = torch.zeros(5, 1)
c = a + b                                          # align from the right: (4,1,3) with (1,5,1) -> (4,5,3)
print("a + b shape:", tuple(c.shape))
print("sum over last dim, keepdim:", tuple(c.sum(dim=-1, keepdim=True).shape))
```

```text
a + b shape: (4, 5, 3)
sum over last dim, keepdim: (4, 5, 1)
```
