> **In plain words**
> `nn.Module` is PyTorch's **building block for models**. You write a class with two methods: `__init__` (create the layers and parameters) and `forward` (say how data flows through them). PyTorch automatically **collects every parameter**, moves them to a device together, switches train/eval mode, and saves/loads them. Modules can contain other modules, so you build big models from small ones, like Lego.

**You need first:** 4.27 PyTorch tensors, 3.17 MLP.

> **Figure 4.28-1 — a module is a tree of modules**
>
> ```mermaid

>     M --> B["ReLU"]

>
> *How to read it:* the network is a parent module holding child modules. Only some leaves own **parameters** (the numbers training will change). Calling `model.parameters()` walks the whole tree and collects all of them, which is exactly what the optimizer needs.

### 1. What is it?
The base class `torch.nn.Module`. Subclass it, define layers in `__init__`, define `forward`, and call the module like a function: `model(x)`.

### 2. Why does it exist?
Models need bookkeeping: which tensors are trainable, what to save, which mode we're in, which device they're on. `Module` does all of this automatically for anything assigned as an attribute.

### 3. Detailed explanation
- **Define:** call `super().__init__()` first; assign layers as attributes (`self.fc = nn.Linear(...)`); they are auto-registered.
- **Call `model(x)`, not `model.forward(x)`:** `__call__` runs hooks and extra logic around `forward` (4.37).
- **`parameters()` / `named_parameters()`** list trainable tensors; `numel()` counts them (code ③).
- **`state_dict()`** returns names → tensors, including buffers. `load_state_dict` restores them. Names come from attribute paths (`fc.weight`) and must match (4.20).
- **Registering a plain tensor** as an attribute does *not* make it a parameter; use `nn.Parameter` or `register_buffer` (buffers move devices and get saved, but aren't trained).
- **Containers:** `nn.Sequential` for simple chains, `nn.ModuleList` / `nn.ModuleDict` for lists/dicts of modules (a plain Python list is **not** registered!).
- **Modes:** `model.train()` and `model.eval()` set `training` on every sub-module (dropout, BatchNorm).
- **Devices and dtypes:** `model.to("cuda")`, `model.to(torch.bfloat16)` move/cast every parameter and buffer.
- **Freezing:** `p.requires_grad_(False)` for parameters you don't want to train (fine-tuning).
- **Hooks** attach functions to forward/backward for monitoring (4.37).
- **Weight tying, shared modules:** the same module object used twice shares parameters (embedding/output tying in LLMs).
- **`torch.compile(model)`** optimizes the module (REVIEW_REQUIRED).
- **Inspecting:** `print(model)` shows the tree; `sum(p.numel() for p in model.parameters())` counts parameters.

### 4. How does it work?
`__setattr__` intercepts attributes: parameters go into `_parameters`, sub-modules into `_modules`, buffers into `_buffers`. Methods like `.parameters()` walk those dictionaries recursively.

### 5. Simple example
A Lego kit with a parts list: each model is built from smaller blocks, and the kit can list all parts, pack them, and ship them as one box.

**By hand.** `Linear(784, 128)` has `784×128 + 128 = 100,480` parameters; `Linear(128, 10)` has `1,290`. Total 101,770.

### 7. Code
**① By hand (plain Python).** A tiny module system that collects parameters from children.

```python
class Param:
    def __init__(self, value):
        self.value = value

class Module:
    def parameters(self):
        found = []
        for v in vars(self).values():
            if isinstance(v, Param):
                found.append(v)
            elif isinstance(v, Module):
                found += v.parameters()
        return found
    def __call__(self, x):
        return self.forward(x)

class Scale(Module):
    def __init__(self, a):
        self.a = Param(a)
    def forward(self, x):
        return self.a.value * x

class Net(Module):
    def __init__(self):
        self.first, self.second = Scale(2.0), Scale(3.0)
    def forward(self, x):
        return self.second(self.first(x))

net = Net()
print("net(1.5) =", net(1.5), "   parameters found:", [p.value for p in net.parameters()])
```

```text
net(1.5) = 9.0    parameters found: [2.0, 3.0]
```

**② With NumPy.** A "layer" as a function plus explicit parameters (what Module automates).

```python
import numpy as np

rng = np.random.default_rng(0)
params = {"W1": rng.normal(0, 0.1, (4, 3)), "b1": np.zeros(4), "W2": rng.normal(0, 0.1, (2, 4)), "b2": np.zeros(2)}

def forward(params, x):
    return np.maximum(0, x @ params["W1"].T + params["b1"]) @ params["W2"].T + params["b2"]

print("output shape:", forward(params, rng.normal(size=(5, 3))).shape)
print("parameter count:", sum(v.size for v in params.values()))
print("names (like a state_dict):", list(params))
```

```text
output shape: (5, 2)
parameter count: 26
names (like a state_dict): ['W1', 'b1', 'W2', 'b2']
```

**③ With PyTorch.** A real module, its parameters, and two classic pitfalls.

```python
import torch
from torch import nn

class MLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1, self.fc2 = nn.Linear(784, 128), nn.Linear(128, 10)
        self.drop = nn.Dropout(0.1)
    def forward(self, x):
        return self.fc2(self.drop(torch.relu(self.fc1(x))))

model = MLP()
print("parameters:", sum(p.numel() for p in model.parameters()))
print("state_dict keys:", list(model.state_dict().keys()))
model.eval()
print("training flag of a child after eval():", model.drop.training)

class Bad(nn.Module):
    def __init__(self):
        super().__init__()
        self.layers = [nn.Linear(2, 2), nn.Linear(2, 2)]           # a plain list: NOT registered
class Good(nn.Module):
    def __init__(self):
        super().__init__()
        self.layers = nn.ModuleList([nn.Linear(2, 2), nn.Linear(2, 2)])
print("parameters seen with a plain list :", len(list(Bad().parameters())))
print("parameters seen with ModuleList   :", len(list(Good().parameters())))
```

```text
parameters: 101770
state_dict keys: ['fc1.weight', 'fc1.bias', 'fc2.weight', 'fc2.bias']
training flag of a child after eval(): False
parameters seen with a plain list : 0
parameters seen with ModuleList   : 4
```

### 9. Enterprise use case
Standardized modules make models portable, testable and serializable across teams.

### 10. AI engineering connection
Hugging Face models, LoRA adapters and quantization wrappers are all `nn.Module` subclasses/wrappers.

### 11. Advantages
Automatic parameter tracking, saving, device moves, composability.

### 12. Limitations
Python overhead; implicit registration rules cause silent bugs.

### 13. Trade-offs
Deep nesting is flexible but harder to read and compile.

### 14. Common mistakes
Forgetting `super().__init__()`; storing layers in a plain list; calling `forward` directly; using Python control flow on tensors in ways that break tracing; reusing a module unintentionally (shared weights); forgetting `eval()`.

### 15. Performance / cost
Fuse small ops (`torch.compile`); avoid creating tensors inside `forward` on the wrong device.

### 16. Security
Loading pickled whole modules can run code; save `state_dict`s and load with weights-only loading.

</details>

### 17. Interview explanation
"`nn.Module` is a container that auto-registers parameters, buffers and sub-modules assigned in `__init__`; `forward` defines the computation and `model(x)` calls it with hooks. Registration enables `parameters()` for the optimizer, `state_dict()` for checkpoints, `.to()` for devices and `.train()/.eval()` for modes. A plain Python list of layers isn't registered; use ModuleList."

### 18. Rapid-fire answer
Subclass `nn.Module`; layers in `__init__`, flow in `forward`; auto-registered parameters; `ModuleList` for lists; `state_dict`, `.to`, `.train/.eval`.

### 20. Hands-on exercise
**Goal:** write a residual block module and count its parameters.

1. A module with `LayerNorm(16)` and `Linear(16, 16)`, whose forward returns `x + linear(norm(x))`.
2. Print the parameter count and check the output shape for input `(4, 16)`.

<details>
<summary>Show a solution</summary>

```python
import torch
from torch import nn

class ResidualBlock(nn.Module):
    def __init__(self, d):
        super().__init__()
        self.norm, self.fc = nn.LayerNorm(d), nn.Linear(d, d)
    def forward(self, x):
        return x + self.fc(self.norm(x))

block = ResidualBlock(16)
print("parameters:", sum(p.numel() for p in block.parameters()), "(LayerNorm 32 + Linear 272)")
print("output shape:", tuple(block(torch.randn(4, 16)).shape))
```

```text
parameters: 304 (LayerNorm 32 + Linear 272)
output shape: (4, 16)
```
