# 4.9 AdamW

**Metadata** — Tier: 4 · Phase: 1 · Priority: P0 · Difficulty: 3/5 · Interview: Very high · Hands-on: High
Prerequisites: 3.29 Weight decay, 4.8 Adam · Leads to: 4.10 Scheduling, Tier 8–10 LLM training

> **In plain words**
> **AdamW** is Adam with **weight decay done the right way**. Ordinary "L2 in the loss" gets mixed up with Adam's per-weight scaling, so the shrinking is uneven and weaker than intended. AdamW applies the shrink **directly to the weights**, separate from the gradient step: `w ← w − lr·(Adam step) − lr·λ·w`.
> It is the standard optimizer for Transformers and LLMs.

**You need first:** 3.29 Weight decay, 4.8 Adam.

>

> *How to read it:* in Adam + L2 the decay term `λw` is added to the gradient and then divided by `√v` like everything else, so weights with large gradients are decayed less and weights with small gradients more. In AdamW the decay bypasses that scaling and shrinks every weight by the same relative amount.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| weight decay `λ` | shrink weights by a fraction `lr·λ` each step |
| L2 regularization | adding `λ/2·‖w‖²` to the loss |
| decoupled | decay is separate from the gradient step |
| parameter groups | some parameters get no decay |
| no-decay set | biases and normalization parameters |
| `betas` | Adam's `(β₁, β₂)` |

### 1. What is it?
Adam with decoupled weight decay (Loshchilov & Hutter, 2017/2019): `θ ← θ − η·( m̂/(√v̂ + ε) + λθ )`.

### 2. Why does it exist?
For SGD, L2 in the loss and weight decay are identical (3.29). For Adam they are not, because Adam rescales the gradient (including the L2 part). Decoupling restores the intended behaviour and makes the best `λ` less dependent on the learning rate.

### 3. Detailed explanation
- **Adam + L2 behaviour.** The decay gradient `λw` is divided by `√v`. Large-gradient weights are barely decayed; small-gradient weights are decayed a lot. Code ③ shows the update sizes differ.
- **AdamW behaviour.** Every weight shrinks by the factor `(1 − lr·λ)` per step, independent of its gradient history.
- **Typical values.** `weight_decay` 0.01–0.1; LLM pre-training commonly uses 0.1 with `betas=(0.9, 0.95)` (REVIEW_REQUIRED).
- **Which parameters are decayed.** Usually matrices (linear and embedding weights) but not biases or LayerNorm/RMSNorm gains; build two parameter groups (code ③).
- **Interaction with the schedule.** The effective decay per step is `lr·λ`, so as the learning rate decays the decay shrinks too.
- **Interaction with normalization.** For weights followed by a norm layer, decay mainly changes the effective learning rate (3.29).
- **Memory and cost** are the same as Adam (2× model state).
- **In PyTorch** `torch.optim.AdamW` is separate from `torch.optim.Adam(weight_decay=...)`, which is the *coupled* L2 version. Mixing them up is a very common mistake.
- **Defaults differ:** `AdamW` defaults to `weight_decay=0.01`, `Adam` to 0.

### 4. How does it work?
Compute the Adam step; separately shrink the weights by `lr·λ`; apply both.

### 5. Simple example
Two ways to reduce a savings account fee: take a fixed percentage of every account (AdamW), or let each account's fee depend on how active it is (Adam + L2): the fee ends up uneven.

**By hand.** `lr = 0.1`, `λ = 0.5`, weight `w = 2`, Adam step 0.05. AdamW: `2 − 0.05 − 0.1·0.5·2 = 1.85`: the decay removed 0.10. With L2 coupled into Adam, the decay's influence depends on `√v`.

### 6. Technical example
`torch.optim.AdamW([{"params": decay, "weight_decay": 0.1}, {"params": no_decay, "weight_decay": 0.0}], lr=3e-4, betas=(0.9, 0.95))`.

### 7. Code
**① By hand (plain Python).** One step of each, from the same state.

```python
import math

w, g, lr, wd = 2.0, 0.5, 0.1, 0.5
m, v = (1 - 0.9) * g, (1 - 0.999) * g * g
adam_dir = (m / (1 - 0.9)) / (math.sqrt(v / (1 - 0.999)) + 1e-8)      # first Adam step direction: about 1

adamw = w - lr * adam_dir - lr * wd * w                               # decay applied to the weight itself
g2 = g + wd * w                                                       # L2 version: decay joins the gradient...
m2, v2 = (1 - 0.9) * g2, (1 - 0.999) * g2 * g2
adam_l2 = w - lr * (m2 / (1 - 0.9)) / (math.sqrt(v2 / (1 - 0.999)) + 1e-8)  # ...then gets rescaled
print("AdamW      new weight:", round(adamw, 4), "  (step 0.1 + decay 0.1)")
print("Adam + L2  new weight:", round(adam_l2, 4), "  (the decay got normalized away)")
```

```text
AdamW      new weight: 1.8   (step 0.1 + decay 0.1)
Adam + L2  new weight: 1.9   (the decay got normalized away)
```

**② With NumPy.** Decay strength under both methods for weights with very different gradient sizes.

```python
import numpy as np

lr, wd = 0.01, 0.1
w = np.ones(3)
g = np.array([0.001, 0.1, 10.0])                                     # tiny, medium, huge gradients
b1, b2 = 0.9, 0.999

def first_step(grad):
    m, v = (1 - b1) * grad, (1 - b2) * grad ** 2
    return lr * (m / (1 - b1)) / (np.sqrt(v / (1 - b2)) + 1e-8)

adam_l2 = first_step(g + wd * w)                                     # decay inside the gradient
adamw = first_step(g) + lr * wd * w                                  # decay outside
print("gradient sizes        :", g)
print("Adam+L2 total change  :", adam_l2.round(5), "<- about lr for every weight")
print("AdamW total change    :", adamw.round(5), "<- Adam step plus a fixed lr*wd*w =", lr * wd)
```

```text
gradient sizes        : [1.e-03 1.e-01 1.e+01]
Adam+L2 total change  : [0.01 0.01 0.01] <- about lr for every weight
AdamW total change    : [0.011 0.011 0.011] <- Adam step plus a fixed lr*wd*w = 0.001
```

**③ With PyTorch.** The two classes behave differently, and the no-decay groups.

```python
import torch

def one_step(opt_cls, **kw):
    w = torch.nn.Parameter(torch.tensor([1.0, 1.0]))
    opt = opt_cls([w], lr=0.1, **kw)
    (w * torch.tensor([0.01, 10.0])).sum().backward()                # gradients 0.01 and 10
    opt.step()
    return w.detach().numpy().round(4)

print("Adam  weight_decay=0.5 (L2):", one_step(torch.optim.Adam, weight_decay=0.5))
print("AdamW weight_decay=0.5     :", one_step(torch.optim.AdamW, weight_decay=0.5))

model = torch.nn.Sequential(torch.nn.Linear(4, 4), torch.nn.LayerNorm(4))
decay = [p for n, p in model.named_parameters() if p.dim() >= 2]
no_decay = [p for n, p in model.named_parameters() if p.dim() < 2]
opt = torch.optim.AdamW([{"params": decay, "weight_decay": 0.1}, {"params": no_decay, "weight_decay": 0.0}], lr=1e-3)
print("parameters decayed:", sum(p.numel() for p in decay), "   not decayed (biases, norm gains):", sum(p.numel() for p in no_decay))
```

```text
Adam  weight_decay=0.5 (L2): [0.9 0.9]
AdamW weight_decay=0.5     : [0.85 0.85]
parameters decayed: 16    not decayed (biases, norm gains): 12
```

### 9. Enterprise use case
The standard recipe for fine-tuning and pre-training; the decay value and which parameters are excluded are logged hyperparameters.

### 10. AI engineering connection
Nearly all open LLM recipes use AdamW; LoRA fine-tuning typically uses it too.

### 11. Advantages
Cleaner regularization; `λ` and `lr` interact less; same cost as Adam.

### 12. Limitations
Still needs tuning of `λ`; 2× model-size state.

### 13. Trade-offs
Stronger decay regularizes more but can underfit.

### 14. Common mistakes
Using `Adam(weight_decay=…)` thinking it is AdamW; decaying biases and norm gains; copying a decay value tuned for a different learning rate; forgetting that the decay scales with the learning rate.

### 15. Performance / cost
Use fused kernels; consider 8-bit optimizer states for very large models.

### 16. Security
No direct issue.

</details>

### 17. Interview explanation
"AdamW decouples weight decay from Adam's gradient scaling: the weights shrink by lr·λ each step independent of their gradient history. With L2 inside Adam the penalty gets divided by the second-moment estimate, so decay is uneven. I use AdamW with decay on matrices only, warm-up and cosine decay."

### 18. Rapid-fire answer
Adam + decoupled decay: `θ −= lr·(adam_step + λθ)`; different from Adam + L2; exclude biases and norms; λ ≈ 0.01–0.1.

### 20. Hands-on exercise
**Goal:** watch weights shrink under pure decay.

1. A single weight starts at 1.0 with zero gradient.
2. Run `AdamW(lr=0.1, weight_decay=0.5)` for 20 steps.
3. Compare with `Adam(lr=0.1, weight_decay=0.5)` (the L2 version).

<details>
<summary>Show a solution</summary>

```python
import torch

for name, cls in (("AdamW", torch.optim.AdamW), ("Adam (L2)", torch.optim.Adam)):
    w = torch.nn.Parameter(torch.tensor([1.0]))
    opt = cls([w], lr=0.1, weight_decay=0.5)
    for _ in range(20):
        opt.zero_grad()
        (w * 0.0).sum().backward()                                    # zero data gradient
        opt.step()
    print(f"{name:<10}: weight after 20 steps = {w.item():.4f}   (pure decay would give {(1 - 0.1 * 0.5) ** 20:.4f})")
```

```text
AdamW     : weight after 20 steps = 0.3585   (pure decay would give 0.3585)
Adam (L2) : weight after 20 steps = -0.2712   (pure decay would give 0.3585)
```
