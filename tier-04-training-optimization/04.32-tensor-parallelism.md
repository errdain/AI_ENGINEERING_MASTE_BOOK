# 4.32 Model / tensor parallelism

**Metadata** — Tier: 4 · Phase: 1 · Priority: P1 · Difficulty: 4/5 · Interview: High · Hands-on: Low
Prerequisites: 4.30 Distributed training intro, 3.16 Dense layer · Leads to: 4.33 Pipeline parallelism, Tier 12 LLM scaling

> **In plain words**
> When a single layer's weight matrix is too big for one GPU, **tensor parallelism** cuts that matrix into pieces and puts one piece on each GPU. Every GPU does part of the multiplication, and a communication step combines the pieces. It is **model parallelism "inside" a layer**, in contrast to pipeline parallelism, which splits "between" layers (4.33).
> The key trick: split a matrix by **columns** and the partial outputs simply sit side by side; split it by **rows** and the partial outputs must be **added**.

**You need first:** 4.30 Distributed training intro, 3.16 Dense layer (matrix multiply).

> **Figure 4.32-1 — splitting a linear layer across two GPUs**
>
> ```mermaid
> flowchart LR
>     X["input x (copied to both)"] --> A["GPU 0: x · W[:, :half]"]
>     X --> B["GPU 1: x · W[:, half:]"]
>     A --> C["outputs side by side<br/>(concatenate)"]
>     B --> C
> ```
>
> *How to read it:* **column parallel**: each GPU owns half of the output columns, so each computes half of the output features from the full input; concatenating them gives the full output with no summing. In **row parallel** each GPU owns half of the input rows and gets half of the input; their partial results are summed with an all-reduce. Chaining column-parallel then row-parallel (the Transformer MLP pattern) needs just one all-reduce per block.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| tensor parallelism (TP) | splitting weight matrices across devices |
| column parallel | split `W` by output columns |
| row parallel | split `W` by input rows |
| all-reduce | sum partial results across GPUs |
| shard | one device's piece of a tensor |
| Megatron-LM | the system that popularized this for Transformers |
| TP degree | how many GPUs a layer is split across |

### 1. What is it?
Partitioning the matrices of a layer (and attention heads) across devices so each device computes a slice of the layer's output.

### 2. Why does it exist?
For very large models, even one layer's weights or one block's activations exceed a GPU. Splitting inside the layer lets several GPUs share one layer's work and memory.

### 3. Detailed explanation
- **Column split (`Y = XW`, `W = [W₁ | W₂]`):** `Y = [XW₁ | XW₂]`. The input is replicated; the outputs are concatenated. No communication in the forward pass if the next op can use the split output.
- **Row split (`W = [W₁; W₂]` stacked, `X = [X₁ | X₂]`):** `Y = X₁W₁ + X₂W₂`. Partial sums need an all-reduce.
- **Transformer MLP:** `Linear(d, 4d)` column-parallel, GELU applied locally to each shard (works because it is elementwise), `Linear(4d, d)` row-parallel, then one all-reduce. Same trick for attention: split heads across GPUs, output projection row-parallel.
- **Communication:** two all-reduces per Transformer layer in forward and two in backward. That is a lot of traffic, so TP is used **within a node** with fast links (NVLink), typically degree 2–8.
- **Memory:** weights, gradients and optimizer state shrink by the TP degree; activations are partly reduced.
- **Embedding and output layers** are split across the vocabulary dimension.
- **Combination:** TP inside a node + pipeline across nodes + data parallel across replicas ("3D parallelism").
- **Not free:** small matrices don't benefit (communication outweighs compute).
- **Numerics:** the order of additions changes results slightly versus a single GPU (4.21).
- **Sequence/context parallelism** splits along the sequence dimension for long inputs (REVIEW_REQUIRED).

### 4. How does it work?
Shard the weights; replicate or split the input accordingly; compute locally; combine by concatenation (column) or sum (row).

### 5. Simple example
Two chefs share one huge recipe card: each prepares half of the dishes (columns), or each does half of the steps of every dish and then they combine (rows).

**By hand.** `x = [1, 2]`, `W = [[1, 2, 3, 4], [5, 6, 7, 8]]`. Column split: GPU 0 gets columns 1–2 → `[1·1+2·5, 1·2+2·6] = [11, 14]`; GPU 1 → `[1·3+2·7, 1·4+2·8] = [17, 20]`; joined: `[11, 14, 17, 20]`.

### 6. Technical example
Megatron-LM style TP degree 8 within a DGX node for a 70B-parameter model (REVIEW_REQUIRED: illustrative).

### 7. Code
**① By hand (plain Python).** Column split and row split on the tiny example.

```python
x = [1, 2]
W = [[1, 2, 3, 4], [5, 6, 7, 8]]                                   # 2 inputs -> 4 outputs

def matvec(x, W):
    return [sum(x[i] * W[i][j] for i in range(len(x))) for j in range(len(W[0]))]

full = matvec(x, W)
left = matvec(x, [row[:2] for row in W])                           # GPU 0 owns the first two columns
right = matvec(x, [row[2:] for row in W])                          # GPU 1 owns the last two columns
print("full result      :", full)
print("column parallel  :", left + right, "(concatenated)")

part0 = [x[0] * W[0][j] for j in range(4)]                         # row parallel: GPU 0 owns row 0, sees x[0]
part1 = [x[1] * W[1][j] for j in range(4)]                         # GPU 1 owns row 1, sees x[1]
print("row parallel     :", [a + b for a, b in zip(part0, part1)], "(partials added by an all-reduce)")
```

```text
full result      : [11, 14, 17, 20]
column parallel  : [11, 14, 17, 20] (concatenated)
row parallel     : [11, 14, 17, 20] (partials added by an all-reduce)
```

**② With NumPy.** The Transformer MLP pattern: column then row, one sum at the end.

```python
import numpy as np

rng = np.random.default_rng(0)
d, h = 8, 32
x = rng.normal(size=(5, d))
W1, W2 = rng.normal(size=(d, h)), rng.normal(size=(h, d))
gelu = lambda v: 0.5 * v * (1 + np.tanh(0.79788456 * (v + 0.044715 * v ** 3)))

full = gelu(x @ W1) @ W2
gpus = 4
outs = []
for k in range(gpus):                                              # each "GPU" holds a slice of the hidden units
    sl = slice(k * h // gpus, (k + 1) * h // gpus)
    local_hidden = gelu(x @ W1[:, sl])                              # column parallel; GELU is local
    outs.append(local_hidden @ W2[sl, :])                           # row parallel partial result
tp = sum(outs)                                                      # the single all-reduce
print("tensor-parallel MLP equals the single-device MLP:", np.allclose(full, tp))
print("weights per GPU:", (W1[:, :h // gpus].size + W2[:h // gpus, :].size), "of", W1.size + W2.size)
```

```text
tensor-parallel MLP equals the single-device MLP: True
weights per GPU: 128 of 512
```

**③ With PyTorch.** A column-parallel plus row-parallel module on one machine (simulated shards).

```python
import torch

torch.manual_seed(0)
lin1, lin2 = torch.nn.Linear(8, 32, bias=False), torch.nn.Linear(32, 8, bias=False)
x = torch.randn(5, 8)
full = lin2(torch.nn.functional.gelu(lin1(x)))

shards = 4
w1 = lin1.weight.chunk(shards, dim=0)                              # (out, in): split the OUTPUT rows = column parallel
w2 = lin2.weight.chunk(shards, dim=1)                              # split the INPUT columns = row parallel
partials = [torch.nn.functional.gelu(x @ a.T) @ b.T for a, b in zip(w1, w2)]
tp = torch.stack(partials).sum(dim=0)                              # the all-reduce
print("equal to the unsplit layer:", torch.allclose(full, tp, atol=1e-5))
print("each shard holds", w1[0].numel() + w2[0].numel(), "weights instead of", lin1.weight.numel() + lin2.weight.numel())
```

```text
equal to the unsplit layer: True
each shard holds 128 weights instead of 512
```

### 9. Enterprise use case
Enables training and serving models whose layers don't fit on one device; node topology (NVLink) dictates the TP degree.

### 10. AI engineering connection
All 100B+ parameter models use TP in training and often in inference serving (Tier 11–12).

### 11. Advantages
Cuts per-device weight and activation memory; keeps compute busy within a layer.

### 12. Limitations
Heavy communication; complex code; best only on fast links.

### 13. Trade-offs
Higher TP degree saves memory but increases communication share.

### 14. Common mistakes
Using TP across slow inter-node links; odd head counts not divisible by the TP degree; forgetting to shard embeddings; mismatched shard layouts when loading checkpoints.

### 15. Performance / cost
Overlap communication, fuse kernels, keep TP within a node.

### 16. Security
Same as other distributed settings.

### 17. Interview explanation
"Tensor parallelism splits weight matrices across GPUs: column-parallel layers produce disjoint output slices, row-parallel layers produce partial sums that need an all-reduce. In a Transformer MLP a column-parallel first layer, a local GELU and a row-parallel second layer need one all-reduce per block, so I keep TP within a node on NVLink."

### 18. Rapid-fire answer
Split matrices: column → concatenate, row → sum (all-reduce); MLP = column then row (one all-reduce); intra-node only.
