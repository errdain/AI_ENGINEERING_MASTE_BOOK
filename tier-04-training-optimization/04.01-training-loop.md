# 4.1 Training loop

**Metadata** — Tier: 4 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: Very high · Hands-on: Very high
Prerequisites: 3.18 Forward propagation, 3.20 Backpropagation · Leads to: 4.2–4.5 (the four steps), 4.6–4.9 (optimizers)

> **In plain words**
> Training a model is **one small routine repeated thousands of times**: (1) look at some examples and make predictions, (2) measure how wrong they are, (3) work out which way to change each weight to be less wrong, (4) change the weights a little. That repeating routine is the **training loop**.
> It is like practising free throws: shoot, see how far you missed, adjust your aim a bit, shoot again.

**You need first:** 3.18 Forward propagation and 3.20 Backpropagation (what a forward and a backward pass are).

> **Figure 4.1-1 — one trip around the training loop**
>
> ```mermaid
> flowchart LR
>     B["1. take a batch<br/>of examples"] --> F["2. forward pass<br/>(predictions)"]
>     F --> L["3. loss<br/>(how wrong?)"]
>     L --> K["4. backward pass<br/>(gradients)"]
>     K --> U["5. update<br/>(change the weights)"]
>     U --> B
> ```
>
> *How to read it:* one lap around the circle is one **step**. Going through all the training examples once is an **epoch**. Training is just many laps until the loss stops improving. Each box is a concept of its own: 4.2 forward, 4.3 loss, 4.4 backward, 4.5 update.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| step (iteration) | one lap of the loop on one batch |
| batch | the small group of examples used in one step |
| epoch | one full pass over all training examples |
| loss | one number saying how wrong the predictions are |
| gradient | for each weight, which way and how strongly the loss changes |
| learning rate | how big a change we make to the weights |
| `zero_grad` | clear the gradients left from the previous step |

### 1. What is it?
The outer program that trains a neural network: repeat *forward → loss → backward → update* over batches of data, epoch after epoch, usually while checking progress on held-out data.

### 2. Why does it exist?
A model starts with random weights and makes bad predictions. Gradient descent (1.22) improves it, but only a little per step, and only using a few examples at a time (the whole dataset may not fit in memory). The loop is how many small improvements add up.

### 3. Detailed explanation
- **The five lines** in PyTorch: `optimizer.zero_grad()`, `loss = loss_fn(model(x), y)`, `loss.backward()`, `optimizer.step()` (and an outer `for batch in loader`). Everything else in Tier 4 is a refinement of one of these lines.
- **Epoch versus step.** With 1,000 examples and batch size 100, an epoch is 10 steps.
- **Shuffle** the training data every epoch so batches differ (2.19).
- **Why clear gradients?** PyTorch *adds* new gradients to old ones. If you forget `zero_grad`, step 2 uses step 1's gradient as well (code ③ shows it). This is deliberate: it makes gradient accumulation (4.14) possible.
- **Train and eval modes.** Before the loop `model.train()` (dropout and BatchNorm active); for validation `model.eval()` and `torch.no_grad()` (3.28, 3.30).
- **Validation** each epoch measures generalization, not memorization; the training loss alone can look perfect while the model is useless (2.27, 4.35–4.36).
- **What to log:** training loss, validation loss, learning rate, gradient norm, time per step (4.35–4.39).
- **Stopping:** after a fixed number of epochs or steps, or early stopping when validation stops improving (2.12).
- **Checkpoints** save progress so a crash does not lose days of work (4.20).

### 4. How does it work?
Start with random weights. For each batch: predict, compute the loss, compute gradients, nudge the weights opposite to the gradient. Repeat.

### 5. Simple example
**Practising free throws.** Shoot (forward), see how far you missed (loss), figure out how to change your aim (backward), adjust (update). One practice shot is one step; a full session is an epoch.

**A tiny worked step.** Fit `y = w·x` to one point `(x = 2, y = 6)` starting at `w = 0`, learning rate 0.1. Prediction 0; loss `(0 − 6)² = 36`; gradient `2(wx − y)x = 2(−6)(2) = −24`; update `w = 0 − 0.1·(−24) = 2.4`. Next step: prediction 4.8, error −1.2, gradient −4.8, `w = 2.88`. The weight is walking toward 3.

### 6. Technical example
Fine-tuning a language model: each step takes a batch of token sequences, computes cross-entropy on the next tokens, backpropagates, and updates with AdamW and a learning-rate schedule (4.9–4.12).

### 7. Code
Fit `y = 3x + 1` three ways.

**① By hand (plain Python).** The whole loop with no libraries.

```python
xs = [0.0, 1.0, 2.0, 3.0]
ys = [1.0, 4.0, 7.0, 10.0]                          # exactly y = 3x + 1
w, b, lr = 0.0, 0.0, 0.05

for epoch in range(1, 201):
    dw = db = loss = 0.0
    for x, y in zip(xs, ys):                        # forward + loss + gradient for every example
        err = (w * x + b) - y
        loss += err ** 2 / len(xs)
        dw += 2 * err * x / len(xs)
        db += 2 * err / len(xs)
    w -= lr * dw                                    # update
    b -= lr * db
    if epoch in (1, 10, 50, 200):
        print(f"epoch {epoch:>3}: loss {loss:8.4f}   w = {w:.3f}   b = {b:.3f}")
```

```text
epoch   1: loss  41.5000   w = 1.200   b = 0.550
epoch  10: loss   0.0255   w = 2.873   b = 1.240
epoch  50: loss   0.0021   w = 2.966   b = 1.073
epoch 200: loss   0.0000   w = 3.000   b = 1.001
```

**② With NumPy.** Same loop, with noisy data and mini-batches.

```python
import numpy as np

rng = np.random.default_rng(0)
X = rng.uniform(-1, 1, 200)
y = 3 * X + 1 + 0.1 * rng.normal(size=200)
w, b, lr, batch = 0.0, 0.0, 0.1, 20

for epoch in range(1, 21):
    order = rng.permutation(200)                                    # shuffle every epoch
    for i in range(0, 200, batch):                                  # 10 steps per epoch
        idx = order[i:i + batch]
        err = (w * X[idx] + b) - y[idx]
        w -= lr * 2 * (err * X[idx]).mean()
        b -= lr * 2 * err.mean()
    if epoch in (1, 5, 20):
        print(f"epoch {epoch:>2}: full-data loss {((w * X + b - y) ** 2).mean():.4f}   w = {w:.2f}   b = {b:.2f}")
```

```text
epoch  1: full-data loss 0.6839   w = 1.64   b = 0.97
epoch  5: full-data loss 0.0120   w = 2.92   b = 1.00
epoch 20: full-data loss 0.0104   w = 2.99   b = 1.00
```

**③ With PyTorch.** The standard five-line loop, and what happens if `zero_grad` is forgotten.

```python
import torch

torch.manual_seed(0)
X = torch.linspace(-1, 1, 200).unsqueeze(1)
y = 3 * X + 1 + 0.1 * torch.randn_like(X)

def train(zero_each_step, steps=100):
    model = torch.nn.Linear(1, 1)
    opt = torch.optim.SGD(model.parameters(), lr=0.1)
    for _ in range(steps):
        if zero_each_step:
            opt.zero_grad()                                          # clear old gradients
        loss = torch.nn.functional.mse_loss(model(X), y)
        loss.backward()                                              # adds to .grad
        opt.step()
    return loss.item(), model.weight.item()

print("with zero_grad    : loss %.4f  w = %.2f" % train(True))
print("without zero_grad : loss %.4f  w = %.2f" % train(False))
```

```text
with zero_grad    : loss 0.0092  w = 2.98
without zero_grad : loss 2.2105  w = 1.84
```

### 8. Input → Process → Output
`batches of (x, y) → forward → loss → backward → update (repeat) → trained weights`

### 9. Enterprise use case
Every training job in production is this loop wrapped with logging, checkpoints, retries and monitoring; reproducible loops make audits and rollbacks possible.

### 10. AI engineering connection
Pre-training, fine-tuning, RLHF and reward-model training all use this loop; only the data, loss and scale differ.

### 11. Advantages
Simple, general, scales from a laptop to thousands of GPUs.

### 12. Limitations
Many hyperparameters (learning rate, batch size, schedule); needs monitoring; can silently train on bad data.

### 13. Trade-offs
Large batches give smoother steps but fewer updates per epoch (4.13).

### 14. Common mistakes
Forgetting `zero_grad`; forgetting `model.eval()` for validation; evaluating on training data; shuffling validation data inconsistently; calling `backward` on a non-scalar; holding the loss tensor in a list (memory leak; use `.item()`).

### 15. Performance / cost
Data loading, host-to-device copies and logging can dominate the step time (4.25–4.26).

### 16. Security
Training data is an attack surface (poisoning, 2.8); log what data and code version were used.

### 20. Hands-on exercise
**Goal:** add validation and find the best epoch.

1. Make 100 noisy points of `y = 3x + 1`; use 80 for training and 20 for validation.
2. Train a `Linear(1, 1)` with SGD (lr 0.1) for 30 epochs, full batch.
3. Print the epoch with the lowest validation loss.

<details>
<summary>Show a solution</summary>

```python
import torch

torch.manual_seed(0)
X = torch.linspace(-1, 1, 100).unsqueeze(1)
y = 3 * X + 1 + 0.3 * torch.randn_like(X)
perm = torch.randperm(100)
tr, va = perm[:80], perm[80:]
model = torch.nn.Linear(1, 1)
opt = torch.optim.SGD(model.parameters(), lr=0.1)

best_epoch, best_val = 0, float("inf")
for epoch in range(1, 31):
    model.train(); opt.zero_grad()
    torch.nn.functional.mse_loss(model(X[tr]), y[tr]).backward(); opt.step()
    model.eval()
    with torch.no_grad():
        val = torch.nn.functional.mse_loss(model(X[va]), y[va]).item()
    if val < best_val:
        best_epoch, best_val = epoch, val
print(f"best epoch: {best_epoch}   validation loss: {best_val:.4f}")
```

```text
best epoch: 30   validation loss: 0.2142
```
