# 4.4 Backward pass

**Metadata** — Tier: 4 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: Very high · Hands-on: Very high
Prerequisites: 3.20 Backpropagation, 3.21 Automatic differentiation, 4.3 Loss · Leads to: 4.5 Parameter update, 4.15 Gradient clipping

> **In plain words**
> The **backward pass** is the step that works out, for **every weight**, **how much it contributed to the loss** (its *gradient*). In PyTorch it is one line: `loss.backward()`. Concept 3.20 explained the chain rule behind it; this page covers what it does **in practice**: where the gradients are stored, that they **add up** if you don't clear them, and what stops them (detach, no_grad).

**You need first:** 3.20 Backpropagation, 3.21 Automatic differentiation, 4.3 Loss.

> **Figure 4.4-1 — where gradients go**
>
> ```mermaid
> flowchart RL
>     L["loss (scalar)"] -->|"loss.backward()"| G["autograd walks the graph<br/>in reverse"]
>     G --> W1["layer 1: weight.grad"]
>     G --> W2["layer 2: weight.grad"]

>
> *How to read it:* `loss.backward()` starts at the scalar loss and walks the recorded graph backwards. For each parameter it **adds** the gradient into that parameter's `.grad` attribute. The optimizer (4.5) then reads `.grad`.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| gradient | how much the loss changes if a weight changes |
| `.grad` | where PyTorch stores a parameter's gradient |
| accumulate | new gradients are added to old ones |
| `requires_grad` | whether a tensor takes part in differentiation |
| `detach` | cut a tensor out of the graph |
| `retain_graph` | keep the graph after backward (rarely needed) |
| leaf tensor | a parameter or input (not computed from others) |

### 1. What is it?
Calling `loss.backward()` to compute `∂loss/∂θ` for every parameter `θ` with `requires_grad=True` and store it in `θ.grad`.

### 2. Why does it exist?
Gradient descent needs the gradient. Autograd (3.21) computes it exactly, at roughly twice the cost of a forward pass (3.20).

### 3. Detailed explanation
- **Starts from a scalar.** `backward()` on a one-number loss. For a non-scalar you must pass a gradient argument; the usual fix is to reduce first (4.3).
- **Accumulation.** `.grad` is *added to*. That is why `optimizer.zero_grad()` exists (4.1), and why gradient accumulation (4.14) simply delays the zeroing.
- **The graph is freed** after `backward()` (to save memory). Calling it twice on the same graph fails unless `retain_graph=True`.
- **Only leaf parameters keep `.grad`** by default.
- **Stopping gradients:** `tensor.detach()`, `torch.no_grad()`, integer operations and `argmax` cut the graph (3.19). Frozen layers (`requires_grad_(False)`) get no gradient: this is how fine-tuning freezes the base model.
- **Cost and memory.** The saved activations from the forward pass are consumed here (4.2). Backward costs about 2× the forward FLOPs (3.20).
- **Checks:** gradients should be finite and not all zero; monitor their norm (4.37). NaNs here mean something overflowed (4.38).
- **Higher-order and custom:** `torch.autograd.grad` returns gradients without touching `.grad`; custom `Function`s define their own backward.
- **Distributed training** averages gradients across devices during the backward pass (4.31).

### 4. How does it work?
Reverse traversal of the recorded graph, applying each operation's local derivative and summing contributions into each leaf's `.grad`.

### 5. Simple example
Tracing blame backwards: the final grade was low, so which earlier homework counted most?

**By hand.** `loss = (w·x − y)²` with `w = 1, x = 2, y = 6`: error `2 − 6 = −4`, `d loss/dw = 2·(−4)·2 = −16`.

### 6. Technical example
`loss.backward()` followed by `torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)` and `optimizer.step()` is the standard LLM training sequence (4.15).

### 7. Code
**① By hand (plain Python).** The gradient of a one-weight model, checked by nudging.

```python
w, x, y = 1.0, 2.0, 6.0
loss = lambda w: (w * x - y) ** 2
analytic = 2 * (w * x - y) * x
h = 1e-6
numeric = (loss(w + h) - loss(w - h)) / (2 * h)
print("analytic gradient:", analytic, "   by nudging w:", round(numeric, 4))
```

```text
analytic gradient: -16.0    by nudging w: -16.0
```

**② With NumPy.** The gradient of a linear layer with mean squared error.

```python
import numpy as np

rng = np.random.default_rng(0)
X, y = rng.normal(0, 1, (8, 3)), rng.normal(0, 1, 8)
w = rng.normal(0, 1, 3)
err = X @ w - y
grad = 2 * X.T @ err / len(y)                                   # d(mean squared error)/dw
loss = lambda w: ((X @ w - y) ** 2).mean()
h, num = 1e-6, np.zeros(3)
for i in range(3):
    e = np.zeros(3); e[i] = h
    num[i] = (loss(w + e) - loss(w - e)) / (2 * h)
print("backward formula:", grad.round(5))
print("by nudging      :", num.round(5))
```

```text
backward formula: [-0.11386  0.63376 -0.49024]
by nudging      : [-0.11386  0.63376 -0.49024]
```

**③ With PyTorch.** Gradients accumulate; the graph is freed; frozen parameters get none.

```python
import torch

w = torch.tensor(1.0, requires_grad=True)
x, y = 2.0, 6.0
for call in (1, 2):
    loss = (w * x - y) ** 2
    loss.backward()                                               # adds into w.grad
    print(f"after backward call {call}: w.grad = {w.grad.item()}")

loss = (w * x - y) ** 2
loss.backward()
try:
    loss.backward()                                               # the graph was freed by the first call
except RuntimeError:
    print("second backward on the same graph: error (the graph is freed after backward)")

w.grad = None
loss = (w * x - y) ** 2
loss.backward(retain_graph=True)
loss.backward()                                                   # allowed: the graph was kept
print("with retain_graph=True a second backward works; w.grad =", w.grad.item())

frozen = torch.nn.Linear(2, 1)
frozen.weight.requires_grad_(False)
frozen(torch.ones(1, 2)).sum().backward()
print("frozen weight grad:", frozen.weight.grad, "  bias grad:", frozen.bias.grad.tolist())
```

```text
after backward call 1: w.grad = -16.0
after backward call 2: w.grad = -32.0
second backward on the same graph: error (the graph is freed after backward)
with retain_graph=True a second backward works; w.grad = -32.0
frozen weight grad: None   bias grad: [1.0]
```

### 8. Input → Process → Output
`scalar loss → reverse traversal → .grad on every trainable parameter`

### 9. Enterprise use case
Cost estimates for training count the backward pass as about 2× the forward (so about 3× total per token).

### 10. AI engineering connection
LoRA and adapters train only a few parameters by freezing the rest, so most `.grad` buffers are never created.

### 11. Advantages
Exact gradients for any differentiable model with one call.

### 12. Limitations
Memory for activations; non-differentiable steps block the gradient.

### 13. Trade-offs
Checkpointing (4.41) trades recomputation for memory.

### 14. Common mistakes
Forgetting `zero_grad`; calling `backward` twice on one graph; detaching by accident; in-place operations on tensors the graph needs; using integer tensors; backward on a non-scalar.

### 15. Performance / cost
Backward matmuls dominate; overlap gradient communication with backward in distributed runs.

### 16. Security
Gradients can leak training data (model inversion, federated learning); clip and add noise for privacy.

### 17. Interview explanation
"`loss.backward()` runs reverse-mode autodiff over the recorded graph and adds each parameter's gradient into its `.grad`. Gradients accumulate, which is why we zero them each step, and the graph is freed afterwards. Frozen or detached tensors get no gradient."

### 18. Rapid-fire answer
Reverse-mode autodiff from a scalar loss; fills `.grad`; accumulates; graph freed after; cost ≈ 2× forward.

### 20. Hands-on exercise
**Goal:** prove that accumulation equals a bigger batch.

1. Make a `Linear(3, 1)` and 8 random examples.
2. Compute the gradient of the mean loss over all 8 at once.
3. Compute it as two backward calls on halves (each loss scaled by ½).
4. Compare.

<details>
<summary>Show a solution</summary>

```python
import torch

torch.manual_seed(0)
model = torch.nn.Linear(3, 1)
X, y = torch.randn(8, 3), torch.randn(8, 1)
mse = torch.nn.functional.mse_loss

model.zero_grad(); mse(model(X), y).backward()
full = model.weight.grad.clone()

model.zero_grad()
for half in (slice(0, 4), slice(4, 8)):
    (0.5 * mse(model(X[half]), y[half])).backward()
accumulated = model.weight.grad.clone()
print("full batch :", full.numpy().round(5))
print("accumulated:", accumulated.numpy().round(5))
print("equal:", torch.allclose(full, accumulated, atol=1e-6))
```

```text
full batch : [[ 0.25892  0.79127 -0.2553 ]]
accumulated: [[ 0.25892  0.79127 -0.2553 ]]
equal: True
```
