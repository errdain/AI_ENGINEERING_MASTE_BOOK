# 4.3 Loss calculation

**Metadata** — Tier: 4 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: Very high · Hands-on: Very high
Prerequisites: 2.17 Loss functions, 4.2 Forward pass · Leads to: 4.4 Backward pass

> **In plain words**
> The **loss** turns "how wrong are the predictions?" into **one number**. Training tries to make that number small. Which formula you pick depends on the task: **mean squared error** for predicting numbers, **cross-entropy** for choosing a class. Doing it correctly in practice has a few traps: pass **logits** not probabilities, **average** over the batch, and ignore **padding**.

**You need first:** 2.17 Loss functions, 4.2 Forward pass.

> **Figure 4.3-1 — from predictions to one number**
>
> ```mermaid
> flowchart LR
>     P["predictions<br/>(logits)"] --> L["loss function"]
>     T["targets<br/>(labels)"] --> L
>     L --> S["per-example losses"]
>     S --> R["reduce:<br/>mean over the batch"]
>     R --> N["one number<br/>(a scalar)"]
> ```
>
> *How to read it:* the loss compares predictions with the right answers for each example, then **reduces** the per-example values (usually their mean) to a single scalar. Backpropagation needs a single scalar to start from.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| loss | the number training tries to reduce |
| MSE | mean squared error, for numbers |
| cross-entropy | loss for classification from logits |
| reduction | how per-example losses are combined (`mean`, `sum`, `none`) |
| logits | raw scores before softmax |
| class weights | extra importance for rare classes |
| `ignore_index` | label value to skip (for example padding tokens) |

### 1. What is it?
Computing a scalar from model outputs and targets, e.g. `F.mse_loss(pred, y)` or `F.cross_entropy(logits, labels)`.

### 2. Why does it exist?
The optimizer needs a single number whose gradient says how to change the weights. The loss encodes what "good" means for the task.

### 3. Detailed explanation
- **Regression:** MSE (smooth, punishes big errors) or MAE/Huber (robust to outliers).
- **Classification:** cross-entropy from **logits** (2.17, 1.37). PyTorch's `cross_entropy` includes log-softmax; never softmax first (3.5 shows the bug).
- **Binary / multi-label:** `binary_cross_entropy_with_logits`.
- **Reduction.** `mean` makes the loss independent of the batch size; `sum` grows with it. If you change the batch size, `mean` keeps the learning rate meaningful (4.13).
- **Padding and masks.** In language models some positions are padding. `ignore_index=-100` skips them; averaging over padded positions silently shrinks the loss (code ③).
- **Class imbalance.** `weight=` or sampling can balance rare classes (2.9).
- **Label smoothing** softens the targets slightly to reduce over-confidence.
- **Sanity checks:** at initialization, cross-entropy over `K` balanced classes should be about `ln K` (log 10 = 2.30). A very different value signals a bug (4.39).
- **Regularization terms** (L2, 3.29) may be added to the loss.
- **Multiple losses** are combined with weights: `loss = loss_a + 0.1·loss_b`.
- **Numerical stability:** use the fused, stable functions (1.43–1.44).

### 4. How does it work?
Compute per-example losses, then reduce them to a scalar; the scalar is the root of the backward pass.

### 5. Simple example
A teacher marking a test: each wrong answer costs points, and the final grade is the average.

**By hand.** Targets `[3, 5]`, predictions `[2, 7]`: errors `[−1, 2]`, squared `[1, 4]`, MSE = `(1 + 4)/2 = 2.5`.

### 6. Technical example
Next-token loss for an LLM: cross-entropy between the predicted distribution and the true next token at every non-padding position, averaged.

### 7. Code
**① By hand (plain Python).** MSE and cross-entropy for one example.

```python
import math

pred, target = [2.0, 7.0], [3.0, 5.0]
print("MSE:", sum((p - t) ** 2 for p, t in zip(pred, target)) / len(pred))

logits = [2.0, 1.0, 0.1]
true_class = 0
log_sum = math.log(sum(math.exp(v) for v in logits))
print("cross-entropy:", round(log_sum - logits[true_class], 4), "(= -log of the probability given to the right class)")
```

```text
MSE: 2.5
cross-entropy: 0.417 (= -log of the probability given to the right class)
```

**② With NumPy.** Stable cross-entropy for a batch, and the "starting value" check.

```python
import numpy as np

rng = np.random.default_rng(0)
K = 10
logits = rng.normal(0, 0.01, (1000, K))                       # an untrained model: almost equal scores
labels = rng.integers(0, K, 1000)
shifted = logits - logits.max(axis=1, keepdims=True)           # subtract the max for stability
log_probs = shifted - np.log(np.exp(shifted).sum(axis=1, keepdims=True))
loss = -log_probs[np.arange(1000), labels].mean()
print("loss at initialization:", round(loss, 3), "   ln(K) =", round(np.log(K), 3))
```

```text
loss at initialization: 2.303    ln(K) = 2.303
```

**③ With PyTorch.** Reductions and masking padded positions.

```python
import torch
import torch.nn.functional as F

torch.manual_seed(0)
logits = torch.randn(6, 5)
labels = torch.tensor([1, 3, 0, 2, -100, -100])               # the last two are padding
print("reduction='none':", F.cross_entropy(logits, labels, ignore_index=-100, reduction="none").numpy().round(3))
print("mean  (ignores padding):", round(F.cross_entropy(logits, labels, ignore_index=-100).item(), 4))
print("sum                    :", round(F.cross_entropy(logits, labels, ignore_index=-100, reduction="sum").item(), 4))
per = F.cross_entropy(logits, labels.clamp(min=0), reduction="none")
print("wrong: average that counts padding as class 0:", round(per.mean().item(), 4))
```

```text
reduction='none': [2.635 1.184 1.757 1.441 0.    0.   ]
mean  (ignores padding): 1.7542
sum                    : 7.0166
wrong: average that counts padding as class 0: 1.6583
```

### 8. Input → Process → Output
`(logits, labels) → per-example loss → reduction → scalar loss`

### 9. Enterprise use case
The loss encodes business priorities (cost of false negatives, class weights); changing it changes behaviour.

### 10. AI engineering connection
LLM pre-training uses token-level cross-entropy; reward-model training uses pairwise losses; distillation uses KL divergence.

### 11. Advantages
One scalar makes optimization simple and general.

### 12. Limitations
The loss may not match the metric you care about (accuracy, F1, human preference).

### 13. Trade-offs
Smooth proxy losses are easy to optimize but imperfect; metrics are meaningful but not differentiable.

### 14. Common mistakes
Softmax before `cross_entropy`; wrong label dtype (needs integer class ids); averaging padded positions; `sum` reduction with a changing batch size; comparing losses of different tasks; ignoring the `ln K` start check.

### 15. Performance / cost
Fused loss kernels save memory for large vocabularies (logits of size batch × tokens × vocabulary).

### 16. Security
Loss values can leak membership information (members have lower loss); be careful exposing per-example losses.

</details>

### 17. Interview explanation
"The loss maps predictions and targets to a scalar. I use cross-entropy on logits for classification, MSE or Huber for regression, reduce by the mean so the scale does not depend on the batch size, and mask padding. A quick sanity check is that the initial cross-entropy is about log K."

### 18. Rapid-fire answer
Scalar from logits + targets; cross-entropy (classification), MSE (regression); `mean` reduction; mask padding; start value ≈ `ln K`.

### 19. Interview questions
- **Basic:** What loss for 10-class classification? What input does it expect?
- **Intermediate:** Why is the initial loss about `ln K`?
- **Advanced:** How do you handle padding in a token-level loss?
- **Scenario:** Loss is 2.3 and never moves on a 10-class problem. What does that tell you?

### 20. Hands-on exercise
**Goal:** verify the `ln K` check for several `K`.

1. For `K` in 2, 10, 100, 1000 create random near-zero logits for 2,000 examples.
2. Compute the cross-entropy with PyTorch.
3. Compare with `ln K`.

<details>
<summary>Show a solution</summary>

```python
import math
import torch
import torch.nn.functional as F

torch.manual_seed(0)
for K in (2, 10, 100, 1000):
    logits = 0.01 * torch.randn(2000, K)
    labels = torch.randint(0, K, (2000,))
    print(f"K = {K:>4}: loss {F.cross_entropy(logits, labels).item():.3f}   ln K = {math.log(K):.3f}")
```

```text
K =    2: loss 0.693   ln K = 0.693
K =   10: loss 2.302   ln K = 2.303
K =  100: loss 4.605   ln K = 4.605
K = 1000: loss 6.907   ln K = 6.908
```
