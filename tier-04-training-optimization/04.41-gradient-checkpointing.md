# 4.41 Gradient checkpointing

**Metadata** — Tier: 4 · Phase: 1 · Priority: P0 · Difficulty: 3/5 · Interview: High · Hands-on: High
Prerequisites: 3.20 Backpropagation, 4.24 GPU memory · Leads to: Tier 10 fine-tuning large models, Tier 12 training LLMs

> **In plain words**
> Backpropagation needs the activations from the forward pass, so training stores them all, and for big models this is the biggest memory cost. **Gradient checkpointing** (activation checkpointing) makes a trade: **don't store most activations; recompute them** when backward needs them. You keep only a few "checkpoints" and re-run small parts of the forward pass. You use far less memory in exchange for about **one extra forward pass** (roughly 30% more compute).

**You need first:** 3.20 Backpropagation, 4.24 GPU memory.

> *How to read it:* ● means "activation kept in memory", ○ means "thrown away and recomputed later". The checkpointed chain keeps every other activation and recomputes the missing ones from the nearest saved one during backward. Choosing about √n checkpoints for n layers minimizes memory at the cost of one extra forward pass.

### 1. What is it?
Saving only selected activations in the forward pass and recomputing the others from them during the backward pass (Chen et al., 2016, "training deep nets with sublinear memory cost").

### 2. Why does it exist?
Activation memory grows with depth × batch × sequence length. Checkpointing cuts it from `O(n)` to about `O(√n)` layers' worth, so larger batches, longer sequences or bigger models fit.

### 3. Detailed explanation
- **Cost/benefit.** Normally: memory ∝ n stored activations, compute = 1 forward + 1 backward (≈ 3 units total, backward is 2). With checkpointing: memory ∝ √n, compute = 2 forwards + 1 backward ≈ 4 units: about **33% more compute** (code ①).
- **How it works in PyTorch:** `torch.utils.checkpoint.checkpoint(fn, *inputs, use_reentrant=False)` runs `fn` under `no_grad` without storing inner activations; in backward it re-runs `fn` with grad enabled, then backpropagates through it (code ③).
- **Where to apply:** around each Transformer block (store only block inputs). Hugging Face: `model.gradient_checkpointing_enable()`.
- **Randomness.** Dropout masks must be the same when recomputing; PyTorch restores the RNG state by default (`preserve_rng_state=True`).
- **Side effects.** Layers with state updates (BatchNorm running stats) can be updated twice; be careful.
- **Combine** with mixed precision (4.19), accumulation (4.14) and sharding (4.34) for the biggest models.
- **Selective activation checkpointing:** save cheap-to-store, expensive-to-compute tensors (matmul outputs) and recompute cheap ones (elementwise) for a better trade (REVIEW_REQUIRED).
- **When it doesn't help:** if memory is dominated by weights or optimizer state (4.24), or when the batch is tiny.
- **Debugging:** results should match the non-checkpointed model exactly (up to numerical noise) (code ③).
- **Speed impact depends:** if the GPU is otherwise memory-starved, enabling larger batches can recover the lost speed.

### 4. How does it work?
Forward: keep only each segment's input. Backward: for each segment (from the end), recompute its forward from the saved input, then backprop through it.

### 5. Simple example
Hiking with limited notebook pages: instead of writing down every turn (store all), you note a landmark every ten turns; if you need to retrace, you re-walk from the nearest landmark.

**By hand.** 100 layers: store all → 100 activations. With 10 checkpoints (segments of 10): store 10 checkpoints + at most 10 inside the segment being recomputed = about 20 activations, with an extra forward pass.

### 6. Technical example
Training a 7B model with sequence length 4096: activations without checkpointing are tens of GB; with per-block checkpointing they drop to a few GB, at about 30% extra compute (REVIEW_REQUIRED: illustrative).

### 7. Code
**① By hand (plain Python).** Memory and compute for `n` layers.

```python
import math

for n in (16, 100, 400):
    k = round(math.sqrt(n))
    stored_all, stored_ckpt = n, k + math.ceil(n / k)
    print(f"{n:>3} layers: store all = {stored_all:>3} activations; checkpointed (~sqrt(n) = {k} segments) = {stored_ckpt:>3}")
print("compute: store all = forward 1 + backward 2 = 3 units; checkpointed = 2 forwards + backward = 4 units (+33%)")
```

**② With NumPy.** A manual checkpointed backward pass gives the same gradient.

```python
import numpy as np

rng = np.random.default_rng(0)
n, d = 8, 4
Ws = [rng.normal(0, 0.5, (d, d)) for _ in range(n)]
x = rng.normal(size=d)
fwd = lambda a, W: np.tanh(W @ a)

# store everything
acts = [x]
for W in Ws:
    acts.append(fwd(acts[-1], W))
g = np.ones(d)
for W, a_in, a_out in zip(reversed(Ws), reversed(acts[:-1]), reversed(acts[1:])):
    g = W.T @ (g * (1 - a_out ** 2))
full_grad = g

# store only every 4th activation, recompute the rest during backward
saved = {0: x}
a = x
for i, W in enumerate(Ws):
    a = fwd(a, W)
    if (i + 1) % 4 == 0:
        saved[i + 1] = a
g = np.ones(d)
for seg_start in (4, 0):                                              # process the last segment first
    seg = [saved[seg_start]]
    for W in Ws[seg_start:seg_start + 4]:
        seg.append(fwd(seg[-1], W))                                   # recompute this segment's activations
    for W, a_out in zip(reversed(Ws[seg_start:seg_start + 4]), reversed(seg[1:])):
        g = W.T @ (g * (1 - a_out ** 2))
print("activations kept in memory:", len(saved), "of", len(acts))
print("gradient identical to the store-everything version:", np.allclose(g, full_grad))
```

```text
activations kept in memory: 3 of 9
gradient identical to the store-everything version: True
```

**③ With PyTorch.** `torch.utils.checkpoint` gives identical gradients with an extra forward call.

```python
import torch
from torch import nn
from torch.utils.checkpoint import checkpoint

torch.manual_seed(0)
calls = {"n": 0}
class Block(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc = nn.Linear(32, 32)
    def forward(self, x):
        calls["n"] += 1
        return torch.relu(self.fc(x))

blocks = nn.ModuleList([Block() for _ in range(6)])
x = torch.randn(8, 32)

def run(use_ckpt):
    calls["n"] = 0
    blocks.zero_grad()
    h = x
    for b in blocks:
        h = checkpoint(b, h, use_reentrant=False) if use_ckpt else b(h)
    h.sum().backward()
    return [p.grad.clone() for p in blocks.parameters()], calls["n"]

g_plain, n_plain = run(False)
g_ckpt, n_ckpt = run(True)
print("forward calls  without / with checkpointing:", n_plain, "/", n_ckpt, "(each block recomputed once in backward)")
print("gradients identical:", all(torch.allclose(a, b, atol=1e-6) for a, b in zip(g_plain, g_ckpt)))
```

```text
forward calls  without / with checkpointing: 6 / 12 (each block recomputed once in backward)
gradients identical: True
```

### 8. Input → Process → Output
`forward (keep checkpoints only) → backward (recompute segment, then backprop) → same gradients, less memory`

### 9. Enterprise use case
Often the cheapest way to fit a larger batch or longer context on existing GPUs.

### 10. AI engineering connection
Standard for LLM training and fine-tuning (long sequences, 7B+ models); combined with FSDP and BF16.

### 11. Advantages
Large activation memory savings with no change in results.

### 12. Limitations
About 30% extra compute; complexity with stateful layers and randomness.

### 13. Trade-offs
Compute for memory; selective checkpointing finds a middle path.

### 14. Common mistakes
Checkpointing tiny layers (overhead exceeds savings); forgetting `use_reentrant=False` guidance; non-deterministic ops inside segments; double-updating BatchNorm statistics; expecting savings when weights dominate memory.

### 15. Performance / cost
Pick segment boundaries at block boundaries; profile the speed/memory trade (4.25, 4.40).

### 16. Security
No direct issue.

### 20. Hands-on exercise
**Goal:** compute the compute overhead of checkpointing every block versus every second block.

1. A model has 12 blocks. Forward costs 1 unit per block; backward costs 2 per block.
2. Checkpoint all blocks (recompute each once) versus none.
3. Compute total cost and the overhead.

<details>
<summary>Show a solution</summary>

```python
blocks = 12
forward, backward = 1 * blocks, 2 * blocks
plain = forward + backward
all_ckpt = forward + backward + forward                               # one extra forward pass over every block
half_ckpt = forward + backward + forward / 2                          # recompute only half of the blocks
print(f"no checkpointing   : {plain} units")
print(f"every block        : {all_ckpt} units  (+{(all_ckpt / plain - 1):.0%})")
print(f"every second block : {half_ckpt:.0f} units  (+{(half_ckpt / plain - 1):.0%})")
```

every block        : 48 units  (+33%)
every second block : 42 units  (+17%)
