# 4.5 Parameter update

**Metadata** — Tier: 4 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: High · Hands-on: Very high
Prerequisites: 1.22 Gradient descent, 4.4 Backward pass · Leads to: 4.6 SGD, 4.7 Momentum, 4.8 Adam

> **In plain words**
> The **parameter update** is the moment the model **actually changes**. Each weight is moved a little in the direction that lowers the loss: `new weight = old weight − learning rate × gradient`. In PyTorch it is `optimizer.step()`. The only thing that differs between optimizers (SGD, momentum, Adam) is the exact rule for *how far and which way* to move.

**You need first:** 1.22 Gradient descent, 4.4 Backward pass.

> **Figure 4.5-1 — one update**
>
> ```mermaid
> flowchart LR
>     W["weight w = 2.0"] --> U["w ← w − lr · grad"]
>     G["gradient = −16"] --> U
>     R["learning rate = 0.05"] --> U
>     U --> N["new weight = 2.8"]
> ```
>
> *How to read it:* the gradient says "increasing `w` would change the loss by −16 per unit", i.e. raising `w` lowers the loss. So we subtract a negative number, which raises `w`. The learning rate (here 0.05) scales the move: `2.0 − 0.05·(−16) = 2.8`.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| update rule | the formula for the new weight |
| learning rate `η` (lr) | how big a move to make |
| `optimizer.step()` | apply the update to all parameters |
| optimizer state | extra numbers the optimizer remembers (momentum, Adam moments) |
| in place | the weight tensor is changed directly |
| `param_groups` | groups of parameters with their own settings |

### 1. What is it?
Changing each trainable parameter using its gradient according to the optimizer's rule. Plain gradient descent: `θ ← θ − η·∇L`.

### 2. Why does it exist?
Without the update there is no learning: gradients are only information. The update turns them into improvement.

### 3. Detailed explanation
- **Direction.** The gradient points toward steeper *increase*, so we step in the opposite direction.
- **Size.** Too large a learning rate overshoots and diverges; too small is slow (code ③ shows both). Typical values: 1e-1 to 1e-3 for SGD, 1e-3 to 1e-5 for Adam-style optimizers (4.8).
- **Done in place, without recording.** PyTorch's `step()` modifies parameters under `no_grad`, so the update itself is not part of the graph.
- **Optimizer state.** Momentum and Adam keep extra tensors per parameter (1× or 2× the model size in memory, 4.24).
- **Parameter groups.** Different learning rates or weight decay for different parts (for example no decay on biases, 3.29; a smaller rate for pretrained layers).
- **The order of the loop matters:** `zero_grad → forward → loss → backward → step`. Calling `step()` before `backward()` uses stale gradients.
- **Schedulers** change `lr` between steps (4.10–4.12).
- **Mixed precision** keeps a float32 master copy of the weights so tiny updates are not lost (4.19).
- **Weight updates are small relative to the weights** (often ~1e-3 of their size per step); monitoring the ratio is a useful health check (4.37).

### 4. How does it work?
For each parameter: read `.grad`, compute the step from the rule (and any state), subtract it from the parameter.

### 5. Simple example
Walking downhill in fog: feel which way the ground slopes (gradient), take a step that way down (update). A giant step might overshoot into the next hill.

**By hand.** Loss `L(w) = (w − 3)²` has gradient `2(w − 3)`. Start at `w = 0`, lr 0.1: gradient −6 → `w = 0.6`; gradient −4.8 → `w = 1.08`; and so on toward 3. With lr 1.1 the steps overshoot more each time and diverge.

### 6. Technical example
`optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4)` and `optimizer.step()` once per batch.

### 7. Code
**① By hand (plain Python).** Gradient descent on `(w − 3)²` with a good and a too-big learning rate.

```python
for lr in (0.1, 1.1):
    w = 0.0
    trail = []
    for step in range(1, 9):
        grad = 2 * (w - 3)
        w = w - lr * grad                                          # the update
        trail.append(round(w, 2))
    print(f"lr = {lr}: w after 8 steps = {trail}")
```

```text
lr = 0.1: w after 8 steps = [0.6, 1.08, 1.46, 1.77, 2.02, 2.21, 2.37, 2.5]
lr = 1.1: w after 8 steps = [6.6, -1.32, 8.18, -3.22, 10.46, -5.96, 13.75, -9.9]
```

**② With NumPy.** The update applied to a vector of weights, with a per-group learning rate.

```python
import numpy as np

rng = np.random.default_rng(0)
w = rng.normal(0, 1, 6)
grad = 2 * w                                                       # gradient of sum(w^2)
lrs = np.array([0.1, 0.1, 0.1, 0.01, 0.01, 0.01])                  # two "groups": first three fast, last three slow
w_new = w - lrs * grad
print("before:", w.round(3))
print("after :", w_new.round(3))
print("relative change per weight:", ((w_new - w) / w).round(3))
```

```text
before: [ 0.126 -0.132  0.64   0.105 -0.536  0.362]
after : [ 0.101 -0.106  0.512  0.103 -0.525  0.354]
relative change per weight: [-0.2  -0.2  -0.2  -0.02 -0.02 -0.02]
```

**③ With PyTorch.** `step()` is the update, and the order of the lines matters.

```python
import torch

w = torch.nn.Parameter(torch.tensor(0.0))
opt = torch.optim.SGD([w], lr=0.1)

loss = (w - 3) ** 2
opt.zero_grad(); loss.backward()
print("gradient:", w.grad.item(), "   weight before step:", w.item())
opt.step()
print("weight after step :", round(w.item(), 3), "   (0 - 0.1 * -6 = 0.6)")

opt.step()                                                           # forgot to recompute the gradient: stale gradient reused
print("step() again with the same gradient:", round(w.item(), 3))
```

```text
gradient: -6.0    weight before step: 0.0
weight after step : 0.6    (0 - 0.1 * -6 = 0.6)
step() again with the same gradient: 1.2
```

### 8. Input → Process → Output
`parameters + gradients (+ optimizer state) → update rule → new parameters`

### 9. Enterprise use case
The optimizer settings are part of every training recipe and are logged for reproducibility (4.21).

### 10. AI engineering connection
LLM fine-tuning uses per-group learning rates and often updates only adapter weights.

### 11. Advantages
Simple and universal.

### 12. Limitations
Sensitive to the learning rate; state costs memory.

### 13. Trade-offs
Aggressive learning rates train faster but risk instability.

### 14. Common mistakes
Wrong order of calls; creating the optimizer before moving the model to the GPU; forgetting parameters (a new layer not given to the optimizer); using the same lr for pretrained and new layers.

### 15. Performance / cost
Fused/foreach optimizer implementations are faster; optimizer state can be sharded (4.34).

### 16. Security
Update logs and checkpoints can reveal training data details; protect them.

### 17. Interview explanation
"The update moves each parameter against its gradient, scaled by the learning rate; adaptive optimizers also use per-parameter state. In PyTorch it is `optimizer.step()` after `backward()`, and the learning rate is the most important hyperparameter."

### 18. Rapid-fire answer
`θ ← θ − η·g` (or the optimizer's variant); `optimizer.step()` after `backward()`; lr too big diverges, too small crawls.

### 20. Hands-on exercise
**Goal:** find the learning-rate threshold for stability.

1. For `L(w) = (w − 3)²`, run 50 steps for lr in 0.1, 0.5, 0.9, 1.0, 1.1.
2. Print the final distance `|w − 3|`.
3. Explain the pattern (hint: each step multiplies the distance by `|1 − 2·lr|`).

<details>
<summary>Show a solution</summary>

```python
for lr in (0.1, 0.5, 0.9, 1.0, 1.1):
    w = 0.0
    for _ in range(50):
        w -= lr * 2 * (w - 3)
    print(f"lr = {lr}: |w - 3| = {abs(w - 3):.2e}   factor per step |1 - 2*lr| = {abs(1 - 2 * lr):.2f}")
```

```text
lr = 0.1: |w - 3| = 4.28e-05   factor per step |1 - 2*lr| = 0.80
lr = 0.5: |w - 3| = 0.00e+00   factor per step |1 - 2*lr| = 0.00
lr = 0.9: |w - 3| = 4.28e-05   factor per step |1 - 2*lr| = 0.80
lr = 1.0: |w - 3| = 3.00e+00   factor per step |1 - 2*lr| = 1.00
lr = 1.1: |w - 3| = 2.73e+04   factor per step |1 - 2*lr| = 1.20
```
