# 4.33 Pipeline parallelism

**Metadata** — Tier: 4 · Phase: 1 · Priority: P1 · Difficulty: 4/5 · Interview: High · Hands-on: Low
Prerequisites: 4.30 Distributed training intro, 4.14 Gradient accumulation · Leads to: 4.34 FSDP/ZeRO

> **In plain words**
> **Pipeline parallelism** puts **different layers on different GPUs**: GPU 0 holds layers 1–8, GPU 1 holds layers 9–16, and so on. A batch flows through the GPUs like items on an assembly line. To keep every GPU busy, the batch is cut into **micro-batches** so that while GPU 1 works on micro-batch 1, GPU 0 can already start micro-batch 2. The unavoidable idle time at the start and end is called the **bubble**.

**You need first:** 4.30 Distributed training intro, 4.14 Gradient accumulation (micro-batches).

> *How to read it:* at time 1 only GPU 0 works; by time 4 all four GPUs are busy. The partly empty early (and, at the end, late) steps are the **bubble**: with `p` stages and `m` micro-batches the idle fraction is `(p − 1) / (m + p − 1)`. More micro-batches → smaller bubble.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| stage | a group of consecutive layers on one device |
| micro-batch | a slice of the batch moving through the pipeline |
| bubble | idle time when some stages wait |
| GPipe | schedule: all forwards, then all backwards |
| 1F1B | schedule: alternate one forward, one backward to save memory |
| activation memory | stored for each in-flight micro-batch |
| stage balance | giving each stage a similar amount of work |

### 1. What is it?
Partitioning a model into sequential stages on different devices and streaming micro-batches through them.

### 2. Why does it exist?
When the model is too deep to fit on one device, and the interconnect between nodes is too slow for tensor parallelism, splitting by layers needs only small activation transfers between neighbouring stages.

### 3. Detailed explanation
- **Communication** is light: only the activations (forward) and their gradients (backward) at the stage boundaries are sent, point-to-point, not all-reduced.
- **Bubble fraction** `(p − 1)/(m + p − 1)`: with `p = 4`, `m = 4` → 3/7 = 43% idle; with `m = 32` → 3/35 = 8.6% (code ①). Use many micro-batches.
- **Schedules:** *GPipe* runs all micro-batch forwards then all backwards (must store activations for all `m` micro-batches). *1F1B* interleaves forwards and backwards so each stage stores activations for about `p` micro-batches at most. *Interleaved* schedules give each device several small stages to shrink the bubble further (REVIEW_REQUIRED).
- **Balance.** The slowest stage sets the pace; give heavier layers (for example the embedding or the output layer) fewer neighbours.
- **Memory.** Weights, gradients and optimizer state divide by `p`; activation memory depends on the schedule.
- **Combination.** Pipeline across nodes, tensor parallel inside nodes, data parallel across replicas.
- **Gradient accumulation** interacts: the micro-batches of one optimizer step are exactly the pipeline's micro-batches.
- **Batch statistics and tied weights** (embedding/output tying) need extra care across stages.
- **Complexity:** harder to debug; stage failures stall the pipeline.
- **Inference** uses the same idea to serve very large models.

### 4. How does it work?
Assign layers to stages, split the batch into micro-batches, send micro-batch activations stage to stage, and (in training) send gradients back.

### 5. Simple example
A car wash with four stations: while car 1 is being rinsed, car 2 is already being soaped. Only at the very start and end are some stations idle.

**By hand.** 4 stations, 4 cars, one time-unit each: finishing takes `4 + 4 − 1 = 7` time units, but busy station-time is `4 × 4 = 16` out of `4 × 7 = 28` possible: 57% busy (43% idle).

### 6. Technical example
A 96-layer model split into 8 stages of 12 layers with 32 micro-batches per step (REVIEW_REQUIRED: illustrative).

### 7. Code
**① By hand (plain Python).** The bubble fraction.

```python
def bubble(p, m):
    return (p - 1) / (m + p - 1)

for p in (4, 8):
    print(f"{p} stages:", {m: f"{bubble(p, m):.0%}" for m in (4, 8, 32, 128)})
print("rule: use many more micro-batches than stages")
```

```text
4 stages: {4: '43%', 8: '27%', 32: '9%', 128: '2%'}
8 stages: {4: '64%', 8: '47%', 32: '18%', 128: '5%'}
rule: use many more micro-batches than stages
```

**② With NumPy.** Simulate the schedule and count idle slots.

```python
import numpy as np

p, m = 4, 6
T = m + p - 1
grid = np.full((p, T), -1)                                           # -1 = idle; otherwise the micro-batch id
for stage in range(p):
    for mb in range(m):
        grid[stage, stage + mb] = mb
for stage in range(p):
    print(f"stage {stage}: " + " ".join("." if v < 0 else str(v) for v in grid[stage]))
print(f"idle fraction: {(grid < 0).mean():.1%}   formula: {(p - 1) / (m + p - 1):.1%}")
```

```text
stage 0: 0 1 2 3 4 5 . . .
stage 1: . 0 1 2 3 4 5 . .
stage 2: . . 0 1 2 3 4 5 .
stage 3: . . . 0 1 2 3 4 5
idle fraction: 33.3%   formula: 33.3%
```

**③ With PyTorch.** Split a model into two stages; micro-batching gives identical results.

```python
import torch
from torch import nn

torch.manual_seed(0)
layers = [nn.Linear(16, 16), nn.ReLU(), nn.Linear(16, 16), nn.ReLU(), nn.Linear(16, 16), nn.ReLU(), nn.Linear(16, 4)]
whole = nn.Sequential(*layers)
stage0, stage1 = nn.Sequential(*layers[:4]), nn.Sequential(*layers[4:])       # two "devices"
x = torch.randn(32, 16)

full = whole(x)
outputs = []
for micro in x.chunk(8):                                                       # 8 micro-batches flow through stage 0, then stage 1
    outputs.append(stage1(stage0(micro)))
piped = torch.cat(outputs)
print("pipeline output equals the unsplit model:", torch.allclose(full, piped, atol=1e-6))
print("parameters per stage:", sum(p.numel() for p in stage0.parameters()), sum(p.numel() for p in stage1.parameters()))
```

```text
pipeline output equals the unsplit model: True
parameters per stage: 544 340
```

### 9. Enterprise use case
Lets teams train very deep models across nodes with ordinary (slower) networking.

### 10. AI engineering connection
A component of 3D parallelism for the largest LLMs.

### 11. Advantages
Light communication; scales across nodes; memory splits by depth.

### 12. Limitations
The bubble; load-balancing difficulty; complexity; micro-batching interacts with BatchNorm.

### 13. Trade-offs
More micro-batches shrink the bubble but can lower per-micro-batch efficiency.

### 14. Common mistakes
Too few micro-batches; unbalanced stages; forgetting activations of in-flight micro-batches in memory planning; tied weights across stages.

### 15. Performance / cost
Use 1F1B; balance stages by measured time (4.25).

### 16. Security
Same as other distributed settings.

### 17. Interview explanation
"Pipeline parallelism assigns consecutive layers to different devices and streams micro-batches through them so stages work concurrently. The idle bubble is (p−1)/(m+p−1) of the time, so I use many micro-batches and a 1F1B schedule, and balance stage times. Communication is only point-to-point activations, which suits slower links."

### 18. Rapid-fire answer
Layers split across devices; micro-batches stream; bubble `(p−1)/(m+p−1)`; 1F1B saves activation memory; light communication.
