# 4.2 Forward pass

**Metadata** — Tier: 4 · Phase: 1 · Priority: P0 · Difficulty: 1/5 · Interview: High · Hands-on: Very high
Prerequisites: 3.18 Forward propagation, 4.1 Training loop · Leads to: 4.3 Loss calculation

> **In plain words**
> The **forward pass** is the model **making its predictions**: examples go in, numbers come out. In training it is the first half of every step. Concept 3.18 explained how it works inside the network; this page is about its **role in the training loop**: what it must remember for later, how to keep it cheap when you don't need gradients, and the traps (train versus eval mode).

**You need first:** 3.18 Forward propagation, 4.1 Training loop.

> **Figure 4.2-1 — the forward pass inside a training step**
>
> ```mermaid
> flowchart LR
>     X["batch x"] --> M["model(x)"]
>     M --> P["predictions"]
>     M -.-> C["saved intermediate values<br/>(needed by backward)"]
>     P --> L["loss (4.3)"]
> ```
>
> *How to read it:* the solid path is the prediction. The dashed branch is the hidden cost of training: PyTorch quietly records every intermediate value so the backward pass (4.4) can use them. That recording is why training needs much more memory than just predicting.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| forward pass | running the model on inputs to get outputs |
| autograd graph | the record PyTorch builds so it can differentiate later |
| `no_grad` | tell PyTorch not to record (saves memory and time) |
| `train()` / `eval()` | switch layers like dropout and BatchNorm between modes |
| logits | the raw scores before softmax |
| inference | using the trained model (forward pass only) |

### 1. What is it?
Calling `model(x)` on a batch to obtain predictions (often *logits*) while PyTorch records the operations needed for the backward pass.

### 2. Why does it exist?
You cannot measure error or compute gradients without predictions. The forward pass is where the model's current weights turn data into answers.

### 3. Detailed explanation
- **Recorded versus unrecorded.** In training the forward pass builds the autograd graph (3.19). Under `torch.no_grad()` (validation, inference) it records nothing: faster and far less memory.
- **Output scale.** Return logits, not probabilities, when the loss expects logits (`cross_entropy` applies log-softmax itself, 4.3).
- **Modes.** `model.train()` enables dropout and uses batch statistics in BatchNorm; `model.eval()` disables dropout and uses running statistics. Forgetting `eval()` for validation gives noisy, worse numbers (code ③).
- **Shapes.** Check `(batch, features)` going in and `(batch, classes)` coming out; most early bugs are shape bugs (3.16).
- **Determinism.** With the same weights and eval mode, the same input gives the same output.
- **Cost.** About `2 × parameters` FLOPs per example (3.18).
- **Mixed precision** runs parts of the forward pass in 16-bit numbers (4.19).
- **Hooks** let you look at intermediate activations without changing the model (4.37).

### 4. How does it work?
Move the batch to the model's device, call the model, keep the predictions (and the graph) for the loss and backward.

### 5. Simple example
Reading a recipe and cooking a dish: the dish is the prediction. While learning you also write down every step you took (the graph), so you can later work out which step caused a bad taste.

**By hand.** Model `y = 2x + 1`, batch `x = [0, 1, 2]` → predictions `[1, 3, 5]`.

### 6. Technical example
A language model's forward pass takes token ids of shape `(batch, sequence)` and returns logits of shape `(batch, sequence, vocabulary)`.

### 7. Code
**① By hand (plain Python).** A forward pass over a batch.

```python
def model(x, w=2.0, b=1.0):
    return w * x + b

batch = [0.0, 1.0, 2.0]
print("predictions:", [model(x) for x in batch])
```

```text
predictions: [1.0, 3.0, 5.0]
```

**② With NumPy.** A two-layer network's forward pass, keeping what backward will need.

```python
import numpy as np

rng = np.random.default_rng(0)
x = rng.normal(0, 1, (4, 3))                                  # batch of 4, 3 features
W1, b1 = rng.normal(0, 0.5, (5, 3)), np.zeros(5)
W2, b2 = rng.normal(0, 0.5, (2, 5)), np.zeros(2)

z1 = x @ W1.T + b1
a1 = np.maximum(0, z1)                                         # saved: needed to differentiate ReLU and W2
logits = a1 @ W2.T + b2
cache = {"x": x, "z1": z1, "a1": a1}
print("logits shape:", logits.shape)
print("numbers saved for backward:", sum(v.size for v in cache.values()))
```

```text
logits shape: (4, 2)
numbers saved for backward: 52
```

**③ With PyTorch.** Recorded versus unrecorded, and train versus eval mode.

```python
import torch

torch.manual_seed(0)
model = torch.nn.Sequential(torch.nn.Linear(4, 8), torch.nn.ReLU(), torch.nn.Dropout(0.5), torch.nn.Linear(8, 2))
x = torch.randn(3, 4)

out = model(x)
print("recorded in the graph (training):", out.requires_grad, "  grad_fn:", type(out.grad_fn).__name__)
with torch.no_grad():
    out2 = model(x)
print("under no_grad                  :", out2.requires_grad)

model.train(); a, b = model(x), model(x)
model.eval();  c, d = model(x), model(x)
print("train mode, same input twice -> identical outputs?", torch.equal(a, b))
print("eval  mode, same input twice -> identical outputs?", torch.equal(c, d))
```

```text
recorded in the graph (training): True   grad_fn: AddmmBackward0
under no_grad                  : False
train mode, same input twice -> identical outputs? False
eval  mode, same input twice -> identical outputs? True
```

`batch → model → logits (+ saved activations for backward)`

### 9. Enterprise use case
Inference services run the forward pass only, in eval mode under `no_grad`; their cost and latency follow from it.

### 10. AI engineering connection
Generation repeats the forward pass once per new token (with caching, Tier 11).

### 11. Advantages
Simple, parallel across the batch.

### 12. Limitations
Training memory is dominated by the saved activations.

### 13. Trade-offs
Activation checkpointing (4.41) trades extra forward compute for memory.

### 14. Common mistakes
Forgetting `eval()`/`no_grad()` for validation; applying softmax before a loss that expects logits; wrong device for inputs; in-place operations that break the graph.

### 15. Performance / cost
Fuse operations, use larger batches that fit, use mixed precision.

### 16. Security
Validate the shape and range of inputs before the forward pass.

</details>

### 17. Interview explanation
"The forward pass maps a batch to predictions and, during training, records the graph and intermediate activations for backpropagation. For validation I use eval mode and no_grad so nothing is recorded and layers like dropout are off."

### 18. Rapid-fire answer
`model(x)` → logits; records the graph in training; use `eval()` + `no_grad()` for validation and inference.

### 20. Hands-on exercise
**Goal:** measure what `no_grad` saves.

1. Build `Linear(512, 512)` ×4 with ReLU.
2. Run a forward pass on a `(256, 512)` batch with and without `no_grad`.
3. Print whether the output has a `grad_fn` in each case.

<details>
<summary>Show a solution</summary>

```python
import torch

torch.manual_seed(0)
layers = []
for _ in range(4):
    layers += [torch.nn.Linear(512, 512), torch.nn.ReLU()]
net = torch.nn.Sequential(*layers)
x = torch.randn(256, 512)

with_graph = net(x)
with torch.no_grad():
    without_graph = net(x)
print("normal call  : grad_fn =", type(with_graph.grad_fn).__name__)
print("under no_grad: grad_fn =", without_graph.grad_fn)
print("same numbers :", torch.allclose(with_graph, without_graph))
```

```text
normal call  : grad_fn = ReluBackward0
under no_grad: grad_fn = None
same numbers : True
```
