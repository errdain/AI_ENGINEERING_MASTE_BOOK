# 4.20 Checkpoints

**Metadata** — Tier: 4 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: High · Hands-on: Very high

> **In plain words**
> A **checkpoint** is a **saved snapshot of training** so you can stop and continue later, recover from a crash, or keep the best version. It must contain more than the model weights: also the **optimizer state**, the **scheduler**, the **step number** and the **random state**. Without them a "resumed" run quietly behaves differently.
> It's the save point in a video game.

**You need first:** 4.1 Training loop, 4.5 Parameter update.

> **Figure 4.20-1 — what goes into a checkpoint**
>
> ```mermaid
> flowchart LR
>     M["model weights"] --> C["checkpoint file"]
>     O["optimizer state<br/>(momentum, Adam m and v)"] --> C
>     S["scheduler state"] --> C
>     T["step / epoch<br/>best metric"] --> C
>     R["random states<br/>(seeds)"] --> C
>     C --> D["resume exactly where you stopped"]
> ```
>
> *How to read it:* the model alone is enough to run predictions, but to **continue training** you need the other boxes too. Adam's `m` and `v` take twice the model's size; losing them makes the first steps after resuming behave like a restart (code ③).

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| checkpoint | a saved snapshot of training state |
| `state_dict` | PyTorch's dictionary of tensors for a model or optimizer |
| resume | continue training from a checkpoint |
| best checkpoint | the one with the best validation metric |
| atomic save | write to a temp file, then rename, so a crash cannot corrupt it |
| sharded checkpoint | split across files/devices for huge models |
| `weights_only` | safer loading that refuses arbitrary code |

### 1. What is it?
Writing the training state to disk (`torch.save`) and restoring it later (`torch.load`, `load_state_dict`).

### 2. Why does it exist?
Long runs crash, jobs get preempted, and you want the best model rather than the last one. Checkpoints turn failures into minor delays.

### 3. Detailed explanation
- **Full checkpoint contents:** `model.state_dict()`, `optimizer.state_dict()`, `scheduler.state_dict()`, global step, epoch, best metric, scaler state (FP16), and RNG states for exact reproduction (4.21).
- **Weights-only** is for inference and sharing; much smaller (Adam state is 2× the weights).
- **When to save:** every N steps (for crashes) and whenever validation improves (best). Keep the last few and the best; delete older ones to save disk.
- **Atomic writes.** Save to `ckpt.tmp` then rename, so a crash mid-write never leaves a broken `ckpt`.
- **Resuming correctly:** build model, optimizer and scheduler with the same settings, load their states, continue from `step + 1` (code ③). The data loader position should resume too, or you reuse/skip data.
- **Device mapping:** `torch.load(..., map_location="cpu")` avoids GPU-memory surprises.
- **Security:** `torch.load` can execute code in pickled files. Load only trusted files, and prefer `weights_only=True` or the `safetensors` format (REVIEW_REQUIRED).
- **Large models:** sharded or distributed checkpoints (each rank writes its part) (4.34).
- **Versioning:** record the code version, config and data version with each checkpoint (4.21).
- **Cost:** a checkpoint of a large model can be hundreds of GB; saving is I/O-heavy, so asynchronous saving is used (REVIEW_REQUIRED).

### 4. How does it work?
Collect the state dicts into one dictionary, save atomically, and to resume, load them back into freshly built objects.

### 5. Simple example
A video game save point: you save position, health and inventory (not just the map). Reloading only the map would be useless.

**By hand.** Training for 1,000 steps crashes at step 700. With a checkpoint every 100 steps you restart from step 700 (nothing lost beyond the save interval); with none you restart from step 0.

### 6. Technical example
`torch.save({"model": m.state_dict(), "opt": o.state_dict(), "sched": s.state_dict(), "step": step}, "ckpt.pt")`.

### 7. Code
**① By hand (plain Python).** Save and resume a counter-based "training" with JSON, atomically.

```python
import json, os, tempfile

path = os.path.join(tempfile.mkdtemp(), "ckpt.json")

def save(state):
    tmp = path + ".tmp"
    with open(tmp, "w") as f:
        json.dump(state, f)
    os.replace(tmp, path)                                             # atomic rename

w, step = 0.0, 0
for step in range(1, 51):
    w -= 0.1 * 2 * (w - 3)
    if step % 25 == 0:
        save({"w": w, "step": step})
state = json.load(open(path))
print("saved:", {k: round(v, 4) for k, v in state.items()})
```

```text
saved: {'w': 3.0, 'step': 50}
```

**② With NumPy.** Save and reload arrays.

```python
import numpy as np, os, tempfile

path = os.path.join(tempfile.mkdtemp(), "ckpt.npz")
rng = np.random.default_rng(0)
W, b = rng.normal(0, 1, (3, 3)), np.zeros(3)
np.savez(path, W=W, b=b, step=np.array(100))
loaded = np.load(path)
print("restored equal:", np.array_equal(W, loaded["W"]), "  step:", int(loaded["step"]))
print("file size (bytes):", os.path.getsize(path))
```

```text
restored equal: True   step: 100
file size (bytes): 834
```

**③ With PyTorch.** Resume exactly, versus resuming without the optimizer state.

```python
import os, tempfile, torch

torch.manual_seed(0)
X = torch.randn(128, 4); y = X.sum(dim=1, keepdim=True)

def build():
    torch.manual_seed(0)
    m = torch.nn.Linear(4, 1)
    o = torch.optim.Adam(m.parameters(), lr=0.05)
    return m, o

def train(m, o, steps):
    for _ in range(steps):
        o.zero_grad(); torch.nn.functional.mse_loss(m(X), y).backward(); o.step()
    return torch.nn.functional.mse_loss(m(X), y).item()

m, o = build(); train(m, o, 10)                                         # the uninterrupted run, 10 steps
reference = train(m, o, 10)                                            # ... and 10 more

m1, o1 = build(); train(m1, o1, 10)
path = os.path.join(tempfile.mkdtemp(), "ckpt.pt")
torch.save({"model": m1.state_dict(), "opt": o1.state_dict()}, path)   # checkpoint at step 10

m2, o2 = build()
ckpt = torch.load(path)
m2.load_state_dict(ckpt["model"]); o2.load_state_dict(ckpt["opt"])      # full resume
m3, o3 = build()
m3.load_state_dict(ckpt["model"])                                       # weights only: Adam restarts cold
print(f"uninterrupted loss after 20 steps  : {reference:.6f}")
print(f"resumed with optimizer state       : {train(m2, o2, 10):.6f}")
print(f"resumed with weights only          : {train(m3, o3, 10):.6f}")
```

```text
uninterrupted loss after 20 steps  : 0.501191
resumed with optimizer state       : 0.501191
resumed with weights only          : 0.373220
```

### 9. Enterprise use case
Checkpointing underpins cost control on preemptible hardware and auditability of model versions.

### 10. AI engineering connection
LLM runs save sharded checkpoints every few hundred steps; released models are weights-only (often `safetensors`).

### 11. Advantages
Fault tolerance; best-model selection; experiment branching.

### 12. Limitations
Disk space; I/O stalls; subtle resume bugs.

### 13. Trade-offs
Frequent saves lose less work but cost more I/O.

### 14. Common mistakes
Saving only the model; saving mid-write non-atomically; not saving the scheduler; resuming the data order from the start; loading untrusted pickles; GPU/CPU mismatch on load.

### 15. Performance / cost
Use sharded or asynchronous saving for big models; compress sparingly.

### 16. Security
`torch.load` of untrusted files can execute code; use `weights_only=True` or `safetensors`, and verify hashes.

### 20. Hands-on exercise
**Goal:** implement "keep the best checkpoint".

1. Train a small tanh network for 200 epochs on 20 noisy points of `sin(3x)`, with 20 more points as validation.
2. After each epoch, if validation loss improved, copy the state dict (`copy.deepcopy`).
3. At the end restore the best and print which epoch it was.

<details>
<summary>Show a solution</summary>

```python
import copy, torch

torch.manual_seed(0)
X = torch.linspace(-1, 1, 40).unsqueeze(1)
y = torch.sin(3 * X) + 0.4 * torch.randn_like(X)
perm = torch.randperm(40)
X, y = X[perm], y[perm]
tr, va = slice(0, 20), slice(20, 40)
model = torch.nn.Sequential(torch.nn.Linear(1, 64), torch.nn.Tanh(), torch.nn.Linear(64, 1))
opt = torch.optim.Adam(model.parameters(), lr=0.03)
best, best_state, best_epoch = float("inf"), None, 0
for epoch in range(1, 201):
    opt.zero_grad(); torch.nn.functional.mse_loss(model(X[tr]), y[tr]).backward(); opt.step()
    with torch.no_grad():
        val = torch.nn.functional.mse_loss(model(X[va]), y[va]).item()
    if val < best:
        best, best_state, best_epoch = val, copy.deepcopy(model.state_dict()), epoch
model.load_state_dict(best_state)
print(f"best epoch {best_epoch} of 200, validation loss {best:.4f}; restored the best weights")
```

```text
best epoch 71 of 200, validation loss 0.1462; restored the best weights
```

</details>
