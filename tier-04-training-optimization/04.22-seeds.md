> **In plain words**
> A **seed** is a number that sets the starting point of a random-number generator. "Random" numbers on a computer are really a long fixed sequence; the seed picks where you start. **Same seed → same "random" numbers → same run.** Different seed → a different but equally valid run. You need to seed every library that uses randomness.

**You need first:** 4.21 Reproducibility.

### 1. What is it?
An integer that initializes a pseudo-random number generator (PRNG). With the same seed, the PRNG outputs the same sequence.

### 2. Why does it exist?
Computers have no true randomness in ordinary code. Seeds make experiments repeatable, and different seeds let you measure how much results depend on luck.

### 3. Detailed explanation
- **What uses randomness in training:** weight initialization, data shuffling, dropout masks, data augmentation, sampling in generation.
- **Seed each library:** `random.seed`, `np.random.seed` / `default_rng`, `torch.manual_seed` (this also seeds CUDA). Seeding PyTorch does not seed NumPy.
- **Prefer explicit generators:** `np.random.default_rng(seed)` and `torch.Generator().manual_seed(seed)` passed to functions, which avoids hidden global state.
- **DataLoader workers:** each worker needs its own seed; use `worker_init_fn` and a `generator=` for the shuffling order. Otherwise augmentations may repeat across workers or differ run to run.
- **Spawning child seeds:** `np.random.SeedSequence(seed).spawn(n)` gives independent streams for parallel jobs.
- **Which seed to choose?** Any. 42 has no special power. Never tune the seed to get a better test score: that is cherry-picking (2.20).
- **Seed variance:** run several seeds, report mean and spread (code ③).
- **Same seed ≠ same result everywhere.** Different hardware or library versions can produce different numbers from the same seed (4.21).
- **Don't reseed inside the loop** unless you intend identical randomness every step (a classic bug: every epoch shuffles identically).
- **Security:** seeds for cryptography must come from a secure source, not a simple seed (REVIEW_REQUIRED).

### 4. How does it work?
`generator = PRNG(seed)`; each call advances the internal state and returns the next number. Same start → same sequence.

### 5. Simple example
A shuffled deck whose order is fixed by a card with a number on it. Hand the same card to two dealers and both deal exactly the same hands.

**By hand.** A tiny generator `x ← (5x + 3) mod 16` starting at seed 7 yields 6, 1, 8, 11, ... Starting at seed 7 again gives the same list.

### 6. Technical example
`def set_seed(s): random.seed(s); np.random.seed(s); torch.manual_seed(s)` called once at the start of a script, plus a seeded `DataLoader(generator=g)`.

### 7. Code
**① By hand (plain Python).** A tiny generator, and Python's own.

```python
def tiny(seed, n=6):
    x, out = seed, []
    for _ in range(n):
        x = (5 * x + 3) % 16
        out.append(x)
    return out

print("tiny generator, seed 7:", tiny(7))
print("tiny generator, seed 7:", tiny(7), "(again)")
print("tiny generator, seed 8:", tiny(8))

import random
random.seed(1); a = [random.randint(0, 9) for _ in range(5)]
random.seed(1); b = [random.randint(0, 9) for _ in range(5)]
print("Python random, seed 1 twice:", a, b)
```

```text
tiny generator, seed 7: [6, 1, 8, 11, 10, 5]
tiny generator, seed 7: [6, 1, 8, 11, 10, 5] (again)
tiny generator, seed 8: [11, 10, 5, 12, 15, 14]
Python random, seed 1 twice: [2, 9, 1, 4, 1] [2, 9, 1, 4, 1]
```

**② With NumPy.** Independent streams from one seed.

```python
import numpy as np

children = np.random.SeedSequence(2024).spawn(3)
streams = [np.random.default_rng(c) for c in children]
print("three independent streams:", [g.integers(0, 100, 4).tolist() for g in streams])
again = [np.random.default_rng(c).integers(0, 100, 4).tolist() for c in np.random.SeedSequence(2024).spawn(3)]
print("same parent seed reproduces them:", again == [np.random.default_rng(c).integers(0, 100, 4).tolist() for c in np.random.SeedSequence(2024).spawn(3)])

np.random.seed(0)
print("global NumPy seed 0:", np.random.rand(3).round(4))
```

```text
three independent streams: [[67, 65, 15, 52], [27, 12, 37, 45], [76, 92, 82, 12]]
same parent seed reproduces them: True
global NumPy seed 0: [0.5488 0.7152 0.6028]
```

**③ With PyTorch.** A seeded data order, and seed-to-seed spread.

```python
import torch
from torch.utils.data import DataLoader, TensorDataset

ds = TensorDataset(torch.arange(10))
def order(seed):
    g = torch.Generator().manual_seed(seed)
    return [b[0].item() for b in DataLoader(ds, batch_size=1, shuffle=True, generator=g)]

print("shuffle order, seed 0:", order(0))
print("shuffle order, seed 0:", order(0), "(same)")
print("shuffle order, seed 1:", order(1))

def final_loss(seed):
    torch.manual_seed(seed)
    net = torch.nn.Linear(3, 1)
    X = torch.randn(32, 3); y = X.sum(dim=1, keepdim=True)
    opt = torch.optim.SGD(net.parameters(), lr=0.05)
    for _ in range(20):
        opt.zero_grad(); torch.nn.functional.mse_loss(net(X), y).backward(); opt.step()
    return torch.nn.functional.mse_loss(net(X), y).item()

losses = [final_loss(s) for s in range(5)]
print("final loss for seeds 0-4:", [round(v, 3) for v in losses])
```

```text
shuffle order, seed 0: [3, 7, 5, 2, 0, 8, 1, 6, 9, 4]
shuffle order, seed 0: [3, 7, 5, 2, 0, 8, 1, 6, 9, 4] (same)
shuffle order, seed 1: [4, 6, 9, 2, 3, 1, 0, 7, 8, 5]
final loss for seeds 0-4: [0.033, 0.037, 0.153, 0.241, 0.101]
```

### 9. Enterprise use case
Standard practice: seed fixed in config, recorded in experiment logs, with multiple seeds for final comparisons.

### 10. AI engineering connection
Evaluation of generative models uses fixed seeds for repeatable samples; benchmarks report multiple seeds.

### 11. Advantages
Cheap, effective, essential for debugging.

### 12. Limitations
Does not guarantee identical results across hardware or versions.

### 13. Trade-offs
Fixing the seed hides variance; also report multi-seed results.

### 14. Common mistakes
Seeding only one library; reseeding inside the loop; forgetting dataloader workers; searching for a lucky seed; assuming a seed makes results portable across machines.

### 15. Performance / cost
Negligible.

### 16. Security
Predictable seeds are fine for ML experiments and unsafe for secrets or tokens.

### 20. Hands-on exercise
**Goal:** reproduce the "reseeding in the loop" bug.

1. Shuffle `range(6)` once per epoch for 3 epochs, calling `torch.manual_seed(0)` before each shuffle.
2. Repeat without reseeding inside the loop.
3. Print the orders.

```python
import torch

print("reseeding inside the loop (bug):")
for epoch in range(3):
    torch.manual_seed(0)
    print("  epoch", epoch, torch.randperm(6).tolist())
print("seeding once (correct):")
torch.manual_seed(0)
for epoch in range(3):
    print("  epoch", epoch, torch.randperm(6).tolist())
```
