# 4.15 Gradient clipping

**Metadata** — Tier: 4 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: High · Hands-on: Very high
Prerequisites: 1.15 Norms, 3.26 Exploding gradients, 4.4 Backward pass · Leads to: 4.37 Gradient monitoring, 4.38 NaN debugging

> **In plain words**
> **Gradient clipping** is a safety limit on the update size. Before the optimizer step, you check how large the whole gradient is (its **norm**). If it is bigger than a limit (often 1.0), you **shrink it to exactly the limit**, keeping its direction. A rare huge gradient then cannot throw the weights across the map.
> Like a speed governor on an engine.

**You need first:** 1.15 Norms, 3.26 Exploding gradients, 4.4 Backward pass.

> **Figure 4.15-1 — clipping in the loop**
>
> ```mermaid
> flowchart LR
>     B["loss.backward()"] --> N["total norm ‖g‖"]
>     N --> Q{"‖g‖ > max_norm ?"}
>     Q -->|"no"| S["optimizer.step()"]
>     Q -->|"yes: g ← g · max_norm / ‖g‖"| S
> ```
>
> *How to read it:* clipping sits between `backward()` and `step()`. It measures the length of the *whole* gradient (all parameters together). If the length is within the limit nothing changes; otherwise every component is scaled by the same factor so the new length equals the limit and the direction is preserved. The exploding-gradient experiment in 3.26 (Figure 3.26-1) shows why: without clipping the loss became infinite in 5 steps.

**Words you'll meet on this page**

| Word | What it means here |
|---|---|
| norm `‖g‖` | length of the gradient vector (all parameters) |
| `max_norm` | the limit (commonly 1.0) |
| clip by norm | scale the whole gradient down if too long |
| clip by value | cap each element separately |
| clip rate | share of steps in which clipping happened |
| `inf` / NaN | overflow; the norm may be non-finite |
| `clip_grad_norm_` | PyTorch's function; returns the norm before clipping |

### 1. What is it?
Rescaling gradients when their global norm exceeds a threshold: `g ← g · min(1, c / (‖g‖₂ + ε))`.

### 2. Why does it exist?
Occasionally a batch (or a bad region of the loss) yields a gradient hundreds of times too big. One giant step can undo thousands of good ones, or produce `inf`. Clipping bounds the damage without changing direction.

### 3. Detailed explanation
- **Global norm, not per-tensor.** Compute one norm over all parameters, then scale all by the same factor so the direction is unchanged (code ②).
- **Typical `max_norm`:** 1.0 for Transformers; 0.5–5 elsewhere (REVIEW_REQUIRED). Pick by looking at the gradient norm during a normal run (4.37): clip a little above its typical size.
- **Order in the loop:** `backward()` → (unscale for fp16, 4.19) → `clip_grad_norm_` → `step()`. With accumulation clip after the last micro-batch (4.14).
- **Clip rate.** Log how often it triggers. Near 0% = rarely needed (fine); near 100% = limit too tight or training is unstable (fix lr, init, data).
- **Clip by value** (`clip_grad_value_`) caps each element; it can change the direction, so it is less common.
- **It treats the symptom.** Persistent explosions come from scale problems (3.22–3.24), learning rate or data; fix those too.
- **Returns the pre-clip norm**, which is the quantity to log and plot.
- **NaN or inf norms** mean the step is already corrupted; PyTorch can raise with `error_if_nonfinite=True`, or skip the step (4.38).
- **Differential privacy** uses per-example clipping to bound each example's influence (DP-SGD).
- **Interacts with Adam:** Adam's normalization reduces, but does not remove, spikes; LLM recipes still clip at 1.0.

### 4. How does it work?
Compute `‖g‖`; if above `c`, multiply all gradients by `c/‖g‖`.

### 5. Simple example
A speed governor: below the limit nothing changes; above it, you are slowed to the limit, and still point the same way.

**By hand.** Gradient `[30, 40]` has norm 50. With `c = 1` the factor is `1/50`: new gradient `[0.6, 0.8]` (norm 1, same direction). A gradient `[0.3, 0.4]` (norm 0.5) is left alone.

### 6. Technical example
`torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)` before every `optimizer.step()` in LLM training.

### 7. Code
**① By hand (plain Python).** The clipping rule.

```python
import math

def clip(g, c=1.0):
    norm = math.sqrt(sum(v * v for v in g))
    scale = min(1.0, c / norm)
    return [v * scale for v in g], norm

for g in ([30.0, 40.0], [0.3, 0.4]):
    clipped, norm = clip(g)
    print(f"gradient {g}: norm {norm:.2f} -> clipped {[round(v, 2) for v in clipped]}")
```

```text
gradient [30.0, 40.0]: norm 50.00 -> clipped [0.6, 0.8]
gradient [0.3, 0.4]: norm 0.50 -> clipped [0.3, 0.4]
```

**② With NumPy.** Global versus per-tensor clipping: only global keeps the direction.

```python
import numpy as np

grads = [np.array([30.0, 40.0]), np.array([0.3, 0.4])]              # two parameter tensors
total = np.sqrt(sum((g ** 2).sum() for g in grads))
global_clip = [g * min(1.0, 1.0 / total) for g in grads]
per_tensor = [g * min(1.0, 1.0 / np.linalg.norm(g)) for g in grads]
direction = lambda gs: np.concatenate(gs) / np.linalg.norm(np.concatenate(gs))
print("original direction  :", direction(grads).round(4))
print("global clip         :", direction(global_clip).round(4), "<- same direction")
print("per-tensor clip     :", direction(per_tensor).round(4), "<- direction changed")
```

```text
original direction  : [0.6   0.8   0.006 0.008]
global clip         : [0.6   0.8   0.006 0.008] <- same direction
per-tensor clip     : [0.5367 0.7155 0.2683 0.3578] <- direction changed
```

**③ With PyTorch.** `clip_grad_norm_` returns the pre-clip norm; log the clip rate.

```python
import torch

torch.manual_seed(0)
model = torch.nn.Sequential(torch.nn.Linear(8, 16), torch.nn.ReLU(), torch.nn.Linear(16, 1))
opt = torch.optim.SGD(model.parameters(), lr=0.05)
norms, clipped_steps = [], 0
for step in range(200):
    X = torch.randn(32, 8)
    y = X.sum(dim=1, keepdim=True)
    if step % 50 == 49:
        y = y * 100                                                   # an occasional corrupted batch
    opt.zero_grad()
    torch.nn.functional.mse_loss(model(X), y).backward()
    norm = torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=5.0).item()
    norms.append(norm); clipped_steps += norm > 5.0
    opt.step()
print("median gradient norm:", round(sorted(norms)[len(norms) // 2], 2))
print("norm on the corrupted batches:", [round(norms[i], 1) for i in (49, 99, 149, 199)])
print(f"clip rate: {clipped_steps / 200:.0%} of steps")
```

```text
median gradient norm: 0.5
norm on the corrupted batches: [1183.3, 1294.8, 1185.7, 1131.8]
clip rate: 3% of steps
```

### 8. Input → Process → Output
`gradients → global norm → scale if above the limit → step`

### 9. Enterprise use case
Clipping plus norm logging makes long, expensive runs more robust to rare bad batches.

### 10. AI engineering connection
Standard in LLM pre-training and fine-tuning (max-norm 1.0); a required part of DP-SGD.

### 11. Advantages
One line; robust; keeps the direction.

### 12. Limitations
Hides the cause; a bad threshold slows learning.

### 13. Trade-offs
Tight clipping: stable but slower. Loose: faster but risks spikes.

### 14. Common mistakes
Clipping before unscaling fp16 gradients; clipping each tensor separately; clipping every micro-batch under accumulation; ignoring the clip rate; clipping after `step()`.

### 15. Performance / cost
Computing the global norm needs one reduction across parameters (and devices).

### 16. Security
Bounded gradients limit the influence of poisoned or outlier batches.

</details>

### 20. Hands-on exercise
**Goal:** show that clipping rescues a diverging run.

1. Fit `y = 3x` with a `Linear(1, 1)` using SGD with an unstable lr 1.5 (full batch, 30 steps).
2. Run without clipping and with `max_norm = 1.0`.
3. Print the final `w`.

<details>
<summary>Show a solution</summary>

```python
import torch

def run(clip):
    torch.manual_seed(0)
    X = torch.linspace(-2, 2, 50).unsqueeze(1); y = 3 * X
    model = torch.nn.Linear(1, 1, bias=False)
    torch.nn.init.zeros_(model.weight)
    opt = torch.optim.SGD(model.parameters(), lr=1.5)
    for _ in range(30):
        opt.zero_grad()
        torch.nn.functional.mse_loss(model(X), y).backward()
        if clip:
            torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        opt.step()
    return model.weight.item()

print("without clipping: w =", f"{run(False):.3g}", "(target 3)")
print("with clipping   : w =", f"{run(True):.3f}", "(target 3)")
```

```text
without clipping: w = -3.03e+15 (target 3)
with clipping   : w = 2.529 (target 3)
```

Clipping caps every step at `lr × 1.0 = 1.5`, so the weight can no longer explode, though it may still bounce around the target.
</details>
