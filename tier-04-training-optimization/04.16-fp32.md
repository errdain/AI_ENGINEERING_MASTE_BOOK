# 4.16 FP32 (single precision)

**Metadata** — Tier: 4 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: Medium · Hands-on: High
Prerequisites: 1.40 Floating-point precision · Leads to: 4.17 FP16, 4.18 BF16, 4.19 Mixed precision

> **In plain words**
> **FP32** stores each number in **32 bits** (4 bytes). It is PyTorch's default and the "safe" format: about 7 decimal digits of accuracy and a huge range (up to roughly 3×10³⁸). Everything else in this part (FP16, BF16, mixed precision) is about using **fewer bits** to go faster and fit bigger models, and what you risk when you do.

**You need first:** 1.40 Floating-point precision.

### 1. What is it?
IEEE-754 single precision: 1 sign bit, 8 exponent bits, 23 fraction bits. PyTorch's default `dtype` (`torch.float32`).

### 2. Why does it exist?
It is a good balance for general computing: wide range and enough precision that rounding errors rarely matter for ordinary training. It is the reference against which cheaper formats are judged.

### 3. Detailed explanation
- **Range** ≈ 1.2×10⁻³⁸ to 3.4×10³⁸; **precision** ≈ 7 decimal digits (`eps = 1.19×10⁻⁷`).
- **Memory.** 4 bytes per number: a 7-billion-parameter model needs 28 GB just for weights; Adam adds 2 more copies (4.24).
- **Speed.** Slower than 16-bit on modern accelerators because 16-bit tensor cores run faster and move half the data.
- **Where it is still needed** even in "low-precision" training: the master copy of weights, optimizer states, loss and reductions (sums, softmax, norms) (4.19).
- **Rounding.** Adding a tiny number to a big one can lose it: `1e8 + 1` is not representable distinctly in FP32 (code ②).
- **Reproducibility.** Results can differ slightly between hardware because additions are not exactly associative (4.21).
- **TF32** (on NVIDIA Ampere+): matmuls use a 10-bit fraction internally for speed while the tensors stay FP32 (REVIEW_REQUIRED: details).
- **FP64** (double) is used for numerics-sensitive science, rarely for deep learning.

### 4. How does it work?
`value = (−1)^sign × 1.fraction × 2^(exponent − 127)`. More exponent bits → bigger range; more fraction bits → finer steps.

### 5. Simple example
A ruler marked in millimetres (FP32) versus one marked only in centimetres (lower precision): the first can measure small differences; the second is lighter to carry.

**By hand.** Near 1.0 the gap between FP32 numbers is about 1.2×10⁻⁷; near 1,000,000 it is 0.0625, so `1,000,000 + 0.01` rounds back to `1,000,000`.

### 6. Technical example
Training a small model with default settings: weights, activations and gradients are all FP32.

### 7. Code
**① By hand (plain Python).** Python floats are 64-bit; `struct` shows what 32-bit storage keeps.

```python
import struct

def to_fp32(x):
    return struct.unpack("f", struct.pack("f", x))[0]

x = 0.1
print("0.1 stored in 64 bits:", repr(x))
print("0.1 stored in 32 bits:", repr(to_fp32(x)))
print("1,000,000 + 0.01 in 32 bits:", to_fp32(1_000_000 + 0.01), "(the 0.01 is lost)")
```

```text
0.1 stored in 64 bits: 0.1
0.1 stored in 32 bits: 0.10000000149011612
1,000,000 + 0.01 in 32 bits: 1000000.0 (the 0.01 is lost)
```

**② With NumPy.** Range, precision and absorption.

```python
import numpy as np

info = np.finfo(np.float32)
print("largest :", info.max, "   smallest normal:", info.tiny, "   epsilon:", info.eps)
big = np.float32(1e8)
print("1e8 + 1 == 1e8 in float32:", big + np.float32(1) == big)
print("1e8 + 1 == 1e8 in float64:", np.float64(1e8) + 1 == np.float64(1e8))
print("bytes per number:", np.dtype(np.float32).itemsize, "(float64:", np.dtype(np.float64).itemsize, ")")
```

```text
largest : 3.4028235e+38    smallest normal: 1.1754944e-38    epsilon: 1.1920929e-07
1e8 + 1 == 1e8 in float32: True
1e8 + 1 == 1e8 in float64: False
bytes per number: 4 (float64: 8 )
```

**③ With PyTorch.** Default dtype and memory for a model.

```python
import torch

print("default dtype:", torch.get_default_dtype())
model = torch.nn.Linear(1024, 1024)
params = sum(p.numel() for p in model.parameters())
print(f"parameters: {params:,}   FP32 weights: {params * 4 / 1e6:.1f} MB   (Adam adds 2 more copies: {params * 12 / 1e6:.1f} MB total)")
print("7B-parameter model, FP32 weights alone:", 7e9 * 4 / 1e9, "GB")
a = torch.tensor(1e8, dtype=torch.float32)
print("float32: 1e8 + 1 == 1e8 ->", bool(a + 1 == a))
```

```text
default dtype: torch.float32
parameters: 1,049,600   FP32 weights: 4.2 MB   (Adam adds 2 more copies: 12.6 MB total)
7B-parameter model, FP32 weights alone: 28.0 GB
float32: 1e8 + 1 == 1e8 -> True
```

### 8. Input → Process → Output
`real number → 1 sign + 8 exponent + 23 fraction bits → nearest representable value`

### 9. Enterprise use case
FP32 is the safe baseline for debugging; a model that fails in FP32 will not be fixed by lower precision.

### 10. AI engineering connection
Master weights and optimizer states stay FP32 even in mixed-precision LLM training.

### 11. Advantages
Wide range, adequate precision, supported everywhere.

### 12. Limitations
Twice the memory and bandwidth of 16-bit; slower on tensor-core hardware.

### 13. Trade-offs
Safety versus speed and memory.

### 14. Common mistakes
Assuming FP32 is exact; summing millions of numbers naively; comparing floats with `==`; forgetting that Python floats are FP64 while tensors are FP32.

### 15. Performance / cost
Memory-bound operations speed up almost 2× simply by halving bytes.

### 16. Security
No direct issue (numerical differences can break bit-exact reproducibility of audits).

### 17. Interview explanation
"FP32 has 1 sign, 8 exponent and 23 fraction bits: about seven digits of precision and a range to 10³⁸. It's the safe default; lower-precision training still keeps FP32 master weights and optimizer state because small updates can vanish at lower precision."

### 18. Rapid-fire answer
32 bits: 1/8/23; eps 1.2e-7, max 3.4e38; default dtype; the safe baseline for master weights and reductions.

### 20. Hands-on exercise
**Goal:** find the largest integer FP32 can count to exactly.

1. Increase a float32 counter by 1 until `x + 1 == x`.
2. Hint: start near 16 million.
3. Print the value.

<details>
<summary>Show a solution</summary>

```python
import numpy as np

x = np.float32(16_777_210)
while x + np.float32(1) != x:
    x = x + np.float32(1)
print("float32 stops counting at:", int(x), "   2**24 =", 2 ** 24)
```

```text
float32 stops counting at: 16777216    2**24 = 16777216
```

Above 2²⁴ the spacing between FP32 numbers is 2, so adding 1 is lost.
