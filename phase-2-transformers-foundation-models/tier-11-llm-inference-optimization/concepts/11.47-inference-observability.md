### 1. WHAT IS IT?

**Inference observability** is the collection of metrics, logs and traces that show how an LLM service behaves in production.

### 2. WHY DOES IT EXIST?

Averages hide tail latency and saturation; you need request- and server-level signals to debug.

### 3. DETAILED EXPLANATION

Per request: queue time, TTFT, ITL distribution, input/output tokens, finish reason (stop / length / error / cancelled), prefix-cache hit, model/version, tenant. Per server: batch size, KV-cache utilization, queue depth, preemptions, tokens/s, GPU memory/utilization, error rates. Alert on p95/p99 TTFT/ITL and on KV-cache saturation; sample prompts/outputs for quality review subject to privacy policy.

### 4. HOW DOES IT WORK?

Instrument gateway and engine → export metrics/traces → dashboards and alerts → postmortems.

### 5. SIMPLE EXAMPLE

A car dashboard: speed, fuel, temperature, warning lights.

### 6. TECHNICAL EXAMPLE

p95 TTFT rises with KV utilization at 100% → memory pressure and preemptions, not "the model is slow".

### 7. CODE

```python
# percentile summary of latencies (stdlib only)
import statistics as st
ttft_ms = [180, 190, 210, 220, 230, 250, 260, 900, 1200, 240]
q = st.quantiles(ttft_ms, n=100)
print("mean", st.mean(ttft_ms), "p50", st.median(ttft_ms), "p95", round(q[94]), "p99", round(q[98]))
```

### 8. INPUT → PROCESS → OUTPUT

```
requests ─► metrics/logs/traces ─► dashboards ─► alerts ─► actions (scale, shed, rollback)
```

### 9. ENTERPRISE USE CASE

SRE teams add LLM-specific SLOs (p95 TTFT, finish-reason rate) next to standard ones.

### 10. AI ENGINEERING CONNECTION

Feeds autoscaling ([11.37 Serving autoscaling](11.37-serving-autoscaling.md)) and cost platforms (Tier 36).

### 11. ADVANTAGES

- Faster diagnosis; data-driven capacity planning.

### 12. LIMITATIONS

- Cardinality and storage cost; privacy limits.

### 13. TRADE-OFFS

Detail vs cost and privacy.

### 14. COMMON MISTAKES

- Only averages. - No finish-reason metric (silent truncation). - Logging raw PII prompts.

### 15. PERFORMANCE / COST CONSIDERATIONS

Sampling and aggregation control overhead.

### 16. SECURITY CONSIDERATIONS

Logs and traces of prompts/outputs are sensitive: redact, restrict, set retention.

### 17. INTERVIEW EXPLANATION

"I monitor latency split into queue, TTFT and ITL, tokens, finish reasons, KV and GPU saturation, error and cancel rates, plus quality samples; I alert on percentiles."

### 18. RAPID-FIRE ANSWER

Percentiles, tokens, finish reasons, KV saturation.

### 19. INTERVIEW QUESTIONS

**Basic:** Which latency metrics? **Intermediate:** Why finish reason? **Advanced:** What does KV 100% imply? **Scenario:** p99 spikes only for one tenant — investigate.
