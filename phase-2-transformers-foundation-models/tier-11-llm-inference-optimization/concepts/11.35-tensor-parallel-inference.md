### 1. WHAT IS IT?

**Tensor-parallel (TP) inference** shards each layer's weight matrices across several GPUs; each GPU computes a slice and results are combined by collective communication (all-reduce) after layer blocks.

### 2. WHY DOES IT EXIST?

The model's weights (and KV cache) may not fit on one GPU, and a single GPU's memory bandwidth may bound latency. Splitting each layer lets N GPUs share the load and read less each.

### 3. DETAILED EXPLANATION

- Attention heads are split across GPUs (query and KV heads — GQA/MQA from [Tier 8](../../tier-08-transformer-architecture/README.md)); MLP matrices are split column- then row-wise so that one all-reduce per block (two per layer) is enough (Megatron-style — `REVIEW_REQUIRED`).
- Per-GPU weights ≈ total/N, so per-token latency can drop (each GPU reads less) — until communication dominates.
- Needs fast interconnect (NVLink-class within a node; `REVIEW_REQUIRED`); TP across slow links hurts badly.
- KV-heads must divide across GPUs; with few KV heads (GQA) TP degree is limited or KV is replicated (`REVIEW_REQUIRED`).

### 4. HOW DOES IT WORK?

```
x ─► [GPU0: W[:, 0:n/2]] ┐
  ─► [GPU1: W[:, n/2:n]] ┘─► partial outputs ─► all-reduce ─► next op
```
1. Split weights at load time. 2. Each GPU computes its partial result. 3. All-reduce sums partials. 4. Repeat per layer; sampling happens on one rank.

### 5. SIMPLE EXAMPLE

Four cooks each chop a quarter of the vegetables for the same dish, then combine at the pass: the dish is ready sooner, but cooks must talk constantly.

### 6. TECHNICAL EXAMPLE

A 70B model in FP16 (≈ 140 GB) does not fit one 80 GB GPU (illustrative); TP=2 puts 70 GB weights on each — too tight with KV — so TP=4 leaves room for KV cache. Quantizing to 4 bits might allow TP=1 or 2 (`REVIEW_REQUIRED`).

### 7. CODE

```python
# Column-parallel then row-parallel matmul in numpy: partial sums equal the full result
import numpy as np
rng = np.random.default_rng(0)
x = rng.normal(size=(2, 8)); A = rng.normal(size=(8, 16)); B = rng.normal(size=(16, 8))
full = (x @ A) @ B
A0, A1 = np.split(A, 2, axis=1)          # column-parallel: each "GPU" holds half of A's columns
B0, B1 = np.split(B, 2, axis=0)          # row-parallel: matching half of B's rows
partial0 = (x @ A0) @ B0
partial1 = (x @ A1) @ B1
assert np.allclose(full, partial0 + partial1)   # the all-reduce is this sum
print("TP split matches")
```

### 8. INPUT → PROCESS → OUTPUT

```
weights ─shard─► N GPUs ─local matmul─► partial sums ─all-reduce─► activations ─► next layer
```

### 9. ENTERPRISE USE CASE

Large dense models served with TP=4 or 8 inside one node.

### 10. AI ENGINEERING CONNECTION

Mandatory when a model exceeds one GPU; interacts with quantization, KV capacity and batch size ([11.44 GPU-memory budgeting](11.44-gpu-memory-budgeting.md)).

### 11. ADVANTAGES

- Fits big models; lower per-token latency; balanced memory.

### 12. LIMITATIONS

- Communication every layer; needs fast links; fixed degree; extra failure domain (one GPU failing stops all).

### 13. TRADE-OFFS

Latency/memory per GPU vs communication overhead and cost.

### 14. COMMON MISTAKES

- TP across nodes on slow network. - Ignoring KV-head divisibility. - Assuming linear speedup.

### 15. PERFORMANCE / COST CONSIDERATIONS

Speedup < N due to all-reduce; compare TP vs more replicas in $/tok.

### 16. SECURITY CONSIDERATIONS

Interconnect traffic carries activations — keep inside trusted network; isolate GPUs per tenant.

### 17. INTERVIEW EXPLANATION

"Tensor parallelism splits each weight matrix across GPUs: column-parallel then row-parallel, so one all-reduce per block recombines results. It both fits larger models and cuts per-token latency, but it needs fast interconnect, so I use it within a node and pipeline parallelism across nodes."

### 18. RAPID-FIRE ANSWER

TP shards each layer across GPUs with an all-reduce per block; fast links needed.
