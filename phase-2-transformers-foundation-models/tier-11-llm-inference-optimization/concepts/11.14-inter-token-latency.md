### 1. WHAT IS IT?

**Inter-token latency (ITL)**, also called time per output token (TPOT), is the time between consecutive output tokens during decode.

### 2. WHY DOES IT EXIST?

It determines how smooth streaming feels and, with output length, total latency.

### 3. DETAILED EXPLANATION

End-to-end latency is about `TTFT + (N_out - 1) x ITL`. ITL is driven by memory bandwidth, batch size and KV-cache size (decode is memory-bound, [11.12 Decode phase](11.12-decode-phase.md)). Per-user tokens/s is about `1/ITL` ([11.15 Tokens per second](11.15-tokens-per-second.md)). Larger batches raise system throughput but also ITL. Track the p95/p99 ITL distribution: occasional long stalls (a prefill interleaved, a preemption) matter more than the mean.

### 4. HOW DOES IT WORK?

Measure timestamps of consecutive streamed tokens; ITL = difference. Lower bound: `weight bytes / bandwidth` plus KV reads.

### 5. SIMPLE EXAMPLE

The gap between words when someone speaks: steady and fast feels natural, long pauses feel broken.

### 6. TECHNICAL EXAMPLE

Chat UIs want ITL below reading speed (illustrative targets such as p95 < 50 ms; REVIEW_REQUIRED).

### 7. CODE

```python
def itls(stamps):
    """stamps: arrival times (s) of each streamed token."""
    return [b - a for a, b in zip(stamps, stamps[1:])]

x = itls([0.50, 0.55, 0.60, 0.80, 0.85])
print(x, "max stall:", max(x))      # the 0.2 s gap is what users notice
```

### 8. INPUT → PROCESS → OUTPUT

```
token_i arrives --(dt)--> token_{i+1} arrives ; ITL = dt, distribution over a request
```

### 9. ENTERPRISE USE CASE

Per-tenant ITL percentiles in the serving dashboard.

### 10. AI ENGINEERING CONNECTION

Agents and voice assistants have hard ITL needs (speech playback must not underrun).

### 11. ADVANTAGES

Easy to compute from streaming timestamps; maps directly to perceived smoothness.

### 12. LIMITATIONS

Averages hide stalls; depends on batch composition.

### 13. TRADE-OFFS

Batch size and concurrency trade ITL against throughput.

### 14. COMMON MISTAKES

Using mean ITL; including prefill gap in ITL; comparing across different batch sizes.

### 15. PERFORMANCE / COST CONSIDERATIONS

Lower ITL needs smaller batches or faster/quantized weights, which cost throughput or accuracy.

### 16. SECURITY CONSIDERATIONS

No distinct concerns beyond telemetry privacy.

### 17. INTERVIEW EXPLANATION

"ITL is the gap between streamed tokens. It's dominated by how many bytes the GPU reads per step, so it rises with batch size and KV size and falls with quantization and more bandwidth. I watch p95 because stalls matter more than averages."

### 18. RAPID-FIRE ANSWER

Time between consecutive output tokens; set by memory bandwidth, batch and KV size.
