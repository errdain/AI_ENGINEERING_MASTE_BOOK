### 1. WHAT IS IT?

**Ollama** is a local model manager: it downloads models from a registry, runs them behind a local HTTP API and offers a simple CLI. It builds on the llama.cpp lineage (`REVIEW_REQUIRED` for exactly which engine/versions it uses today). All details here are concept-level — check current Ollama docs.

### 2. WHY DOES IT EXIST?

Running a local LLM used to need compiling, converting and choosing flags. Ollama packages "pull a model, run it" into two commands, aimed at developer laptops and quick prototypes.

### 3. DETAILED EXPLANATION

- Models are referenced by name and tag (e.g. a size/quantization tag); defaults for quantization and **context length** may not match your assumption — check them (`REVIEW_REQUIRED`).
- A local server (default port 11434 — `REVIEW_REQUIRED`) exposes native and OpenAI-compatible endpoints.
- A `Modelfile` can set system prompt, parameters and base model (`REVIEW_REQUIRED`).
- It targets one user's machine; concurrency options exist but are not its design focus.

### 4. HOW DOES IT WORK?

`ollama pull` fetches a quantized model ─► `ollama serve` (background) loads it on demand into RAM/VRAM ─► requests go to the HTTP API ─► tokens stream back; idle models are unloaded after a timeout (`REVIEW_REQUIRED`), which causes a "cold start" ([11.38 Cold starts](11.38-cold-starts.md)) on the next request.

### 5. SIMPLE EXAMPLE

An app store for local models: tap install, tap run.

### 6. TECHNICAL EXAMPLE

A developer prototypes a RAG app against `localhost:11434` with no API cost or data leaving the laptop, then swaps in a hosted or vLLM endpoint for production.

### 7. CODE

```bash
# not executed in this book's tests; REVIEW_REQUIRED for current syntax
ollama pull llama3.1:8b
ollama run llama3.1:8b "Say hi in five words."
```
```python
# not executed in this book's tests: needs a running Ollama server
import json, urllib.request
req = urllib.request.Request("http://127.0.0.1:11434/api/generate",
        data=json.dumps({"model": "llama3.1:8b", "prompt": "Hi", "stream": False}).encode(),
        headers={"Content-Type": "application/json"})
print(json.load(urllib.request.urlopen(req, timeout=60))["response"])
```

### 8. INPUT → PROCESS → OUTPUT

```
CLI / app ─► localhost:11434 API ─► model manager ─► llama.cpp-style runtime ─► tokens
```

### 9. ENTERPRISE USE CASE

Privacy-first demos, internal tooling prototypes, offline developer environments; not usually the production serving tier for many users.

### 10. AI ENGINEERING CONNECTION

Easiest local backend for agent and RAG prototyping; OpenAI-compatible endpoints make swapping to [11.32 vLLM](11.32-vllm.md) simple.

### 11. ADVANTAGES

- Very easy setup; model registry; local privacy; OpenAI-compatible API.

### 12. LIMITATIONS

- Limited concurrency/throughput tuning; hidden defaults; single-machine focus.

### 13. TRADE-OFFS

Convenience vs control and peak throughput.

### 14. COMMON MISTAKES

- Assuming default context length is large. - Benchmarking on a laptop and extrapolating. - Binding the server to a public interface.

### 15. PERFORMANCE / COST CONSIDERATIONS

First request after idle includes model load; memory use = weights + KV for the configured context.

### 16. SECURITY CONSIDERATIONS

Default binds to localhost; exposing it (`OLLAMA_HOST=0.0.0.0` style settings, `REVIEW_REQUIRED`) without auth exposes your model and prompts. Pull models only from trusted registries.

### 17. INTERVIEW EXPLANATION

"Ollama is a developer-friendly local runtime: pull a quantized model and call a local API. It's great for prototypes and privacy, whereas vLLM targets multi-user GPU throughput."

### 18. RAPID-FIRE ANSWER

Ollama = easy local LLM manager and API; vLLM = high-throughput GPU serving.

### 19. INTERVIEW QUESTIONS

**Basic:** What does Ollama do? **Intermediate:** Why can the first request be slow? **Advanced:** How would you migrate a prototype from Ollama to production? **Scenario:** Answers truncate mid-thought; check what? (context length and max output defaults.)
