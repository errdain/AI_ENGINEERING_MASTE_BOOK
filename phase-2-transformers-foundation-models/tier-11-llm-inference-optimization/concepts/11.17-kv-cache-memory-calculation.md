### 1. WHAT IS IT?

**KV-cache memory calculation** is the formula and arithmetic for how many bytes the KV cache needs:

`bytes = 2 (K and V) x layers x kv_heads x head_dim x seq_len x batch x bytes_per_element`

### 2. WHY DOES IT EXIST?

Capacity planning needs a number: how many concurrent sequences fit, and what long contexts cost. The weights are fixed per model; the KV cache scales with traffic.

### 3. DETAILED EXPLANATION

- Use **KV heads**, not query heads: GQA/MQA models have far fewer KV heads (Tier 8).
- Per token: `2 x layers x kv_heads x head_dim x bytes`.
- Worked example (illustrative 7B-class shape, REVIEW_REQUIRED for any real model): 32 layers, 8 KV heads, head_dim 128, fp16 (2 B) -> per token `2x32x8x128x2 = 131,072 B = 128 KiB`. A 4,096-token sequence is **512 MiB**; 8 such sequences are 4 GiB. With full multi-head attention (32 KV heads) the same context costs **4x** more (2 GiB per sequence).
- Illustrative 70B-class shape: 80 layers, 8 KV heads, head_dim 128, fp16 -> 320 KiB per token, 8,192 tokens = 2.5 GiB per sequence.
- The lab verifies the formula against the real tensor sizes (`benchmark.py`: 32,768 B measured = 32,768 B formula for 4 layers, 2 KV heads, head_dim 16, 32 tokens, fp32; test `test_kv_formula`).

### 4. HOW DOES IT WORK?

1. Read layers, KV heads, head_dim from the model config.
2. Pick dtype bytes (fp16 = 2, fp8/int8 = 1, int4 = 0.5).
3. Multiply by 2 (K and V).
4. Multiply by tokens and batch.

### 5. SIMPLE EXAMPLE

Luggage: each passenger (token) needs a fixed number of bags (layers x heads x dims x 2); the cargo hold is the GPU.

### 6. TECHNICAL EXAMPLE

How many 4k-token sequences fit on an 80 GB GPU after 16 GB of weights? See [11.44 GPU-memory budgeting](11.44-gpu-memory-budgeting.md).

### 7. CODE

```python
from kv_memory import kv_bytes, kv_bytes_per_token, max_concurrent

per_tok = kv_bytes_per_token(layers=32, kv_heads=8, head_dim=128, dtype="fp16")
print(per_tok, "bytes per token")                         # 131072
seq = kv_bytes(32, 8, 128, seq_len=4096, batch=1)
print(seq / 2**20, "MiB per 4k sequence")                 # 512.0
print(max_concurrent(gpu_gb=80, weights_gb=16, per_seq_bytes=seq))   # sequences (overhead 10 %)
```

See [`../lab/kv_memory.py`](../lab/kv_memory.py).

### 8. INPUT → PROCESS → OUTPUT

```
config (L, kv_heads, d_head) x dtype x tokens x batch x 2  ->  bytes  ->  max concurrent sequences
```

### 9. ENTERPRISE USE CASE

Platform teams publish per-model "max concurrent tokens" tables for each GPU type.

### 10. AI ENGINEERING CONNECTION

Context-length pricing, GQA adoption and KV quantization are all driven by this formula.

### 11. ADVANTAGES

Simple, exact (up to engine overhead), actionable.

### 12. LIMITATIONS

Excludes activations, workspace, CUDA graphs and fragmentation; real engines need headroom.

### 13. TRADE-OFFS

Longer context and larger batches versus fewer concurrent users.

### 14. COMMON MISTAKES

Using query heads instead of KV heads; forgetting the factor 2; assuming fp16 when the engine stores fp8/int8 KV; ignoring headroom.

### 15. PERFORMANCE / COST CONSIDERATIONS

KV memory per token times concurrent tokens decides GPU count for a fixed latency target.

### 16. SECURITY CONSIDERATIONS

Denial-of-service via very long contexts: cap max context per request and per tenant.

### 17. INTERVIEW EXPLANATION

"KV bytes equal two times layers times KV heads times head dimension times tokens times batch times bytes per element. For a 7B-class model with GQA that's around 128 KiB per token, so a 4k context costs half a gigabyte. That, not weights, usually limits concurrency."

### 18. RAPID-FIRE ANSWER

`2 x layers x kv_heads x head_dim x tokens x batch x dtype_bytes`.

### 19. INTERVIEW QUESTIONS

**Basic.** What is the formula? **Intermediate.** Compute for 80 layers, 8 KV heads, head_dim 128, fp16, 8k tokens. (2.5 GiB.) **Advanced.** How much does MQA save vs MHA with 32 heads? (32x fewer KV heads.) **Scenario.** The team wants 128k context; what changes? (Per-sequence KV is 32x the 4k case; limit concurrency or quantize KV.)
