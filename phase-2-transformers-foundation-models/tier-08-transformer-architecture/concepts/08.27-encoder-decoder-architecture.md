### 1. WHAT IS IT?

**Encoder-decoder architecture** (family view). This entry is the roadmap's second listing of the concept; the wiring of the two stacks and cross-attention is taught in [8.4 Encoder-decoder architecture](08.04-encoder-decoder-architecture.md). Here the focus is **when to choose this family** compared with encoder-only and decoder-only models.

### 2. WHY DOES IT EXIST?

A product requirement tells you the architecture: vectors/labels, free-form generation, or strict input-to-output transformation. This concept is the decision rule.

### 3. DETAILED EXPLANATION

| | Encoder-only | Decoder-only | Encoder-decoder |
|---|---|---|---|
| Self-attention | full | causal | encoder full, decoder causal |
| Cross-attention | - | - | **yes** |
| Objective | masked | causal | span/denoising (seq2seq) |
| Generates text? | not natively | **yes** | yes |
| Typical use | embeddings, classification, rerank | chat, code, general LLM | translation, summarisation |
| Examples | BERT-family | GPT-family, many open LLMs | T5, BART |
| Params per block | `12d^2` | `12d^2` | enc `12d^2`, dec `16d^2` |

**Decision rule.** Need vectors or labels cheaply -> encoder-only. Need open-ended generation or tool use -> decoder-only. Need a strict input->output transformation with a smaller model -> encoder-decoder can still be competitive. Cost drivers: parameters ([8.21 Parameter counting](08.21-parameter-counting.md)), context length ([Tier 11 — Inference](../../tier-11-llm-inference-optimization/README.md)), serving complexity (two stacks vs one).

### 4. HOW DOES IT WORK?

1. Describe the task as input -> output. 2. If output is a label/vector: encoder-only. 3. If open-ended text: decoder-only. 4. If a bounded transformation of a given source: consider encoder-decoder.

### 5. SIMPLE EXAMPLE

Choosing between a reader (encoder), a writer (decoder), or a translator-who-reads-then-writes (encoder-decoder).

### 6. TECHNICAL EXAMPLE

Summarising invoices into structured JSON with a small 220 M-class model versus a general LLM: the smaller encoder-decoder is cheaper if quality suffices (`REVIEW_REQUIRED` for any specific size).

### 7. CODE

```python
def choose_family(output: str, needs_open_generation: bool, source_bounded: bool) -> str:
    """Toy decision helper mirroring the table above."""
    if output in ("label", "vector", "span"):
        return "encoder-only"
    if needs_open_generation:
        return "decoder-only"
    return "encoder-decoder" if source_bounded else "decoder-only"

assert choose_family("label", False, True) == "encoder-only"
assert choose_family("text", True, False) == "decoder-only"
assert choose_family("text", False, True) == "encoder-decoder"
```

### 8. INPUT → PROCESS → OUTPUT

```
task -> output type? -> label/vector -> encoder-only
                     -> open text   -> decoder-only
                     -> bounded rewrite of a source -> encoder-decoder
```

### 9. ENTERPRISE USE CASE

Architecture choice is a cost decision: small encoders for classification at scale, decoder LLMs for assistants, seq2seq for bounded transformations.

### 10. AI ENGINEERING CONNECTION

Tier 12 shows modern variants; RAG pipelines typically combine an encoder (retrieval) with a decoder (generation).

### 11. ADVANTAGES

Right-sized models; clear task fit.

### 12. LIMITATIONS

Ecosystem and tooling are strongest for decoder-only.

### 13. TRADE-OFFS

Task fit and cost versus tooling and flexibility.

### 14. COMMON MISTAKES

Using a causal LM for embeddings without pooling or training; assuming BERT is obsolete; mixing tokenizers between model and checkpoint.

### 15. PERFORMANCE / COST CONSIDERATIONS

Two stacks double serving complexity; encoders cost far less per classification than LLMs.

### 16. SECURITY CONSIDERATIONS

Different families have different injection surfaces: generators follow instructions in their input; classifiers can be fooled by adversarial text.

### 17. INTERVIEW EXPLANATION

*"I choose by output type: labels or vectors, an encoder; open-ended generation or tool use, a decoder-only LLM; a bounded rewrite of a given source, an encoder-decoder can be competitive and cheaper. Decoder-only dominates general LLMs because of one objective, simple serving and in-context learning."*

### 18. RAPID-FIRE ANSWER

Pick by output type: encoder for labels, decoder for open text, enc-dec for bounded rewrites.
