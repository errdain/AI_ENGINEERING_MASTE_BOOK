### 1. WHAT IS IT?

The **number of layers** `L` is the depth of the stack: how many blocks the stream passes through.

### 2. WHY DOES IT EXIST?

Depth gives more sequential computation per token and more parameters; it is the other main size knob besides width.

### 3. DETAILED EXPLANATION

- Parameters and per-token latency grow linearly in `L` (about `12 d^2` parameters each).
- Layers cannot be parallelised for a single token at inference.
- Typical depths: a handful for toy/small models up to around a hundred for very large ones (`REVIEW_REQUIRED` per model).
- Training stability, not parameter count, is the first limit on depth ([8.10 Residual connections](08.10-residual-connections.md), [8.12 Pre-LN](08.12-pre-ln.md)).

{fig('11_width_depth_heads.png', 'Figure 11 - Middle: parameters grow linearly with L (d = 768).')}

### 4. HOW DOES IT WORK?

1. Pick `L`. 2. Total block params `L * 12 d^2`. 3. Latency `~ L * per-block time`.

### 5. SIMPLE EXAMPLE

More floors in a building: more space and more steps between ground and roof.

### 6. TECHNICAL EXAMPLE

GPT-2 small: 12; a 7 B-class open model: 32; its 70 B sibling: 80 (`REVIEW_REQUIRED`).

### 7. CODE

```python
from mini_gpt import GPTConfig, count_params_formula

base = dict(vocab_size=50257, block_size=1024, d_model=768, n_head=12)
for L in (6, 12, 24):
    print(L, f"{count_params_formula(GPTConfig(**base, n_layer=L))/1e6:.1f} M")
d1 = count_params_formula(GPTConfig(**base, n_layer=13)) - count_params_formula(GPTConfig(**base, n_layer=12))
assert d1 == count_params_formula(GPTConfig(**base, n_layer=2)) - count_params_formula(GPTConfig(**base, n_layer=1))
print("one more layer =", d1, "parameters")   # 7,087,872 for d=768 with biases
```

### 8. INPUT → PROCESS → OUTPUT

```
choose L -> params += 12 d^2 per layer -> latency += one block per token
```

### 9. ENTERPRISE USE CASE

Deeper models need more pipeline stages; shallow-wide models parallelise better across a node.

### 10. AI ENGINEERING CONNECTION

Depth affects KV cache size (one K and V per layer) and serving latency ([Tier 11 — Inference](../../tier-11-llm-inference-optimization/README.md)).

### 11. ADVANTAGES

More sequential reasoning steps.

### 12. LIMITATIONS

Latency; vanishing gradients; diminishing returns.

### 13. TRADE-OFFS

Depth versus width versus latency.

### 14. COMMON MISTAKES

Assuming depth is free; ignoring KV cache growth.

### 15. PERFORMANCE / COST CONSIDERATIONS

Per-token latency ~`L`; KV cache ~`L`.

### 16. SECURITY CONSIDERATIONS

None specific.

### 17. INTERVIEW EXPLANATION
