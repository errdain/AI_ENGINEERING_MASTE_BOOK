### 1. WHAT IS IT?

The **hidden dimension** (`d_model`) is the width of the residual stream: the size of the vector that represents each token between sub-layers.

### 2. WHY DOES IT EXIST?

It sets the representational capacity per layer and the size of every weight matrix.

### 3. DETAILED EXPLANATION

- Parameters per block grow as `d^2` (about `12 d^2`).
- `d` must be divisible by the number of heads ([8.19 Number of heads](08.19-number-of-heads.md)); a multiple of 64/128 is typical for tensor-core efficiency.
- Wider vs deeper is a trade-off studied in scaling work ([Tier 9 — Pre-training](../../tier-09-foundation-model-pretraining/README.md) owns scaling laws).
- Doubling `d` makes block parameters and per-token FLOPs ~4x (the embedding table 2x).

### 4. HOW DOES IT WORK?

1. Choose `d` (e.g. 768). 2. All projections become `d x d` or `d x d_ff`. 3. Embedding tables become `V x d`.

### 5. SIMPLE EXAMPLE

The width of the pipe: wider pipes carry more information per token but cost quadratically more to build.

### 6. TECHNICAL EXAMPLE

GPT-2 small `d=768`; Mini-GPT `d=96`; `d=1024` gives `12*1024^2 = 12.6 M` parameters per block.

### 7. CODE

```python
from mini_gpt import GPTConfig, count_params_formula

for d in (256, 512, 1024):
    cfg = GPTConfig(vocab_size=50257, block_size=1024, n_layer=12, n_head=8, d_model=d)
    print(d, f"{count_params_formula(cfg)/1e6:.1f} M")
a = count_params_formula(GPTConfig(vocab_size=50257, block_size=1024, n_layer=12, n_head=8, d_model=512))
b = count_params_formula(GPTConfig(vocab_size=50257, block_size=1024, n_layer=12, n_head=8, d_model=1024))
assert 3 < (b - 50257 * 1024 - 1024 * 1024) / (a - 50257 * 512 - 1024 * 512) < 4.2   # blocks ~4x
```

### 8. INPUT → PROCESS → OUTPUT

```
choose d -> block params ~12 d^2 -> embeddings V*d -> total
```

### 9. ENTERPRISE USE CASE

Memory per replica and tensor-parallel degree are chosen from `d`; GPUs prefer multiples of 128.

### 10. AI ENGINEERING CONNECTION

Wider models carry more per layer; KV cache per token is `~2 * L * d` values, so width affects serving memory ([Tier 11 — Inference](../../tier-11-llm-inference-optimization/README.md)).

### 11. ADVANTAGES

More capacity per layer; good tensor-core use.

### 12. LIMITATIONS

Quadratic parameter and compute growth.

### 13. TRADE-OFFS

Width versus depth versus context at fixed budget.

### 14. COMMON MISTAKES

`d` not divisible by heads; scaling `d` without `d_ff` consistently; ignoring the 2x embedding growth.

### 15. PERFORMANCE / COST CONSIDERATIONS

Block cost ~`d^2`; KV cache ~`d`.

### 16. SECURITY CONSIDERATIONS

No specific attack surface.

### 17. INTERVIEW EXPLANATION

*"The hidden dimension is the width of the residual stream; every weight matrix scales with it, so parameters grow quadratically in d, and it must divide evenly into heads."*

### 18. RAPID-FIRE ANSWER

`d_model`: stream width; parameters scale as `d^2`.
