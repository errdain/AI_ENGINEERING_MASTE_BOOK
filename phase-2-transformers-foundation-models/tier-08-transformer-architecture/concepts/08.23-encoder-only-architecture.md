### 1. WHAT IS IT?

**Encoder-only architecture** is the model family built from a stack of encoder blocks alone (bidirectional self-attention, no decoder, no cross-attention), producing one contextual vector per token and trained with a masked objective ([8.30 Masked objective](08.30-masked-objective.md)).

### 2. WHY DOES IT EXIST?

Many products need *representations or labels*, not generated text. A bidirectional model with a task head is the cheapest accurate way to get them.

### 3. DETAILED EXPLANATION

- Output: `(B,T,d)`; add a head for classification, tagging, span extraction, or pool into one embedding.
- Objective: masked language modelling; later work also uses contrastive training for retrieval embeddings (Tier 20).
- Cannot generate fluently token by token.
- Examples: the BERT family ([8.24 BERT](08.24-bert.md)) and many embedding/reranker models.

| | Encoder-only | Decoder-only | Encoder-decoder |
|---|---|---|---|
| Self-attention | full | causal | encoder full, decoder causal |
| Cross-attention | - | - | yes |
| Objective | masked | causal | span/denoising |
| Generates text? | not natively | yes | yes |
| Typical use | embeddings, classification, rerank | chat, code, general LLM | translation, summarisation |

### 4. HOW DOES IT WORK?

1. Tokenise; add special tokens (e.g. a classification token). 2. Run the encoder. 3. Take a pooled vector or per-token vectors. 4. Apply the head.

### 5. SIMPLE EXAMPLE

Reading a whole page and then answering multiple-choice questions about it.

### 6. TECHNICAL EXAMPLE

A ticket classifier or a reranker scoring (query, document) pairs; semantic-search embedding models.

### 7. CODE

```python
import torch, torch.nn as nn

class Classifier(nn.Module):
    def __init__(self, vocab=100, d=64, n_cls=3):
        super().__init__()
        self.emb = nn.Embedding(vocab, d)
        self.enc = nn.TransformerEncoder(nn.TransformerEncoderLayer(d, 4, 4 * d, 0.0, batch_first=True, norm_first=True), 2)
        self.head = nn.Linear(d, n_cls)
    def forward(self, ids, pad):                       # pad: (B,T) True = padding
        h = self.enc(self.emb(ids), src_key_padding_mask=pad)
        keep = (~pad).unsqueeze(-1).float()
        pooled = (h * keep).sum(1) / keep.sum(1)       # mean pooling over real tokens
        return self.head(pooled)

m = Classifier().eval()
ids = torch.randint(1, 100, (2, 6)); pad = torch.tensor([[0]*6, [0, 0, 0, 1, 1, 1]], dtype=torch.bool)
print(m(ids, pad).shape)                               # (2, 3)
```

### 8. INPUT → PROCESS → OUTPUT

```
tokens -> encoder (bidirectional) -> (B,T,d) -> pool -> head -> labels / embedding
```

### 9. ENTERPRISE USE CASE

High-volume classification, routing, PII tagging, search embeddings and reranking at low latency.

### 10. AI ENGINEERING CONNECTION

Backbone of retrieval stacks for RAG (Tier 20) and of guard/classifier models around LLMs.

### 11. ADVANTAGES

Cheap, fast, deterministic, strong for understanding tasks; no KV cache.

### 12. LIMITATIONS

No native generation; fixed context; masked pre-training is sample-inefficient.

### 13. TRADE-OFFS

Cost and speed versus generative flexibility.

### 14. COMMON MISTAKES

Using an encoder for generation; forgetting pooling choice/pad mask; domain mismatch.

### 15. PERFORMANCE / COST CONSIDERATIONS

One forward pass; orders of magnitude cheaper than an LLM for classification (REVIEW_REQUIRED for any specific ratio).

### 16. SECURITY CONSIDERATIONS

Truncation can drop the decisive text; inputs are untrusted; adversarial examples can flip classifiers.

### 17. INTERVIEW EXPLANATION

*"Encoder-only models read the whole input bidirectionally and output a vector per token. Trained with masked language modelling, they are the workhorse for classification, tagging, embeddings and reranking, and far cheaper than an LLM for those jobs, but they cannot generate text."*

### 18. RAPID-FIRE ANSWER

Bidirectional stack for understanding tasks.
