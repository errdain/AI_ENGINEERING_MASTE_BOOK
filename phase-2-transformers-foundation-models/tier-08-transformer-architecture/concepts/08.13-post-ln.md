### 1. WHAT IS IT?

**Post-LN** is the original layout: `x <- Norm(x + F(x))`. The norm is applied after the residual add, so the stream passes through a normalisation every sub-layer.

### 2. WHY DOES IT EXIST?

It was the 2017 design: it keeps every layer's input at a controlled scale and gives good final quality when training succeeds.

### 3. DETAILED EXPLANATION

- The stream is pinned to RMS ~1 after every sub-layer (see Figure 4 left).
- No final norm is needed: the last sub-layer already ends with one.
- Deep stacks need **learning-rate warm-up** and careful initialisation; large learning rates can diverge.
- Used by the original Transformer and original BERT (`REVIEW_REQUIRED` per model); mostly replaced by [8.12 Pre-LN](08.12-pre-ln.md) in LLMs.

### 4. HOW DOES IT WORK?

1. Compute `F(x)`.
2. Add to the stream: `x + F(x)`.
3. Normalise the sum.
4. Repeat for the FFN sub-layer.

### 6. TECHNICAL EXAMPLE

Setting `prenorm=False` in `GPTConfig` builds a Post-LN Mini-GPT (and drops the final norm: `final_norm = nn.Identity()`).

### 7. CODE

```python
import torch
from mini_gpt import GPTConfig, Block

cfg = GPTConfig(vocab_size=41, block_size=16, n_layer=1, n_head=2, d_model=32, prenorm=False)
blk = Block(cfg).eval()
x = torch.randn(2, 8, 32)
manual = blk.n1(x + blk.attn(x))               # Norm(x + F(x))
manual = blk.n2(manual + blk.mlp(manual))
assert torch.allclose(blk(x), manual, atol=1e-6)
print("RMS after block:", blk(x).pow(2).mean().sqrt().item())   # close to 1 (LayerNorm output)
```

### 8. INPUT → PROCESS → OUTPUT

```
x --> F --> (+) --> Norm --> next      (x also feeds (+))
```

### 9. ENTERPRISE USE CASE

Legacy encoder models (BERT-family) are Post-LN; fine-tuning them with large learning rates and no warm-up can diverge.

### 10. AI ENGINEERING CONNECTION

Explains why many older encoder checkpoints need warm-up in fine-tuning ([Tier 10 — Fine-tuning](../../tier-10-fine-tuning-alignment/README.md)).

### 11. ADVANTAGES

Controlled scale at every layer; strong quality when trained well.

### 12. LIMITATIONS

Hard to train deep without warm-up; gradient path passes norms.

### 13. TRADE-OFFS

Possibly higher final quality versus stability ([8.12 Pre-LN](08.12-pre-ln.md)).

### 14. COMMON MISTAKES

Forgetting that Post-LN needs warm-up; building a final norm that is not in the original; using Pre-LN weights in a Post-LN graph.

### 15. PERFORMANCE / COST CONSIDERATIONS

Same FLOPs as Pre-LN; failed runs cost more.

### 16. SECURITY CONSIDERATIONS

Same checkpoint-mismatch risk as [8.12 Pre-LN](08.12-pre-ln.md).

### 17. INTERVIEW EXPLANATION

*"Post-LN normalises after the residual add. It is the original Transformer layout; it keeps scale controlled, but deep stacks need warm-up because gradients pass through every norm."*

### 18. RAPID-FIRE ANSWER
