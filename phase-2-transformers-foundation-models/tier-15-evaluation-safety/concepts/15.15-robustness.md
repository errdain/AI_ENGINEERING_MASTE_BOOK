### 1. WHAT IS IT?

Robustness is how little model behaviour degrades when inputs change in ways that should not matter (typos, paraphrase, formatting, noise) or when conditions vary (prompt template, seed).

### 2. WHY DOES IT EXIST?

Users do not type like benchmarks. A model that is brittle to harmless perturbations is unreliable in production.

### 3. DETAILED EXPLANATION

Perturbation families: typos/casing/whitespace, paraphrase, reordering of options, prompt-template changes, irrelevant context, language or dialect variation, noisy OCR/ASR input.

Metrics: accuracy under perturbation, **drop** = clean - perturbed, **consistency** = fraction of items whose answer is unchanged, worst-case over a perturbation set, and variance across prompt templates and seeds.

Robustness is related to but distinct from adversarial testing (""[15.16 Adversarial testing](15.16-adversarial-testing.md)""; worst-case, intentional) and distribution shift (""[15.17 Distribution-shift evaluation](15.17-distribution-shift-evaluation.md)""; systematic input change). Figure 6 shows accuracy moving toward chance as more inputs are perturbed.

### 4. HOW DOES IT WORK?

Define label-preserving perturbations -> apply to each test item (seeded) -> re-run -> compare per-item and aggregate -> report drop and consistency with CIs.

### 5. SIMPLE EXAMPLE

A driver who is fine in daylight but loses control in light rain is not robust.

### 6. TECHNICAL EXAMPLE

Multiple-choice benchmark: shuffling option order changes accuracy by several points for some models; report the mean and range over several orderings.

### 7. CODE

```python
# run inside lab/ -- accuracy of a toy model as more inputs are perturbed
from toy import noisy_accuracy
for noise in (0.0, 0.25, 0.5, 1.0):
    print(f"perturbed {noise:4.0%}: accuracy {noisy_accuracy(0.9, noise, rng_seed=1):.3f}")
```

### 8. INPUT → PROCESS → OUTPUT

```
clean items -> perturb (label-preserving) -> model -> compare answers -> drop + consistency
```

### 9. ENTERPRISE USE CASE

Customer-facing assistants test against noisy real-world inputs (typos, mixed languages) before launch.

### 10. AI ENGINEERING CONNECTION

Prompt sensitivity makes robustness part of every LLM evaluation protocol ([15.29 Evaluation reproducibility](15.29-evaluation-reproducibility.md)).

### 11. ADVANTAGES

- Reveals brittleness cheaply.

### 12. LIMITATIONS

- Perturbations must preserve labels; coverage is endless.

### 13. TRADE-OFFS

- Breadth of perturbations vs cost.

### 14. COMMON MISTAKES

- Perturbations that change the correct answer.
- One template only.

### 15. PERFORMANCE / COST CONSIDERATIONS

Multiplies evaluation runs by number of perturbations; sample.

### 16. SECURITY CONSIDERATIONS

Overlaps with attack surface; see adversarial testing.

### 17. INTERVIEW EXPLANATION

Robustness is stability under harmless input changes. I apply seeded label-preserving perturbations, report accuracy drop, answer consistency and variance across prompt templates, and treat adversarial and shift evaluation as separate tests.

### 18. RAPID-FIRE ANSWER
