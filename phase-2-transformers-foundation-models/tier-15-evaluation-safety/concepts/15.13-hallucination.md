### 1. WHAT IS IT?

Hallucination is model output that is unsupported by the input context or by reality, presented as if it were reliable.

### 2. WHY DOES IT EXIST?

It is the main trust failure of generative models; it needs a precise taxonomy and measurable rates to be managed.

### 3. DETAILED EXPLANATION

Taxonomy (commonly used; wording varies, REVIEW_REQUIRED):
- **Intrinsic**: contradicts the given source (summary says the opposite of the document).
- **Extrinsic**: adds claims not in the source (may or may not be true).
- **Factual**: contradicts the world.
- **Fabricated references**: invented citations, APIs, quotes.

Causes (hypotheses, not a settled list): training objective rewards plausible continuation, gaps in long-tail knowledge, ambiguous prompts, stale knowledge, decoding randomness, over-compliance after post-training.

Measure: hallucination rate = unsupported claims / claims (or responses with >=1 unsupported claim / responses). Report both, with intervals, per slice and per abstention behaviour: a model that refuses more hallucinates less but helps less (""[15.35 Safety vs capability trade-offs](15.35-safety-vs-capability-trade-offs.md)""). Mitigations belong to later tiers (retrieval, citations, abstention, guardrails); this tier measures.

### 4. HOW DOES IT WORK?

Define 'unsupported' against a reference (context for intrinsic/extrinsic, trusted sources for factual); label a sample with humans; calibrate automatic detectors against it; track rate over time.

### 5. SIMPLE EXAMPLE

A student confidently describing a book they never read.

### 6. TECHNICAL EXAMPLE

Summarisation: 200 summaries, claims labelled supported/unsupported by two annotators (kappa checked, [15.27 Human evaluation](15.27-human-evaluation.md)); response-level hallucination rate 12% [9%, 17%] with a bootstrap CI.

### 7. CODE

```python
# run inside lab/ -- response-level rate with a bootstrap CI from labelled responses
import numpy as np
from metrics import bootstrap_ci
has_unsupported = np.array([1] * 12 + [0] * 88, dtype=float)    # 12 of 100 responses contain an unsupported claim
lo, hi = bootstrap_ci(has_unsupported, seed=0)
print(f"hallucination rate {has_unsupported.mean():.2f}  95% CI [{lo:.2f}, {hi:.2f}]")
```

### 8. INPUT → PROCESS → OUTPUT

```
response + reference -> claims labelled supported / unsupported -> response- and claim-level rates -> by slice
```

### 9. ENTERPRISE USE CASE

Regulated domains set maximum tolerated rates and require human review of flagged samples.

### 10. AI ENGINEERING CONNECTION

Hallucination drives RAG, citation requirements and refusal/abstention policy.

### 11. ADVANTAGES

- Named failure modes make mitigation targeted.

### 12. LIMITATIONS

- Labels are subjective at the margin; rates depend on prompt mix.

### 13. TRADE-OFFS

- Lower hallucination via abstention costs helpfulness.

### 14. COMMON MISTAKES

- One global rate; ignoring severity; judging only fluent-looking answers.

### 15. PERFORMANCE / COST CONSIDERATIONS

Human labelling dominates cost.

### 16. SECURITY CONSIDERATIONS

Hallucinated packages or links can be exploited by attackers who register the invented names (REVIEW_REQUIRED for documented cases).

### 17. INTERVIEW EXPLANATION

Hallucination is unsupported output presented as reliable: intrinsic (contradicts source), extrinsic (adds unsupported content) or factual. I measure claim- and response-level rates against a defined reference, with intervals and slices, and track them against abstention rate.

### 18. RAPID-FIRE ANSWER

Unsupported-but-confident; measure by claims, with CIs, vs abstention.
