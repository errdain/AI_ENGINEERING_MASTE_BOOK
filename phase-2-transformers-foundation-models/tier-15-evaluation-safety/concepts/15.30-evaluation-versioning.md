### 1. WHAT IS IT?

Evaluation versioning assigns identities to datasets, scorers, harness code and results so that any number can be traced to exactly what produced it and compared only with like.

### 2. WHY DOES IT EXIST?

Datasets and scorers change; without versions, a score change cannot be attributed to the model.

### 3. DETAILED EXPLANATION

What to version:
- **Dataset**: content hash of all examples (order-independent). In the lab, `Dataset.version` changes if any id, input, reference or tag changes.
- **Scorer and harness**: a version string (`HARNESS_VERSION`) stored in each result.
- **Result**: JSON with model id, dataset name+version, scorer, seed, per-example scores, aggregates and a deterministic `run_id`; filename `<model>__<run_id>.json` under a folder per dataset.
- **Comparison rule**: `compare` raises an error if dataset versions differ.
- **Changelog**: reason for each dataset change; keep old versions for trend analysis.

No wall-clock timestamps are embedded in the run id (they would break reproducibility); store dates in a separate registry or in the file's metadata if needed. For large datasets use a registry (for example data-version-control tooling; REVIEW_REQUIRED) instead of hashing in-process.

### 4. HOW DOES IT WORK?

Hash content -> store with results -> refuse mismatched comparisons -> keep immutable history.

### 5. SIMPLE EXAMPLE

Library editions: 'the 2024 edition, page 10' is unambiguous, 'the book' is not.

### 6. TECHNICAL EXAMPLE

Two result files have identical model ids but different dataset versions: tooling flags them as not comparable instead of showing a misleading delta.

### 7. CODE

```python
# run inside lab/
import tempfile, json
from evalharness import run_eval, EvalResult, compare
from demo import make_ds, model_v1, model_v2
ds = make_ds(); a = run_eval(model_v1, "v1", ds)
with tempfile.TemporaryDirectory() as d:
    p = a.save(d); print(p.name)                                  # v1__<run_id>.json
    print(EvalResult.from_json(p.read_text()).run_id == a.run_id)  # round trip
ds.examples[0].reference = "changed"
try: compare(a, run_eval(model_v2, "v2", ds))
except ValueError as e: print("blocked:", e)
```

Lab code: [`lab/evalharness.py`](../lab/evalharness.py), [`lab/test_tier15.py`](../lab/test_tier15.py).

### 8. INPUT → PROCESS → OUTPUT

```
dataset -> content hash; result -> JSON with versions -> registry -> compare only equal dataset versions
```

### 9. ENTERPRISE USE CASE

A results registry (files, database or experiment tracker) stores every run immutably; release records link to run ids.

### 10. AI ENGINEERING CONNECTION

Same principle as model and prompt versioning in later tiers.

### 11. ADVANTAGES

- Traceable, comparable, auditable.

### 12. LIMITATIONS

- Needs discipline; hashes do not capture semantic equivalence.

### 13. TRADE-OFFS

- Strict versioning (many versions) vs convenience.

### 14. COMMON MISTAKES

- Editing datasets in place.
- Comparing across versions.
- No harness version.

### 15. PERFORMANCE / COST CONSIDERATIONS

Hashing is cheap; storage grows with per-example scores.

### 16. SECURITY CONSIDERATIONS

Result files expose test data and model outputs; control access.

### 17. INTERVIEW EXPLANATION

Evaluation versioning gives datasets a content hash, results a deterministic run id with full configuration, and enforces comparison only across identical dataset versions, so every number is traceable.

### 18. RAPID-FIRE ANSWER

Hash the data, record the config, compare like with like.
