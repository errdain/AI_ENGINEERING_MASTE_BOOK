### 1. WHAT IS IT?

Evaluation reproducibility means that re-running an evaluation with the same model, data, code and configuration produces the same (or statistically indistinguishable) result.

### 2. WHY DOES IT EXIST?

If results cannot be reproduced, differences between runs cannot be attributed to model changes, and decisions rest on noise.

### 3. DETAILED EXPLANATION

Sources of non-reproducibility and fixes:
- **Random seeds**: seed Python, NumPy and framework RNGs; in the lab each example gets a seed derived from (run seed, example id), so results do not depend on iteration order.
- **Sampling**: use temperature 0 or fixed seeds, and when the model stays stochastic, run several seeds and report mean and spread.
- **Data drift**: pin dataset versions by content hash ([15.30 Evaluation versioning](15.30-evaluation-versioning.md)).
- **Prompt/template and decoding settings**: store them with the result.
- **Library/hardware non-determinism**: GPU kernels, batch composition and library versions can change outputs; record versions (REVIEW_REQUIRED for specifics).
- **Hosted models change under you**: pin model version identifiers where available; record dates.
- **Judges and humans**: judge model version, rubric and rater pool are part of the configuration.

Reproducibility is assessed by re-running; the lab test `test_reproducible_same_seed_same_run_id` shows identical JSON for identical inputs.

### 4. HOW DOES IT WORK?

Fix seeds -> record all config (model id, dataset version, scorer, harness version, decoding) in the result -> derive a run id from them -> re-run to verify -> compare runs only if configs match.

### 5. SIMPLE EXAMPLE

A recipe that lists exact ingredients, oven temperature and timings so another cook gets the same cake.

### 6. TECHNICAL EXAMPLE

Two runs with different seeds give 0.71 and 0.74 on a stochastic model; the team reports mean 0.725 and range, and sets the gate on the lower bound.

### 7. CODE

```python
# run inside lab/
from evalharness import run_eval
from demo import make_ds, model_v1
a = run_eval(model_v1, "v1", make_ds(), seed=3)
b = run_eval(model_v1, "v1", make_ds(), seed=3)
print(a.run_id == b.run_id, a.to_json() == b.to_json())      # True True
c = run_eval(model_v1, "v1", make_ds(), seed=4)
print("different seed -> id may differ:", a.run_id != c.run_id)
```

### 9. ENTERPRISE USE CASE

CI re-runs a canary evaluation nightly to detect environment drift; any unexplained change opens an investigation.

### 10. AI ENGINEERING CONNECTION

Prompt sensitivity and sampling make LLM evaluation especially fragile; hosted models may change silently.

### 11. ADVANTAGES

- Trustworthy comparisons; audit trail.

### 12. LIMITATIONS

- Bitwise determinism may be unattainable on some hardware; hosted models may be non-deterministic.

### 13. TRADE-OFFS

- Determinism (temperature 0) vs realism (sampling at deployment settings).

### 14. COMMON MISTAKES

- Not storing config.
- Comparing runs across dataset versions.
- Single run on stochastic models.

### 15. PERFORMANCE / COST CONSIDERATIONS

Multiple seeds multiply cost; use fewer seeds with larger n or paired analysis.

### 16. SECURITY CONSIDERATIONS

Stored configs may include prompts and data references: apply access control.

### 17. INTERVIEW EXPLANATION

Reproducibility means the same configuration yields the same result. I seed everything per example, pin dataset and model versions, store the full configuration with a derived run id, run multiple seeds for stochastic models and refuse to compare runs with different configurations.

### 18. RAPID-FIRE ANSWER

Seed, pin, record, re-run.
