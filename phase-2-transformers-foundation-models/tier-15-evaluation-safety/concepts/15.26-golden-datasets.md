### 1. WHAT IS IT?

A golden dataset is a curated, high-quality, representative set of inputs with trusted expected outputs (or rubrics) that serves as the reference for quality tracking and release decisions.

### 2. WHY DOES IT EXIST?

You need one stable, trusted yardstick to compare versions over time; ad-hoc examples cannot give a reliable trend.

### 3. DETAILED EXPLANATION

Build:
1. Sample inputs from real traffic (stratified by task, difficulty, language, risk).
2. Write or verify expected outputs with domain experts; use two annotators on a subset and report kappa ([15.27 Human evaluation](15.27-human-evaluation.md)).
3. Tag slices; freeze and version with a content hash ([15.30 Evaluation versioning](15.30-evaluation-versioning.md)); keep a private portion.
4. Size for power: choose n so the interval resolves the change you care about ([15.6 Benchmark design](15.06-benchmark-design.md)).
5. Refresh on a schedule, preserving a stable core for trend lines; log every change to the set.

Guard against over-fitting: if developers tune against the golden set it stops being a held-out measurement; keep a second untouched split. Golden != regression: golden estimates overall quality; regression guards specific past failures ([15.25 Regression datasets](15.25-regression-datasets.md)).

### 4. HOW DOES IT WORK?

Sample -> annotate -> adjudicate -> tag -> freeze -> version -> run on every candidate -> store results ([15.30 Evaluation versioning](15.30-evaluation-versioning.md)).

### 5. SIMPLE EXAMPLE

The reference standard weights in a lab: you compare every new scale against the same trusted set.

### 6. TECHNICAL EXAMPLE

400 support tickets stratified over six intents; two experts agreed with kappa 0.82; accuracy per intent tracked for each model version.

### 7. CODE

```python
# run inside lab/
from evalharness import Dataset, Example
core = [Example(f"g{i}", f"question {i}", f"answer {i}", ["intent_a" if i % 2 else "intent_b"]) for i in range(20)]
golden = Dataset("support-golden", "golden", core)
print(golden.version, len(golden.slice("intent_a").examples))
golden.examples[0].reference = "edited"      # any edit changes the version -> old results are not comparable
print(golden.version)
```

### 9. ENTERPRISE USE CASE

A named owner maintains the golden set, approves changes and signs the release gate that depends on it.

### 10. AI ENGINEERING CONNECTION

Foundation for model selection, prompt changes and Tier 30 application evaluation.

### 11. ADVANTAGES

- Stable trend line; trusted reference.

### 12. LIMITATIONS

- Expensive; ages; can be overfitted.

### 13. TRADE-OFFS

- Stability (trend) vs freshness (representativeness).

### 14. COMMON MISTAKES

- Tuning on the golden set.
- Silent edits without versioning.
- Unverified expected outputs.

### 15. PERFORMANCE / COST CONSIDERATIONS

Annotation cost is the main cost; reuse across many runs amortises it.

### 16. SECURITY CONSIDERATIONS

Contains realistic data; restrict access and keep a private portion unseen by developers.

### 17. INTERVIEW EXPLANATION

A golden dataset is a stratified, expert-verified, versioned reference set used to track quality and gate releases. I measure annotator agreement, tag slices, freeze and hash it, keep an untouched held-out part and refresh with a stable core.

### 18. RAPID-FIRE ANSWER

Stratified, verified, frozen, versioned, protected.
