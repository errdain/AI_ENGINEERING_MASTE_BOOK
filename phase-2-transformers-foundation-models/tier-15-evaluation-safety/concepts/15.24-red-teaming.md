### 1. WHAT IS IT?

Red teaming is structured, adversarial probing of a model or system by people (and tools) trying to elicit harmful or policy-violating behaviour, to find failures before attackers or users do.

### 2. WHY DOES IT EXIST?

Standard test sets only cover anticipated failures. Creative adversaries find new ones; red teaming discovers them and measures attack success.

### 3. DETAILED EXPLANATION

Process: define scope and threat model -> assemble diverse testers (security, domain experts, affected communities) -> guidelines and safe-handling rules -> attack campaign (manual plus automated) -> record attempts, successes, severity -> triage, fix, retest -> convert successes into regression cases ([15.25 Regression datasets](15.25-regression-datasets.md)).

Metrics: attack success rate by technique and category (Figure 9 funnel: attempts -> not refused -> harmful -> human-verified), time-to-first-success, severity distribution, novel-vs-known attack share. ASR must be quoted with budget and tester pool.

Limits: coverage depends on tester diversity; results are a lower bound on risk; models change, so repeat. Red-team findings must feed fixes and regression tests or the effort is wasted.

### 4. HOW DOES IT WORK?

Scope -> recruit -> attack -> log -> verify -> severity -> fix -> retest -> add to regression set.

### 5. SIMPLE EXAMPLE

Hiring ethical hackers to break into your building before burglars do.

### 6. TECHNICAL EXAMPLE

1,000 attack prompts: 220 not refused, 60 flagged harmful by the classifier, 41 verified by humans -> ASR 4.1% (illustrative funnel in Figure 9).

### 7. CODE

```python
# run inside lab/ -- funnel bookkeeping and conversion to regression cases
funnel = {"attempts": 1000, "not_refused": 220, "flagged_harmful": 60, "verified_harmful": 41}
print("ASR (verified):", funnel["verified_harmful"] / funnel["attempts"])
from evalharness import Dataset
reg = Dataset("redteam-regress", "regression", [])

print(len(reg.examples), reg.version)
```

### 9. ENTERPRISE USE CASE

Internal and external red teams run before major releases; findings go to a tracked backlog with owners and deadlines.

### 11. ADVANTAGES

- Finds unanticipated failures.

### 12. LIMITATIONS

- Not exhaustive; tester-dependent; expensive.

### 13. TRADE-OFFS

- Human creativity vs automated scale.

### 14. COMMON MISTAKES

- One-off exercise.
- No regression conversion.
- No safe-handling rules.

### 15. PERFORMANCE / COST CONSIDERATIONS

Human time; automate the repetitive search.

### 16. SECURITY CONSIDERATIONS

Attack logs are sensitive; restrict access; follow responsible disclosure for third-party issues.

### 17. INTERVIEW EXPLANATION

Red teaming is adversarial probing by diverse testers to find unanticipated failures. I scope with a threat model, log attempts and verified successes with severity, quote ASR with budget and tester pool, fix and retest, and convert every success into a regression case.

### 18. RAPID-FIRE ANSWER

Diverse testers, verified ASR with budget, fix, retest, regress.
