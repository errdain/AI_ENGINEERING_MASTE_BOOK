### 1. WHAT IS IT?

Distribution-shift evaluation measures performance when test data differs systematically from training or validation data (new topics, domains, time periods, languages, user populations).

### 2. WHY DOES IT EXIST?

Models are trained on yesterday's data and deployed on tomorrow's. Performance and calibration measured in-distribution may not transfer.

### 3. DETAILED EXPLANATION

Types: covariate shift (inputs change), label/prior shift (class mix changes), concept shift (the right answer for the same input changes), temporal drift, and domain or language shift.

Evaluation: build held-out splits that differ along the axis you worry about (by time, source, domain, language), compare in-distribution vs out-of-distribution scores, and also compare **calibration** (ECE) since confidence usually degrades first (""[15.11 Calibration](15.11-calibration.md)""). In production, monitor input statistics and proxies (embedding drift, refusal/escalation rate) because labels arrive late (Tier 30). Figure 6 (right): a fixed rule's accuracy falls smoothly as the data moves.

### 4. HOW DOES IT WORK?

Choose a shift axis -> split data accordingly -> evaluate in-dist and OOD -> report gap, per-slice and calibration -> decide on data refresh or guardrails.

### 5. SIMPLE EXAMPLE

A weather model trained on one country's climate evaluated in another.

### 6. TECHNICAL EXAMPLE

Support bot evaluated on last quarter's tickets scores 90%; on tickets about a newly launched product it scores 70%: the OOD gap of 20 points sets priorities.

### 7. CODE

```python
# run inside lab/ -- accuracy of a fixed rule as the data shifts (toy)
import numpy as np
rng = np.random.default_rng(0)
for shift in (0.0, 1.0, 2.0):
    x = rng.normal(0, 1, (5000, 2)) + np.array([shift, 0])
    y = (x[:, 0] - shift + x[:, 1] > 0)           # true rule moves with the data
    pred = (x[:, 0] + x[:, 1] > 0)                # fixed rule learned at shift 0
    print(f"shift {shift}: accuracy {(pred == y).mean():.3f}")
```

### 8. INPUT → PROCESS → OUTPUT

```
training data vs deployment data -> split along shift axis -> compare scores + calibration -> gap
```

### 9. ENTERPRISE USE CASE

Teams re-evaluate monthly on fresh traffic samples and trigger data refresh when the OOD gap exceeds a threshold.

### 10. AI ENGINEERING CONNECTION

LLM knowledge cutoffs and changing user behaviour make shift permanent; evaluation sets must be refreshed.

### 11. ADVANTAGES

- Predicts deployment performance better than i.i.d. splits.

### 12. LIMITATIONS

- Unknown shifts cannot be tested; OOD labels cost money.

### 13. TRADE-OFFS

- Refresh frequency vs labelling cost.

### 14. COMMON MISTAKES

- Random train/test splits for temporal data.
- Checking accuracy but not calibration.

### 15. PERFORMANCE / COST CONSIDERATIONS

Needs fresh labelled data; use targeted sampling.

### 16. SECURITY CONSIDERATIONS

Shift can be adversarially induced (poisoning); monitor inputs.

### 17. INTERVIEW EXPLANATION

Distribution-shift evaluation compares performance on data that differs from training along a chosen axis (time, domain, language). I split by that axis, report the gap and calibration change, and monitor drift in production because labels arrive late.

### 18. RAPID-FIRE ANSWER

Split by the axis that will change; compare accuracy and calibration.
