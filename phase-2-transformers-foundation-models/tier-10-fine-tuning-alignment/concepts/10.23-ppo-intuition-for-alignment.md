### 1. WHAT IS IT?

**PPO (Proximal Policy Optimization)** is a policy-gradient algorithm that takes many small, safe steps by clipping the change in action probabilities.

### 2. WHY DOES IT EXIST?

Plain policy gradients can take destructively large steps; PPO bounds each update.

### 3. DETAILED EXPLANATION

It raises the probability of sampled actions with positive **advantage** (better than expected) and lowers those with negative advantage, but **clips** the ratio `pi_new / pi_old` so one batch can't move the policy far. In RLHF an "action" is a token (or response), the reward arrives at the end, a **value model** estimates expected reward to reduce variance, and the KL penalty adds a second brake. Remember: *clipping = trust region, advantage = better-than-average signal, KL = leash to the reference.*

![PPO clip](../figures/12_ppo_clip_and_kl.png)

*Figure (analytic): left and middle, the clipped objective `min(r*A, clip(r, 1-eps, 1+eps)*A)` for positive and negative advantage; once the ratio leaves the shaded trust region in the improving direction the gradient vanishes.*

### 4. HOW DOES IT WORK?

1. Sample with `pi_old`. 2. Compute advantages (value baseline). 3. Maximise clipped surrogate for a few epochs. 4. Update `pi_old`.

### 5. SIMPLE EXAMPLE

Adjust a recipe a pinch at a time, never drastically after one tasting.

### 6. TECHNICAL EXAMPLE

Epsilon = 0.2 is a common value in the PPO paper (`REVIEW_REQUIRED`); the figure uses it.

### 7. CODE

```python
def ppo_clip_objective(ratio, adv, eps=0.2):
    return torch.minimum(ratio * adv, torch.clamp(ratio, 1 - eps, 1 + eps) * adv).mean()
```
(conceptual; not in the lab)

### 8. INPUT → PROCESS → OUTPUT

```
samples --> advantage --> ratio pi_new/pi_old --> clipped surrogate --> small safe update
```

### 9. ENTERPRISE USE CASE

Internal to RLHF stacks; application teams rarely implement it.

### 10. AI ENGINEERING CONNECTION

Core algorithm in classic RLHF; later RL variants (e.g. group-relative methods) modify it (`REVIEW_REQUIRED`).

### 11. ADVANTAGES

Stable relative to vanilla policy gradient.

### 12. LIMITATIONS

Many hyper-parameters; needs a value model.

### 13. TRADE-OFFS

Stability versus sample efficiency.

### 14. COMMON MISTAKES

Wrong sign of advantage; no value baseline; epsilon too large.

### 15. PERFORMANCE / COST CONSIDERATIONS

Needs online generation and a value network.

### 16. SECURITY CONSIDERATIONS

Reward hacking persists; PPO doesn't make a bad reward safe.

### 17. INTERVIEW EXPLANATION

PPO nudges the policy to favour better-than-expected samples, but clips the probability ratio so it can't move far in one batch. In RLHF a value model supplies the baseline and a KL penalty keeps the policy near the reference. I only need the intuition: clip is the trust region, advantage is the signal, KL is the leash.

### 18. RAPID-FIRE ANSWER

PPO: clip, advantage, KL leash.
