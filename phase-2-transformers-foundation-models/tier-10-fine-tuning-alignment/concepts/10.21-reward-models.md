### 1. WHAT IS IT?

A **reward model (RM)** maps `(prompt, answer)` to a scalar score of quality, trained on preference pairs.

### 2. WHY DOES IT EXIST?

RL needs a numeric reward; humans give comparisons. The RM turns comparisons into a differentiable score.

### 3. DETAILED EXPLANATION

Trained with the **Bradley-Terry** model: `P(chosen > rejected) = sigmoid(r_c - r_r)`, loss `-log sigmoid(r_c - r_r)`. Only reward *differences* matter (adding a constant changes nothing). Usually an LM with a scalar head, initialised from the SFT model. *Tests:* loss = log 2 at equal rewards, decreases as the gap grows, increases when reversed.

[Explore Bradley-Terry fitting](../interactive/dpo_bt.html) (part A fits four items from six pairs, one deliberately contradictory: the loss stalls above zero because noisy labels cap confidence).

**Risk: reward hacking / over-optimisation.** The policy finds outputs the RM scores high but humans don't (length, flattery). RMs are only reliable near their training distribution.

### 4. HOW DOES IT WORK?

1. Score both answers. 2. Loss = `-log sigmoid(r_c - r_r)`. 3. Backprop into the RM. 4. Use the RM as the RL reward ([10.22](10.22-rlhf.md)) or for best-of-n.

### 5. SIMPLE EXAMPLE

Referees trained on past match comparisons to score new plays.

### 6. TECHNICAL EXAMPLE

Lab test `test_bradley_terry`: loss at equal rewards = log 2 = 0.693.

### 7. CODE

```python
# ../lab/alignment.py
def bradley_terry_loss(r_chosen, r_rejected):
    return -F.logsigmoid(r_chosen - r_rejected).mean()
```
Stretch exercise: add a scalar head to `TinyLM`, train on (correct, sloppy) pairs, then best-of-8.

### 8. INPUT → PROCESS → OUTPUT

```
(x, y_c), (x, y_r) --> RM --> r_c, r_r --> -log sigmoid(r_c - r_r) --> update RM
```

### 9. ENTERPRISE USE CASE

Used to rank candidate responses (best-of-n) and as RL reward in assistant training.

### 10. AI ENGINEERING CONNECTION

Also the idea behind LLM judges and verifiers (Tier 15/30).

### 11. ADVANTAGES

Reusable scalar scorer; enables best-of-n.

### 12. LIMITATIONS

Imperfect proxy; exploited by optimisation; costs a model.

### 13. TRADE-OFFS

RM + RL versus direct methods ([10.25](10.25-direct-preference-optimization-dpo.md)).

### 14. COMMON MISTAKES

Treating RM scores as absolute; no held-out RM evaluation; over-optimising against one RM.

### 15. PERFORMANCE / COST CONSIDERATIONS

One more large model to train and hold in memory during RLHF.

### 16. SECURITY CONSIDERATIONS

A leaked RM reveals the optimisation target; RMs can encode bias.

### 17. INTERVIEW EXPLANATION

A reward model scores an answer with a scalar, trained on preference pairs with the Bradley-Terry loss: minus log sigmoid of the chosen minus rejected reward. Only differences matter. It's a proxy, so over-optimising the policy against it leads to reward hacking.

### 18. RAPID-FIRE ANSWER

RM: a learned referee, hackable.
