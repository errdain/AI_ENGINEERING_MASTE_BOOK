### 1. WHAT IS IT?

**Parameter-efficient fine-tuning (PEFT)** freezes the pretrained weights and trains only a small number of new or selected parameters.

### 2. WHY DOES IT EXIST?

Full fine-tuning needs 16 B/param, a full copy per task and risks forgetting. PEFT cuts gradient/optimizer memory and makes per-task artifacts tiny (MBs).

### 3. DETAILED EXPLANATION

Families: **additive** (bottleneck adapters, [10.16](10.16-adapters.md)), **reparameterised** (LoRA, [10.11](10.11-lora.md)), **soft prompts** (prompt/prefix tuning, [10.17](10.17-prompt-tuning.md)) and **selective** (train only biases or norms, BitFit-style). Benefits: less memory for grads and optimizer state, many adapters on one base. Costs: potentially lower ceiling, and *new hyper-parameters* (rank, targets, learning rate).

![Full vs LoRA vs QLoRA](../figures/05_full_vs_lora_vs_qlora.png)

*Figure (measured, one seed): left = trainable parameters (log), middle = held-out accuracy, right = plain-text loss after SFT (dotted = before). Adapters train 4-40x fewer parameters but needed more steps here and did not forget less. The ordering is not a claim about large models.*

### 4. HOW DOES IT WORK?

Freeze base -> insert or select a small trainable set -> train only it -> store only it -> at serve time either swap it in or merge it ([10.30](10.30-adapter-merging.md)).

### 5. SIMPLE EXAMPLE

Keeping the textbook and adding sticky notes instead of rewriting the book.

### 6. TECHNICAL EXAMPLE

Lab trainable counts: q,v LoRA r=4 = 1,536 (2.3 % of 64,512); all six matrices r=8 = 13,824 (17.6 %, large only because toy d=48). Numbers here come from the seeded lab run (`../lab/run_lab.py`, 64,512-parameter char model, one seed, CPU); they teach mechanics, not large-model behaviour.

### 7. CODE

```python
# ../lab/lora.py: freeze everything, then add trainable low-rank pieces
layers = apply_lora(model, targets=("q_proj", "v_proj"), r=4, alpha=8.0)
trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
```

### 8. INPUT → PROCESS → OUTPUT

```
pretrained W (frozen) + small trainable delta --> task artifact (MBs) --> serve: swap / merge
```

### 9. ENTERPRISE USE CASE

One 7B base plus dozens of per-tenant or per-task adapters instead of dozens of model copies.

### 10. AI ENGINEERING CONNECTION

PEFT is the default way application teams adapt open-weight models and the basis of QLoRA ([10.15](10.15-qlora.md)).

### 11. ADVANTAGES

Memory, storage and multi-task serving advantages; often near full-FT quality (published comparisons mix; `REVIEW_REQUIRED`).

### 12. LIMITATIONS

Lower ceiling for large domain shifts or new knowledge; extra hyper-parameters; in the toy it did not reduce forgetting.

### 13. TRADE-OFFS

Capacity versus cost; additive modules add latency, LoRA can be merged for free.

### 14. COMMON MISTAKES

Forgetting `requires_grad=False` on the base; comparing at identical learning rates; claiming PEFT always forgets less.

### 15. PERFORMANCE / COST CONSIDERATIONS

Saves optimizer/gradient memory (not forward activations); training steps per second are not necessarily faster.

### 16. SECURITY CONSIDERATIONS

Adapters are small files that can carry leaked training data; treat them as sensitive artifacts and bind them to a base hash.

### 17. INTERVIEW EXPLANATION

PEFT freezes the pretrained weights and trains a small set of extra parameters, such as LoRA matrices. It slashes optimizer memory and makes task artifacts a few megabytes, so one base serves many tasks. The cost is possibly lower capacity and extra hyper-parameters.

### 18. RAPID-FIRE ANSWER

PEFT = freeze the giant, train the sliver.
