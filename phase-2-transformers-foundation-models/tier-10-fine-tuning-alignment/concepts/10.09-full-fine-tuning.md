### 1. WHAT IS IT?

**Full fine-tuning** updates *every* parameter of the model on the new data.

### 2. WHY DOES IT EXIST?

It is the most expressive adaptation and the baseline against which PEFT is compared.

### 3. DETAILED EXPLANATION

**Memory per parameter** with Adam in mixed precision: fp16 weights 2 B + fp16 grads 2 B + fp32 master copy 4 B + Adam `m`,`v` 8 B = **16 B/param** (an assumption: frameworks differ; activations are extra), so a 7B model needs about 112 GB before activations.

![Memory comparison](../figures/03_lora_params_and_memory.png)

*Figure: the right panel is rough weights+grads+optimizer memory for full FT vs LoRA vs QLoRA (analytic).* [Explore memory](../interactive/qlora_memory.html).

Pros: best ceiling. Cons: memory, one full copy per task, the largest drift from the base and hence the highest forgetting risk ([10.28](10.28-catastrophic-forgetting.md)).

### 4. HOW DOES IT WORK?

Forward -> loss -> backward through all layers -> optimizer updates all weights. The learning rate is typically much smaller than in pretraining (lab: 1e-3 for a tiny model; real LLM values are far lower, `REVIEW_REQUIRED`).

### 5. SIMPLE EXAMPLE

Repainting a whole house versus painting one wall.

### 6. TECHNICAL EXAMPLE

Lab: full FT gets the best accuracy (**0.88**) but plain-text loss rises 0.59 to 2.96 ([methods figure](../figures/05_full_vs_lora_vs_qlora.png)). With 30 % replay the loss stays at 0.62 but accuracy at equal steps is 0.36 (fewer task batches in the mix). Numbers here come from the seeded lab run (`../lab/run_lab.py`, 64,512-parameter char model, one seed, CPU); they teach mechanics, not large-model behaviour.

### 7. CODE

```python
# ../lab/lora.py
from lora import finetune_memory_gb
print(finetune_memory_gb(7, "full_fp16_adam"))   # 112.0 GB, before activations
```
Training loop: [`../lab/run_lab.py`](../lab/run_lab.py).

### 8. INPUT → PROCESS → OUTPUT

```
batch --> all weights trainable --> grads for all --> Adam states for all --> new weights (full copy)
```

### 9. ENTERPRISE USE CASE

Used when the behaviour shift is large, data and GPUs are plentiful and one dedicated model per task is acceptable.

### 10. AI ENGINEERING CONNECTION

Baseline for every PEFT comparison; also how most vendor post-training is done.

### 11. ADVANTAGES

Highest capacity and quality ceiling.

### 12. LIMITATIONS

Memory, storage per task, forgetting.

### 13. TRADE-OFFS

Quality ceiling versus cost ([10.35](10.35-fine-tuning-cost-and-deployment-trade-offs.md)).

### 14. COMMON MISTAKES

Too high a learning rate; no replay; comparing against LoRA at the same learning rate (LoRA wants a higher one).

### 15. PERFORMANCE / COST CONSIDERATIONS

16 B/param plus activations; multi-GPU sharding is commonly needed for large models.

### 16. SECURITY CONSIDERATIONS

A full weight copy per tenant multiplies leakage and governance surface.

### 17. INTERVIEW EXPLANATION

Full fine-tuning updates every weight. It has the highest ceiling but needs about 16 bytes per parameter with Adam in mixed precision, a full model copy per task, and forgets the most. I use it when the shift is big and I have the data and GPUs; otherwise LoRA.

### 18. RAPID-FIRE ANSWER

Full FT = everything moves.
