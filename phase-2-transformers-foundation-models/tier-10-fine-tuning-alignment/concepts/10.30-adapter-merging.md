### 1. WHAT IS IT?

**Adapter merging** either folds one LoRA adapter into its base (`W' = W + (alpha/r) B A`) or combines several adapters into one model.

### 2. WHY DOES IT EXIST?

Folding removes serving overhead; combining aims to get several skills in one model.

### 3. DETAILED EXPLANATION

(a) **Fold one adapter into its base:** exact (tested). (b) **Combine several adapters:** add weighted deltas `delta W_1 + delta W_2`, or average the A and B factors (which is *not* the same as averaging the products). **Measured negative result:** in an exploratory run (not kept in the lab to stay under 60 s) naively summing two independently trained adapters (the `up` and `rv` word-reverse tasks) at weights 1.0 and 0.5 gave **0 % on both** tasks: independent adapters interfere when they overwrite the same behaviour in the same layers. Practical fixes: train jointly on a mix, give each task its own routing or prefix, or use sign-resolving schemes (TIES/DARE-style, `REVIEW_REQUIRED`).

[Explore merging](../interactive/forgetting_merge.html).

### 4. HOW DOES IT WORK?

Fold: `W += scale * B @ A`, unmerge: subtract. Combine: sum or average deltas with weights, then evaluate every task.

### 5. SIMPLE EXAMPLE

Gluing two sets of sticky notes onto the same page: if both rewrite the same line, they collide.

### 6. TECHNICAL EXAMPLE

Fold exactness is tested to 1e-5/1e-6 (`test_merged_weights_equal_adapter_output`, `test_merge_unmerge_roundtrip_and_plain_state`). The two-adapter sum result is exploratory and *not* in the committed lab; reproduce via Exercise 4.

### 8. INPUT → PROCESS → OUTPUT

```
base + adapter(s) --> weighted delta sum --> merged weights --> evaluate each task
```

### 9. ENTERPRISE USE CASE

Fold the winning adapter for zero-latency serving; keep adapters separate for multi-tenant hot-swap.

### 10. AI ENGINEERING CONNECTION

Serving engines either merge or batch multiple adapters ([Tier 11](../../tier-11-llm-inference-optimization/README.md)).

### 11. ADVANTAGES

Free inference after folding; composable skills (when it works).

### 12. LIMITATIONS

Combining independent adapters can interfere; merging into quantized weights is lossy.

### 13. TRADE-OFFS

Serving speed (merged) versus flexibility (separate adapters).

### 14. COMMON MISTAKES

Assuming merged = sum of skills; merging without re-evaluating every task; merging into a 4-bit base.

### 15. PERFORMANCE / COST CONSIDERATIONS

Merged model: no overhead; separate: small extra matmuls per request.

### 16. SECURITY CONSIDERATIONS

A merged model loses the ability to remove one tenant's adapter; keep per-tenant isolation unmerged when data separation matters.

### 17. INTERVIEW EXPLANATION

Merging an adapter folds BA into W exactly, so inference is free and reversible if I keep the adapter. Combining several adapters by adding deltas can fail when they edit the same behaviour; in my toy the sum scored zero on both tasks. I evaluate every task after merging.

### 18. RAPID-FIRE ANSWER

Folding is exact; combining is not.

### 19. INTERVIEW QUESTIONS
