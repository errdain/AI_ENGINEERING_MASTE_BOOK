### 1. WHAT IS IT?

**SFT data curation** is deduping, filtering, balancing and cleaning instruction data before training.

### 2. WHY DOES IT EXIST?

Quality beats quantity: noisy demonstrations are imitated.

### 3. DETAILED EXPLANATION

Dedupe (near-duplicates inflate memorisation and eval leakage), filter wrong/unsafe/low-effort answers, balance task types and lengths, strip PII and secrets, keep a held-out evaluation set **before** looking at the data, and version everything (Tier 38). Check the response distribution: if all answers start "Certainly!" the model learns that tic.

### 4. HOW DOES IT WORK?

Inspect -> dedupe (exact then near) -> rule/model filters -> balance -> split -> freeze and version.

### 5. SIMPLE EXAMPLE

Editing a textbook before students study it.

### 6. TECHNICAL EXAMPLE

Lab: SFT on a 50 % noisy set (half the answers are sloppy lower-case echoes) imitates the noise: greedy answers are correct only **42 %** of the time and 45 % sloppy ([10.25](10.25-direct-preference-optimization-dpo.md)). `sft_batch(noise=0.5)` in [`../lab/data.py`](../lab/data.py). Numbers here come from the seeded lab run (`../lab/run_lab.py`, 64,512-parameter char model, one seed, CPU); they teach mechanics, not large-model behaviour.

### 7. CODE

```python
rng = random.Random(0)
x, y, m = sft_batch(rng, train_combos, tasks=("up",), batch=32, noise=0.5)  # half the answers corrupted
```

### 8. INPUT → PROCESS → OUTPUT

```
raw data --> dedupe --> filter --> balance --> held-out split --> versioned SFT set
```

### 9. ENTERPRISE USE CASE

Teams run curation as a versioned pipeline with sampled human review.

### 10. AI ENGINEERING CONNECTION

Curated data determines the behaviour of agents and RAG answerers built on the model.

### 11. ADVANTAGES

Large gains per example; cheap relative to compute.

### 12. LIMITATIONS

Needs judgement; filters can remove useful diversity.

### 13. TRADE-OFFS

Aggressive filtering versus coverage.

### 14. COMMON MISTAKES

Curating after peeking at the eval set; filtering with the model being tuned without checks.

### 15. PERFORMANCE / COST CONSIDERATIONS

Cheap compared to training; human review is the cost.

### 16. SECURITY CONSIDERATIONS

Scrub PII and secrets; control contributors ([10.34](10.34-fine-tuning-data-security-considerations.md)).

### 17. INTERVIEW EXPLANATION

I treat curation as the main lever: dedupe, filter incorrect or unsafe answers, balance tasks and lengths, scrub PII, and hold out an evaluation set before touching the data. Noisy demonstrations get imitated; in my lab half-noisy SFT gave only 42 % correct answers.

### 18. RAPID-FIRE ANSWER

Curate: clean, balanced, held-out, versioned.

### 19. INTERVIEW QUESTIONS

**Basic:** Why dedupe SFT data?

**Intermediate:** How do you balance task types?

**Advanced:** How do you filter without biasing the data?

**Scenario:** A fine-tuned model repeats one phrase. Diagnose.

### 20. HANDS-ON EXERCISE

Count first-token frequencies in a small SFT set and spot tics.
