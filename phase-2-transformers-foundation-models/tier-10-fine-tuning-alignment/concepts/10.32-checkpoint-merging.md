### 1. WHAT IS IT?

**Checkpoint merging** averages checkpoints from one training run (the last K, or an exponential moving average).

### 2. WHY DOES IT EXIST?

To smooth noise in the final steps and reduce sensitivity to the stopping step.

### 3. DETAILED EXPLANATION

Same mechanics as model merging (`average_states`), but no cross-model assumptions: it is only valid for checkpoints in the same basin, i.e. late in training. It often generalises slightly better than the final checkpoint (`REVIEW_REQUIRED` as a general claim).

### 4. HOW DOES IT WORK?

Save checkpoints -> average parameters (or EMA) -> evaluate versus the last checkpoint.

### 5. SIMPLE EXAMPLE

Averaging several photos of the same scene to cancel noise.

### 6. TECHNICAL EXAMPLE

No lab result; `average_states` is tested for correctness only.

### 7. CODE

```python
# ../lab/merge.py
smoothed = average_states([ckpt_8, ckpt_9, ckpt_10])
```

### 8. INPUT → PROCESS → OUTPUT

```
ckpt_k-2, ckpt_k-1, ckpt_k --> average --> smoothed model
```

### 9. ENTERPRISE USE CASE

Training pipelines keep an EMA copy for evaluation and release.

### 10. AI ENGINEERING CONNECTION

Cheap robustness for fine-tuning runs and a bridge to model merging.

### 11. ADVANTAGES

Free; smoother.

### 12. LIMITATIONS

Invalid for early or divergent checkpoints; minor gains.

### 13. TRADE-OFFS

Extra storage versus smoothness.

### 14. COMMON MISTAKES

Averaging checkpoints from different runs or phases; not re-evaluating.

### 15. PERFORMANCE / COST CONSIDERATIONS

Storage for K checkpoints; averaging is negligible.

### 16. SECURITY CONSIDERATIONS

None specific.

### 17. INTERVIEW EXPLANATION

Checkpoint merging averages the last several checkpoints, or keeps an EMA, from one run. It smooths late-training noise and reduces sensitivity to when I stop, but only works for checkpoints in the same basin.

### 18. RAPID-FIRE ANSWER

Average the last few steps of the walk.
