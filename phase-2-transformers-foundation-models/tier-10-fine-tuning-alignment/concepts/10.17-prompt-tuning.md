### 1. WHAT IS IT?

**Prompt tuning** learns a few **soft prompt vectors** (continuous embeddings) prepended to the input while the whole model stays frozen; **prefix tuning** does this at every layer.

### 2. WHY DOES IT EXIST?

Extremely small per-task artifacts (thousands of parameters) and trivial multi-task batching.

### 3. DETAILED EXPLANATION

Typically weaker for small models and sensitive to initialisation and learning rate; reports show the gap closing as models grow (`REVIEW_REQUIRED`). Not the same as *prompt engineering* (Tier 17), which edits discrete text.

### 4. HOW DOES IT WORK?

Initialise k vectors of size d (random or from token embeddings), prepend to the input embeddings, backprop only into them.

### 5. SIMPLE EXAMPLE

Like finding the best invisible "magic words" in embedding space instead of in text.

### 6. TECHNICAL EXAMPLE

k=20 soft tokens at d=4096 is 81,920 parameters (arithmetic, not a benchmark). Not implemented in the lab.

### 7. CODE

```python
soft = nn.Parameter(torch.randn(20, d) * 0.02)          # trainable
def embed_with_prompt(tok_emb):                          # tok_emb: (T, d)
    return torch.cat([soft, tok_emb], 0)                  # frozen model sees k extra positions
```
(illustrative)

### 8. INPUT → PROCESS → OUTPUT

```
soft prompt (k x d, trainable) + token embeddings --> frozen model --> loss --> grad to soft prompt only
```

### 9. ENTERPRISE USE CASE

Useful when thousands of tiny per-user tuned prompts must share one frozen model.

### 10. AI ENGINEERING CONNECTION

Shows that behaviour can be steered in embedding space; related to context-length use.

### 11. ADVANTAGES

Tiny, multi-task friendly.

### 12. LIMITATIONS

Weaker on small models, uses context positions, hard to interpret.

### 13. TRADE-OFFS

Parameter count versus quality.

### 14. COMMON MISTAKES

Confusing with prompt engineering; high-variance LR.

### 15. PERFORMANCE / COST CONSIDERATIONS

Adds k tokens of context to every request.

### 16. SECURITY CONSIDERATIONS

Soft prompts are not human-readable, which complicates review.

### 17. INTERVIEW EXPLANATION

Prompt tuning trains a handful of continuous prompt vectors in front of the input with the model frozen. It's tiny and multi-task friendly, but weaker on smaller models; prefix tuning does it at every layer. It is different from hand-written prompt engineering.

### 18. RAPID-FIRE ANSWER

Soft prompts: tuned vectors, frozen model.
