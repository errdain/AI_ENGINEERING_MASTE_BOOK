### 1. WHAT IS IT?

**Post-training** is everything done to a pretrained model after pretraining: SFT, preference optimization (RLHF/DPO and relatives), reinforcement learning with verifiable rewards for reasoning, safety tuning, distillation and merging.

### 2. WHY DOES IT EXIST?

To turn a text predictor into an assistant that is helpful, formatted, safe and cheap to serve, without paying pretraining cost again. Compute is a small fraction of pretraining, but data quality and evaluation dominate success (exact fractions are not public for most models; `REVIEW_REQUIRED`).

### 3. DETAILED EXPLANATION

![Post-training pipeline](../figures/01_post_training_pipeline.png)

*Figure: blue = Tier 9 output; orange = first chat-capable model; purple/red/green = alignment stages; teal = the adapter trick, usable at any stage. Both RLHF and DPO consume the same preference pairs and differ in how.*

| Stage | Signal | Typical data (order of magnitude, `REVIEW_REQUIRED`) | Teaches | Main risk |
|---|---|---|---|---|
| SFT | exact answer tokens | 10^3-10^6 examples | format, style, skills | imitates errors; forgets |
| Reward model | pairwise labels | 10^4-10^6 pairs | a scalar "goodness" | reward hacking |
| RLHF (PPO) | reward + KL leash | prompts (online) | optimises the reward | instability, cost |
| DPO | pairwise labels, offline | 10^4-10^6 pairs | same preference, simpler | likelihood displacement |

### 4. HOW DOES IT WORK?

1. SFT on demonstrations. 2. Collect preferences. 3. Either train a reward model and run RL, or optimise the pairs directly (DPO). 4. Optionally RL with programmatic checkers (math, code). 5. Safety tuning, distillation, merging. 6. Evaluate on held-out tasks plus a regression suite ([10.33](10.33-fine-tuning-evaluation.md)). Any stage can use full fine-tuning or adapters ([10.10](10.10-parameter-efficient-fine-tuning-peft.md)).

### 5. SIMPLE EXAMPLE

Learning to cook (pretraining) versus working in a restaurant: following orders (SFT), diner feedback (preferences), house rules (safety).

### 6. TECHNICAL EXAMPLE

The lab runs a miniature of the pipeline: pretrain a tiny model, SFT it, then DPO on preference pairs (measured outcomes in [10.25](10.25-direct-preference-optimization-dpo.md)).

### 7. CODE

No standalone code; the stages map to lab files: SFT `../lab/data.py` + `../lab/tiny_lm.py`, adapters `../lab/lora.py`, preferences `../lab/alignment.py`, merging `../lab/merge.py`.

### 8. INPUT → PROCESS → OUTPUT

```
base --SFT--> instruct --preferences (RM+RL or DPO)--> aligned --(distill / merge / quantize)--> served model
```

### 9. ENTERPRISE USE CASE

Application teams usually start from a vendor instruct model and add task SFT plus optional DPO-style tuning with LoRA; labs run the full pipeline.

### 10. AI ENGINEERING CONNECTION

Defines where each later concept in this tier fits; connects to evaluation (Tier 15), serving ([Tier 11](../../tier-11-llm-inference-optimization/README.md)) and security (Tier 32).

### 11. ADVANTAGES

A shared mental model; each stage has a clear signal and failure mode.

### 12. LIMITATIONS

Real pipelines are mostly proprietary; stage boundaries blur (RL stages interleaved with SFT).

### 13. TRADE-OFFS

Simplicity (SFT + DPO) versus ceiling and online exploration (RL).

### 14. COMMON MISTAKES

Skipping SFT before preference tuning; evaluating only with loss; no regression suite.

### 15. PERFORMANCE / COST CONSIDERATIONS

Cheap relative to pretraining; labelling and evaluation are the real cost.

### 16. SECURITY CONSIDERATIONS

Every stage can inject or erode safety behaviour; data provenance matters throughout.

### 17. INTERVIEW EXPLANATION

Pretraining learns the distribution of text. Post-training reshapes it toward helpful, formatted, safe answers: SFT on demonstrations first, then preference optimization from comparisons. Adapters like LoRA make each stage cheap, and merging and distillation combine or compress the results.

### 18. RAPID-FIRE ANSWER

Post-training = SFT, then preferences, then safety/distill/merge.
