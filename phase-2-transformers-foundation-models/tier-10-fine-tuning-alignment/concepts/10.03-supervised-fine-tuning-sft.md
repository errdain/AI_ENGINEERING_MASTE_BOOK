### 1. WHAT IS IT?

**Supervised fine-tuning (SFT)** continues training with the same next-token cross-entropy, but on (prompt, answer) pairs rendered through a chat template, computing the loss **only on the answer tokens** (the *loss mask*).

### 2. WHY DOES IT EXIST?

Pretraining does not teach answering, format or stopping. SFT teaches them from demonstrations with a stable, cheap, well-understood objective.

### 3. DETAILED EXPLANATION

**Why mask the prompt?** You want the model to learn *answering*, not to imitate user text; prompts carry no demonstration of desired behaviour. (Some recipes train on prompts too; it is a tunable choice.)

[Explore the loss mask](../interactive/chat_template.html): an interactive page showing which tokens receive loss.

**Trade-offs.** SFT only teaches what is *demonstrated*: it cannot say "this answer is better than that one" (hence [10.19](10.19-preference-data.md) to [10.25](10.25-direct-preference-optimization-dpo.md)), it imitates errors in the data ([10.6](10.06-sft-data-curation.md)), and it can teach a model to *sound* confident about facts it does not know.

### 4. HOW DOES IT WORK?

1. Render the conversation with the chat template ([10.5](10.05-chat-templates.md)); tokenize.
2. Build `labels` = input ids shifted by one, with prompt positions masked.
3. Minimise `-sum_t mask_t * log p(x_t | x_<t) / sum_t mask_t`.
4. Evaluate on *held-out* prompts with an output-level metric, not only loss ([10.33](10.33-fine-tuning-evaluation.md)).
The learned `<|end|>` token is what makes the model stop, so serving can cut generation.

### 5. SIMPLE EXAMPLE

A student copying model answers to exam questions, graded only on the answer they write, not on the question text.

### 6. TECHNICAL EXAMPLE

Lab, full fine-tuning, 150 steps, lr 1e-3: exact-match accuracy on 33 unseen word pairs **0.88** (base model 0.00); task: upper-case the words (`up cat sun` becomes `CAT SUN`). Real analogues: support-bot tone, JSON formats, domain jargon, tool-call syntax. Numbers here come from the seeded lab run (`../lab/run_lab.py`, 64,512-parameter char model, one seed, CPU); they teach mechanics, not large-model behaviour.

### 7. CODE

```python
# ../lab/data.py: loss only on the response (+ <|end|>)
ids, mask = sft_example("up", ["cat", "sun"])   # mask = 0 over the prompt, 1 over "CAT SUN<|end|>"
x, y, m = collate([(ids, mask)])
loss = lm_loss(model, x, y, m)                 # ../lab/tiny_lm.py
```
Files: [`../lab/data.py`](../lab/data.py), [`../lab/tiny_lm.py`](../lab/tiny_lm.py); test `test_sft_loss_mask_covers_only_response` in [`../lab/test_tier10.py`](../lab/test_tier10.py).

### 8. INPUT → PROCESS → OUTPUT

```
(prompt, answer) --template--> token ids --> model --> logits --> CE loss x mask --> update
                                  mask: 0 on prompt, 1 on answer + <|end|>
```

### 9. ENTERPRISE USE CASE

Support-bot tone, JSON/SQL output formats, domain terminology, tool-call syntax, brand voice.

### 10. AI ENGINEERING CONNECTION

SFT is stage 1 of every assistant; its output is the reference model for DPO/RLHF ([10.25](10.25-direct-preference-optimization-dpo.md)).

### 11. ADVANTAGES

Simple, stable, cheap; works with adapters; demonstrations are easy to inspect.

### 12. LIMITATIONS

Imitates errors and style tics; cannot encode relative quality; memorises small sets; can add confident hallucination.

### 13. TRADE-OFFS

Data size and diversity versus epochs (memorisation); full fine-tuning versus adapters ([10.9](10.09-full-fine-tuning.md) vs [10.10](10.10-parameter-efficient-fine-tuning-peft.md)).

### 14. COMMON MISTAKES

(1) Loss on prompt tokens by accident; (2) no `<|end|>` so generation never stops; (3) training/serving template mismatch; (4) too many epochs on a small set.

### 15. PERFORMANCE / COST CONSIDERATIONS

Cost is tokens x epochs; with adapters, gradient/optimizer memory drops by an order of magnitude ([10.15](10.15-qlora.md)).

### 16. SECURITY CONSIDERATIONS

Poisoned or secret-laden demonstrations are memorised and can be regurgitated ([10.34](10.34-fine-tuning-data-security-considerations.md)).

### 17. INTERVIEW EXPLANATION

SFT is next-token training again, but on prompt-answer pairs formatted by the chat template, with the loss masked to the answer tokens. That teaches format, style and skills, including when to stop. It is cheap and stable but only teaches what is demonstrated, so for relative quality I follow it with preference optimization.

### 18. RAPID-FIRE ANSWER

SFT = next-token loss on answers only.
