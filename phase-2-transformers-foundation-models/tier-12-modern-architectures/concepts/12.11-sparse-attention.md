### 1. WHAT IS IT?

Sparse attention computes only selected `(query, key)` pairs: windows, dilated strides, blocks, and global tokens, chosen by fixed or learned patterns.

### 2. WHY DOES IT EXIST?

Reduce `O(n²)` pair computation while keeping long-range paths.

### 3. DETAILED EXPLANATION

Pattern families: sliding window, **dilated** (stride gaps), **block-sparse** (full inside blocks plus summaries), **global + local** (a few tokens see everyone). Longformer, BigBird and Sparse Transformer are classic examples (REVIEW_REQUIRED details).

### 4. HOW DOES IT WORK?

Build a boolean mask (or block layout), run attention only where the mask is true; efficient kernels use block-sparse layouts to be fast on GPUs.

### 5. SIMPLE EXAMPLE

Sending mail only to neighbours plus a few hub offices instead of to everyone.

### 6. TECHNICAL EXAMPLE

For n=32: window 6 → 34%, dilated(4) → 25%, block(8) → 36%, global+local → 43% of causal pairs (computed by `make_figures.py`).

### 7. CODE

```python
import numpy as np
n, w, g = 32, 6, 2
i, j = np.indices((n, n))
mask = (j <= i) & ((i - j < w) | (j < g))       # local window + g global (sink) tokens
print(mask.sum(), "of", n * (n + 1) // 2)
```

### 8. INPUT → PROCESS → OUTPUT

```
mask pattern → compute selected scores → softmax over allowed keys → output
```

### 9. ENTERPRISE USE CASE

Long genomic/log/document sequences.

### 10. AI ENGINEERING CONNECTION

Mostly superseded in LLMs by windows + GQA + FlashAttention, but still conceptually central.

### 11. ADVANTAGES

Sub-quadratic cost; keeps some global flow.

### 12. LIMITATIONS

Hardware-unfriendly if irregular; fixed patterns may miss needed pairs.

### 13. TRADE-OFFS

Sparsity vs reach vs kernel efficiency.

### 14. COMMON MISTAKES

Counting theoretical FLOP savings that the kernel cannot realise.

### 15. PERFORMANCE / COST CONSIDERATIONS

Cost ∝ number of allowed pairs, if kernels exploit it.

### 16. SECURITY CONSIDERATIONS

None specific.
