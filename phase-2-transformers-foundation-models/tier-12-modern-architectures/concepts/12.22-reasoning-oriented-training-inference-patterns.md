### 1. WHAT IS IT?

Reasoning-oriented patterns spend more **tokens at inference** (chain-of-thought, sampling and verification) and train models with reinforcement or verifier signals to use that budget well. Mostly training/inference *patterns*, not new layers.

### 2. WHY DOES IT EXIST?

Some tasks improve when the model writes intermediate steps before answering.

### 3. DETAILED EXPLANATION

Architecture-relevant consequences: long generated outputs make **decode cost and KV growth** dominant; cheap-per-token architectures (GQA, windows, SSM hybrids) become more valuable; majority-vote or best-of-N multiplies compute. Training specifics (RL with verifiable rewards, distillation of reasoning) are in [Tier 10](../../tier-10-fine-tuning-alignment/README.md). Claims about particular systems: REVIEW_REQUIRED.

### 4. HOW DOES IT WORK?

Prompt or train the model to emit reasoning tokens; optionally sample multiple chains and select by vote/verifier.

### 5. SIMPLE EXAMPLE

Showing your work on an exam.

### 6. TECHNICAL EXAMPLE

2,000 reasoning tokens per answer at 128 KiB/token adds 250 MiB KV on the GQA-8 archetype and 2,000 decode steps.

```
question → reasoning tokens (N steps) → answer   (cost ∝ N)
```

### 14. COMMON MISTAKES

### 15. PERFORMANCE / COST CONSIDERATIONS

Cost ∝ generated tokens.

### 16. SECURITY CONSIDERATIONS

Long chains enlarge attack surface; do not trust intermediate text as explanation.
