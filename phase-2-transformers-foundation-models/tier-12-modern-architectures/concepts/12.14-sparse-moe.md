### 1. WHAT IS IT?

Sparse MoE activates only the **top-k of E** experts per token, so the layer is sparse in parameters even though the model is large.

### 2. WHY DOES IT EXIST?

Dense MoE (all experts) would cost `E×` FFN compute; sparsity keeps cost near `k×`.

### 3. DETAILED EXPLANATION

Active parameters per layer = attention + `k` experts + router; total = attention + `E` experts + router (formulas in the lab). Typical settings: top-1 (Switch-style) or top-2 (Mixtral-style), REVIEW_REQUIRED.

![MoE routing with capacity](../figures/06_moe_routing_capacity.gif)

*Animation: tokens routed with top-2 to 8 experts; red bars hit capacity and overflow.*

### 4. HOW DOES IT WORK?

Compute router logits → softmax → take top-k → renormalise weights → dispatch tokens to experts → combine.

### 5. SIMPLE EXAMPLE

Each parcel goes to the two most suitable depots, not to all eight.

### 6. TECHNICAL EXAMPLE

`ffn_params_layer(spec, active=True)` vs `active=False`; hand-checked in tests with E=4, k=2.

### 7. CODE

```python
import sys; sys.path.insert(0, "lab")
import arch_matrix as am
toy = am.ArchSpec("toy","decoder",8,2,4,2,16,10,n_experts=4,top_k=2)
print(am.ffn_params_layer(toy, False), am.ffn_params_layer(toy, True))   # 1568 800
```

### 8. INPUT → PROCESS → OUTPUT

```
logits (T×E) → top-k per row → capacity check → expert batches → combine
```

### 9. ENTERPRISE USE CASE

Same as 12.13; relevant for sizing GPU memory vs compute.

### 10. AI ENGINEERING CONNECTION

Inference engines need expert parallelism and good batching.

### 11. ADVANTAGES

Capacity/FLOP; specialisation.

### 12. LIMITATIONS

Imbalance, dropped tokens, batch-size sensitivity.

### 13. TRADE-OFFS

Larger E and smaller k: more capacity, more routing noise.

### 14. COMMON MISTAKES

Forgetting router parameters; assuming k experts means k× faster than dense of same total.

### 15. PERFORMANCE / COST CONSIDERATIONS

Small batches activate many different experts, reducing the effective bandwidth saving.

### 16. SECURITY CONSIDERATIONS

See [12.16 Expert load balancing](12.16-expert-load-balancing.md).

### 17. INTERVIEW EXPLANATION

*"Sparse MoE routes each token to its top-k experts, so only k of E expert FFNs run; compute scales with k and memory with E."*

### 18. RAPID-FIRE ANSWER
