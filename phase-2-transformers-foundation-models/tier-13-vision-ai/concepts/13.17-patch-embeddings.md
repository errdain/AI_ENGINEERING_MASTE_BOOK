### 1. WHAT IS IT?

A patch embedding is the learned linear map that turns each flattened patch vector (p*p*C numbers) into a d-dimensional token, followed by adding position embeddings.

### 2. WHY DOES IT EXIST?

The Transformer works in a d-dim space; the projection is the vision analogue of the token-embedding table in [Tier 6 Tokenization & Embeddings](../../tier-06-tokenization-embeddings/).

### 3. DETAILED EXPLANATION

**Equivalence.** A linear layer on flattened patches equals a Conv2d with kernel=stride=p (tested numerically in the lab).

**Parameters.** `p*p*C*d + d`: p=16, C=3, d=768 -> 590,592.

**Position.** Learned 1-D position embeddings (N+1 vectors) are added; 2-D sin-cos and relative variants exist (REVIEW_REQUIRED per model). When changing resolution, position embeddings are usually interpolated.

**CLS token.** A learned extra token whose final state represents the whole image (some models use mean pooling instead).

Play: embed-dim slider in [`vit_patches.html`](../interactive/vit_patches.html) shows parameter count.

### 4. HOW DOES IT WORK?

`tokens = patches @ W + b` (shape (N,d)); concatenate CLS; add pos embedding (N+1,d).

### 5. SIMPLE EXAMPLE

Each 48-number patch becomes a 32-number token in the lab ViT.

### 6. TECHNICAL EXAMPLE

`test_torch_patches_match_numpy_and_patch_embed_is_conv` builds a Conv2d(3,32,4,stride=4), reshapes its weight to (32,48) and shows the same numbers come out of the linear projection.

### 7. CODE

```python
import torch, torch.nn as nn
conv = nn.Conv2d(3, 32, 4, stride=4)
x = torch.randn(2, 3, 16, 16)
tokens = conv(x).flatten(2).transpose(1, 2)      # (2, 16, 32): the ViT patch embedding
print(tokens.shape, sum(p.numel() for p in conv.parameters()))   # 3*4*4*32+32 = 1568
```
Lab: [`../lab/test_tier13.py`](../lab/test_tier13.py).

### 8. INPUT → PROCESS → OUTPUT

Input: (B,N,p*p*C). Process: linear + position. Output: (B,N+1,d).

### 9. ENTERPRISE USE CASE

Fine-tuning at a new resolution requires position-embedding interpolation; teams include this in conversion scripts and test with a golden image.

### 10. AI ENGINEERING CONNECTION

Same idea feeds image tokens into VLMs (then projected into the LLM space, [13.22 Vision-language models (VLMs)](13.22-vision-language-models-vlms.md)).

### 11. ADVANTAGES

Simple; conv implementation is fast.

### 12. LIMITATIONS

Linear map of raw pixels is a weak first stage; resolution-tied positions.

### 13. TRADE-OFFS

d: capacity vs cost; learned vs fixed positions: flexibility vs extrapolation.

### 14. COMMON MISTAKES

Wrong flatten order versus pretrained weights; forgetting to scale/normalize first; position embeddings missing -> model is permutation-invariant over patches.

### 15. PERFORMANCE / COST CONSIDERATIONS

Embedding is a tiny fraction of FLOPs; the encoder blocks dominate.

### 16. SECURITY CONSIDERATIONS

Not applicable.

### 17. INTERVIEW EXPLANATION

The patch embedding is a linear projection (implemented as a strided convolution) from p*p*C pixels to d dimensions, then position embeddings and a CLS token are added. Without positions the Transformer cannot tell where a patch came from.

### 18. RAPID-FIRE ANSWER

Linear (=strided conv) projection of flattened patches to d dims, plus positions.
