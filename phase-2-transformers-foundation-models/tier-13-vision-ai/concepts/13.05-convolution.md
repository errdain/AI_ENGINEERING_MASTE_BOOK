### 1. WHAT IS IT?

Convolution (as implemented in deep-learning libraries, strictly *cross-correlation*) slides a small kernel over the image; at each position it multiplies overlapping values and sums them into one output value.

### 2. WHY DOES IT EXIST?

It detects the same local pattern anywhere in the image with a handful of weights, and its cost and output size are predictable from a simple formula.

### 3. DETAILED EXPLANATION

**Formula.** For input size n, kernel k, padding p, stride s, dilation d: `out = floor((n + 2p - d(k-1) - 1) / s) + 1`. For d=1: `floor((n + 2p - k)/s) + 1`.

**Multi-channel.** A kernel has shape (C_in, k, k); the dot product runs over all channels and positions, giving one output channel. C_out kernels give C_out output channels. Weights: `C_out*C_in*k*k (+ C_out bias)`.

**Cross-correlation vs convolution.** True convolution flips the kernel; libraries skip the flip because the kernel is learned anyway.

**Cost.** Multiply-adds `= H_out*W_out*C_out*C_in*k*k`.

### 4. HOW DOES IT WORK?

For each output (i,j): take the k x k x C_in patch at (i*s, j*s) of the padded input, element-wise multiply by the kernel, sum, add bias. Vectorized implementations use im2col + matrix multiply or FFT/Winograd (REVIEW_REQUIRED for what a given library picks).

### 5. SIMPLE EXAMPLE

Kernel `[-1,0,1]` over the row `[0,0,5,5]`: positions give `5-0=5`, `5-0=5`... large where intensity jumps - a 1-D edge detector.

### 6. TECHNICAL EXAMPLE

12x12 input, 3x3 Sobel-x, s=1, p=0: out = floor((12+0-3)/1)+1 = 10. With p=1 the output is 12 ('same'). The lab's `conv2d_naive` (explicit loops) matches `torch.nn.functional.conv2d` to 1e-9 in tests.

### 7. CODE

```python
import sys; sys.path.insert(0, "../lab")
import numpy as np, torch, torch.nn.functional as F
from vision import conv2d_naive, conv_out_size
x, w = np.random.rand(3, 9, 9), np.random.rand(4, 3, 3, 3)
mine = conv2d_naive(x, w, stride=2, pad=1)
ref = F.conv2d(torch.tensor(x)[None], torch.tensor(w), stride=2, padding=1)[0].numpy()
print(np.allclose(mine, ref), mine.shape, conv_out_size(9, 3, 2, 1))   # True (4,5,5) 5
```

### 8. INPUT → PROCESS → OUTPUT

Input: (C_in,H,W) + kernels (C_out,C_in,k,k). Process: slide, multiply-sum per position. Output: (C_out,H_out,W_out).

### 9. ENTERPRISE USE CASE

Medical-imaging teams count conv FLOPs per slice to size GPU servers before committing to an architecture and input resolution.

### 10. AI ENGINEERING CONNECTION

Convolutions are the basis of CNN backbones, U-Nets for segmentation ([13.27 Image segmentation](13.27-image-segmentation.md)) and diffusion denoisers ([13.30 Diffusion-model introduction](13.30-diffusion-model-introduction.md)); ViT's patch embedding is also a strided convolution ([13.17 Patch embeddings](13.17-patch-embeddings.md)).

### 11. ADVANTAGES

Parameter-efficient, parallel, translation-equivariant, exact size formula.

### 12. LIMITATIONS

Fixed small window per layer; not exactly scale- or rotation-equivariant; naive implementation is slow.

### 13. TRADE-OFFS

Kernel size (larger = more context, k^2 cost) vs depth of 3x3 layers (same receptive field, fewer weights, more nonlinearity).

### 14. COMMON MISTAKES

Applying the output formula without floor; forgetting that padding applies to both sides (2p); mixing cross-correlation/convolution when comparing to a signal-processing text; wrong channel count in kernels.

### 15. PERFORMANCE / COST CONSIDERATIONS

Two stacked 3x3 convs cover a 5x5 field with 18*C^2 weights vs 25*C^2 for one 5x5 (per C->C layers).

### 16. SECURITY CONSIDERATIONS

No special risk beyond untrusted input sizes: bound H,W and C before allocating activations.

### 17. INTERVIEW EXPLANATION

Convolution slides a small kernel across the image computing a dot product at each position; one kernel yields one feature map and weights are shared across positions. Output size is floor((n+2p-k)/s)+1. It is cross-correlation in practice. Stacked 3x3 layers beat large kernels on parameters and nonlinearity.

### 18. RAPID-FIRE ANSWER

Slide a shared kernel, multiply-and-sum: out = floor((n+2p-k)/s)+1.
