### 1. WHAT IS IT?

Contrastive learning trains an encoder so that embeddings of *matching* pairs (two views of one image, or an image and its caption) are close and non-matching pairs are far apart.

### 2. WHY DOES IT EXIST?

Labels are expensive but pairs are abundant (web alt-text, augmented views). The contrastive objective turns paired data into a supervised-like signal with no class list.

### 3. DETAILED EXPLANATION

**InfoNCE (symmetric, CLIP-style).** For a batch of N pairs with normalized embeddings, logits `S_ij = cos(z_i, t_j)/T`. Loss = average of cross-entropy over rows (image->text) and columns (text->image), with the diagonal as the correct class.

**Temperature T.** Small T sharpens the softmax (hard-negative emphasis, risk of instability); large T flattens it. At T->infinity the loss tends to ln N (no information).

**Negatives.** Other items in the batch: larger batches = more negatives. *False negatives* (two different items that actually match, e.g. same caption) hurt; our toy has only 12 distinct captions so collisions are frequent, yet it still trains.

**Properties verified by tests.** Aligned pairs give ~0 loss; random embeddings give ~ln N at high T; loss is scale-invariant (cosine) and symmetric.

### 4. HOW DOES IT WORK?

Encode both views -> normalize -> `S = Z_i Z_t^T / T` -> cross-entropy with labels `arange(N)` in both directions -> backprop to both towers.

### 5. SIMPLE EXAMPLE

Seat N people at N tables; each person must pick their own partner's table from N choices. Training makes the right choice easy.

### 8. INPUT → PROCESS → OUTPUT

Input: batch of pairs. Process: embed, normalize, similarity matrix, bidirectional cross-entropy. Output: loss and trained towers.

### 9. ENTERPRISE USE CASE

A retailer trains a product-image/title model on its catalog pairs; hard negatives (same brand, different item) are mined to improve fine-grained retrieval.

### 10. AI ENGINEERING CONNECTION

Contrastive pretraining is how CLIP-style encoders learn ([13.20 CLIP](13.20-clip.md)) and why they work zero-shot; SigLIP-style variants use a sigmoid pairwise loss instead of softmax (REVIEW_REQUIRED).

### 11. ADVANTAGES

No class labels needed; scales with web data; produces aligned multimodal spaces.

### 12. LIMITATIONS

Needs large batches/many negatives; false negatives; learns shortcuts (e.g. text in images); noisy captions.

### 13. TRADE-OFFS

Batch size (more negatives vs memory), temperature (sharp vs stable), hard negatives (better vs risk of false negatives).

### 14. COMMON MISTAKES

Forgetting to normalize; using T too small from the start; duplicate items in a batch; evaluating retrieval on training pairs.

### 15. PERFORMANCE / COST CONSIDERATIONS

Similarity matrix is N x N; large-batch training needs distributed gathering of embeddings (REVIEW_REQUIRED for implementation specifics).

### 16. SECURITY CONSIDERATIONS

Web-scraped pairs can contain harmful or private content and poisoned pairs; filter and audit data ([Tier 9 Pretraining](../../tier-09-foundation-model-pretraining/)).

### 17. INTERVIEW EXPLANATION

Contrastive learning pulls matching pairs together and pushes others apart: normalize embeddings, compute an N x N cosine matrix divided by a temperature, and apply cross-entropy with the diagonal as labels in both directions. Temperature controls sharpness; more negatives help; false negatives hurt.

### 18. RAPID-FIRE ANSWER

InfoNCE: softmax over in-batch similarities where the diagonal is the right answer.
