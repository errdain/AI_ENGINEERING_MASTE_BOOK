### 1. WHAT IS IT?

The tensor view of an image: pixels are entries, channels (R, G, B) are stacked planes, and the whole thing is a 3-D array. Libraries differ on layout: channels-first (C, H, W; PyTorch) vs channels-last (H, W, C; PIL, NumPy images, TensorFlow default).

### 2. WHY DOES IT EXIST?

Neural-network layers are defined on tensors with a known axis meaning. Axis-order bugs run without error but silently produce garbage.

### 3. DETAILED EXPLANATION

**Shapes.** One image: (C, H, W) in PyTorch. A batch: (B, C, H, W). Grayscale: C=1. RGBA: C=4 (alpha is transparency, usually dropped).

**Dtype and range.** `uint8` 0-255 on disk; `float32` in [0, 1] after dividing by 255; often standardized further ([13.3 Image preprocessing](13.03-image-preprocessing.md)).

**Why channels matter.** Each channel is a full-resolution 'feature map' ([13.11 Feature maps](13.11-feature-maps.md)); the first conv layer mixes the 3 colour channels, later layers mix learned channels (16, 64, 512...).

![Channels of a synthetic image](../figures/01_image_as_tensor.png)

*Look at: each channel plane is a separate H x W array; the blue square is bright only in channel B.*

### 4. HOW DOES IT WORK?

Decode -> `(H, W, 3) uint8` -> `permute`/`transpose` to `(3, H, W)` -> cast to float -> divide by 255 -> stack into a batch `(B, 3, H, W)`.

### 5. SIMPLE EXAMPLE

A red square on black: channel R is a block of 1s, G and B are all 0.

### 6. TECHNICAL EXAMPLE

`img.reshape(3,16,16)[2]` is the blue plane. `np.transpose(hwc, (2,0,1))` converts HWC to CHW; getting this wrong on a square image shows no shape error, just scrambled content.

### 7. CODE

```python
import numpy as np
hwc = np.random.default_rng(0).integers(0, 256, (16, 16, 3), dtype=np.uint8)
chw = hwc.transpose(2, 0, 1).astype(np.float32) / 255.0   # (3,16,16) in [0,1]
batch = np.stack([chw, chw])                                # (2,3,16,16)
assert batch.shape == (2, 3, 16, 16) and np.isclose(chw[2, 4, 5], hwc[4, 5, 2] / 255.0)
```
The lab's synthetic data is already `(N, 3, H, W)`: [`../lab/vision.py`](../lab/vision.py).

### 8. INPUT → PROCESS → OUTPUT

Input: HWC uint8 array. Process: transpose, cast, scale, batch. Output: float tensor (B, C, H, W).

### 9. ENTERPRISE USE CASE

A pipeline serving two models (one TensorFlow channels-last, one PyTorch channels-first) needs an explicit layout contract at the boundary, plus a golden-image test that both produce the same prediction.

### 10. AI ENGINEERING CONNECTION

ViT patch extraction ([13.16 Image patches](13.16-image-patches.md)) reshapes exactly this tensor; VLMs resize and tile it before the vision encoder ([13.18 Vision encoders](13.18-vision-encoders.md)).

### 11. ADVANTAGES

A uniform tensor interface lets the same ops run on any image; batching gives GPU efficiency.

### 12. LIMITATIONS

Fixed shape per batch (images must be resized/padded to match); layout differences between libraries.

### 13. TRADE-OFFS

Channels-first vs last: layout can change kernel speed on some hardware (REVIEW_REQUIRED per device); float32 vs fp16/uint8 trades memory against precision.

### 14. COMMON MISTAKES

HWC fed to a CHW model; BGR (OpenCV) vs RGB; forgetting the batch dimension; normalizing before casting to float (integer division).

### 15. PERFORMANCE / COST CONSIDERATIONS

Batch memory = B*C*H*W*bytes; a batch of 64 float32 224x224 RGB images is about 38.5 MB (64*150,528*4 bytes).

### 16. SECURITY CONSIDERATIONS

Shape/dtype validation at the API edge prevents crashes and resource exhaustion from absurd dimensions.

### 17. INTERVIEW EXPLANATION

An image is a (C,H,W) tensor of intensities; a batch adds a leading dimension. I always state the layout and dtype at module boundaries because HWC/CHW and BGR/RGB mistakes run silently and just wreck accuracy.

### 18. RAPID-FIRE ANSWER

(Batch, Channels, Height, Width) array of numbers, e.g. (B,3,224,224).
