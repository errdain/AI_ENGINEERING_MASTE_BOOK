### 1. WHAT IS IT?

Sinusoidal positional encoding is the fixed, parameter-free scheme from the original Transformer: each position gets a vector of sines and cosines at geometrically spaced frequencies, added to the token embedding.

### 2. WHY DOES IT EXIST?

Provides unique, smoothly varying position codes with no parameters, and makes relative offsets easy to compute (a shift by *k* is a linear map of the encoding).

### 3. DETAILED EXPLANATION

```
PE[pos, 2i]   = sin(pos / 10000^(2i/d))
PE[pos, 2i+1] = cos(pos / 10000^(2i/d))
```
Each dimension pair is a wave with its own wavelength, from `2*pi` up to `10000*2*pi`: fast pairs resolve neighbouring positions, slow pairs distinguish far ones, like the digits of a clock. A shift by *k* acts on each (sin, cos) pair as a rotation by `k*omega_i`, hence a **linear map**; this was the design motivation. In practice it extrapolates only weakly to lengths unseen in training (`REVIEW_REQUIRED` for strength of claim).

### 5. SIMPLE EXAMPLE

A clock with many hands: the second hand tells fine differences, the hour hand tells coarse ones; together they identify the time uniquely.

### 6. TECHNICAL EXAMPLE

Position 0 is `[0,1,0,1,...]` (all sines 0, all cosines 1), a fact the lab test checks.

### 7. CODE

```python
# run inside lab/
import numpy as np
from positional import sinusoidal
pe = sinusoidal(50, 16)
print(pe.shape, np.abs(pe).max() <= 1.0)       # (50, 16) True
print(pe[0, :4])                                # [0. 1. 0. 1.]
# dot product with position 10's code: maximal (d/2 = 8) at position 10 itself, lower elsewhere:
print((pe @ pe[10]).round(1)[[10, 11, 15, 30]])
```

### 8. INPUT → PROCESS → OUTPUT

```
pos, dim-pair i ──► sin/cos(pos·ω_i) with ω_i = 10000^(-2i/d) ──► vector added to token embedding
```

### 9. ENTERPRISE USE CASE

Rarely a deployment choice today, but appears in many baseline/legacy models and encoders for time-series and vision patches.

### 10. AI ENGINEERING CONNECTION

Historical foundation; the rotation idea is the conceptual ancestor of RoPE ([6.24 RoPE](06.24-rope.md)).

### 11. ADVANTAGES

No parameters; any length can be computed; smooth; interpretable.

### 12. LIMITATIONS

Absolute (relative info is implicit); weak extrapolation in practice; added at the input only.

### 13. TRADE-OFFS

No parameters versus less flexibility than learned or relative methods.

### 14. COMMON MISTAKES

- Odd `d_model`.
- Forgetting to scale embeddings consistent with the original recipe.
- Assuming it guarantees length generalization.

### 15. PERFORMANCE / COST CONSIDERATIONS

Precompute the table once; O(L*d) memory.

### 16. SECURITY CONSIDERATIONS
