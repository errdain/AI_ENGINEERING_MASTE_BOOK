### 1. WHAT IS IT?

Word tokenization splits text into words (usually on whitespace and punctuation) and gives each distinct word one vocabulary entry.

### 2. WHY DOES IT EXIST?

Words are the natural unit humans reason about and give short sequences; classic NLP (bag-of-words, word2vec, early RNN models) was built on them.

### 3. DETAILED EXPLANATION

Strengths: short sequences and each token already carries a recognizable meaning.

Weaknesses: (1) the vocabulary explodes: every inflection, typo, name, URL and number is a new entry, easily 10^5-10^6 types; (2) anything unseen becomes `<UNK>` ([6.8 UNK](06.08-unk.md)), losing information at exactly the rare words that often matter; (3) no parameter sharing between `unhappy` and `unhappiness`; (4) the rule "split on spaces" fails for Chinese, Japanese and Thai, which do not use spaces between words.

### 4. HOW DOES IT WORK?

Split with a rule or regex, build a word->ID table from the most frequent N words, map everything else to `<UNK>`.

### 5. SIMPLE EXAMPLE

A dictionary of whole words: fast to look things up, but a new slang term has no entry at all.

### 6. TECHNICAL EXAMPLE

A 50,000-word vocabulary with d=768 embeddings is ~38M parameters in the table; covering a billion-word web corpus without UNK would need far more entries, which is the problem subwords ([6.5 Subword tokenization](06.05-subword-tokenization.md)) solve.

### 7. CODE

```python
import re
from collections import Counter
corpus = "the cat sat on the mat the cat ran"
words = re.findall(r"\w+|[^\w\s]", corpus.lower())
vocab = {"<UNK>": 0}
for w, _ in Counter(words).most_common(4):
    vocab[w] = len(vocab)
encode = lambda s: [vocab.get(w, 0) for w in re.findall(r"\w+|[^\w\s]", s.lower())]
print(encode("the dog sat"))   # 'dog' is unseen -> 0 (UNK)
```

### 8. INPUT → PROCESS → OUTPUT

```
"the dog sat" ──split──► [the, dog, sat] ──lookup──► [1, 0(UNK), 3]
```

### 9. ENTERPRISE USE CASE

Still used in classical search/analytics (TF-IDF, keyword filters, BM25) where whole words are the right unit; not used as the input layer of modern LLMs.

### 10. AI ENGINEERING CONNECTION

Motivates [6.8 UNK](06.08-unk.md) and [6.5 Subword tokenization](06.05-subword-tokenization.md); also the reason lexical retrieval (BM25) and neural tokenization see text differently in hybrid RAG.

### 11. ADVANTAGES

Shortest sequences; interpretable tokens; fast.

### 12. LIMITATIONS

Huge vocabularies; frequent `<UNK>`; no morphology sharing; language-dependent splitting rules.

### 13. TRADE-OFFS

Short sequences versus a giant embedding/softmax table and OOV loss.

### 14. COMMON MISTAKES

- Using whitespace splitting for languages without spaces.
- Forgetting that punctuation and casing multiply the vocabulary.
- Treating `<UNK>` rate as a harmless statistic (it hides entities and numbers).

### 15. PERFORMANCE / COST CONSIDERATIONS

Embedding and output softmax grow with V (see [6.28 Vocabulary-size trade-offs](06.28-vocabulary-size-trade-offs.md)); sparse gradients make rare words nearly untrained.

### 16. SECURITY CONSIDERATIONS

Out-of-vocabulary entities (new product names, injected strings) all collapse to the same `<UNK>`, which hides them from downstream checks.

### 17. INTERVIEW EXPLANATION

*"Word tokenization gives short sequences but an enormous vocabulary and unknown-word problem. Subword tokenization keeps frequent words whole and splits rare ones, getting the best of both."*

### 18. RAPID-FIRE ANSWER

One token per word: short sequences, huge vocab, OOV.
