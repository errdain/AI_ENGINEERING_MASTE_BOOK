### 1. WHAT IS IT?

Byte fallback keeps a normal subword vocabulary but encodes characters it does not contain as raw UTF-8 bytes (e.g. `<0xE6>` tokens) instead of `<UNK>`.

### 2. WHY DOES IT EXIST?

Makes any input representable (no UNK) while keeping compact tokens for common text; avoids the full cost of pure byte-level tokenization.

### 3. DETAILED EXPLANATION

Mechanism: reserve 256 byte tokens in the vocabulary. At encode time, a character not covered by any piece is replaced by its UTF-8 bytes, each emitted as a byte token. Decoding concatenates byte tokens back into characters. Used by SentencePiece-based models such as Llama-family tokenizers (verify per model, `REVIEW_REQUIRED`).

Contrast with byte-level BPE ([6.4 Byte tokenization](06.04-byte-tokenization.md), [6.12 BPE](06.12-bpe.md)): there bytes are the *base alphabet* for all merges; with byte fallback the vocabulary is character/subword based and bytes are only the escape hatch. Rare scripts therefore cost 2-4 byte tokens per character - the same asymmetry as pure bytes.

### 4. HOW DOES IT WORK?

Encode: segment as usual; for uncovered characters emit byte tokens. Decode: join all pieces; merge consecutive byte tokens and UTF-8 decode.

### 5. SIMPLE EXAMPLE

A dictionary with a 'spell it out in Morse' appendix for words that are not in it.

### 6. TECHNICAL EXAMPLE

An emoji absent from the vocabulary becomes four byte tokens instead of one UNK.

### 7. CODE

```python
# toy illustration of byte fallback (self-contained)
vocab = {"hello": 0, " world": 1, " ": 2}      # byte tokens get ids 100 + byte value

def encode(s):
    out, i = [], 0
    pieces = sorted(vocab, key=len, reverse=True)
    while i < len(s):
        p = next((p for p in pieces if s.startswith(p, i)), None)
        if p:
            out.append(vocab[p]); i += len(p)
        else:                                   # fall back to raw UTF-8 bytes
            out += [100 + b for b in s[i].encode("utf-8")]; i += 1
    return out

print(encode("hello world"))     # [0, 1]
print(encode("hello 🙂"))         # [0, 2, 340, 259, 253, 230]: emoji = 4 UTF-8 bytes = 4 byte tokens
```

### 8. INPUT → PROCESS → OUTPUT

```
text ─► known pieces?  yes → subword token
                 no  → UTF-8 bytes → byte tokens (never UNK)
```

### 9. ENTERPRISE USE CASE

Multilingual products rely on byte fallback so unexpected scripts, emoji or symbols never crash or silently vanish.

### 10. AI ENGINEERING CONNECTION

A reason modern LLMs essentially never emit UNK ([6.8 UNK](06.08-unk.md)).

### 11. ADVANTAGES

No UNK; keeps compact tokens for common text.

### 12. LIMITATIONS

Fallback characters are expensive (2-4 tokens each); byte tokens carry little meaning.

### 13. TRADE-OFFS

Universal coverage with small vocabularies versus high cost for uncovered scripts.

### 14. COMMON MISTAKES

- Forgetting to enable byte fallback and getting UNK.
- Assuming it fixes cost for uncovered scripts.
- Decoding byte tokens individually (broken characters).

### 15. PERFORMANCE / COST CONSIDERATIONS

Uncovered scripts: 2-4x tokens per character.

### 16. SECURITY CONSIDERATIONS

Byte tokens make arbitrary input representable; combine with token caps and normalization checks.

### 17. INTERVIEW EXPLANATION
