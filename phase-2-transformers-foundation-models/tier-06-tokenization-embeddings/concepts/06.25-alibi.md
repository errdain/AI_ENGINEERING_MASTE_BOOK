### 1. WHAT IS IT?

ALiBi (Attention with Linear Biases) uses no position vectors: it adds a *linear penalty proportional to distance* to the attention logits, with a different fixed slope per head.

### 2. WHY DOES IT EXIST?

To get a parameter-free position scheme that extrapolates to longer sequences than were seen in training (reported in the original work; `REVIEW_REQUIRED` for magnitude).

### 3. DETAILED EXPLANATION

For query *i* and key *j* (causal, j <= i): `score(i,j) = q_i . k_j - m_h * (i - j)`. Slopes `m_h` form a geometric sequence per head: `2^(-8*h/n_heads)` for h = 1..n (n a power of two): with 8 heads, 1/2, 1/4, ..., 1/256. Heads with small slopes attend widely; heads with large slopes are strongly local. Distant tokens are softly down-weighted. Used by some open models (e.g. BLOOM, MPT; `REVIEW_REQUIRED`).

Compared to RoPE ([6.24 RoPE](06.24-rope.md)): ALiBi changes only the score; nothing is added to embeddings or rotated; it is simpler but inherently biased toward recency.

### 4. HOW DOES IT WORK?

Add `bias[h, i, j] = -m_h * (i - j)` to the score matrix before softmax; causal mask sets j > i to -inf.

### 5. SIMPLE EXAMPLE

A tax on reading far-back words: the further back, the bigger the discount on its influence.

### 6. TECHNICAL EXAMPLE

With slope 0.5, a token 3 steps back gets -1.5 added to its logit.

### 7. CODE

```python
# run inside lab/
import numpy as np
from positional import alibi_slopes, alibi_bias
print(alibi_slopes(8))                 # [0.5, 0.25, ..., 0.0039]
b = alibi_bias(4, 0.5)
print(b[3])                            # [-1.5 -1.  -0.5  0. ]  (distance 3,2,1,0)
print(b[0, 3])                         # -inf above the diagonal (causal)
```
Code: [`lab/positional.py`](../lab/positional.py) (`alibi_slopes`, `alibi_bias`)

### 8. INPUT → PROCESS → OUTPUT

```
scores q·k ──+ (−slope_h × distance) ──+ causal −inf──► softmax ──► weights favouring recent tokens
```

### 9. ENTERPRISE USE CASE

Chosen when training budgets don't allow long-context training but long inference contexts are needed (`REVIEW_REQUIRED`).

### 10. AI ENGINEERING CONNECTION

One of the two main parameter-free relative schemes; contrast with [6.24 RoPE](06.24-rope.md).

### 11. ADVANTAGES

No parameters; trivial; good length extrapolation in original reports; no embedding changes.

### 12. LIMITATIONS

Strong recency bias can hamper long-range retrieval; less adopted in recent models than RoPE (`REVIEW_REQUIRED`).

### 13. TRADE-OFFS

Simplicity and extrapolation versus recency bias.

### 14. COMMON MISTAKES

- Wrong slope schedule for non-power-of-two head counts.
- Forgetting the causal mask for decoder models.

### 15. PERFORMANCE / COST CONSIDERATIONS

Bias is precomputable; negligible compute.

### 16. SECURITY CONSIDERATIONS

None specific; recency bias can make models more susceptible to instructions placed at the end of long prompts (`REVIEW_REQUIRED`).

### 17. INTERVIEW EXPLANATION
