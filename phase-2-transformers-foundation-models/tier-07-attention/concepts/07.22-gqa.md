### 1. WHAT IS IT?

Grouped-Query Attention (GQA): query heads are partitioned into `G = H_kv` groups, each group shares one K/V head. `H_kv = H` ⇒ MHA; `H_kv = 1` ⇒ MQA.

### 2. WHY DOES IT EXIST?

MQA saves the most memory but can cost quality; MHA is best but expensive to cache. GQA gives a tunable middle ground with near-MHA quality and much of MQA's savings.

### 3. DETAILED EXPLANATION

Ainslie et al., 2023 (`REVIEW_REQUIRED`). Several open LLM families use GQA (e.g. Llama-2-70B and Llama-3, Mistral-7B per their reports — `REVIEW_REQUIRED` per model; check the model card's `num_key_value_heads`).

| Variant | H_kv | KV cache vs MHA | Quality | Used when |
|---|---|---|---|---|
| MHA | H | 1× | best baseline | small models, encoders |
| GQA | 1 < H_kv < H | H_kv/H | near MHA | most recent large LLMs |
| MQA | 1 | 1/H | slight drop possible | maximum cache/bandwidth savings |

**Converting a trained MHA checkpoint to GQA.** The GQA paper proposes mean-pooling the K/V head weights within each group then briefly continuing training ("uptraining", `REVIEW_REQUIRED`).

![MHA vs GQA vs MQA](../figures/05_mha_mqa_gqa.png)

*Figure — group structure: query heads in the same colour group read the same K/V head.*

### 4. HOW DOES IT WORK?

1. Choose `H_kv` dividing `H`.
2. Project K, V to `H_kv` heads.
3. Repeat each K/V head `H/H_kv` times (`repeat_interleave`, not `repeat`): query head `i` uses KV head `i // group_size`.
4. Per-head attention.

### 5. SIMPLE EXAMPLE

Classrooms of students (query heads); each classroom shares one textbook (K/V head).

### 6. TECHNICAL EXAMPLE

Cache for `n = 8192`, 32 layers, `d_h = 128`, fp16: 32 KV heads = 4 GiB; 8 KV heads = 1 GiB per sequence (exact for these shapes).

### 7. CODE


### 8. INPUT → PROCESS → OUTPUT

```
Q: H heads    K,V: H_kv heads ─► repeat_interleave ─► H heads ─► attention
```

### 9. ENTERPRISE USE CASE

Larger batch/context on the same GPU memory; cheaper serving.

### 10. AI ENGINEERING CONNECTION

Default design in many recent LLMs; interacts with paged KV caches (Tier 11).

### 11. ADVANTAGES

Near-MHA quality with a much smaller cache.

### 12. LIMITATIONS

Needs `H_kv | H`; quality still can vary; cannot be changed after pre-training without uptraining.

### 13. TRADE-OFFS

Pick `H_kv` between 1 and H to trade quality versus memory.

### 14. COMMON MISTAKES

`n_heads % n_kv_heads != 0`; using `repeat` instead of `repeat_interleave` (wrong groups, no shape error); sizing cache with `H` instead of `H_kv`.

### 15. PERFORMANCE / COST CONSIDERATIONS

Cache bytes `2·L·H_kv·d_h·n·B·bytes`; parameters of W_k, W_v shrink by `H_kv/H`.

### 16. SECURITY CONSIDERATIONS

None specific.

### 17. INTERVIEW EXPLANATION

*"GQA groups query heads and shares one K/V head per group: H_kv = H is MHA, H_kv = 1 is MQA. It cuts the KV cache by H/H_kv, so serving throughput and batch size improve, and quality stays close to MHA."*

### 18. RAPID-FIRE ANSWER

Fewer KV heads than query heads: smaller KV cache, little quality loss.
