### 1. WHAT IS IT?

Dividing scores by `√d_k` keeps their variance near 1 regardless of head size, so softmax does not saturate.

### 2. WHY DOES IT EXIST?

If components of q and k are independent with mean 0 and variance 1, `q·k` is a sum of `d_k` products each with variance 1, so **`Var(q·k) = d_k`** and its standard deviation is `√d_k`. Large spreads push softmax toward one-hot, where its gradient `p(1−p)` vanishes and learning stalls.

### 3. DETAILED EXPLANATION

Dividing by `√d_k` restores unit variance. This is the argument from the original paper; real trained activations are not exactly unit-variance, so treat it as the design motivation rather than an exact guarantee. Scaling does **not** change which key has the largest score, only how peaked the distribution is (it acts as a fixed temperature, [7.9 Softmax](07.09-softmax.md)). Use `√d_k` of the **head** (`d_h`), not `√d_model`.

### 4. HOW DOES IT WORK?

1. Compute `Q Kᵀ`.
2. Multiply by `1/√d_k` (a constant).
3. Continue to softmax.

### 5. SIMPLE EXAMPLE

Turning down a microphone gain when the speaker is louder in bigger rooms, so the output level stays comfortable.

### 6. TECHNICAL EXAMPLE

Empirically check: sample q, k ~ N(0, I) with d_k = 256; variance of `q·k` ≈ 256 unscaled and ≈ 1 scaled.

### 7. CODE

```python
import numpy as np
rng = np.random.default_rng(0)
for d in (16, 64, 256):
    q, k = rng.normal(size=(20000, d)), rng.normal(size=(20000, d))
    s = (q * k).sum(1)
    print(d, round(s.var(), 1), round((s / np.sqrt(d)).var(), 2))   # ~d, ~1
```

### 8. INPUT → PROCESS → OUTPUT

```
scores (var ≈ d_k) ─► ÷√d_k ─► scores (var ≈ 1) ─► softmax (not saturated)
```

### 9. ENTERPRISE USE CASE

A missing/incorrect scale is a classic silent bug in custom kernels and ports: loss trains slower or diverges, with no error.

### 10. AI ENGINEERING CONNECTION

Some recent models change attention scaling or add QK-normalisation for stability (`REVIEW_REQUIRED`: model-specific; see Tier 12).

### 11. ADVANTAGES

Keeps gradients healthy; constant; free.

### 12. LIMITATIONS

Assumes unit-variance independent components; trained activations deviate.

### 13. TRADE-OFFS

Fixed scale (simple) versus learnable temperature or QK-norm (more flexible, more parameters/complexity).

### 14. COMMON MISTAKES

Scaling by `1/d_k` instead of `1/√d_k`; using `√d_model` in multi-head; forgetting scale in custom kernels.

### 15. PERFORMANCE / COST CONSIDERATIONS

One elementwise multiply (often fused into the matmul).

### 16. SECURITY CONSIDERATIONS

None specific.

### 17. INTERVIEW EXPLANATION

*"Dot products of d_k-dimensional unit-variance vectors have variance d_k, so scores get larger with head size. Without dividing by √d_k softmax saturates and gradients vanish."*

### 18. RAPID-FIRE ANSWER

Divide by √d_k to keep score variance ≈ 1.
