### 1. WHAT IS IT?

Head dimension `d_h = d_model / H`: the width of each head's Q, K and V vectors.

### 2. WHY DOES IT EXIST?

Splitting the model width into H equal slices keeps total compute equal to one wide head while allowing H separate attention patterns.

### 3. DETAILED EXPLANATION

Example: `d_model = 4096`, `H = 32` ⇒ `d_h = 128`. Implementation = reshape: `(B,T,E) → (B,T,H,d_h) → (B,H,T,d_h)` (`split_heads`), run attention batched over `H`, then `merge_heads` (transpose back and reshape). `d_model` must be divisible by `H` (assert!). Increasing `H` at fixed `d_model` shrinks `d_h`: more diverse patterns, but each head's dot product has fewer dimensions. Common head sizes in published models are 64–128 (`REVIEW_REQUIRED` per model). KV-cache size scales with `H_kv · d_h` ([7.24 Attention memory requirements](07.24-attention-memory-requirements.md)). Scaling uses `√d_h` ([7.8 Scaling by √dk](07.08-scaling-by-dk.md)).

Interactive: set d_model and H in [the multi-head / GQA explorer](../interactive/multihead_gqa.html).

### 4. HOW DOES IT WORK?

1. Assert `E % H == 0`.
2. `x.reshape(B,T,H,d_h).transpose(0,2,1,3)`.
3. After attention: `transpose(0,2,1,3).reshape(B,T,H·d_h)`.

### 5. SIMPLE EXAMPLE

Cutting a long ribbon into H equal strips, one per head.

### 6. TECHNICAL EXAMPLE

`test_split_merge_roundtrip` verifies `merge_heads(split_heads(x)) == x`.

### 7. CODE

```python
import numpy as np
from attention_np import split_heads, merge_heads
x = np.arange(2*3*8, dtype=float).reshape(2, 3, 8)
h = split_heads(x, 4)                     # (2, 4, 3, 2): d_h = 8/4 = 2
print(h.shape, np.array_equal(merge_heads(h), x))
```
Source: [`../lab/attention_np.py`](../lab/attention_np.py).

### 8. INPUT → PROCESS → OUTPUT

```
(B,T,E) ─reshape─► (B,T,H,d_h) ─transpose─► (B,H,T,d_h)  … attention …  ─► (B,T,E)
```

### 9. ENTERPRISE USE CASE

Chosen at pre-training; cannot be changed in deployment.

### 10. AI ENGINEERING CONNECTION

Head dim interacts with RoPE (rotates pairs within `d_h`; Tier 6) and kernel support.

### 11. ADVANTAGES

Cheap split; balanced compute.

### 12. LIMITATIONS

Small `d_h` limits per-head capacity; divisibility constraint.

### 13. TRADE-OFFS

Few big heads versus many small heads.

### 14. COMMON MISTAKES

Missing transpose; non-divisible sizes; scaling by `√d_model`.

### 15. PERFORMANCE / COST CONSIDERATIONS

Kernels favour certain `d_h` sizes (`REVIEW_REQUIRED` per hardware).

### 16. SECURITY CONSIDERATIONS

None specific.

### 17. INTERVIEW EXPLANATION

*"Head dimension is d_model divided by the number of heads; each head works in that smaller space and results are concatenated back to d_model."*

### 18. RAPID-FIRE ANSWER

d_h = d_model / H.
