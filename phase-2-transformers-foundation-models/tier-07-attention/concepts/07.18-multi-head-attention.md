### 1. WHAT IS IT?

Multi-head attention (MHA) runs `H` scaled dot-product attentions in parallel on lower-dimensional subspaces, concatenates the results and mixes them with an output projection `W_o`.

### 2. WHY DOES IT EXIST?

One attention gives one weighting per query. Multiple heads can attend to different relations (previous token, nearby words, syntactic partners…) simultaneously at no extra parameter cost versus one wide head.

### 3. DETAILED EXPLANATION

```
head_h = Attention(X W_q^h, X W_k^h, X W_v^h)      h = 1..H, each with d_h = d_model / H
MHA(X) = Concat(head_1, …, head_H) · W_o
```
Total FLOPs and parameters are about the same as a single head of width `d_model`. Implementation is a reshape, not a loop ([7.19 Head dimensions](07.19-head-dimensions.md)). Variants that share K/V across heads: MQA/GQA ([7.21 MQA](07.21-mqa.md), [7.22 GQA](07.22-gqa.md)).

### 4. HOW DOES IT WORK?

1. Project to Q, K, V (full width).
2. Split into `H` heads: `(B,T,E) → (B,H,T,d_h)`.
3. Attention per head (batched).
4. Merge heads and apply `W_o`.

### 5. SIMPLE EXAMPLE

A panel of H reviewers each reading the same page with a different focus, then a chair merging their notes.

### 6. TECHNICAL EXAMPLE

### 7. CODE

```python
import numpy as np
from attention_np import MultiHeadAttention, causal_mask
x = np.random.default_rng(1).normal(size=(2, 5, 16))
mha = MultiHeadAttention(d_model=16, n_heads=4)
y = mha(x, mask=causal_mask(5))
print(y.shape, mha.last_weights.shape)    # (2, 5, 16) (2, 4, 5, 5): one 5x5 map per head
```

### 8. INPUT → PROCESS → OUTPUT

```
X ─► Q,K,V ─► split into H heads ─► H× attention ─► concat ─► ·W_o ─► Y
```

### 9. ENTERPRISE USE CASE

Head count and head dim are architecture choices fixed at pre-training; they determine KV-cache size and kernel efficiency.

### 10. AI ENGINEERING CONNECTION

Core of every Transformer block (Tier 8).

### 11. ADVANTAGES

Diverse relations in parallel; same FLOPs as one wide head.

### 12. LIMITATIONS

Many heads in trained models are redundant or prunable (reported in the literature — `REVIEW_REQUIRED`); not every head is interpretable.

### 13. TRADE-OFFS

More heads = more diversity but smaller `d_h` per head.

### 14. COMMON MISTAKES

Reshaping `(B,T,E)` to `(B,H,T,d_h)` without the transpose (silently mixes tokens and heads; shapes still match); forgetting `W_o`; scaling by `√d_model` instead of `√d_h`.

### 15. PERFORMANCE / COST CONSIDERATIONS

Same FLOPs as one wide head; throughput depends on `d_h` (kernels favour multiples of 8/16 — `REVIEW_REQUIRED`).

### 16. SECURITY CONSIDERATIONS

Nothing head-specific.

### 17. INTERVIEW EXPLANATION

*"Multi-head attention splits d_model into H smaller heads, runs scaled dot-product attention in each in parallel with its own Q/K/V projections, concatenates, and applies an output projection. It lets the model attend to different relations at once at the same cost as one big head."*

### 18. RAPID-FIRE ANSWER

H parallel attentions on d_model/H slices, concatenated and mixed by W_o.
