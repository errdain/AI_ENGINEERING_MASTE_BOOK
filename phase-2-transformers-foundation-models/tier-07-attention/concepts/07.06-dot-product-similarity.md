### 1. WHAT IS IT?

Dot-product similarity measures how aligned a query and a key are: `s_ij = q_i · k_j = ‖q_i‖‖k_j‖cos θ`.

### 2. WHY DOES IT EXIST?

Attention needs a cheap, differentiable similarity. The dot product is a single multiply-add per dimension and, for all pairs at once, a single matrix multiply, which maps perfectly onto GPUs and accelerators.

### 3. DETAILED EXPLANATION

The dot product is large and positive when vectors point the same way **and** when they are long; it is negative for opposed vectors. Because it depends on length as well as angle, its scale grows with `d_k` ([7.8 Scaling by √dk](07.08-scaling-by-dk.md)). Stacking all pairs: `S = Q Kᵀ ∈ ℝ^{T×S}`. Other similarity choices exist (additive attention in Bahdanau-style models, cosine similarity), but dot-product attention dominates because it uses optimised matmul kernels (`REVIEW_REQUIRED` for historical comparison details).

### 4. HOW DOES IT WORK?

1. For one query, multiply elementwise with a key and sum: `Σ_d q_d k_d`.
2. For all queries and keys: `Q @ K.T`.

### 5. SIMPLE EXAMPLE

Two arrows from the same origin: if they point the same direction, their dot product is big; at right angles it is zero.

### 6. TECHNICAL EXAMPLE

With T = 4096 tokens and d_h = 128, `Q Kᵀ` is a 4096×4096 matrix per head, computed as one GEMM.

### 7. CODE

```python
import numpy as np
rng = np.random.default_rng(0)
q, K = rng.normal(size=4), rng.normal(size=(5, 4))
scores = K @ q                                   # one score per key
cos = scores / (np.linalg.norm(K, axis=1) * np.linalg.norm(q))
print(scores.round(2), cos.round(2))             # same ordering only if key norms are equal
```
Batch form: `q @ np.swapaxes(k, -1, -2)` in [`../lab/attention_np.py`](../lab/attention_np.py).

### 8. INPUT → PROCESS → OUTPUT

```
Q (T×d_k) @ Kᵀ (d_k×S) ─► raw score matrix (T×S)
```

### 9. ENTERPRISE USE CASE

GEMM-friendly: hardware vendors optimise this exact operation.

### 10. AI ENGINEERING CONNECTION

The same dot product is used for embedding similarity in retrieval (Tier 20); there vectors are usually normalised so dot product equals cosine.

### 11. ADVANTAGES

Fast, differentiable, parallel.

### 12. LIMITATIONS

Sensitive to vector length and `d_k` (scale grows); needs scaling ([7.8 Scaling by √dk](07.08-scaling-by-dk.md)).

### 13. TRADE-OFFS

Dot-product (fast) versus additive scoring (more flexible, slower).

### 14. COMMON MISTAKES

Assuming dot product equals cosine similarity; forgetting to scale.

### 15. PERFORMANCE / COST CONSIDERATIONS

B·H·T·S·d_k multiply-adds ([7.23 Attention complexity](07.23-attention-complexity.md)).

### 16. SECURITY CONSIDERATIONS
