### 1. WHAT IS IT?

Attention is a mechanism that builds each output as a **weighted average of value vectors**, where the weights come from comparing a *query* with every *key*. It is a differentiable, content-based, soft lookup.

### 2. WHY DOES IT EXIST?

Early sequence-to-sequence models squeezed a whole source sentence into one fixed-size vector, and long sentences lost information. Attention (introduced for translation by Bahdanau et al., 2014; `REVIEW_REQUIRED` for citation details) let the decoder look back at **all** encoder states and choose which matter for the *current* output step. "Attention Is All You Need" (Vaswani et al., 2017; `REVIEW_REQUIRED`) then showed attention alone, with no recurrence, is enough, which also made training parallel across positions (Tier 8).

### 3. DETAILED EXPLANATION

**Soft dictionary lookup.** A hash map returns the value whose key *equals* the query. Attention returns a blend of *all* values, each weighted by how well its key *matches* the query. Because the match score and the blend are both differentiable, the "lookup" can be learned by gradient descent.

**RNN versus attention.** An RNN (Tier 5 Sequence Models) passes information through a fixed-size state one step at a time, so two distant tokens interact only through a long chain of updates. Attention lets **every position read every other position directly in one step**, with data-dependent weights. The price is that the number of query–key pairs is n², which drives almost every engineering topic in 7.23–7.30.

**Scope of this tier.** Tier 7 owns the attention *math*. Tier 8 owns how attention sits inside encoder/decoder blocks (residuals, norms, FFN). Positional methods (RoPE, ALiBi) are Tier 6; serving-time KV-cache engineering is Tier 11.

### 4. HOW DOES IT WORK?

1. Start with token representations `X` (T × d_model).
2. Project them to queries, keys and values ([7.5 Q/K/V projections](07.05-q-k-v-projections.md)).
3. Compare every query with every key ([7.6 Dot-product similarity](07.06-dot-product-similarity.md), [7.7 Attention scores](07.07-attention-scores.md)), scale ([7.8 Scaling by √dk](07.08-scaling-by-dk.md)).
4. Normalise each row with softmax ([7.9 Softmax](07.09-softmax.md)).
5. Blend the values with those weights ([7.10 Weighted values](07.10-weighted-values.md)); the formula is assembled in [7.11 Scaled dot-product attention](07.11-scaled-dot-product-attention.md).

### 5. SIMPLE EXAMPLE

You are looking for a recipe (the **query**). Every cookbook has a spine label (its **key**) and contents (its **value**). You compare your need with all spine labels, give each book a relevance share, and read a blend of the contents weighted by those shares.

### 6. TECHNICAL EXAMPLE

In a Transformer language model, the token "it" in "The cat sat because **it** was tired" needs information from "cat". Its query vector scores high against the key of "cat", so the output at "it" is dominated by the value of "cat". Decoder-only LLMs use this at every layer (see [7.12 Self-attention](07.12-self-attention.md), [7.14 Causal attention](07.14-causal-attention.md)).

```python
# Minimal soft lookup (run from lab/): full implementation in ../lab/attention_np.py
import numpy as np
from attention_np import scaled_dot_product_attention
rng = np.random.default_rng(0)
q, k, v = rng.normal(size=(3, 4)), rng.normal(size=(5, 4)), rng.normal(size=(5, 2))
out, w = scaled_dot_product_attention(q, k, v)
print(out.shape, w.shape, w.sum(-1))   # (3, 2) (3, 5) [1. 1. 1.]
```

### 8. INPUT → PROCESS → OUTPUT

```
X (T×d) ─► project ─► Q, K, V ─► Q·Kᵀ/√d_k ─► softmax ─► weights (T×S) ─► weights·V ─► output (T×d_v)
```

### 9. ENTERPRISE USE CASE

Attention is the hot loop of LLM inference; teams profile it because it dominates latency at long context. Understanding it lets you read a profiler trace, decide when to use an optimised kernel ([7.25 FlashAttention](07.25-flashattention.md)) and debug NaNs or out-of-memory errors.

### 10. AI ENGINEERING CONNECTION

Every LLM, embedding model, vision transformer and many diffusion models use attention. In RAG and agents (Tiers 17, 20, 25) "context" works because prompt tokens are attended to; context-window length, latency and cost all trace back to attention cost ([7.23 Attention complexity](07.23-attention-complexity.md), [7.24 Attention memory requirements](07.24-attention-memory-requirements.md)).

### 11. ADVANTAGES

Direct token-to-token paths; parallel across positions; content-based (not fixed-offset) mixing; one primitive reused everywhere.

### 12. LIMITATIONS

O(n²) time and (naively) memory in sequence length; no inherent notion of order (Tier 6 adds position); weights are not an explanation of model behaviour ([7.26 Attention visualization](07.26-attention-visualization.md)).

### 13. TRADE-OFFS

Global, content-based mixing and parallel training versus quadratic pairwise cost.

### 14. COMMON MISTAKES

Describing attention weights as "what the model is thinking". They are one intermediate quantity at one layer and head.

### 15. PERFORMANCE / COST CONSIDERATIONS

Cost grows with the square of sequence length; see [7.23 Attention complexity](07.23-attention-complexity.md) and [7.24 Attention memory requirements](07.24-attention-memory-requirements.md).

### 16. SECURITY CONSIDERATIONS

Attention has no privilege levels: untrusted text in the prompt is attended to exactly like trusted text, which is one architectural reason prompt injection works (later security/backend tiers; `REVIEW_REQUIRED` which tier owns it).

### 17. INTERVIEW EXPLANATION

*"Attention lets each token build its representation as a weighted average of other tokens' values, with weights from query–key similarity. It replaced the recurrent bottleneck: any two tokens interact in one step, and it parallelises across the sequence. The cost is quadratic in sequence length."*

### 18. RAPID-FIRE ANSWER

Content-based soft lookup: weights from query·key, output = weighted values.
