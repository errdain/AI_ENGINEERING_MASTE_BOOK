### 1. WHAT IS IT?

A padding mask hides `<PAD>` tokens: a key-side boolean mask of shape `(B,1,1,S)` broadcast over heads and queries.

### 2. WHY DOES IT EXIST?

Batches are rectangular, so short sequences are padded. PAD tokens carry no information; attending to them leaks noise and makes results depend on batch composition.

### 3. DETAILED EXPLANATION

`padding_mask([5, 8])` gives `True` for real tokens. `test_padding_mask_ignores_pad_tokens` writes garbage into PAD value rows and shows the output does not change.

**Fully masked rows.** A query whose every key is masked produces `softmax([−∞,…])` = NaN with true `−inf`. Left-padded sequences or windows that exclude everything can trigger this. Defences: use a large finite negative (as `lab/attention_np.py` does), or zero the output of rows you discard anyway (`test_fully_masked_row_is_finite_in_numpy`).

![Padding in the masks figure](../figures/03_attention_masks.png)

*Figure — the second panel is a padding mask (5 real tokens of 8). Set "real keys" in [the mask explorer](../interactive/mask_explorer.html).*

### 4. HOW DOES IT WORK?

1. Compute lengths per sequence.
2. `mask = arange(S) < lengths[:, None]`.
3. AND with causal; apply to scores.

### 5. SIMPLE EXAMPLE

Ignoring blank pages stapled to the end of short reports.

### 6. TECHNICAL EXAMPLE

Batched serving of requests with different prompt lengths; left-padding for generation needs matching position IDs (Tier 6).

### 7. CODE

```python
import numpy as np
from attention_np import padding_mask, scaled_dot_product_attention
rng = np.random.default_rng(0)
q, k, v = rng.normal(size=(1, 8, 4)), rng.normal(size=(1, 8, 4)), rng.normal(size=(1, 8, 4))
pm = padding_mask([5], 8)[:, None, :]                  # (1,1,8): key-side
out1, _ = scaled_dot_product_attention(q, k, v, pm)
v2 = v.copy(); v2[:, 5:] = 999                          # garbage in PAD positions
out2, _ = scaled_dot_product_attention(q, k, v2, pm)
print(np.allclose(out1, out2))                          # True: PAD values are ignored
```

### 8. INPUT → PROCESS → OUTPUT

```
lengths [5, 8] ─► bool (B×S) ─► broadcast (B,1,1,S) ─► scores masked ─► softmax
```

### 9. ENTERPRISE USE CASE

Every batched inference server handles ragged requests with padding masks or packed sequences.

### 10. AI ENGINEERING CONNECTION

Tokenizers add PAD (Tier 6); position IDs must skip PADs.

### 11. ADVANTAGES

Makes batching exact.

### 12. LIMITATIONS

Padding wastes compute; fully masked rows need care.

### 13. TRADE-OFFS

Padding (simple) versus packing/ragged tensors (efficient, more complex).

### 14. COMMON MISTAKES

Forgetting the mask at inference; left- versus right-padding mismatch; using the decoder length for encoder keys; position IDs ignoring padding.

### 15. PERFORMANCE / COST CONSIDERATIONS

Wasted FLOPs proportional to padding fraction; sort/bucket by length to reduce.

### 16. SECURITY CONSIDERATIONS

Wrong padding handling can leak or mix information across requests in a batch.

### 17. INTERVIEW EXPLANATION

*"A padding mask is a key-side mask that sets PAD positions to −∞ before softmax so padded tokens never contribute; it combines with the causal mask by AND."*
