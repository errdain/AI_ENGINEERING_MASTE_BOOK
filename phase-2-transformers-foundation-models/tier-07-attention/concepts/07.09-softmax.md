### 1. WHAT IS IT?

Softmax turns each row of scores into a probability distribution: `w_ij = exp(s_ij) / Σ_j' exp(s_ij')`.

### 2. WHY DOES IT EXIST?

Attention needs non-negative weights that sum to 1 so the output is a *weighted average*, and a smooth, differentiable way to focus on the best-matching keys.

### 3. DETAILED EXPLANATION

Properties: non-negative, sums to 1, monotone in the score, differentiable. Applied over the **key** axis (last axis). Practical points:

* **Stable form:** subtract the row max before `exp` (`softmax(x) = softmax(x − max x)`), otherwise large scores overflow (`test_softmax_rows_sum_to_one_and_stable`).
* **Temperature:** dividing scores by `T`: `T → 0` approaches argmax (one-hot), `T → ∞` approaches uniform. The `1/√d_k` factor is a fixed temperature chosen for stability ([7.8 Scaling by √dk](07.08-scaling-by-dk.md)).
* **Low precision:** softmax is usually computed in higher precision (fp32 accumulation) even when matmuls are fp16/bf16; forgetting this is a common source of NaNs.
* **Fully masked rows:** `softmax` of all `−∞` is NaN ([7.17 Padding masks](07.17-padding-masks.md)).
* **Mass must go somewhere:** weights sum to 1, so a query with nothing relevant still distributes mass (see attention sinks, [7.28 Attention sinks](07.28-attention-sinks.md)).

### 4. HOW DOES IT WORK?

1. Subtract the row max.
2. Exponentiate.
3. Divide by the row sum.

### 5. SIMPLE EXAMPLE

Turning raw judge scores into vote shares that add up to 100%.

### 6. TECHNICAL EXAMPLE

Online softmax ([7.25 FlashAttention](07.25-flashattention.md)) computes the same result tile by tile using a running max and a running sum.

### 7. CODE

```python
import numpy as np
from attention_np import softmax        # ../lab/attention_np.py
x = np.array([[1000., 1001., 999.]])   # naive exp would overflow
print(softmax(x), softmax(x).sum())    # stable
print(softmax(x / 0.1).round(3))       # low temperature: ~one-hot
```

### 8. INPUT → PROCESS → OUTPUT

```
score row (S reals) ─► −max ─► exp ─► ÷sum ─► weight row (S probs, sum = 1)
```

### 9. ENTERPRISE USE CASE

Numerical-stability audits of custom kernels; precision policies (softmax in fp32).

### 10. AI ENGINEERING CONNECTION

The same function turns LLM logits into token probabilities (Tier 11 decoding); attention softmax is over keys, output softmax is over the vocabulary.

### 11. ADVANTAGES

Smooth, differentiable, normalised.

### 12. LIMITATIONS

Cannot output exact zeros (except via masks) or "attend to nothing"; saturates at large scores; costs a row-wise reduction (memory traffic).

### 13. TRADE-OFFS

Softmax (standard) versus alternatives such as linear attention kernels or sigmoid attention (`REVIEW_REQUIRED`; Tier 12).

### 14. COMMON MISTAKES

Softmax over the wrong axis; no max-subtraction; fp16 accumulation; masking after softmax.

### 15. PERFORMANCE / COST CONSIDERATIONS

O(T·S) exps and adds; memory-bound on accelerators, which motivates [7.25 FlashAttention](07.25-flashattention.md).

### 16. SECURITY CONSIDERATIONS

None specific.

### 17. INTERVIEW EXPLANATION

*"Softmax exponentiates the scores and normalises each row so weights are positive and sum to one. It is computed with max subtraction for stability, usually in fp32, and temperature controls how peaked it is."*

### 18. RAPID-FIRE ANSWER

Row-wise exp-normalise over keys; subtract the max first.
