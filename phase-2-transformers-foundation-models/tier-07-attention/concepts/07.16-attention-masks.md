### 1. WHAT IS IT?

An attention mask specifies which (query, key) pairs are allowed. It is applied to the **scores before softmax**: forbidden entries become −∞ (or a large negative number), so their weight is exactly 0 and the rest renormalise.

### 2. WHY DOES IT EXIST?

To enforce causality, ignore padding, restrict to windows, or implement block structure, without changing the attention formula.

### 3. DETAILED EXPLANATION

* **Boolean mask:** `True = keep` (PyTorch SDPA boolean `attn_mask` convention — verify in the docs for your version, `REVIEW_REQUIRED`).
* **Additive mask:** floats added to scores (`0` or `−inf`); this is also how ALiBi-style or relative-position biases (Tier 6) enter.
* **Combining:** masks combine with logical AND (or by adding additive masks). A decoder batch needs **causal AND padding**.

![Masks](../figures/03_attention_masks.png)

*Figure — from left: causal, padding (a sequence of length 5 padded to 8), their AND, and a sliding window. Green = allowed. Combine and resize in [the mask explorer](../interactive/mask_explorer.html).*

### 4. HOW DOES IT WORK?

1. Build a boolean `(T, S)` mask (broadcast over batch/heads).
2. `scores = where(mask, scores, −large)`.
3. Softmax.

Blacking out some lines on a page before the reader chooses where to look.

### 6. TECHNICAL EXAMPLE

Mask shapes in practice: causal `(1,1,T,T)`; padding `(B,1,1,S)`; combined broadcast to `(B,H,T,S)`.

### 7. CODE

```python
import numpy as np
from attention_np import causal_mask, padding_mask, sliding_window_mask
m = causal_mask(8) & padding_mask([5], 8)[:, None, :]   # causal AND padding -> (1, 8, 8)
print(m.shape, m[0].sum())
print(sliding_window_mask(8, window=3, sinks=1).astype(int))
```

### 8. INPUT → PROCESS → OUTPUT

```
scores (T×S) + mask (T×S) ─► masked scores ─► softmax (masked weights = 0)
```

### 9. ENTERPRISE USE CASE

Batched serving needs correct masks for ragged requests.

### 10. AI ENGINEERING CONNECTION

Block-diagonal masks pack several documents into one sequence (sample packing); prefix-LM masks mix bidirectional and causal parts (`REVIEW_REQUIRED` for specific models).

### 11. ADVANTAGES

One mechanism for many constraints.

### 12. LIMITATIONS

A dense mask is T×S memory; fully masked rows give NaN ([7.17 Padding masks](07.17-padding-masks.md)).

### 13. TRADE-OFFS

Dense masks (simple) versus implicit masks computed inside kernels (memory-efficient).

### 14. COMMON MISTAKES

Masking after softmax (rows no longer sum to 1); inverted boolean polarity; wrong broadcast axes.

### 15. PERFORMANCE / COST CONSIDERATIONS

Dense mask adds T×S memory unless computed implicitly (e.g. `is_causal=True`).

### 16. SECURITY CONSIDERATIONS

A missing or wrong mask is a **data-leak** bug: batch mix-ups let one request influence another; a missing causal mask makes a model that cheats.

### 17. INTERVIEW EXPLANATION

*"Masks are applied to the scores before the softmax, setting disallowed pairs to minus infinity so their weight is exactly zero. They combine with AND."*

### 18. RAPID-FIRE ANSWER

Mask scores with −∞ before softmax; never after.
