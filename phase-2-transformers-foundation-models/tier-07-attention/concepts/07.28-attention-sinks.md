### 1. WHAT IS IT?

Attention sinks: softmax weights must sum to 1, so a query with nothing relevant still puts its mass somewhere; many trained LLMs put a large share on the first token(s) regardless of content.

### 2. WHY DOES IT EXIST?

Understanding sinks explains why naive sliding-window KV eviction collapses quality and why streaming systems keep initial tokens.

### 3. DETAILED EXPLANATION

Observed empirically (Xiao et al., StreamingLLM, 2023 — `REVIEW_REQUIRED`). If you evict the first tokens from the KV cache (e.g. with a naive sliding window), quality can collapse; keeping a few initial "sink" tokens plus a recent window (the *window + sinks* panel below) restores stable behaviour for streaming. Some work adds explicit sink tokens or per-head learnable sink logits (`REVIEW_REQUIRED`).

![Window + sinks](../figures/07_attention_patterns_window_sinks.png)

*Figure — third panel: window plus sink tokens. Toggle sinks in [the mask explorer](../interactive/mask_explorer.html).*

### 4. HOW DOES IT WORK?

1. Keep first `s` tokens in the cache permanently.
2. Keep the last `w` tokens.
3. Evict the middle.

### 5. SIMPLE EXAMPLE

A "parking spot" for attention you do not need to spend: token zero.

### 6. TECHNICAL EXAMPLE

`sliding_window_mask(t, window, sinks)` implements the pattern; `test_sliding_window_and_sinks` checks it.

### 7. CODE

```python
from attention_np import sliding_window_mask
m = sliding_window_mask(10, window=3, sinks=2)
print(m.astype(int))      # every row can see columns 0 and 1 (sinks) plus its 3 most recent keys
```

### 8. INPUT → PROCESS → OUTPUT

```
cache: [sink tokens | …evicted… | recent window] ─► attention keeps a stable sink
```

### 9. ENTERPRISE USE CASE

Long-running assistants with fixed cache budgets.

### 10. AI ENGINEERING CONNECTION

Streaming inference and KV eviction policies (Tier 11).

### 11. ADVANTAGES

Enables stable fixed-memory streaming.

### 12. LIMITATIONS

Does not give the model access to evicted facts; effect depends on the model.

### 13. TRADE-OFFS

Memory budget versus recall of old context.

### 14. COMMON MISTAKES

Evicting position 0 first; assuming sinks hold semantic information.

### 15. PERFORMANCE / COST CONSIDERATIONS

Cache bounded by `s + w`.

### 16. SECURITY CONSIDERATIONS

None specific.

### 17. INTERVIEW EXPLANATION

*"Because softmax forces weights to sum to one, models learn to park spare attention on the first token. If you slide the window and drop it, quality collapses, so streaming approaches keep a few initial tokens plus the recent window."*

### 18. RAPID-FIRE ANSWER

Sinks: first tokens absorb surplus attention mass; keep them when evicting.
