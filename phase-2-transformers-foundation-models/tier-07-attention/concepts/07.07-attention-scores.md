### 1. WHAT IS IT?

**Attention scores** are the raw (pre-softmax) similarity values `Q Kᵀ` (plus any scale or additive mask), one per (query, key) pair.

### 2. WHY DOES IT EXIST?

Scores are the intermediate quantity on which scaling, masking and softmax operate; keeping the name distinct from "weights" avoids confusing pre- and post-softmax values.

### 3. DETAILED EXPLANATION

Terminology: **scores / logits** = before softmax (any real number); **weights / probabilities** = after softmax (non-negative, rows sum to 1). Masks (additive `−∞` or large negative) act on *scores* ([7.16 Attention masks](07.16-attention-masks.md)). Additive position biases (ALiBi-style, Tier 6) also act here. Score shape is `T × S` per head: square for self-attention, rectangular for cross-attention ([7.13 Cross-attention](07.13-cross-attention.md)).

### 4. HOW DOES IT WORK?

1. `scores = Q Kᵀ`.
2. Scale ([7.8 Scaling by √dk](07.08-scaling-by-dk.md)).
3. Add mask ([7.16 Attention masks](07.16-attention-masks.md)) and optional bias.
4. Softmax ([7.9 Softmax](07.09-softmax.md)).

### 5. SIMPLE EXAMPLE

Raw judge scores before they are converted to percentages.

### 6. TECHNICAL EXAMPLE

Debugging NaNs: inspect the **scores** tensor (max/min/inf) before softmax; fp16 overflow shows up there first.

### 7. CODE

```python
import numpy as np
rng = np.random.default_rng(0)
q, k = rng.normal(size=(3, 8)), rng.normal(size=(4, 8))
scores = q @ k.T / np.sqrt(8)       # (3, 4) pre-softmax scores
print(scores.min(), scores.max())
```

### 8. INPUT → PROCESS → OUTPUT

```
Q, K ─► Q Kᵀ ─► ÷√d_k ─► + mask/bias ─► scores (T×S) ─► softmax
```

### 9. ENTERPRISE USE CASE

Monitoring score ranges is a numerical-stability check in training.

### 10. AI ENGINEERING CONNECTION

Additive biases (ALiBi, relative position) and masks are all injected here; so are attention soft-capping tricks in some models (`REVIEW_REQUIRED`).

### 11. ADVANTAGES

Single place to inject masks and biases.

### 12. LIMITATIONS

The T×S matrix is what makes attention quadratic.

### 13. TRADE-OFFS

Materialising scores (simple) versus fusing (memory-efficient, [7.25 FlashAttention](07.25-flashattention.md)).

### 14. COMMON MISTAKES

Calling post-softmax values "scores"; masking after softmax.

### 15. PERFORMANCE / COST CONSIDERATIONS

Memory for naive storage: B·H·T·S·bytes ([7.24 Attention memory requirements](07.24-attention-memory-requirements.md)).

### 16. SECURITY CONSIDERATIONS
