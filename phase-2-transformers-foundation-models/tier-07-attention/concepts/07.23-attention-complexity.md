### 1. WHAT IS IT?

Attention complexity: for sequence length `n`, head dim `d_h`, `H` heads, batch `B`, one layer needs ≈ `4·B·H·n²·d_h` FLOPs, quadratic in `n`.

### 2. WHY DOES IT EXIST?

Understanding which term grows how lets you decide whether to shorten prompts, use fused kernels, windows or GQA, and predict latency and cost.

### 3. DETAILED EXPLANATION

* `QKᵀ`: `B·H·n²·d_h` multiply-adds; `WV`: the same ⇒ ≈ **`4·B·H·n²·d_h` FLOPs** (2 FLOPs per multiply-add).
* Q/K/V/O projections: `O(n·d_model²)`, linear in `n`.
* For short sequences projections and FFN (Tier 8) dominate; at long context the `n²` term takes over (crossover around `n ≈ d_model`-scale, `REVIEW_REQUIRED` as a rule of thumb).

**Prefill versus decode.** Prefill processes all prompt tokens at once (n² work, compute-bound). Each decode step has **one** query against `n` cached keys: `O(n)` work per generated token, but dominated by reading the KV cache (memory-bound; Tier 11).

### 4. HOW DOES IT WORK?

1. Count `QKᵀ` and `WV` multiply-adds.
2. Add projection costs.
3. Compare terms as n grows.

### 5. SIMPLE EXAMPLE

Every guest at a party shaking hands with every other guest: doubling guests quadruples handshakes.

### 6. TECHNICAL EXAMPLE

Doubling the prompt from 4k to 8k multiplies the attention FLOPs by 4 but the projection/FFN FLOPs only by 2.

### 7. CODE

```python
def attn_flops(n, d_h, H, B=1):          # QK^T and WV, 2 FLOPs per multiply-add
    return 4 * B * H * n * n * d_h
for n in (1024, 2048, 4096, 8192):
    print(n, attn_flops(n, 128, 32) / 1e9, "GFLOPs/layer")   # grows 4x per doubling
```

### 8. INPUT → PROCESS → OUTPUT

```
n tokens ─► n² query-key pairs ─► ≈ 4·B·H·n²·d_h FLOPs per layer
```

### 9. ENTERPRISE USE CASE

Capacity planning, pricing per token, SLAs on time-to-first-token.

### 10. AI ENGINEERING CONNECTION

Why long-context requests are slower and costlier; motivation for GQA, flash, windows ([7.25 FlashAttention](07.25-flashattention.md), [7.30 Sliding-window attention (introduction only)](07.30-sliding-window-attention-introduction-only-full-architecture.md)).

### 11. ADVANTAGES

Understanding enables targeted optimisation.

### 12. LIMITATIONS

Quadratic term cannot be removed by exact kernels, only by approximations/restrictions.

### 13. TRADE-OFFS

Exact full attention versus windows/sparse/linear approximations (Tier 12).

### 14. COMMON MISTAKES

Believing FlashAttention removes the quadratic FLOPs; ignoring decode's memory-bound nature.

### 15. PERFORMANCE / COST CONSIDERATIONS

Prefill compute-bound, decode memory-bound.

### 16. SECURITY CONSIDERATIONS

Long inputs are a resource-exhaustion vector; enforce token limits.

### 17. INTERVIEW EXPLANATION

*"Attention cost per layer is about 4·B·H·n²·d_h FLOPs: the n² comes from every query against every key. Prefill is compute-bound; each decode step does one query against n cached keys and is memory-bound."*

### 18. RAPID-FIRE ANSWER

≈4·B·H·n²·d_h FLOPs per layer; quadratic in n.
