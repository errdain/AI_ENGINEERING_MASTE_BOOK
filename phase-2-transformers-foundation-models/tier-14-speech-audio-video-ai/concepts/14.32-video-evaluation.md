### 1. WHAT IS IT?

Video evaluation measures how well video systems work: classification accuracy, retrieval recall@K, temporal localisation IoU, captioning/QA quality (including LLM-judged), generation quality (e.g. FVD-style distribution metrics and human preference), robustness, latency and cost.

### 2. WHY DOES IT EXIST?

Video models are easy to fool with single-frame shortcuts and hard to evaluate fairly; without careful metrics you cannot tell whether temporal understanding actually improved.

### 3. DETAILED EXPLANATION

**Task metrics.**
- *Classification/action recognition:* top-1/top-5 accuracy (sensitive to the number of frames and clips averaged at test time).
- *Retrieval:* recall@K, median rank (`recall_at_k`), text-to-video and video-to-text directions.
- *Temporal grounding/detection:* temporal IoU between predicted and true intervals (`temporal_iou`), recall at IoU thresholds (0.3/0.5/0.7).
- *Shot boundary detection:* precision/recall/F1 within a tolerance of frames ([14.24](14.24-scene-shot-segmentation.md)).
- *Captioning:* n-gram metrics (BLEU/CIDEr-like) and embedding or LLM-judge metrics (`REVIEW_REQUIRED` on validity and known biases).
- *Video QA/long-video benchmarks:* multiple-choice accuracy with controls (question-only and single-frame baselines) to check temporal need (`REVIEW_REQUIRED` for benchmark names and current numbers).
- *Generation:* distribution metrics such as FVD plus human evaluation; metrics correlate imperfectly with perceived quality.

**Controls that matter.** Compare with a *single-frame* baseline, a *shuffled-frames* baseline (if order does not matter, the model is not temporal), and a *text-only* baseline (language priors). Keep sampling (fps/K) identical across systems.

**Operational metrics.** Latency, cost per minute ([14.33](14.33-audio-video-performance-and-cost-considerations.md)), failure/timeout rate, slices (video length, motion, lighting, language).

**Statistical care.** Confidence intervals, held-out data, leakage checks (web videos may be in pre-training data).

### 4. HOW DOES IT WORK?

```
predictions + ground truth ─► metric per task (acc | recall@K | IoU | F1 | judge) ─► slice by length/motion/language ─► CIs ─► gates
controls: single-frame, shuffled-frame, text-only baselines
```

### 5. SIMPLE EXAMPLE

Testing a film critic: ask about things that need the whole story (order of events), and check they don't just guess from a single still or the title.

### 6. TECHNICAL EXAMPLE

`temporal_iou((10,20),(15,30))` is 5/20 = 0.25; `recall_at_k(sim, 1)` is 1.0 when each query's best match is on the diagonal.

### 7. CODE

```python
# run inside lab/
import numpy as np
from video_core import temporal_iou, recall_at_k

print(round(temporal_iou((10, 20), (15, 30)), 3))            # 0.25
rng = np.random.default_rng(0)
sim = np.eye(5) * 0.5 + rng.random((5, 5)) * 0.4             # 5 queries, correct match on the diagonal
print(recall_at_k(sim, 1), recall_at_k(sim, 3))              # recall grows with K
```

### 8. INPUT → PROCESS → OUTPUT

```
model outputs + labels ─► task metric + controls ─► sliced report ─► confidence intervals ─► release decision
```

### 9. ENTERPRISE USE CASE

Platforms evaluate moderation recall at fixed precision per category, search relevance (recall@K) and latency, with human review of samples before launching changes.

### 10. AI ENGINEERING CONNECTION

Evaluation discipline links to model-evaluation tiers (benchmark design, slices, gates); video adds temporal controls and sampling consistency.

### 11. ADVANTAGES

Task-specific metrics are objective and cheap; controls expose shortcut learning.

### 12. LIMITATIONS

Metrics miss semantic quality; benchmark leakage; judge models are biased; generation metrics correlate weakly with human preference.

### 13. TRADE-OFFS

Automatic metrics (cheap) vs human or judge evaluation (expensive/noisy).

### 14. COMMON MISTAKES

- No single-frame or shuffled-frame baseline.
- Different sampling for different systems.
- Reporting one average without slices.
- Benchmarks contaminated by training data.

### 15. PERFORMANCE / COST CONSIDERATIONS

Evaluation compute is dominated by running models over videos; cache embeddings and frames.

### 16. SECURITY CONSIDERATIONS

Evaluation video may contain sensitive content: control access, redact, and obtain consent for human raters.

### 17. INTERVIEW EXPLANATION

*"I pick the metric to match the task: accuracy for classification, recall@K for retrieval, temporal IoU for grounding, F1 for boundaries. Then I add controls such as single-frame and shuffled-frame baselines to prove temporal understanding, keep sampling identical across systems and report slices with confidence intervals."*

### 18. RAPID-FIRE ANSWER

Task metrics (acc, recall@K, IoU, F1) plus controls proving the model uses time, reported per slice.

### 19. INTERVIEW QUESTIONS

- **Basic:** Define temporal IoU.
- **Intermediate:** Why add a shuffled-frame baseline?
- **Advanced:** Why might a video-QA benchmark be solvable from one frame?
- **Scenario:** A new video LLM improves a benchmark by 4 points. How do you decide if it is real?
