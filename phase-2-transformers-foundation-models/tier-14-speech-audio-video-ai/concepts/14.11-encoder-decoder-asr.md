### 1. WHAT IS IT?

Encoder-decoder (sequence-to-sequence) ASR uses an audio *encoder* to produce a sequence of acoustic states and a text *decoder* that generates tokens autoregressively, attending to the encoder states through cross-attention.

### 2. WHY DOES IT EXIST?

CTC frames are independent and there is no language model inside; an attention decoder conditions each token on all previous tokens *and* the audio, so it learns grammar, spelling and context together and can also do multiple tasks (translation, language ID) by changing the decoder prompt.

### 3. DETAILED EXPLANATION

**Encoder.** Convolutional subsampling of log-mel (stride 2-4 in time) followed by Transformer or Conformer layers ([Tier 8](../../tier-08-transformer-architecture/README.md)); output `[T', d]`.

**Decoder.** A causal Transformer decoder over text tokens (subwords, [Tier 6](../../tier-06-tokenization-embeddings/README.md)). Self-attention covers previous tokens; **cross-attention** uses decoder states as queries and encoder states as keys/values ([Tier 7](../../tier-07-attention/README.md) owns the attention math).

**Training.** Teacher forcing with cross-entropy on the next token. Many systems add a CTC loss on encoder outputs (hybrid CTC/attention) to help monotonic alignment (`REVIEW_REQUIRED`).

**Decoding.** Autoregressive: feed the prefix, predict the next token, repeat until an end token; use beam search and length control. Cost grows with output length; a KV cache ([Tier 11](../../tier-11-llm-inference-optimization/README.md)) avoids recomputing the prefix.

**Failure modes.** Non-monotonic attention can *skip* or *repeat* text, and the decoder can hallucinate fluent text on silence or noise; long-form audio needs chunking with context carry-over.

**Streaming.** Plain cross-attention over the full utterance is offline; streaming variants limit attention (monotonic chunkwise attention, windowed encoders) or use transducers (`REVIEW_REQUIRED`).

### 4. HOW DOES IT WORK?

```
log-mel [T,80] ─► conv subsample ─► encoder (N layers) ─► E [T',d] ──────────────┐ keys/values
  <sot> <lang> <task> t1 t2 ... ─► decoder: self-attn(causal) ─► cross-attn(E) ─► FFN ─► next-token softmax
```

### 5. SIMPLE EXAMPLE

A translator listening to a recording: the encoder is the part of the brain that listens and remembers, the decoder writes the transcript one word at a time, glancing back at the memory to check what was said.

### 6. TECHNICAL EXAMPLE

Whisper-style models are encoder-decoder Transformers; the decoder starts from special tokens (start-of-transcript, language, task, timestamp mode) and emits subword tokens until end-of-text ([14.12](14.12-whisper-as-an-asr-case-study.md)).

### 7. CODE

```python
# shape-level demo of cross-attention in PyTorch (random weights; no training)
import torch, torch.nn as nn
torch.manual_seed(0)
d, T_enc, U = 32, 100, 7                       # encoder frames, decoder tokens so far
enc = torch.randn(1, T_enc, d)                 # encoder output (keys/values)
dec = torch.randn(1, U, d)                     # decoder states (queries)
xattn = nn.MultiheadAttention(d, 4, batch_first=True)
out, w = xattn(dec, enc, enc)                  # each text token attends over audio frames
print(out.shape, w.shape)                      # torch.Size([1, 7, 32]) torch.Size([1, 7, 100])
print(torch.allclose(w.sum(-1), torch.ones(1, U), atol=1e-5))   # True: a distribution over frames
```
A full trained encoder-decoder ASR is beyond this lab's scope; the toy model uses CTC ([14.10](14.10-ctc.md)). Production use goes through libraries (**not run here, `REVIEW_REQUIRED`**).

### 8. INPUT → PROCESS → OUTPUT

```
audio features ─► encoder ─► E ─► decoder(prefix tokens, E) ─► token t_i ─► append ─► ... ─► <eot> ─► text
```

### 9. ENTERPRISE USE CASE

Offline transcription of calls, podcasts and lectures, where latency is minutes not milliseconds, is dominated by encoder-decoder models due to accuracy and multilingual flexibility.

### 10. AI ENGINEERING CONNECTION

It is the same architecture as text seq2seq models, so all Tier 7-8 tooling (attention, KV cache, beam search) applies; it also underlies speech translation and is the template for multimodal LLMs that attach an audio encoder.

### 11. ADVANTAGES

Joint acoustic and language modeling; multi-task via prompts; strong accuracy; leverages transformer tooling.

### 12. LIMITATIONS

Autoregressive latency, hallucination/repetition, non-streaming by default, quadratic attention over long audio.

### 13. TRADE-OFFS

vs CTC: accuracy and flexibility against latency and robustness to silence. vs transducer: simplicity against streaming.

### 14. COMMON MISTAKES

- Feeding audio longer than the training window without chunking.
- Trusting output on silence (hallucination).
- Greedy decoding without repetition control.
- Comparing across models without identical text normalisation.

### 15. PERFORMANCE / COST CONSIDERATIONS

Encoder cost ~ frames; decoder cost ~ output tokens x (prefix attention + cross-attention over T'). Use KV caching, batching and quantisation; chunk long audio.

### 16. SECURITY CONSIDERATIONS

Hallucinated text can look authoritative: do not auto-act on unreviewed transcripts in high-stakes contexts. Untrusted audio can carry spoken prompt-injection into downstream LLMs.

### 17. INTERVIEW EXPLANATION

*"Encoder-decoder ASR encodes the audio into a sequence of states and then a decoder writes the transcript token by token, attending to those states with cross-attention. It models language and acoustics jointly, so it is more accurate and flexible than CTC, but it is autoregressive, harder to stream and can hallucinate on silence."*

### 18. RAPID-FIRE ANSWER

Audio encoder + autoregressive text decoder with cross-attention; accurate but slower, can hallucinate.
