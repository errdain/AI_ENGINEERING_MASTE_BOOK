### 1. WHAT IS IT?

Video-language models (video LLMs) take video (and often audio) plus a text prompt and produce text: answers, captions, summaries or timestamps. Typical design: vision encoder -> projector/resampler -> LLM, with sampled frames as the visual tokens.

### 2. WHY DOES IT EXIST?

Many practical questions about video ('what happened at the end of the demo?') need language reasoning over visual events; LLMs provide reasoning and generation, vision encoders provide perception.

### 3. DETAILED EXPLANATION

**Architecture (`REVIEW_REQUIRED` per model).**
1. *Frame sampling* ([14.23](14.23-frame-sampling.md)): choose K frames or an fps.
2. *Vision encoder* (CLIP/SigLIP-style ViT, [Tier 13](../../tier-13-vision-ai/README.md)) -> patch tokens per frame.
3. *Connector:* linear/MLP projector, or a resampler (Q-Former/Perceiver-style) that compresses `S` patch tokens per frame to a few learned queries.
4. *LLM* ([Tier 8](../../tier-08-transformer-architecture/README.md)) receives `[visual tokens ... text tokens]`.
5. Optional *audio branch* ([14.7](14.07-audio-embeddings.md)) or transcript text ([14.29](14.29-audio-video-text-alignment.md)); timestamp tokens or text timestamps for temporal grounding.

**Token budget is the central constraint.** `visual tokens = frames x tokens_per_frame`. 10 minutes at 1 fps with 256 tokens per frame is 153 600 tokens (illustrative); typical context windows and cost push systems to lower fps, fewer tokens per frame (pooling), or chunked/hierarchical processing with retrieval.

**Training.** Alignment pre-training on image/video-caption pairs, then instruction tuning on video QA/dialogue; temporal reasoning data is scarcer than image data (`REVIEW_REQUIRED`).

**Failure modes.** Missing events between sampled frames, temporal-order errors, hallucinated details, over-reliance on language priors or on the transcript instead of visuals.

### 4. HOW DOES IT WORK?

```
video ─► sample K frames ─► ViT ─► [K,S,d] ─► projector/resampler ─► [K,m,d_llm] ─┐
                                                         prompt tokens ───────────┴─► LLM ─► answer / timestamps
```
Cost explorer: [explore: `video_sampling_explorer.html`](../interactive/video_sampling_explorer.html) (tokens per frame and price sliders).

### 5. SIMPLE EXAMPLE

A friend who watches 1 screenshot per second of a match and a printed commentary, then answers your questions: good overall, blind to anything quicker than a second.

### 6. TECHNICAL EXAMPLE

A product-QA assistant samples 1 fps from a 5-minute demo (300 frames), compresses each frame to 64 tokens (19 200 tokens), adds the ASR transcript and asks the LLM for a timestamped summary.

### 8. INPUT → PROCESS → OUTPUT

```
video + question ─► sample + encode + project ─► [visual tokens + text tokens] ─► LLM ─► answer (+ timestamps)
```

### 9. ENTERPRISE USE CASE

Customer-support video triage, lecture/meeting summarisation, video search assistants and compliance review.

### 10. AI ENGINEERING CONNECTION

A direct extension of multimodal LLMs: the visual tokens are inputs to an LLM ([Tier 8](../../tier-08-transformer-architecture/README.md)/[Tier 11](../../tier-11-llm-inference-optimization/README.md) for serving); retrieval ([14.29](14.29-audio-video-text-alignment.md)) reduces how much video the LLM must see.

### 11. ADVANTAGES

Flexible natural-language interface; leverages LLM reasoning; combines modalities.

### 12. LIMITATIONS

Token budget limits temporal detail; hallucination; weaker temporal reasoning than image reasoning; expensive.

### 13. TRADE-OFFS

fps vs tokens per frame vs context vs cost; end-to-end video models vs frame-captioning + text LLM cascades.

### 14. COMMON MISTAKES

- Assuming the model saw every frame.
- Ignoring audio/transcript.
- Evaluating on benchmarks answerable from a single frame.
- No timestamp grounding in the prompt.

### 15. PERFORMANCE / COST CONSIDERATIONS

Prefill cost is proportional to visual tokens; cache encoded frames; retrieve segments first for long videos.

### 16. SECURITY CONSIDERATIONS

Visual and audio prompt injection (text in frames, spoken instructions); privacy of people in video; restrict tool access from video-derived instructions.

### 17. INTERVIEW EXPLANATION

*"A video-language model samples frames, encodes them with a vision encoder, compresses them with a projector into a manageable number of tokens, and feeds those with the prompt to an LLM. The central constraint is the token budget, so fps, tokens per frame and retrieval of relevant segments are the main design levers."*

### 18. RAPID-FIRE ANSWER

Sampled frames encoded and projected into an LLM's token space; limited by token budget.
