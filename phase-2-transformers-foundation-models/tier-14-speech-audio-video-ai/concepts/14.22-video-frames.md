### 1. WHAT IS IT?

A video frame is one still image at a time index. Decoding produces frames from a compressed stream; compressed video stores keyframes (I-frames) fully and other frames (P/B) as differences, with timestamps (PTS) saying when each frame is shown.

### 2. WHY DOES IT EXIST?

Understanding how frames are stored tells you what is cheap (seeking to a keyframe) and what is expensive (decoding every frame), and why frame indices and timestamps must be handled carefully.

### 3. DETAILED EXPLANATION

**Frame properties.** Resolution `H x W`, colour space (RGB or YUV), bit depth, timestamp, frame type.

**Compression in one paragraph.** Video codecs split a stream into groups of pictures (GOPs). An I-frame is coded independently; P-frames store motion-compensated differences from earlier frames; B-frames from earlier and later frames (`REVIEW_REQUIRED` for codec specifics). To decode frame `t` you may need to decode back to the previous keyframe, so random access is cheapest near keyframes, and decoding every 30th frame still costs near a full decode unless you seek.

**Frame rate and timestamps.** Constant 24/25/30/60 fps is common but variable frame rate (VFR) exists (phone recordings), so `frame_index / fps` is *not* always the true time: use presentation timestamps.

**Preprocessing.** Resize with aspect-ratio policy (letterbox/crop), normalise with the model's mean/std, convert to `[C,H,W]` or channels-last, batch. Many pipelines use libraries such as ffmpeg/PyAV/decord/OpenCV (`REVIEW_REQUIRED` for APIs).

**Frame differences.** `|frame[t+1] - frame[t]|` highlights motion and cuts; the histogram distance used for shot detection ([14.24](14.24-scene-shot-segmentation.md)) is a more robust version.

### 4. HOW DOES IT WORK?

```
H.264 stream: I P B B P B B I ...  ──decode (needs refs)──►  frames t=0,1,2,...  (+ PTS timestamps)
```

### 5. SIMPLE EXAMPLE

Each page of a flip-book is a frame; compressed video is a flip-book where most pages say only 'same as before, but the ball moved here'.

### 6. TECHNICAL EXAMPLE

A moderation pipeline seeks to keyframes, decodes only them (cheap), runs an image classifier, then decodes dense frames only around flagged regions.

### 7. CODE

```python
# run inside lab/
import numpy as np
from video_core import synth_video

v = synth_video(90, 32, (30, 60))
diff = np.abs(np.diff(v, axis=0)).mean((1, 2))            # mean absolute frame difference
print(int(diff.argmax()) + 1, round(float(diff.max()), 3))   # biggest jump = a cut (frame 30)
print(v[0].shape, float(v.min()) >= 0, float(v.max()) <= 1)  # (32, 32) True True
```

### 8. INPUT → PROCESS → OUTPUT

```
compressed stream ─► demux ─► decode (keyframes + deltas) ─► frames + PTS ─► resize/normalise ─► tensor
```

### 9. ENTERPRISE USE CASE

Media pipelines transcode to fixed GOP structures so editors and ML jobs can seek; ad-tech samples keyframes for brand-safety checks.

### 10. AI ENGINEERING CONNECTION

Frame extraction quality (resize, colour range, timestamps) directly affects model inputs; mismatched preprocessing is the video analogue of tokenizer mismatch.

### 11. ADVANTAGES

Frames are simple tensors; keyframe seeking is cheap; frame differences are a fast motion cue.

### 12. LIMITATIONS

Decode cost, VFR timing issues, compression artefacts, colour-space mistakes.

### 13. TRADE-OFFS

Decoding every frame (accurate, expensive) vs keyframes only (fast, coarse).

### 14. COMMON MISTAKES

- Using `index / nominal_fps` as time for VFR video.
- Forgetting colour range/space conversion (washed-out frames).
- Normalising with the wrong mean/std.
- Decoding the entire file to get ten frames.

### 15. PERFORMANCE / COST CONSIDERATIONS

Decoding is often the bottleneck: use hardware decoders, seek to keyframes, decode at reduced resolution, cache extracted frames.

### 16. SECURITY CONSIDERATIONS

Media decoders are a classic attack surface (malformed files): sandbox, patch, limit resources.

### 17. INTERVIEW EXPLANATION

*"A frame is one image in time. Compressed video stores keyframes fully and the rest as differences, so you can seek cheaply to keyframes but dense decoding is expensive. I extract frames with timestamps rather than assuming constant frame rate, then resize and normalise exactly as the model expects."*

### 18. RAPID-FIRE ANSWER

One image per time step; compressed streams store keyframes plus deltas with timestamps.
