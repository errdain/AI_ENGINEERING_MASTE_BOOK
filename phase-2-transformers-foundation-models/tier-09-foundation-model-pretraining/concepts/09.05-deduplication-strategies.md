### 1. WHAT IS IT?

Removing duplicate and near-duplicate text from the training corpus at three levels: **exact** (hash), **near-duplicate** (MinHash + LSH over shingles) and **substring** (shared long passages).

### 2. WHY DOES IT EXIST?

Web data is full of copies (mirrors, boilerplate, quoted articles, licence headers, forked repositories). Duplicates (a) waste compute, (b) bias the model toward repeated text, (c) increase **memorisation** and verbatim regurgitation (published dedup studies report large reductions in memorised sequences; `REVIEW_REQUIRED` for numbers) and (d) leak evaluation data into training ([9.11](09.11-data-contamination.md)).

### 3. DETAILED EXPLANATION

| Level | Method | Catches | Scale |
|---|---|---|---|
| Exact | hash of normalised text (lab: SHA-256 of lower-cased, whitespace-collapsed text) | byte-identical mirrors | trivial |
| Near-duplicate | **MinHash + LSH** over word shingles | copies with small edits, the same article on different sites | standard at web scale |
| Substring | suffix-array / n-gram window matching | shared long passages inside different documents (licences, quoted blocks) | heavier |

**MinHash.** Turn a document into a *set of k-word shingles*. The **Jaccard similarity** of two sets is `|A∩B| / |A∪B|`. Apply `n` random hash functions and keep, for each, the *minimum* hash over the set. For one hash function `P[min(A) = min(B)] = Jaccard(A,B)` (the minimum over the union lands in the intersection exactly when the sets agree on it), so the fraction of agreeing slots between two signatures is an **unbiased estimate** of similarity using `n` numbers per document instead of thousands of shingles.

**LSH banding.** All-pairs comparison is O(n²). Split each signature into `b` bands of `r` rows (`n = b·r`); hash each band; documents colliding in **any** band become a *candidate pair*. The probability of being a candidate at similarity `s` is `1 − (1 − sʳ)ᵇ`, an S-curve whose steep part you place at your threshold by choosing `b` and `r`.

**Design decisions.** Shingle size (too small: everything looks similar; too large: one edit breaks all shingles), signature length, threshold, *which copy to keep* (lab: first; production often keeps highest-quality or most recent), dedup within and across sources, document vs paragraph level.

### 4. HOW DOES IT WORK?

1. Exact pass: normalise, hash, keep first of each hash. 2. Shingle each document (k-word windows, hashed with a **stable** hash). 3. Compute an `n`-slot MinHash signature. 4. Band the signature; bucket by band hash. 5. For candidate pairs, confirm with estimated Jaccard >= threshold. 6. Union near-duplicate pairs into clusters and keep one per cluster. 7. Record how many were dropped (provenance, [9.9](09.09-data-provenance.md)).

### 5. SIMPLE EXAMPLE

Two newspaper articles that differ by one word: a hash of the whole text says "different", but 99% of their phrases match. MinHash is a cheap fingerprint that says "nearly the same".

### 6. TECHNICAL EXAMPLE

The lab's crawl contains exact mirrors and copies where one word was replaced by "today". Exact dedup removes the former; MinHash/LSH at threshold 0.7 removes the latter while keeping genuinely distinct documents (`test_near_dedup_removes_near_copies_keeps_distinct`).

### 7. CODE

```python
# Run from lab/: MinHash estimate vs truth, then near-dedup on the synthetic crawl.
import data_prep as dp
from data_prep import shingles, minhash_signature, estimated_jaccard, jaccard, near_dedup

a = "the old sailor describes the quiet river near the hill and the pilot finds a heavy box"
b = a.replace("heavy", "light")
sa, sb = shingles(a), shingles(b)
print(jaccard(sa, sb), estimated_jaccard(minhash_signature(sa, 64), minhash_signature(sb, 64)))

docs = [{**d, "text": dp.clean_text(d["text"])} for d in dp.make_synthetic_crawl(0, 300)]
docs, n_exact = dp.exact_dedup(docs)
kept, n_near = near_dedup(docs, threshold=0.7, num_perm=64, bands=16)   # keeps first of each cluster
print(n_exact, n_near, len(kept))
```

Source: [`../lab/data_prep.py`](../lab/data_prep.py).

### 8. INPUT → PROCESS → OUTPUT

```
docs -> exact hash -> shingles -> MinHash sigs -> LSH buckets -> candidate pairs -> verify -> clusters -> keep one each
```

### 9. ENTERPRISE USE CASE

Deduplicating internal knowledge bases (many copies of the same policy, slide decks, email threads) before continued pretraining or RAG indexing, which also stops one popular document from dominating retrieval results.

### 10. AI ENGINEERING CONNECTION

Dedup is the main defence against both memorisation and benchmark leakage; the same MinHash/LSH machinery is used for near-duplicate detection in RAG corpora and for decontamination ([9.12](09.12-benchmark-contamination.md)).

### 11. ADVANTAGES

- Saves compute; reduces memorisation and regurgitation.
- MinHash makes near-duplicate detection near-linear instead of quadratic.

### 12. LIMITATIONS

- Probabilistic: misses pairs near the threshold, may link distinct documents.
- Does not catch paraphrases or translations.

### 13. TRADE-OFFS

Aggressive dedup removes genuinely repeated but useful text (a legitimately quoted poem); some repetition of high-quality data is acceptable ([9.6](09.06-data-mixture-design.md)). More hashes/bands: better recall and precision, more memory and shuffle.

### 14. COMMON MISTAKES

- Deduplicating only exact copies.
- Deduplicating train but not against eval sets.
- Unstable hashing: Python's built-in `hash()` is randomised per process; use a stable hash (the lab uses `blake2b`).
- Splitting train/validation *before* dedup so near-copies straddle the split and validation loss looks too good.

### 15. PERFORMANCE / COST CONSIDERATIONS

Signature building is embarrassingly parallel (map); candidate grouping is a shuffle by band key. At web scale this is a distributed job (Spark/Ray-style), not a Python loop. Memory is O(documents x signature length).

### 16. SECURITY CONSIDERATIONS

Dedup reduces verbatim memorisation of private text but does not remove it; scrub PII and secrets separately. An attacker can evade near-dup filters with small perturbations, so do not treat dedup as a poisoning defence.

### 17. INTERVIEW EXPLANATION

"For near-duplicate removal I shingle each document, compute MinHash signatures so the fraction of agreeing slots estimates Jaccard similarity, then use LSH banding to find candidate pairs without all-pairs comparison. Bands and rows set where the S-curve threshold sits. It matters because duplicates waste compute, increase memorisation and contaminate evals."

### 18. RAPID-FIRE ANSWER

MinHash approximates Jaccard cheaply; LSH finds likely-similar pairs without O(n²) comparison.
