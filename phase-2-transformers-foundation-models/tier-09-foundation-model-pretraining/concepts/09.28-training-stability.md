### 1. WHAT IS IT?

Keeping a long pretraining run numerically healthy: avoiding loss spikes, divergence (NaN/inf), rising gradient norms, drift off the predicted scaling curve and MoE expert collapse ([9.27](09.27-load-balancing.md)).

### 2. WHY DOES IT EXIST?

A diverged run wastes weeks of compute; an unnoticed instability can silently worsen the final model. Stability practices are cheap relative to the cost of a lost run.

### 3. DETAILED EXPLANATION

**Symptoms.** *Loss spikes* (sudden jumps, sometimes recovering, sometimes not), *divergence* (NaN/inf), a rising gradient-norm, slow drift away from the predicted scaling curve, MoE expert collapse.

**Usual causes and defences** (exact recipes vary by lab; `REVIEW_REQUIRED` for attributions):

| Cause | Defence |
|---|---|
| LR too high / no warmup | warmup then cosine/linear decay (`lr_at`), lower peak LR |
| Exploding gradients | gradient clipping by global norm (lab: 1.0) |
| Bad data batch (garbage, huge repeats) | data filtering; skip or replay-with-different-order after rolling back |
| Numerical precision (fp16 overflow) | bf16 / loss scaling; fp32 for sensitive ops (softmax, norms, router) |
| Attention/logit growth | QK-normalisation, z-loss on output logits (techniques reported in the literature) |
| Adam ε / β₂ interactions | β₂ ≈ 0.95 for large-batch LM training (lab uses it); tune ε |
| Hardware faults / silent data corruption | health checks, replay verification, auto-restart from checkpoint |

**In the lab.** `train` keeps an exponential moving average of the loss and logs a `loss_spike` event when the current loss exceeds `3x` the EMA (after warmup), and aborts with `non_finite_loss_abort` on NaN/inf; both land in `metrics.json -> history.events`. Alert on grad-norm and loss-vs-EMA, not just loss.

### 4. HOW DOES IT WORK?

Per step: (1) LR from schedule (warmup then decay); (2) forward/backward; (3) compute the global gradient norm; (4) clip to a maximum norm; (5) AdamW update; (6) update the loss EMA, flag `loss > 3 x EMA` and non-finite values; (7) on trouble: stop, inspect (grad-norm, data window, precision events), roll back to a checkpoint before the onset, change *one* thing.

### 5. SIMPLE EXAMPLE

Driving: too gentle on the accelerator and you never arrive (LR too low); floor it from a standstill and you skid (no warmup, LR too high); a speed limiter (clipping) prevents the worst skids.

### 6. TECHNICAL EXAMPLE

A 3-week run spikes at day 9. You check grad-norm history, locate the offending data window, roll back to the last checkpoint before the onset, lower the LR or skip that window, keep clipping, and confirm that restore reproduces the earlier loss exactly ([9.22](09.22-training-checkpoints.md)).

### 7. CODE

```python
# Run from lab/: clipping and the spike detector in action (a deliberately aggressive LR, ~10 s).
import tempfile
import run_lab
from model import ModelConfig
from pretrain import TrainConfig, train

tok, tr, va, _ = run_lab.prepare()
for clip in (1.0, 1e9):
    cfg = TrainConfig(steps=60, lr=3e-2, grad_clip=clip, eval_every=10**6, ckpt_every=10**6,
                      model=ModelConfig(vocab_size=tok.vocab_size))
    m = train(cfg, tr, va, tempfile.mkdtemp())
    gn = [h["grad_norm"] for h in m["history"]["train"]]
    print(f"clip={clip:g}: final loss {m['final_train_loss']:.2f}, max grad-norm {max(gn):.1f}, events {[e['event'] for e in m['history']['events']]}")
```

Source: [`../lab/pretrain.py`](../lab/pretrain.py) (`lr_at`, `train`).

### 8. INPUT → PROCESS → OUTPUT

```
loss, grad-norm, LR, data window, precision flags -> monitors (EMA spike test, NaN check) -> clip / alert / stop -> roll back to checkpoint + one change
```

### 9. ENTERPRISE USE CASE

Training platforms ship dashboards and automatic guards: alerts on grad-norm and loss-vs-EMA, auto-pause on NaN, auto-restart from validated checkpoints, and run logs that record every knob change.

### 10. AI ENGINEERING CONNECTION

The same stability tools (warmup, clipping, bf16 and norm placement) apply to fine-tuning ([Tier 10](../../tier-10-fine-tuning-alignment/README.md)), where a too-high LR causes catastrophic forgetting rather than divergence.

### 11. ADVANTAGES

- Protects weeks of compute; cheap safeguards.
- Early-warning signals (grad-norm) beat waiting for loss to explode.

### 12. LIMITATIONS

- Causes are often interacting and not fully understood; remedies are empirical.
- Clipping masks problems (a spike is capped, not cured).

### 13. TRADE-OFFS

Lower LR: safer, slower and potentially worse final loss. More clipping/regularisation: stable, may slow learning. Skipping data windows: avoids spikes, changes the data distribution.

### 14. COMMON MISTAKES

- Restarting from the *last* checkpoint when the bad region began earlier.
- Changing several knobs after a spike so the cause is lost.
- Watching only the average loss.
- Mistaking a curriculum boundary ([9.13](09.13-data-curriculum.md)) for instability.

### 15. PERFORMANCE / COST CONSIDERATIONS

Monitoring is nearly free; rollbacks cost the work since the checkpoint (frequency trade-off, [9.22](09.22-training-checkpoints.md)). bf16 gives speed and range; fp16 needs loss scaling.

### 16. SECURITY CONSIDERATIONS

Instabilities can be induced by poisoned data (spiky batches); log the data window with each spike. Silent data corruption on hardware is a rare but real cause (`REVIEW_REQUIRED`); health checks and replay verification help.

### 17. INTERVIEW EXPLANATION

"Loss spiked at step 40k — I'd stop and inspect: grad-norm history, the data window, any precision events. Then roll back to a checkpoint before the onset, lower the LR or skip the offending data, make sure clipping and norm safeguards are on, and change one thing at a time. Prevention is warmup, clipping, bf16 with fp32 for sensitive ops, and alerting on grad-norm, not just loss."

### 18. RAPID-FIRE ANSWER

Warmup, clipping, careful precision, monitoring grad-norm and loss-vs-EMA, and rollback to a checkpoint before the onset.
