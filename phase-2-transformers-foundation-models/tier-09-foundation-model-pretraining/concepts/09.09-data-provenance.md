### 1. WHAT IS IT?

A durable record of where each document came from and what was done to it: source, URL/ID, retrieval date, license, pipeline version and filter decisions.

### 2. WHY DOES IT EXIST?

It lets you answer "which documents taught the model X?", honour deletion/opt-out requests, reproduce a dataset, and debug regressions ("the new crawl made code worse").

### 3. DETAILED EXPLANATION

Provenance has three layers: **record-level** metadata (source, license, URL, date), **pipeline-level** lineage (which stages ran, versions, per-stage counts and drop reasons) and **artifact-level** links (checkpoint -> dataset version -> pipeline commit). Without the third layer a metrics file cannot be tied to the exact data that produced it.

In the lab each document dict carries `source`, `license`, `url`; the pipeline `report` records per-stage counts and drop reasons; training stores `train_fingerprint` (SHA-256 of the token stream) in `metrics.json`.

![Funnel](../figures/01_data_pipeline_funnel.png)

*Figure 1 — The funnel is the pipeline-level provenance record: counts and reasons per stage, in the same order the pipeline ran.*

### 4. HOW DOES IT WORK?

1. Attach metadata at acquisition. 2. Never drop it during cleaning. 3. Each stage records `(name, count_in, count_out, reason)`. 4. Fingerprint the final token stream. 5. Store a manifest `checkpoint -> dataset version -> pipeline commit -> config`.

### 5. SIMPLE EXAMPLE

A museum catalogue entry: where the object came from, when, under what terms, and every restoration done since.

### 6. TECHNICAL EXAMPLE

A takedown request arrives for a domain. With record-level provenance you list affected documents, see which dataset versions and checkpoints used them, and plan a re-train or mitigation; without it you cannot even say whether the data was used.

### 7. CODE

```python
# Run from lab/: provenance artefacts the lab produces.
import run_lab

tok, tr, va, report = run_lab.prepare()
print(report["stages"])                 # per-stage counts
print(report["dropped"])                # per-stage drop reasons
print(report["train_fingerprint"])      # ties results to the exact token stream
```

### 8. INPUT → PROCESS → OUTPUT

```
documents + metadata -> pipeline stages log (count, reason) -> fingerprint -> manifest linking checkpoint, data, code
```

### 9. ENTERPRISE USE CASE

Data lineage tooling, immutable dataset versions, a dataset card/datasheet per release, and an audit trail answering regulators and customers ("was my data used?").

### 10. AI ENGINEERING CONNECTION

The same lineage ideas apply to RAG indexes and fine-tuning sets; model cards and evaluation reports are only trustworthy if tied to data versions.

### 11. ADVANTAGES

- Enables audits, deletions and reproduction.
- Makes data regressions debuggable.

### 12. LIMITATIONS

- Cannot remove data already baked into weights (it only tells you what went in).
- Metadata can be wrong or missing at the source.

### 13. TRADE-OFFS

Rich per-record metadata costs storage and engineering effort; minimal metadata is cheap but leaves you unable to comply or debug.

### 14. COMMON MISTAKES

- Dropping metadata during cleaning or tokenization.
- Mutating a dataset in place instead of versioning it.
- No link between a trained checkpoint and the dataset version.

### 15. PERFORMANCE / COST CONSIDERATIONS

Metadata and lineage logs are small relative to text; the real cost is process discipline. Fingerprints are cheap (a hash over the final stream).

### 16. SECURITY CONSIDERATIONS

Provenance lets you trace and purge poisoned sources, and sign datasets so tampering is detectable. Protect the manifest itself (it may reveal confidential sources).

### 17. INTERVIEW EXPLANATION

"Provenance is a record of where each document came from and what the pipeline did to it, plus a manifest tying checkpoint to dataset version to code commit. It's what lets me answer deletion requests, reproduce results and debug data regressions — if you can't trace it, you can't remove it."

### 18. RAPID-FIRE ANSWER

Per-document source/license metadata plus pipeline lineage and a checkpoint-to-dataset manifest.
