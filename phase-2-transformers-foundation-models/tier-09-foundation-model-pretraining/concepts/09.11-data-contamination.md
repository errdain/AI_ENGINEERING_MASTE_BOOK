### 1. WHAT IS IT?

Any unwanted overlap between training data and data that should stay held out: validation sets, test sets, or user data that must not be memorised. It also covers unintentionally training on your own model's earlier outputs.

### 2. WHY DOES IT EXIST?

(As a problem, not a feature.) Web-scale corpora contain copies of almost everything, so held-out data leaks in unless you deliberately prevent it. Consequences: inflated metrics, hidden memorisation and privacy leakage.

### 3. DETAILED EXPLANATION

Leak routes: (1) near-copies straddling a random train/validation split; (2) public test sets re-posted on the web ([9.12](09.12-benchmark-contamination.md)); (3) validation data built from the same crawl without dedup against training; (4) model-generated text re-crawled into later training sets; (5) user data that should be excluded. The remedy is layered: dedup *then* split, decontaminate against known held-out sets, and keep truly private held-out sets that were never published.

### 4. HOW DOES IT WORK?

1. Deduplicate the corpus. 2. Split train/validation by **document hash** ([9.31](09.31-pretraining-evaluation.md)). 3. Compute n-gram overlap of training docs against held-out sets. 4. Remove or flag matches. 5. Report contamination rate before and after.

### 5. SIMPLE EXAMPLE

A student who sees the exam questions in the textbook's practice section: a high mark proves memory, not understanding.

### 6. TECHNICAL EXAMPLE

In the lab a benchmark sentence is leaked into the crawl; `contamination_before = 1.0` and after the pipeline `contamination_after = 0.0` (`test_pipeline_funnel_monotonic_and_removes_leak`).

### 7. CODE

```python
# Run from lab/: measure and remove overlap with a held-out text.
import data_prep as dp
from run_lab import BENCH

train = [{"text": BENCH[0] + " " + BENCH[0]}, {"text": "an unrelated document about the cat and the garden near the hill"}]
print(dp.contamination_rate(train, BENCH, n=8))        # fraction of held-out items found in training data
clean, removed = dp.decontaminate(train, BENCH)
print(removed, len(clean))
```

### 8. INPUT → PROCESS → OUTPUT

```
train docs + held-out texts -> n-gram sets -> overlap test -> removed docs + contamination rate before/after
```

### 9. ENTERPRISE USE CASE

Keeping a private evaluation set (customer-representative queries) strictly out of any fine-tuning or pretraining data, with an automated overlap check in CI.

### 10. AI ENGINEERING CONNECTION

Contamination undermines every evaluation of an LLM, including those used in RAG and agent systems; it is also why "model-collapse"-style feedback loops (training on generated text) need provenance tags (`REVIEW_REQUIRED` for quantified claims).

### 11. ADVANTAGES

(Of decontamination.) Honest metrics, less memorisation, fewer privacy surprises, trustworthy comparisons between runs.

### 12. LIMITATIONS

- n-gram matching misses paraphrases and translations.
- You can only decontaminate against sets you know about.

### 13. TRADE-OFFS

Strict overlap thresholds remove more legitimate text that merely shares common phrases; loose ones leave leaks. Larger n gives fewer false positives but misses short overlaps.

### 14. COMMON MISTAKES

- Splitting train/validation before dedup.
- Decontaminating after tuning hyper-parameters on the same set.
- Forgetting that held-out data may be re-posted in blogs, forums and repositories.

### 15. PERFORMANCE / COST CONSIDERATIONS

n-gram hashing of the corpus against a held-out index is a streaming job linear in corpus size; keep the held-out n-gram index in memory/Bloom filter form.

### 16. SECURITY CONSIDERATIONS

Contamination with private or customer data is a privacy leak (memorised text can be extracted). Keep held-out and private sets in access-controlled stores, excluded by construction from training pipelines.

### 17. INTERVIEW EXPLANATION

"Contamination is any overlap between training data and data that should be held out. At web scale it happens by default, so I dedup before splitting, decontaminate against known held-out sets with n-gram overlap, keep some private never-published sets, and report results on clean vs possibly-contaminated subsets."

### 18. RAPID-FIRE ANSWER

Unwanted train/held-out overlap that inflates metrics and hides memorisation; prevent with dedup-then-split and n-gram decontamination.
