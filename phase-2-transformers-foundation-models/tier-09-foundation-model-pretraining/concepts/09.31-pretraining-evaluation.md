### 1. WHAT IS IT?

What to measure while a pretraining run is alive and when it ends: validation loss/perplexity, per-domain and per-language loss, bits-per-byte, downstream few-shot benchmarks, run-health signals and memorisation probes. *Evaluation as a discipline (datasets, LLM-as-judge, metrics) is owned by Tier 15 and later; here only the pretraining-specific signals.*

### 2. WHY DOES IT EXIST?

A multi-week run needs early, low-noise signals that it is learning, generalising and not regressing in some domain; benchmark accuracy is too noisy and too late for that.

### 3. DETAILED EXPLANATION

| Signal | What it tells you | Watch out |
|---|---|---|
| Training loss | optimisation health | not generalisation |
| **Held-out validation loss / perplexity** | generalisation on the *training distribution* (`evaluate` in the lab; `val_ppl` in metrics) | must be deduped against train ([9.5](09.05-deduplication-strategies.md)) |
| **Per-domain / per-language loss** | hidden regressions ([9.8](09.08-domain-balancing.md)) | needs domain-tagged val sets |
| **Bits per byte** (`loss_nats x tokens / (bytes x ln 2)`) | tokenizer-independent, so comparable across tokenizers | compute on the same text |
| Downstream benchmark suites (few-shot) | capability proxies | contamination ([9.12](09.12-benchmark-contamination.md)); noisy at small scale |
| Gradient norm, LR, throughput (MFU), MoE load | run health | alert thresholds |
| Memorisation / regurgitation probes | privacy and copyright risk | needs designed probes |

Early in training, loss is a better and less noisy signal than benchmark accuracy; small models often score at chance on hard benchmarks, so use loss and "emergence-friendly" metrics (`REVIEW_REQUIRED`).

**Lab check.** `metrics.json -> history.eval` holds `val_loss` and `val_ppl` at every `eval_every` steps; the validation split is chosen by *document hash* so a document can never be on both sides (`test_split_is_stable_and_disjoint`). The toy validation set is templated text, so a perplexity near 2-3 says nothing about real language modelling.

### 4. HOW DOES IT WORK?

1. Build validation sets *after* dedup, split by document hash, tagged by domain and language. 2. Every `eval_every` steps compute loss/perplexity overall and per tag. 3. Convert to bits-per-byte when comparing across tokenizers. 4. Log health signals (grad-norm, MFU, expert load). 5. Run benchmark suites at intervals on decontaminated sets. 6. Compare to the predicted scaling curve and alert on deviations.

### 5. SIMPLE EXAMPLE

A student's weekly quizzes (validation loss) tell you far sooner and more reliably than the final exam (benchmarks) whether study is working.

### 6. TECHNICAL EXAMPLE

Two runs with different tokenizers have validation losses 2.9 and 3.3 nats per token. Converting to bits-per-byte with each run's tokens-per-byte shows which model actually compresses the same text better.

### 7. CODE

```python
# Run from lab/: validation loss, perplexity and bits-per-byte (tokenizer-independent) for a trained lab model.
import math, tempfile
import run_lab
from model import ModelConfig
from pretrain import TrainConfig, train

tok, tr, va, rep = run_lab.prepare()
cfg = TrainConfig(steps=30, eval_every=30, ckpt_every=30, model=ModelConfig(vocab_size=tok.vocab_size))
m = train(cfg, tr, va, tempfile.mkdtemp())
ev = m["final_val"]
n_bytes = len(tok.decode(va.tolist()).encode("utf-8"))             # bytes of the validation text
bpb = ev["val_loss"] * len(va) / (n_bytes * math.log(2))
print(f"val_loss {ev['val_loss']:.3f}  ppl {ev['val_ppl']:.2f}  tokens {len(va)}  bytes {n_bytes}  bits/byte {bpb:.3f}")
```

Source: [`../lab/pretrain.py`](../lab/pretrain.py) (`evaluate`), [`../lab/data_prep.py`](../lab/data_prep.py) (`split_train_val`).

### 8. INPUT → PROCESS → OUTPUT

```
held-out sets (per domain/language) + checkpoints -> loss, perplexity, bits/byte, benchmarks, health signals -> dashboard + alerts + go/no-go
```

### 9. ENTERPRISE USE CASE

Release gates for a custom base model: per-domain validation loss must not regress beyond a threshold, privacy probes pass, decontaminated benchmark results meet targets, and the model card records evaluation data versions.

### 10. AI ENGINEERING CONNECTION

Pretraining metrics predict, but do not equal, downstream quality; they feed fine-tuning decisions ([Tier 10](../../tier-10-fine-tuning-alignment/README.md)) and are complemented by task and safety evaluation (Tier 15 and Tier 30).

### 11. ADVANTAGES

- Loss is smooth, cheap and early; per-domain slices expose regressions.
- Bits-per-byte allows fair comparison across tokenizers.

### 12. LIMITATIONS

- Loss is not capability or helpfulness.
- Validation sets can leak (dedup/contamination) or be unrepresentative.

### 13. TRADE-OFFS

Frequent evaluation gives finer feedback but costs compute; broad benchmark suites are informative but noisy and contamination-prone; per-domain sets cost curation effort.

### 14. COMMON MISTAKES

- Validation not deduped against training, so loss looks too good.
- Comparing losses across tokenizers.
- Relying on a single benchmark number.
- Ignoring per-domain regressions behind a good average.

### 15. PERFORMANCE / COST CONSIDERATIONS

Evaluation on a few hundred thousand tokens every few hundred steps is a small fraction of training cost; full benchmark suites are run at coarser intervals on saved checkpoints.

### 16. SECURITY CONSIDERATIONS

Memorisation probes (extraction attempts, canary strings, membership-inference tests) measure privacy and copyright risk; keep evaluation data access-controlled so it does not leak into training.

### 17. INTERVIEW EXPLANATION

"Early in a run I trust clean held-out validation loss more than benchmark scores: it's smooth and cheap. I'd track it per domain and language, make sure the validation set is deduped against training, and use bits-per-byte when comparing across tokenizers. I'd add run-health signals like grad-norm and MFU, benchmark suites on decontaminated sets at intervals, and memorisation probes before release."

### 18. RAPID-FIRE ANSWER

Clean held-out loss (overall and per domain), bits-per-byte across tokenizers, health signals and decontaminated benchmarks.
