### 1. WHAT IS IT?

Automatic Speech Recognition (ASR, speech-to-text) maps an audio signal to a word (or character/subword) sequence. Modern ASR is a neural network: audio features go into an encoder, and either a CTC head, a transducer or a decoder produces text.

### 2. WHY DOES IT EXIST?

Voice is the natural interface, and transcripts unlock search, analytics, captions, accessibility and LLM pipelines. Hand-built pipelines (acoustic model + pronunciation lexicon + language model) were replaced by end-to-end networks that learn the whole mapping.

### 3. DETAILED EXPLANATION

**Problem shape.** Input `T` frames (100/s), output `U` tokens (about 2-3 words per second); `T >> U` and the alignment between them is *unknown*. Everything in ASR design is about handling that unknown monotonic alignment.

**Three modern families.**
1. *CTC* ([14.10](14.10-ctc.md)): per-frame label posteriors with a blank symbol; fast, non-autoregressive, streaming-friendly, conditional independence between frames.
2. *Attention encoder-decoder* ([14.11](14.11-encoder-decoder-asr.md), Whisper-style, [14.12](14.12-whisper-as-an-asr-case-study.md)): decoder attends to encoder states; strong accuracy and multi-task, but autoregressive and can hallucinate.
3. *Transducer (RNN-T)*: joint network combining acoustic and label history; the usual choice for on-device streaming (`REVIEW_REQUIRED` for current industry practice).

**Classical pipeline for context.** Features -> GMM/HMM or DNN/HMM acoustic model -> pronunciation lexicon -> n-gram LM -> WFST decoding. Still instructive: an external language model can rescore end-to-end hypotheses (shallow fusion).

**Output units.** Characters (tiny vocabulary, our toy uses 6 symbols), subwords (BPE/SentencePiece, [Tier 6](../tier-06-tokenization-embeddings/README.md)), or words.

**Metrics.** Word error rate (WER) and character error rate (CER), [14.20](14.20-audio-evaluation.md); latency/RTF for streaming ([14.18](14.18-streaming-speech.md)).

**Our lab model.** `FramewiseCTC`: Conv1d -> BiGRU -> linear over log-mel frames, trained with CTC loss on synthetic phoneme tones. After 30 epochs on 200 utterances, the lab run reports CER about 5% and RTF about 0.004 on 60 held-out utterances (`python lab/lab_demo.py`; numbers vary by seed/hardware and are of a *toy* task, not real speech).

### 4. HOW DOES IT WORK?

```
audio ─► log-mel [T,80] ─► encoder ─┬─► CTC head ─► per-frame labels ─► collapse ─► text
                                    ├─► decoder (cross-attention) ─► tokens, one at a time ─► text
                                    └─► transducer joint ─► labels while streaming ─► text
```

### 5. SIMPLE EXAMPLE

A court stenographer converts a continuous stream of speech into written words without ever being told exactly where each word starts.

### 6. TECHNICAL EXAMPLE

A meeting-transcription product chunks audio with VAD ([14.13](14.13-speech-segmentation.md)), runs an encoder-decoder ASR per chunk, merges overlaps, aligns timestamps ([14.15](14.15-timestamps-alignment.md)), runs diarization ([14.14](14.14-speaker-diarization.md)), and measures WER against a human-corrected sample.

### 7. CODE

```python
# run inside lab/ (about 12 s on 2 CPU threads): train the toy CTC recogniser, then decode
import torch; torch.set_num_threads(2)
from ctc_asr import FramewiseCTC, make_dataset, train, transcribe
from audio_core import cer

tr, te = make_dataset(200, seed=1), make_dataset(30, seed=2)
model = FramewiseCTC()
losses = train(model, tr, epochs=24)
feats, text, wav, _ = te[0]
print(text, "->", transcribe(model, feats), "| loss", round(losses[0], 1), "->", round(losses[-1], 2))
errs = [cer(t, transcribe(model, f)) for f, t, *_ in te]
print("mean CER", round(sum(errs) / len(errs), 3))      # small, task is synthetic
```

### 8. INPUT → PROCESS → OUTPUT

```
speech waveform ─► features ─► neural model ─► (labels | tokens) ─► decode ─► text ─► (punctuation, timestamps, speakers)
```

### 9. ENTERPRISE USE CASE

Contact centres, medical dictation, subtitling and meeting assistants run ASR at scale, usually with domain vocabulary boosting, PII redaction after transcription and human review for regulated content.

### 10. AI ENGINEERING CONNECTION

ASR is the 'ears' of voice agents and the first stage of cascaded speech systems ([14.19](14.19-realtime-speech-systems.md)); its transcripts feed LLMs and RAG ([14.29](14.29-audio-video-text-alignment.md)). Errors propagate: a mis-heard product name becomes a wrong answer.

### 11. ADVANTAGES

Hands-free input, accessibility, searchable audio, strong accuracy on clean speech with large models.

### 12. LIMITATIONS

Accents, noise, overlapping speech, domain terms and low-resource languages degrade accuracy; autoregressive decoders can hallucinate; WER hides which errors matter.

### 13. TRADE-OFFS

Accuracy vs latency vs cost: bigger encoder-decoder is more accurate but slower; CTC/transducer streams faster; on-device vs cloud privacy vs quality.

### 14. COMMON MISTAKES

- Reporting one WER without text normalisation rules.
- Evaluating on clean data only.
- Ignoring entity/number errors (they matter more than function words).
- Not measuring latency and RTF.
- Assuming the language is known.

### 15. PERFORMANCE / COST CONSIDERATIONS

Cost = audio minutes x model cost. Encoder FLOPs scale with frames, so hop and stride matter; batch offline jobs, stream online ones. Real-time factor (RTF) = processing time / audio time must stay below 1 with headroom.

### 16. SECURITY CONSIDERATIONS

Recordings are sensitive (consent laws, PII, health data): redact transcripts, restrict access, set retention. Prompt-injection can arrive through spoken content that an LLM later reads. Adversarial audio can force target transcripts (`REVIEW_REQUIRED`).

### 17. INTERVIEW EXPLANATION

*"ASR maps audio to text. The hard part is that audio frames far outnumber output tokens and the alignment is unknown, so we use CTC, attention encoder-decoders or transducers. CTC is fast and streams; encoder-decoder models like Whisper are more accurate and flexible but autoregressive. I would evaluate with WER on normalised text across accents and noise, and track latency separately."*

### 18. RAPID-FIRE ANSWER

Neural speech-to-text; encoder over audio features with CTC, attention-decoder or transducer output.
