### 1. WHAT IS IT?

Text-to-Speech (TTS) converts text into a speech waveform. Modern neural TTS typically has stages: text normalisation and phonemisation, an acoustic model that predicts mel-spectrogram (or codec tokens) with prosody and duration, and a vocoder ([14.17](14.17-vocoders.md)) that turns that into audio.

### 2. WHY DOES IT EXIST?

Voice interfaces, accessibility, audiobooks, dubbing and assistants need natural, controllable speech. Concatenating recorded units sounded robotic; neural models generate smooth, expressive audio.

### 3. DETAILED EXPLANATION

**Pipeline (two-stage, classic neural).**
1. *Text front-end:* normalise numbers, dates, abbreviations ('Dr.' -> 'Doctor'); convert graphemes to phonemes (G2P).
2. *Acoustic model:* predicts the mel-spectrogram. Autoregressive models (Tacotron 2-style, with attention) are natural but can skip/repeat words; non-autoregressive models (FastSpeech-style) predict phoneme **durations** explicitly, expand phoneme states to frames (a *length regulator*), and generate all frames in parallel (`REVIEW_REQUIRED` for the specifics of each system).
3. *Vocoder:* mel -> waveform ([14.17](14.17-vocoders.md)).

**End-to-end and codec-LM TTS.** VITS-style models fold acoustic model and vocoder into one network; codec language models predict neural-codec tokens ([14.8](14.08-audio-tokenization-and-neural-codecs.md)) with a decoder-only transformer conditioned on text and a short voice prompt (the VALL-E line, `REVIEW_REQUIRED`); diffusion/flow models are another family.

**What must be controlled.** Duration, pitch, energy (prosody), speaker identity (speaker embedding or prompt), style/emotion, streaming latency (time to first audio, [14.18](14.18-streaming-speech.md)).

**Evaluation.** Intelligibility (ASR-WER on the synthesised audio), naturalness (MOS listening tests or predicted MOS), speaker similarity, latency and RTF ([14.20](14.20-audio-evaluation.md)).

**Toy 'TTS' in the lab.** `synth_utterance(text)` is a rule-based synthesiser: each symbol maps to a two-tone burst with a random duration, separated by gaps; it demonstrates the text -> duration expansion -> waveform structure, and the CTC recogniser can transcribe it back (a *TTS-to-ASR round trip*, a common intelligibility check).

### 4. HOW DOES IT WORK?

```
text ─► normalise ─► phonemes ─► [acoustic model: durations + pitch + energy] ─► mel [T,80] ─► vocoder ─► waveform
                                       ▲ speaker embedding / style prompt
```

### 5. SIMPLE EXAMPLE

A reader who first turns the page into a score (what notes, how long, how loud) and then plays the score on an instrument (the vocoder).

### 6. TECHNICAL EXAMPLE

The lab's synthesiser draws the duration of each symbol (7-12 frames) and inserts 2-3 frame gaps; a non-autoregressive TTS does the same with *learned* durations and learned spectral shapes.

### 7. CODE

```python
# run inside lab/ -- rule-based 'text -> speech' and the round-trip idea
import numpy as np
from ctc_asr import synth_utterance, SR, HOP

rng = np.random.default_rng(0)
wave, frame_labels = synth_utterance("abc", rng)
print(len(wave) / SR, "seconds;", len(frame_labels), "frames; labels:", sorted(set(frame_labels.tolist())))
# the duration of each symbol, in frames (what a duration model predicts):
runs = [(int(l), int(n)) for l, n in zip(*np.unique(frame_labels[frame_labels > 0], return_counts=True))]
print(runs)
```

### 9. ENTERPRISE USE CASE

Contact centres use TTS for IVR and agent replies; media firms localise voices; accessibility tools read screens. Enterprises add pronunciation dictionaries (brand and drug names), SSML control, voice licensing and watermarking.

### 10. AI ENGINEERING CONNECTION

TTS is the 'mouth' of voice agents ([14.19](14.19-realtime-speech-systems.md)). LLM output is streamed into TTS sentence by sentence to reduce time-to-first-audio, so TTS latency and chunking affect the whole agent.

### 11. ADVANTAGES

Scalable, controllable, multilingual; natural quality with modern vocoders; voices can be adapted from small samples.

### 12. LIMITATIONS

Prosody errors, mispronunciations of rare words, hallucinated words in autoregressive models, voice-cloning misuse risk, expensive training data.

### 13. TRADE-OFFS

Autoregressive/codec-LM: expressive but slower and can hallucinate; non-autoregressive: fast and stable but flatter prosody; bigger vocoders: quality vs latency.

### 14. COMMON MISTAKES

- Skipping text normalisation (numbers read wrong).
- Synthesising a whole paragraph before playback.
- Clipping or inconsistent loudness between sentences.
- Cloning voices without consent.

### 15. PERFORMANCE / COST CONSIDERATIONS

Latency components: text processing, acoustic model time-to-first-frame, vocoder RTF, network. Stream sentence/phrase chunks; cache common phrases.

### 16. SECURITY CONSIDERATIONS

High-quality TTS enables fraud (voice cloning scams) and impersonation: require consent and verification for custom voices, add watermarking/provenance, rate-limit and log (`REVIEW_REQUIRED` legal/regulatory). Sanitize SSML/text input.

### 17. INTERVIEW EXPLANATION

*"TTS turns text into speech in stages: normalise text and get phonemes, predict a spectrogram with durations and prosody, then vocode to a waveform; newer systems model codec tokens with a language model. I care about intelligibility, naturalness, speaker similarity and time-to-first-audio, and I treat voice cloning as a security and consent issue."*

### 18. RAPID-FIRE ANSWER

Text to phonemes to acoustic features (mel or codec tokens) to waveform via a vocoder.
