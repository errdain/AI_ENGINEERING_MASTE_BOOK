### 1. WHAT IS IT?

Temporal representation is how a model encodes *time* in video: spatio-temporal patches (tubelets), 3-D convolutions, frame differences/optical flow, temporal positional encodings, and token pooling across frames.

### 2. WHY DOES IT EXIST?

A bag of per-frame features forgets order and motion ('door opened' vs 'door closed' look the same as sets of frames). The representation must carry order and change while keeping the token count manageable.

### 3. DETAILED EXPLANATION

**Options.**
- *Per-frame features + temporal model:* an image encoder per frame, then a transformer/GRU over frame embeddings (cheap, reuses [Tier 13](../tier-13-vision-ai/README.md) encoders).
- *Tubelets (ViViT-style):* patches that extend over `t` frames: a `2 x 8 x 8` tubelet of a clip becomes one token; `patchify_video` implements this; token count `= (T/t) x (H/p) x (W/p)` (`REVIEW_REQUIRED` for specific model details).
- *3-D convolutions* (C3D, I3D, SlowFast two-pathway) learn local motion; *two-stream* networks add optical flow explicitly.
- *Frame differences* as cheap motion cues.
- *Temporal positional information:* learned or sinusoidal time embeddings, or rotary/relative encodings extended to the time axis, as in [Tier 6](../tier-06-tokenization-embeddings/README.md).
- *Token reduction:* pool across time, merge similar tokens, or select keyframes to cut tokens.

**Audio time axis.** Our audio features have 100 frames/s; video 1-30 frames/s: aligning the two axes is [14.30](14.30-multimodal-synchronization.md).

**Trade-off.** Larger tubelets reduce tokens but blur fast motion; smaller keep detail at higher cost.

### 4. HOW DOES IT WORK?

```
video [T,H,W] ─► tubelets (t x p x p) ─► flatten ─► linear embed ─► + (space, time) position ─► tokens [N, d]
N = (T/t) * (H/p) * (W/p)
```

### 5. SIMPLE EXAMPLE

Reading a comic strip: a panel shows an instant (spatial); arrows and the order of panels give the story (temporal). Tubelets are like cutting the strip into little blocks that span two panels.

### 6. TECHNICAL EXAMPLE

`patchify_video(v[:16], tubelet=2, patch=8)` of a 16x32x32 clip gives `(16/2) x 16 = 128` tokens of dimension `2x8x8=128`.

### 7. CODE

```python
# run inside lab/
from video_core import synth_video, patchify_video, video_token_count

v = synth_video(16, 32, shots=())
tokens = patchify_video(v, tubelet=2, patch=8)
print(tokens.shape)                              # (128, 128)
print(video_token_count(16, 32, 8, tubelet=2))   # 128 = (16/2) * (32/8)**2
print(video_token_count(16, 32, 8, tubelet=1))   # 256: smaller tubelet, 2x tokens
```
Code: [`lab/video_core.py`](lab/video_core.py) | tests: `test_tubelets_and_token_counts`.

### 8. INPUT → PROCESS → OUTPUT

```
frames ─► spatio-temporal patching ─► token embeddings + time/space position ─► transformer ─► video features
```

### 9. ENTERPRISE USE CASE

Sports analytics and surveillance pick temporal resolution per use: high frame rate for fast actions, low for scene-level descriptions.

### 10. AI ENGINEERING CONNECTION

Determines the token sequence a transformer ([Tier 8](../tier-08-transformer-architecture/README.md)) processes; the attention pattern over it is [14.26](14.26-temporal-attention.md).

### 11. ADVANTAGES

Captures motion and order; flexible token budget through tubelet size.

### 12. LIMITATIONS

More tokens, more compute; designed time resolution is fixed; per-frame models miss motion.

### 13. TRADE-OFFS

Tubelet size vs speed vs motion detail; per-frame reuse vs end-to-end video pretraining.

### 14. COMMON MISTAKES

- Dropping temporal position information.
- Shuffling frames in augmentation without intending to.
- Pooling over time too early (losing order).
- Mismatched tubelet configuration with pretrained weights.

### 15. PERFORMANCE / COST CONSIDERATIONS

Token count drives attention cost quadratically; halving frames or doubling tubelet size cuts it by 2-4x.

### 16. SECURITY CONSIDERATIONS

Nothing specific beyond video privacy; fewer tokens can hide small adversarial patches differently: evaluate robustness.

### 17. INTERVIEW EXPLANATION

*"Temporal representation is how the model sees time: I can run an image encoder per frame and model order on top, use tubelets that span a few frames per token, or use 3-D convolutions or flow. I always add time position information and count tokens, since the token count drives attention cost."*

### 18. RAPID-FIRE ANSWER

Spatio-temporal tokens (tubelets, 3-D conv, flow) with time position encodings.
