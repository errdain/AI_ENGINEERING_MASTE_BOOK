### 1. WHAT IS IT?

Audio evaluation measures how well speech/audio systems perform: recognition accuracy (WER/CER), diarization (DER), TTS quality (MOS, intelligibility, speaker similarity), codec/vocoder fidelity, latency and cost (RTF), robustness across conditions.

### 2. WHY DOES IT EXIST?

Unmeasured speech systems fail quietly on accents, noise and domain vocabulary. A single clean-set WER hides what matters in production.

### 3. DETAILED EXPLANATION

**WER.** `(S + D + I) / N_ref` with edit distance over words; can exceed 100%; CER is the same on characters (better for languages without spaces). Implemented with a backtrace in `edit_distance` / `wer` / `cer`; [explore: `ctc_wer_lab.html`](interactive/ctc_wer_lab.html) shows the alignment ops.

**Text normalisation is half the metric.** Lowercasing, punctuation, numbers ('twenty' vs '20'), contractions, filler words, spelling variants. Compare systems only under the *same* normaliser, and also report entity-level errors (names, numbers, medication) because not all words matter equally.

**Other metrics.**
- *Diarization:* DER ([14.14](14.14-speaker-diarization.md)).
- *TTS:* MOS (human 1-5 listening scores, with confidence intervals), predicted-MOS models, WER of ASR on synthesised speech (intelligibility), speaker-embedding cosine similarity, pronunciation error counts.
- *Vocoder/codec:* spectral convergence / mel distortion ([14.17](14.17-vocoders.md)), PESQ/STOI/ViSQOL-style perceptual metrics, SNR (`snr_db`) (`REVIEW_REQUIRED` for exact definitions and usage).
- *Latency:* time-to-first-partial, final latency, RTF.
- *Robustness:* slice by accent, noise level, device, domain, speaker.

**Statistical care.** Report confidence intervals (bootstrap over utterances), use held-out, representative data, avoid test-set contamination (public benchmarks may be in training sets of large models, `REVIEW_REQUIRED`).

### 4. HOW DOES IT WORK?

```
reference text ─┐
                ├─► normalise ─► edit-distance alignment ─► S, D, I counts ─► WER = (S+D+I)/N
hypothesis text ─┘
```
Open [explore: `ctc_wer_lab.html`](interactive/ctc_wer_lab.html) and edit both strings; watch substitutions, deletions and insertions get coloured in the alignment table.

### 5. SIMPLE EXAMPLE

Grading a dictation test: count wrong, missed and extra words and divide by the number of words in the original.

### 6. TECHNICAL EXAMPLE

In the lab, `lab_demo.py` reports CER, utterance error rate and RTF for greedy and beam decoding of the toy model; the WER tests include `wer('a','a b c d') == 3.0` (above 100%).

### 7. CODE

```python
# run inside lab/
from audio_core import edit_distance, wer, cer, real_time_factor

ref, hyp = "the cat sat on the mat", "the cat sit on mat today"
total, subs, dels, ins = edit_distance(ref.split(), hyp.split())
print(total, subs, dels, ins)                       # 3 1 1 1
print(round(wer(ref, hyp), 3), round(cer(ref, hyp), 3))
print(real_time_factor(process_seconds=2.0, audio_seconds=60.0))   # 0.0333 (30x faster than real time)
```

### 8. INPUT → PROCESS → OUTPUT

```
system outputs + references + metadata (accent, noise) ─► normalise ─► metrics per slice ─► report + CI ─► ship/no-ship
```

### 9. ENTERPRISE USE CASE

Enterprises build a golden set of real, consented call audio, transcribed by humans, and gate every ASR/TTS change on WER by slice, entity accuracy and latency; regression dashboards track drift over time.

### 10. AI ENGINEERING CONNECTION

Evaluation discipline here mirrors Tier 15 (foundation-model evaluation and release gates) but with audio-specific metrics; the same ideas of slices, confidence intervals and golden sets apply to voice agents end to end.

### 11. ADVANTAGES

Objective, cheap to compute, comparable over time.

### 12. LIMITATIONS

WER treats all words equally, depends on normalisation, ignores meaning and speaker; MOS is costly and noisy; benchmarks may not match your domain.

### 13. TRADE-OFFS

Automatic metrics (cheap, consistent) vs human judgement (expensive, closer to quality); aggregate vs sliced reporting.

### 14. COMMON MISTAKES

- Comparing WER across different normalisers.
- Reporting only clean-data WER.
- Ignoring entity errors.
- No confidence intervals.
- Testing on data seen in training.

### 15. PERFORMANCE / COST CONSIDERATIONS

Metrics are cheap; collecting and transcribing a golden set is the cost. Sample smartly (stratify by slice) and refresh periodically.

### 16. SECURITY CONSIDERATIONS

Evaluation audio is customer data: consent, access control, retention; do not send it to third-party raters without agreements; redact PII.

### 17. INTERVIEW EXPLANATION

*"WER is substitutions plus deletions plus insertions over reference words, computed via edit distance after normalising text. It is useful but crude: I normalise consistently, report CER for non-spaced languages, slice by accent and noise, track entity accuracy and latency, and give confidence intervals. For TTS I add MOS, intelligibility and speaker similarity."*

### 18. RAPID-FIRE ANSWER

WER=(S+D+I)/N after consistent normalisation, plus slices, latency (RTF), and task-specific metrics like DER and MOS.
