### 1. WHAT IS IT?

Audio/video performance and cost considerations cover compute, memory, latency, storage and money for speech and video systems: what drives them (duration, sample rate, frames, tokens, model size, concurrency) and how to reduce them.

### 2. WHY DOES IT EXIST?

Audio and video are orders of magnitude bigger than text. A design that works on a demo clip can be too slow or too expensive at thousands of hours; the multipliers must be known up front.

### 3. DETAILED EXPLANATION

**Audio cost drivers.** Minutes of audio x model cost. Frame rate (hop) sets encoder sequence length; model size sets per-frame cost; streaming adds idle overhead; TTS cost scales with characters and vocoder RTF. API pricing is per audio minute (parameter in the explorer; real prices are `REVIEW_REQUIRED`).

**Video cost drivers.** frames x tokens per frame (+ attention quadratic in tokens) + decode cost + storage. 10 minutes at 1 fps, 256 tokens/frame: 153 600 visual tokens; at 2 fps double (`video_cost`).

**Levers.** (1) *Reduce what you process:* VAD ([14.13](14.13-speech-segmentation.md)), frame sampling ([14.23](14.23-frame-sampling.md)), shot-level dedup, triggers. (2) *Reduce per-unit cost:* smaller/distilled/quantised models, token pooling, lower resolution. (3) *Reuse:* cache features/embeddings; precompute offline. (4) *Batch and schedule:* offline jobs on spot GPUs; real-time on reserved capacity. (5) *Right tier:* cheap model first, escalate uncertain segments to a large model.

**Latency vs cost.** Real-time needs reserved capacity and smaller batches (lower utilisation, higher cost per minute); offline can maximise batch size. RTF < 1 with headroom for peak.

**Build-vs-buy.** API cost = hours x 60 x price/min; self-host cost = hours x RTF x GPU price / utilisation (explorer section 3). The crossover depends on volume, utilisation and engineering cost (`REVIEW_REQUIRED` for any price).

**Measure.** Cost per audio minute, per video minute, p50/p95 latency, RTF, GPU utilisation, cache hit rate, and accuracy per dollar.

### 5. SIMPLE EXAMPLE

Shipping parcels: weight (duration x quality) drives cost, so you shrink the parcel (VAD, sampling), pick a cheaper carrier (smaller model) and avoid shipping the same parcel twice (caching).

### 6. TECHNICAL EXAMPLE

With 5 000 hours/month, API price 0.006 USD/min gives 1 800 USD; self-hosting at RTF 0.1 on a 1.5 USD/hour GPU at 50% utilisation gives 5 000 x 0.1 x 1.5 / 0.5 = 1 500 USD (illustrative parameters only).

### 7. CODE

# run inside lab/
from video_core import video_cost, audio_cost

hours = 5000
api = audio_cost(minutes=hours * 60, usd_per_min=0.006, rtf=0.0)["usd"]
gpu_hours = hours * 0.1 / 0.5                    # RTF 0.1, 50% utilisation
print(round(api), "USD API vs", round(gpu_hours * 1.5), "USD self-host (illustrative prices)")

### 9. ENTERPRISE USE CASE

Call-centre transcription at scale, video moderation and media search budget per minute; FinOps teams track unit cost and set guardrails.

### 10. AI ENGINEERING CONNECTION

Same cost/latency logic as LLM serving ([Tier 11](../tier-11-llm-inference-optimization/README.md)); video tokens inherit [Tier 13](../tier-13-vision-ai/README.md) patch counts; evaluation of the quality side is [14.20](14.20-audio-evaluation.md) and [14.32](14.32-video-evaluation.md).

### 11. ADVANTAGES

Predictable budgeting; large savings from simple levers (VAD, sampling, caching).

### 12. LIMITATIONS

Prices and speeds change; utilisation is workload-dependent; quality-cost trade-offs need measurement.

### 13. TRADE-OFFS

Accuracy vs cost vs latency; API convenience vs self-host control; real-time headroom vs utilisation.

### 14. COMMON MISTAKES

- Budgeting on average load not peak.
- Ignoring decode and storage costs.
- No caching of embeddings.
- Optimising cost without tracking accuracy.
- Comparing APIs without equal normalisation.

### 15. PERFORMANCE / COST CONSIDERATIONS

Key measurements: RTF, tokens/s, GPU utilisation, p95 latency; use batching offline, streaming-friendly small batches online.

### 16. SECURITY CONSIDERATIONS

Cost controls are also security controls: cap input duration and tokens per request to prevent cost-DoS; authenticate and rate-limit uploads.

### 17. INTERVIEW EXPLANATION

*"Audio and video cost scales with duration, frame or token counts and model size. I shrink the workload first with VAD, frame sampling and caching, then choose a model tier, and I compare API cost per minute with self-hosting cost using RTF and utilisation. I always track accuracy per dollar and p95 latency, not just averages."*

### 18. RAPID-FIRE ANSWER

Duration x frames x tokens x model cost: cut volume (VAD, sampling), cache, tier models, and compare API vs self-host.
