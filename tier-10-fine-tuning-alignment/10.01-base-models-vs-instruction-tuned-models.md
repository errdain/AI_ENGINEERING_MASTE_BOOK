### 1. WHAT IS IT?

A **base model** is a network trained only to predict the next token on a large corpus. An **instruction-tuned (chat/instruct) model** is a base model that was further trained (post-training) so that the most likely continuation of a user request is a helpful answer in a fixed chat format.

### 2. WHY DOES IT EXIST?

Pretraining ([Tier 9](../tier-09-foundation-model-pretraining/README.md)) gives knowledge and fluency but no *behaviour*: nothing tells the model to answer, refuse unsafe requests, use a format, or stop. Post-training adds those behaviours cheaply on top of the expensive pretrained weights.

### 3. DETAILED EXPLANATION

Given `"What is the capital of France?"` a base model may continue with *more quiz questions*, because that is a likely continuation of a quiz page. An instruct model has seen many (request, answer) pairs inside a template, so the likely continuation is the answer followed by an end-of-turn token. Both are the *same architecture*; only the weights (and the template they expect) differ.

| | Base | Instruct / chat |
|---|---|---|
| Training signal | next token on raw text | plus demonstrations and preferences |
| Prompt style | completion / few-shot text | chat template with roles |
| Stops cleanly? | not reliably | yes (learned end token) |
| Best for | further post-training, scoring, raw likelihoods, code completion | assistants, tool use, products |

Vendors usually publish both; naming conventions vary, so check the model card (`REVIEW_REQUIRED`).

### 4. HOW DOES IT WORK?

1. Start from pretrained weights.
2. Render (prompt, answer) pairs through a chat template ([10.5](10.05-chat-templates.md)).
3. Train with next-token loss on the answer only ([10.3](10.03-supervised-fine-tuning-sft.md)).
4. Optionally train on preferences ([10.19](10.19-preference-data.md) to [10.25](10.25-direct-preference-optimization-dpo.md)).

### 5. SIMPLE EXAMPLE

A new hire who has read the whole company wiki (base) versus one who has also been trained to answer customer tickets politely and to know when to stop (instruct).

### 6. TECHNICAL EXAMPLE

In the lab, the pretrained tiny model has next-token loss 0.59 on its own text but **0 % accuracy** on the prompt `<|user|>up cat sun<|asst|>`: it never saw that format. After SFT it answers `CAT SUN` (88 % exact match on 33 unseen word pairs, full fine-tuning, 150 steps). See the [pipeline figure](figures/01_post_training_pipeline.png). Numbers here come from the seeded lab run (`lab/run_lab.py`, 64,512-parameter char model, one seed, CPU); they teach mechanics, not large-model behaviour.

### 7. CODE

```python
# lab/data.py + lab/tiny_lm.py : the same prompt before and after SFT
from data import render_chat, encode, decode
from tiny_lm import generate
prompt = encode(render_chat([{"role": "user", "content": "up cat sun"}], add_generation_prompt=True))
print(decode(generate(base_model, prompt)))   # base: does not follow the format
print(decode(generate(sft_model,  prompt)))   # sft : "CAT SUN"
```
Lab entry point: [`lab/run_lab.py`](lab/run_lab.py).

### 8. INPUT → PROCESS → OUTPUT

```
raw text --> [pretraining] --> BASE --> [post-training] --> INSTRUCT
prompt in template --> instruct model --> answer + <|end|>
```

### 9. ENTERPRISE USE CASE

Teams pick a **base** checkpoint when they will run their own heavy post-training or need raw likelihoods (scoring, editor completion), and an **instruct** checkpoint when they want an assistant now with only light adaptation.

### 10. AI ENGINEERING CONNECTION

Every chat product, tool-calling agent and RAG answerer sits on an instruct model; knowing that "chat" is a *learned format* explains template mismatches and runaway generation.

### 11. ADVANTAGES

Instruct models are usable immediately; base models are flexible and keep more raw diversity.

### 12. LIMITATIONS

Instruct models can lose some calibration and diversity to post-training; base models need prompt engineering to behave.

### 13. TRADE-OFFS

Control and flexibility (base) versus convenience and built-in safety behaviour (instruct).

### 14. COMMON MISTAKES

Prompting a base model with a chat template, or an instruct model with raw few-shot text, and blaming the model; assuming "instruct" means "knows more".

### 15. PERFORMANCE / COST CONSIDERATIONS

No inference-cost difference at the same size; the cost is the post-training you do or inherit.

### 16. SECURITY CONSIDERATIONS

Instruct models carry safety tuning that fine-tuning can erode ([10.34](10.34-fine-tuning-data-security-considerations.md)); base models have no refusal behaviour at all.

### 17. INTERVIEW EXPLANATION

A base model is trained only to predict the next token. An instruct model is the same network after post-training, mainly SFT on demonstrations and then preference optimization, so a request is followed by a helpful answer and an end token. Pretraining gives knowledge, post-training gives behaviour. I start from a base checkpoint for custom heavy post-training and from an instruct one when I want an assistant quickly.

### 18. RAPID-FIRE ANSWER

Base = knows; instruct = behaves.
