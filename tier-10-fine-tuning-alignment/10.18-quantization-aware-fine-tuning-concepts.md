### 1. WHAT IS IT?

**Quantization-aware fine-tuning concepts** separate three ideas: **PTQ** (compress a finished model), **QAT** (simulate quantization during training), and **QLoRA** (quantized frozen base plus trainable high-precision adapter).

### 2. WHY DOES IT EXIST?

Aggressive PTQ can lose quality; QAT or QLoRA recipes recover or avoid it.

### 3. DETAILED EXPLANATION

**PTQ:** quantize after training ([Tier 11](../tier-11-llm-inference-optimization/README.md)). **QAT:** insert "fake-quant" (round then dequantize) in the forward pass with a straight-through estimator for the gradient, so weights learn to be robust to rounding. **QLoRA:** base quantized and frozen; the *adapter* is not quantization-aware. QAT recovers quality at the price of extra training; a practical path is QLoRA for training, then PTQ or merge-and-quantize for serving.

![Quantization noise](figures/13_quantization_levels.png)

*Figure: the right panel shows the rounding noise that QAT would train the model to tolerate.*

### 4. HOW DOES IT WORK?

QAT forward: `w_q = dequant(quant(w))`; backward: pass the gradient as if `w_q = w` (straight-through estimator).

### 5. SIMPLE EXAMPLE

Practising a speech with the microphone you'll actually use.

### 6. TECHNICAL EXAMPLE

The lab's `quantize_4bit` demonstrates the rounding noise (max error about half a quantization step). A QAT loop is not implemented; no QAT result is claimed.

### 7. CODE

```python
def fake_quant(w):                       # straight-through estimator
    q = dequantize_4bit(*quantize_4bit(w))
    return w + (q - w).detach()          # forward = q, gradient = identity
```
(illustrative; relies on `lab/lora.py` quantizer)

### 8. INPUT → PROCESS → OUTPUT

```
PTQ: train fp16 -> quantize.   QAT: train with fake-quant -> quantize.   QLoRA: 4-bit frozen base + fp16 adapter
```

### 9. ENTERPRISE USE CASE

Edge deployments use QAT when PTQ accuracy is insufficient; training teams use QLoRA for cost.

### 10. AI ENGINEERING CONNECTION

Links training-time quantization choices to serving-time inference formats.

### 11. ADVANTAGES

Clear taxonomy prevents mixing goals.

### 12. LIMITATIONS

QAT costs extra training; methods differ by hardware format.

### 13. TRADE-OFFS

Training cost versus deployed accuracy at low bit-width.

### 14. COMMON MISTAKES

Calling QLoRA "QAT"; assuming PTQ and QAT give equal quality.

### 15. PERFORMANCE / COST CONSIDERATIONS

QAT adds fake-quant overhead to training.

### 16. SECURITY CONSIDERATIONS

Quantized models can change safety behaviour slightly; re-run safety evals on the served artifact.

### 17. INTERVIEW EXPLANATION

PTQ compresses a trained model, QAT trains with simulated rounding using a straight-through estimator so the model adapts to it, and QLoRA keeps a quantized frozen base with a high-precision adapter. I usually do QLoRA to train and PTQ or merge-then-quantize to serve.
