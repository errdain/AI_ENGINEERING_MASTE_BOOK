### 1. WHAT IS IT?

**QLoRA** stores the *frozen* base model in 4-bit (blockwise quantized), dequantizes on the fly, and trains LoRA adapters in higher precision.

### 2. WHY DOES IT EXIST?

To fit fine-tuning of large models on small GPUs: the base dominates memory, and it never needs gradients.

### 3. DETAILED EXPLANATION

The base never receives updates, so quantization error does not accumulate through training. The published QLoRA adds the **NF4** data type (levels at normal-distribution quantiles), **double quantization** of the scale constants, and **paged optimizers** (`REVIEW_REQUIRED`).

![Quantization levels](figures/13_quantization_levels.png)

*Figure: left, 16 uniform levels (what the lab uses) versus an NF4-like quantile placement (an illustrative construction, not the published NF4 table). Right, real rounding error of the lab quantizer on N(0, 0.05) weights with block 64.*

**Memory:** base ~ `0.5 + 4/block` bytes/param (4 bits + one fp32 absmax per block), so a 7B base is about 3.9 GB at block 64, plus adapter and optimizer state; activations are extra. [Explore memory](interactive/qlora_memory.html).

### 4. HOW DOES IT WORK?

1. Quantize frozen weights blockwise. 2. Forward/backward: dequantize a block to bf16/fp16, compute, discard. 3. Gradients flow through the dequantized weights to the LoRA factors only. 4. Merge into an fp16 copy of the base (not into the 4-bit weights) if a merged model is wanted, then re-quantize for serving ([Tier 11](../tier-11-llm-inference-optimization/README.md)).

### 6. TECHNICAL EXAMPLE

Lab "QLoRA-lite": uniform int4 absmax per block of 64, written back as dequantized values so training sees real quantization noise. Result: accuracy **0.45** vs LoRA r8 **0.55** at 200 steps, **within seed variation** (0.45-0.85 across seeds), so no ranking is claimed. Not NF4. Numbers here come from the seeded lab run (`lab/run_lab.py`, 64,512-parameter char model, one seed, CPU); they teach mechanics, not large-model behaviour.

### 7. CODE

```python
# lab/lora.py
q, absmax, shape, pad = quantize_4bit(weight, block=64)   # int8 codes in -8..7 + per-block scale
w_hat = dequantize_4bit(q, absmax, shape, pad)
quantize_model_inplace(model)                             # simulated QLoRA base
print(finetune_memory_gb(7, "qlora_4bit", r_params_m=20))  # ~4.3 GB incl. adapter state
```
Tests: `test_quantize_4bit_levels_and_error` (<=16 levels, error <= half a step). File: [`lab/lora.py`](lab/lora.py). Library route: `bitsandbytes` + PEFT (verify versions, `REVIEW_REQUIRED`).

### 8. INPUT → PROCESS → OUTPUT

```
W (fp16) --quantize--> 4-bit blocks + scales (frozen)
x --dequantize block--> matmul + LoRA(A,B) in 16-bit --> loss --> grads to A,B only
```

### 9. ENTERPRISE USE CASE

Single-GPU fine-tuning of a large open model for a domain; then merge into fp16 and re-quantize for serving.

### 10. AI ENGINEERING CONNECTION

Makes 30B+ class models tunable on modest hardware; a standard recipe for open-weight SFT/DPO.

### 11. ADVANTAGES

Massive memory savings; quality close to 16-bit LoRA is reported (`REVIEW_REQUIRED`).

### 12. LIMITATIONS

Slower per step (dequantization); merging into the 4-bit base is lossy; extra moving parts.

### 13. TRADE-OFFS

Memory versus speed and complexity.

### 14. COMMON MISTAKES

Merging adapters directly into quantized weights; assuming QLoRA = QAT; comparing runs with different LRs or seeds.

### 15. PERFORMANCE / COST CONSIDERATIONS

Weights ~0.56 B/param at block 64; training slower than 16-bit LoRA due to dequantization (magnitude hardware-dependent).

### 16. SECURITY CONSIDERATIONS

Adapters trained on a quantized base should be validated on the exact serving base.

### 17. INTERVIEW EXPLANATION

QLoRA keeps the frozen base in 4-bit, dequantizes blocks on the fly, and trains LoRA adapters in 16-bit. Because the base never gets gradients, quantization error doesn't compound. It lets me fine-tune big models on one GPU; the price is slower steps and that merging should go into an fp16 copy, then re-quantize for serving.

### 18. RAPID-FIRE ANSWER

4-bit frozen base, 16-bit trainable adapter.
