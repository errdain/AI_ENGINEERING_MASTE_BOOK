### 1. WHAT IS IT?

**Fine-tuning data and security considerations** cover the risks of training data and tuned models: memorisation, poisoning, safety erosion, template injection, licences and governance.

### 2. WHY DOES IT EXIST?

Fine-tuning changes the model with your data; whatever is in that data can leak, backdoor or break the model.

### 3. DETAILED EXPLANATION

* **Memorisation & leakage:** tuned models can regurgitate training examples (PII, secrets, customer data); dedupe, scrub, and use only data with consent.
* **Poisoning / backdoors:** a few malicious examples can plant trigger behaviours; control provenance and review contributors.
* **Safety erosion:** benign fine-tuning can weaken refusals; re-run safety evals after every tune.
* **Template injection:** control tokens in user content let users forge roles ([10.5](10.05-chat-templates.md); the lab tokenizer does this on purpose).
* **Licences & contamination:** dataset licences, teacher-output terms, benchmark leakage ([Tier 9](../tier-09-foundation-model-pretraining/README.md)).
* **Governance:** record data version, base model + hash, hyper-parameters and eval results (Tier 31/32).

### 4. HOW DOES IT WORK?

Threat-model the pipeline: data in, training, artifact out, serving. Add controls at each stage.

### 5. SIMPLE EXAMPLE

Don't put the vault key in the training notebook the model will memorise.

### 6. TECHNICAL EXAMPLE

A support bot fine-tuned on raw tickets repeats a customer's address when prompted cleverly; and a later tune weakens refusals. Both are preventable by scrubbing and regression checks. No lab measurement of leakage is claimed.

### 7. CODE

```python
import re
EMAIL = re.compile(r"[\w.+-]+@[\w-]+\.[\w.]+")
def scrub(text): return EMAIL.sub("<EMAIL>", text)      # minimal example; real PII scrubbing needs more
```

### 8. INPUT → PROCESS → OUTPUT

```
data --> scrub / dedupe / provenance --> train --> safety + leakage eval --> signed artifact --> serve
```

### 9. ENTERPRISE USE CASE

Regulated teams require data lineage, consent records and model cards for every tuned artifact.

### 10. AI ENGINEERING CONNECTION

Directly relevant to agent safety and guardrails (Tier 32).

### 11. ADVANTAGES

Knowing the threats lets you set cheap controls early.

### 12. LIMITATIONS

Controls add process; leakage is hard to prove absent.

### 13. TRADE-OFFS

Utility of real data versus privacy risk.

### 14. COMMON MISTAKES

Tuning on raw logs; no post-tune safety eval; hand-built templates that parse user specials; no lineage.

### 15. PERFORMANCE / COST CONSIDERATIONS

Scrubbing and evals add pipeline cost.

### 16. SECURITY CONSIDERATIONS

Treat adapters and datasets as sensitive; sign artifacts; restrict who can train.

### 17. INTERVIEW EXPLANATION

Fine-tuned models memorise their data, so I scrub PII and secrets, control provenance against poisoning, re-run safety evaluations since even benign tunes can erode refusals, escape control tokens in user input, and keep lineage of data, base hash and eval results.
