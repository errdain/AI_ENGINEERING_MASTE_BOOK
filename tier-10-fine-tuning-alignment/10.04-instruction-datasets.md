### 1. WHAT IS IT?

**Instruction datasets** are collections of (instruction, optional input, output) triples or multi-turn conversations used for SFT.

### 2. WHY DOES IT EXIST?

To demonstrate to the model the tasks and format it should perform, with controlled coverage.

### 3. DETAILED EXPLANATION

Sources: **human-written** (expensive, highest control), **mined** from existing tasks and templated, **synthetic** from a stronger model ([10.7](10.07-synthetic-training-data.md)), and **logs** of real usage (only after consent and scrubbing). Public datasets vary widely in licence and quality; check licences before use (Tier 32). Rules: diversity of *tasks*, correctness of *answers*, consistency of *format*. Hundreds to thousands of high-quality examples can shift style a lot; large capability gains need more and harder data (published claims differ; `REVIEW_REQUIRED`).

### 4. HOW DOES IT WORK?

Collect or generate -> normalise to a schema -> dedupe/filter ([10.6](10.06-sft-data-curation.md)) -> render with the template -> split train/held-out.

### 5. SIMPLE EXAMPLE

A workbook of solved exercises: question, optional given data, worked answer.

### 6. TECHNICAL EXAMPLE

Lab: synthetic rule-generated tasks `up` and `rv`; 99 train / 33 held-out word pairs ([`lab/data.py`](lab/data.py)).

### 7. CODE

```python
example = {"instruction": "up", "input": "cat sun", "output": "CAT SUN"}   # schema; the lab renders it via render_chat
```

### 8. INPUT → PROCESS → OUTPUT

```
sources (human / mined / synthetic / logs) --> schema --> filter --> template --> SFT set + held-out set
```

### 9. ENTERPRISE USE CASE

Companies build small curated sets from expert answers and tickets, with legal review of licences and PII.

### 10. AI ENGINEERING CONNECTION

Dataset design is the main lever for assistant behaviour and tool-call formats used by agents.

### 11. ADVANTAGES

Directly controls behaviour; reusable.

### 12. LIMITATIONS

Licensing, bias, label noise; may not match production prompts.

### 13. TRADE-OFFS

Quality versus quantity; human versus synthetic cost.

### 14. COMMON MISTAKES

Mixing licences blindly; no held-out split; a single prompt phrasing.

### 15. PERFORMANCE / COST CONSIDERATIONS

Storage is trivial; labelling and review dominate cost.

### 16. SECURITY CONSIDERATIONS

Provenance, PII, and poisoning by contributors ([10.34](10.34-fine-tuning-data-security-considerations.md)).

### 17. INTERVIEW EXPLANATION

Instruction data are prompt/answer pairs or conversations. I care about task diversity, answer correctness and format consistency, and about licences and PII. A small clean set often beats a large messy one, and I hold out an evaluation split first.

### 18. RAPID-FIRE ANSWER

Instruction data = prompt/answer demonstrations; quality over quantity.

### 19. INTERVIEW QUESTIONS

**Basic:** What fields does an instruction example have?

**Intermediate:** Name four sources of instruction data.

**Advanced:** Why hold out a split before inspecting data?

**Scenario:** A vendor offers 1M scraped instruction pairs. What do you check?
