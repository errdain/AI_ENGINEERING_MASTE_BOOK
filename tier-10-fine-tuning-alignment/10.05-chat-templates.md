### 1. WHAT IS IT?

A **chat template** is the exact function that turns a list of messages `[{role, content}, ...]` into the token string the model saw during post-training: role markers, separators, end-of-turn tokens and an optional system prompt.

### 2. WHY DOES IT EXIST?

The model learned *this* format. A different one (wrong separator, missing end token, extra space) silently degrades quality or causes runaway generation.

### 3. DETAILED EXPLANATION

Tokenizer libraries ship the template with the model ([Tier 6](../tier-06-tokenization-embeddings/README.md): special tokens). In the lab each special is **one** token id.

[Explore the template and loss mask](interactive/chat_template.html): three simplified styles (formats are illustrations; exact whitespace and specials differ per model, `REVIEW_REQUIRED`), a generation-prompt toggle and a mask-prompt toggle.

**Security.** If user text contains the literal string of a control token and the tokenizer parses specials in user content, the user can forge roles. The lab tokenizer does exactly that on purpose (`test_chat_template_and_special_tokens`). Production tokenizers should escape or disable specials for user content (Tier 32).

### 4. HOW DOES IT WORK?

1. Wrap each message with its role marker. 2. End assistant turns with an end token. 3. At inference, append the assistant header (the *generation prompt*) so the model continues as the assistant. 4. During SFT, mask loss on everything except assistant content ([10.3](10.03-supervised-fine-tuning-sft.md)).

### 5. SIMPLE EXAMPLE

A form with fixed boxes: write in the wrong box and the clerk misreads it.

### 6. TECHNICAL EXAMPLE

`render_chat([{user:"up cat"},{assistant:"CAT"}])` gives `<|user|>up cat<|asst|>CAT<|end|>`.

### 7. CODE

```python
# lab/data.py
from data import render_chat
print(render_chat([{"role": "user", "content": "up cat"}], add_generation_prompt=True))
# <|user|>up cat<|asst|>
```
In production use the tokenizer's own template (for example `tokenizer.apply_chat_template` in Hugging Face Transformers; verify the API for your version, `REVIEW_REQUIRED`). Lab file: [`lab/data.py`](lab/data.py).

### 8. INPUT → PROCESS → OUTPUT

```
messages --> template --> text with specials --> tokenizer --> ids (+ loss mask)
```

### 9. ENTERPRISE USE CASE

Platform teams pin the template with the model version and test it in CI so training and serving agree.

### 10. AI ENGINEERING CONNECTION

Template mismatch is a top cause of "the fine-tuned model got worse"; tool calling and system prompts rely on it.

### 11. ADVANTAGES

Small, deterministic, essential.

### 12. LIMITATIONS

Different models use different templates; easy to get subtly wrong.

### 13. TRADE-OFFS

Fidelity to the training format over convenience.

### 14. COMMON MISTAKES

Hand-formatting prompts for a chat model; double BOS; inference without the generation prompt (model continues the *user's* turn); parsing control tokens in user input.

### 15. PERFORMANCE / COST CONSIDERATIONS

Free to compute; mistakes cost quality.

### 16. SECURITY CONSIDERATIONS

Role forgery via control tokens in user content; escape them (Tier 32).

### 17. INTERVIEW EXPLANATION

The chat template flattens messages into the exact token string the model was trained on, with role markers and an end-of-turn token. It is effectively part of the model: a mismatch quietly hurts quality or breaks stopping. At inference you add the generation prompt, and you must stop users from injecting control tokens.

### 18. RAPID-FIRE ANSWER

The template is part of the model.

### 19. INTERVIEW QUESTIONS

**Basic:** What is a chat template?

**Intermediate:** What is the generation prompt?

**Advanced:** How can user text forge a system role?

**Scenario:** A model looks fine in training eval but poor in production. Check template equality between train and serve.
