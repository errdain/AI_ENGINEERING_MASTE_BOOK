### 1. WHAT IS IT?

Evaluation objectives state the decision an evaluation must support (capability, reliability, safety, cost, fairness, readiness) before any metric is chosen.

### 2. WHY DOES IT EXIST?

Without a stated objective teams measure what is easy and then argue about what it means. An objective turns evaluation from a report into an input to a decision.

### 3. DETAILED EXPLANATION

Typical objective families:

| Objective | Question | Example measurement |
|---|---|---|
| Capability | Can it do the task? | accuracy, pass@k ([15.8 Task-specific evaluation](15.08-task-specific-evaluation.md)) |
| Reliability | Does it do so consistently? | variance across seeds, robustness ([15.15 Robustness](15.15-robustness.md)) |
| Calibration | Does it know when it is wrong? | ECE ([15.11 Calibration](15.11-calibration.md)) |
| Safety | Does it avoid harm? | attack success rate ([15.24 Red teaming](15.24-red-teaming.md)) |
| Fairness | Are groups treated comparably? | group gaps ([15.18 Bias evaluation](15.18-bias-evaluation.md)) |
| Efficiency | Is it affordable and fast? | latency, cost per request |
| Readiness | May we release? | gate pass/fail ([15.34 Release/readiness criteria](15.34-release-readiness-criteria.md)) |

An objective should be written as a testable statement: 'On the support-ticket golden set, accuracy lower-confidence bound >= 0.85 and refusal rate on disallowed requests >= 0.99'.

### 4. HOW DOES IT WORK?

1) Name the decision. 2) Name the stakeholders and failure costs. 3) Translate into metrics and thresholds. 4) Choose data and scorers. 5) Decide who acts on the result and how.

### 5. SIMPLE EXAMPLE

Buying a car: 'the best car' is meaningless until you say commute, family or towing. Objectives are the 'for what'.

### 6. TECHNICAL EXAMPLE

A customer-support assistant has three objectives: resolve rate (capability), no invented policies (factuality, [15.12 Factuality](15.12-factuality.md)), no personal data leakage ([15.20 Privacy evaluation](15.20-privacy-evaluation.md)). Each gets its own dataset, metric and gate.

### 7. CODE

```python
# run inside lab/ -- objectives as explicit gates (the lab harness makes them executable)
from evalharness import Gate
objectives = [
    Gate("capability", "ci_low", min=0.85),
    Gate("safety refusals", "slice:safety", min=0.99),
]
for g in objectives:
    print(g.name, g.metric, g.min)
```

### 8. INPUT → PROCESS → OUTPUT

```
decision to make -> objectives (testable) -> metrics + data -> thresholds -> gate
```

### 9. ENTERPRISE USE CASE

Product, risk and legal agree objectives and thresholds up front; ML engineers implement them; the release process enforces them.

### 10. AI ENGINEERING CONNECTION

Objectives are the contract between an LLM feature and the organisation; they also define which Tier 30 application-level evaluations are required.

### 11. ADVANTAGES

- Aligns teams before building metrics.
- Makes thresholds auditable.

### 12. LIMITATIONS

- Objectives drift as products change.
- Some objectives (user trust) resist direct measurement.

### 13. TRADE-OFFS

- More objectives give more coverage but more cost and more conflicting gates.

### 14. COMMON MISTAKES

- Choosing metrics first.
- Writing objectives without thresholds.
- Ignoring objectives that are hard to measure.

### 15. PERFORMANCE / COST CONSIDERATIONS

Cost scales with the number of objectives; prioritise by failure cost.

### 16. SECURITY CONSIDERATIONS

Safety and privacy objectives should be hard gates, not soft targets, and owned by someone outside the feature team (REVIEW_REQUIRED per organisation).

### 17. INTERVIEW EXPLANATION

An evaluation objective is the decision the evaluation supports: capability, reliability, calibration, safety, fairness, efficiency or readiness. I write each as a testable statement with a metric and threshold so the result can be turned into a pass/fail gate.

### 18. RAPID-FIRE ANSWER

Decision first, metric second, threshold third.

### 19. INTERVIEW QUESTIONS

- **Basic:** What is an evaluation objective?
- **Intermediate:** Give a testable objective for a support chatbot.
- **Advanced:** How do you handle conflicting objectives such as safety and helpfulness?
- **Scenario:** Stakeholders disagree on what 'good' means; what do you do?
