### 1. WHAT IS IT?

Benchmark design is choosing the task, items, scoring rule, splits and reporting protocol of a standard test so that its scores mean what they claim.

### 2. WHY DOES IT EXIST?

A poorly designed benchmark is saturated, contaminated, ambiguous or noisy, and misleads model selection.

### 3. DETAILED EXPLANATION

Design checklist:

1. **Construct validity**: does the test measure the skill you name? Write the claim ('multi-step arithmetic reasoning'), then check items match it.
2. **Item quality**: unambiguous questions, verified answers, no label noise (even 3% wrong labels caps achievable accuracy).
3. **Coverage and slices**: tag items so you can report per-topic, per-difficulty and per-demographic results.
4. **Size and power**: choose n so confidence intervals resolve the differences you care about (Figure 4; interval half-width about 1.96*sqrt(p(1-p)/n)).
5. **Scoring**: deterministic where possible (exact match, unit tests); documented rubric where not.
6. **Splits and secrecy**: keep a private held-out portion; version the dataset ([15.30 Evaluation versioning](15.30-evaluation-versioning.md)).
7. **Prompt protocol**: fix few-shot examples, template and decoding settings, and report them ([15.29 Evaluation reproducibility](15.29-evaluation-reproducibility.md)).
8. **Saturation and lifespan**: plan refresh; as top models approach ceiling the benchmark stops discriminating.

Sample-size rule of thumb: for accuracy near 0.7, n=300 gives about +/-5 points; to resolve a 1-point gap unpaired you need on the order of tens of thousands of items, which is why paired comparison ([15.33 Model comparison](15.33-model-comparison.md)) matters.

### 4. HOW DOES IT WORK?

Define claim -> collect/author items -> verify labels -> tag slices -> pick scorer -> pilot to measure noise -> freeze version -> publish protocol.

### 5. SIMPLE EXAMPLE

A driving test that only checks parking would not certify drivers; it needs the right manoeuvres, enough of them, and a fixed marking scheme.

### 6. TECHNICAL EXAMPLE

A 300-item QA benchmark gives CIs about +/-5 points; two models 2 points apart cannot be ranked. Doubling items shrinks the interval by about 29% (1/sqrt(2)).

### 7. CODE

```python
# run inside lab/ -- how many items do I need? (half-width of a 95% CI for accuracy p)
import math
def n_needed(p, half_width):
    return math.ceil(1.96 ** 2 * p * (1 - p) / half_width ** 2)
for hw in (0.05, 0.02, 0.01):
    print(f"half-width {hw:.2f} at p=0.7 needs n >= {n_needed(0.7, hw)}")
```

### 9. ENTERPRISE USE CASE

Internal benchmarks built from real tickets, with private test splits, are the main evidence used to choose among vendors.

### 10. AI ENGINEERING CONNECTION

Benchmark design principles carry over to every dataset in this tier (golden, regression, safety) and to Tier 30 application evaluation.

### 11. ADVANTAGES

- Clear claims, reproducible comparison.
- Slices expose hidden weaknesses.

### 12. LIMITATIONS

- Validity is argued, not proven.
- Static benchmarks saturate and leak.

### 13. TRADE-OFFS

- Size vs labelling cost.
- Public (comparability) vs private (contamination resistance).

### 14. COMMON MISTAKES

- No confidence intervals.
- Unverified labels.
- Changing the prompt protocol between runs.
- Reporting only the aggregate.

### 15. PERFORMANCE / COST CONSIDERATIONS

Labelling cost dominates; run cost scales with n x models x samples.

### 16. SECURITY CONSIDERATIONS

Private test sets need access control; leaked test items destroy the benchmark ([15.21 Memorization/data-leakage evaluation](15.21-memorization-data-leakage-evaluation.md)).

### 17. INTERVIEW EXPLANATION

A good benchmark has a clear construct, clean verified items, tagged slices, enough items for its intervals to resolve the differences that matter, deterministic scoring where possible, a documented prompt protocol, versioning and a private held-out split. I always report intervals.

### 18. RAPID-FIRE ANSWER

Valid, clean, sliced, sized, scored, versioned, protected.

### 19. INTERVIEW QUESTIONS

- **Basic:** What makes a benchmark good?
- **Intermediate:** How many items to detect a 2-point accuracy difference?
- **Advanced:** Why does paired analysis need fewer items than unpaired?
- **Scenario:** Your top two candidates differ by 1 point on a 500-item set; what do you do?
