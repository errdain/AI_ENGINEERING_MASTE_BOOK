### 1. WHAT IS IT?

An evaluation pipeline automates the path from a candidate model/prompt to a decision: load versioned data, run the model, score, aggregate with uncertainty, store results, apply gates and report.

### 2. WHY DOES IT EXIST?

Manual evaluation is slow and inconsistent; a pipeline makes evaluation a repeatable step in the development loop, like unit tests.

### 3. DETAILED EXPLANATION

Stages (Figure 9 right-hand side shows the gate at the end):
1. **Trigger**: code, prompt or model change; schedule; manual.
2. **Load** golden, regression, safety and benchmark datasets (versions pinned).
3. **Run** the candidate with seeds.
4. **Score**: automatic scorers, validated judges, queue for human review of ambiguous or high-severity items ([15.27 Human evaluation](15.27-human-evaluation.md)).
5. **Aggregate**: means, CIs, per-slice results ([15.6 Benchmark design](15.06-benchmark-design.md)).
6. **Store**: versioned JSON ([15.30 Evaluation versioning](15.30-evaluation-versioning.md)).
7. **Compare** with baseline (paired, [15.33 Model comparison](15.33-model-comparison.md)).
8. **Gate** ([15.32 Evaluation gates](15.32-evaluation-gates.md)) and **report** with reasons.

Design choices: tiered suites (fast smoke set on every commit, full suite nightly, expensive human review before release), caching of model outputs, parallelism, and failing closed when evidence is missing.

### 4. HOW DOES IT WORK?

Config in -> deterministic run -> JSON out -> gate report; the lab's `run_eval`, `import_human_reviews`, `evaluate_gates` implement the core stages.

### 5. SIMPLE EXAMPLE

A factory quality line: every product passes the same stations and gets a signed inspection sheet.

### 6. TECHNICAL EXAMPLE

CI runs a 200-case smoke set in 2 minutes; the nightly job runs the full golden, safety and regression sets; release candidates add human review of 100 sampled outputs.

### 7. CODE

```python
# run inside lab/ -- the whole pipeline in a few lines
import tempfile
from evalharness import run_eval, evaluate_gates, Gate
from demo import make_ds, model_v1, model_v2
ds = make_ds()
baseline = run_eval(model_v2, "v2", ds, seed=1)                    # 3. run (+4. score)
cand = run_eval(model_v1, "v1", ds, seed=1)
with tempfile.TemporaryDirectory() as d: cand.save(d)               # 6. store
gates = [Gate("accuracy floor", "ci_low", min=0.8), Gate("no regression", "mean", max_regression=0.02)]
print(evaluate_gates(cand, gates, baseline))                       # 8. gate + reasons
```

Lab code: [`lab/evalharness.py`](lab/evalharness.py), [`lab/demo.py`](lab/demo.py).

```
trigger -> load versioned data -> run -> score -> aggregate (+CI) -> store -> compare -> gate -> report
```

### 9. ENTERPRISE USE CASE

ML platform teams provide the pipeline as a service; product teams configure datasets and gates.

### 10. AI ENGINEERING CONNECTION

The evaluation counterpart of CI/CD for LLM applications; Tier 30 extends it with traces and online signals.

### 11. ADVANTAGES

- Repeatable, fast feedback, audit trail.

### 12. LIMITATIONS

- Maintenance; flaky scorers undermine trust.

### 13. TRADE-OFFS

- Coverage (full suites) vs speed (smoke sets).

### 14. COMMON MISTAKES

- Running only manually.
- No caching.
- Passing when data is missing.

### 15. PERFORMANCE / COST CONSIDERATIONS

Cache model outputs keyed by (model, prompt, seed); parallelise examples.

### 16. SECURITY CONSIDERATIONS

Pipelines hold secrets (API keys) and test data; least privilege and secret management.

### 17. INTERVIEW EXPLANATION

An evaluation pipeline automates load, run, score, aggregate, store, compare and gate, with pinned versions and seeds, tiered suites and fail-closed behaviour. I store every run as versioned JSON and report gate failures with reasons.
