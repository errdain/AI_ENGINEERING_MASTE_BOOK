### 1. WHAT IS IT?

Privacy evaluation tests whether a model or system reveals personal or confidential information it should not: training-data leakage, PII in outputs, membership inference, or exposure of prompts and context.

### 2. WHY DOES IT EXIST?

Models can memorise and regurgitate training data, and applications can leak context. Privacy failures are legal and reputational incidents.

### 3. DETAILED EXPLANATION

Test categories:
- **Verbatim extraction**: prompt with a prefix of known sensitive text and check for completion ([15.21 Memorization/data-leakage evaluation](15.21-memorization-data-leakage-evaluation.md)).
- **PII leakage in outputs**: run detectors (regex plus model-based) over generations; report leak rate per PII type with precision/recall of the detector itself ([15.10 Precision/recall/F1 in model evaluation](15.10-precision-recall-f1-in-model-evaluation.md)).
- **Membership inference**: can an attacker tell whether a record was in training data? Report attack AUC; 0.5 is chance (advanced, REVIEW_REQUIRED).
- **Context and prompt leakage**: does the assistant reveal system prompts or other users' retrieved documents?
- **Canaries**: insert unique fake secrets into training or context and test whether they come back (a controlled leak measure).

Report leak rate with confidence intervals and what was queried; a zero count on small n does not prove zero risk (rule of three: with 0 leaks in n trials the 95% upper bound is about 3/n).

### 4. HOW DOES IT WORK?

Define sensitive categories -> build probes and canaries -> run -> detect leaks (automatic then human) -> compute rate with CI -> gate release on a ceiling.

### 5. SIMPLE EXAMPLE

Testing a bank clerk by asking tricky questions to see whether they reveal another customer's balance.

### 6. TECHNICAL EXAMPLE

1,000 probe prompts, 0 canary leaks: upper 95% bound is about 0.3%. The team states the bound, not 'zero'.

### 7. CODE

```python
# run inside lab/ -- PII regex detector + 'rule of three' bound
import re
EMAIL = re.compile(r"[\w.+-]+@[\w-]+\.[\w.]+")
outputs = ["contact me at jane.doe@example.com", "no personal data here"]
print([bool(EMAIL.search(o)) for o in outputs])
n, leaks = 1000, 0
print("95% upper bound on leak rate with 0 leaks in n =", n, "->", round(3 / n, 4))
```

### 8. INPUT → PROCESS → OUTPUT

```
probes + canaries -> model -> outputs -> PII detector + human check -> leak rate + upper bound
```

### 9. ENTERPRISE USE CASE

Privacy and legal teams define PII categories and acceptable bounds; evaluation results go into the data-protection impact assessment (jurisdiction-specific, REVIEW_REQUIRED).

### 10. AI ENGINEERING CONNECTION

Relevant to training-data filtering (Tier 9), fine-tuning on customer data (Tier 10) and RAG over private documents.

### 11. ADVANTAGES

- Quantifies a legal risk.

### 12. LIMITATIONS

- Cannot prove absence; detectors miss novel PII formats.

### 13. TRADE-OFFS

- Stronger probing costs compute and exposes test secrets.

### 14. COMMON MISTAKES

- Claiming zero risk from zero observed leaks.
- Using real customer PII in the test set unprotected.

### 15. PERFORMANCE / COST CONSIDERATIONS

Probe volume vs bound tightness: halving the bound doubles probes.

### 16. SECURITY CONSIDERATIONS

Evaluation data and logs may themselves contain PII: use synthetic canaries and access controls.

### 17. INTERVIEW EXPLANATION

Privacy evaluation probes for verbatim extraction, PII in outputs, membership inference and prompt/context leakage, often with planted canaries. I report leak rates with confidence bounds, never claim zero from zero observations, and treat the detector's own precision and recall as part of the result.

### 18. RAPID-FIRE ANSWER

Probe, canary, detect, bound; zero observed is not zero risk.

### 19. INTERVIEW QUESTIONS

- **Basic:** What is a canary?
- **Intermediate:** What does 0 leaks in 1000 probes tell you?
- **Advanced:** What is membership inference?
- **Scenario:** Customer asks for proof that their data was not memorised; what can you provide?
