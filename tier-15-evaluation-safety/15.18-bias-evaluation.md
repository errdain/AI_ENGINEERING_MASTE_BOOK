### 1. WHAT IS IT?

Bias evaluation measures whether model behaviour differs systematically across groups (gender, ethnicity, religion, language, age) in ways that are unfair or stereotyped.

### 2. WHY DOES IT EXIST?

Foundation models absorb societal patterns from data. Unmeasured bias becomes discrimination at scale.

### 3. DETAILED EXPLANATION

Two families of measurement:
1. **Outcome/decision metrics** (for classifiers and rankers): per-group selection rate, TPR, FPR; gaps such as demographic-parity difference (max-min selection rate) and equalized-odds difference (max TPR or FPR gap). Hand check in the lab tests.
2. **Generation/representation probes**: templated prompts that vary only a group term and compare sentiment, toxicity, refusal or stereotype-consistent answers (BBQ-style QA, counterfactual pairs; REVIEW_REQUIRED for dataset details).

Practice: use counterfactual pairs (swap the group term), report per-group sample sizes and CIs (small groups are noisy), slice by intersection, and keep **measurement** (here) separate from **normative choice of what is fair** (""[15.19 Fairness considerations](15.19-fairness-considerations.md)""). Figure 7 and the explorer show how gap metrics move with group rates.

### 4. HOW DOES IT WORK?

Define groups and attributes (legally and ethically reviewed) -> build counterfactual or labelled data -> compute per-group rates -> compute gaps with CIs -> investigate causes.

### 5. SIMPLE EXAMPLE

Giving two identical CVs that differ only in the name and checking if the replies differ.

### 6. TECHNICAL EXAMPLE

Resume-screening classifier: group selection rates 0.48 vs 0.21 (DP gap 0.27) while TPR/FPR are equal across groups (EO gap 0), because the base rates differ.

### 7. CODE

```python
# run inside lab/
import numpy as np
from metrics import group_rates, demographic_parity_diff, equalized_odds_diff
y = np.array([1]*50 + [0]*50 + [1]*10 + [0]*90); g = np.array(["a"]*100 + ["b"]*100)
pred = y.copy()                                   # a perfect classifier
print(group_rates(y, pred, g))
print("DP gap", demographic_parity_diff(pred, g), "EO gap", equalized_odds_diff(y, pred, g))
```

### 8. INPUT → PROCESS → OUTPUT

```
model + group-labelled or counterfactual data -> per-group rates -> gap metrics + CIs
```

### 9. ENTERPRISE USE CASE

Regulated uses (hiring, lending) require documented bias testing; sensitive attributes are held in a separate, access-controlled evaluation store.

### 10. AI ENGINEERING CONNECTION

Generative bias probes (stereotype QA, counterfactual prompts) extend classic fairness metrics to LLMs.

### 11. ADVANTAGES

- Makes disparities visible and trackable.

### 12. LIMITATIONS

- Needs group labels (privacy trade-off); metrics can conflict; templated probes have limited validity.

### 13. TRADE-OFFS

- Which metric to prioritise is a value judgement.

### 14. COMMON MISTAKES

- Reporting only the aggregate; tiny groups without CIs; assuming one metric means 'fair'.

### 15. PERFORMANCE / COST CONSIDERATIONS

Cheap once data exists; collection is the hard part.

### 16. SECURITY CONSIDERATIONS

Group-attribute data is itself sensitive; minimise, protect and document use.

### 17. INTERVIEW EXPLANATION

Bias evaluation measures group-wise differences: outcome gaps (selection, TPR, FPR) and generative probes with counterfactual prompts. I report per-group rates with CIs and intersections, and keep measurement separate from the normative question of which fairness criterion applies.

### 18. RAPID-FIRE ANSWER

Per-group rates, gaps with CIs, counterfactual pairs.

### 19. INTERVIEW QUESTIONS

- **Basic:** What is demographic parity?
- **Intermediate:** How do you probe an LLM for bias?
- **Advanced:** Why can demographic parity and equalized odds not both hold?
