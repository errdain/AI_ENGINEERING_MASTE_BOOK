### 1. WHAT IS IT?

**Weight tying** shares one matrix between the input embedding `E (V x d)` and the output head `W (d x V)`: `W = E^T`. One parameter tensor, two uses.

### 2. WHY DOES IT EXIST?

The embedding table is `V*d` parameters; for large vocabularies it is a big share of a small model. Tying removes it and acts as a regulariser (Press & Wolf 2017; Inan et al. 2016).

### 3. DETAILED EXPLANATION

- Saves `V*d` parameters: for `V=50k, d=768` about 38 M, a quarter of the untied 163 M-parameter model; for very large models the saving is a small fraction and some families leave it untied (`REVIEW_REQUIRED` per model).
- In PyTorch tying is *sharing the same Parameter* (`head.weight = tok.weight`); `model.parameters()` counts it once while `state_dict()` contains both keys: a source of off-by-`V*d` counting bugs.
- The original Transformer shared embeddings too.

{fig('12_weight_tying_savings.png', 'Figure 12 - Left: total parameters tied vs untied for three configs. Right: percentage saved by tying: 1.1 % for Mini-GPT, 23.7 % for GPT-2-small shape, 7.3 % for a larger d=2048 model.')}

### 4. HOW DOES IT WORK?

1. Create `E`. 2. Set `head.weight = E.weight`. 3. Gradients from input and output both update `E`.

### 5. SIMPLE EXAMPLE

One dictionary used both to look words up and to decide which word to write: the same meaning map in both directions.

### 6. TECHNICAL EXAMPLE

Mini-GPT: tying saves `41*96 = 3,936` of 349,728 (1.1 %); GPT-2-small shape: saves `50257*768 = 38,597,376`.

### 7. CODE

```python
from mini_gpt import GPTConfig, MiniGPT, count_params, count_params_formula

cfg = dict(vocab_size=41, block_size=64, n_layer=3, n_head=4, d_model=96)
tied, untied = MiniGPT(GPTConfig(**cfg)), MiniGPT(GPTConfig(**cfg, tie_weights=False))
assert tied.head.weight is tied.tok.weight
assert count_params(untied) - count_params(tied) == 41 * 96
print(len(tied.state_dict()), len(list(tied.parameters())))     # state_dict has both keys, parameters() counts once
```

### 8. INPUT → PROCESS → OUTPUT

```
token id -> E[id] (d) ... blocks ... -> final h (d) -> h E^T (V logits)
```

### 9. ENTERPRISE USE CASE

Counting bugs when comparing to a model card; checkpoint converters must handle the duplicated keys.

### 10. AI ENGINEERING CONNECTION

Used by GPT-2-style models; relevant to fine-tuning embeddings (Tier 10).

### 11. ADVANTAGES

Fewer parameters; regularisation; consistent input/output geometry.

### 12. LIMITATIONS

Constrains the output space; less useful for huge models.

### 13. TRADE-OFFS

Fewer parameters versus flexibility.

### 14. COMMON MISTAKES

Counting twice; saving/loading mismatched keys; forgetting tying when converting.

### 15. PERFORMANCE / COST CONSIDERATIONS

Saves `V*d` memory and gradient state.

### 16. SECURITY CONSIDERATIONS

Pickle-format checkpoints execute code when loaded; use `safetensors`.

### 17. INTERVIEW EXPLANATION

*"Weight tying makes the output head reuse the input embedding matrix. It saves V times d parameters and regularises; in PyTorch the same Parameter is shared so parameters() counts it once."*

### 18. RAPID-FIRE ANSWER

Tying: one matrix for reading tokens and for writing them.
