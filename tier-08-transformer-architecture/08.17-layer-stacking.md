### 1. WHAT IS IT?

**Layer stacking** composes `L` blocks sequentially: `x_L = B_L(...B_2(B_1(x_0)))`, each block with its **own weights**, all reading from and writing to the same-shaped residual stream.

### 2. WHY DOES IT EXIST?

One block can only do a limited amount of mixing and processing. Repeating it gives progressively more refined representations: more sequential computation steps.

### 3. DETAILED EXPLANATION

- Shapes are preserved, so stacking is just a loop.
- Weights are not shared (unlike a few research models with layer sharing).
- Early layers tend to capture local/syntactic features and later ones more abstract features in many analyses (empirical, `REVIEW_REQUIRED` for strong claims).
- The residual stream ([8.10 Residual connections](08.10-residual-connections.md)) makes deep stacks trainable; norm placement ([8.12 Pre-LN](08.12-pre-ln.md)) decides stability.
- At inference layers cannot be parallelised across depth for a single token.

### 4. HOW DOES IT WORK?

1. Embed tokens + positions to `x_0`. 2. For `l = 1..L`: `x_l = Block_l(x_{l-1})`. 3. Final norm and head.

### 5. SIMPLE EXAMPLE

An assembly line of identical-looking workstations, each with its own tools, that progressively refine the same product.

### 6. TECHNICAL EXAMPLE

Mini-GPT: `L=3`; GPT-2 small: `L=12`; very large models around a hundred layers (`REVIEW_REQUIRED` per model).

### 7. CODE

```python
import torch
from mini_gpt import GPTConfig, MiniGPT

m = MiniGPT(GPTConfig(vocab_size=41, block_size=16, n_layer=4, n_head=2, d_model=32)).eval()
x = m.tok(torch.randint(0, 41, (1, 10))) + m.pos(torch.arange(10))
shapes = []
for b in m.blocks:                      # layer stacking = a loop over independent blocks
    x = b(x); shapes.append(tuple(x.shape))
print(shapes)
assert len(set(shapes)) == 1                                   # same shape after every block
w = [b.attn.qkv.weight for b in m.blocks]
assert all(not torch.equal(w[0], w[i]) for i in range(1, 4))   # independent weights per layer
```

### 8. INPUT → PROCESS → OUTPUT

```
x0 -> Block1 -> x1 -> Block2 -> x2 -> ... -> BlockL -> xL -> final norm -> head
```

### 9. ENTERPRISE USE CASE

Layer count drives latency (sequential) and memory; deployment teams quote it in model cards.

### 10. AI ENGINEERING CONNECTION

Layer pruning, early exit, distillation to fewer layers and pipeline-parallel training are all about this axis.

### 11. ADVANTAGES

Simple; scalable; trainable.

### 12. LIMITATIONS

Sequential latency; training stability limits depth; diminishing returns.

### 13. TRADE-OFFS

Depth versus latency and training stability ([8.20 Number of layers](08.20-number-of-layers.md)).

### 14. COMMON MISTAKES

Believing parameters, not stability, limit depth; sharing weights by accident; forgetting final norm.

### 15. PERFORMANCE / COST CONSIDERATIONS

Parameters and latency grow linearly with `L`.

### 16. SECURITY CONSIDERATIONS

Per-layer activations can be inspected; leaking them can reveal training data (research-level concern).

### 17. INTERVIEW EXPLANATION

*"Layer stacking just applies N independent blocks in sequence on the residual stream. Each layer refines the representation; depth gives more sequential computation but costs linear latency and needs stable training."*

### 18. RAPID-FIRE ANSWER

Stacking = `L` independent blocks in a row on one residual stream.

### 19. INTERVIEW QUESTIONS

**Basic.** How are layers connected? **Intermediate.** Are weights shared? **Advanced.** What limits depth in practice? **Scenario.** Latency too high: what does cutting layers trade away?
