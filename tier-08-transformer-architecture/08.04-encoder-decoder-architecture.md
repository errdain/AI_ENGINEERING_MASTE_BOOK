### 1. WHAT IS IT?

The **encoder-decoder architecture** (structure) joins an encoder stack and a decoder stack with one connection: **cross-attention** from every decoder layer to the final encoder output. This concept is about *how the two stacks are wired and counted*; [8.27 Encoder-decoder architecture](08.27-encoder-decoder-architecture.md) (listed again later in the roadmap) covers the *family*, when to choose it and how it compares with the other two.

### 2. WHY DOES IT EXIST?

Sequence-to-sequence tasks have a clear input and a clear output. Reading the input bidirectionally once and then generating conditioned on it separates understanding from generation.

### 3. DETAILED EXPLANATION

- The encoder runs **once** on the source: `memory (B,S,d)`.
- Each decoder layer: causal self-attention over target tokens, then cross-attention with `Q` from the decoder and `K,V` from `memory`, then FFN.
- The only data path from source to target is cross-attention; remove it and the decoder is a language model that ignores the input.
- Parameters per layer: encoder `~12 d^2`, decoder `~16 d^2` (extra `4 d^2`).

### 4. HOW DOES IT WORK?

1. Encode the source once (cache `memory`).
2. For each target step, self-attend causally, cross-attend to `memory`, apply the FFN.
3. Project to vocabulary logits; sample or take argmax; append and repeat.
4. Training uses teacher forcing: all target positions in parallel, loss on shifted targets.

### 5. SIMPLE EXAMPLE

A translator who first reads the whole paragraph, keeps notes (the memory), then writes the translation sentence by sentence, glancing back at the notes.

### 6. TECHNICAL EXAMPLE

Summarising a 2000-token article: the encoder reads all of it once; the decoder writes a 100-token summary, each token attending over the 2000 encoder vectors.

### 7. CODE

```python
import torch, torch.nn as nn

d = 64
model = nn.Transformer(d_model=d, nhead=4, num_encoder_layers=2, num_decoder_layers=2,
                       dim_feedforward=256, dropout=0.0, batch_first=True, norm_first=True).eval()
src, tgt = torch.randn(2, 9, d), torch.randn(2, 4, d)
mask = nn.Transformer.generate_square_subsequent_mask(4)
out = model(src, tgt, tgt_mask=mask)
print(out.shape)                                           # (2, 4, 64)
enc = sum(p.numel() for p in model.encoder.layers[0].parameters())
dec = sum(p.numel() for p in model.decoder.layers[0].parameters())
print(enc, dec, dec - enc)       # decoder layer = encoder layer + one extra attention block (~4d^2)
assert abs((dec - enc) - (4 * d * d + 4 * d + 2 * d)) < 1     # extra attention + its LayerNorm
```

### 8. INPUT → PROCESS → OUTPUT

```
src (B,S) -> [Encoder] -> memory (B,S,d) --K,V--+
tgt (B,T) -> [Decoder: self-attn -> cross-attn <-+ -> FFN] -> logits (B,T,V)
```

### 9. ENTERPRISE USE CASE

Document translation, summarisation, data-to-text and structured rewriting services where a smaller specialised model beats a general LLM on cost.

### 10. AI ENGINEERING CONNECTION

Background for T5/BART-family models ([8.28 T5/BART](08.28-t5-bart.md)) and for speech models that decode text from audio encoders (later tiers). Retrieval-augmented generation can be viewed as cross-attention to external memory, but implemented through the prompt in decoder-only models.

### 11. ADVANTAGES

Clean separation of reading and writing; bidirectional source understanding; efficient when the source is long and output short (encode once).

### 12. LIMITATIONS

Two stacks to deploy and shard; cross-attention adds parameters and a KV cache for memory; less common in general-purpose LLMs so tooling support is thinner.

### 13. TRADE-OFFS

Task fit and parameter efficiency versus serving complexity and a smaller ecosystem.

### 14. COMMON MISTAKES

Confusing the encoder mask (full) with the cross-attention mask (full over source, padding only); recomputing the encoder at every decode step; forgetting the extra `4d^2` per decoder layer when counting.

### 15. PERFORMANCE / COST CONSIDERATIONS

Encoder cost is paid once per input; decoder cost per output token includes self-attention over the prefix and cross-attention over `S` source tokens, so long sources increase every step.

### 16. SECURITY CONSIDERATIONS

Source text content flows into every decoder step: prompt-injection-style attacks on summarisers act through the source. Sanitise and bound the source length.

### 17. INTERVIEW EXPLANATION

*"An encoder-decoder runs a bidirectional encoder once over the source and a causal decoder that cross-attends to the encoder output at every layer. Cross-attention is the only link between the stacks. It suits translation and summarisation; the cost is two stacks and about 4d-squared extra parameters per decoder layer."*

### 18. RAPID-FIRE ANSWER

Two stacks, one bridge: decoder queries read encoder keys and values.
