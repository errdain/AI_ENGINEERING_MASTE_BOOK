### 1. WHAT IS IT?

**SwiGLU** is a *gated* FFN (Shazeer 2020, *GLU Variants Improve Transformer*): `FFN(x) = (SiLU(x W_gate) * (x W_up)) W_down`. A learned, input-dependent gate multiplies a linear value.

### 2. WHY DOES IT EXIST?

A gated unit lets the token decide how open each hidden unit is; empirically gated FFNs improve quality at equal parameters (`REVIEW_REQUIRED` on the size of the effect).

### 3. DETAILED EXPLANATION

- **Three matrices** instead of two, so to keep parameters equal `d_ff` shrinks to about `(8/3) d`, usually rounded to a hardware-friendly multiple (e.g. 4096 -> 11008 in a well-known 7 B family; `REVIEW_REQUIRED`).
- Cost: three matmuls, more weight-conversion bookkeeping (`gate` vs `up` order is a classic checkpoint-loading error).
- Used by many recent open model families (`REVIEW_REQUIRED` per model card).

### 4. HOW DOES IT WORK?

1. `gate = SiLU(x W_gate)`. 2. `value = x W_up`. 3. `h = gate * value`. 4. `out = h W_down`.

### 5. SIMPLE EXAMPLE

A tap with two controls: one is the amount of water (value), the other (the gate) decides how far the tap opens for this particular token.

### 6. TECHNICAL EXAMPLE

For `d=96`: a GELU FFN has `d_ff=384` and `2*96*384 = 73,728` weights; a SwiGLU FFN with `d_ff=256` has `3*96*256 = 73,728` weights - equal.

### 7. CODE

```python
import torch
from mini_gpt import GPTConfig, MLP

d = 96
gelu = MLP(GPTConfig(vocab_size=41, block_size=16, n_layer=1, n_head=4, d_model=d, bias=False))
swi = MLP(GPTConfig(vocab_size=41, block_size=16, n_layer=1, n_head=4, d_model=d, bias=False, act="swiglu", d_ff=256))
n = lambda m: sum(p.numel() for p in m.parameters())
print(n(gelu), n(swi))                    # 73728 73728
assert n(gelu) == n(swi)
x = torch.randn(2, 5, d)
assert torch.allclose(swi(x), swi.down(torch.nn.functional.silu(swi.gate(x)) * swi.up(x)), atol=1e-6)
```

### 8. INPUT → PROCESS → OUTPUT

```
x -> gate path: x W_gate -> SiLU --+
                                    * -> W_down -> out
x -> value path: x W_up -------------+
```

### 9. ENTERPRISE USE CASE

Checkpoint conversion bugs (swapped gate/up) give garbage with no error; always check logits against a reference.

### 10. AI ENGINEERING CONNECTION

Standard in many recent open LLM families alongside RMSNorm ([8.14 RMSNorm](08.14-rmsnorm.md)); see [Tier 12 — Modern architectures](../tier-12-modern-architectures/).

### 11. ADVANTAGES

Better quality at equal parameters (reported); input-dependent gating.

### 12. LIMITATIONS

Three matmuls; more bookkeeping; `d_ff` rounding choices.

### 13. TRADE-OFFS

Quality versus implementation complexity.

### 14. COMMON MISTAKES

Using `d_ff = 4d` with SwiGLU (50 % larger FFN); swapping gate and up weights; counting two matrices in the formula.

### 15. PERFORMANCE / COST CONSIDERATIONS

Equal parameters at `d_ff = 8d/3` but three smaller matmuls; fused kernels help.

### 16. SECURITY CONSIDERATIONS

Same conversion-integrity concerns; hash and parity-test converted weights.

### 17. INTERVIEW EXPLANATION

*"SwiGLU multiplies a SiLU-gated projection by a linear projection before the down projection. It uses three matrices, so the hidden size is cut to about 8/3 of d to keep parameters equal, and it tends to improve quality, which is why many recent LLMs use it."*

### 18. RAPID-FIRE ANSWER

SwiGLU: a learned gate decides how much of each hidden unit passes.
