### 1. WHAT IS IT?

The **position-wise MLP** is the property that the FFN applies the *same* weights to *each token vector independently*; nothing flows between positions inside it. It is the same module as [8.8 Feed-forward network](08.08-feed-forward-network.md), seen through its sharing property.

### 2. WHY DOES IT EXIST?

It makes the FFN trivially parallel over `B*T` tokens and cleanly separates "communicate" (attention) from "compute" (MLP).

### 3. DETAILED EXPLANATION

In the 2017 paper the FFN is described as "two convolutions with kernel size 1", i.e. a linear layer applied at every position. Implementation: reshape `(B,T,d) -> (B*T,d)`, apply the MLP, reshape back (PyTorch does this automatically for `nn.Linear`). Consequences: permuting tokens permutes the outputs; the FFN cost scales linearly in `T` (unlike attention); expert routing in MoE is done per token.

### 4. HOW DOES IT WORK?

1. Treat every token vector as a row in a matrix. 2. Multiply by `W_up`, apply the activation, multiply by `W_down`. 3. Reshape back.

### 5. SIMPLE EXAMPLE

A factory line where each part goes through the same machine independently of the part next to it.

### 6. TECHNICAL EXAMPLE

With `T=128` tokens the same `W_up` is applied 128 times (as one matmul); cost `~ T * 8 d^2`.

### 7. CODE

```python
import torch
from mini_gpt import GPTConfig, MLP

mlp = MLP(GPTConfig(vocab_size=41, block_size=16, n_layer=1, n_head=2, d_model=32)).eval()
x = torch.randn(1, 6, 32)
perm = torch.randperm(6)
assert torch.allclose(mlp(x)[:, perm], mlp(x[:, perm]), atol=1e-6)    # permutation-equivariant
assert torch.allclose(mlp(x)[:, 2], mlp(x[:, 2:3])[:, 0], atol=1e-6)  # token 2 alone gives the same output
```

### 8. INPUT → PROCESS → OUTPUT

```
(B,T,d) -> reshape (B*T,d) -> same MLP on every row -> reshape (B,T,d)
```

### 9. ENTERPRISE USE CASE

Tensor parallelism splits these matrices across GPUs; MoE routers pick an expert MLP per token.

### 10. AI ENGINEERING CONNECTION

Explains why only attention needs the KV cache: the FFN has no cross-position state ([Tier 11 — Inference](../tier-11-llm-inference-optimization/README.md)).

### 11. ADVANTAGES

Linear in sequence length; embarrassingly parallel; no state.

### 12. LIMITATIONS

Cannot mix neighbouring tokens; capacity is per-token only.

### 13. TRADE-OFFS

Simplicity and parallelism versus no local context mixing.

### 14. COMMON MISTAKES

Trying to give the FFN context by concatenating neighbours; forgetting that padding tokens are also processed (they must be ignored later).

### 15. PERFORMANCE / COST CONSIDERATIONS

Linear in `T`; batch tokens together for good GPU utilisation.

### 16. SECURITY CONSIDERATIONS

Because it is per-token, a token-level privacy filter placed here sees no context; filters must run on attention outputs or text.

### 17. INTERVIEW EXPLANATION

*"Position-wise means the same MLP is applied to each token on its own. Information crosses positions only in attention, which is why attention needs a KV cache and the FFN does not."*

### 18. RAPID-FIRE ANSWER

Same MLP, every token, no talking between positions.
