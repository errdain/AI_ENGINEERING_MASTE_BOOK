### 1. WHAT IS IT?

**LayerNorm** normalises each token's feature vector to zero mean and unit variance, then applies a learned scale and shift: `LN(x) = gamma * (x - mu) / sqrt(sigma^2 + eps) + beta`, with statistics computed over the feature dimension of *one token* and learned `gamma, beta` in `R^d` (`2d` parameters).

### 2. WHY DOES IT EXIST?

Activation scale drifts with depth and with the data; unnormalised deep stacks train slowly or diverge. BatchNorm depends on batch statistics, which is awkward for variable-length sequences and batch size 1 at inference. LayerNorm depends only on the token itself.

### 3. DETAILED EXPLANATION

- Identical behaviour in training and inference (no running averages).
- Works for any batch size and sequence length.
- The learned `gamma` lets the network undo the normalisation where useful; `beta` re-introduces a bias.
- `eps` (typically 1e-5 or 1e-6) prevents division by zero.
- Placement matters: [8.12 Pre-LN](08.12-pre-ln.md) vs [8.13 Post-LN](08.13-post-ln.md).

### 4. HOW DOES IT WORK?

1. Compute `mu = mean(x)` and `sigma^2 = mean((x-mu)^2)` over the last axis.
2. Subtract `mu`, divide by `sqrt(sigma^2 + eps)`.
3. Multiply by `gamma`, add `beta` (both per feature).

### 5. SIMPLE EXAMPLE

Grading on a curve per student: each token's scores are re-centred and rescaled so no single token's numbers dominate.

### 6. TECHNICAL EXAMPLE

In the trained Mini-GPT every block has two LayerNorms and Pre-LN adds a final one: `(2*3 + 1) * 2d = 14 * 96 = 1344` parameters for `d=96, L=3`.

### 7. CODE

```python
import torch, torch.nn as nn

x = torch.randn(4, 6, 16) * 3 + 2          # (B, T, d) with offset and scale
mu = x.mean(-1, keepdim=True)
var = x.var(-1, unbiased=False, keepdim=True)
ln = nn.LayerNorm(16, eps=1e-5)
manual = (x - mu) / torch.sqrt(var + 1e-5) * ln.weight + ln.bias
assert torch.allclose(ln(x), manual, atol=1e-5)
assert ln(x).mean(-1).abs().max() < 1e-5   # per-token zero mean
print(sum(p.numel() for p in ln.parameters()), "parameters (2d)")
```

### 8. INPUT → PROCESS → OUTPUT

```
token vector (d) -> subtract mean -> divide by std -> * gamma + beta -> normalised vector (d)
```

### 9. ENTERPRISE USE CASE

Model-conversion pipelines must keep `eps` and the norm type identical to the source model or outputs drift.

### 10. AI ENGINEERING CONNECTION

Instability at long training, bf16 overflow and loss spikes are often diagnosed via norm placement, epsilon and stream scale.

### 11. ADVANTAGES

Stable activations; batch-independent; simple.

### 12. LIMITATIONS

Extra memory traffic; mean subtraction costs a pass; does not by itself guarantee gradient stability.

### 13. TRADE-OFFS

Quality and stability versus the extra cost that RMSNorm ([8.14 RMSNorm](08.14-rmsnorm.md)) removes.

### 14. COMMON MISTAKES

Normalising over the wrong axis (batch instead of features); forgetting `eps`; comparing biased vs unbiased variance; wrong `eps` when porting weights.

### 15. PERFORMANCE / COST CONSIDERATIONS

Memory-bandwidth bound; fused kernels matter; `2d` parameters per norm (small).

### 16. SECURITY CONSIDERATIONS

Wrong epsilon or dtype can silently change outputs of a converted checkpoint; always run a numerical parity test.

### 17. INTERVIEW EXPLANATION

*"LayerNorm standardises each token's feature vector to zero mean and unit variance, then applies a learned scale and shift. Unlike batch norm it does not depend on the batch, so training and inference behave the same and sequence length does not matter. Where it is placed, before or after the residual add, decides how deep models train."*

### 18. RAPID-FIRE ANSWER

Per-token standardisation over features with a learned scale and shift.
