### 1. WHAT IS IT?

**Decoder-only architecture** is the family built from decoder blocks with **causal** self-attention and *no* cross-attention, trained with the causal objective ([8.29 Causal objective](08.29-causal-objective.md)). Generation is autoregressive: predict the next token, append, repeat.

### 2. WHY DOES IT EXIST?

One architecture, one objective (next-token prediction), every training position gives a signal, and prompting handles many tasks without task heads; it is the simplest recipe to scale and to serve.

### 3. DETAILED EXPLANATION

- Conditioning is done by placing context in the prompt; the model reads it with ordinary self-attention.
- Serving uses a KV cache so each new token costs one pass over the new position only ([Tier 11 — Inference](../tier-11-llm-inference-optimization/README.md)).
- The Mini-GPT in this tier is a decoder-only model; GPT-2 is the template it follows ([8.26 GPT](08.26-gpt.md)).
- Why it won for general LLMs: single objective, all positions supervised, simpler serving, in-context learning (nuanced and empirical: `REVIEW_REQUIRED`).

### 4. HOW DOES IT WORK?

1. Tokenise the prompt. 2. Forward pass with causal mask: logits `(B,T,V)`. 3. Take the last position's distribution, sample. 4. Append and repeat.

### 5. SIMPLE EXAMPLE

A person finishing your sentences, one word at a time, based only on what has been said so far.

### 6. TECHNICAL EXAMPLE

The lab's `MiniGPT.generate` samples from a trained 345,792-parameter model.

### 7. CODE

```python
import json, torch, pathlib
from mini_gpt import GPTConfig, MiniGPT

out = pathlib.Path("outputs"); h = json.loads((out / "train_log.json").read_text())
chars = json.loads((out / "chars.json").read_text()); stoi = {c: i for i, c in enumerate(chars)}
cfg = GPTConfig(vocab_size=len(chars), block_size=h["block"], n_layer=h["n_layer"], n_head=h["n_head"], d_model=h["d_model"])
m = MiniGPT(cfg)
sd = torch.load(out / "mini_gpt_fp16.pt", map_location="cpu", weights_only=True)
m.load_state_dict({k: v.float() for k, v in sd.items()}, strict=False)
torch.manual_seed(0)
idx = torch.tensor([[stoi[c] for c in "The "]])
text = "".join(chars[i] for i in m.generate(idx, 80, temperature=0.8, top_k=8)[0].tolist())
print(text)
assert text.startswith("The ") and len(text) == 84
```

### 8. INPUT → PROCESS → OUTPUT

```
prompt -> [causal blocks x L] -> logits -> sample -> append -> (loop)
```

### 9. ENTERPRISE USE CASE

Chat assistants, code assistants, document drafting, agents.

### 10. AI ENGINEERING CONNECTION

Foundation of LLM products, RAG (context in prompt) and agents; pre-training ([Tier 9 — Pre-training](../tier-09-foundation-model-pretraining/README.md)), fine-tuning ([Tier 10 — Fine-tuning](../tier-10-fine-tuning-alignment/README.md)), inference ([Tier 11 — Inference](../tier-11-llm-inference-optimization/README.md)).

### 11. ADVANTAGES

Simple; scalable; flexible via prompting; efficient serving with KV cache.

### 12. LIMITATIONS

Sequential generation; unidirectional context; quadratic attention.

### 13. TRADE-OFFS

Generality versus per-token latency and unidirectional context.

### 14. COMMON MISTAKES

Using a causal LM directly for embeddings without pooling/training; leaking future tokens; ignoring context limits.

### 15. PERFORMANCE / COST CONSIDERATIONS

Cost per token ~`2N` FLOPs; KV cache memory grows with context.

### 16. SECURITY CONSIDERATIONS

Prompt injection and data exfiltration act through the prompt context; covered in later tiers.

### 17. INTERVIEW EXPLANATION

*"Decoder-only models use causal self-attention and are trained to predict the next token. Generation repeats predict-and-append. It is the dominant LLM design because one objective supervises every position, conditioning is just prompting, and serving is a single stack with a KV cache."*

### 18. RAPID-FIRE ANSWER

Causal blocks, next-token objective, generate by appending.
