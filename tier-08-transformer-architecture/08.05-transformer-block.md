### 1. WHAT IS IT?

A **Transformer block** is the repeating unit: one attention sub-layer and one feed-forward sub-layer, each wrapped in a residual connection and a normalisation. Input and output are both `(B, T, d_model)`, so blocks stack freely. In Pre-LN form: `x -> x + Attention(Norm(x)) -> x + FFN(Norm(x))`.

### 2. WHY DOES IT EXIST?

Deep networks need a layer that (a) mixes information between positions, (b) transforms each position non-linearly, and (c) keeps shapes and gradients well behaved so dozens of copies can be trained. The block packages exactly that.

### 3. DETAILED EXPLANATION

**Division of labour.** Attention is the only place information moves *between positions*; the FFN works on each position alone and holds most of the parameters. A widely used working hypothesis is that FFN layers act as key-value memories storing factual associations; it is empirical, not proven (`REVIEW_REQUIRED` for any strong claim).

**Shapes.** `(B,T,d)` everywhere on the residual stream; `(B,T,3d)` inside the fused QKV projection; `(B,h,T,T)` for scores; `(B,T,d_ff)` inside the FFN.

**Two layouts.** Post-LN ([8.13 Post-LN](08.13-post-ln.md)) is the 2017 form; Pre-LN ([8.12 Pre-LN](08.12-pre-ln.md)) is what most modern LLMs use.

### 4. HOW DOES IT WORK?

1. **Norm** the stream per token.
2. **Attention sub-layer**: project to Q, K, V; split into `h` heads of width `d_k = d/h`; scores `QK^T/sqrt(d_k)`; mask; softmax; weight the values; concatenate heads; output projection `W_O` (mathematics: Tier 7).
3. **Add** the result back to the stream.
4. **Norm** again.
5. **FFN sub-layer**: expand `d -> d_ff`, non-linearity, project back to `d`.
6. **Add** again.

### 5. SIMPLE EXAMPLE

A shared document: each editor (block) first reads a tidy copy (norm), writes a suggested change (attention or FFN output), and the change is *added* to the document rather than replacing it.

### 6. TECHNICAL EXAMPLE

For `B=4, T=128, d=512, h=8, d_ff=2048`: stream `(4,128,512)`; QKV `(4,128,1536)`; per-head Q,K,V `(4,8,128,64)`; scores `(4,8,128,128)`; FFN hidden `(4,128,2048)`; block output `(4,128,512)`. The block has about `12 d^2 = 3.1 M` weights.

### 7. CODE

```python
import torch
from mini_gpt import GPTConfig, Block

cfg = GPTConfig(vocab_size=41, block_size=16, n_layer=1, n_head=4, d_model=64)
blk = Block(cfg).eval()
x = torch.randn(2, 10, 64)
y = blk(x)
assert y.shape == x.shape                       # (B, T, d) in and out
# the whole Pre-LN block is two residual lines (see Block.forward in lab/mini_gpt.py):
#   x = x + attn(norm1(x));  x = x + mlp(norm2(x))
manual = x + blk.attn(blk.n1(x)); manual = manual + blk.mlp(blk.n2(manual))
assert torch.allclose(y, manual, atol=1e-6)
print("block output", tuple(y.shape))
```

Full code: [`lab/mini_gpt.py`](lab/mini_gpt.py) (`Block`).

### 8. INPUT → PROCESS → OUTPUT

```
x (B,T,d) -+-> Norm -> Attention --(+)-+-> Norm -> FFN --(+)--> x' (B,T,d)
           +---------- skip -----------+  +-------- skip -------+
```

### 9. ENTERPRISE USE CASE

Every LLM an enterprise buys, hosts or fine-tunes is a stack of these blocks; capacity planning (GPU memory, latency) is block arithmetic times layer count.

### 10. AI ENGINEERING CONNECTION

Understanding the block lets you read a model card, size a deployment, debug a conversion script (norm placement, gate/up order, head layout) and explain where RAG context ends up (in the attention keys/values of every block).

### 11. ADVANTAGES

Uniform and scalable by changing `L`, `d`, `h`; parallel over `T` in training; the same code serves encoders and decoders (only the mask differs).

### 12. LIMITATIONS

Attention memory/compute grows `O(T^2)` ([Tier 7 — Attention](../tier-07-attention/README.md), [Tier 11 — Inference](../tier-11-llm-inference-optimization/README.md)); no built-in sense of order ([Tier 6 — Tokenization & Embeddings](../tier-06-tokenization-embeddings/README.md)); the sequential block chain limits inference latency.

### 13. TRADE-OFFS

Width vs depth vs context length vs cost ([8.18 Hidden dimension](08.18-hidden-dimension.md), [8.20 Number of layers](08.20-number-of-layers.md)).

### 14. COMMON MISTAKES

`d_model` not divisible by `n_head`; adding the residual before the norm in one sub-layer and after in the other; scaling by `sqrt(d)` instead of `sqrt(d_k)`; forgetting the final norm in Pre-LN stacks.

### 15. PERFORMANCE / COST CONSIDERATIONS

About `12 d^2` parameters and `~24 d^2` forward FLOPs per token per block, plus an attention term growing with `T`.

### 16. SECURITY CONSIDERATIONS

A mask bug is a data-leak bug: the model sees the answer in training and fails in production ([8.29 Causal objective](08.29-causal-objective.md)). Config mismatch when loading checkpoints is a silent integrity failure.

### 17. INTERVIEW EXPLANATION

*"A Transformer block normalises the token stream, lets attention move information between tokens, adds the result back, normalises again, and lets a feed-forward network process each token, adding that back too. Residuals keep a clean path for gradients so we can stack dozens of blocks. Attention is communication, the FFN is computation."*

### 18. RAPID-FIRE ANSWER

Block = (norm -> attention -> add) then (norm -> FFN -> add).

### 19. INTERVIEW QUESTIONS

**Basic.** What are the two sub-layers? **Intermediate.** Where do the parameters live? (about 1/3 attention, 2/3 FFN) **Advanced.** Why must every sub-layer map `d -> d`? **Scenario.** Output shape is right but loss will not fall: list five block-level bugs to check.
