### 1. WHAT IS IT?

The **feed-forward network (FFN)** is the second sub-layer of a block: two linear layers with a non-linearity between them, `FFN(x) = W_down * act(W_up * x)`, with `W_up: d -> d_ff` and `W_down: d_ff -> d`, usually `d_ff = 4d` for a GELU FFN.

### 2. WHY DOES IT EXIST?

Attention is (given the softmax weights) a *linear* mixing of value vectors. Without a non-linearity a stack of attention layers would be far less expressive. The FFN adds non-linearity and a large per-token capacity.

### 3. DETAILED EXPLANATION

- **Size.** With `d_ff = 4d` the FFN has `2*d*4d = 8d^2` weights versus attention's `4d^2`: about **two-thirds of a block's parameters** are FFN.
- **Role.** A widely used working hypothesis treats FFN layers as key-value memories that store associations; treat strong claims as `REVIEW_REQUIRED`.
- **Variants.** Gated forms such as SwiGLU ([8.16 SwiGLU](08.16-swiglu.md)) use three matrices and a smaller `d_ff`; Mixture-of-Experts replaces one FFN by many (Tier 12).

### 4. HOW DOES IT WORK?

1. Normalise the stream (Pre-LN).
2. Expand every token vector `d -> d_ff`.
3. Apply the activation ([8.15 GELU](08.15-gelu.md) / [8.16 SwiGLU](08.16-swiglu.md)).
4. Project back `d_ff -> d`.
5. Add to the stream.

### 5. SIMPLE EXAMPLE

Attention is the team meeting where people exchange information; the FFN is each person going back to their desk to think about what they heard.

### 6. TECHNICAL EXAMPLE

GPT-2 small: `d=768`, `d_ff=3072`; one FFN has `2*768*3072 + 3072 + 768 = 4,722,432` parameters (with biases) compared with `2,362,368` for attention.

### 7. CODE

```python
import torch
from mini_gpt import GPTConfig, MLP

cfg = GPTConfig(vocab_size=41, block_size=16, n_layer=1, n_head=4, d_model=96)
mlp = MLP(cfg)
n = sum(p.numel() for p in mlp.parameters())
d, ff = 96, 4 * 96
assert n == 2 * d * ff + ff + d          # = 8 d^2 + 5 d for d_ff = 4d
x = torch.randn(2, 7, d)
print(mlp(x).shape, n)
```

Code: `MLP` in [`lab/mini_gpt.py`](lab/mini_gpt.py).

### 8. INPUT → PROCESS → OUTPUT

```
x (B,T,d) -> Linear d->d_ff -> activation -> Linear d_ff->d -> (B,T,d)   (same weights for every token)
```

### 9. ENTERPRISE USE CASE

When fine-tuning with LoRA or pruning, the FFN matrices are the biggest targets; MoE serving is an FFN-routing problem.

### 10. AI ENGINEERING CONNECTION

The FFN dominates parameters and therefore memory and training FLOPs; quantisation and sparsity work on it first.

### 11. ADVANTAGES

Non-linearity; large capacity; trivially parallel; easy to shard.

### 12. LIMITATIONS

Quadratic growth in `d`; no cross-token information; most memory bandwidth at inference goes here.

### 13. TRADE-OFFS

`d_ff` multiplier versus quality and cost.

### 14. COMMON MISTAKES

Treating `d_ff` as free (doubling `d` makes the FFN 4x bigger); expecting the FFN to "see neighbours".

### 15. PERFORMANCE / COST CONSIDERATIONS

`~8 d^2` MACs per token per layer; the dominant matmul; compute-bound in training, memory-bound at small batch inference.

### 16. SECURITY CONSIDERATIONS

Memorised training data is hypothesised to sit largely in FFN weights, which matters for privacy and extraction risk (`REVIEW_REQUIRED`).

### 17. INTERVIEW EXPLANATION

*"After attention moves information between tokens, the FFN processes each token independently: expand to about four times the width, apply a non-linearity, project back. It supplies non-linearity and most of the per-layer parameters, roughly two-thirds."*

### 18. RAPID-FIRE ANSWER

Per-token two-layer MLP, `d -> 4d -> d`, holding about two-thirds of block parameters.
