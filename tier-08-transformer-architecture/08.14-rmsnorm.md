### 1. WHAT IS IT?

**RMSNorm** rescales a vector by its root mean square and a learned gain: `RMSNorm(x) = gamma * x / sqrt(mean(x^2) + eps)`. It has no mean subtraction and no bias, so `d` parameters instead of `2d` (Zhang & Sennrich, 2019).

### 2. WHY DOES IT EXIST?

LayerNorm's re-centring may not be what makes normalisation work; dropping it saves operations and memory traffic with, as reported, similar quality.

### 3. DETAILED EXPLANATION

- Fewer operations: no mean pass, no `beta`.
- Used by many recent open LLM families (verify per model card: `REVIEW_REQUIRED`).
- Preserves the mean of the input, only controlling scale.
- Implemented as `RMSNorm` in the lab; test `test_rmsnorm_unit_rms_and_layernorm_zero_mean` checks it numerically.

### 4. HOW DOES IT WORK?

1. Compute `ms = mean(x^2)` over features. 2. Multiply by `rsqrt(ms + eps)`. 3. Multiply by `gamma`.

### 5. SIMPLE EXAMPLE

Rescaling a recipe so the total amount is standard without caring about its average ingredient level.

### 6. TECHNICAL EXAMPLE

Replacing LayerNorm by RMSNorm in a Mini-GPT with `d=96`, `L=3`: `7 * 96 = 672` norm parameters instead of `1344`.

### 7. CODE

```python
import torch
from mini_gpt import RMSNorm, GPTConfig, MiniGPT, count_params, count_params_formula

x = torch.randn(4, 6, 32) * 5 + 3
n = RMSNorm(32)
y = n(x)
assert torch.allclose(y.pow(2).mean(-1), torch.ones(4, 6), atol=1e-3)     # RMS 1 per token
assert y.mean(-1).abs().max() > 0.1                                       # mean NOT removed
cfg = dict(vocab_size=41, block_size=16, n_layer=2, n_head=2, d_model=32)
ln, rms = GPTConfig(**cfg), GPTConfig(**cfg, norm="rmsnorm")
print(count_params_formula(ln) - count_params_formula(rms))              # d per norm: (2*2+1)*32 = 160
assert count_params(MiniGPT(rms)) == count_params_formula(rms)
```

### 8. INPUT → PROCESS → OUTPUT

```
x (d) -> mean(x^2) -> rsqrt -> x * rsqrt * gamma -> (d)
```

### 9. ENTERPRISE USE CASE

Switching a deployed model's norm type is not a drop-in change; weights trained with one must be served with the same.

### 10. AI ENGINEERING CONNECTION

Standard in many recent LLM families together with SwiGLU ([8.16 SwiGLU](08.16-swiglu.md)); see [Tier 12 — Modern architectures](../tier-12-modern-architectures/).

### 11. ADVANTAGES

Cheaper than LayerNorm; fewer parameters; simple.

### 12. LIMITATIONS

Does not centre; sensitive to outlier features in the same way as LayerNorm.

### 13. TRADE-OFFS

Slight cost savings versus a historical default.

### 14. COMMON MISTAKES

Using LayerNorm weights in an RMSNorm graph; forgetting `eps`; assuming it has a bias.

### 15. PERFORMANCE / COST CONSIDERATIONS

Saves one reduction and `d` parameters per norm; small but measurable in bandwidth-bound inference.

### 16. SECURITY CONSIDERATIONS

Same conversion-mismatch risk as [8.11 LayerNorm](08.11-layernorm.md).

### 17. INTERVIEW EXPLANATION

*"RMSNorm divides the vector by its root mean square and applies a learned gain. It drops LayerNorm's mean subtraction and bias, so it is cheaper, and many recent LLMs use it."*

### 18. RAPID-FIRE ANSWER

RMSNorm: scale by the RMS only, no mean, no bias.
