# 1.36 Entropy

**Metadata** — Tier: 1 · Phase: 1 · Priority: P1 · Difficulty: 3/5 · Interview: Medium-High · Hands-on: Medium
Prerequisites: 1.28, 1.41 · Leads to: 1.37, 1.38, decision trees (Tier 2), perplexity, sampling

### 1. What is it?
The average surprise (information content) of a distribution:

`H(p) = −Σ p(x) log p(x)`

With `log₂` the unit is **bits**; with natural log, **nats**. Convention: `0·log 0 = 0`.

### 2. Why does it exist?
It quantifies uncertainty: how many yes/no questions, on average, to identify the outcome, or the best possible average code length for the source.

### 3. Detailed explanation
- Surprise of one outcome: `−log p(x)`; rare events are more surprising.
- Fair coin: 1 bit. Certain outcome: 0. Uniform over 8: 3 bits (tested). Maximum entropy for `K` outcomes is `log K`, achieved by the uniform distribution (tested with random distributions).
- Peaked distribution → low entropy → predictable; flat → high entropy.
- Temperature in softmax directly changes entropy (high `T` → higher entropy).
- **Perplexity** = `exp(H)` (nats) = effective number of equally likely choices; for a language model, `exp(cross-entropy)` on a test set (1.37).
- Decision trees choose splits that maximize **information gain** = reduction in entropy.
- Entropy is invariant to relabeling outcomes; it depends only on the probabilities.
- Continuous (differential) entropy exists but can be negative and is not directly comparable; this chapter covers discrete entropy.

### 4. How does it work?
Take each probability, multiply by `−log p`, sum. Terms with `p=0` contribute 0.

### 5. Simple example
Guess a number 1–8 with yes/no questions: 3 questions (3 bits). For a biased coin showing heads 99% of the time, you need far less than 1 question on average (entropy ≈ 0.08 bits).

### 6. Technical example
Monitoring the entropy of an LLM's next-token distribution flags uncertain steps; high entropy often precedes hallucination-prone content (a heuristic, not a guarantee). Dataset label entropy tells class balance.

### 7. Code
```python
import numpy as np
from info_numerics import entropy
print(entropy([0.5, 0.5]))          # 1.0 bit
print(entropy(np.full(8, 1/8)))     # 3.0 bits
print(entropy([1.0, 0.0]))          # 0.0
print(entropy([0.99, 0.01]))        # ≈ 0.081
```
TESTED: known values, base conversion, invalid distribution rejected, uniform = maximum entropy.

### 8. Input → Process → Output
`distribution p → Σ −p log p → average surprise (bits/nats)`

### 9. Enterprise use case
Data compression, anomaly detection (sudden entropy change in logs), feature engineering for tree models (information gain).

### 10. AI engineering connection
Cross-entropy loss and perplexity, sampling temperature, entropy bonuses in RL (exploration), uncertainty metrics for LLM outputs, decision trees.

### 11. Advantages
Single scalar uncertainty measure with strong theory.

### 12. Limitations
Depends on the distribution you believe; says nothing about meaning; token-level entropy is not factual uncertainty; the estimation from samples is biased for small samples.

### 13. Trade-offs
Entropy vs Gini impurity in trees (similar results, Gini cheaper); bits vs nats (just a constant factor `ln 2`).

### 14. Common mistakes
Mixing bits and nats when comparing perplexities; treating `0·log 0` as NaN; computing entropy of unnormalized scores; assuming high entropy means "wrong".

### 15. Performance / cost
`O(K)` per distribution; compute from log-probabilities (`log_softmax`) to avoid `log(0)`.

### 16. Security
Low-entropy outputs may reveal memorized content; high-entropy randomness requirements (keys, tokens) are a different, cryptographic notion.

### 17. Interview explanation
"Entropy is the average surprise of a distribution: minus the sum of p log p. A fair coin has one bit, a uniform choice over eight things has three. In ML it shows up as the floor of cross-entropy, as perplexity for language models, and in decision tree splits."

### 18. Rapid-fire
H = −Σ p log p; max at uniform (log K); perplexity = exp(H).
