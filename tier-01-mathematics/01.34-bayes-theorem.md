# 1.34 Bayes' theorem

**Metadata** — Tier: 1 · Phase: 1 · Priority: P0 · Difficulty: 3/5 · Interview: Very high · Hands-on: Medium-High
Prerequisites: 1.33 · Leads to: 1.35 MLE, Naive Bayes / Bayesian methods (Tier 2), calibration, detection systems

### 1. What is it?
A rule for reversing a conditional probability:

`P(H | E) = P(E | H) · P(H) / P(E)`

- `P(H)` — **prior**: belief before seeing evidence
- `P(E | H)` — **likelihood**: how probable the evidence is if `H` is true
- `P(E)` — **evidence** (normalizer): `Σ P(E|Hᵢ)P(Hᵢ)` by total probability
- `P(H | E)` — **posterior**: updated belief

### 2. Why does it exist?
We usually know `P(evidence | cause)` (a test's behaviour) but want `P(cause | evidence)` (is the patient sick, is this fraud, which class is it). Bayes converts one into the other.

### 3. Detailed explanation
- **Base-rate neglect:** a test with 99% sensitivity and 5% false positives for a disease with 1% prevalence gives `P(disease | positive) = 0.99·0.01 / (0.99·0.01 + 0.05·0.99) = 1/6 ≈ 16.7%`, not 99%. Most positives are false because healthy people vastly outnumber sick ones (tested). With a 50% prior the same test gives >90%.
- Posterior ∝ likelihood × prior. Use the unnormalized form and normalize at the end (`posterior_categorical`).
- **Sequential updating:** today's posterior becomes tomorrow's prior.
- **MAP estimate** = argmax posterior; MLE (1.35) is MAP with a flat prior. L2 weight decay corresponds to a Gaussian prior on weights, L1 to a Laplace prior.
- Naive Bayes classifiers assume features are conditionally independent given the class: `P(c | x) ∝ P(c) Π P(xᵢ | c)`; computed in log space (1.41).
- Bayes is a mathematical identity, always valid; *Bayesian inference* additionally treats parameters as random variables.

### 4. How does it work?
Multiply prior by likelihood for each hypothesis, sum for the evidence, divide.

### 5. Simple example
You hear hoofbeats outside: horses (common) or zebras (rare)? The prior favours horses even if zebras make the sound equally well.

### 6. Technical example
Spam filter: `P(spam | "free money") ∝ P("free money" | spam)·P(spam)`. Alert triage: `P(real incident | alert)` depends on the alert's precision *and* the incident base rate.

### 8. Input → Process → Output
`prior + likelihood → multiply → normalize by evidence → posterior`

### 9. Enterprise use case
Triage systems (fraud, security alerts, medical screening): the policy must account for base rates, otherwise teams drown in false positives or ignore real ones.

### 10. AI engineering connection
Naive Bayes, Bayesian optimization (hyperparameter search), uncertainty estimation, regularization as priors, probabilistic reasoning in agents, interpreting retrieval/classifier scores as posteriors only if calibrated.

### 11. Advantages
Principled evidence updating; handles small data with informative priors; interpretable.

### 12. Limitations
Needs priors and likelihoods that are hard to specify; exact posterior is intractable for complex models (approximations: MCMC, variational inference); Naive Bayes independence assumption is rarely true.

### 13. Trade-offs
Strong priors help with little data but bias results; weak priors let data speak but need more of it.

### 14. Common mistakes
Ignoring base rates; confusing likelihood with posterior; forgetting normalization; double-counting evidence that is not independent; treating a classifier's softmax score as the Bayesian posterior without calibration/prior-shift correction.

### 15. Performance / cost
Exact normalization sums over all hypotheses; fine for a few classes, impossible for huge discrete spaces without approximation.

### 16. Security
Adversaries can shift base rates (flood the system with benign alerts or poisoned examples) to degrade a posterior-based decision rule. Monitor prior drift.

### 17. Interview explanation
"Bayes' theorem flips a conditional: the posterior is the likelihood times the prior, normalized. The classic lesson is base rates: a 99%-sensitive test for a rare disease still gives mostly false positives, about 1 in 6 true. I apply the same thinking to fraud and alert triage."
