# 1.17 Cosine similarity

**Metadata** — Tier: 1 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: Very high · Hands-on: Very high
Prerequisites: 1.10, 1.15, 1.16 · Leads to: Tier 6 embeddings, Tier 20 RAG, Tier 7 attention intuition

### 1. What is it?
The cosine of the angle between two vectors:

`cos(a, b) = (a · b) / (‖a‖ ‖b‖)`  ∈ [−1, 1]

`1` same direction, `0` orthogonal (unrelated), `−1` opposite.

### 2. Why does it exist?
The raw dot product grows with vector length. Cosine removes magnitude so only *direction* is compared — useful when length is not meaning (document length, word frequency, embedding norm).

### 3. Detailed explanation
Derives from `a·b = ‖a‖‖b‖cosθ` (1.10). It is invariant to positive scaling: `cos(a, c·b) = cos(a, b)` for `c>0`. It is undefined for a zero vector (division by zero) — a real production edge case (empty text → zero embedding). Floating-point rounding can push the value slightly outside [−1,1]; clip before `arccos`. With **L2-normalized** vectors, cosine equals the dot product, so one normalization at ingest makes search a pure matrix multiply.

Interpretation caution: values depend on the embedding model. A "0.78" from one model is not comparable to a "0.78" from another, and thresholds must be calibrated on your data. Cosine is not a probability.

### 4. How does it work?
Dot product, divided by the product of the two L2 norms. All-pairs form: normalize rows of `X (n,d)` and `Y (m,d)`, then `X̂ Ŷᵀ` gives an `(n,m)` similarity matrix.

### 5. Simple example
Two documents with the same word proportions but one twice as long: same direction, cosine = 1.

### 6. Technical example
Semantic search: embed the query, compare to chunk embeddings, return top-k by cosine. Attention scores are dot products, i.e., cosine scaled by the vector norms.

### 7. Code
```python
import numpy as np
from linalg_core import cosine_similarity, cosine_matrix
a, b = np.array([1.0, 0.0]), np.array([1.0, 1.0])
print(cosine_similarity(a, b))             # 0.7071...
print(cosine_similarity(a, 100 * b))       # unchanged: scale invariant
X, Y = np.random.default_rng(0).standard_normal((4, 6)), np.random.default_rng(1).standard_normal((3, 6))
print(cosine_matrix(X, Y).shape)           # (4, 3)
```
TESTED: known values, scale invariance, opposite/orthogonal cases, zero-vector error, all-pairs matches pairwise.

### 8. Input → Process → Output
`two vectors → normalize (or divide) → dot product → score in [−1, 1]`

### 9. Enterprise use case
Customer-support RAG ranks knowledge-base chunks by cosine; deduplication and clustering of tickets; recommendation "similar items".

### 10. AI engineering connection
Core of embedding retrieval (Tier 20), reranking features, semantic caching (reuse an answer if a new query's cosine to a cached query exceeds a calibrated threshold), embedding evaluation.

### 11. Advantages
Length-invariant, bounded, cheap, works well for text embeddings.

### 12. Limitations
Ignores magnitude (sometimes informative); not a true metric; undefined for zero vectors; similar scores across a narrow band in high dimensions make thresholds fragile.

### 13. Trade-offs
Cosine (direction) vs dot product (direction + magnitude, can favor high-norm items) vs L2. Normalize-then-dot gives cosine at dot-product speed.

### 14. Common mistakes
Using raw dot product on unnormalized embeddings and calling it cosine; comparing scores across models; a global threshold without calibration; not handling zero vectors; confusing similarity (higher=closer) with distance (lower=closer).

### 15. Performance / cost
`O(d)` per pair. Pre-normalize at write time to avoid repeated norm computation. 10⁶ docs × 1536-d float32 ≈ 6 GB; ANN indexing is needed beyond brute force at scale.

### 16. Security
Semantic caching on cosine thresholds can return another user's cached answer if the cache is not scoped per tenant/permissions. Retrieval must filter by access rights.

### 17. Interview explanation
"Cosine similarity is the dot product divided by the two vector lengths, so it measures only the angle between them. I use it for embeddings because length isn't meaning. If I normalize vectors once at ingest, cosine becomes just a dot product, which is fast. I'd calibrate thresholds on real data because scores aren't comparable across models."
