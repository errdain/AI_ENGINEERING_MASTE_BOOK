# 1.14 Matrix inverse

**Metadata** — Tier: 1 · Phase: 1 · Priority: P1 · Difficulty: 3/5 · Interview: Medium · Hands-on: High
Prerequisites: 1.11, 1.13 · Leads to: linear regression (Tier 2), 1.19 SVD, pseudo-inverse

### 1. What is it?
For a square matrix `A`, its inverse `A⁻¹` satisfies `AA⁻¹ = A⁻¹A = I`. It "undoes" the transformation `A`.

### 2. Why does it exist?
To solve `Ax = b` as `x = A⁻¹b`, and to reverse linear transformations.

### 3. Detailed explanation
`A⁻¹` exists only if `A` is square and **full rank** (determinant ≠ 0; columns linearly independent). Otherwise `A` is *singular*: it collapses some direction, and information is lost. Properties: `(AB)⁻¹ = B⁻¹A⁻¹`, `(Aᵀ)⁻¹ = (A⁻¹)ᵀ`.

Numerically, "invertible" is not binary. The **condition number** `κ(A) = σ_max/σ_min` (see 1.19) measures how much errors get amplified: a `κ` near `1/ε_machine` means the inverse is meaningless. Example: `[[1, 1.0000001],[1, 1]]` has `κ ≈ 4×10⁷`.

### 4. How does it work?
Gauss–Jordan elimination: augment `[A | I]`, row-reduce (with partial pivoting for stability) until the left side is `I`; the right side is `A⁻¹`. Cost `O(n³)`.

### 5. Simple example
Undo a rotation by rotating back; undo "multiply by 2" by "multiply by ½".

### 6. Technical example
Linear regression normal equations: `w = (XᵀX)⁻¹Xᵀy`. In practice solve via QR/SVD/`solve` instead of forming the inverse.

### 7. Code
```python
import numpy as np
from linalg_core import inverse_manual
A = np.array([[4., 1.], [2., 3.]])
Ai = np.array(inverse_manual(A.tolist()))      # [[0.3,-0.1],[-0.2,0.4]]
assert np.allclose(A @ Ai, np.eye(2))
x = np.linalg.solve(A, np.array([1., 2.]))     # preferred over Ai @ b
```
TESTED: matches `np.linalg.inv`, round-trip to `I`, singular and non-square inputs raise, `solve` residual (`test_linalg_core.py`).

### 8. Input → Process → Output
`A (n,n) full rank → pivoted elimination → A⁻¹ (n,n)`

### 9. Enterprise use case
Analytic/regression models in risk or forecasting pipelines where the normal equations are solved; monitoring `κ` flags unstable feature sets.

### 10. AI engineering connection
Closed-form linear models, Gaussian processes, whitening, natural-gradient/second-order methods. Deep learning almost never explicitly inverts large matrices; it uses gradient methods instead.

### 11. Advantages
Exact solution for well-conditioned small systems; conceptually clean.

### 12. Limitations
`O(n³)` time, `O(n²)` memory; unstable for ill-conditioned matrices; undefined for singular or non-square matrices.

### 13. Trade-offs
`solve`/factorization (LU, Cholesky, QR) is faster and more accurate than forming `A⁻¹`; the explicit inverse is only worth it when you need it many times or for the inverse itself.

### 14. Common mistakes
Computing `inv(A) @ b` instead of `solve(A, b)`; ignoring conditioning; inverting `XᵀX` with collinear features; assuming a "small determinant" test is reliable (determinant scales with units).

### 15. Performance / cost
`≈ 2n³` FLOPs for inversion. A 10,000×10,000 float64 matrix is 800 MB and infeasible to invert casually.

### 16. Security
User-supplied matrices must be size-limited. Do not expose raw solver errors that leak internals.

### 17. Interview explanation
"The inverse undoes a matrix, but it only exists for square, full-rank matrices. In practice I almost never form it explicitly: I solve the linear system with a factorization, and I check the condition number, because an ill-conditioned matrix gives garbage even if it is technically invertible."

### 18. Rapid-fire
`AA⁻¹ = I`; needs square + full rank; prefer `solve`; watch the condition number.
