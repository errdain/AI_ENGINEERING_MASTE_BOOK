# 1.37 Cross-entropy

**Metadata** — Tier: 1 · Phase: 1 · Priority: P0 · Difficulty: 3/5 · Interview: Very high · Hands-on: Very high
Prerequisites: 1.35, 1.36, 1.43 · Leads to: 1.38 KL, classification and LLM training (Tier 3–10), distillation

### 1. What is it?
The average surprise when events are drawn from `p` but you use model `q` to assign probabilities:

`H(p, q) = −Σ p(x) log q(x)`

When `p` is one-hot with true class `y`, this is just `−log q(y)`, the **negative log probability of the correct class**.

### 2. Why does it exist?
It scores how well a predicted distribution matches the true one, and it is the NLL (1.35) for categorical models. It punishes confident wrong answers heavily and has well-behaved gradients with softmax.

### 3. Detailed explanation
- **Decomposition:** `H(p, q) = H(p) + KL(p ‖ q)`. Since KL ≥ 0, `H(p, q) ≥ H(p)` (Gibbs' inequality; tested). Minimizing cross-entropy over `q` = minimizing KL to `p`, because `H(p)` is constant.
- If `q(x) = 0` where `p(x) > 0`, cross-entropy is infinite: the model called a possible event impossible.
- **Softmax + cross-entropy gradient:** `∂L/∂logits = softmax(z) − onehot(y)`. Simple, bounded, and the reason this pairing is standard (cf. the softmax Jacobian in 1.24).
- **Compute from logits, never from probabilities:** `L = −z_y + logsumexp(z)` (1.43). Taking `log(softmax(z))` naively can overflow/underflow. Extreme logits `[−1000, 1000]` with target 0 give a finite loss of 2000 with the stable form (tested).
- **Binary cross-entropy:** `−[y log p + (1−y) log(1−p)]`.
- **Perplexity** = `exp(mean cross-entropy in nats)`.
- **Label smoothing** replaces one-hot with a softened target to reduce overconfidence.
- Class imbalance: weight classes or use focal loss; the loss value alone doesn't mean good accuracy.
- Units: bits (`log₂`) vs nats (`ln`); frameworks use nats.

### 4. How does it work?
Compute `log q` stably (log-softmax), pick/weight by `p`, sum, average over the batch.

### 5. Simple example
You predict 90% rain and it rains: small surprise (−ln 0.9 ≈ 0.105). You predict 1% rain and it rains: huge surprise (−ln 0.01 ≈ 4.6).

### 6. Technical example
LLM pretraining loss at each position is the cross-entropy between the one-hot next token and the model's softmax over the vocabulary, averaged across tokens. A uniform guess over a 50k vocabulary starts at `ln 50000 ≈ 10.8` nats.

### 7. Code
```python
import numpy as np
from info_numerics import cross_entropy, cross_entropy_from_logits, log_softmax, entropy, kl_divergence
p, q = np.array([0.7, 0.2, 0.1]), np.array([0.5, 0.3, 0.2])
print(cross_entropy(p, q), entropy(p) + kl_divergence(p, q))        # equal
logits = np.array([2.0, 0.5, -1.0])
print(cross_entropy_from_logits(logits, 0), -np.log(np.exp(log_softmax(logits))[0]))
print(cross_entropy_from_logits(np.array([-1000.0, 1000.0]), 0))    # 2000.0, finite
```
TESTED: decomposition, Gibbs inequality, one-hot equals −log q, extreme logits finite, zero-probability gives infinity.

### 8. Input → Process → Output
`logits → log-softmax → pick log q(y) → negate → mean over batch → loss`

### 9. Enterprise use case
Training loss/validation loss curves are the primary health signal in model training pipelines; eval perplexity compares model versions on the same tokenizer and data.

### 10. AI engineering connection
Classification and language-model training, knowledge distillation (cross-entropy to teacher probabilities), calibration (NLL as a proper scoring rule), RLHF's KL-regularized objectives.

### 11. Advantages
Matches probabilistic modelling, smooth gradient, proper scoring rule (minimized only by true probabilities).

### 12. Limitations
Sensitive to label noise (confidently wrong labels give huge loss); can promote overconfidence; says little about ranking quality or business metrics.

### 13. Trade-offs
Cross-entropy (probabilistic, smooth) vs accuracy/F1 (decision-based, non-differentiable). Use cross-entropy to train, task metrics to judge.

### 14. Common mistakes
Applying softmax then cross-entropy that applies softmax again (double softmax); using `log(p)` of probabilities instead of logits; comparing perplexities across different tokenizers; mixing bits and nats; ignoring padding tokens in the average.

### 15. Performance / cost
For large vocabularies the logit tensor `(batch·seq, vocab)` is a major memory cost; fused/chunked cross-entropy kernels reduce it.

### 16. Security
Loss values and per-token log-probs can enable membership inference (training examples have lower loss); restrict exposure of log-probs for sensitive models.

### 17. Interview explanation
"Cross-entropy measures how surprised the model is by the true label: minus the log of the probability it gave the correct class. It's the negative log-likelihood for classification, equals entropy plus KL, and with softmax its gradient is simply prediction minus target. I always compute it from logits with log-sum-exp for stability."

### 18. Rapid-fire
H(p,q) = H(p) + KL(p‖q); one-hot case = −log q(y); gradient = softmax − onehot; compute from logits.
