# 1.33 Conditional probability

**Metadata** — Tier: 1 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: Very high · Hands-on: High
Prerequisites: 1.26, 1.28 · Leads to: 1.34 Bayes, 1.35 MLE, language models (autoregression), precision/recall

### 1. What is it?
The probability of `A` given that `B` has happened:

`P(A | B) = P(A ∩ B) / P(B)`, defined when `P(B) > 0`.

### 2. Why does it exist?
New information changes what is likely. Conditioning restricts the sample space to the cases where `B` holds and renormalizes.

### 3. Detailed explanation
- **Product (chain) rule:** `P(A ∩ B) = P(A | B)P(B)`; for sequences `P(x₁,…,x_T) = Π P(x_t | x_<t)`. This is exactly how **autoregressive language models** factorize text.
- **Law of total probability:** `P(A) = Σᵢ P(A | Bᵢ)P(Bᵢ)` for a partition `{Bᵢ}`.
- **Independence:** `P(A | B) = P(A)`.
- `P(A | B) ≠ P(B | A)` in general (the "prosecutor's fallacy"; fixed by Bayes, 1.34).
- Conditioning on a **random variable** gives a conditional distribution `p(y | x)`: what discriminative models (classifiers) learn.
- ML metrics are conditional probabilities: precision = `P(actually positive | predicted positive)`, recall = `P(predicted positive | actually positive)`.
- Conditional independence (`A ⟂ B | C`) underlies Naive Bayes and graphical models.

### 4. How does it work?
Count only the outcomes where `B` occurred, and among them the fraction where `A` also occurred. Example: two dice, `P(sum = 7 | first die = 3) = 1/6` (the second die must be 4); simulation agrees (tested).

### 5. Simple example
`P(rain | dark clouds)` is much larger than `P(rain)`.

### 6. Technical example
A language model computes `P(next token | previous tokens)`. A spam classifier computes `P(spam | words)`. In RAG, `P(answer | question, retrieved passages)`.

### 7. Code
```python
import numpy as np
rolls = np.random.default_rng(3).integers(1, 7, size=(300_000, 2))
s = rolls.sum(axis=1)
p = ((s == 7) & (rolls[:, 0] == 3)).mean() / (rolls[:, 0] == 3).mean()
print(p)   # ≈ 0.1667 = P(sum=7 | first=3)
```

### 8. Input → Process → Output
`event B observed → restrict & renormalize → P(A | B)`

### 9. Enterprise use case
Fraud systems report P(fraud | flagged); alert fatigue is a precision problem (conditional on an alert firing), which depends on base rates.

### 10. AI engineering connection
Autoregressive factorization, classifiers `p(y|x)`, conditional generation (prompts condition the distribution), precision/recall, conditioning on context in RAG and agents.

### 11. Advantages
Exact framework for updating beliefs with evidence; supports decomposing huge joint distributions into manageable conditionals.

### 12. Limitations
Conditionals are only as good as the data in each condition (sparse conditions give noisy estimates); conditioning on a zero-probability event is undefined.

### 13. Trade-offs
Full conditional tables explode combinatorially; use independence assumptions (Naive Bayes) or neural parameterization.

### 14. Common mistakes
Confusing `P(A|B)` with `P(B|A)`; ignoring base rates; conditioning on the wrong population (selection bias); assuming independence to multiply probabilities; evaluating a model on data conditioned differently from production.

### 15. Performance / cost
Autoregressive decoding computes one conditional per token (sequential), the reason generation latency scales with output length.

### 16. Security
Prompt injection can be viewed as adversarial conditioning: attacker-controlled text shifts `P(output | context)`.

### 17. Interview explanation
"Conditional probability is the chance of A once I know B happened: P(A and B) over P(B). Language models are built on it — the probability of a text is the product of each token's probability given the previous ones. And I'm careful that P(A given B) is not P(B given A)."

### 18. Rapid-fire
P(A|B)=P(A∩B)/P(B); chain rule factorizes sequences; not symmetric.
