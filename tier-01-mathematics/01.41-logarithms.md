# 1.41 Logarithms

**Metadata** — Tier: 1 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: Medium-High · Hands-on: High
Prerequisites: 1.20 · Leads to: 1.35–1.38, 1.42–1.44, log-probabilities, perplexity

### 1. What is it?
The inverse of exponentiation: `log_b(x) = y ⇔ b^y = x`. In ML, `log` almost always means the natural log `ln` (base `e`); information theory often uses base 2. Domain: `x > 0`. `log(1) = 0`, `log(0) = −∞`.

### 2. Why does it exist?
It turns multiplication into addition and compresses huge ranges into manageable ones. Probabilities of long sequences are products of many small numbers; logs make them sums that fit in floating point.

### 3. Detailed explanation
- `log(ab) = log a + log b`; `log(a/b) = log a − log b`; `log(aᵏ) = k log a`; change of base `log_b x = ln x / ln b`.
- **Monotonic increasing:** maximizing `f` and maximizing `log f` have the same argmax (the basis of MLE, 1.35).
- Derivative: `d/dx ln x = 1/x`; large for small `x`, so `−log p` heavily punishes small probabilities on the correct class.
- **Log-probabilities** are ≤ 0. Sequence log-prob = sum of token log-probs (tested: summing logs of 400 values of 1e-3 works while the product underflows to 0).
- Multiplicative effects become additive: ratios become differences, so a relative change of 1% ≈ `log` change of 0.01.
- `log1p(x) = log(1+x)` and `expm1` stay accurate for tiny `x` (tested: `log(1+1e-20)=0` vs `log1p(1e-20)=1e-20`).
- `log(0)` gives `−inf` (and a warning) → loss `inf`/NaN downstream; clip or add ε only where it's mathematically justified.
- Logarithmic scales for plotting heavy-tailed data (latency, loss curves, learning rates).
- Bits vs nats: 1 nat = 1/ln 2 ≈ 1.4427 bits.

### 4. How does it work?
Computed by library routines with high relative accuracy; its gradient `1/x` can blow up near 0, which is why fused, stable implementations exist (log-softmax, BCE-with-logits).

### 5. Simple example
Earthquake magnitude: each +1 is 10× the amplitude: a log scale.

### 6. Technical example
Naive Bayes with 10,000 word features: multiply 10,000 probabilities and you get exactly 0; sum 10,000 log-probabilities and you get a usable score.

### 7. Code
```python
import numpy as np
print(np.log(3.7 * 0.25), np.log(3.7) + np.log(0.25))     # equal
p = np.full(400, 1e-3)
print(np.prod(p), np.sum(np.log(p)))                      # 0.0  -2763.1
print(np.log(1 + 1e-20), np.log1p(1e-20))                 # 0.0  1e-20
```

### 8. Input → Process → Output
`probabilities (products) → log → sums → numerically safe scores`

### 9. Enterprise use case
Scoring and ranking with log-odds (credit/risk models, logistic regression); latency/cost charts on log scales.

### 10. AI engineering connection
NLL/cross-entropy, perplexity, log-odds (logits), log-probs returned by LLM APIs (`logprobs`), RLHF log-ratio rewards, `logsumexp`.

### 11. Advantages
Stable products, additive structure, nice gradients with softmax.

### 12. Limitations
Undefined for ≤0; gradient explodes near 0; hides absolute scale.

### 13. Trade-offs
Log space is safer but needs `logsumexp` for sums of probabilities (1.43).

### 14. Common mistakes
`log(0)`; adding probabilities in log space as if they were probabilities (must use logsumexp); mixing bases; forgetting that ln of a probability is negative, so sign errors in loss.

### 15. Performance / cost
`log` is slightly costlier than multiply but negligible in practice; fused log-softmax saves memory.

### 16. Security
Exposing token log-probs can leak membership/training information (see 1.37); expose selectively.

### 17. Interview explanation
"Logs turn products into sums, which is why we work with log-probabilities: a sentence's probability underflows, but its log-probability is just a sum. Since log is monotonic the best parameters don't change, and it gives the cross-entropy loss."

### 18. Rapid-fire
log(ab)=log a+log b; monotonic; domain x>0; use log-probs; log1p for tiny x.
