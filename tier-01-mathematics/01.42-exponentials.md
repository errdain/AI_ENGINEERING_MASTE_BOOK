# 1.42 Exponentials

**Metadata** — Tier: 1 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: Medium · Hands-on: High
Prerequisites: 1.20, 1.21, 1.41 · Leads to: softmax, sigmoid, 1.43, 1.44, temperature, learning-rate decay

### 1. What is it?
The function `exp(x) = eˣ`, `e ≈ 2.71828`. It is positive for every `x`, increasing, equals its own derivative (`d/dx eˣ = eˣ`), and is the inverse of `ln`.

### 2. Why does it exist?
It models growth and decay proportional to current size, and it converts any real number (a *score* or *logit*) into a positive number, which can then be normalized into probabilities (softmax).

### 3. Detailed explanation
- `e^(a+b) = eᵃeᵇ`; `e^(−x) = 1/eˣ`; `exp(ln x) = x` (tested).
- **Growth is explosive:** `exp(10) ≈ 2.2×10⁴`, `exp(100) ≈ 2.7×10⁴³`, `exp(710)` overflows float64, `exp(89)` overflows float32, `exp(11)` overflows float16 (REVIEW_REQUIRED: thresholds from the dtype maxima: ln(3.4e38) ≈ 88.7, ln(65504) ≈ 11.09, ln(1.8e308) ≈ 709.8). This is why softmax subtracts the max (1.43).
- **Decay:** `exp(−x)` underflows to 0 for large `x` (`exp(−745)` is the smallest float64 subnormal region).
- **Softmax:** `softmax(z)ᵢ = exp(zᵢ)/Σexp(zⱼ)`: shift-invariant (adding a constant to all logits changes nothing; tested) and temperature scales logits before exp.
- **Sigmoid:** `σ(x) = 1/(1+e^(−x))`, maps ℝ → (0,1); `σ′ = σ(1−σ) ≤ 0.25`.
- **Exponential decay schedules:** learning rate `η_t = η₀ e^(−kt)`; **EMA** with decay `β` behaves like exponential forgetting.
- Rate of change: a doubling every `T` steps is `2^(t/T)`; small relative errors in logits become large relative errors in probabilities because of exp.
- Log-odds: `logit(p) = ln(p/(1−p))` is the inverse of the sigmoid.

### 4. How does it work?
Computed via range reduction and polynomial approximations, with relative error of a few ULP. Overflow occurs when the exponent leaves the dtype's range.

### 5. Simple example
Compound interest or bacteria doubling: growth proportional to current size.

### 6. Technical example
Attention weights are `softmax(QKᵀ/√d)`: exp amplifies score differences, so a score gap of 5 gives a weight ratio of `e⁵ ≈ 148`.

### 7. Code
```python
import numpy as np
print(np.exp(np.log(3.7)))                      # 3.7
print(np.exp(710.0), np.exp(-800.0))            # inf (overflow warning)  0.0 (underflow)
print(np.expm1(1e-20), np.exp(1e-20) - 1)       # 1e-20  0.0
```
TESTED: identities, `expm1`, and stable-vs-naive softmax.

### 8. Input → Process → Output
`real score → exp → positive number → normalize → probability`

### 9. Enterprise use case
Capacity forecasting with exponential growth; exponential backoff with jitter for retries (`delay = base · 2^attempt`) in resilient AI API clients.

### 10. AI engineering connection
Softmax, sigmoid, temperature, attention, LR schedules, EMA of weights, Boltzmann/energy-based views, retry policies for model APIs.

### 11. Advantages
Smooth, positive, simple derivative.

### 12. Limitations
Overflow/underflow; sensitivity amplification; saturating derivative in tails (sigmoid/softmax) causing vanishing gradients.

### 13. Trade-offs
Sharper softmax (high-scale logits) = more decisive but less smooth gradients; temperature controls this.

### 14. Common mistakes
`exp` of unshifted logits; computing `exp(a)/exp(b)` instead of `exp(a−b)`; sigmoid via naive `1/(1+exp(−x))` for very negative `x` (overflow in exp); forgetting retries need a cap and jitter.

### 15. Performance / cost
`exp` is relatively expensive; fused softmax kernels and approximations (e.g., in attention) matter at scale.

### 16. Security
Unbounded exponential retry/backoff or amplification can create DoS patterns; cap and add jitter.

### 17. Interview explanation
"The exponential function is positive, grows fast, and is its own derivative. We use it in softmax to turn scores into positive weights, which is also why we subtract the max first: exp overflows quickly, in fp16 already around 11."

### 18. Rapid-fire
eˣ>0, own derivative, inverse of ln; softmax/sigmoid use it; overflows fast.
