# 1.26 Probability

**Metadata** — Tier: 1 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: High · Hands-on: Medium
Prerequisites: 1.1 · Leads to: 1.27–1.38 (everything probabilistic), Tier 2, LLM sampling

### 1. What is it?
A number in `[0, 1]` that quantifies uncertainty about an event. Formal setup: a **sample space** Ω (all outcomes), **events** (subsets of Ω), and a probability measure `P` satisfying Kolmogorov's axioms:
1. `P(A) ≥ 0`
2. `P(Ω) = 1`
3. For disjoint events, `P(A ∪ B) = P(A) + P(B)`

### 2. Why does it exist?
Data is noisy, labels are imperfect, the future is uncertain, and a model's output is rarely a single certain answer. Probability is the consistent language for reasoning under uncertainty.

### 3. Detailed explanation
Consequences: `P(Aᶜ) = 1 − P(A)`; `P(A ∪ B) = P(A) + P(B) − P(A ∩ B)`; `P(∅) = 0`. **Independence:** `P(A ∩ B) = P(A)P(B)`. Two interpretations: **frequentist** (long-run frequency) and **Bayesian** (degree of belief). ML uses both views.

Important caution: a model's output "0.9" is a *score* shaped like a probability, not necessarily a *calibrated* probability that it is right 90% of the time. Calibration must be measured (Tier 15, Tier 30).

### 4. How does it work?
Count favourable outcomes / total (equally likely case), or model/estimate frequencies from data. Combine with the sum and product rules; conditional probability (1.33) and Bayes (1.34) come next.

### 5. Simple example
Fair die: `P(even) = 3/6 = 0.5`; `P(even or ≥5) = 3/6 + 2/6 − 1/6 = 4/6`.

### 6. Technical example
A language model assigns a probability to each next token; probabilities over the vocabulary sum to 1 (a softmax output is a valid distribution: positive, sums to 1).

### 7. Code
```python
import numpy as np
from calculus_prob import softmax
p = softmax(np.array([2.0, 1.0, 0.1]))
print(p, p.sum())                    # positive entries, sum = 1.0
print(softmax(np.array([1000.0, 0.0])))   # [1. 0.] — stable (no overflow)
# P(even or >=5) by enumeration:
print(sum(1 for r in range(1, 7) if r % 2 == 0 or r >= 5) / 6)   # 0.666...
```
TESTED: softmax is a distribution, is shift-invariant, and stays finite for large logits.

### 8. Input → Process → Output
`uncertain situation → assign P to events (axioms) → compute P of compound events`

### 9. Enterprise use case
Risk scoring, fraud probability, SLA reasoning ("probability a request exceeds 2 s"). Decisions use costs × probabilities.

### 10. AI engineering connection
Classification outputs, sampling in LLM decoding, uncertainty estimates, Bayesian reasoning, evaluation (precision/recall as conditional probabilities).

### 11. Advantages
Unified, mathematically consistent treatment of uncertainty.

### 12. Limitations
Needs a sensible model or enough data; real events are often dependent (not independent); probabilities are only as good as the assumptions.

### 13. Trade-offs
Simple independence assumptions (Naive Bayes) are tractable but can be wrong; richer models need more data.

### 14. Common mistakes
Assuming independence by default; treating softmax scores as calibrated confidence; probability of a union by simple addition when events overlap; base-rate neglect (1.34); gambler's fallacy.

### 15. Performance / cost
Computing in probability space underflows for products of many small numbers; use log-probabilities (1.41, 1.43).

### 16. Security
Over-trusting model confidence invites attacks and unsafe automation; use thresholds validated on held-out data and fallback paths for low confidence.

### 17. Interview explanation
"Probability quantifies uncertainty between 0 and 1, built on a few axioms: non-negative, total one, additive for disjoint events. In ML, classifier outputs and next-token distributions are probability vectors, but I check calibration rather than assuming a 0.9 really means 90%."

### 18. Rapid-fire
P ∈ [0,1], P(Ω)=1, additive for disjoint events; softmax ≠ guaranteed calibration.
