# 1.39 Numerical stability

**Metadata** — Tier: 1 · Phase: 1 · Priority: P0 · Difficulty: 3/5 · Interview: High · Hands-on: Very high
Prerequisites: 1.14, 1.40–1.44 · Leads to: mixed precision (Tier 4/11), stable softmax/loss, normalization layers

### 1. What is it?
An algorithm is **numerically stable** if small errors (rounding, noise in inputs) do not blow up into large errors in the result. A problem is **well-conditioned** if the answer is insensitive to small input changes; **ill-conditioned** otherwise.

### 2. Why does it exist as a concern?
Computers use finite-precision arithmetic (1.40). Mathematically equivalent formulas can behave very differently: one returns the right answer, the other NaN. Most training "mysteries" (NaN loss, silent accuracy drop) are stability issues.

### 3. Detailed explanation
Two separate things:
- **Conditioning** is a property of the *problem* (e.g., the condition number `κ = σ_max/σ_min` of a matrix, 1.14, 1.19). Error in output ≈ `κ ×` error in input.
- **Stability** is a property of the *algorithm*. A stable algorithm gives an answer that is the exact answer to a slightly perturbed problem.

Standard tricks:
1. **Subtract the max before exponentiating** (stable softmax, log-sum-exp; 1.43). Tested: naive softmax of `[1000,1001,1002]` is NaN; the shifted version is fine.
2. **Work in log space** for products of probabilities (1.41, 1.44). Tested: a product of 400 values of 1e-3 underflows to 0, the sum of logs does not.
3. **Fuse operations** (`log_softmax`, cross-entropy from logits, `log1p`, `expm1`). Tested: `log(1+1e-20)=0` but `log1p(1e-20)=1e-20`.
4. **Add ε** to denominators (`√(var+ε)`), but choose ε relative to dtype.
5. **Avoid subtracting nearly equal numbers** (catastrophic cancellation): e.g. `E[X²]−E[X]²` (1.30); use Welford.
6. **Solve, don't invert** (1.14).
7. **Normalize** inputs/activations; use residual connections; clip gradients (1.15).
8. **Accumulate in higher precision** (sum in float32/64 while computing in fp16/bf16); loss scaling for fp16 gradients (1.40).
9. **Order of summation** matters; pairwise or compensated (Kahan) summation reduces error.

### 4. How does it work?
Reformulate the computation algebraically to keep intermediate values in a safe range and avoid cancellation; verify against a higher-precision reference.

### 5. Simple example
Computing `(10¹⁶ + 1) − 10¹⁶` in float64 gives 0 instead of 1: the +1 is lost to rounding.

### 6. Technical example
Attention softmax over scores in fp16 can overflow; implementations subtract the row max, and flash-attention uses an online (streaming) version of this trick.

### 7. Code
```python
import numpy as np
from info_numerics import naive_softmax, log_softmax, logsumexp
z = np.array([1000.0, 1001.0, 1002.0])
print(naive_softmax(z))                 # [nan nan nan]  (exp overflow → inf/inf)
print(np.exp(log_softmax(z)))           # [0.0900 0.2447 0.6652]
print(np.log(1 + 1e-20), np.log1p(1e-20))   # 0.0  1e-20
```
TESTED: naive vs stable softmax, shift invariance, `log1p`/`expm1`, underflow of probability products, finite loss for extreme logits.

### 8. Input → Process → Output
`formula → stable reformulation → bounded intermediates → trustworthy result`

### 9. Enterprise use case
Training pipelines add NaN/Inf checks and loss-scale monitoring; financial/risk code uses higher precision and compensated summation for aggregates.

### 10. AI engineering connection
Stable softmax/cross-entropy, LayerNorm ε, mixed-precision training, quantization error, attention kernels, gradient clipping, RMSNorm.

### 11. Advantages
Prevents silent corruption and wasted compute.

### 12. Limitations
Stability tricks add code complexity; some problems are inherently ill-conditioned and cannot be rescued by algorithms.

### 13. Trade-offs
Higher precision (safer, slower, more memory) vs lower precision with careful scaling (faster, riskier).

### 14. Common mistakes
`log(softmax(x))` instead of `log_softmax`; `exp` of large numbers; division by variance without ε; comparing floats with `==`; detecting NaNs only at the end of an epoch; assuming "it ran without error" means "it is right".

### 15. Performance / cost
Stable forms are usually free or fused; debugging a NaN run can cost days of GPU time, so add early checks (`isfinite` on loss, grad norms).

### 16. Security
Numerical edge cases (NaN, Inf, huge values) in user-controlled inputs can crash or poison services; validate and clamp inputs.

### 17. Interview explanation
"Numerical stability is about keeping floating-point errors from blowing up. Mathematically identical formulas can differ wildly: naive softmax overflows, so we subtract the max; products of probabilities underflow, so we use logs; and we compute loss from logits with log-sum-exp. I also watch the condition number for linear solves."

### 18. Rapid-fire
Shift before exp, log-space for products, fuse ops, add ε, solve don't invert, check for NaN.
