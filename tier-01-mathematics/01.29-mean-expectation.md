# 1.29 Mean and expectation

**Metadata** — Tier: 1 · Phase: 1 · Priority: P0 · Difficulty: 2/5 · Interview: High · Hands-on: High
Prerequisites: 1.27, 1.28 · Leads to: 1.30–1.32, 1.35–1.38, SGD, loss functions

### 1. What is it?
- **Expectation** (population mean) of a random variable: `E[X] = Σ x·p(x)` (discrete) or `∫ x f(x) dx` (continuous). The probability-weighted average.
- **Sample mean:** `x̄ = (1/n) Σ xᵢ`, an estimate of `E[X]` from data.

### 2. Why does it exist?
To summarize a distribution by its "centre", and more importantly to define *expected loss*: training minimizes the expected loss over the data distribution, which we approximate by an average over samples.

### 3. Detailed explanation
- **Linearity (always true):** `E[aX + b] = aE[X] + b` and `E[X+Y] = E[X] + E[Y]`, even if dependent.
- **Function of X (LOTUS):** `E[g(X)] = Σ g(x)p(x)`. Note `E[g(X)] ≠ g(E[X])` in general (Jensen's inequality: for convex `g`, `E[g(X)] ≥ g(E[X])`).
- `E[XY] = E[X]E[Y]` only if `X, Y` are uncorrelated/independent.
- Fair die: `E[X] = 3.5`, a value never rolled: the mean need not be a possible outcome.
- Mean is sensitive to outliers; the median is robust. For skewed/heavy-tailed data (latency, income) report percentiles too.
- **Mini-batch gradient is an unbiased estimator** of the full gradient because the average over a random batch has expectation equal to the full-data average.
- Estimation error of a sample mean shrinks as `σ/√n` (see 1.31).

### 4. How does it work?
Weight each value by its probability and sum/integrate; or average samples (Monte-Carlo estimate).

### 5. Simple example
A game pays 10 with probability 0.2 and 0 otherwise: `E = 2`.

### 6. Technical example
Training objective: `θ* = argmin E_{(x,y)~D}[ℓ(f(x;θ), y)]`, estimated by the batch average `(1/B) Σ ℓᵢ`.

### 7. Code
```python
import numpy as np
from calculus_prob import expectation
v, p = np.arange(1, 7), np.full(6, 1/6)
print(expectation(v, p))                       # 3.5
x = np.random.default_rng(1).standard_normal(100_000)
print((3*x + 5).mean(), 3*x.mean() + 5)        # equal: linearity
# expectation([1, 2], [0.7, 0.7]) -> ValueError: probs must sum to 1
```
TESTED: fair die = 3.5, bad probabilities rejected, linearity.

### 8. Input → Process → Output
`values + probabilities (or samples) → weighted average → single centre value`

### 9. Enterprise use case
Expected cost/revenue of decisions: `E[cost] = Σ P(outcome)·cost(outcome)` drives thresholds for fraud blocking, human escalation, and model routing.

### 10. AI engineering connection
Loss = expected error; mean pooling; batch normalization statistics; moving averages (EMA) of weights/metrics; evaluation metrics are means (accuracy = mean of correct indicators).

### 11. Advantages
Simple, linear, easy to estimate and optimize.

### 12. Limitations
Outlier-sensitive; may not exist (heavy-tailed distributions like Cauchy have no mean); hides distribution shape and per-group differences.

### 13. Trade-offs
Mean (efficient, sensitive) vs median/trimmed mean (robust, less efficient).

### 14. Common mistakes
Averaging averages with unequal group sizes; using mean for skewed metrics; `E[g(X)] = g(E[X])`; averaging probabilities vs logits without thought; reporting an aggregate that masks subgroup failure.

### 15. Performance / cost
Running means can be computed online in O(1) memory; averaging across distributed workers needs an all-reduce.

### 16. Security
Aggregate metrics can hide targeted attacks or poisoned slices; evaluate per slice.

### 17. Interview explanation
"Expectation is the probability-weighted average of a random variable. In ML the training loss is an expectation over the data distribution, which we estimate with a mini-batch average. Linearity makes it easy to work with, but I remember the mean is outlier-sensitive and that E of a function is not the function of the mean."

### 18. Rapid-fire
E[X] = Σ x·p(x); linear; sample mean estimates it; E[g(X)] ≠ g(E[X]).
