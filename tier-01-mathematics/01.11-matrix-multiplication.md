# 1.11 Matrix multiplication

**Metadata** — Tier: 1 · Phase: 1 · Priority: P0 · Difficulty: 3/5 · Interview: Very high · Hands-on: Very high
Prerequisites: 1.3, 1.5, 1.10 · Leads to: 1.12–1.14, 1.19, Tier 3 (layers), Tier 7 (attention), Tier 11 (inference cost)

### 1. What is it?
For `A` of shape `(m, n)` and `B` of shape `(n, p)`, the product `C = AB` has shape `(m, p)` with
`C[i, j] = Σₖ A[i, k] · B[k, j]` — the dot product (1.10) of row `i` of `A` with column `j` of `B`.

### 2. Why does it exist?
It composes linear transformations: applying `B` then `A` is the single matrix `AB`. It also computes *many dot products at once*, which is exactly what GPUs are built for.

### 3. Detailed explanation
Three equivalent views:
1. **Entry view:** each output is one dot product.
2. **Column view:** each column of `C` is `A` applied to the matching column of `B`.
3. **Outer-product view:** `AB = Σₖ (column k of A)(row k of B)`.

Rules that matter in practice:
- Inner dimensions must match: `(m,n)@(n,p)`.
- **Not commutative:** `AB ≠ BA` in general (and `BA` may not even exist).
- **Associative:** `(AB)C = A(BC)` — same result, possibly very different cost.
- Distributive: `A(B+C) = AB + AC`.
- Transpose reverses order: `(AB)ᵀ = BᵀAᵀ` (1.12).
- Elementwise product (`*`) is a different operation from matrix product (`@`).

### 4. How does it work?
Loop form: for each `i` (row of A), each `j` (column of B), accumulate over `k`. Cost is `m·n·p` multiply-adds ≈ `2mnp` FLOPs. Libraries (BLAS, cuBLAS) tile the work to reuse data in cache/shared memory, so a naïve Python loop can be many orders of magnitude slower than `A @ B`.

### 5. Simple example
Recipes × prices: a `(dishes, ingredients)` matrix times an `(ingredients, shops)` price matrix gives the cost of each dish at each shop.

### 6. Technical example
- Linear layer: `Y = XWᵀ + b` with `X:(B·T, d_in)`, `W:(d_out, d_in)`.
- Attention scores: `S = QKᵀ/√dₖ` with `Q:(T,d)`, `Kᵀ:(d,T)` → `S:(T,T)`; then `SV`.
- Per-token FLOPs of a dense Transformer are dominated by such products.

### 7. Code
```python
import numpy as np
from linalg_basics import matmul_manual

A = np.arange(6.0).reshape(2, 3)       # (2, 3)
B = np.arange(12.0).reshape(3, 4)      # (3, 4)
C = A @ B                              # (2, 4)
assert np.allclose(matmul_manual(A.tolist(), B.tolist()), C)

# Associativity changes cost, not the answer:
x = np.ones((1, 1000)); W1 = np.ones((1000, 1000)); W2 = np.ones((1000, 1000))
y = (x @ W1) @ W2      # ~2 * 1000*1000 mults (vector-matrix twice)
z = x @ (W1 @ W2)      # ~1000^3 mults first: far more work
```

### 8. Input → Process → Output
`A (m,n) , B (n,p) → m·p dot products of length n → C (m,p)`

### 9. Enterprise use case
Batch scoring services stack requests into one matrix so a single large matmul replaces many small ones, raising GPU utilization and lowering cost per request.

### 10. AI engineering connection
Training and inference are mostly matmuls. Cost estimates for LLMs (FLOPs/token ≈ 2 × parameters for the dense forward pass) come from this. Parameter-efficient fine-tuning (LoRA, Tier 10) replaces a big update with a product of two thin matrices.

### 11. Advantages
Highly optimized hardware path (BLAS, tensor cores); expressive composition of linear maps.

### 12. Limitations
Cost grows with the product of the three sizes; attention's `(T,T)` score matrix makes cost and memory quadratic in sequence length.

### 13. Trade-offs
Lower precision (bf16/fp16/int8) speeds up matmul and cuts memory but reduces numerical accuracy (see 1.40). Bigger batches raise throughput but also latency and memory.

### 14. Common mistakes
Using `*` instead of `@`; wrong operand order; ignoring that `(AB)ᵀ = BᵀAᵀ`; picking a bad multiplication order in chains; forgetting the batch axis (`@` batches over leading axes in NumPy/PyTorch).

### 15. Performance / cost
`≈ 2mnp` FLOPs. Example: `(4096×4096) @ (4096×4096)` ≈ 1.4×10¹¹ FLOPs. Small matrices are memory/launch-bound, not compute-bound, so batching matters. Chain order: for a chain, choose parenthesization to minimize intermediate sizes.

### 16. Security
Shape and size of user-controlled operands must be bounded (resource exhaustion). Reduced-precision accumulation can change outputs slightly between hardware, so do not rely on bit-exact reproducibility across devices.

### 17. Interview explanation
"Matrix multiplication takes the dot product of every row of the first matrix with every column of the second, so inner dimensions must match. It composes linear transformations and it's what neural network layers and attention are made of — which is why GPUs and tensor cores are tuned for it."

### 18. Rapid-fire
`(m,n)@(n,p)→(m,p)`; each entry is a row–column dot product; associative, not commutative; ~2mnp FLOPs.
