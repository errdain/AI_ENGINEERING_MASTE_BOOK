### 1. WHAT IS IT?

*Pretraining* is the first, most expensive training stage of a foundation model: fit a large neural network on a huge, broad, mostly unlabeled corpus with a self-supervised objective (usually next-token prediction). The product is a **base model** (a checkpoint) that later stages adapt (Tier 10), serve (Tier 11) and evaluate (Tier 15).

### 2. WHY DOES IT EXIST?

Labels are expensive and task-specific; raw text is abundant. Learning general language, code and world regularities once, from unlabeled data, and then adapting many times cheaply is far more economical than training a model per task from scratch.

### 3. DETAILED EXPLANATION

Quality of the base model depends, in rough order of leverage, on **(1) the data**, **(2) compute spent sensibly** (parameters N and tokens D together) and **(3) keeping a very long run alive and reproducible**. This tier is organised around those three: the data pipeline (9.2–9.15), the objective and scale reasoning (9.16–9.21), and run operations (9.22–9.28), followed by adaptation of a finished base (9.29–9.31).

Scope rule: attention math is Tier 7, the Transformer block and the objective *definitions* are Tier 8, MoE as an *architecture family* is Tier 12. This tier owns the **data, scale, optimization and operations** around them.

### 5. SIMPLE EXAMPLE

A child who reads thousands of books, with no teacher, learns grammar, facts and style by constantly guessing the next word. Later, a short course (fine-tuning) teaches them to answer questions politely.

### 6. TECHNICAL EXAMPLE

The lab (`lab/run_lab.py`) runs the whole path in miniature on CPU: synthetic crawl, pipeline `753 -> 597` documents, BPE tokenizer (vocab 380), ~57k training tokens, a 128,512-parameter decoder trained for 200 steps (204,800 tokens seen, `6ND ~ 1.6e11` FLOPs), `metrics.json` with a data fingerprint and loss history. Numbers are from the authoring machine and may vary with library versions.

### 7. CODE

```python
# Run from the lab/ directory: the entire miniature pretraining path, as a library call.
import run_lab
from model import ModelConfig
from pretrain import TrainConfig, train
import tempfile

tok, train_stream, val_stream, report = run_lab.prepare()           # data pipeline + tokenizer
cfg = TrainConfig(steps=20, eval_every=20, ckpt_every=20,           # 20 steps: just a smoke run
                  model=ModelConfig(vocab_size=tok.vocab_size))
metrics = train(cfg, train_stream, val_stream, tempfile.mkdtemp())
print(report["stages"][-1], metrics["n_params"], metrics["tokens_seen"])
```

### 9. ENTERPRISE USE CASE

Almost no company pretrains a frontier model; most *select, adapt and serve* one. You still need this knowledge to read a model card, judge data/licensing risk, estimate what a custom or continued-pretraining project would cost, and decide between pretraining, fine-tuning and RAG.

### 10. AI ENGINEERING CONNECTION

Every behaviour of an LLM (knowledge cutoff, language coverage, code ability, memorised text, biases) is inherited from pretraining data and scale. Fine-tuning ([Tier 10](../tier-10-fine-tuning-alignment/README.md)), inference cost ([Tier 11](../tier-11-llm-inference-optimization/README.md)) and RAG are all shaped by what the base model learned here.

### 11. ADVANTAGES

- One expensive run serves many downstream uses.
- No human labels required.
- Capability improves predictably with scale (9.20).

### 12. LIMITATIONS

- Very high cost; hard to reproduce; irreversible once data is baked into weights.
- Inherits biases, errors and legal risk of the corpus.
- Loss is not capability: a good base model is not yet a helpful assistant.

### 13. TRADE-OFFS

Build vs buy vs adapt: pretrain from scratch (control, huge cost), continue pretraining an open base (cheaper, some control), fine-tune or RAG (cheapest, least control).

### 14. COMMON MISTAKES

- Spending on model size before fixing data quality.
- No dataset versioning or provenance, so results cannot be reproduced or audited.
- Treating a toy lab result as evidence about real scale.

### 15. PERFORMANCE / COST CONSIDERATIONS

Headline cost is `6ND / (peak FLOP/s x MFU) x price` (see [9.15](09.15-compute-budgets.md)), but real programmes also pay for failed runs, ablations, data processing, storage and people, often a multiple of the headline.

### 16. SECURITY CONSIDERATIONS

Training data is an attack surface (poisoning, planted prompt-injection text) and a privacy liability (memorised secrets/PII). Checkpoints are code-execution risks if loaded via pickle (see [9.22](09.22-training-checkpoints.md)).

### 17. INTERVIEW EXPLANATION

"Pretraining is the big self-supervised stage where a model learns to predict the next token over a huge cleaned corpus. The recipe is data pipeline first, then a budget of parameters and tokens guided by scaling laws, then an operationally robust run: deterministic data order, checkpoints, stability monitoring. The output is a base model that fine-tuning and alignment then specialise. In practice most teams adapt an existing base, but you need this to judge data risk and cost."

### 18. RAPID-FIRE ANSWER

Self-supervised training of a large model on broad unlabeled data to produce a reusable base model.
