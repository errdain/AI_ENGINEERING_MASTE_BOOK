### 1. WHAT IS IT?

Deciding which documents are *worth training on*. Three families, usually combined: **heuristic rules**, **classifier-based** filters and **model/perplexity-based** filters.

### 2. WHY DOES IT EXIST?

Raw crawl is mostly low-value text. Better data shifts the whole loss-vs-compute curve down; quality-filtered data can let a smaller model match a larger one trained on raw crawl (a recurring finding in the open-data literature; `REVIEW_REQUIRED` for specific claims).

### 3. DETAILED EXPLANATION

| Family | Example | Cost | Failure mode |
|---|---|---|---|
| Heuristic rules | min words, symbol/alpha ratio, repeated-line ratio, mean word length, stop-word presence | cheap | brittle; biased against dialects, code, tables |
| Classifier-based | small model separating "reference-like" text from random crawl; keep high scorers | moderate | inherits the bias of the "good" seed set |
| Model / perplexity-based | score documents with a small LM; drop extremes | moderate | removes unusual-but-valuable text |

Filtering *reduces* D, so quality-vs-quantity is itself a budget decision ([9.14](09.14-token-budgets.md)). The lab implements family 1; its thresholds are illustrative, and in real work you **tune on a labelled sample** while inspecting what each rule removes.

### 4. HOW DOES IT WORK?

`quality_filter(text)` returns `(keep, reason)` so every drop is explainable: (1) fewer than `min_words` words -> `too_short`; (2) symbol fraction above `max_symbol_ratio` -> `symbol_ratio`; (3) extreme repeated-line fraction (only above 0.8, since code legitimately repeats lines) -> `repeated_lines`; else `ok`.

### 5. SIMPLE EXAMPLE

A librarian rejecting pamphlets that are one line long, all punctuation, or the same sentence repeated.

### 6. TECHNICAL EXAMPLE

A classifier trained to separate encyclopedia-like text from random crawl scores each page and the top 30% are kept. Held-out loss improves, but informal dialects silently vanish, so per-language validation loss must be checked ([9.31](09.31-pretraining-evaluation.md)).

### 8. INPUT → PROCESS → OUTPUT

```
cleaned docs -> rules / classifier / LM score -> (keep, reason) -> kept docs + per-reason drop report
```

### 9. ENTERPRISE USE CASE

Filtering an internal document dump before continued pretraining: drop auto-generated reports, log files and near-empty pages, and report drops by department so no team's text disappears silently.

### 10. AI ENGINEERING CONNECTION

The same classifier/heuristic ideas filter RAG corpora and fine-tuning data. Quality filters are also where hidden bias enters: whatever the "good" seed set looks like, the model will look like.

### 11. ADVANTAGES

- Biggest single lever on data quality; reduces compute wasted on junk.
- Heuristics are cheap and explainable; classifiers capture subtler quality.

### 12. LIMITATIONS

- Proxies of "quality" are biased (formal English, Wikipedia-like).
- Thresholds do not transfer across languages or domains.

### 13. TRADE-OFFS

Strict filter: higher quality, fewer tokens (may force repeated epochs, [9.6](09.06-data-mixture-design.md)). Loose filter: more tokens, more noise. Cheap rules vs costly model-based scoring.

### 14. COMMON MISTAKES

- Filtering on a single proxy (e.g. "looks like Wikipedia") and deleting whole dialects or domains.
- Never inspecting dropped samples.
- Applying thresholds tuned on English to every language.

### 15. PERFORMANCE / COST CONSIDERATIONS

Heuristics are nearly free; classifier or LM scoring adds inference cost proportional to corpus size (a model forward pass per document), so use a small scorer and run it distributed.

### 16. SECURITY CONSIDERATIONS

Adversaries can craft pages that look "high quality" to your classifier to get poisoned text through. Filters are not a security control; combine with provenance and source allowlists.

### 17. INTERVIEW EXPLANATION

"I'd combine cheap heuristics — length, symbol ratio, repetition — with a classifier or small-LM scorer, always returning a reason for every drop. To check a filter helped, I train small proxy models on filtered vs unfiltered data at equal token counts and compare held-out loss and downstream evals, then inspect dropped samples by language and domain, because the main risk is silently deleting a dialect or domain."

### 18. RAPID-FIRE ANSWER

Keep documents worth learning from, using rules, classifiers or LM scores, and verify with proxy-model ablations.
