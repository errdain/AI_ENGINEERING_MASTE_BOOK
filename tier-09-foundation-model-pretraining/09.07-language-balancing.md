### 1. WHAT IS IT?

Choosing how much of the training stream each language receives, typically with **temperature sampling**: language *i* is sampled with probability proportional to `nᵢ^α`.

### 2. WHY DOES IT EXIST?

Raw crawls are dominated by a few languages. Following the data (`α = 1`) leaves low-resource languages almost unseen; forcing uniform (`α → 0`) repeats tiny corpora many times, which can overfit them.

### 3. DETAILED EXPLANATION

`α = 1` follows the data; `α = 0` is uniform; practice picks an intermediate α (`REVIEW_REQUIRED` for specific values in named models). The bottom half of [mixture_explorer.html](interactive/mixture_explorer.html) shows the shares change as α moves.

Tokenizer interaction ([Tier 6](../tier-06-tokenization-embeddings/README.md)): a language that tokenizes poorly consumes more *tokens* per sentence, so equal *token* share is *less* text. Build the tokenizer on the same balanced mix, and balance by **tokens**, not documents.

![Mixture and epochs](figures/03_mixture_epochs.png)

*Figure 3 — The same epochs-per-source arithmetic applies per language: a language with few unique tokens that is given a large share is repeated. Use the language-sampling panel of [mixture_explorer.html](interactive/mixture_explorer.html) to see shares vs α.*

### 4. HOW DOES IT WORK?

1. Count unique tokens `nᵢ` per language. 2. Compute `pᵢ = nᵢ^α / Σⱼ nⱼ^α`. 3. Convert to requested tokens (`pᵢ x budget`). 4. Check epochs per language. 5. Evaluate per-language validation loss, not just the average.

### 5. SIMPLE EXAMPLE

A radio station that plays 95% English because that is what it has. Temperature sampling is a dial that turns up the minority languages without turning off English.

### 6. TECHNICAL EXAMPLE

Languages with 1000, 100, 10 (units of billions of tokens): `α=1` gives shares 90/9/0.9%; `α=0.5` gives `√` weights 31.6/10/3.2 -> about 70/22/7%; `α=0` gives 33/33/33% and, for a budget equal to the total data (1,110), the smallest language (10 unique) is repeated about 37x.

### 7. CODE

```python
# Temperature sampling of languages (standalone).
def language_shares(tokens_by_lang: dict[str, float], alpha: float) -> dict[str, float]:
    w = {k: v ** alpha for k, v in tokens_by_lang.items()}
    z = sum(w.values())
    return {k: v / z for k, v in w.items()}

n = {"en": 1000, "de": 100, "sw": 10}
for a in (1.0, 0.5, 0.0):
    print(a, {k: round(v, 2) for k, v in language_shares(n, a).items()})
```

### 8. INPUT → PROCESS → OUTPUT

```
tokens per language -> raise to alpha -> normalise -> shares -> requested tokens -> epochs per language check
```

### 9. ENTERPRISE USE CASE

A company serving customers in several markets chooses α to keep its main language strong while lifting smaller markets, then monitors per-language loss and support-ticket quality per locale.

### 10. AI ENGINEERING CONNECTION

Multilingual quality of a model (and per-language token cost at inference) is set here and in the tokenizer. Retrieval and RAG pipelines inherit the same language gaps.

### 11. ADVANTAGES

- One knob controls the head/tail language balance.
- Cheap to simulate before training.

### 12. LIMITATIONS

- Does not create new data: tiny languages are repeated, not enriched.
- A single α may not suit all languages equally.

### 13. TRADE-OFFS

Higher α: best on dominant language, weak tail. Lower α: better tail, risk of overfitting small corpora and slightly worse head.

### 14. COMMON MISTAKES

- Balancing by documents instead of tokens.
- Not building the tokenizer on the same balanced mix.
- Reporting one average metric that hides a collapsing low-resource language.

### 15. PERFORMANCE / COST CONSIDERATIONS

Poor tokenization of a language raises its training and inference cost per sentence; budgeting must be in tokens.

### 16. SECURITY CONSIDERATIONS

Safety training and filters are often weaker in low-resource languages; up-sampling them without matching safety data can widen the gap (`REVIEW_REQUIRED` for quantified claims).

### 17. INTERVIEW EXPLANATION

"Raw crawls are dominated by a few languages, so I use temperature sampling: probability proportional to size to the power alpha. Alpha 1 follows the data, alpha 0 is uniform. I'd pick something in between, balance in tokens not documents, build the tokenizer on the same mix, and watch per-language validation loss so the tail isn't hidden by an average."

### 18. RAPID-FIRE ANSWER

Sample languages proportional to `n^α`; α trades head quality for tail coverage.
