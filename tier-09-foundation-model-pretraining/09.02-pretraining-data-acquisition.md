### 1. WHAT IS IT?

Collecting the raw text (and code, math, etc.) a model will learn from: web crawls, code hosts, books, papers, encyclopedias, forums, licensed or curated corpora, and increasingly **synthetic data** generated by other models ([Tier 10](../tier-10-fine-tuning-alignment/README.md)).

### 2. WHY DOES IT EXIST?

Model capability is bounded by the diversity and size of what it sees. Web-scale breadth gives coverage; denser sources (books, code, math, encyclopedias) give reasoning and factual density.

### 3. DETAILED EXPLANATION

A realistic acquisition design balances **breadth** (web) and **density** (curated sources), freezes and **versions** snapshots (freshness vs reproducibility), and keeps per-record **metadata** (`url`, crawl date, source, license, language) from the first byte, because later stages (licensing, deduplication, decontamination, per-domain evaluation) depend on it.

![Funnel](figures/01_data_pipeline_funnel.png)

*Figure 1 — Acquisition is the left-most bar: everything after it is attrition. The lab salts its synthetic crawl with junk so each later stage has work to do. [data_funnel.html](interactive/data_funnel.html) lets you set raw volume and per-stage drop rates.*

### 4. HOW DOES IT WORK?

1. A crawler fetches pages (respecting `robots.txt` and terms of service). 2. HTML is parsed and main-content text extracted. 3. Language is identified. 4. Each record stores its metadata. 5. Snapshots are stored immutably with a version ID. 6. Downstream stages read from the snapshot, never from the live web.

### 5. SIMPLE EXAMPLE

Stocking a library: some shelves of everything (web), plus shelves of textbooks and manuals (curated). You note where each book came from and under what terms you hold it.

### 6. TECHNICAL EXAMPLE

`lab/data_prep.make_synthetic_crawl` emits records `{id, text, source, license, url}` and injects exact mirrors, one-word-edit near copies, HTML boilerplate pages, symbol-soup pages, restricted-license copies, and (in `run_lab.prepare`) a leaked benchmark item.

### 7. CODE

```python
# Run from lab/: inspect the synthetic crawl and its metadata.
from collections import Counter
import data_prep as dp

raw = dp.make_synthetic_crawl(seed=0, n_docs=200)
print(len(raw), Counter(d["source"] for d in raw))

```

### 8. INPUT → PROCESS → OUTPUT

```
URLs / dumps / licensed corpora --> fetch + extract + language-ID + metadata --> versioned raw snapshot
```

### 9. ENTERPRISE USE CASE

Enterprises acquire internal documents (with access-control metadata), licensed vendor corpora and curated public sets. The acquisition manifest (what, from where, under which terms, which version) is what legal, security and ML teams all sign off on.

### 10. AI ENGINEERING CONNECTION

The same crawl-extract-metadata pipeline feeds RAG ingestion (Tier 20) and fine-tuning sets; mistakes here (lost metadata, mixed versions) propagate everywhere.

### 11. ADVANTAGES

- Breadth gives general capability; curated sources give density.
- Versioned snapshots make runs reproducible.

### 12. LIMITATIONS

- The web is skewed (languages, topics, demographics) and increasingly contains model-generated text.
- High-quality unique text is finite (the "data wall"), pushing toward synthetic and repeated data.

### 13. TRADE-OFFS

Crawl breadth vs quality; freshness vs reproducibility; owning data vs renting (licensing) it; synthetic data scale vs risk of compounding model errors (`REVIEW_REQUIRED` for quantified claims).

### 14. COMMON MISTAKES

- Discarding metadata, so licensing or opt-outs cannot be honoured later.
- Ignoring `robots.txt` and terms of service.
- Training on whatever is easiest to scrape, not what the target capabilities need.

### 15. PERFORMANCE / COST CONSIDERATIONS

Crawling, storage and bandwidth are significant; most of what is downloaded is discarded later, so budget raw volume as `final tokens / yield` (see [9.14](09.14-token-budgets.md)).

### 16. SECURITY CONSIDERATIONS

Public web text is attacker-controlled input to your model: **data poisoning** (a small number of planted documents can implant triggered behaviour; `REVIEW_REQUIRED` for quantified claims) and planted prompt-injection text. Keep provenance so offending sources can be traced and purged.

### 17. INTERVIEW EXPLANATION

"Acquisition is gathering a mix of broad web data and denser curated sources, with metadata attached to every record and the snapshot frozen and versioned. I care about it because later stages — licensing, dedup, decontamination, per-domain evals — all need that metadata, and because the web is an attack surface, not a trusted source."

### 18. RAPID-FIRE ANSWER

Collect broad and dense text sources, keep per-record metadata, and freeze a versioned snapshot.
