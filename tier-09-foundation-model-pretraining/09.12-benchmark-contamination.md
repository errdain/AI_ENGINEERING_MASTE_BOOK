### 1. WHAT IS IT?

The specific case where **benchmark questions (or answers) appear in the pretraining corpus**, so a high score may measure memory, not capability. Because benchmarks are published on the web, they are *likely* to be crawled.

### 2. WHY DOES IT EXIST?

Benchmarks are public by design, and web crawls are broad. Without active defence, scores inflate and model comparisons become meaningless.

### 3. DETAILED EXPLANATION

| Technique | How | Weakness |
|---|---|---|
| n-gram overlap | flag/drop training docs sharing an n-gram (n around 8-13 words; the choice is a trade-off, `REVIEW_REQUIRED` for any specific published value) with any benchmark item | misses paraphrases and translations |
| Decontaminate before training | remove matched docs (lab: `decontaminate`) | requires knowing the benchmarks up front |
| Canary strings / private held-out sets | evaluate on data created after the training cutoff or never published | costly to maintain |
| Report both | publish results on "clean" vs "possibly contaminated" subsets | still partial |

The lab leaks one benchmark sentence into the crawl; the pipeline's last stage removes it. This concept keeps benchmarks honest; *using* evaluation suites is taught in Tier 15 (and Tier 30).

### 4. HOW DOES IT WORK?

1. Collect the benchmark texts you care about. 2. Build the set of word n-grams for each. 3. Scan training documents; any document containing a benchmark n-gram is flagged. 4. Drop (or mask) flagged documents. 5. Re-measure contamination; 6. Evaluate also on fresh/paraphrased variants.

### 5. SIMPLE EXAMPLE

A quiz show where a contestant has seen the answer sheet; a perfect score tells you nothing about knowledge.

### 6. TECHNICAL EXAMPLE

The lab's leaked item `BENCH[0]` is repeated twice in one training document; `contamination_rate(..., n=8)` reports 1.0 before and 0.0 after `decontaminate` (`test_contamination_detect_and_remove`).

### 7. CODE

```python
# Run from lab/: detect and remove benchmark leakage using 8-gram overlap.
import data_prep as dp
from run_lab import BENCH

docs = [
    {"text": "intro text. " + BENCH[0] + " more text."},      # leaked
    {"text": "a harmless sentence about a red boat near the quiet river in the morning today"},
]
print(dp.contamination_rate(docs, BENCH, n=8))
clean, n_removed = dp.decontaminate(docs, BENCH, n=8)
print(n_removed, dp.contamination_rate(clean, BENCH, n=8))
```

Source: [`lab/data_prep.py`](lab/data_prep.py).

### 8. INPUT → PROCESS → OUTPUT

```
benchmark items + training docs -> n-gram index -> overlap flags -> decontaminated corpus + clean/contaminated eval split
```

### 9. ENTERPRISE USE CASE

Vendors selling models should disclose decontamination methods; buyers should run their own private, never-published eval set (customer-representative tasks) before trusting leaderboard numbers.

### 10. AI ENGINEERING CONNECTION

A leaderboard score is only as trustworthy as its decontamination. For model selection (evaluation methodology is Tier 15, with Tier 30 for the production side) always add a private eval.

### 11. ADVANTAGES

(Of decontamination.) Scores that reflect capability; cleaner comparisons between runs and vendors.

### 12. LIMITATIONS

- Paraphrased, translated or reformatted leaks pass n-gram filters.
- You must know the benchmark in advance; new benchmarks can't be removed retroactively without re-training.

### 13. TRADE-OFFS

Aggressive removal can drop legitimate documents that quote a benchmark in teaching material; loose removal leaves leaks. Choice of `n` trades false positives vs misses.

### 14. COMMON MISTAKES

- Decontaminating only exact matches.
- Decontaminating *after* choosing hyper-parameters on the same benchmark (test-set tuning).
- Forgetting benchmark re-posts in blogs, forums and GitHub.

### 15. PERFORMANCE / COST CONSIDERATIONS

An n-gram scan is linear in corpus size and cheap relative to training; the cost of *not* doing it is untrustworthy evaluation and possible re-training.

### 16. SECURITY CONSIDERATIONS

Deliberately seeding benchmark answers into public web pages can be used to game leaderboards. Keep a private set and canary strings to detect training on them.

### 17. INTERVIEW EXPLANATION

"The model scores 90% on a public benchmark — can I trust it? Not without asking how it was decontaminated. I'd check n-gram overlap handling, test on a fresh or paraphrased held-out variant, compare clean vs possibly-contaminated subsets, and rely on a private eval for the decision."

### 18. RAPID-FIRE ANSWER

Benchmark text in the training data inflates scores; remove n-gram matches and verify with fresh private evals.
