### 1. WHAT IS IT?

Pretraining a model in which **all parameters are used for every token**, so training FLOPs per token ≈ `6N`, and parameter count, compute per token and memory all move together.

### 2. WHY DOES IT EXIST?

It is the simplest, most predictable architecture to train and serve, and the baseline that scaling laws ([9.20](09.20-scaling-laws.md)) describe and sparse (MoE) models are compared against.

### 3. DETAILED EXPLANATION

Dense models are simpler to train and to serve and more predictable; the cost is that capacity only grows with compute per token. The lab model `TinyLM` (pre-norm decoder, tied embeddings) is dense by default (`moe_experts=0`): **128,512 parameters**, about `1.6e11` training FLOPs for the 200-step run (`6ND`, printed by `run_lab.py`). A standard training recipe: AdamW (β₂ ≈ 0.95), weight decay on matrices only, warmup + cosine LR, gradient clipping at 1.0, deterministic batches.

### 4. HOW DOES IT WORK?

For each step: (1) set LR from the schedule; (2) draw a deterministic batch; (3) forward pass through all layers (all parameters active); (4) cross-entropy loss; (5) backward; (6) clip global gradient norm; (7) AdamW update (no decay on biases/norm parameters); (8) log, evaluate and checkpoint periodically.

### 5. SIMPLE EXAMPLE

A school where every teacher teaches every student every day: simple and predictable, but costs scale with staff size.

### 6. TECHNICAL EXAMPLE

`python run_lab.py` trains the 128,512-parameter dense model for 200 steps on ~57k tokens (204,800 tokens seen), reaching validation loss ≈ 0.96 on the authoring machine (toy data; not a finding).

### 7. CODE

```python
# Run from lab/: a dense run in a few lines, and the non-embedding parameter count used for scaling fits.
import tempfile
import run_lab
from model import ModelConfig
from pretrain import TrainConfig, train

tok, tr, va, _ = run_lab.prepare()
cfg = TrainConfig(steps=30, eval_every=30, ckpt_every=30, model=ModelConfig(vocab_size=tok.vocab_size))  # moe_experts=0 -> dense
m = train(cfg, tr, va, tempfile.mkdtemp())
print(m["n_params"], m["n_params_non_embedding"], f'{m["train_flops_6nd"]:.2e}', m["final_val"])
```

### 9. ENTERPRISE USE CASE

Most enterprise-trained models (small domain models) are dense: they are easier to debug, deploy on commodity serving stacks and reason about cost (`6N` per token).

### 10. AI ENGINEERING CONNECTION

Dense decoders are the default for open-weight families; serving cost scales directly with N ([Tier 11](../tier-11-llm-inference-optimization/README.md)), which motivates MoE and smaller over-trained models ([9.21](09.21-compute-data-model-scaling-trade-offs.md)).

### 11. ADVANTAGES

- Simple, stable, well-understood; maps cleanly onto scaling laws.
- No routing or load-balancing complexity; easy to serve.

### 12. LIMITATIONS

- Capacity grows only with compute per token: every parameter is paid for on every token.
- Memory and inference cost scale with total N.

### 13. TRADE-OFFS

Dense vs MoE: simplicity and predictability vs more capacity per FLOP at the cost of memory, communication and training complexity ([9.25](09.25-mixture-of-experts-pretraining.md)).

### 14. COMMON MISTAKES

- Weight decay on norm/bias parameters.
- Peak LR copied from another model size without a sweep.
- Comparing dense models at equal total parameters but different tokenizers.

### 15. PERFORMANCE / COST CONSIDERATIONS

FLOPs ≈ `6ND`; memory ≈ 16 bytes per parameter plus activations ([9.23](09.23-distributed-pretraining.md)); throughput is limited by MFU and data loading.

### 16. SECURITY CONSIDERATIONS

Larger dense models memorise more; apply dedup, scrubbing and extraction tests. The training pipeline is code: pin dependencies and verify artefacts.

### 17. INTERVIEW EXPLANATION

"A dense model uses every parameter for every token, so compute per token is about six times N for training and everything scales together. It's the baseline: simplest to train and serve, and what scaling laws describe. MoE gets more capacity per FLOP, but at the cost of memory and routing complexity."

### 18. RAPID-FIRE ANSWER

All parameters active per token; training FLOPs per token ≈ 6N.
