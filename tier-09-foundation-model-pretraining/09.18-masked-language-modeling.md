### 1. WHAT IS IT?

In MLM a random subset of tokens is hidden and the model predicts them using context from **both** sides. (The definition is owned by Tier 8, topic 8.30; this file covers its place among pretraining objectives.)

### 2. WHY DOES IT EXIST?

Bidirectional context gives excellent representations for classification, retrieval and tagging (encoders), which a left-to-right model cannot see in one pass.

### 3. DETAILED EXPLANATION

BERT masked 15% of tokens, of which 80% became a mask token, 10% a random token and 10% stayed unchanged (`REVIEW_REQUIRED`: verify on the BERT paper). Attention is bidirectional, but only the masked ~15% of positions give a loss signal per sequence, and there is no natural left-to-right generation.

| | Causal (next-token) | Masked (MLM) |
|---|---|---|
| Context seen | left only | both sides |
| Loss positions | all | masked subset only |
| Generation | natural | awkward |
| Typical use | decoder LLMs | encoders (embeddings, classifiers) |

![Objectives](figures/10_objectives_masks.png)

*Figure 10, middle panel — the fully bidirectional mask: every row sees every column, but only the red-outlined (masked) rows are scored.*

### 4. HOW DOES IT WORK?

1. Choose ~15% of positions. 2. Replace with `[MASK]` (80%), random token (10%) or keep (10%). 3. Forward pass with bidirectional attention. 4. Cross-entropy only at the chosen positions. 5. Backprop.

### 5. SIMPLE EXAMPLE

A cloze test: "The ___ sat on the mat" — you use words on both sides to guess "cat".

### 6. TECHNICAL EXAMPLE

An encoder pretrained with MLM is fine-tuned for classification or used as the base of an embedding model for retrieval; its masked-token loss is not comparable to a causal model's loss (different task).

### 7. CODE

```python
# Standalone BERT-style masking (the 80/10/10 recipe, REVIEW_REQUIRED) in numpy.
import numpy as np

def mask_tokens(ids: np.ndarray, vocab: int, mask_id: int, rng: np.random.Generator, p: float = 0.15):
    ids = ids.copy()
    chosen = rng.random(ids.shape) < p                      # positions that get a loss
    labels = np.where(chosen, ids, -100)                    # -100 = ignored by the loss
    r = rng.random(ids.shape)
    ids[chosen & (r < 0.8)] = mask_id                       # 80% -> [MASK]
    rand = chosen & (r >= 0.8) & (r < 0.9)                  # 10% -> random token
    ids[rand] = rng.integers(0, vocab, rand.sum())
    return ids, labels                                      # remaining 10% unchanged

rng = np.random.default_rng(0)
x, y = mask_tokens(np.arange(40), vocab=100, mask_id=99, rng=rng)
print(x); print(y)
```

### 8. INPUT → PROCESS → OUTPUT

```
tokens -> choose 15% -> mask/random/keep -> bidirectional encoder -> logits at chosen positions -> loss on those only
```

### 9. ENTERPRISE USE CASE

Domain encoders (legal, biomedical) continued-pretrained with MLM improve retrieval and classification for enterprise search.

### 10. AI ENGINEERING CONNECTION

Many embedding and reranker models used in RAG (Tier 20) are descended from MLM-pretrained encoders; decoder LLMs use causal LM instead ([9.17](09.17-next-token-prediction.md)).

### 11. ADVANTAGES

- Bidirectional context gives strong representations.
- Efficient for understanding tasks at moderate scale.

### 12. LIMITATIONS

- Only ~15% of tokens per sequence carry a loss, so it is less sample-efficient per token.
- Train/inference mismatch: `[MASK]` never appears at inference.
- No natural generation.

### 13. TRADE-OFFS

Understanding quality vs generation ability; sample efficiency of causal LM vs bidirectional context.

### 14. COMMON MISTAKES

- Comparing an MLM loss to a causal loss.
- Forgetting to ignore unmasked positions in the loss.
- Masking tokenizer subwords independently when whole-word masking was intended.

### 15. PERFORMANCE / COST CONSIDERATIONS

Same per-token forward/backward FLOPs, but fewer scored positions, so more tokens may be needed to reach the same signal; the output softmax only needs computing at masked positions.

### 16. SECURITY CONSIDERATIONS

Same memorisation risks as other likelihood objectives; masked-token probing can extract memorised text from encoders as well.

### 17. INTERVIEW EXPLANATION

"Masked LM hides a random fraction of tokens and predicts them from both sides, so you get bidirectional representations — great for encoders, classification and retrieval. The trade-off versus next-token prediction is that only about 15% of positions give a loss and you can't generate naturally. So decoders use causal LM and encoders use MLM."

### 18. RAPID-FIRE ANSWER

Predict randomly masked tokens from bidirectional context; good for encoders, awkward for generation.
